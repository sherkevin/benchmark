# v06：把目标写成能核对的误差要求

## 旧版为什么不可信

旧版有真实结果作锚点，但未来结果是逐表独立挑出来的。整数、百分比算对了，不等于分布合理。我把来源和算术审查写成“科学复核通过”，这个表述不准确。新的独立审查对旧版六项评分为 2/0/1/0/1/1（每项满分 4），判断为低置信度。旧版完整保留。

这次先从逐分子记录重建：哪些工具共同犯错、两个方法分别救回和误伤哪些题、各拟合折和延迟怎样变化，再往上推均值。没有运行新实验。

## 新版最关键的关系

1. **自然场景不是“没有学习”，而是 82 次救回和 82 次误伤抵消。** 受控漂移为 780 次救回、112 次误伤。因此直接压低更新幅度可能改善自然结果，却损失漂移恢复，不能给两条曲线随手填上相同的正收益。
2. **旧 E1 两个目标对错误识别能力要求很高。** 若只靠修复已有误伤，同时达到自然 +48、受控 +58，需要避免约 59.67% 的误伤、仅损失约 1.13% 的救回。在同一个误差模型和原 scaffold 权重下，自然对旧 permutation 的差值只有约 +0.44pp，不是旧版另填的 +1pp。新候选仍须重新跑它自己的 permutation 才能评价归因。
3. **E3 的学习型 prior 目前确实变差。** BCE seed0 为 567/722，对 Corrected 的救回/误伤是 16/28。若想只通过避免误伤达到 591，至少要修复 24/28=85.71% 的误伤，且保留全部救回。不能把“有39题空间”当作已经知道如何救回。
4. **E4 的 1770 目标需要新救回能力。** 当前 Query 为1740；它相对同 prior 的 Frozen 只有23次误伤。全部修掉也只有1763，至少还要额外救回7次其它错误。114次可救错误中109次已有正确候选的反馈释放，需要进一步检查局部上下文和反馈使用。这是 provider 层的反馈覆盖，不是局部支持，也不能据此给提前反馈的因果收益设上界。
5. **E6 不能只匹配总覆盖率。** 每个拟合条件的接受量必须分别保持119/134/137/137/136。目标少8个接受错误可换算到95.78%接受准确率及对应效用，但还须证明允许使用的特征能找到这些交换，不能直接用真值挑样本。

## 科学家可以对标什么

- 真实四工具的16种联合正确向量，而不是四个独立错误率；开发/当前fresh队列分别有104/7个全工具共同错误分子。
- 各方法的救回、误伤、共同错误，以及各折、延迟和事件前后分布。自然五个拟合条件的净正确变化为−16/+4/−2/+14/0，不能只看汇总为0。
- 明确的条件误差预算：误伤减少多少、原有救回损失多少，由同一记录推导 pooled、scaffold 和分层结果。保留零收益、负收益和非单调延迟，不人为生成“稳定提升”。
- 新 prior 与新 update 的共同因子对照，以及同接受量的错误交换。组件目标不能直接加成一个完整方法结果。

## 置信度的含义

已有联合错误、分母、配对关系和分层数值可以核验；给定显式条件后的预算可以精确验算。这两层能够给科学家可靠的参照。

未来候选能不能达到这些选择性要求，目前没有经过验证的概率模型。新 Guide 因此不造预测区间、不造 seed 方差，也不把修补旧终局记录说成真实在线轨迹。30个配置共享同一批157分子、同一到达顺序，多数seed还完全重复；已有配置SD不能充当未来效果的置信度。

目标仍然保留。新版把“想达到什么”与“要改变哪些错误才能达到”连起来，让失败能指向具体的方法问题，而不是再换一组漂亮数字。
