# Figure 1 prompt v05 — modular MIRA-Relay overview

- Status: current prompt after TopConf gallery round-2 review and user visual review
- Revision from v04: turns the figure from a text-heavy four-panel flowchart into a compact architecture overview. The figure now shows modules, interaction, data flow, and the relay innovation with short labels only.
- Intended output: flat vector draft, 1600×560 or about 3:1 aspect ratio
- Final paper asset: use the generated image only as a composition reference; redraw exact labels and arrows in editable SVG/HTML/PDF

## Design target

Make this an architecture/framework figure, not a poster and not a numbered tutorial. A reader should see one sentence from the geometry alone: released state enters a two-part selector, one provider is called, a frozen judge creates selected-only feedback, and a delayed event updates the family residual and provider bias before a later decision. Use modules and arrows; do not use paragraphs inside boxes.

## Visual structure

Use one left-to-right pipeline with three compact grouped regions and a small method inset.

1. **Decision state.** On the left, show a compact input bundle with molecule, endpoint, eligible provider menu, and released state `$S_t$`. Next show a candidate menu with at most three provider cards. One card is highlighted blue as `selected provider`; the other cards are pale grey and labelled only `eligible`, with no output bubbles. Add a small closed-eye icon or faded outline to indicate that unselected outputs are unavailable; do not draw a large cross.

2. **Selector.** Inside a blue-outlined group labelled `MIRA-Relay`, place two parallel scoring modules: a grey locked `fit-only reference` and a blue `family residual + provider bias`. Show a small shared-family bracket or three linked provider chips with `$\times N$` to make the transfer mechanism visible. Both scores merge into the single selected provider card. The fit-only reference is immutable; it is not connected to the online update arrow.

3. **Call and evidence.** The selected provider flows to one `tool call` module. Its output and runtime status enter a compact terminal record. The terminal record feeds an amber `frozen endpoint judge` only after termination and produces a small `chemical correctness` badge for valid returns. A separate grey branch labelled `runtime failure` goes to the runtime ledger. Do not draw a second call or a verifier/refusal path.

4. **Delayed relay update.** The selected outcome enters a purple queue with a small clock icon and label `$\tau_t=t+1+D$`. The queue feeds a blue `released state` node, then loops back to the selector input. Put a small grey `diagnostic ledger only` node on the fallback outcome branch; it must not connect to the blue relay update. Add a tiny legend: solid = observed/completed, dashed = waiting/control, faded = unavailable.

## Prompt to copy

Create a clean, publication-ready flat vector architecture/framework figure for a top multi-agent systems paper. Use a 1600×560 white canvas, one left-to-right data-flow pipeline, three compact grouped regions, one small method inset, a single Arial/Helvetica/Inter sans-serif font, flat fills, thin black arrows, and no paragraphs. Every module label must be one to four words; equations may use short symbols only. The figure must remain legible at 8 pt equivalent in a full-width paper figure.

Left region: draw a compact input bundle with a molecule symbol, an endpoint document, an eligible provider menu, and a blue cylinder labelled “released state S_t”. Feed these into a small candidate menu containing at most three abstract provider cards. Highlight exactly one card in blue as “selected provider”; keep the remaining cards pale grey and labelled only “eligible”. Show their outputs as unavailable with a small closed-eye icon or faded outline, never a large cross and never an output value.

Center region: draw a blue-outlined group titled “MIRA-Relay”. Inside it, place two parallel scoring modules: a grey locked box “fit-only reference” and a blue box “family residual + provider bias”. Show a small bracket linking three provider chips with the label “shared family ×N”, plus small individual bias chips. Both scoring modules merge into the single selected-provider card. Draw the fit-only reference as immutable and do not connect it to the online update path.

Right-center region: draw one box “tool call”, followed by a compact terminal record containing “output” and “runtime status”. From the terminal record, draw an amber box “frozen endpoint judge” with a short label “after termination”. From it, draw a small badge “chemical correctness”; from runtime status, draw a separate grey branch “runtime failure” into a grey ledger. Do not draw a second call, verifier, refusal, escalation, or full output panel.

Bottom/right feedback path: draw the selected outcome entering a purple cylinder or queue labelled “selected outcome” and “τ_t = t + 1 + D”. Connect it to a blue node “released state” and a return arrow to the selector input. Add a small grey dashed node “diagnostic ledger only” on the fallback outcome branch; it must not touch the blue relay update. Add a tiny legend with solid arrow = observed/completed, dashed arrow = waiting/control, faded card = unavailable.

Use only navy #2E5DA1 for MIRA-Relay, selected provider, and released state; light grey #B8C0CC for frozen/reference, runtime ledger, and unselected menu cards; amber #D99000 for terminal record and frozen judge; muted purple #6B4C9A for pending queue and delayed event; black text; white background. Use shape and line style as redundant encodings so the figure works in grayscale.

Do not create a text wall, numbered six-step tutorial, giant crossed-out boxes, red/green correctness colors, gradients, 3-D effects, drop shadows, decorative cartoon characters, molecular artwork larger than the input icon, fake metrics, provider names, extra agents, a second tool call, or a circular instantaneous-learning loop. Do not connect unselected outputs or fallback bookkeeping to the online relay.

## Negative prompt

Avoid infographic poster layouts, dashboard cards, long explanatory sentences inside modules, crossed-out candidate panels, arrows from unselected outputs, arrows from correctness to the current action, mutable fallback weights, and mixed serif/sans-serif typography.
