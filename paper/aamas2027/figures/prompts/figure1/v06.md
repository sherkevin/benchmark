## Prompt to copy

Create a clean, publication-ready flat vector architecture/framework figure for a top multi-agent systems paper. Use a 1600×560 white canvas, one left-to-right data-flow pipeline, three compact grouped regions, one small method inset, a single Arial/Helvetica/Inter sans-serif font, flat fills, thin black arrows, and no paragraphs. Every module label must be one to four words; equations may use short symbols only. The figure must remain legible at 8 pt equivalent in a full-width paper figure.

Left region: draw a compact input bundle with a molecule symbol, an endpoint document, an eligible provider menu, and a blue cylinder labelled “released state S_t”. Show at most three pale-grey provider cards labelled “eligible” inside the menu. These cards are candidates before selection; none may be labelled “selected provider”, and none may have an output bubble. Use a small closed-eye icon or faded outline for unavailable outputs, never a large cross. Draw one arrow from the input bundle and candidate menu into the MIRA-Relay selector; do not draw an arrow from a candidate card directly into the fit-only reference.

Center region: draw a blue-outlined group titled “MIRA-Relay”. Inside it, place two parallel scoring modules: a grey locked box “fit-only reference” and a blue box “family residual + provider bias”. Show a small bracket linking three provider chips with the label “shared family ×N”, plus small individual bias chips. Both scoring modules merge into the only selected card in the whole figure, labelled “selected provider”. The fit-only reference is immutable and must not connect to the online update arrow.

Right-center region: draw one box “tool call”, followed by a compact terminal record containing “output” and “runtime status”. From the terminal record, draw an amber box “frozen endpoint judge” with a short label “after termination”. From the judge, draw a small badge “chemical correctness”; from runtime status, draw a separate grey branch “runtime failure” into a grey “runtime ledger”. Do not draw a second call, verifier, refusal, escalation, or full output panel.

Bottom/right feedback path: draw the selected outcome entering a purple cylinder or queue labelled “selected outcome” and “τ_t = t + 1 + D”. Connect it to a blue node “released state” and a return arrow to the input state used by the selector. Add a separate small grey dashed token labelled “fallback outcome” that goes to a grey node “diagnostic ledger only”; this branch must not pass through runtime failure and must not touch the blue relay update. Add a tiny legend with solid arrow = observed/completed, dashed arrow = waiting/control, faded card = unavailable.

Use only navy #2E5DA1 for MIRA-Relay, the single selected provider, and released state; light grey #B8C0CC for frozen/reference, runtime ledger, and unselected menu cards; amber #D99000 for terminal record and frozen judge; muted purple #6B4C9A for pending queue and delayed event; black text; white background. Use shape and line style as redundant encodings so the figure works in grayscale.

Do not show a selected provider before the selector. Do not connect candidate cards directly to the fit-only reference. Do not route runtime failure to diagnostic ledger only. Do not create a text wall, numbered tutorial, giant crossed-out boxes, red/green correctness colors, gradients, 3-D effects, drop shadows, decorative cartoon characters, molecular artwork larger than the input icon, fake metrics, provider names, extra agents, a second tool call, or a circular instantaneous-learning loop. Do not connect unselected outputs or fallback bookkeeping to the online relay.

Negative prompt: avoid duplicate selected-provider cards, pre-selection arrows, ambiguous fallback/failure branches, infographic poster layouts, dashboard cards, long explanatory sentences inside modules, crossed-out candidate panels, arrows from unselected outputs, arrows from correctness to the current action, mutable fallback weights, and mixed serif/sans-serif typography.
