- Status: revised visual exploration prompt

## Natural-language structure

Use one vertical lane with six numbered stages, each stage containing at most two short lines of text and no overlapping boxes. Draw a clear horizontal phase boundary between the action at tick `t` and the release phase at tick `t+1+D`. The action side contains decision, one selected provider call, and terminal status. The judge is after termination. The queue is a waiting state and hides correctness from the selector. The release phase updates the post-release state `S_{t+1}` for `D=0` or the corresponding later state for larger D; only the next decision sees it. A small ghost of an unselected output remains outside the main lane and is explicitly marked unavailable. Even when `D=0`, the event becomes visible only at `t+1` and never changes action `t`. Use line style as a second encoding for timing.

## Prompt to copy

Create a clean, publication-quality flat vector lifecycle diagram for a top multi-agent systems paper, 900×1000 canvas, white background, portrait layout, one vertical lane with six numbered stages, each stage max two short lines of text and no overlapping boxes, large high-contrast labels. Show an explicit phase boundary: the action at tick “t” is completed before any feedback can update state; the release phase occurs at “tau_t = t + 1 + D”. Phase 1: “decision t: choose one eligible provider”. Phase 2: “selected call”. Phase 3: “termination: output + runtime status”. Phase 4: “frozen endpoint judge after termination: chemical correctness”. Phase 5: “pending queue: correctness hidden for D ticks”. Phase 6: “release phase: update post-release state S; only the next decision reads it”. Add a small crossed-out ghost “unselected output — not observed” outside the main lane, with no arrow to the updater. Show separate branches for “system failure” and “chemical correctness”. Use navy #2E5DA1 for state and decision, light grey #B8C0CC for execution, amber #D99000 for the terminal record and frozen judge, muted purple #6B4C9A for pending and delayed release. Solid arrows mean completed transitions; dashed arrows mean waiting. Even for “D=0”, show visibility only at “t+1”, never as feedback to action “t”. No same-action feedback, no second call, no refusal branch, no gradients, no 3-D, no fake metrics, no decorative icons, no tiny text. At the final paper width, use at least 8 pt equivalent; shorten secondary labels instead of shrinking them.

## Negative prompt

Do not draw a circular instantaneous learning loop, do not connect unselected outputs to the queue, do not place correctness before termination, do not imply that D=0 changes action t, do not use red/green-only semantics, and do not use illegible AI-generated equations.
