## Natural-language structure

A vertical timeline with six numbered phases: decision tick `t`; exactly one eligible provider is selected; the selected tool returns an output and runtime status; after termination a frozen endpoint judge emits correctness; the event waits in a pending queue for `D` ticks and is not visible during the wait; at `tau_t = t + 1 + D` the event is released and updates the relay; the first next action can read the released state. A faint crossed-out unselected output appears at the side and has no feedback arrow. Runtime failure and chemical correctness are separate rows.

## Prompt to copy

Create a publication-quality flat vector single-column lifecycle diagram for an AAMAS paper, portrait-friendly aspect ratio 0.9:1, white background, a vertical timeline with six large numbered stages. Stage 1: “decision tick t — choose one eligible provider”. Stage 2: “one selected tool call”. Stage 3: “terminal runtime status + independent frozen endpoint judge after termination”. Stage 4: “pending queue — not visible during D ticks”. Stage 5: “release at tau_t = t + 1 + D”. Stage 6: “relay update — first next action reads S”. Add a faint crossed-out unselected output labelled “not observed”; do not draw a feedback arrow from it. Separate “system failure” from “chemical correctness”. Use navy for selector/state, grey for execution, amber for the judged event and queue, muted purple for delayed visibility. Solid arrows are completed events and dashed arrows are waiting/control flow. No second call, refusal, escalation, gradients, 3-D, fake values, or decorative icons. Keep every label readable at single-column print size.
