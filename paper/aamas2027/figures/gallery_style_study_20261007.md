## 我们旧图的问题

1. v08 把内部运算压成说明框，读者需要读完整句子才能理解方法；蓝色主体没有显示如何得到动作。
2. AI v05 仍用很大的标题条和同义记录卡。图中 terminal outcome 的下箭头落向下方分区边缘，未实际接到左侧 selected outcome；旧“16/16”记录不足以排除这处绕过队列的歧义。
3. 用户原图 v07 更紧凑，但 `family residual + provider bias` 已不是当前正文的实现。其反馈回路也未展开队列释放后的计数更新。
4. “没有网格、没有渐变”只是在排除错误，不足以产生好的设计。必须同时写清视觉中心、模块内部形态和箭头的起止位置。

## Figure 1：需要画出的机制

一眼读出的主张：冻结分数与已释放的单 provider 残差合成当前选择；只有已选结果经过释放，才能更新该 provider 的计数。

- 左：分子、性质和候选菜单；均是输入，无当前工具输出。
- 中：最大的浅蓝方法区。冻结 scorer 用特征格与固定权重块表达；在线状态用按 provider 分行的两列计数格表达；残差进入合并算子，输出 score vector，再选一个 provider。
- 右：调用、返回记录、冻结判分器；运行失败进入灰色独立账本，不生成化学标签。
- 下：判分后的有效已选反馈进入紫色队列，释放后回到蓝色计数格。回路直接进入更新位置，不另画一排重复的 terminal/selected/released outcome 框。
- 图中只有一个小公式 `$q=q^0+\Delta$` 和释放时钟 `$\tau_t=t+1+D$`。概率、准确率、性能提升不在概念图里虚构。

## Figure 2：需要画出的时序

用一条紧凑的事件路径表达 decision → call → terminal → queue → release → later decision。
判分发生在 terminal 后；本事件隐藏到释放时钟；其他已释放事件仍能被使用。
只画一条紫色等待路径和一个蓝色更新回折，不画泳道横线、表格列线或跨全图固定的旧状态轨道。

## 风格规格与验收

以下数字是本项目的设计目标，不是所有顶会图的统一规则。

| 项目 | 可检查要求 |
|---|---|
| 主方法比例 | Figure 1 中方法区为最大分区，约占画面宽度 40–45%；不让 evaluator 成为视觉中心 |
| 文本密度 | 除公式外不超过约 70 个英文词；单节点最多两行短标签；解释性句子进入 caption |
| 图形语法 | 数据/记录用卡片，参数用固定权重块，状态用计数格，合成用算子，延迟用队列；不把所有东西画成同一种方框 |
| 配色 | 深蓝 `#2E5DA1` 为在线核心；灰为冻结/外部；琥珀为终态判分；低饱和紫为等待；背景白或极浅色 |
| 线条 | 同一箭头和边框体系；箭头接到具体节点，不悬在分区边缘；无相交和不明方向 |
| 版面 | 约 2.7:1 的通栏画幅；紧凑、边距均匀；不用巨大标题条、通栏网格、叉号或占位装饰 |
| 方法一致性 | 不出现 family-sharing、可训练 backbone、额外 provider 调用或伪造反馈；运行失败不更新化学计数 |
| 因果路径 | 已选调用→终态→判分→队列→释放→计数→后续选择完整；不能直接从终态跳到 released state |
| 纸面可读性 | 在实际 7-inch 通栏 PDF 检查模块和标签，不能只在放大的 PNG 上打分 |
| 留痕 | 每轮完整 prompt、原始 AI 输出、参考图 hash、审查意见和选用状态分别保存；不手工修改 AI 像素 |

审查使用 8 项、每项 0/1/2 分：视觉中心、模块表达、信息密度、布局、色彩线条、数据路径、方法一致性、纸面可读性。
其中数据路径或方法一致性出现实质错误即不接入论文，不能用总分抵消。
