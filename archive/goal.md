## 1. 根本目的（一句话）

> **为材料发现和生物分子（药物）发现领域，造一套 long-horizon agent benchmark：不只看 agent 最终给出的分子对不对，更看它寻找分子的过程对不对——每一个关键步骤都有可机器判定的检查点。**

---

## 1.5 两类任务（v3.0 锁定，题集的顶层划分）

**题集只分两大类，两类考的能力不同、造题法不同、判分口径也不同。**

### 类型一 · fixed 推理类

约束已给全、**gt 本身就在 agent 能查到的数据库里**，query 的目的就是把它查出来。考的是能不能把活干对——逐项查证、正确筛选、不跳步。按 GT-first 反查法造（**§2**），判分重**过程**（checkpoint DAG + 路径拓扑验证）。

### 类型二 · open 发现探索类（discovery_haystack）

> **权威定义：[ADR-0012](governance/adr/0012-两类benchmark设计范式与query专家背书要求.md) §1 第二类（Accepted，2026-08-02）。下文为其摘要，不得与之冲突。**

数据库分为 **A（agent 可查）** 与 **B（agent 不可查）**。给一个设计目标（如“针对 xxx 的分子，xxx 尽可能好、xxx 尽可能低”），**agent 根据 A 中的信息推理出一个 A 中不存在的分子**。它不知道该分子是否存在，只能给出推断；评分时去 B 里查这个推断，看它是否猜对。

**三条关键设计约束（缺一不可）**：

| 约束 | 含义 |
|---|---|
| **线索性联系** | 被推理出的分子必须与 A 中分子有线索性联系（如“加上一个原子 a 就会增加 xxx 性质”），**保证推理有据可依、不是瞎猜** |
| **存在性查询接口** | agent 推出分子 m 后查接口判 m 存不存在：在 B 里就是存在（任务结束），不在就重新推断直至存在。**agent 只能知道“存不存在”，不知道 m 的性质** |
| **B 不可见** | agent 在推理过程中**完全看不到 B 的内容**，只能通过存在性接口验证 |

- **考的能力**：不是“会不会多调一个工具”，而是**能不能从已知线索推出未知的东西**——生成式发现。
- **判分口径**：`open_score = 𝟙[hit(G_B)] × 𝟙[grounding_pass]`（**唯一口径，详见 §2b**）——终态须命中 B 侧**合格集 `G_B`**（非"B 中任意分子"）**且** 产物落地验证通过；**不做路径拓扑验证**。
- **为何有价值**：真实科研的核心动作就是“从已知推未知”，而非在现成库里检索。

### ⚠️ 必读：两个容易搞错的命名陷阱

**陷阱一：已落盘的 `open_discovery` 模板不是本节的 open 发现类。** `dag_poc/templates/open_discovery/` 实测是**约束最优型、6 个 cp（含 cp5 按目标排序）、评过程**，**它属于 fixed 推理类**，与本节类型二语义相反。

**陷阱二：open 发现类当前完成度为 0。** 不要因为 §7 写“4 套 template 已可运行”就认为 open 已有。

### 四类模板 ↔ 两类任务的映射

两类是**判分口径的顶层划分**（评过程 / 评终态），[task17 的四类](task/task17/query类型分化设计.md)是**模板实现层的细分**，两者不竞争：

| 本节两类 | task17 四类 | 落盘状态 |
|---|---|---|
| **fixed 推理类**（评过程） | 类型1 约束满足 + 类型2 约束最优（含 `open_discovery`）+ 类型3 证据溯源 | 类型1/2 已落盘；类型3 未做 |
| **open 发现探索类**（终态闸门 + grounding，见 §2b） | 类型4（需按 ADR-0012 重定义：B 不可见 + 推理生成，而非原写的“换源检索”） | **0 template / 0 case** |

### 未来方向 · 长程偏探索任务（非本版范围）

基于本 benchmark 再往前一步：造**长程偏探索**的任务，**引导 agent 更倾向于追寻未知，而不是停在 A 里吃现成的**。

与 open 发现类的**三条区分轴**（避免概念模糊）：

| 轴 | open 发现类 | 长程偏探索 |
|---|---|---|
| 推理跳数 | 一轮推断即可验证 | **多轮/多跳**，需反复修正假设 |
| gt 形态 | 单点唯一 gt | 可为 **Pareto 前沿**而非单点 |
| 停止判据 | 存在性接口命中即结束 | **agent 需自主判断何时停止搜索**（long-horizon 的真难点） |

> **范围声明**：本方向属**第二阶段候选**，**不包含在 §6 步 6 “项目最终完成”的定义内**，E1–E6 不预先投入。

## 2. fixed 推理类的造题法：GT-first 反查构造法（四步）

> **作用域：本节四步法仅适用于 fixed 推理类。** open 发现探索类的造题法见 **§2b**。

### 第 1 步 · 寻找具体分子并反查性质
从科学数据库中**先选定一个具体的、已知优秀的分子**（gold root），用分子性质/结构查询接口反查出它的若干性质（如：稳定性、毒性、成药性、带隙、结构合理性等）。这些反查值就是后续一切判分的**真值（ground truth）**——答案先于题目存在，且可复核。

**入题必经的防污染门（原等价匿名变换，[ADR-0023](governance/adr/0023-取消分子匿名化防污染改靠任务设计.md) 已取消匿名、改靠任务设计）**：答案不写在题面、必须靠多步推理 + 工具探索才能到达，性质与真实世界保持一致，否则 agent 可靠训练记忆直接蒙对（§5 红线 5）。时间差声明：任务设计层全面落地前，本 benchmark 不对外声称抗记忆污染。

### 第 2 步 · 构造专属 Query
根据反查出的性质，**反向构造**针对该分子（或该类分子）的专属自然语言任务：例如"为应用 X 寻找一个满足性质 P1、P2、P3 的材料/分子"。**题目隐去答案本身与具体数值**——agent 看到的是约束，不是答案。

### 第 3 步 · 生成问题模板与 DAG
按问题类别生成专属流程模板（先做什么、再做什么、后做什么），并固化为一张 **checkpoint DAG**：图中每个节点是一个**中间检查点**（如"确认目标性质窗口→构建候选池→逐项评估稳定性/毒性/目标性质→筛选排序→提交"），每个节点都有确定性验证器，检查 agent 是否真实、正确地完成了该步。DAG 只连真实依赖，允许等价路径。

### 第 4 步 · 运行与结果验证（双验证）
让 agent 跑完整流程，然后双路验证：

**(a) 终态验证（结果对不对）**——两层都成立：
- (a1) **最优结果已知**：反查前确定的那个分子就是已知的优解（加上同等合格的其它分子构成正例集 G），agent 的最终答案落在 G 内且各项性质经接口复核通过，才算终态对；
- (a2) **性质符合预期**：终态分子的每项性质都可经反查接口**重新查询并打分**（毒性、结构合理性、稳定性……全是可执行的数值/布尔判定）。

**(b) 路径验证（过程对不对）**——把 agent 的执行轨迹在关键节点处打平成序列，与 DAG 的合法拓扑序对比：**检查关键 checkpoint 的完成顺序是否与依赖关系匹配**（无依赖可换序，有依赖不可逆、不可跳）。路径不匹配（跳步/逆序/缺节点）即判过程有误，**即使终态答案碰巧正确也不能过总闸门**。

### 2.1 过程验证的两个正交概念（两类任务适用范围不同）

为避免与 §1.5 open 类口径矛盾，“过程验证”必须拆为两个独立概念：

| 概念 | 含义 | fixed 类 | open 类 |
|---|---|---|---|
| **路径拓扑验证** | 顺序/跳步/缺节点与 DAG 拓扑序比对 | ✅ 适用（即上述 (b)） | ❌ **豁免**（推理路径不唯一，强制则误判） |
| **产物落地验证（grounding）** | 产物数值必须被真实接口调用支撑，不得编造 | ✅ 必须 | ✅ **必须**（不可豁免） |

> 两类都保留 grounding，所以 open 类 **不属于§5 红线 1 所禁的“不带 checkpoint 的退化版”**。

## 2b. open 发现探索类的造题法（五步）

> 本节填补 §2 四步法不覆盖的部分。权威约束见 [ADR-0012](governance/adr/0012-两类benchmark设计范式与query专家背书要求.md) §1 第二类与 §3。

| 步 | 动作 | 要点 |
|---|---|---|
| **① 在 B 源选定 gt 与合格集** | 从 B 库选定目标分子并反查性质，**并穷举出 B 侧合格集 `G_B`**（gt + 同等合格者）并落盘 | 沿用 GT-first；**gt 必须经防污染门**（答案不写题面 + 裸答基线核验；ADR-0023 匿名已取消）。`G_B` 是评分基准，**不是“命中 B 中任意分子”** |
| **② 切分 A / B** | A = agent 可查；B = 不可查，**且 gt 在 A 中不存在** | 需后端库**物理分层**，A 的任何查询不得带出 B 内容；**A 侧须支持全域穷举**（供 ④ 使用） |
| **③ 埋线索性联系** | A 中分子与 gt 存在可推导的结构-性质关系 | **线索必须完全可由 A 内数据归纳得出**（同系列 ≥k 条同向样本）——线索不在 A 内自足则 ④ 永远过不了；ADR-0023 真实态下 agent 外部先验有效，防污染由此收敛到「答案不写题面 + 裸答基线核验」，不再依赖匿名压制先验 |
| **④ 可发现性质量门**（open 类的质量门，两条均为可执行断言） | **第一条（A 侧无替代解）**：用可解性穷举器在 **A 全域**求解题面目标，须证**A 内不存在满足全部硬约束且目标量不劣于 gt（容差 δ）的分子**；<br>**第二条（线索可达）**：case 须声明 `anchor ∈ A` + `edit_op ∈ 封闭算子集` + **跳数 ≤2** + `evidence_set`（A 内 ≥k 条同向证据），脚本校验 `edit_op(anchor)` 规范化后 **== gt** 且 `evidence_set` 均可由 A 侧接口查得 | 两条任一不成立则该 case **废弃**。<br>**注意**：第一条不能写成“仅穷举 A 拿不到 gt”——那是 ② 的**重言式**、零过滤力；真正要卡的风险是“**A 内已有不劣于 gt 的合格解**”，那会使题目退化为 fixed 检索。<br>超出算子集或 >2 跳的 case 一律废弃（否则算子空间爆炸、质量门不可判） |
| **⑤ 存在性接口与终态判定（三者必须分离）** | 见下表 | 切勿把“接口返存在”直接当得分依据，那会构成自证循环并被暴力枚举攻破 |

### ⑤ 的三个独立概念（混用即设计失效）

| 概念 | 定义 |
|---|---|
| **停止信号** | `check_molecule_exists` 返“存在”→ agent 可结束本轮推断 |
| **接口语义（定义域，必须写死）** | 返值严格等价于 `m ∈ B`：**A 内分子与库外分子一律返“不存在”**；返回**单个 bool**，不带任何性质/相似度/距离信息。若对 A 内分子返“存在”，agent 直接交 A 中分子即过，**整个设计崩塌** |
| **评分依据** | 推断分子 **∈ `G_B`**（① 落盘的合格集）**且** 经 B 侧性质复核满足题面目标窗口。**不是“命中 B 中任意分子”**——否则 agent 循环猜常见分子即可刷分 |
| **尝试预算** | 存在性接口设 `max_attempts`（建议 ≤10，写进 §6 步 3 出入参）；**超限记 0 分**，且 attempts 计入指标 |

### open 类的总闸门（唯一口径，其他章节均引用本式）

$$\text{open\_score} = \mathbb{1}[\text{hit}(G_B)] \times \mathbb{1}[\text{grounding\_pass}]$$

其中：
- $\mathbb{1}[\cdot]$：指示函数，条件成立取 1、不成立取 0；
- $\text{hit}(G_B)$：agent 提交的推断分子属于 ① 落盘的 B 侧合格集 $G_B$，且经 B 侧性质复核满足题面目标窗口；
- $\text{grounding\_pass}$：产物落地验证通过（定义见下节）；
- 乘法关系意味着**两者缺一则总分为 0**；预算耗尽未命中也记 0。

### open 类的产物落地验证（grounding）——必须有数据源

不先规定答卷字段，“grounding”就没有可校的对象（与 `no_path_violation` 当年的“悬空符号”同型错误，ADR-0008 教训）。因此 **open 答卷 schema 硬要求**：

| 字段 | 要求 |
|---|---|
| `anchor_molecules[]` | 推理所基于的锚点分子，**必须 ∈ A** |
| `cited_values[{mol, prop, value}]` | 推理所引用的 A 侧性质值 |
| `edit_op` | 从 anchor 到提交分子的结构编辑算子 |

**grounding 通过条件（三条均成立）**：① 每条 `cited_value` 与 trace 中**真实工具返回值在容差内一致**；② `anchor ∈ A`；③ `edit_op(anchor)` 规范化后 **== 所提交分子**。该 schema 与 `answer_schema.json` 同批交付（§6 步 3）。

### open 类特有的防蒙对手段（必需）

open 类没有**路径拓扑**检查（仍有 grounding），“靠记忆蒙对”在此最难检出，因此额外要一道门：

> **无工具裸答基线检验（阈值写死，不得各人各判）**：不给 tools、固定 temperature，直接把题面问模型 **k=10 次**。
> - **open 类**：任一次命中 `G_B` 即判污染并**废弃**（因 open 的候选空间实质无界，随机命中率≈ 0，不能写“显著高于随机”这种不可执行的说法）；
> - **fixed 类**：以“同 case 候选池内随机抽样命中率”为基线，裸答 pass@10 **超基线 2×** 即废弃。

## 3. 三条硬边界（题目形态的筛选口径，继承 v1.0）

1. **单 Agent**：被测对象是一个智能体，非多智能体协同；
2. **一次性输入**：任务信息一次给全，执行中无模拟用户对话、无长期记忆检索（agent 调工具查数据不算交互，那是它的工作方式）；
3. **hard 中间 checkpoint**：所有检查点判定必须是**可执行的**（数值容差/集合成员/结构解析/约束函数/状态比对），**不用 LLM judge、不用人工主观分**；仅当某语义点确实无法规则化时才允许 LLM judge 且必须配 κ 校准（人评一致率），并报告。

> **作用域说明（避免与造题期质量门混淆）**：本条约束的是**运行期对 agent 的判分**。**造题期**的质量门（§2b ④、§4 支柱 3）允许人工/专家参与，但其产物必须冻结为确定性判据（`G_B` / anchor 白名单 / 容差 δ / checksum），**运行期不得再有任何主观判断**。

## 4. 方法的可信度支柱（为什么这么造是可靠的）

1. **GT-first 反查**：答案锚定科学数据库/文献的已知分子与性质，天然"每题有解、真值可验"，避开"先出题再找答案"的三大坑（无解、真值不可验、出题泄漏）；
2. **验证器查产物不认动作**：checkpoint 验证的是中间**产物/状态**（"毒性评估的产物存在且数值与真值一致"），而非"agent 是不是用了某个特定工具"——等价路径不受罚，编造产物可被"工具落地检查"（产物数值必须被真实接口调用支撑）抓出。**注**：§2.1 的"产物落地验证（grounding）"校的是产物数值的**来源**、而非工具身份，故与本支柱不冲突；
3. **质量门**：金标准轨迹回放必须全过（必要性）+ 负例/空转轨迹不应全过（区分度）+ 实例内容指纹防变体泄漏 + 无解题测诚实性。**（open 类以 §2b ④ 可发现性质量门 + 裸答基线替代轨迹回放）**；
4. **调研先行**：构造方法已从 35+ 现有 benchmark 提炼（见 `research/`），不重复发明；过程级 hard checkpoint 经多轮补盲确认为空白（见 `research/science_agent_benchmark.md`）。
5. **防污染设计**（[ADR-0023](governance/adr/0023-取消分子匿名化防污染改靠任务设计.md) 重定）：匿名变换已取消（元素级替换可被拓扑反推、且与测结构推理冲突，2026-08-15 全库已回滚真实态），防污染改靠**任务设计**——答案不写在题面、必须靠多步推理 + 工具探索才能到达；open 类加跑**无工具裸答基线**——命中率显著高于随机即判该 case 污染并废弃。**时间差声明**：任务设计层全面落地前，不对外声称抗记忆污染。

## 5. 红线（命中即偏离，须立即叫停）

- ❌ 出**整体**"不带 checkpoint、只看终答"的退化版本 —— 丧失项目存在理由。**注**：open 发现探索类可豁免**路径拓扑验证**，但**不得豁免产物落地（grounding）检查**（见 §2.1），故不算退化；
- ❌ 拿通用 agent 任务（SWE/网页/办公）凑数 —— 领域定位失焦（只借法、不重做）；
- ❌ 用 LLM-as-judge 凭知识硬判、不要 GT —— 指标可信度归零（ChemCrow 已实证 GPT-4 裁判分不清对错）；
- ❌ 跳过调研直接造题 —— 等于重新发明，且很可能与现有 benchmark 同构；
- ❌ 用 LLM 训练分布内的热门分子当答案而不做防污染设计（答案写进题面 / 不跑裸答基线）—— agent 靠记忆蒙对、过程评测失效。防污染不靠匿名（ADR-0023 已取消），靠任务设计 + 裸答基线核验。

**ICLR 2027：摘要 9/18、正文 9/25**（T-29 已定，含 Plan A/B 与八周排期）。这是 §6 六步链路的**外部时间边界**——E1–E6 的排期必须倒推自这两个日期，关键路径若赶不上，须按 T-29 的 Plan B 降级验收范围而非静默延期。

**机时账**：满额 3,600 次、并发 8 路约 50 h ≈ 2 天 ⇒ **机时不是瓶颈**。

### 7.5 矩阵重复轮次与噪声门（2026-08-09 owner 裁定，补 §6 步 6 未覆盖项）

§6 步 6 原文只写"跑三层矩阵"，**未规定每格重复几轮**，也未规定"差异多大才算真差异"。文献线撞出的实证使这条成为必补项：**同一配置重复 23 次，分数跨度达 18.9 个百分点**（`BenchmarkingBenchmarks`，2607.02577）。若只跑一轮就下结论，审稿人一问"你的差异在噪声范围内吗"即无法回答。

**裁定三条**：

| # | 规定 |
|---|---|
| 1 | **轮次保持 3 轮**（即满额 3,600 次不变）——机时不是瓶颈，但盲目加轮次挤占的是排期，收益不如把噪声如实报出来 |
| 2 | **每格必须报离散度**：结果表除均值外，须同时给出该格 3 轮的极差（max−min）或标准差，**不得只报均值** |
| 3 | **噪声门（下结论的硬前提）**：任何"A 优于 B"的论断，其**均值差必须大于两者离散度**；不满足则该对比只能如实写"未能区分"，**不得声称差异** |

其中：

- **离散度**：同一 (模型, harness, template 类型) 格内 3 轮得分的散布程度，用极差或标准差表示，衡量"同样条件下重跑能差多少"；
- **均值差**：两个被比较对象各自 3 轮均值之差，衡量"看起来差多少"；
- **判据含义**：看起来的差距必须大过重跑本身的抖动，否则那个差距可能只是运气。

> 第 3 条同时是对 §5 红线的补强——指标不可信与指标被噪声淹没，对论文的杀伤是同一量级。
