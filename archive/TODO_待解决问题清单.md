## 第 15 项（新增 2026-08-09）· checkpoint DAG 边集须从链式改为偏序【已裁定，待落地】

> **2026-08-09 Owner 已裁定**：见 `governance/adr/0021-checkpoint-DAG判定采用偏序语义.md`。
> 语义定为**偏序** —— DAG 的全部拓扑排序构成合法 trace 集合，判定取与实际 trace 最相近的那条合法 trace 比。
> 故 trajectory lock-in 批评在语义层面不成立。
> **但监工实测发现落地差距**：当前边集是一条链，拓扑排序数 = 1，事实上退化为唯一全序。
> 因此本项由「须裁定」转为「**待落地**」：需重定边集（删除无科学强依赖的边）。

**来源**：`reference/BenchmarkingBenchmarks/`（arXiv:2607.02577，2026-06-30）审计四大工具调用
benchmark，把 **trajectory lock-in**（评测锁定唯一正确路径、别的合理路径被判错）
列为**确定性 benchmark 的五类典型失效之一**。该文实测评分器与人工不一致率 18.5%（496 条中 92 处）。

**我们的暴露面**：`CP_DAG_EDGES` 强制 cp1(文献)→cp2(建池)→cp3(查证)→cp4(筛选)→cp5(排序)→cp6(答案)
**严格全序**，且 strict 模式下证据时刻相等也判不通过。

**问题**：化学上"先建候选池、再查文献确认方向"同样是合理工作流。
按现行判据这类轨迹会被判违规并卡 gate —— 我们可能在惩罚一种正确做法。

**已弃用的两个备选（保留记录）**：
- **方案A 承认为设计约束**：在文档与题面里明写"本 benchmark 规定唯一合法执行顺序"，
  agent 事先知道规则就不算冤枉。改动量为 0，但削弱"评测自然工作流"的说服力。
- **方案B 放宽为偏序**：只保留真正有科学依赖的边（如 cp3 必须早于 cp4，因为没查性质无法筛选），
  去掉 cp1→cp2 这类无强依赖的边。更贴合真实工作流，但需重定义边集并重跑判分。

**关联**：与不同点 2（顺序判定）直接相关，已写入 `research/我方与现有benchmark差异对照.md`，
若改判据则该节须同步修订。

**优先级**：**高** —— 涉及判分口径，须在矩阵全量结果定稿前完成，否则结果需重判。

## 第 17 项（新增 2026-08-09）· cp3 只有一个覆盖率，分不清两种失败

**来源**：读 PowerAgentBench-SS 正文（arXiv:2606.18789，`reference/PowerAgentBench/`）。
它把"有没有证据"拆成**三个召回率**，分子不同：

- 只看交了什么：$R_{sub} = |\hat{D} \cap O_m| / |O_m|$
- 交了**且**验证过才计分：$R_{evid} = |\hat{D} \cap V \cap O_m| / |O_m|$
- 只看找到没找到（即使没交）：$R_{found} = |V \cap O_m| / |O_m|$

其中 $O_m$ 是隐藏的 oracle top-m 集、$\hat{D}$ 是 agent 提交集、$V$ 是 agent 真的调工具验证过的集合。

**为何要拆**：这三个能分辨两种完全不同的失败 ——
① **找到了但没交**（$R_{found}$ 高而 $R_{sub}$ 低，说明是提交环节出问题）；
② **交了但没验**（$R_{sub}$ 高而 $R_{evid}$ 低，说明在编）。

**我们的现状**：cp3 只有一个"覆盖性检查"（该查的都查了就给分），**上面两种失败分不开**。

**待做**：考虑把 cp3 拆成两个分量（提交覆盖率 / 有证据支撑的覆盖率），或至少在结果报告里分开统计。

**优先级**：中。不阻塞矩阵，但影响结果的可解释性。

## 第 18 项（新增 2026-08-09）· 缺"漏报危险项"的加重惩罚与预算约束

**来源**：同上文献。它有两项我们完全没有的机制：

**一、false-safe 惩罚**。它定义
$FSR = |D \setminus (\hat{D} \cap V)| / \max\{1,|D|\}$，
以及严重度加权版 $SWFN = \sum_{C \in D \setminus (\hat{D} \cap V)} s(C) / \sum_{C \in D} s(C)$，
其中 $D$ 是隐藏的危险案例集、$s(C)$ 是隐藏的严重度。
**含义**：把危险的东西漏掉（或报了但没验证）要单独罚，而且越严重罚越重。

**对应到我们**：agent 声称"该候选满足所有约束"但实际不满足（假阳性），
与"漏掉一个本该入选的候选"（假阴性）——**我们的 cp4 目前同等处理**。
按此文献思路，前者应罚得更重。

**二、验证预算**。它设 B=80，agent 只能验证 1035 个案例中的 80 个，
因此能考出"预算怎么花"。**我们不限制工具调用次数，所以考不出预算意识**。

**待做**：①决定是否给 cp4 引入非对称惩罚；②决定是否引入工具调用预算
（注意：引入预算会改变任务性质，需 owner 裁定，且会使已跑的矩阵结果不可直接对比）。

**优先级**：低（属能力维度扩展，非缺陷修复）。但**若不做，应在文档中声明"本 benchmark 不考预算意识"**。

## 第 19 项（新增 2026-08-09）· ADR-0022 落地：开放结构可见性与反查接口

**来源**：Owner 裁定（见 `governance/adr/0022-开放结构可见性与结构反查接口.md`）。

**要解决的问题**：agent 做不了分子层面的外推推理。它查了 aab 和 abb 的性质，
想再查 aabb，但拿不到 aabb 的实体 ID，所以查不了。实测断在两处：`get_entity` 不给拓扑
（只给各标签个数），且没有"结构串 → ID"的反查入口。

**Owner 裁定两件事一起做**：`get_entity` 增返匿名域结构串（保留拓扑）；新增反查接口。

**四项工程改动**（详见 ADR §7）：

| # | 位置 | 改什么 |
|---|---|---|
| 1 | `tools_schema.json` | `get_entity` 出参增结构串字段；新增反查工具定义 |
| 2 | `gateway.py` | 复用 `_entity_smiles` 透传；建「规范化结构串 → 实体 ID」逆映射（同一次遍历，只多存一个字典）；反查计入预算 |
| 3 | `mock_server.py` | 注册新工具；暴露面断言基准 9 → 10 |
| 4 | `docs/AGENT_TOOLS.md` | 补第 10 个工具，更新 `get_entity` 出参 |

**三条约束须落成机器断言**：只做精确匹配不做相似检索；计入查证预算；只对可见侧生效、
答案侧一律返回"不在"。

**两项验证未做，做完前不得声称完成**：
1. 新链条端到端跑通一道现有题；
2. **泄漏面量化** —— 单题仅 28 个可见实体条件下，给出拓扑后反推真实分子有多容易。
   在此项完成前不得声称泄漏风险可控。

**优先级**：高（它决定 benchmark 能不能测化学推理，不只是流程守规）。

**注意**：判分不动。是否加"外推准确度"卡点须另行立项。新链条启用后的结果与既有矩阵结果
不可直接对比，因为 agent 可用能力变了。

## 第 20 项（新增 2026-08-09）· ADR-0024 §8 判分层三项落地

**来源**：Owner 裁定，见 `governance/adr/0024-工具集精简为SMILES原生5工具.md` §8。

**三项裁定**：

1. **checkpoint 两层结构**——模板定骨架（每个题型自己的卡点序列与判分表达式），
   每道 query 填槽位成为自己的 check 实例。`evaluate.py` 的 `CP_WEIGHTS`/`CP_THRESHOLDS`
   硬编码常量须改为从 template 读，代码不再持有固定六关表。
2. **删除 cp2**——理由是 agent 凭自身化学知识提候选属真知识不该罚；且三因子分别被
   cp4/cp5/cp6、cp6、以及 `get_property` 兜底覆盖。
3. **全面 SMILES 化**——`gt.id` → `gt.smiles`，`response` 三字段改 SMILES，
   判分两侧规范化后比对。

**落地清单**：`evaluate.py`、三个在用 template、`discovery_haystack` 补 template.json、
150 个 case 的 gt 迁移、response 契约。

**两项前置未做，做完前不得开工**：

- **各题型该留哪几关须先实测**，尤其 `discovery_haystack` 30 道题在六关下哪几关是摆设
  （cp2 就是这样被发现无效的）。无实测不得凭感觉裁关数。
- **`get_neighbors` 邻居定义与数据源未定**。它是删掉 `search_candidates` 后唯一的候选
  发现入口，不落地则 fixed 类题流程断裂。

**影响**：既有矩阵结果全部失效（关数、分母、标识体系三者皆变），须重跑且不与旧结果对比。
对外报分须按题型分开报，**不得报跨题型的全局平均分**（关数不同不可平均）。

**优先级**：高，但须等两项前置。
