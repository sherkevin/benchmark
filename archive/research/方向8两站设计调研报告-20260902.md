# 方向8两站设计调研报告：go/no-go 阈值、两站归因、难度与 generality

性质：调研报告（决策支持）。对应 governance/提案_20260901_制药科学预测冲突诊断与恢复Benchmark.md §6 方向8，以及 task/team提示词_八方向第二轮深推.md 方向8节的四个待深推问题。数据实测与文献核验截止 2026-09-02。

**一句话答案**：两站设计在 BBB 单点上即刻可做——阈值取 0.5（概率的规范决策边界，不是我们调的旋钮），题量 400 行（与现有冲突集逐行重合），判分五字段四格、机械可判；"站一选对但站二错"可能且只有一种形态（信对了工具没照做）；多数票基线 76.5% 连固定选 morgan 的 80.5% 都不及，题没有变简单；generality 句子已定稿且不构成未验证宣称。跨模态扩展继续冻结。

**速读区**

- 阈值 0.5 的三重依据：DeepPurpose 论文原文以 0.5 算二分类 F1；ADMET-AI 官方只输出概率，二值化只能按"取概率大的一类"做即 0.5；普查代码在真值关联之前就钉死 0.5。公开检索未找到任何切模型概率的药学或监管规则。
- 题量 400 行：730 行按 p≥0.5 二值化后，四工具不同侧的行恰 400，entity_id 与普查 400 行冲突集完全相同；真值偏斜 265:135；每行至少一个工具决策正确（12 行四工具全错全部在冲突集外）；1 行 = 0.25 个百分点。
- 参照线：恒答 66.3% ｜ 多数票 76.5% ｜ 固定选 morgan 80.5% ｜ 固定选 admet_ai 79.2% ｜ 理想选择器 100%。
- 难度分布：决策正确工具数为 1/2/3 的行分别是 56/82/262，逐工具甄别的难点集中在前 56 行。
- 证据来源：本地数据 730 行（screening_ledger.jsonl，脚本实测）＋ 文献核验（PubMed / PMC / arXiv 镜像 / 官方 GitHub，2026-09-02），详见附录。

## 读前必备的区分

- **数值差冲突与决策冲突**：本报告全部指决策冲突（不同工具的二值结论相反），与概率差大小无关——这是第一轮已定的锚（governance/讨论_20260901 §3.3）。
- **两个"阈值"分管两件事**：go/no-go 决策为什么是 BBB 的函数（药学文献管）；工具概率在哪一侧（模型的规范决策边界管）。混起来就会拿药学文献去切概率，是范畴错误。
- **站一真值口径的细化**：第一轮结论四写"真值取逐实例最优工具"，本报告细化为"决策正确的工具集合"。依据：262 行有 3 个工具决策全对，指定唯一"最优"必须回答"三个都对时哪个更对"，那是新旋钮；集合口径零旋钮。属细化，不推翻第一轮结论。
- **素材口径**：四工具 = ADMET-AI 1.4.0（下称 admet_ai，Chemprop 集成模型）与 DeepPurpose 的三个分子编码变体 cnn（SMILES 卷积）、morgan（Morgan 指纹）、mpnn（消息传递神经网络）。730 行分子来自 BBB_Martins 数据集（TDC 谱系，带二值实验真值），普查对每分子跑四工具、discovery/replay1/replay2 三轮，复测标签漂移全 0。
- **方向口径**：血脑屏障（BBB）通透为正即 go（CNS 候选须入脑），否则 no-go；恒答 66.3% 即恒答 go，撞上真值偏斜 265:135；票型 k = 判 BBB+ 的工具个数。

## 证据组一：阈值 0.5 的可辩护来源（问题一）

**0.5 的辩护分两层；换任何别的值都要求我们自己拍一个成本不对称，那才是旋钮。**

药学文献管不了概率切点。检索到的 CNS 候选标准全部作用在理化描述符上：CNS MPO 给六个理化参数（ClogP、ClogD、分子量、TPSA、氢键供体数、pKa）计 0-6 分，≥4 为高分（Wager 2016）；Pajouhesh & Lenz 总结的也是上市 CNS 药的理化特征区间（NeuroRx 2005）。公开检索未找到任何切模型概率的药学或监管规则（没查到，检索范围见附录）。引它们切概率，等于拿量分子量的尺子去量温度。

药学文献能管的只有：go/no-go 为什么看 BBB。CNS 候选须入脑——Wager 2016 摘要明说 CNS MPO 提升了被提名进临床开发的候选中"能穿越血脑屏障"者的占比；Pajouhesh & Lenz 2005 开篇即把 CNS 药物的理化特征与其 BBB 穿透能力绑定。这一层只回答"决策是 BBB 的函数"，不回答切点。

概率唯一无旋钮的切法是它自己的规范决策边界 p≥0.5（二分类模型的标准用法：取概率大的一类）。任何别的切点等于断言两类错误的代价不对称，而这份不对称没有文献依据。三重佐证，说明 0.5 不是本项目发明的：

1. DeepPurpose 论文原文：二分类评测用"F1 score at threshold 0.5"（Huang 2021）。
2. ADMET-AI v1.4.0 官方代码的预测函数无阈值化步骤，网页模板自述"预测值是该分子具有该性质的概率"（Swanson 2024，已核验代码与模板）。它不输出二值判定，二值化只能由使用方做，按"取概率大的一类"即 0.5。其论文与代码均无明示默认阈值（没查到），不冒引。
3. 普查代码 THRESHOLD = 0.5 在真值关联之前就钉死：冲突集先封存、真值后关联（ledger 的 joined_after_initial_conflict_set_sha256 字段，即真值在冲突集封存之后才关联的防调参标记），0.5 无从按结果调（src/probe_headless/tool_conflict_census.py）。

**实测实例数：400 行。** 730 行按 p≥0.5 二值化（2920 条 label 与 raw_probability≥0.5 全部一致，0 违例），四工具不同侧的行恰 400，entity_id 集合与普查 400 行冲突集完全相等。题量上限就是现有冲突集，零新增数据。

## 证据组二：两站归因的判分器输出格式（问题二）

**五字段、四格；站一对站二错可能且只有一种形态；退化条件是判分器替 agent 做概率到决策的换算，设计上排除。**

逐行五字段：

| 字段 | 含义 | 谁来算 |
|---|---|---|
| tool_choice | agent 选择信任的工具 | agent 输出 |
| decision | agent 给出的 go/no-go | agent 输出 |
| ok_tools | 决策与真值一致的工具集合，即站一真值 | 判分器按真值机械计算 |
| s1 | tool_choice 是否属于 ok_tools | 判分器 |
| s2 | decision 是否等于真值决策 | 判分器 |

归因四格：

| 站一 | 站二 | 判读 |
|---|---|---|
| 对 | 对 | 完整通过 |
| 错 | 对 | 仅站一错：选错工具但决策反而对，agent 推翻了所选工具的指向 |
| 对 | 错 | 仅站二错：选对工具却给出相反决策，信对了人没照钉死规则做 |
| 错 | 错 | 连贯错 |

"站一选对但站二仍错"可能吗？可能，且只有一种形态：agent 选了 ok_tools 里的工具，最终决策却与该工具按钉死阈值的机械推算相反——要么没把概率按 0.5 换算对，要么自己推翻了所选证据。这不是退化，恰是站二的独立信号：测"信对了人有没有照做"。

为什么只有一种形态：决策冲突行上，进 ok_tools 的工具按 0.5 的机械推算必等于真值——决策对是入集合的定义——所以"选对却决策错"只能来自 agent 自己没照推算执行。

**退化条件与排除。** 若判分器自己从所选工具的概率机械推出决策再比对，站二就只是站一的函数，两站塌成一站。因此 decision 必须由 agent 亲口输出，判分器不做任何代劳。

**agent 题面（输入侧）。** 每行独立施测。题面 = 分子（SMILES）＋四个工具名与其 BBB 通透原始概率＋钉死的决策规则句（p≥0.5 判 BBB+，BBB+ 即 go）；agent 只交 tool_choice 与 decision 两个字段。概率取普查 discovery 轮的 raw_probability（复测漂移 0）。题面必须给原始概率而不是二值结论——只给结论的话站二无事可做，这是两站不退化在输入侧的条件。

三个设计要点：

- 站一真值取集合（见"读前必备的区分"第三条）。400 行每行 ok_tools 非空，实测 0 例外，口径每行良定义。
- 阈值钉在题面属任务语义，不属拐杖：它不告诉 agent 信谁、何时用哪个检查器，只规定决策怎么判，与第一轮结论六的拐杖/工具分界一致（分界：被告知何时用的是拐杖，只给工具、不写使用说明的才是合规工具）。
- 归因信号分层汇总：仅站一错、仅站二错、连贯错分开报，后续修复干预各找各的靶。

## 证据组三：决策锚是否让题变简单（问题三）

**风险真实，但三道实测把它压住：多数票基线 76.5%，不及固定选 morgan 的 80.5%，距理想 100% 还有 23.5 个点——题没有变简单。**

反向风险的逻辑是：筛掉的行四工具同侧，留下的全跨阈值，直觉上"分歧显著=好判断"。三道反证：

1. 同侧行不是难题，是无信息行。四工具同侧时选谁都得出同一决策，站一无判别内容；筛掉它们筛的是任务相关性，不是难度。
2. 最尖锐的分歧恰由自信的错误工具制造。cnn 高置信 247 行错 153（置信是反指标，普查已实测）；3:1 票型 247 行中 223 行的少数派正是 cnn——分歧越扎眼，越可能是它挖的坑。
3. 数量验证。多数票（82 行四工具 2:2 平票判 BBB+）总体 306/400 = 76.5%；平票改判 BBB− 则 300/400 = 75.0%；非平票部分 262/318 = 82.4%。两个口径都不及 morgan 的 80.5%。"看着分歧猜多数"这个最省事的策略亏二十多个点。

难度分布：决策正确工具数为 1/2/3 的行是 56/82/262。3 个工具都对的行随便选也对（随机选工具的期望通过率 (56×1+82×2+262×3)/1600 = 62.9%，由分布直算），真正要逐工具甄别的行集中在前 56 行。

类别偏斜 265:135 的后果由恒答参照线显性化：全答 go 即 66.3%，判别力一律看超出参照线的部分；如需按真值侧（go/no-go）分层汇总，数据在同一 ledger，需要时从同一脚本直出（本轮未做分层统计）。

透明度义务：五条参照线（恒答 66.3 / 多数票 76.5 / morgan 80.5 / admet_ai 79.2 / 理想 100）全部预注册进报告（先于 agent 开跑固定）；题变没变简单，读者直接读得出来，不藏。

## 证据组四：generality 声明的确切措辞（问题四）

**只声明判分器的代码结构性质、显式否认跨模态实证效果、句中无未跑的数——三关都过。**

确切句子（放论文讨论章节）：

> 本文判分器不含任何 BBB 特异分支：其全部输入仅为各工具原始输出、逐实例实验真值与预先固定的二值决策规则，替换真值表与工具清单即可在同构数据上原样运行；本文不对其他模态上的实证判别力作任何宣称。

句中"同构数据"指同结构的数据表：多工具逐行输出、逐行实验真值、二值决策规则三件齐备。

为什么不构成未验证宣称：

1. 唯一的事实断言是"判分器代码里没有模态特异分支"。这是结构性质，可机械验证：落一条测试断言，让判分器在合成非 BBB 夹具（假工具输出 × 假真值 × 假决策规则）上原样运行通过即证。
2. "不对其他模态作宣称"是显式否认——声明的是没做什么，不是能做什么。
3. 句中没有任何未跑出来的数字。

配套义务：这条断言按项目纪律落成机器断言（裁定类约束必须机器可判），随判分器实现一并交付。断言形式示例：构造一份与 BBB 无关的合成夹具（三个假工具、若干行假概率与假真值、一个假决策规则），断言判分器照常输出五字段且四格与手工预期一致——夹具运行通过即证判分器无模态特异分支。

## 反面证据（主动找过推翻结论的材料）

- 找过"决策锚让题变简单"的证据：多数票 76.5% < morgan 80.5%，没找到变简单的迹象（证据组三）。
- 找过替代阈值来源：CNS MPO、Lipinski-CNS、Pajouhesh & Lenz 规则全部作用在理化描述符上，无一能切模型概率——替代来源不存在，0.5 的地位反而更稳。
- 找过 0.5 的反例：ADMET-AI 官方不输出二值判定（v1.4.0 代码无阈值化步骤）；若官方日后发布默认阈值，应以官方为准重新核对本设计。
- 找过两站退化路径：判分器代劳概率到决策的换算即退化（证据组二），设计上已排除。

## 没查到的 / 仍开放的问题

- ADMET-AI 的公开默认阈值：论文与 v1.4.0 代码均无明示（已核验，2026-09-02）。
- Martins 2012 原文的 logBB 切点：正文付费墙、摘要无数值。与本案无关（本地真值文件 dag_poc/data/sources/TDC_ADMET/bbb_martins.tsv 是纯二值 Y 列），仅记录核验失败，避免后人重复踩墙。
- agent 实测通过率：本报告全部数字是真值数据上的机械基线，agent 未开跑——两站四格的实测分布待回填，属下一步工作。
- 2:2 平票 82 行对判分器无影响（agent 不投票），只影响多数票基线的报告口径；两种口径（判 BBB+ 76.5%、判 BBB− 75.0%）都已给出。

## 对我们的直接影响

1. 题库零成本成立：400 行冲突集直接入题，不新增任何数据；1 行 = 0.25 个百分点，对照"80 行测试集只能检出 8 个点"的工程测算（task/team提示词_八方向第二轮深推.md 共同背景），粒度足够。

3. 预注册参照线五条：恒答 66.3 / 多数票 76.5 / morgan 80.5 / admet_ai 79.2 / 理想 100。
4. 论文讨论章节句子定稿：证据组四原文，不再动。
5. 跨模态继续冻结：与 2026-08-28"收敛到制药"裁定一致，本方向交付止于 BBB 单点的两站设计与判分规范。
