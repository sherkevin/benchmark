# Agent 能力 × 数据库匹配（能力清单的数据底座，2026-08-26）

> **为什么有这份文档**：owner 2026-08-26 指示——"我们要测的能力必须要跟数据库做对应，
> 去查看数据库的内容，做相应的匹配，去写这些 Agent 的能力，而不是瞎写。"
>
> **owner 同日定的三条原则（本文的框架）**：
> 1. **能力拆分与改造**：能力太大就拆细，但**不直接删掉**；对数据库不合适的，
>    **根据数据库改造成合适的原子能力**。不丢掉现有的测试能力，而是在它上面做改动。
> 2. **最终目标**：把这些原子能力最终**串成一串**（第一步做什么、第二步做什么），
>    整体当成一个大的能力去测。
> 3. **当前阶段**：现在做的是前置工作——**原子能力测试**；后续把它变成"查目标"的测试，
>    **长目标 = 包含若干个小目标的列表**。
>
> **"数据库"的定义（owner 原话）**：后端连接的 KB 查询被 mock 成的库。预测蛋白质结构、
> 预测分子性质时调的工具会输出性质，这些 mock 掉的查询结果就是数据库。
> mock 的理由：不实时查询、先把数据查好放进去，降低时延——公开 benchmark 都这么做。
>
> 本文所有数字都是**实跑后端得出**（`BENCH_SPEC.md §3` 闸2 纪律），复跑命令见 §7。

## §3 原子如何串成链（最终目标形态）

owner 定的最终目标：**长目标 = 若干个小目标的列表**，测整条链。
每个原子的输出是下一个原子的输入；acquire 工具（查实体/查性质/查文献…）是链的关节。
示例（材料发现链）：

```
定方向：D-Constraint（约束→候选空间）
  → 查性质（acquire: get_property / crystal_predict）
  → B-Trend（归纳系列规律） → C-Extrap（外推到未测成分）
  → A-Conflict（两条记录打架，裁决） → A-Anomaly（认出伪影）
  → D-Avoid（性质信号→该改哪） → F-Gen（生成新实体）
  → 验证（acquire: crystal_predict mock 回值） → E-Select（下一步测哪个）
```

当前阶段只测**单个节点**（原子能力题，一道题一个原子）；链式阶段测**整条**。
⇒ 现在造每道原子题时，**题面与判分器就要写清"这个原子的输入是什么、输出是什么"**，
否则将来串不起来（输出类型对不上输入类型的原子是断链）。

## §4 阶段定位（owner 2026-08-26 定）

| 阶段 | 测什么 | 产物形态 |
|---|---|---|
| **当前（前置）** | **原子能力**：单个判断类型，一次一问 | 一道题测一个原子，只判最终 output（`BENCH_SPEC.md` §8） |
| 后续 | **查目标**：长目标 = 若干小目标的列表，agent 自己排序、逐步完成 | 链式题，判每步落点 + 终态 |

两阶段的衔接件就是 §3 的输入/输出类型表。

## §5 三个硬约束（造题时绕不开的）

1. **多性质联合薄**：≥2 个 ADMET 性质的分子只有 661 个。多约束题要么池子 ≤661、要么 mock。
2. **文献库是"死"的**：2,655 篇、25 个固定 query、无实体链接、无摘要。支撑"按主题粗筛文献"，
   **不支撑**实体级文献共现推理（#27 在静态库里做不了，须 mock）。
3. **`condition` 字段名存实亡**：17,252 条里 17,214 条"未知"。#7 在静态库里确认做不了。

## §6 数据底座 ↔ 可背性的根本张力（必须带着走的事实）

> **静态库里"有实测值"的分子/材料，几乎都是被研究透的 ⇒ 模型背得住**
> （实测：尼泊金酯裸问误差 0.11；`Ba-Ca-Cu-F-O` 裸答 20/21）。
> **mock 注入可以防背，但注入的规律必须有独立文献/物理依据**（NobelClaw 模式），
> 否则测的是"读懂造题人"。
>
> ⇒ 每个原子的题，造之前先回答：**真值从静态库来（过闸5 防背），还是从 mock 来
> （过"规律有据"审）**。这一问在 `BENCH_SPEC.md` 闸2 之后必答。
