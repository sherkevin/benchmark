## 二、被完全推翻的那一条（最重要）

### BPOP [A] 已经把我们的核心数学做完了，而且做得更深

**原文**：De-Linearizing Agent Traces: Bayesian Inference of Latent Partial Orders for Efficient Execution（arXiv:2602.02806，2026-02-02，v3 2026-05-24）

| 我在 ADR-0021 里写的 | BPOP 已有的 |
|---|---|
| DAG 的拓扑排序集合 = 合法 trace 集合 | `models traces as stochastic linear extensions of an underlying graph`（**linear extension 就是拓扑排序的标准数学术语**） |
| 判定取实际轨迹与最近合法轨迹的距离 | 用 **MCMC** 从噪声轨迹中**推断**潜在偏序，而非预设 |
| —— | **明确指出枚举线性扩展是 #P-hard**，并用 frontier-softmax likelihood 规避 |
| —— | 在 Cloud-IaC-6 与 WFCommons 科学工作流上实测，**优于 process-mining 基线** |

**它比我们做得多的地方**：我们**预先给定** DAG 再判轨迹；它**从轨迹反推** DAG。反推是更难的问题。

### 附带暴露我方一处技术错误

我在 ADR-0021 与对比文档里写的判据：

$$\mathrm{violation}(\hat{\pi}) = \min_{\pi \in \mathcal{T}(G)} d(\hat{\pi}, \pi)$$

**这个式子在一般情况下不可计算** —— BPOP 明确指出**枚举/边缘化线性扩展是 #P-hard**。

- 我们 6 个卡点时 $|\mathrm{Perm}(V)| = 720$，穷举勉强可行（实测已跑过）；
- 但**卡点一旦增多就爆炸**，且我把它写成了一般性判据，未标注复杂度前提。

**正确的写法**是判 $\hat\pi \in \mathcal{T}(G)$ 是否成立（对每条边逐条检查，$O(|E|)$），**而不是求最小距离**。有意思的是：**我们代码里的实现本来就是逐边检查**（`all(evidence_time(u) < evidence_time(v) for u,v in edges)`），**是我在文档里把它"升级"成了一个不可计算的公式**。文档比代码错得更厉害。

### 而且"检查轨迹是否符合流程模型"是个成熟领域

| 工作 | 做的事 |
|---|---|
| **LLM-Orchestrated Conformance Checking** [B]（2026-06） | 从临床文本抽患者轨迹 → 从指南文本抽规范规则 → **翻译成可执行脚本** → 算 **Trace Conformance Indicator**。用 50 条规则测数百条轨迹，86% 符合 |
| **Detecting Undesired Process Behavior** [C]（BPM Forum 2025） | 用 RAG 替代流程模型来检测不良流程行为 |
| **Skill Learning Using Process Mining** [D]（ICPM 2024） | 用 **conformance checking 做技能检索**，并明确支持**并行执行** |
| **EnvTrace** [E]（2025-11） | **execution trace alignment** 评 LLM 代码语义等价，用数字孪生做同步辐射光束线控制 |

**[B] 与我们的流程几乎同构**：抽轨迹 → 定规则 → 落成可执行判定 → 算符合度指标。它在医疗，我们在化学。

**我为什么此前没搜到**：我搜的是 `DAG`、`topological`、`checkpoint`，而这个领域的词汇是 **conformance checking / linear extension / process mining / event log / trace alignment**。**这正是 Owner 指出的确认偏差 —— 用自己的术语搜，只会找到自己的同类。**

## 三、被降级的三条

### 第 5 条（答案不可检索）：主张早有

**Search-Time Contamination** [F]（arXiv:2606.05241，2026-06）定义了三级污染，其中最严重一级就叫 **Explicit Answer Leakage（显式答案泄漏）**，并**明确倡导 isolated sandboxes（隔离沙箱）**。

- 它做的是**测量**污染（实测虚高最多 4%）；
- 我们做的是**构建**一个答案不可达的库。

**准确表述**：不是我们发现了"答案要隔离"，而是**我们把已有主张实现成了一套具体机制**。

### 第 6 条（抗污染匿名化）：已有五条路径，我们是第五条

| 路径 | 代表 |
|---|---|
| 活网合成 + 定期更新 | EvoBrowseComp |
| 答案未公开 | URSA |
| 构造性无固定题 | MetanymGame |
| 语义变体现场生成 | GSM-SEM · **AgentAbstain [G]（AbstainGen 自动合成沙箱，可按需重生成新实例）** |
| **标识符匿名化** | **我们** |

另有一条与我们思路相通的：**MatVQA** [H]（2025-05）用**迭代过程消除"文本捷径"**，逼模型必须做细粒度视觉分析。**我们的匿名化在做同一件事**——消除"靠记忆答对"这条捷径，逼 agent 必须查库。它在视觉，我们在化学标识符。

### 第 7 条（真值从工具记录反查）：这是 conformance checking 的标准输入

比对**事件日志**（event log）而非自报结果，是 process mining 的立身之本。加上 PowerAgentBench 的 `evidence-backed recall`、FEV 的 workflow correctness 主张，这条**没有新意**。

## 四、修正后还站得住的是什么

删掉自我否决的两条、承认被推翻的一条、降级三条之后，**剩下的诚实表述只有两点**：

### 站得住的第 1 点：把成熟机制搬到一个没人搬过的组合上

**不是任何单一机制新，而是这个特定组合此前无人实现**：

> 化学/材料发现任务 × 闭合匿名库 × 过程符合性检查（全硬判定）× 答案物理隔离

**逐项都有先例，组合无先例**。这是"应用型贡献"，不是"方法型贡献"。**必须这样定位，否则任何一位懂 BPM 或懂污染检测的评审都会指出前人工作。**

### 站得住的第 2 点：一个具体的领域适配问题

化学发现任务的**依赖结构与判据**此前没有被形式化过：哪些卡点有科学强依赖（未查性质无法筛选）、哪些无（文献检索与候选建池）、性质约束如何转成可执行断言。**这部分工作量真实存在，且必须由懂化学的人做**（对应 Owner 已定的"case 必须工程师手写"）。

## 六、方法论教训（写给后续调研）

1. **只用自己的术语搜索 = 只能找到自己的同类。** 必须主动猜"别人会怎么叫这件事"，尤其要跨到相邻学科（本次：BPM / process mining / 统计推断）。
2. **"我们不做 X"不是差异点。** 少做一件事是范围选择，不是能力。
3. **文档不可比代码"更漂亮"。** 我把逐边检查写成了最小距离公式，看起来更学术，实际不可计算。**形式化不等于更严谨，可能只是更容易错。**
4. **声称"首个"前，先假设它已被做过并去证伪。** 本轮三次反向搜索就推翻了一条核心主张；若不做，这条会一直留到投稿被拒。
