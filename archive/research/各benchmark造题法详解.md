## ★ 本文精华：把 8 家的可复用件拼成我们自己的造题产线（先看这个）

**一句话：好 benchmark 的题不是“先编题再找答案”，而是“先锁死一个可验证的真值 → 反向把题面拼出来 → 专门花力气砍掉能走捷径/靠背诵的题 → 逐步判过程”。** 把 8 家的可复用件拼起来，就是下面这条 6 步产线（全程用同一个真例子走：**“为某中枢神经系统(CNS)适应症找一个候选分子”**）。

| 步 | 产线环节 | 学谁的什么 | 我方是否已有 |
|---|---|---|---|
| 1 | 反查真值 | SWE-bench、InfoMosaic | ✅ GT-first 已锁定 |
| 2 | 反事实改写防污染 | NewtonBench | 🟡 现只有匿名化，需补受控反事实 |
| 3 | 组织成题 + 埋线索 | InfoMosaic Stage 1 | 🟡 fixed 已有，open 埋线索待做 |
| 4 | 专门砍捷径 | InfoMosaic Stage 2 + ScienceAgentBench | ⬜ 捷径闸未建 |
| 5 | 逐 checkpoint 判过程 | **无人做†（我方全部价值）** | 🟡 已跑通，但 cp4 指标冲突 + cp5 空集给满分两处待修 |
| 6 | 判分口径 | ColorBench + SWE-bench + MLE-bench | 🟡 条件通过率/无回归待补 |

† **“无人做”的准确含义**：已有部分分（ColorBench 的 CR、InfoMosaic 的子条件通过率、ScienceAgentBench 的 rubric）与过程奖励（RLVMR 的元推理标签），但**无一是“对 agent 产出的中间科学结论做数值真值比对、且全程可执行不含 LLM judge”**。这才是我方的空白位。

### 步 1 · 反查真值（答案先于题目）——学 SWE-bench / InfoMosaic

- **学到的**：真值不能是人拍脑袋写的，要是“已存在、可执行”的东西——SWE-bench 用仓库自带的测试，InfoMosaic 用工具查证过的证据。这是它们能自动化、不用人标真值、规模化到 10³ 的根因。
- **我方怎么做**：先从科学数据库选定一个已知优秀的分子（gold root，如某 CNS 候选药），用性质接口**反查**出它的 ADMET 性质（能进大脑=BBB 透过高、心脏安全=hERG 阴性、口服吸收好=Caco-2 高）——这些反查值就是后续全部判分的真值。答案（这个分子）先于题目存在，可复核。
- **卡点**：真值只认接口返回值（ACTION_RULES §6），不信 LLM 自报；真值底座落在 `reference/NobelClaw/` 证据文档 + mock 数据库。

### 步 2 · 反事实改写防污染——学 NewtonBench

- **学到的**：NewtonBench 把真定律在表达式树上“突变”成平行宇宙定律，再用一个内嵌常量补偿量纲——让 agent 背不到，只能真推。
- **我方怎么做**：光抹分子名不够（LLM 可能背过 metoprolol），做两层：① **分子匿名化**（mock 数据库抹名，题面只给数值约束）；② **受控反事实**——在 mock 库里构造“平行宇宙”分子（真实性质分布、但不是训练分布内的具体名分子），或把某些性质窗口系统性平移，并像 NewtonBench 那样保留一个“补偿自由度”保证自洽。
- **卡点**：只对“相对比较型”约束平移（“logD 在窗口内”可平移）；物理常量型（如“Tc 高于 77K 液氮温”）不平移，逐性质白名单。

### 步 3 · 组织成题 + 埋线索——学 InfoMosaic Stage 1

- **学到的**：“总指挥定约束 + 工人查证据 + 整合成一道多源题”的双 agent 流水线。
- **我方怎么做**：把步 1 反查的性质拼成一道“为 CNS 适应症找满足 P1/P2/P3 的分子”，隐去答案与具体数值。两类分岔：**fixed 类**把约束直接写在题面；**open 类**把这几条线索打散**埋进一篇长上下文**（合成的研究报告/筛选日志）让 agent 大海捞针。
- **走例**（CNS）：open 类把“BBB 透过高”“hERG 阴性”“Caco-2 吸收好”分散埋进 3 篇不同文档，同一分子用不同别名指代，逼 agent 做共指消解才能把线索串起来。

### 步 4 · 专门砍捷径——学 InfoMosaic Stage 2 fuzzing + ScienceAgentBench 删点/重切

- **学到的**：一道题如果“一搜就中”或“背一下就对”，就不是长程题。InfoMosaic 用 fuzzing 把太露的条件改写；ScienceAgentBench 用删测试点/重切/dummy 标签防背诵。
- **我方怎么做**：① **捷径闸**（“闸”= 自动跑一遍就淘汰退化题的过滤器）——用“单次全表查询 + 排序”的 trivial baseline 跑全题集，被它解掉的题淘汰或升难；② **条件模糊化**——若某约束“一查就锁定分子”（如某极罕见性质值），改写或与别的约束合并；③ **唯一性闸**——加完干扰项后自动验证“不产生第二个正确答案”。
- **卡点**：捷径闸与唯一性闸必须自动化跑，否则题集会慢慢混进退化题。

### 步 5 · 逐 checkpoint 判过程（我方独有，全部价值所在）

- **学到的**：**已有部分分与过程奖励，但没人做“内容级硬判”**——ColorBench 的 CR 判“到没到某屏幕”（位置非内容）、InfoMosaic 报子条件通过率（判最终答案而非轨迹中间结论）、ScienceAgentBench 的 rubric 掺 GPT-4o judge、NewtonBench 靠 LLM 事后标注意图。**没有一家做到“中间产物 vs 数值真值、全可执行”。**
- **我方怎么做**：把解题必经的中间产物做成 checkpoint DAG：cp1 目标确认 → cp2 候选池 → cp3 性质查证 → cp4 筛选 → cp5 排序 → cp6 提交；每个 cp 一个可执行 `reward∈[0,1]`，判的是“agent 产出的中间科学结论 vs 数据库真值”，不是判它用没用某个工具。open 类：把步 3 的每条线索做成一个“证据 checkpoint”，判 agent 是否真找到并用对。
- **卡点**：查产物不认动作（等价路径不罚）；编造产物被“工具落地检查”抓出（声称的值必须有真实工具调用支撑）。

### 步 6 · 判分口径：条件通过率 + 无回归 + 人类分布标尺——学 ColorBench / SWE-bench / MLE-bench

- **学到的**：ColorBench 的 AC 条件化分母、SWE-bench 的 PASS_TO_PASS 无回归、MLE-bench 的人类排行榜分位。
- **我方怎么做**：① 每个 cp 报**条件通过率** `P(cp_i✓ | 前置全✓)`，级联失败不污染诊断；② 加 **`no_regression` cp**：后续步骤不许覆盖前面已确认对的性质值；③ open/无唯一解题用“击败数据库中 x% 已知分子”当标尺。
- **一级指标**：Horizon Length `H_s`——能以概率 s 无错走完多少个 cp（默认 s=0.5，学 ICLR 2026《The Illusion of Diminishing Returns》）。直觉：`H_s = ln s / ln p`，单步准确率 p=0.9 时 H≈6.6 步，p=0.99 时≈69 步——**单步的小改善会带来长程的大跃升**，这就是为什么必须按步测而不是只看终答。

> **一句话拿走**：步 1–4 + 步 6 都是把别人的可复用件拼起来；**真正没人做、也是我们全部价值的是步 5**——把“证据/条件/中间产物”从“生成题面用”升级为“逐条可执行硬判分的 checkpoint”（准确限定见文首表格脚注 †）。

## 0. 造题法一览（先总）

18 篇里真正有"造题产线"的分两类。**Tier A（8 篇，有完整可复现的造题流水线，本文重点展开）**；**Tier B（其余，造的是环境/训练信号而非静态题，简述）**。

| 造题法家族 | 代表 | 一句话产线 | 我们能不能用 |
|---|---|---|---|
| **反查真值合成**（答案先于题目） | InfoMosaic、SWE-bench、NewtonBench | 先拿到可验证真值 → 反向拼出题面 → 砍掉捷径 | ✅ **这就是我们的 GT-first 路线** |
| **从论文/竞赛 harvest** | ScienceAgentBench、MLE-bench | 挑开源论文/Kaggle 竞赛 → 补判据 → 防污染重切 | ✅ 药物/材料线可照搬 |
| **真机录轨迹建图** | ColorBench | 真机跑任务录屏 → 合成状态图 → 标里程碑 | ⚠️ 我方无 GUI，思想可借（状态图） |
| **人类标注员造题** | GAIA | 人基于可信来源编题 + 记录步数/工具 | ⚠️ 成本高，仅难度分层可借 |
| **反事实改写** | NewtonBench | 真定律 → 系统性突变成“平行宇宙定律” | ✅ **防污染的关键手法** |
| **真实软件初态 + 手写判分脚本** | Toolathlon | 真实软件导出初始状态 → 每题一个确定性评测脚本 | ✅ 对应我方 mock 快照 + `reward` 表达式 |

**一句话总规律**：好 benchmark 的题**不是"先编题再找答案"，而是"先锁死一个可验证的真值，再反向把题面拼出来，最后专门花力气砍掉能走捷径/靠背诵的题"**。三步里第三步（防捷径/防污染）最费功夫，也最决定质量。

## 1. 【我们自己】一条真实的 CNS 题，从题面走到得分

> 先看我们自己的题；下面第 2 章的 8 家（Toolathlon / NewtonBench / SWE-bench / InfoMosaic / ScienceAgentBench / ColorBench / GAIA / MLE-bench）是对照组，本节末尾 ⑥ 给出逐项对比。

> **本节结论（先看这三句）**：
> 1. 过程分真的能**区分“同样答对”的三个模型**（glm 花 40 次工具调用且漏查了格子，kimi 只用 9 次全查到）——这是下面 8 家都给不出的。
> 2. 但**三个模型的最终得分都是 0.30**（不是 0.85/0.87）——因为 cp4 未过阈导致门控不过，而 cp4 未过阈是**指标设计冲突**造成的。
> 3. 当前有**三处判分口径待修**（cp4 指标冲突 / cp5 空集给满分 / 伪命中嫌疑），修前不能当最终数据用。
>
> 材料出处：`dag_poc/templates/fixed_discovery/{template,case_cns_metoprolol}.json`（规格）、`src/benchmark/evaluate.py`（**当前实现**，与规格有出入，已逐条标注）、`dag_poc/data/mock_db.json`、`dag_poc/traces/_all_results.json`、`TODO.md` T-21/T-37。

#### ① agent 看到的题面（`case_cns_metoprolol.json` 的 `query` 原文）

> 为中枢神经系统寻找一个候选：需要一个能进入大脑、对心脏安全、口服吸收良好的药物。你可以用检索工具查文献与候选库、用性质查询接口查证性质。最终输出你认为最优的答案。

**题面里没有任何数字**——三句大白话背后是三条机器可判的硬约束（agent 看不到）：

| 大白话要求 | 内部硬约束 | 真值 |
|---|---|---|
| 能进入大脑 | `bbb == 1`（血脑屏障透过） | 1 |
| 对心脏安全 | `herg == 0`（不阻断 hERG 钾通道） | 0 |
| 口服吸收良好 | `caco2 > -5.0`（Caco-2 渗透率） | −4.35 |

**排优目标** `target_metric = -{caco2}`。caco2 是对数渗透率，**负得越少（越接近 0）吸收越好**，所以 −4.35 优于 −4.85；前面那个负号只是“改成降序”的开关（模板默认升序取最小）。

#### ② 答案与防背诵（GT-first 反查 + 匿名化）

- 真实答案是 **Metoprolol（美托洛尔）**，在题目世界里只叫 **`aa`**。真名仅存 `mock_db._mapping_scoring_only`（**只有评分侧可见**）。
- 候选宇宙 = mock 库 **20 个匿名分子**（ID 为 `aa`–`ah`、`ba`–`bh`、`ca`–`cd`）。
- 性质真值血缘钉在 `reference/NobelClaw/证据_admet_gt.md`（真实数据库反查值，可复核）。
- 穷举 20 个分子，同时满足三条约束的**合格集 |G| = 1**（只有 `aa`）——这个事实是下面多个问题的根源。

#### ③ 6 个 checkpoint 具体各判什么

这是本文最关键的一张表。**注意区分两列口径**：模板规格（`template.json`）与当前实现（`evaluate.py`，产出下面 ④ 那张表的分数）在 cp5/cp6 上并不一致。

| cp | 判什么（大白话） | 拿什么和什么比 | 权重 | 过线 |
|---|---|---|---|---|
| **cp1** 文献检索 | 有没有真去查文献 | `min(1, 检索次数/2) × min(1, 不重复 DOI 数/3)`（两项**相乘**，不是门槛）。**不信 agent 自报 DOI** | 1 | 0.6 |
| **cp2** 候选建池 | 交的候选是不是真查到的 | 交的 ID 必须在它**实际调工具拿到的 ID 集**里（grounded）且包含 `gt.id`。⚠️ 规格说的是“从入参提取的 ID”（问过），实现取的是返回结果（查到）——口径待统一 | 2 | 1.0 |
| **cp3** 性质查证覆盖 | 该查的格子查没查满 | 候选×约束性质的**格子覆盖率** | 2 | 0.8 |
| **cp4** 筛选正确性 | 判没判对谁合格 | 用**工具真实返回值**重算合格集 G，与 agent 交的集合 P 算 **F1 = 2·\|P∩G\| / (\|P\|+\|G\|)** | 2 | 1.0 |
| **cp5** 排序正确性 | 优劣排序对不对 | 实现：**集合相等就给 1.0**（不看顺序），不等才逐位比。⚠️ **空集==空集也给 1.0 → 已知 bug** | 1 | 1.0 |
| **cp6** 最终推荐 | 答案对不对 | 命中 `gt.id` → 1.0；否则在合格集内 → **实现给常数 0.5**（规格写的是按距离衰减，尚未实现）；不在 → 0 | 2 | 1.0 |

**一个完整 reward 表达式长什么样**（cp3 规格原文）：

```python
sum(int(p in {tools.predict_admet.out.results[c]}
        and {tools.predict_admet.out.results[c][p]} is not None)
    for c in {response.candidate_result.ranked_candidates}
    for p in case_props({gt.properties}))
/ max(1, len({response.candidate_result.ranked_candidates}) * len(case_props({gt.properties})))
```

**用人话翻译**：把候选当行、约束性质当列画一张表，得分 = **填了几格 ÷ 该填几格**。本 case 实测：kimi 交 5 个候选×3 条性质 = 15 格全填 → 1.0；glm 交 6 个×3 = 18 格填了 17 格 → 0.94。

**汇总打分**（`template.json` 的 `scoring`）：过程分 = 权重平均；`gate` = **所有** cp 均过阈；
`task_score = gate ? 0.5×process + 0.5 : min(0.3, 0.5×process)`——**门控未过封顶 0.3**（注：条件是门控，不是“答错”）。

**两个读数**：
1. **过程分真的把模型差异摸出来了**——三个模型都答对了（cp6=1.0），但 glm 花 40 次工具调用、cp3 还漏了一格（0.94）；kimi 只用 9 次就全查到。这种“同样答对、过程质量不同”的分辨，下面 8 家里只有 ColorBench 的 CR/AC 能做到一半（但它判的是屏幕位置，不是科学内容）。
2. **但三个模型的最终得分都是 0.300**。cp4 卡在 0.29/0.33 远低于过线 1.0 → gate 不过 → `task_score = min(0.3, 0.5×0.867) = 0.300`。别把 0.85/0.87 当成绩看。

#### ⑤ 实跑暴露的五个问题（2026-08-01 已全部修复，不粉饰）

**问题 1：cp4 指标设计冲突 → 已修（拆字段）。**
`ranked_candidates` 这**一个字段被两个 cp 当成不同东西用**：cp2/cp3 把它当“候选池”（交得多才显得查得全），cp4 把它当“合格集”（交得多就被 F1 罚）。因 |G|=1，F1 = 2/(k+1)（k=提交数）：实测 kimi/qwen 交 5 个→0.33，glm 交 6 个→0.29，与实跑吻合。注意**它并非天花板**——agent 只交 `{aa}` 就能拿 1.0，真问题是“池子要大、合格集要小”的自相矛盾。
**修法**：答卷契约拆成两个字段——`screened_pool`（考察过的全部候选，cp2/cp3 按此评）与 `ranked_candidates`（判定合格的，cp4/cp5/cp6 按此评）。旧答卷无 `screened_pool` 时自动回落，向后兼容。

**问题 2：cp5 空集给满分 → 已修。**
原实现 `set(ranked)==gps → 1.0`，空集等空集也满分。实跑里 glm 在 **4 道题**上 `best=None`（没交答案）却 `cp5=1.0`。**修后这 4 处均为 0.0**，对应 process 从 0.17–0.20 降到 0.067–0.10。

**问题 3：伪命中排查 → 已定位，真因不是匿名化被穿透。**
原先怀疑 Metoprolol 太有名、模型能从常识反推。诊断后发现真因更简单也更严重：**所有模型的候选池都只覆盖 `aa`–`ae`**（见问题 4），而 4 道题的 gt 落在 `ba/bb/bc`——**gt 根本不在池子里，必然答错**。qwen 在两道答错题上交 `aa`，只是因为池子里只有 `aa`–`ae` 可选。

**问题 4（最根本，此前未被发现）：mock 检索工具截断导致 3 道题结构性无解 → 已修。**
`mock_server.py` 的 `search_molecule_database` 在检索词匹配不上时 fallback 返回 `db.molecule_search_all()[:5]`。由于查询词是自然语言（而库里只有 SMILES 与匿名 ID），**字面匹配永远为 0、永远走 fallback**，于是 20 个分子里只有 `aa`–`ae` 能被取到，另 15 个永不可见。后果：

| case | gt | 修复前 | 修复后 |
|---|---|---|---|
| cns_metoprolol | `aa` | 可解 | 可解 |
| bronchodilator_theophylline | `ab` | 可解 | 可解 |
| cardiac_sotalol | `ba` | **结构性无解** | 可解 |
| anxiolytic_diazepam | `bb` | **结构性无解** | 可解 |
| antibiotic_sulfamethoxazole | `bc` | **结构性无解** | 可解 |

**修法**：fallback 返回全库（20 条）。这解释了为何原命中率只有 4/15——其中 3 道题任何模型都不可能做对。

**问题 5（顺带发现）：评分脚本没读真实答卷 → 已修。**
`evaluate.py` 的 main 原先不读 `_response.json`，而是从 trace 的 `predict_admet` 入参**"推断"**一个假 response，推断出 `C0CC`、`Donepezil` 这类根本不是候选 ID 的值。现已改为只读真实答卷，并输出 `process / gate / task_score / submitted / gold_pass_set` 全字段。

> 另：合格集 |G|=1 还导致 **cp6 的“接近度衰减”分支自始至终无 case 触发**（这才是 T-21 “造多合格者 case”的立项理由，见 ADR-0009）。**修复 mock 截断后候选池扩到 20 个，|G| 是否仍为 1 需重跑确认**——这是下一步。

## 2. Tier A · 有完整造题流水线的 8 家

> 下面 8 家按“与我方相关度”排序。每家四件事：① 一条完整题 ② 怎么构建 ③ 怎么打分 ④ 与我方的差异化点。

### A1. InfoMosaic-Bench（⭐ 与我方 open 类最像）

> **一句话**：621 题 / 77 个工具 / 6 个域，靠“工具查证据→反向拼题→再用只会网页搜索的 Verifier 反复砍捷径”造出来；GPT-5 也只有 38.2% accuracy、67.5% pass rate。**它的“子条件”就是我方证据 checkpoint 的原型。**

**① 一条完整题**（论文附录 Table 10 原文，Finance 域）：
- agent 看到：**"找一家科技上市公司：总部在 Austin TX；2025 Q1 净利润为正、Q2 为负；截至 2025-09-19 年内涨幅 10–20% 且 beta>5；Q2 营收 7000万–8000万美元。股票代码是？"**
- 答案：**CORZ**（Core Scientific）。

**② 怎么构建的**（InfoMosaic-Flow，§3.1，"organizer–worker 双agent"产线）：

> 打个比方：一个**总指挥（organizer）**只动脑不动手，负责想"要什么条件、怎么验证"；一群**工人（worker）**只动手不动脑，负责真的去调工具查数据。

- **Stage 1 信息搜寻（先攒出一道题）**：
  1. **场景提议**：从种子（维基/百度百科/去哪儿网/NCI 疾病 ID）里，总指挥提一个场景，好让不同领域的工具都能被用上；
  2. **领域取证**：总指挥发子任务 `executor(子任务, 领域)`，工人在该领域工具集里**自由选工具**查出可验证事实、回传证据；总指挥消化后再发下一条——**每个条件都被真实工具查证过**（这就是"答案先于题目"）；
  3. **整合**：总指挥把所有验证过的工具结果拼成一道"多源、跨条件"的问题。
- **Stage 2 迭代精炼（专门砍捷径）**：此时工人换成**只有网页搜索的 Verifier**。
  1. **条件拆解**：把题拆成单条件，让 Verifier 一条条单独去解；
  2. **条件模糊化（fuzzing）**：如果某个条件"太露"（一次网页搜索就能直接搜出答案），就把它改写/和别的条件合并，削掉捷径；
  3. **收尾**：反复迭代，直到同时满足——**(a) 纯网页搜索解不出整题；(b) 没有任何单一条件能独自定出答案**。才收进数据集。

**②' 三道自动质量闸（我方“捷径闸”的原型，§3.2）**：Tool-Call Filtering（滤掉不需调工具的题）+ Answer–Evidence Consistency（答案须与工具证据一致）+ Coherence Filtering（题面自洽），之后再人工复核。论文 Table 7 的 fuzzing 消融证明这一步最决定难度：**无剪枝 45.1% → Quick Fuzz 41.7% → Advanced Fuzz 31.3%**（成绩越低说明题越难、捷径越少）。

**③ 怎么打分**：终态答案 accuracy + pass rate；另报每个子条件的通过率（判的是**最终答案**是否满足各子条件）。

**④ 对我们的直接启示**（产线细节见 ★ 步 3、步 4）：差异化点在判分对象——**它判“最终答案”是否满足各子条件；我们判 agent “轨迹中产出的中间结论”是否等于数据库真值**。前者可以靠猜对答案蒙过，后者必须真的一步步做对。

### A2. NewtonBench（⭐ 反事实防污染的样板）

> **一句话**：12 条真定律 → 突变成 108 条“平行宇宙定律” → ×3 种系统复杂度 = 324 题；**每例只给 ≤10 轮实验、实测模型平均只用 3–8 轮**——它的“长”在搜索深度，不在轮数（这正是我方 horizon 更长的对照）。

**① 一条完整题**：agent 读到一段 prompt——"有个测力装置，你提交 (mass1, mass2, distance)，我返回测到的力；最后交一个 `discovered_law(mass1,mass2,distance)` 函数。"它要靠反复做实验，反推出隐藏的力学公式。真值（agent 看不到）是一段代码，如 `F = C·m1·m2 / r^1.5`。

**② 怎么构建的**（§3.1 物理定律 curation，两阶段）：
1. **收集正典种子定律**：按 3 条标准选 12 条真实定律——必须是领域基础定律、跨多个物理域、且**允许"量纲一致的突变"**；
2. **反事实定律漂移（Counterfactual Law Shift）**：把定律写成**表达式树**，在树上做突变——
   - 改**算子**（加号改乘号），或改**常量/指数**（`r²` 改 `r^1.5`、平方改立方）；
   - 突变会破坏量纲一致性 → 用定律里嵌入的**物理常量**去补偿（所以**每条定律必须至少含一个补偿常量**，这是硬约束）；
3. **难度分三档**：Easy = 正典突变 1–2 次；Medium = 在 Easy 上再突变 1–2 次；Hard = 在 Medium 上再突变。3 位领域专家把关，12 条正典 → **108 条改写定律**；
4. 每条 × 3 种系统复杂度（Vanilla 单方程 / Simple / Complex 埋在多方程里）= **324 题**。

**③ 怎么打分**：把 agent 交的函数与隐藏 GT 函数做**符号等价**比对（忽略常量取值）+ RMSLE 预测误差。

**④ 对我们的直接启示**：**"反事实改写"是我们防污染最该抄的手法**。我方现在只是"抹分子名"，抗记忆弱；可以对某类性质做**受控平移/改写**（造一个"平行宇宙"的性质数据库），并像它一样保留一个"补偿自由度"保证物理自洽。难度也可以照它做"突变次数"这个客观旋钮。

### A3. SWE-bench（⭐ “真值=已存在的测试”，可规模化到 10³）

> **一句话**：从 12 个流行 Python 仓库自动挖出 **2,294 道题**（另有 19,000 条可扩展池），全程不用人标真值——**靠的就是“真值 = 仓库自带的测试”这一条**，可一比一搬到我方“真值 = 数据库反查值”。

**① 一条完整题**：给 agent 一个代码库快照 + 一条 GitHub issue（"某功能报错……"），它产出一个修复 patch。真值 = 仓库里已有的测试。

**② 怎么构建的**（§ Task instance construction，全自动挖 PR）：
1. **挖满足 3 条件的 PR**：① 状态是 Merged（改动被真正合入）；② 解决了 ≥1 个 issue（扫 PR 的标题/正文/commit 找 "fixes #24" 这类链接）；③ 引入了 ≥1 个新测试（改动碰了含 "test" 的文件）；
2. **转成题**：代码库 C = repo + base commit；题面 P = 相关 issue 标题+描述+**PR 首次 commit 之前的评论**（时间截断，防答案泄漏）；PR 的代码改动**拆成两半**——`gold patch δ`（修复，藏起来当答案）+ `test patch`（判据）；
3. **执行式验证筛题**：建虚拟环境 → 装 C → 应用 δ 前跑一次测试、应用 δ 后再跑一次；**任何步骤失败就剔除**；还要求至少一个测试从 fail→pass（保证 δ 非平凡）；剔除那些"测试调用了 δ 里新建函数"的题（人也做不了）。

**③ 怎么打分**：`FAIL_TO_PASS`（修复后必须过）全过 **且** `PASS_TO_PASS`（原本过的不许弄坏）全过 = resolved。

**④ 对我们的直接启示**：两条。① **"真值必须是已存在、可执行的东西"** 是可规模化到 10³ 的根本原因（它不用人标真值）——我方 GT-first 反查数据库同理，要在论文里把这条对齐讲清楚。② **`PASS_TO_PASS`（不许弄坏已对的）正是我方缺的 `no_regression` checkpoint**——agent 后面步骤不许覆盖前面已确认对的性质值。

### A4. ScienceAgentBench（⭐ 从论文 harvest + 防污染最细）

> **一句话**：从 44 篇开源论文抽 **102 题** / 4 学科，9 位专家两轮把关；**防污染做得最细**（随机删测试点 + 重切 + dummy 标签），这套组合我方药物/材料线可直接照搬。

**① 一条完整题**：给指令+数据+数据集说明，agent 产出一个可执行程序（如"对这批化合物做某分析、出图"），跑出来的输出要满足成功判据。

**② 怎么构建的**（§ 从 44 篇论文抽 102 题，5 步 + 防污染）：
1. **选源**：在 4 个学科（生信/计算化学/GIS/心理认知神经）里，找**开源了代码和数据**的同行评审论文；
2. **5 步标注每题**：① 从论文里挑一段自包含、文档良好的代码例转成任务 → ② 收集预处理它用的数据 → ③ 把原代码改写成"参考程序" → ④ 把成功判据实现成**可执行脚本** + 用 GPT-4o 起草逐步 rubric → ⑤ 写指令和数据说明；
3. **防污染 + 防捷径**（两招，很值得抄）：① 每个数据集从 **test set 随机删 5 个测试点**——agent 若用了训练语料里见过的自动数据加载器，就会因对不上而失败（**例外**：若删点会破坏数据集完整性，如导致地理图不完整，则跳过此步）；② 需要建模的题**重切数据集，测试标签只留评分用、原位替成 dummy 值（如 -1）**——防 agent 直接偷读测试标签作弊；
4. **两轮人工把关**：9 位领域专家按 4 步问卷验证 → 改 41 条指令、删 3 题；标注者交叉复核 → 再改 29 条。

**③ 怎么打分**：VER（能不能无错跑）→ SR（输出满不满足判据）→ CBS（与参考程序相似度）→ Cost；图用 GPT-4o judge（这点我方不抄）。

**④ 对我们的直接启示**：**"随机删测试点 + 重切 + dummy 标签"这套防污染/防捷径组合，是我们药物/材料线可以直接照搬的**。它证明了"从公开论文反查任务"这条路 ICLR 认可——我方从数据库反查分子是同一逻辑，且我方匿名化比它更彻底。

### A5. Toolathlon（⭐ 真实软件初始状态 + 每题手写判分脚本）

> **一句话**：108 题 / 32 个真实软件 / 604 个工具，**平均约 20 turns 工具调用**（这是当前“长程”的标定线），最强的 Claude-4.5-Sonnet 只有 **38.6%**；但判分**只看终态、没有过程分**。

**① 一条完整题**（`reference/ICLR-Tool-Decathlon/sample_task_ab-testing.md` 原文）：从 BigQuery 读 A/B 测试点击流 → 算各场景转化率均值 → 填 `record.csv` → 若 B 胜就建前缀 `promo-assets-for-b` 的云存储桶，否则往日志桶写一条指定 JSON。

**② 怎么构建的**（§2.3–2.4）：
1. **108 题人工搜集/编写**，覆盖 32 个真实软件、604 个工具；
2. **给 67% 的题配"真实初始状态"**：一个 `state 初始化脚本` 或一个预置的 workspace 目录，**状态从真实软件导出**（如含几十名学生的 Canvas 课程、真实财务表），且刻意做得贴真实场景（如混进 10 个有用+无关文件）——这是它相对前人的主要改进（别人多从空状态起）；
3. **每题一个人工手写的确定性评测脚本**：要么和 GT 环境的静态快照做鲁棒比对，要么按参考执行流动态取实时值（如英伟达股东）；隔离容器里并行评测。

**③ 怎么打分**：终态执行式（读 record.csv 按 0.05% 容差比对 + 查桶是否存在），报 pass@1/@3/^3，**无过程分**。

**④ 对我们的直接启示**：① **"每题一个手写确定性判分脚本"是 ICLR 可接受的成本**——我方 `reward` 表达式比它更结构化，是加分项。② 它的"真实初始状态"= 我方 mock 数据库快照，要在论文里强调"工具+初始状态随 benchmark 出厂"。③ 它明摆着**没有过程分**——正是我方缺口。

### A6. ColorBench（⭐ 真机录轨迹 → 状态图 → 里程碑）

> **一句话**：**175 题**（74 单应用 + 101 跨应用）、平均 13+ 步，真机录屏建成状态图后在图上标里程碑；**它是 8 家里唯一给出过程部分分（CR/AC）的**——但里程碑判的是“到没到某屏幕”，不是科学内容。

**① 一条完整题**（`reference/WWW-ColorBench/sample_tasks_3.json` 原文）：`{query:"去小红书搜 ai agent，把某论文转发给微信好友1，再去 arxiv 下 pdf 发给他", optimal_steps:36, app_num:4, milestone:[{ability:search,...},{ability:share,...},{ability:save,...},{ability:share,...}]}`。

**② 怎么构建的**（§4.2，两阶段：轨迹收集 + 图合并）：
1. **轨迹收集（真机录屏）**：
   - **BFS（广度）**：抓浅层高频页。用 VLM A 识别页面上所有可交互 UI 元素 → VLM B 逐个点、记录跳转轨迹；
   - **DFS（深度）**：抓复杂长程任务。专家团队设计"支持多路径"的典型长程任务 → 训练过的操作员**在真机上手动执行、逐步截图** → 用 VLM 补全截图之间缺失的动作，重建完整轨迹；
2. **图合并**：用语义+视觉标准，以"动作转移"区分不同 page node（屏幕状态），VLM 自动标 UI 框，最后**人工质检**；
3. 在图上标 **milestone（里程碑=完成一个子任务=到达某个屏幕状态）**，每个里程碑归到 15 类原子能力之一。

**③ 怎么打分**：SR（所有里程碑达成）+ CR（达成里程碑数/总数，部分分）+ AC（原子能力条件通过率，**分母排除因前序失败而没机会执行的子任务**）。

**④ 对我们的直接启示**：① **AC 的"条件化分母"必须抄**——每个 checkpoint 报"条件通过率"（前置全对的前提下本步对不对），别让级联失败污染诊断。② 它的里程碑判的是"到没到某屏幕"（**位置**），我方 checkpoint 判"中间科学结论对不对"（**内容**）——这是我方核心差异，写作时要点明。

### A7. GAIA（⭐ 人类造题 + 步数/工具数分层）

> **一句话**：**466 题**纯人工造，人类 92% vs 带插件的 GPT-4 仅 15%；**Level 3 上所有系统都是 0%**——这正是“只判终答无法区分‘走对 8 步’和‘第 1 步就跑偏’”的铁证。

**① 一条完整题**（论文 Figure 1）："找那个测试'从健康皮肤分离的局部共生葡萄球菌菌株'的多中心 AD 临床试验，其研究点位于芝加哥 I-90 州际公路以北……"→ 唯一事实性短答案（如某 NCT 编号）。

**② 怎么构建的**（§3.3–3.4，纯人工）：
1. **人类标注员造题**：作者先给初始例子+指令，标注员基于"**sources of truth**"（维基、Papers With Code、arXiv，或题目自带的附件、或自包含谜题）造题——**通常要组合多个来源的信息才能得到一个特定答案**；不固定来源清单，以防背诵；
2. **造完即标注**：题目创建者给出答案 + 元数据（需要哪些工具、走了哪些步、耗时多少）；
3. **难度按"标注员的步数+工具数"分 3 层**：Level 1 ≤5 步/至多 1 工具；Level 2 约 5–10 步/需多工具；Level 3 任意长/任意工具。

**③ 怎么打分**：终态精确匹配（答案设计成"唯一、事实性、简洁"，所以免 LLM judge）。

**④ 对我们的直接启示**：① **"唯一事实性短答案"是免 LLM judge 的根本**——我方答卷 schema 同理。② **难度用"专家步数+工具数"分层**是被广泛接受的客观代理量，我方可用"专家需要的数据库查询次数 + checkpoint 数"同构分层。③ 它采了人类步骤元数据却只用来分难度——我方把这份元数据升级成判分对象。

### A8. MLE-bench（⭐ 无唯一解时用“人类排行榜”当客观标尺）

> **一句话**：5673 个 Kaggle 竞赛筛到 **75 题**，用**人类排行榜的铜/银/金牌**当标尺解决“没有唯一正确答案怎么打分”——我方 open 类可照搬为“击败数据库中 x% 的已知分子”。

**① 一条完整题**：一个 Kaggle 竞赛（描述+数据），agent 自主跑最长 24h 产出一个提交，按竞赛官方指标评分。

**② 怎么构建的**（§2.1 Dataset Curation）：
1. **从 5673 个已完赛 Kaggle 竞赛**起 → 排除 Community 竞赛 → 对**剩余 586 个**做人工相关性筛查 → **排除"无法复现评分"或"无法重建合理 train/test split"的**；
2. **每题打包**：描述（爬 Overview/Data 页）+ 数据集（多数**重切 train/test**：新 test 取原 train 的 10%，并核对示例提交在新旧 test 上分数相近以保证同分布）+ 复现的评分代码 + **排行榜快照**；
3. **人工标复杂度**：Low（专家 <2h 出解）/ Medium（2–10h）/ High（>10h），得 75 题（22/38/15）+ 7 题开发集。

**③ 怎么打分**：竞赛官方指标 → 映射到**人类排行榜分位**（拿到铜/银/金牌的比例）。

**④ 对我们的直接启示**：**我方 open 类（无唯一解，如"找 Tc 尽量高的超导体"）可以照抄"人类/文献分布当标尺"**——把 agent 候选放进已知材料的性质分布里，报"击败了数据库中 x% 的已知材料"，比自定阈值更客观、更好写。

## 3. Tier B · 环境/方法类（造的是环境或训练信号，非静态题）

> **一句话**：这 9 家不提供“题”，只提供三样能直接拿的东西——**度量语言**（Illusion 的 `H_s`）、**过程奖励先例**（RLVMR 的规则化元推理奖励）、**“补判据本身就是可发表贡献”的先例**（LoTa-Bench 给现成数据集补 goal condition）。

| benchmark | "造题"的实质是造什么 | 关键机制（一句话） | 对我方 |
|---|---|---|---|
| **WebRL** | 造**训练任务**（原本没有） | 自演化课程：从上一阶段"失败但接近成功"的尝试自动生成新任务 + 训一个 ORM 当奖励 | 我方可改成"从 agent 卡住的 checkpoint 处生成同类新题" |
| **AgentGym-RL** | 造**RL 环境套件** | 把 5 类现成环境（WebArena/DeepSearch/TextCraft/BabyAI/SciWorld）工程化、可并行、可 reset | "环境+RL方法"打包投稿的形态参照 |
| **RLVMR** | 造**过程奖励信号** | 给 agent 每步打元推理标签(plan/explore/reflect/monitor)，规则化给稠密奖励 | 过程 verifiable reward 先例；我方 checkpoint 比它更硬 |
| **Illusion**（《The Illusion of Diminishing Returns》） | 造**合成探针**（非对照集，只借它的度量语言） | key→value 字典 + 给定 plan，每步 retrieve+compose；长度可无限延伸 | 给了 `H_s` 长程度量语言，我方一级指标直接用 |
| **RoboVQA** | 造**训练数据集**(82.9万对) | 自顶向下众包：给长程任务让人拆成中程步骤录视频，长程连贯性免费附带 | "先造完整专家流程再切 checkpoint"的采集哲学 |
| **LoTa-Bench** | **补 goal condition** | 给现成 ALFRED/WAH 数据集补上可机器判定的目标条件 | "补判据本身是可发表贡献" |
| **AstaBench** | **改造+聚合既有集** | 11 个子集统一到一个带工具的 Asta 环境，加语料日期截止防污染 | "工具随 benchmark 出厂 + 控成本 + 防污染"五条 checklist |
| **MOSMAC** | 造**多智能体环境** | StarCraft II 顺序子任务 + 多目标奖励 | 多智能体，撞我方硬边界，仅调性参照 |
| **CaStL / AgentPRM** | 无数据集（方法论文） | NL→PDDL 翻译 / 步级 promise-progress 学习 | 仅方法参照 |
