# 未闭环 5 问 · 外部已有做法调研证据（2026-07）

> 目的：为"达摩院 AI4S 方案 5 个未闭环点"的逐项讨论提供可追溯的外部做法证据。来源均标注。

## Q1 trace→checkpoint 对齐（别人怎么锚定"节点已完成"）

**两大路线：状态锚定（hard） vs 轨迹解读（soft/人工）**

1. **状态锚定（环境/产物查询，hard，主流且可靠）**
   - **TheAgentCompany**（NeurIPS'25）：checkpoint 在出题阶段定义，评测时"每个 checkpoint 必须具体实现为一个 evaluator 函数"——逐点手写函数**查询环境状态**（查 ans.txt 内容正则、查 RocketChat 是否有某消息），而不是在自由文本 trace 里做模式匹配。锚点是"世界状态/产物"，不是"行为叙述"。[arxiv 2412.14161; NeurIPS'25 PDF]
   - **AgentBoard**（本地已拆代码）：PDDL 符号状态机，progress = 当前世界状态中目标文字满足比例（`constraint_satisfaction_metric`）。对齐靠符号状态比对。
   - **SUPER**：中间步骤靠"执行结果"判定（SQL 执行产物/action 正确性），金标准步骤来自 harvest。
   - **AgentQuest**（NEC, NAACL'24 demo）：模块化框架 + "Reached milestones" 指标——milestone 定义为**可验证的环境事件/状态**（如 CTF 拿到 flag），进度=已达里程碑占比。[arxiv 2404.06411; github nec-research/agentquest]
2. **轨迹解读（标注/判断，soft 或人工）**
   - **ProcessBench/PRM800K**：逐步人工标注数学推理对错；任务是"定位第一个错误步"。对齐=人工标注，不自动。[arxiv 2412.06559]
   - **TRAIL / Who&When**：失败归因标注（哪步、哪类错、哪个 agent），靠人工/专家标注 trace。
3. **结论**：要在分子发现场景 hard 判"节点完成"，走**状态锚定**——checkpoint=可查询的中间产物/状态（"毒性检查产物存在且有效"），用验证器查产物而非认动作。"用了非预期工具"不归因工具，只验产物——正是 TheAgentCompany 的做法，与卡片"节点是中间结果不是工具调用"一致。

## Q2 LLM judge 校准（κ/人评一致性怎么做）

1. **MT-Bench**（Zheng'23，11k+ 引）：GPT-4 judge 与人类偏好一致率 **>80%**（≈人-人一致水平），成为事实标准线；揭示 position bias / verbosity bias / self-enhancement bias；缓解=位置交换、CoT 判官、参考答案引导、few-shot。[arxiv 2306.05685]
2. **PaperBench**（OpenAI'25）：建 SimpleJudge 后，**专门构建人工评分验证集**评估 judge 与人评分的一致性（report agreement/F1）——即"人评 grounding 子集"做法，正是卡片要的 κ 校准的业界对应。[arxiv 2504.01848]
3. **方法论共识**：校准=抽人评子集→报告 judge↔人一致率/κ→修判官 prompt→达标（≥80% 或 κ≥0.7）才允许上线；无 human grounding 的 judge 分数不可信。[futureagi 2026 综述; justintime 大规模 judge 评测; arxiv 2503.05061]
4. **结论**：LLM judge 必须配"人评金样子集 + 一致性报告 + 偏差缓解"三件套；硬验证器覆盖不到的语义点才可交给它，且占比要压小（卡片 ≤30% 合理）。

## Q3 数值容差设计（阈值怎么定）

1. **SciCode**（NeurIPS'24）：每子问题的数值容差由**领域科学家按物理/数值性质设计**（numerical + domain-specific 双轨）；target 由金标准解生成；另有 50 个 validation 子问题用于调参，288 个 test 冻结。[SciCode NeurIPS'24 PDF §2.3; 本地已拆]
2. **MLE-bench**（OpenAI'24）：不设绝对容差，**用 Kaggle 历史排行榜分位数当阈值**——铜/银/金=top 40%/20%/10%（按参赛队数分档），把"容差"锚定到人类基线。[arxiv 2410.07095; ICLR'25 slides]
3. **通用原则**：物理量用相对容差 rtol（近零辅以 atol）；阈值在 dev/validation 上调、冻结 test 后不再动；能锚定人类/基线分布就不拍绝对值。
4. **结论**：我们的容差设计=①默认相对容差；②在 dev 集上用金标准解+真实 API 漂移分布定阈；③能拉基线（历史数据/文献值）就锚定基线而非拍脑袋。

## Q4 困难负例相似度（"尽量相似但恰失败"怎么定义）

1. **Activity cliffs**（van Tilborg'22, JCIM, 367 引）：分子 ML 界标准的"相似但性质迥异"构造——Morgan/ECFP 指纹 Tanimoto ≥ 阈值（常用 0.8–0.9）但活性差 ≥1–2 个数量级；30 靶点 activity-cliff 评测集。[JCIM 2c01073; PMC9749029]
2. **Lo-Hi**（Steshin'23）：按 train/test 间 Tanimoto 相似度上限切分，用相似度阈值直接控制难度。[arxiv 2310.06399]
3. **Scaffold split**（MoleculeNet 标准）：骨架不相交的切分=标准"难泛化"设定。
4. **结论**：卡片缺的"相似度判据"业界默认=**ECFP/Morgan 指纹 + Tanimoto**；"困难负例"=Tanimoto≥0.8（相似）且恰违反 1 条约束；"简单负例"=相似度低或违反多条；与 activity-cliff 定义同构，可直接引用做依据。

## Q5 规模化实例验证（发布前怎么验题）

1. **金标准解回放**：SciCode——target 全由科学家金标准解跑出，验证器必过金解（必要性）。
2. **执行过滤**：SWE-bench——FAIL_TO_PASS 测试必须"打补丁前真挂、打后真过"，PASS_TO_PASS 保持绿，执行不过滤掉实例；Verified 再加人工筛。近期 OpenAI 自曝污染/坏测试→**发布后还要持续监测**。[SWE-bench#505; openai.com 2026]
3. **人工抽检**：PaperBench——rubric 与论文作者共建；judge 用人工评分集校准。
4. **变体/泄漏检测**：内容指纹（卡片已设计：模板+实体+快照+种子联合 hash）业界对应=SWE-bench 污染检测讨论。
5. **结论**：质量门=①金解回放全过（必要性）②负例/非解轨迹不全过（区分度）③执行过滤④分层人工抽检⑤内容指纹防变体泄漏⑥发布后污染监测。卡片 0005/0006 已覆盖①③⑤⑥，缺②④的明文化。
