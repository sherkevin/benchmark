# 达摩院 AI4S Benchmark 构建方法 · 梳理与评价

> **来源**：`~/work/resume/cards-01-damoyuan.md` 项目一（AI4S Benchmark，含 §1 问题、§2 Pipeline、§4.1–4.13 技术细节）。
> **一句话结论**：这是一套 **GT-first 反向构建 + checkpoint DAG 过程评测 + 两层数据架构** 的科学 Agent 评测题构造方法——从冻结科学数据库里先选"已知正确的答案"，反向出成自然语言题，让 Agent 正向解回来，既判最终结果，也判中间过程链。方法本身严谨、可直接复用；主要风险在"企业版规模化尚未执行"和"agent trace 与 DAG 节点的对齐工程"。

---

## 1. 这套方法是什么（金字塔：先总后分）

### 1.1 核心思想三句话

1. **评的是 checkpoint 依赖图，不是唯一标准思路**——允许等价路径（同题可不同解法），但必要的中间结果必须到位；只对真实依赖定序，无依赖的步骤可换序。
2. **出题和考试用两套数据源**——"出卷层"用冻结数据库快照（保证答案可重复），"答卷层"用真实工具 API（保证考试真实）；同一个查询、两套接口。
3. **≥70% checkpoint 由确定性硬验证器判分**——只有"证据综述"这类无法规则化的才用 LLM judge。

### 1.2 造一道题的完整 Pipeline（以 EGFR 药物筛选为例）

| 步骤 | 做什么 | 关键约束 |
|---|---|---|
| 0 备料 | 遍扫科学数据库接口，规约化为统一入参的 **provider 库**（靶点身份/活性/毒性/价格/可合成性…），每个 provider 对应一种 checkpoint，数据源冻结快照 | 同一类分子统一规范化描述 |
| 1 选根 | 从冻结快照选一个已知好分子（如 Gefitinib），调 provider 拉出全部属性 | 全部事实绑定**同一实体、同一快照** |
| 2 画图 | 按属性间真实依赖排出 **checkpoint DAG**（确认靶点→候选池→{活性,毒性,价格,可合成性 并行}→筛选→提交） | 节点是"中间结果"不是"工具调用"；无依赖不连边 |
| 3 出题 | 反向把属性改写成自然语言研发请求 | **题目隐去答案根与一切具体数值**；LLM 只做改写、不写真值 |
| 4 复核 | 独立 solver 只看题目+工具正向做一遍 | 做出多个解→扩正例集；做不出→淘汰该题 |
| 5 造干扰 | 按属性反查相似分子，按"违反几条约束"分级：全满足→**加入正例集 G**；只差一条→**困难负例**；差多条→**简单负例**；另造**无解题**测诚实性 | 不得为保"唯一答案"把合格分子强判负例；无解题建议占 15–25% |
| 6 封卷 | 打包 **TaskSpec**（题目/工具/预算/数据版本/正例集/DAG/负例/验证器），运行 Agent 记录完整 trace，分别报告答案、检查点、红线、帮助量、成本 | 原始工具结果不因喂 LLM 截断而丢失 |

### 1.3 关键设计件

- **TaskSpec schema**：`template`（流程骨架，**不含工具名**——Agent 运行时才见工具列表，自己决定怎么完成每个 checkpoint）+ `prompts L0–L3`（考前给多少提示）+ `checkpoints`（每点含 tier/kind/critical/depends_on/gold）+ `intervention_cards D1–D3`（考中卡住给多少帮助）+ `acceptance`（任何满足依赖的拓扑序皆可）+ `global_invariants`（预算/证据落地/高风险审批）。
- **三条独立难度轴**：L0–L3＝考前复习资料量；D1–D3＝考中提示量；permission＝高风险操作需人批准。`autonomy@0` 只算 L0 + 0 运行时帮助。
- **打分**：`过程分 = 检查点加权平均`；`总闸门 = 最终答案对 AND 关键检查点全过 AND 安全/预算红线没踩`；`任务分 = 0.5×过程分 + 0.5×总闸门`。必报 final_success / process_score / critical_pass / critical_gate / autonomy@0 / success@budget / permission 校准；失败超时违规全留在分母。
- **六道质量门**：同根一致 / 自然问题 / 确实长程 / 答案可发现 / 防泄漏（先按实体·模板·时间切分再实例化，优先冷门或 cutoff 后数据）/ 独立正向复核。
- **验证器两层**：Tier 1 硬验证（数值容差、集合成员、排名指标、结构可解析、守恒、工具落地、图子集）；Tier 2 LLM judge 仅用于不可规则化的语义点。
- **企业版规模化规范（12,800 任务，未执行）**：少量人工模板 × 数据库实体组合 × 约束/反事实种子批量实例化；先按模板族·实体簇·快照时间切 2,800 dev + 10,000 frozen test，再实例化；test 内抽 1,000 高风险/长尾做双人专家金标，其余确定性验证器+分层抽检。**实例 ID 用内容指纹**（模板+实体+快照+约束种子+反事实版本联合 hash），禁止随机编号——可发现训练集/测试集是否同题变体。

## 2. 评价：这套方法怎么样

### 2.1 优点（值得肯定且可直接复用）

1. **GT-first 从根本上保证"每题有解且可验证"**，避免了科学领域"先出题再找答案"的三大坑（无解、真值不可验、出题过程泄漏）。真值锚数据库/论文而非 LLM，是把 benchmark 可信度建在可查证据上的正确选择。
2. **DAG 只绑真实依赖**，正面回应了"流程符合性 vs 结果等价"难题（即本项目 OQ1）：它明确选择"评中间状态、不绑流程"的立场，既保留过程量信号，又允许等价路径——比"唯一标准 trace"派（如 PaperBench rubric 树）更宽容，比纯终态判分（SWE-bench）更有信息量。
3. **两层架构（出卷层/答卷层）干净地解决了可重复性与真实性的矛盾**：判分锚冻结快照，考试接真实 API + 验证器容差。这是工程上很少被讲清、但做科学 benchmark 必踩的坑。
4. **负例体系完整**：困难负例测"是否真做了检查"、无解题测诚实性、改错步骤只进验证器校准不冒充正题——与防泄漏的"内容指纹 ID + 先切分后实例化"共同构成反污染闭环。
5. **三难度轴分离 + 指标全套**（autonomy@0、success@budget、permission 校准），把"给多少提示"从"Agent 自主能力"中解耦，度量口径清晰。

### 2.2 风险与尚未闭环之处

1. **企业版 12,800 是构建规范、不是已执行数据**——当前可核验的只有 39 个样板实例 + 验证器。规模化的真实性（组合实例是否都自然、依赖是否都闭合）未经实证，引用时必须区分"规范"与"已跑"。
2. **agent trace → DAG 节点的对齐工程是最大落地难点**：DAG 说"不绑流程"，但判分时仍要把 agent 的自由 trace 锚定到 checkpoint 节点（哪个动作算"完成了毒性检查"）。工具落地验证能抓"声称查了但没调工具"，但"用了非预期工具完成节点"的归因仍需设计，卡片未展开。
3. **LLM judge 部分需 κ 校准**：语义类 checkpoint（证据综述）用 LLM 判官，缺人评一致性报告前，其分数可信度未知（本项目 TODO §B-D2 同款问题）。
4. **容差设计敏感**：答卷层真实 API 返回值漂移时，数值类验证器容差（如 ≤0.05 eV/atom）需要在 dev 上调——"只在 dev 调阈、冻结 test 后一次性执行"是对的，但 dev 仅 2,800 时调参泛化性待验。
5. **困难负例依赖相似性度量**：反查"尽量相似但违反一条约束"的分子，相似度怎么定（结构指纹？属性距离？）直接影响负例质量，卡片未给判据。

## 3. 速查：高频追问标准答案（摘自卡片，与本梳理一致）

- **"结果对"vs"过程链对"**：结果对只看最终输出；过程链对要求关键检查点、证据、工具落地、状态转移有效，但允许等价路径。
- **必须固定顺序吗**：不必须，只对真实依赖定序。
- **正例能多个吗**：能。正向复核发现同等合格分子必须加入正例集，不得强判负例。
- **hard negative 怎么造**：找尽量相似、但恰在一条关键约束上失败的候选。
- **checkpoint 越多越好吗**：不是。每个检查点必须满足至少一条——是后续决策的真实依赖 / 能抓一种明确错误模式 / 是不可违反的安全约束 / 能区分"蒙对"和"有证据地对"。与最终决策无关的只留辅助 metadata。
- **强检验 vs 弱检验**：数值/守恒/结构=硬校验；集合成员=外延校验。两者都确定可重复，"弱"仅指它证明的是局部必要条件，不代表不可靠。
