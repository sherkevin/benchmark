## 0.1 别人怎么做：按本项目的三个目标去比

> 比较维度直接来自 `ai4sci benchmark 项目概览.md` 的三个目标：
> ① 测 agent 在**制药任务**上的完成情况；② 测出 agent 的**三个能力维度**（推理 / 记忆 / 工具调用）；
> ③ 分数最终要能**用来改善 agent**。
> 数据源：本项目 `research/benchmark图鉴_每家测什么怎么判.md`（已收录 44 家）+ 本文 3.1。
> 图例：✅ 有 ー ⭕ 部分 ー ❌ 无。**"无"不等于做得差**，只说明这不在它的设计目标里。

### 0.1.1 五个维度的含义（先说人话）

| 维度 | 一句话解释 | 出自概览哪条 |
|---|---|---|
| **一道题是一个完整任务吗** | 题目是"一整件制药里真会发生的事"（例如从一个已有药出发、改造出同时满足多项要求的新分子），还是被切碎的单点（算一个性质、生成一个分子、写一段代码） | 目标① + 做法 2「做长任务不做短任务」 |
| **能不能分开测三种能力** | 一道题做对了，是**想出来的**（推理）、**背出来的**（记忆）、还是**查出来的**（工具调用）？能不能分辨 | 基本事实 1 |
| **难度可调吗** | 想要难一点的题，有没有一个旋钮可以拧，还是只能靠碰 | 要求 4「得分不能太好，留改进空间」+ 做法 2「原子问题数目当难度」 |
| **分数能用来改模型吗** | 分数除了排名，能不能告诉你"该改哪一步"，从而拿去训练 | 目标② + 要求 5「训练信号跑完即可提供」 |
| **什么算抄答案，讲清了吗** | 有没有明确定义"作弊"，并在设计上堵住 | 做法 4「唯一的作弊 = 调用能直接返回答案的工具」 |

### 0.1.3 这张表看出什么

**先说不利的：前四个维度上，我们没有一条是独占的。**

- 完整任务：ChemCrow、RetroAgent、MDArena、NewtonBench、InfoMosaic、MADE 都是完整任务。
- 分开测三种能力：**ChemToolAgent 的主轴就是"带工具 vs 纯 LLM"**，跟我们的对照臂是同一件事，而且是公开发表的。
- 难度可调：RetroAgent 用调用预算、MDArena 标三档、NewtonBench 三种复杂度、InfoMosaic 用跳数——都有旋钮。
- 作弊定义：NewtonBench 与 InfoMosaic 都有明确且更彻底的做法。

**我们真正不一样的只有两处：**

| # | 不一样在哪 | 具体是什么 |
|---|---|---|
| 1 | **把三种能力的"分离"做成系统设计，而不是一次对照** | 别人是"给工具 / 不给工具"两组。我们是**工具供给三档（基本 / 部分便捷 / 全便捷）× 候选可见性两种（给候选目录 / 不给）= 六格**，同一道题、同一真值，只动这两个旋钮。目的是把"做对了是靠想、靠背、还是靠查"拆开看，而不只是回答"工具有没有用" |
| 2 | **一开始就把"分数要拿去改模型"当设计前提** | 上表最后一列，别家基本是 ❌ 或 ⭕——能给逐条分，但那是为了**打分更细**，不是为了**训练**。我们把它当目标②，所以要求分数不只能排名、还要能定位到"哪一步该改" |

**第 2 处必须自己先说清的短板**：逐子问题分数已经落盘了，但"能定位到哪一步该怎么改"的信号**还只是设想、零实例**，所以那一格标 ⭕ 不标 ✅。

**第 1 处也有短板**：六格已跑完的那批数据属**已作废的评分范式**；现行两道新题只跑了两条臂，**三档一个 run 都没跑**。

### 0.1.4 更正一处我之前的错误说法

本节早先的版本用了另外七个维度（是否报重跑波动、是否逐子问题落盘、有没有无工具对照臂等），并称其中三列"几乎全空、是我们的空白优势"。

**那个说法有两个错，在此更正：**

1. **层面错了。** 那七个维度全是"做实验的质量控制手段"，而项目目标是"测制药 agent 并改善它"。拿质量控制去跟别人的研究目标比，等于别人比车跑多快、我们比螺丝拧多紧。
2. **"空白"是过度解读。** 论文里不报重跑波动，不等于没做，很可能只是不写进正文。**把"没报"读成"没做"是不成立的推论。**

那七条本身仍然有用，但只能作为**内部质量纪律**（见 §0.2、§0.3.2），不能当作与他人的差异或创新点。

## 0.2 我们怎么做：设计要点与内部质量纪律

> 本节与上文 1.8（十大结构性缺口）、3.1（代表性工作横向比较）一一对应。
> **差别不在“我们又提了一个机制”，而在“那些缺口我们真去量了，而且量出了与普遍假设相反的结果”。**

### 0.2.1 七条差异总表

|---|---|---|---|---|

| 5 | 1.8 “未知性不足”的应对是**消除**记忆（匿名、快照、时间切分） | 记忆是**合法能力维度**，不消除、而是**定量披露占比**；唯一的作弊是“调用可直接返回答案的工具绕过多轮推理” | 等价匿名变换（只换符号、数值一个不改）重跑：最强模型 **0.9 → 0.658**，另两个模型**归零** ⇒ 该题的分数几乎全部来自记忆维度 | 实测，已成方法学样板 |

### 0.2.2 上表里最值得单独讲的三条

**第 1 条：噪声底把我们自己的一部分结论否证了。**
跑间标准差 0.18–0.29 意味着：**任何小于 0.2 的“提升”都可能是重跑带来的漂动**。
拿它回溯已有的**六个对比跳（差值 ÷ 同批跑间 SD）**：

| 对比跳 | 差值 | 差值/SD | 结论 | 范式 |
|---|---|---|---|---|
| qed fixed basic→some | +0.345 | **1.70** | 过 | 已作废 |
| qed open basic→some | +0.111 | 0.58 | 不过 | 已作废 |
| qed open some→enough | +0.078 | 0.38 | 不过 | 已作废 |
| qed fixed some→enough | +0.037 | 0.18 | 不过 | 已作废 |
| cns 有工具 − 零工具地板 | +0.058 | 0.22 | 不过 | 现行 |
| sarflip 有工具 − 零工具地板 | +0.545 | ❗ 同批算不出（自由度 0），跑批口径 **1.22–2.44** | 取最保守值仍弱于首行 | 现行 |

❗ **两个必须同时说的限定**：
① 前四行那批数据属**已作废的评分范式**，只能当方法学例证用，不能当现行结论；
② 最后一行同批只有一个批次、自由度为 0，噪声底**算不出来**，只能改用“同模型换批重跑”取值，
而那个口径下三个算法给出 1.22 / 1.72 / 2.44 三个值——本文取**最保守的 1.22**。

这条对外的意义大于对内：本综述 3.1 里大量“某配置优于某配置”的结论，
如果没有同时报出重跑漂动，**无法判断它站不站得住**。

**第 3 条：“把评分做细”这个直觉是错的，而且错得有数学必然性。**
若两把尺子都是同一个底层量（如“满足几条”）的**单调变换**，则任意两份答卷的相对高低不变
⇒ 秩不变 ⇒ 非参检验的 p 值逐位相同，均值差与合并标准差同比例缩放 ⇒ 效应量也相同。
**推论：凡是底层量的单调函数，判别力完全一样。** 想提高判别力只能去读**另一个量**。
这直接否定了一类常见修题动作：分不开就去换更细的评分函数。

**第 6 条：它是目前样本量最大、且判定无争议的一条。**
重复查同一个确定性结果不带来任何新信息，所以 27.1% 这个数**不需要知道最优路径就能判**。
它同时提供了一个现有 reward 结构**表达不出来**的信号：
一份答卷浪费了 89% 的调用，只要最终答案对，终点 reward 与零浪费的答卷**完全相同**。
在制药场景下这个差别不是效率问题而是成本问题：每一次实验都是钱和时间。

**第 4 条：补批后改了主指标——“效应量守住了”不能当硬结论。**
补到两臂各 11 个样本后，效应量从 1.291 升到 **1.477**、精确置换 p=**0.012**。
**但这个“升”不能读作信号变强。** 无工具臂得分恒为 0、方差为 0，
效应量退化成只含通过率与样本量的闭式，**光加样本就会把它抬高**：
一条因超时被剔的样本结构上必然是 0 分、零信息，可光把它加进分母，效应量就从 1.477 涨到 1.514。
⇒ **原计划的验收目标（看效应量守不守得住）选错了指标**，已如实登记。

真正挣到的是另一件：**无工具臂那个 0 分是挣来的，不是被门禁判死的。**
该臂交出 60 个名额、**42 个不同分子**，命中合格集 **0** 个（底层比例 9.5%，随机期望应命中 5.7 个）；
且它在两扇独立于评分门的检查（零假阳性、外推）上同样全灭 ⇒ **删掉评分门它还是 0 分**。
坏消息一并报：差值除以噪声底只有 **1.22**，**弱于第 1 条里那个唯一过关的档间跳（1.70）**。

❗ 剔 run 的方向与“想让数字好看”相反：留着那条超时的是 1.514 / p=0.0046，剔掉是 1.477 / 0.0124。
照预先登记的机械判据剔，**不因为看到结果就重新解释判据**。

### 0.2.3 一条被自己数据否证的假设（如实登记）

曾推测“agent 会系统性地在该调工具的地方硬算”。拿 **1166 份答卷**离线重判：

| 结果 | 占比 |
|---|---|
| 报的实测值**有账本支撑** | **95.9%** |
| 凭空写（账本里没这次调用） | 2.0% |
| 调了但报的数与返回值不符 | 0.0% |
| 整个账本为空 | 2.1% |

⇒ **题面把“什么该测”说清时，agent 基本都照做了。** 该假设不成立。

但它与第 2 条那道题的现象并不矛盾，**差别在题面有没有把“什么该测”告诉它**：
材料侧那批题面明写了哪些能测、哪些测不了；而那道药物题四条轴都能测、要 agent 自己判断测不测，
它判断错了（该道题 12 份无工具答卷中 **11 份自报“四条全满足”、实算无一份到四条**，
其中 2 份交的分子化学软件根本读不出来）。

❗ **写下这条的另一个理由**：第一版检测器把工具名写错（找 `measure_tc`，而账本里实际是
`get_property(prop='tc')`），于是一个都没匹配上，脚本报出“**100% 凭空写**”。
那个数差一步就被用作立项依据。⇒ **任何“过于惊人”的统计结果，先怀疑检测器、再怀疑 agent**；
自查做法是先将账本里的工具名与参数键**枚举打印一遍**。

### 0.2.4 这些差异合起来指向的定位

本综述 3.2 已给出五条共同结论（严格完成 ≠ 部分进展、执行正确 ≠ 科学正确……）。
本项目的实测在它们之上多一层：

> 上面每一条“共同结论”本身，都需要先回答“这个差异超过重跑漂动了吗、声明的难度是真的吗、
> 分数是能力挣的还是记忆挣的”。**不先把这三件量清，任何横向比较都可能建在噪声上。**

因此本项目的产出不止于“又一个制药 benchmark”，而包含两层：

| 层 | 产出物 | 当前状态 |
|---|---|---|
| 测量层 | 制药任务上的 agent 能力分数 + **分数可信度的配套披露**（噪声底、逐子问题通过率、记忆占比） | 机制已立，单题已验 |
| 改进层 | 从任务结构反解最优路径 ⇒ 自动定位次优步骤 ⇒ 无需 teacher / 裁判的训练信号 | **方向已定，零实例，未验** |

改进层能否成立，取决于两件未验的事：① 最优路径能不能真的从题目结构解出来（目前判断：
**信息获取部分能，生成/决策部分不能**）；② 这类过程监督能不能**替代** reward、
而不只是给 reward 加一项。第②件目前无法论证，如实标出。

## 0.3 创新点到底有几条：按硬度分三类

上面七条差异**不是七个创新点**。按“别人有没有做过”与“我们验到什么程度”拆成三类，
**能当创新点讲的只有 A 类三条**；对外陈述时 B、C 两类不得当创新点用。

❗ **本节已按 §0.1.4 的更正重排。** 早先的版本把“报重跑波动”与“查无效调用”当作两个创新点，
那是错的：它们属于**做实验的质量控制**，不在项目目标那个层面上，而且“别人没报”不等于“别人没做”。
现行分类如下。

### 0.3.1 A 类：真的不一样、且有实测支撑（只有两条）

| # | 创新点一句话 | 硬在哪 | 自己的弱点（必须一并讲） |
|---|---|---|---|
| A1 | **把“推理 / 记忆 / 工具调用”的分离做成系统设计**：同一道题同一真值，工具供给三档 × 候选可见性两种 = 六格 | 别人（ChemToolAgent / ChemCrow）做的是“给工具 vs 不给”**两组对照**，只能回答“工具有没用”；六格是为了回答**“做对了是靠想、靠背、还是靠查”** | 六格已跑完的那批属**已作废评分范式**；现行两道新题只跑了两条臂，**三档一个 run 都没跑** |
| A2 | **从一开始就把“分数要拿去改模型”当设计前提**，而不是先做榜、事后再想怎么用 | §0.1.2 最后一列，别家基本是 ❌ 或 ⭕——能给逐条分，但那是为了**打分更细**，不是为了**训练** | 只做到一半：逐子问题分数已落盘，但“能定位到哪一步该怎么改”的信号**零实例** |

**为何只剩两条（而不是之前写的三条）**：原 A1（报重跑波动）与原 A3（查无效调用）已按 §0.1.4 降级为
**内部质量纪律**（见 §0.2）；原 A2（单调变换不改秩）仍成立但属**方法学纠错**，见下一小节。

### 0.3.2 B 类：方法学纠错与内部纪律（有用，但不是面向外部的创新点）

| 项 | 内容 | 为何不能当创新点 |
|---|---|---|
| 换更细的评分函数救不了分不开的题 | 底层量的**单调变换不改秩** ⇒ 非参检验 p 与效应量逐位相同。直接否定一类常见修题动作 | 是**限制性**结论（说什么没用），不提供新能力；属于避坑知识 |
| 报差值必报重跑波动（噪声底 0.18–0.29） | 拿它回溯自己，六个对比跳只一跳过关 | 别人不写进正文 ≠ 没做（§0.1.4）；这是实验基本功 |
| 查无效工具调用（27.1% 重复） | 样本量最大、判定无争议；且它是现有 reward 表达不出的信号 | 可能只是**效率**而非**能力**；且“记成本”已有多家在做 |
| 逐子问题通过率开跑前强制落盘 | 不先拆就会把“两臂都倒在同一条轴”误读成“工具没信息” | MatTools 逐条断言、PaperBench 逐条 rubric 已在做 |
| 定量记忆占比 | 等价变换测分数落差 | NewtonBench 反事实改写是**更强的防背手段**；我们只是目标不同，不是比它强 |

### 0.3.3 C 类：潜力最大但零实例（只能当方向讲）

**从任务结构反解最优路径，用作不靠 teacher / 不靠裁判的过程监督。**

为什么只有我们能做：因为**题是我们出的、真值是我们算的**，所以"最少几步能到"在造题时就知道，
不需任何模型来演示。拿现成数据集做不到这件事——**这也回答了"为何必须自己造 benchmark"**。

监督信号来源的三条路对比：

| 路子 | 监督从哪来 | 能力上限被谁锁死 |
|---|---|---|
| 模仿学习 / 蒸馏 | 人或更强模型的**演示** | 演示者 |
| 强化学习（含 GRPO 类） | 标量回报 + 自己探索 | 自己的探索空间 |
| **本项目设想的第三条** | **从任务形式结构反解的最优路径** | **不被任何模型锁死** |

形式关系：

$$L_{\min} \le N$$

其中：
- $L_{\min}$：完成这道题所需的**最少工具调用次数**（单位：次），由真值与题目结构在造题时确定性算出，**不由任何模型产生**；
- $N$：该题的**原子问题个数**（声明难度），原子问题定义为不可再分、最多一步工具调用、无任务依赖前置；
- 不等号由"最多一步工具调用"直接得出；若部分原子问题可纯推理解决，则严格小于。

⇒ **原子问题数目不只是难度标签，它同时是最优轨迹长度的上界、即过程监督的参照基线。**

❗ **两个硬边界，对外必须一并讲**：

1. **只能解出"信息获取"部分，解不出"生成/决策"部分。**
   实例：某道题能算出"先纯推理三条轴、再测第四条"，但"发现超标后该怎么改结构"的最优做法**我们不知道**——
   而那正是该题的真实卡点。
2. **尚不能证明这类监督能替代 reward、而不只是给 reward 加一项。**
   若最终只能落到"在现有回报里加一项冗余惩罚"，则仍属在别人框架里添东西，**不构成训练范式创新**。

### 0.3.4 对外陈述时的两句红线

| 不能说 | 可以说 | 理由 |
|---|---|---|
| "我们能让模型在制药任务上变强" | "我们已能自动产出改进所需的信号，下一步验能不能训进去" | 改进层**零实例**；训练栈未装，已判过分的轨迹约 23 条 |
| 拿"提升了多少"当卖点 | 先报噪声底，再报提升是否超过它 | 噪声底 0.18–0.29；小于它的提升读不出意义。**对内守这条，对外更要守** |

## 执行摘要

本报告把制药领域放在最前，先回答药物研发链条上“已有 Benchmark 在测什么、如何判分、哪些只是模型测试、哪些真正评价 Agent 工作流、哪些能够连接现实结果”，再用通用科研智能体评测框架解释这些工作的共同方法和能力边界。

当前制药 AI 评测已形成三层结构：第一层评价分子、蛋白、组学或临床数据上的模型与科研对象；第二层评价 Agent 是否能规划、调用工具并交付完整科研 workflow；第三层用时间后验、私有数据、盲法 assay、真实仪器或独立复验校准前两层。三层不能混成一个总分：更高的 docking、预测或生成分数，不自动等于更可靠的药物候选，更不等于完成了药物研发。

> 核心判断：制药领域真正稀缺的不是又一个静态单分数榜单，而是能够同时测量多轮实验选择、证据充分性、预算效率、负结果学习、工具冲突恢复和未见 target/scaffold/time 泛化，并最终由冻结审计或现实锚点裁决的 Agent Benchmark。

本报告得到六项结论：

1. 制药 Benchmark 应至少区分模型/对象级、Agent workflow 级和现实锚点级；还要单列逆合成、开放问题与生物安全，避免版图被“分子生成 + 生信分析”主导。
2. 科研 Agent Benchmark 不应只检查最终答案。更高可信度的评价必须检查代码和产物是否实际执行、多个结果是否一致、关键主张是否由真实证据支持，以及 Agent 是否会根据失败和冲突修正。
3. 下一阶段的竞争点将从“有没有过程分”转向“过程证据能否被独立验证”。关键 claim 应与工具回执、数据版本、形成时间、单位、条件和科学依赖绑定。
4. 严格 Pass、部分进展、成本和稳定性必须分开报告。60%-90% 的局部完成度仍可能对应零个可交付任务。
5. Harness、预算和反馈界面都是实验变量。只有固定基础模型、匹配计算预算、隐藏最终测试并从头重跑候选版本，才能把改进归因于可继承的系统资产。
6. 动态 Benchmark 可以作为课程和对手持续暴露能力边界，但不能同时充当最终裁判。最终主张必须落在 Frozen Audit、可信硬验证器或现实实验锚点上。

## PART I 制药领域 Benchmark 版图

### 1.1 三层评价结构

制药领域的 Benchmark 至少有三种含义。

| 层级 | 评测对象 | 典型输入与输出 | 主要裁判 | 能支持的主张 |
|---|---|---|---|---|
| 第一层：模型/科研对象 | 预测模型、分子、序列、结构、数据方法 | 性质、排序、生成结果、结构、预测值 | 固定 split、metric、oracle | 某个模型或对象在冻结任务上的性能 |
| 第二层：Agent workflow | 检索、分析、筛选、模拟、实验设计、报告交付 | 工具轨迹、代码、表格、分子、图、报告 | 执行器、任务 grader、专家 rubric | Agent 是否能可靠完成一段科研工作流 |
| 第三层：现实锚点 | 时间后验、私有数据、真实仪器、盲法实验 | 后续被证实的发现、实验结果、可执行协议 | 独立专家、时间后验、实验复验 | 代理评价是否具有外部效度 |

第一层可大规模自动化，第二层最能暴露工具编排和最后一公里问题，第三层成本最高却不可替代。合理的制药评测体系应让三层相互校准，而不是用一个代理指标替代全部研发价值。

### 1.2 按测试对象划分的十类制药 Benchmark

| 类别 | Benchmark 类型 | 主要测试内容 | 代表工作 | 判断 |
|---|---|---|---|---|
| I | 模型与科研对象级 | 性质预测、分类、排序、生成、结构合理性 | MoleculeNet、TDC、GuacaMol、GenBench3D | 标准化成熟，但不测 Agent 规划和工具使用 |
| II-A | 知识、文献与靶点情报 | 文献检索、图表阅读、数据库导航、靶点与竞争格局 | LAB-Bench、LABBench2、TRQA | 易规模化；公开答案和静态语料容易受污染 |
| II-B | 生信、多组学与研究判断 | RNA-seq、变异、因果估计、组学、数据质量与解释 | BixBench、BioAgent Bench、BiomniBench、GeneBench-Pro、SciAgentArena | 已能测真实数据和过程，但评分与工具版本复杂 |
| II-C1 | 分子生成与约束设计 | 文本到分子、约束满足、多目标设计 | GuacaMol、TOMG-Bench、SMDD-Bench | 目标清晰、易自动验证；容易优化代理函数 |

| II-C3 | 筛选与 Lead Optimization | 药效团、scaffold hopping、筛选、迭代优化 | MolBench、MolClaw、SMDD-Bench | 最接近药化决策，但多数反馈仍来自 oracle/proxy |
| II-D | 分子代码与模拟 | 可执行化学代码、MD 系统准备、自由能、增强采样 | MolViBench、MDGYM、MDArena | 物理与执行约束强，能识别未运行和伪造数值 |
| II-E | 蛋白与生物药发现 | 序列-功能、蛋白优化、专用模型与工具生成 | VenusAgentEval、VenusFactory2 | 系统级评测正在出现，公共标准化仍较弱 |
| II-F | 临床、EHR 与试验设计 | cohort、统计、EHR 建模、试验诊断和协议优化 | EHRFlowBench、ClinicalReTrial、LifeSciBench | 必须处理偏倚、因果、隐私和 surrogate exploitation |
| II-G/III | 开放问题、安全与现实执行 | 未决问题、忠实引用、诚实拒答、生物安全、机器人实验 | OpenBioRQ、ABC-Bench、AutoLabs、前瞻性 assay | 最接近现实风险和未知性，但成本高、样本小 |

### 1.3 第一层：模型与科研对象级基准

MoleculeNet、Therapeutics Data Commons、GuacaMol 和 GenBench3D 是制药 AI 的基础设施。它们分别覆盖小分子性质与 ADMET、全治疗研发数据任务、分子生成与目标优化、三维结构合理性。很多 Agent 系统仍把这些 metric 或 oracle 作为候选筛选器。

它们的限制同样明确：任务通常静态、可离线反复查询，scoring function 可能被直接投机；经典 split 不一定代表新靶点、新骨架和未来时间；最终分数也不包含合成失败、实验噪声、毒性、项目成本和真实决策。

| Benchmark | 规模与任务 | 如何测试 | 主要边界 |
|---|---|---|---|
| MoleculeNet | 17 个数据集、700k+ 化合物、800+ 子任务 | MAE、RMSE、ROC-AUC、PRC-AUC 等 | 部分 split 已老化；不测工具链 |
| TDC | 66 个数据集、22 类学习任务 | 冷启动、时间、scaffold split 与多类 oracle | 覆盖广但粒度不一，不能直接组成端到端 Agent 分数 |
| GuacaMol | 5 个分布学习任务、20 个目标优化任务 | validity、uniqueness、KL、FCD、目标函数 | 容易出现 proxy hacking，缺少合成与湿实验效度 |
| GenBench3D | 口袋条件 3D 生成 | 键长、键角、构象、松弛、docking 与 strain | 更物理，但仍不是实验结果 |

### 1.4 知识、证据与生命科学研究判断

LAB-Bench 主要测文献、图表、数据库和序列等生物学能力切片；LABBench2 进一步转向开放回答、专用 verifier、实验 protocol 错误注入和可执行 DSL。TRQA 把文献知识与药物研发竞争格局数据库结合，但仍以 QA 为主。

LifeSciBench 提供 750 个专家编写任务，覆盖七类 workflow、七个生物领域、1,062 个附件和 19,020 条 rubric。它的价值不只是规模，而是把研究请求、证据、决策、理由、限制和格式放进同一任务，并同时报告 task-level Pass 与平均 rubric 分。

GeneBench-Pro 用 129 个合成因果世界中的复杂计算生物学问题测“研究判断”：Agent 必须诊断数据、选择 estimand 和分析路径、迭代试验并作出下游决策。因为数据生成机制已知，评价器能对合理方法差异给出 acceptance region，同时通过消融拒绝科学上错误但数值偶然接近的路径。

OpenBioRQ 则走向另一端：它用无固定答案键的未决生物医学问题测检索忠实性、证据支持关系和 abstention。它提醒评测者：引用能打开不等于引用真正支持 claim；已知答案任务也无法充分测试面对未知问题时的诚实性。

### 1.5 生信、多组学和端到端数据工作流

BixBench、BioAgent Bench、BioMed-AQA、BiomniBench 和 SciAgentArena 将评测从知识问答推进到真实数据分析。Agent 需要处理文件、选择工具、写代码、运行统计并解释生物意义。高质量任务会注入 decoy、损坏输入、方法冲突和 prompt bloat，用来区分“结果能跑”和“科学结论成立”。

SciAgentArena 约有 200 个逐步验证的真实科学任务，并使用与 Agent 无关的交互环境。它与本地 evidence-state 方案高度相关：创新点不能只是 stepwise verification 或 DAG，而应落在 claim 级 provenance、路径等价、私有验证和评分器对抗测试上。

### 1.6 小分子设计、逆合成与闭环搜索

SMDD-Bench 把药效团识别、interaction point、scaffold hopping、lead optimization 和 fragment assembly 构造成保证可解的长程任务，并限制 oracle 调用。MolBench 更强调筛选、优化和完整 discovery workflow 的连续工具编排；TOMG-Bench 则通过通用化学属性函数验证文本到分子的约束满足。

逆合成应单列。URSA 测最多十步的化学感知路线规划；RetroAgent 在 AND-OR 搜索空间中利用结构化记忆做全局规划。该类任务不能只看是否生成一条路线，还应检查反应模板适用性、原料可购状态、路线终止条件、全局搜索覆盖和多路线多样性。

闭环搜索协议可借鉴 MADE：在受限 oracle 预算下循环 propose-evaluate-refine，并与随机、相似度、贝叶斯优化或传统搜索算法比较 anytime curve、best-so-far 和单位成本收益。虽然 MADE 面向材料发现，但其协议比一次性分子生成更接近真实药物优化。

### 1.7 分子代码、模拟、蛋白、临床与现实执行

MolViBench、MDGYM 和 MDArena 依赖真实执行而不是语言判断。它们检查代码能否运行、物理体系是否稳定、轨迹是否存在、结果是否来自真实计算，以及交付物之间是否一致。这类 Benchmark 说明，通用 coding 能力不会自动转化为可信的分子模拟能力。

VenusAgentEval、EHRFlowBench、ClinicalReTrial 和 AutoLabs 分别覆盖蛋白发现、EHR 研究、临床试验协议优化和机器人实验。越接近真实研发，越不能只依赖一个标准答案：必须检查数据适用性、统计设计、安全边界、硬件可执行性和专家判断。尤其是 ClinicalReTrial 的结局预测器只能视为闭环模拟评价，不能直接等同于临床有效性。

### 1.8 制药 Benchmark 的十大结构性缺口

| 缺口 | 当前表现 | 建议机制 |
|---|---|---|
| 阶段割裂 | 性质、设计、模拟、EHR 各自有分数 | 构造跨阶段任务，要求 provenance 和跨产物一致性 |
| 逆合成缺位 | 生成和筛选多，路线规划少 | 单列反应/逆合成，验证模板、原料、终止和路线多样性 |
| 代理-现实鸿沟 | docking、QSAR、预测成功率可被优化 | 独立 evaluator + 时间后验或盲法实验；报告 proxy-to-reality gap |
| 未知性不足 | 公开数据与论文可能被记忆 | target/scaffold/time split；pre-discovery 快照；prospective pool |
| 证据真实性不足 | 有引用或有工具调用不等于 claim 被支持 | claim-level provenance、来源真实性、支持关系与形成时间 |
| 缺少成本与延迟 | oracle 常被视为免费即时返回 | 统一记录 token、GPU-hour、wall-clock、assay slot 和货币成本 |
| 负结果学习薄弱 | 只奖励最优候选 | 行动前概率预测、Brier/NLL、surprise test、错误坚持长度 |
| 工具故障与恢复不足 | 超时、版本漂移、损坏输入被忽略 | fault injection、checkpoint、rollback、替代流程和 clean replay |
| 自进化归因不清 | 更好结果可能只是更多采样 | Compute-Scaled、Artifact-Only、Memory、Harness 修改的匹配预算对照 |
| 安全与合规 | 隐私、双重用途和不可逆实验缺少系统评价 | 最小权限、签名资产、审计 ledger、human gate 和生物安全任务 |

## PART II 科研智能体 Benchmark 的通用评测框架

### 2.1 先区分评测对象和证据强度

单一“成熟度阶梯”容易误导。开放研究不一定比可执行复现更成熟，Harness 优化也不是科学交付的自然上位层。建议用二维矩阵描述 Benchmark。

| 评测对象 | 典型输出 | 适用问题 |
|---|---|---|
| 答案与局部能力 | 答案、检索结果、排序 | 是否会检索、阅读、编码和调用工具 |
| 单一可执行产物 | 脚本、表格、单个结果 | 是否能把科学描述转成有效产物 |
| 多文件 workflow | 代码、图表、报告、数据包 | 是否完整满足任务合同 |
| 轨迹与证据状态 | 假设、证据链、belief update | 是否会验证、反驳、修正和诚实拒答 |
| Harness/训练算法 | prompt、tool、memory、代码和数据策略 | 系统本身是否会持续改进 |
| Evaluator/任务分布 | 动态任务、评价器和审计版本 | 选择压力是否可信、是否保持代际可比 |

证据强度则从规则/数值硬验证、实际执行、专家 rubric、时间后验逐步延伸到现实实验锚点。同一工作可能跨多个对象和多种证据强度。

### 2.2 七类评测范式

| 类别 | 名称 | 测试思想 | 代表工作 | 核心边界 |
|---|---|---|---|---|
| A | 知识检索与组件能力 | 把科研拆成检索、阅读、代码和分析子任务 | AstaBench、LAB-Bench | 易规模化，但离完整交付较远 |
| B | 可执行产物与复现 | 生成可运行代码或重建论文结果 | ScienceAgentBench、CORE-Bench、PaperBench、NatureBench | 多数是已知目标 |
| C | 端到端工作流与交付 | 从固定输入交付多文件 bundle | FrontierChallenge、MDArena、LifeSciBench 部分任务 | 最能暴露最后一公里，但任务议程已给定 |
| D | 开放研究与过程诊断 | 隐藏目标或只给高层问题，评价假设、证据和更新 | FIRE-Bench、ResearchClawBench、InquiTree、OpenBioRQ | Judge 复杂、泄漏和小样本风险高 |
| E | 闭环产物与工程优化 | 从次优初始产物出发反复执行和改进 | RE-Bench、AutoLab、Frontier-Eng、MADE | 适合测 persistence，不等于科学新颖性 |
| F | Harness、数据与训练算法自改进 | 把“改进 Agent 系统”设为任务 | HarnessOpt-Bench、Evo-Bench、AI4AI-Bench、RSIBench-Data | 必须固定模型和预算做归因 |
| G | Benchmark/Evaluator 共进化 | 任务或 evaluator 随能力变化 | Lean 共进化、Red Queen Gödel Machine | 动态课程不能成为最终自由漂移的裁判 |

### 2.3 横向评价基础设施

GLEAN、TRACER、ScienceBoard、NatureBench、Agents' Last Exam 和 BenchGuard 不应只被当成普通任务集，它们代表评价基础设施的不同方向。

- GLEAN 把专家指南编译成轨迹中的证据累积信号，并把不确定性用于主动补证。
- TRACER 将每个答案句与工具回合、证据单元和支持关系绑定，处理 claim-level provenance gap。
- ScienceBoard 直接读取科学软件或虚拟机内部状态，并用故意构造的欺骗状态测试 validator。
- NatureBench 强调论文筛选、逐任务容器、信息防火墙、隐藏测试和 maintainer-side reproduction。
- Agents' Last Exam 强调真实项目、专家与工程师分工、reference output 和滚动私有题池。
- BenchGuard 把任务描述、数据、grader、可解性和替代有效方案作为被审计对象。

### 2.4 进入协议设计前最容易混淆的三组概念

| 容易混淆 | 应如何区分 | 报告要求 |
|---|---|---|
| 任务难度 vs. 科学有效性 | 难题只能说明求解成本高；只有评价目标、证据与真实研究主张对齐，才说明有效性高 | 同时给出 hard-pass 指标与 construct-validity 说明 |
| 过程反馈 vs. 最终裁判 | 搜索期反馈可帮助 Agent 修正，但最终 Judge 必须隔离，避免把裁判信息变成训练信号 | 分开记录 feedback channel、hidden evaluator 和泄漏面 |
| 开放性 vs. 不可验证性 | 允许多条科学路径不等于没有边界；开放任务仍需定义允许主张、证据门槛和 abstention | 使用 claim-level 证据契约、替代解审查与 NO_SOLUTION |

因此，Benchmark 协议首先要写清“允许据此声称 Agent 会什么”，再决定任务形式和分数。否则越复杂、越开放的题目，越可能只扩大测量噪声。

## PART III 代表性 Benchmark 的测试协议

### 3.1 代表性工作横向比较

| Benchmark | 评测单位 | 搜索期反馈 | 最终裁判 | 真正测量 | 主要局限 |
|---|---|---|---|---|---|
| AstaBench | 11 个科研子 benchmark | 检索、notebook 与任务指标 | 子任务专用 grader | 受控环境下的组件能力和综合表现 | 总分可能掩盖端到端弱点 |
| ScienceAgentBench | 自包含 Python 程序 | 执行日志和错误 | 程序、数值与成本 | 科学描述到可运行分析代码 | 单文件目标，不是完整交付 |
| CORE-Bench | 论文结果复现 | 环境执行反馈 | 自动结果核验 | 环境处理和计算复现 | 已知结论，不测自主选题 |
| PaperBench | 整篇研究复现 | 代码运行 | 作者 rubric + judge | 长周期研究工程 | 成本高且仍受目标论文约束 |
| NatureBench | 论文衍生算法任务 | 容器执行、无网络搜索 | 隐藏测试和维护方复跑 | 在标准环境中达到或超过论文 SOTA | 可自动化论文只是科研子集 |
| FrontierChallenge | 多文件 workflow | 工具和代码反馈 | 任务 grader + Strict Pass | 是否完整交付研究合同 | 议程预先给定 |
| SciAgentArena | 逐步科学任务 | 交互环境和 stepwise feedback | 分阶段 verifier | 真实科学需求下的跨 Agent 对比 | 对 verifier 可信度仍需独立审计 |
| LifeSciBench | 专家研究请求 | 提示与附件 | 任务特定专家 rubric | 真实生命科学判断和交付 | rubric 成本高、Judge 需校准 |
| GeneBench-Pro | 合成因果分析世界 | 隔离 workspace 和数据 | 已知目标、容差和消融 | 模糊数据中的研究判断 | 合成真实性不等于现实外部效度 |
| FIRE-Bench | 科研 insight 重发现 | 实验结果 | insight 与证据对齐 | 自主实验和再发现 | 可能受记忆或检索泄漏 |
| ResearchClawBench | 隐藏论文再发现 | 原始数据和代码反馈 | 专家多模态 rubric | 论文级端到端再发现 | 等价新路径可能难评分 |
| OpenBioRQ | 未决生医问题 | 多轮检索工具 | 引用支持、忠实性、abstention | 面对无答案问题的证据诚实性 | 开放性判定和未来证据会变化 |
| MADE | 闭环候选搜索 | 受限 oracle | 稳定候选与效率曲线 | 预算下的自适应发现 | 仿真/计算代理与现实有距离 |
| HarnessOpt-Bench | Harness 版本 | dev/validation 分级反馈 | held-out normalized gain | prompt、tool、memory、control flow 改进 | seed 和下游任务决定难度 |
| AI4AI-Bench | 训练算法源码 | proxy metric | sealed rerun + hidden metric | 是否改变模型如何学习 | 训练成本高、proxy 可被利用 |

### 3.2 共同结论

严格完成与部分进展是不同变量。FrontierChallenge、MDArena、AstaBench 和 LifeSciBench 都表明，高部分分不等于可交付；必须同时报告 Strict Pass、平均进展和跨产物一致性。

执行正确不等于科学正确。代码能跑不保证物理稳定、统计方法合适或主张由证据支持。语法/执行、科学过程、证据和最终结论必须分层评价。

Harness 是重要实验变量。同一个基础模型在不同 coding harness、工具接口、上下文策略和恢复机制下可能排名反转。报告必须把 model × harness × budget 作为完整配置。

长程能力需要 anytime evaluation。只看 final submission 会错过中途最佳版本，也无法区分高效发现和最后一刻偶然命中。应报告 best validated utility 随累计成本变化的曲线。

LLM-as-judge 必须被视为测量仪器。需要专家校准、重复判分、对抗样例、置信区间和硬检查组合，不能把 Judge 输出当成无误真值。

### 3.3 高质量 Benchmark 的最低披露要求

| 要素 | 最低内容 |
|---|---|
| 研究主张 | 明确最终允许支持的能力主张及不能支持的主张 |
| 任务 lineage | 来源、时间戳、许可、去重、污染与已知泄漏 |
| 评测单位 | 答案、产物、workflow、证据状态、Harness 或 evaluator |
| 可修改边界 | 文件、prompt、tool、memory、模型和 evaluator 的权限 |
| 执行环境 | 容器、工具版本、数据库快照、网络、硬件、随机种子和超时 |
| 预算 | token、调用、实体查询、GPU-hour、wall-clock、提交次数和并行度 |
| 评价器 | 硬检查、rubric、Judge 配置、专家一致性与攻击测试 |
| 分数语义 | Strict Pass、部分进展、成本、稳定性和置信区间分报 |
| 轨迹与产物 | 中间 checkpoint、工具回执、final artifacts、失败标签 |
| 版本治理 | 版本号、bug 修复、任务失效、重跑范围和 grader 开放程度 |

## PART IV 面向制药 Agent 的 Benchmark 建设方案

### 4.1 研究定位

建议把项目定位为 evidence-grounded scientific agent evaluation，而不是泛称自动科学发现 Benchmark。隐藏已知实体的任务最多属于“受限发现”或“隐藏目标重发现”；只有当问题或关键反馈在系统冻结后产生，并由独立现实评价验证，才支持更强的未知发现主张。

> 潜在创新不在于首次使用 GT-first、checkpoint DAG 或过程评分，而在于构建跨药物与材料任务复用的 evidence-state benchmark compiler：从需求、候选宇宙、性质定义和证据依赖生成结构化答卷、工具绑定和私有 verifier；允许路径自由与替代证据，同时用因果式攻击验证评分器的辨识力，并用隐藏论文、未来时间段或前瞻性实验校准外部效度。

### 4.2 本项目的位置与创新点

> 已整块前移到文档开头的**速读区 PART 0**。此处不重复，避免两处维护而漂移。
> 见 §0.1（别人怎么做）、§0.2（我们怎么做）、§0.3（创新点按硬度分三类）。

### 4.4 三赛道 × 四生命周期

任务类型和数据生命周期应正交设计。

| 赛道 | 测什么 | 主要任务 | 主要裁判 |
|---|---|---|---|
| 确定性主榜 | 证据充分的约束判断、排序和无解 | 约束满足、约束最优、信息不足 | 私有冻结 universe 上的 hard verifier |
| 隐藏重发现榜 | 预算下的自适应搜索 | 时间切分、隐藏目标、有限 oracle | 命中、regret、AUDC、成本、证据链、诚实性 |
| 开放真实性校准集 | 主榜分数是否代表真实科研可靠性 | 隐藏论文、未公开课题、前瞻性 target | 专家 rubric、时间后验、实验复验 |

| 生命周期 | Agent 可见性 | 用途 | 是否允许变化 |
|---|---|---|---|
| Evolution Pool | 可反复运行，完整反馈 | 生成失败簇、训练和 Harness patch | 可受控进化 |
| Gate Pool | 任务和 evaluator 隐藏，提交有限 | 候选晋升、拒绝和回滚 | 只能按治理流程更新 |
| Frozen Audit | 全项目不可见，最终极少运行 | 论文主终点和 OOD 泛化 | 永久冻结 |
| Reality Anchor | 时间后验、私有数据、盲法实验 | 校准代理评价器与外部效度 | Agent 和 Evolver 不可修改 |

红线：任何能读取 Frozen Audit 或 Prospective Pool 的进程，都不能参与 Harness patch、任务生成或父代选择。动态任务是 Curriculum/Challenger，不是最终 Judge。

### 4.5 v1 核心任务族

先做四个 task family、每类 10-20 题的 pilot，不提前锁死总题量。pilot 后再依据属性交集、独立实体族、专家预算、效应量和重复运行方差扩容。

| 任务族 | 核心未知 | Agent 动作 | 主要指标 |
|---|---|---|---|
| 多目标 Lead Optimization | 活性、选择性、ADMET、SA 和新颖性冲突 | 修改分子、调用多个 proxy、请求 assay、更新 Pareto | DE-AUC、Pareto hypervolume、约束满足率 |
| Scaffold Hopping | 保持机制同时摆脱 IP/毒性约束 | 药效团抽取、生成新骨架、验证相互作用 | 新 scaffold hit、机制保持、相似度约束 |
| Budgeted Hit Discovery | 大库、少量实验位、模型不确定性 | 分批选择、探索/利用、迭代模型 | enrichment、hit/assay、信息增益/成本 |
| Mechanism Discrimination | 多个竞争机制解释当前证据 | 选择区分性实验、预注册预测、更新后验 | 机制识别、Brier/NLL、实验信息值 |
| Tool Conflict & Recovery | docking/QSAR/MD/文献冲突或 assay 伪影 | 交叉验证、复验、降权、回滚和替代流程 | 错误检测、恢复率、无效依赖清除 |
| Retrosynthesis Planning | 多条路线、原料和反应条件存在不确定性 | 搜索 AND-OR 图、验证模板和原料、比较路线 | 成功路线、成本、深度、多样性、全局覆盖 |

### 4.6 Evidence-state 证据契约

checkpoint DAG 应升级为 evidence-state dependency graph。每个关键节点至少包含：

- `claim_id`：要成立的科学主张；
- `evidence_requirements`：必要证据和允许的替代证据；
- `provenance`：工具、数据集、版本、实体、字段、单位、条件和回执 ID；
- `claim_time` 与 `evidence_time`：拒绝先猜答案、事后补证；
- `dependencies`：claim 成立前必须已有的证据状态；
- `uncertainty`：区分 fail、missing、conflict、unknown 和 not-applicable。

评分检查“结论形成时是否已有充分、真实、及时的前置证据”，而不是匹配唯一工具序列。无依赖步骤可以换序、并行或回退，合法替代工具应通过。

过程分建议拆成六个维度：Outcome、Evidence、Dependency、Search、Honesty、Efficiency。主论文优先报告多维 profile；总分只作辅助。

### 4.7 评价器栈

| 层级 | 评价内容 | 实现示例 | 修改权限 |
|---|---|---|---|
| L0 硬验证 | 结构、格式、化学价态、执行、预算、引用真实性 | RDKit、schema、container exit、cost ledger | Evolver 永不可修改 |
| L1 计算代理 | potency、ADMET、MD/FEP、选择性、SA、新颖性 | 多模型 ensemble + uncertainty | 只能新增辅助 evaluator |
| L2 科学质量 | 可证伪性、证据链、负结果、校准、替代解释 | 确定性轨迹检查 + 专家 rubric + 抽样盲评 | epoch 内冻结 |
| L3 现实锚点 | 时间后验、私有数据、盲法 assay、外部复验 | 新 scaffold hit、正交 assay、独立实验室 | 绝对不可修改 |

### 4.8 评分器攻击测试

Evaluator 本身必须像模型一样接受系统评测。至少生成以下攻击轨迹：

- 只查询猜中的 gold；
- 缩小候选池并伪造高 coverage；
- 先给结论再事后补证据；
- 调用工具但结论没有引用返回值；
- 答卷数值与工具回执不一致；
- 伪造 evidence ID；
- 批量调用绕过预算；
- 故意不查询强竞争者；
- 用极端 decoy 操纵归一化；
- 永远报 NO_SOLUTION；
- 只挑最好一次 run 上榜。

还要生成“应当不降分”的合法对照：无依赖节点换序、合法替代工具、并行执行和失败后回退。论文应报告攻击识别率、合法变体误杀率，以及单因素攻击是否只影响对应分轴。

### 4.9 公平对照与统计

| 实验臂 | 允许变化 | 排除的替代解释 |
|---|---|---|
| A0 Static | 固定模型和 Harness | 基础性能参照 |
| A1 Compute-Scaled | 与自改进组匹配 token、并行、工具和 wall-clock | 排除只是更多计算 |
| A2 Artifact-Only | 可优化分子/假设/协议，但不能改 Harness | 隔离任务内搜索收益 |
| A3 Memory/Skill | 可写跨任务经验，核心代码和拓扑固定 | 区分记忆与可执行自修改 |
| A4 Harness-Fixed-Tasks | Harness 可改，任务分布固定 | 测 Harness 自修改本身 |
| A5 Harness-Dynamic | Harness 可改，受控 Challenger 在 epoch 边界更新 | 测动态课程对冻结泛化的增益 |
| A6 External Meta-Agent | 强外部 coding/meta agent 优化弱系统 | 估计可达上限 |
| H Human | 专家使用相同工具与实验位 | 提供现实参照 |

所有配置尽量运行同一批任务，至少重复三次；按 template family 和 entity root 做 cluster bootstrap；报告任务级配对差异、置信区间和 model × harness 排名反转。Strict Pass、部分分、成本和稳定性分开报告。

### 4.10 任务生产与专家流程

1. 先定义允许支持的研究主张、候选宇宙、硬约束、目标函数和预算。
2. 建立数据注册表，冻结版本、单位、条件、缺失值、冲突处理和许可证。
3. 在 task-family 层定义 claim、必要证据和替代证据，再批量实例化。
4. 先按 scaffold、材料体系、模板族、数据源或时间分组切分，再调模板和 verifier。
5. 每题运行 schema、reference solver、隐藏路径、负例、污染和可解性检查。
6. 数据审核者、领域专家、盲做者和 validator 红队分工；开放题、无解题、跨库 JOIN 和边界题全部深审。
7. 冻结后记录版本、hash、变更原因、受影响结果和重跑政策。

## PART V 结论与选型建议

### 5.1 按研究问题选择 Benchmark

| 研究目标 | 优先参考 | 必须注意 |
|---|---|---|
| 科研组件能力 | AstaBench、LAB-Bench/LABBench2、TRQA | 统一工具与语料并报告成本 |
| 可执行科研产物 | ScienceAgentBench、CORE-Bench、NatureBench、MolViBench | 优先硬执行和数值检查 |
| 专业工作流交付 | FrontierChallenge、LifeSciBench、SciAgentArena、MDArena | 同时报 Strict Pass、部分分和一致性 |
| 开放研究与再发现 | FIRE-Bench、ResearchClawBench、InquiTree、OpenBioRQ | 区分记忆、检索泄漏和真正 inquiry |
| 受预算闭环发现 | MADE、SMDD-Bench、Lead Optimization 环境 | 报 anytime curve、传统算法基线和 oracle 成本 |
| 证据与评价器可信度 | GLEAN、TRACER、ScienceBoard、BenchGuard | 做 claim 绑定、校准和对抗测试 |
| Harness 是否会变强 | HarnessOpt-Bench、Evo-Bench | 固定模型、匹配预算、隐藏最终测试 |
| 递归自我改进 | AI4AI-Bench、RSIBench-Data、PAST-Bench | 使用 Reset、Swap、Reversal 做归因 |

### 5.2 最终判断

制药领域最值得建设的不是覆盖全链条的单一总榜，而是一个以多目标 Lead Optimization 为主干、以证据状态和预算搜索为共同协议的多轨评测系统。确定性任务负责稳定测量，隐藏目标题测自适应搜索，开放问题与时间后验任务校准未知性，前瞻性 assay 负责最终外部效度。

通用科研 Agent 评测正在从“能不能答题”转向“能不能可靠完成研究合同”，再转向“能不能在可执行反馈下持续改进自身”。决定可信度的核心不是任务看起来多真实，而是评价边界是否清晰、证据是否真实、反馈是否隔离、预算是否公平、产物与轨迹是否可审计，以及评价器能否经受投机攻击。

## 附录：新建 Benchmark 一页检查清单

| 检查项 | 最低要求 |
|---|---|
| 研究主张 | 写清允许与不允许支持的能力结论 |
| 评测单位 | 明确答案、产物、workflow、证据状态、Harness 或 evaluator |
| 可修改边界 | 列出 Agent/Evolver 能和不能修改的资源 |
| 数据划分 | Evolution、Gate、Frozen Audit；真实科研再加时间或 Prospective |
| 可解性 | reference solution/witness 必须通过；开放题与硬评分题分开 |
| 执行真实性 | 容器、工具、数据库、网络和硬件固定；结果必须真实执行产生 |
| 证据契约 | claim、provenance、时间、单位、依赖和替代证据可验证 |
| 公平预算 | 模型、工具、token、GPU、wall-clock、并行和提交次数匹配 |
| 稳定性 | 多随机种子、任务配对、cluster bootstrap 和置信区间 |
| 归因 | Compute-Scaled、Artifact-Only、Memory Reset、Harness Swap、Reversal |
| 防投机 | 隐藏 final evaluator、预算防绕过、攻击轨迹与合法等价路径 |
| 发布治理 | 版本号、changelog、任务失效政策、重跑范围和审计记录 |
