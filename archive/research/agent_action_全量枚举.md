# Agent Action 全量枚举

> 三领域 × 三类（infer 要测 / acquire 调工具 / 固有不测），共 **44** 个动作（见文末总账；表头旧写 43，已更正）。
> 本表是"组合 trace → 反推 query 类型"的地基，每条边对应一类 query。
>
> ⚠️ **一个 action ≠ 一种能力（2026-08-25 更正，原文写的是"考一种能力"）**：
> action 是**题材**（做哪种操作），能力是"具备与不具备时行为差在哪"。**同一个 action 可以由
> 背诵 / 穷举 / 推理三条路走完，且分数一样** —— 所以**从本表挑编号不等于锚定了能力**。
> 实证：`layer_01` 从 #4「层型变」出发造题、归位干净、数据也实跑验过，
> 结果零数据裸答 **0.952** 反超 123 个真跑 run 的 **0.602**。
> ⇒ 造题必须先过 **`BENCH_SPEC.md §2 闸0`**（写下能力四条），本表只在闸1 用来登记编号。

## 一、infer 类（我们要测的科学推理能力）

## 两个落地缺口（如实标注）

| 缺口 | 说明 |
|---|---|
| **结构改动后查不到性质** | edit_molecule 能改结构，但改完的性质库里没有——除非补"现场算性质"的 oracle 或限定改动结果在库内已有实体 |
| **基因领域 10 个动作里 9 个无数据** | perturb-seq/表达谱/突变-表型全空；只有 #26（药物-基因关联）靠 BindingDB+UniProt 勉强可做 |
| **逆合成规划（#44）无数据** | 需反应数据库，现有 backend 无；同基因类，动作成立但数据缺 |

## 明确不列入 action 的三类（owner 裁定，防混）

以下三类看似像 action，但**不是 agent 在世界里做发现时迈的一步**，不得当 action 枚举：

| 看似的 action | 为何不是 | 它实际是什么 |
|---|---|---|
| 轨迹诊断（读别人 trace 挑错） | 把 agent 当**评委**，不是它自己做发现（ProcessBench/TRAIL/PRM800K 都是这路） | 另一类 benchmark（评判力），不在本项目范围 |
| 稳定性 pass^k（同题跑 k 次全过） | 是**判分口径**，套在 goal/评分外层，不是世界里的一步 | goal/评分机制的一部分 |
| 反应顺序推理（排基元步骤先后） | 要么是**化学知识对不对**（自然界客观顺序）、要么已并进 #44 逆合成 | 不单列；属化学知识或逆合成的一个侧面 |
