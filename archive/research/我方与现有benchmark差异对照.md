# Agent Benchmark：测什么，怎么测，我们立足点在哪里



## 总述（too long to see）
现在的任何 agent benchmark 都在下面的矩阵中组合产生，没有例外：

### 1. 测什么
| 三类动作 | 测试的什么能力 | 
|---|---|
| infer | 科学推理，是 agent 本身的思维推理能力，不借助任何外部工具，比如联想能力，根据分子结构推断相似性质分子的能力等 | 
| acquire | 和外部交互的能力，即获取外部帮助的能力，比如做实验，查文献等自身能力受限不能解决的问题 |


### 2. 怎么测

| 维度 | 问的是什么 | 分几档 | 
|---|---|---|
| 结果验证强度 | 输出答案的可验证度，输出数字，输出程序就是强；输出非直接可得分的就是弱 | 强 / 弱 |
| 问题范式 | 题目给不给候选名单，agent 是从题目中选一个好答案，还是从题目要求中探索出一个好答案 | 生成式不给 / 判别式给 | 
| 中间 check 点强度 | 除了终答，中途判不判，如果判，是哪种程度：类似 GUI 这种是有强状态点，比如一定按过某个按钮，这是状态切换的标志，这是强；类似终答有小得分，比如 credit 消耗，或是人工分成若干个子程序做验证，这是弱，本质还是对终答的另一种衡量 | 强衡量 / 弱衡量 |
| 工具供给 | 如果没有工具，就是测的agent 的纯 infer 能力，如果有工具，根据工具强弱，多少，又可以分，如果是基本工具，那么完成任务的难度显然更大，如果是强工具，那么本身工具调用可以替代一部分 agent 的 infer 思考，自然难度降低，这时更多的考察的是 agent 会不会调工具，类似于 AI 搜的形式，却弱化了infer 能力| 强推理少 / 弱推理适量 / 强工具多 | 

### 我们的立足点在哪
- 首先我们既然是 agent benchmark，自然就不能违背这两个矩阵，这是毋庸置疑的，所谓创新的领域其实也必须框在这里面
1. 分阶段验证：首先我们要明确构建 benchmark 是有难度之分的，这个难度之分最显然的是在 tools 的提供上，所以我的想法是首先给 agent 提供必要工具，比如调研文献，提交答案这两个工具，如此，agent 在
做任务的时候遇到的一切问题都必须通过 infer 能力解决而不能通过 acquire，在对一个 query 得到对应的 case 之后我们可以去分析其在哪里会经常失败，理想中其可能会在推断分子性质，推断分子结构上失败，如此，
我们可以提供给其一个对应的 tools 来解决这个问题，也就是同样的 query，我们有不同难度的setup，区别就是工具的不同
2. 任务多样化： 我们的任务有 fixed 和 open 任务之分，所谓 fixed 指的是判别式任务，答案就在题面上，agent 去找到它，open 任务指的是同任务但是去除题目中的候选，属于 open 任务，并且这里我们会将 agent 可以访问的数据库（查性质，查结构等）
分为两类，A 和 B，A 是 agent 可以看的，B 是不可以看的，且 gt 在 B 里，agent 只能通读 A 的内容推断出在 B 里的 gt
3. 如果要强 check 中间点，必须有 state 的转换，这时候可以递归构建问题，比如问题 1 的答案是问题 2 的输入且问题 2 必须依赖问题 1，这样才能构建强中间 check 点，但是这个推迟，先构建原子的 state 评测再做后面的递归组合

- 之前说的 mock 掉分子，这不可行，没有一个 benchmark 这么做了，之前将其视为创新是不对的，因为这是个伪命题，如果 agent 看不到分子结构，那么其无法做有效的推理，如果看到了分子结构，那么只对元素做 mock 没有任何作用，mock 程度太小，基本没用
- 我们现在能做的还是弱中间 check 点验证，因为我们没有可强验证的中间锚点，只能通过类似 credit 消耗，是否过了毒性，温度这些小关来看分数，之前说的看其输入和后续的 action 是否有对应关系是否有推导关系我觉得不可行，这本身正好打在了 agent 的自由动作上，让任何妄图测
agent action 的 benchmark 都将失败，因为其无法枚举所有 action，也不知道 agent 是否有其他 actions 可以完成目标，有中间 check 的必须要有固定的状态转换锚点，不达到这个状态点就无法达到目的，本质上所谓的没有中间 check 点的benchmark 所测的都是原子 state，也就是从头到尾是一个 state，没有 state 的转换，自然就没有锚点

### 原则点
- 我认为所有用 llm 作judge的都是伪 benchmark，不可参考不可用，是伪科学
- 我认为我们做 benchmark 本质上是在做新时代的 loss 函数，旧时代的 loss 函数是为全局做梯度下降而用的，是一个标准值，来衡量本次执行效果与真实值的偏差，因为之前的 model 的输入输出都是规范化的，
输出一般都是强验证，所以 loss 值的设计更多的聚焦在不同的计算 trick 上，但是新时代的 loss，也就是 agent 的 loss 本身第一步就是难点：
如何拿到一个可以数字化衡量的 loss，这将是我们能否复用之前的所有训练经验的一个基石，在我看来，未来的 agent 训练范式一定是 agent 在一个 benchmark 上活动，得分，反传，更新，后面的一切都是
可以做自动化的，唯独构建这个 benchmark 是一个需要大量人工介入的工作
- 我认为一个好的 benchmark 的标准是立足在 业务目标精准描述 + 测的  agent 能力点清晰对应 + 有中间值可判断。为此我们构建 benchmark 其实是在构建一个更高维度的 world，我们希望我们
可以洞悉在这个 world 里发生的一切事情，可以解释这里发生的一切事情，这里的物理定律和世界运行规律由我们自己定义，我们属于更高维度的全知者，这是很重要的，因为只有这样，我们才能对
agent的所有 action 做充分的分析和解释，才能拿到其失败的原因和做 train dataset 的针对性构建

# 第一章 测什么：29 个科学推理动作

不知道测什么，讨论怎么判就是空的，所以能力层放在判分层前面。全量清单见 [`agent_action_全量枚举.md`](agent_action_全量枚举.md)，这里只提炼进入判分设计的部分。

## 1.1 三分法：一个动作只有三种命运

把 agent 做科学发现迈的每一步拆开，逐条可数 44 个动作（枚举文档开头写 43、总账写 44，两处不一致，这里按逐条可数的 44 计），每个只落进三类之一：

$$\text{动作} \in \underbrace{\text{infer}}_{29 \text{ 个，要测}} \ \cup\ \underbrace{\text{acquire}}_{9 \text{ 个，给工具}} \ \cup\ \underbrace{\text{固有 infer}}_{6 \text{ 个，留痕不算分}}$$

其中：

- infer，29 个，科学推理，科学家在纸上和脑子里完成的。这是判分对象，checkpoint 判的就是这些动作做对没有；
- acquire，9 个，从外部世界拉新信息，科学家得离开书桌才能拿到的。这是给工具的位置，但不判「会不会调工具」本身；
- 固有 infer，6 个，包括决定停不停、决定换方向、决定优先级、规划整体策略、自我纠错、上下文总结。它们出现在轨迹里，checkpoint 不判。

固有 infer 不测，不是因为不重要，是判不硬。「决定换方向」太自由，没法形式化；「自我纠错」有价值但太软；「上下文总结」是 LLM 通用能力，不是科学特异能力。这跟第二章维度三的立场一致：只判能硬判的，判不硬的宁可不判，不拿 LLM 裁判凑数。

三分法和「给不给工具」的判据是同一件事。ADR-0025 的科学家代入判据是：

$$\text{给工具} \iff \text{这一步是查资料或做实验} \iff \text{这一步属于 acquire}$$

所以 action 枚举不是另一套东西，它是维度四判据的动作级展开：把「哪些步骤该给工具」这个抽象判据，逐条落到 44 个具体动作上。

## 1.2 infer 的三种型：结构改动、趋势外推、机理推理

29 个 infer 动作按领域分四组（材料 8、药物 9、基因 10、跨领域 2），但按推理类型只有三种，这三种才是判分要区分的：

| 型 | 在问什么 | 材料域例子 | 药物域例子 |
|---|---|---|---|
| 结构改动 | 改这里会怎样 | 把 A 位换成同族元素看 Tc 怎么变；从单层钙钛矿改双层 | 给分子加一个官能团看 ADMET 怎么变；甲基换乙基 |
| 趋势外推 | 顺着规律往下推 | 铜氧化物系列里 Tc 随成分的走向 | 同系列 logS 走向，推该往哪改 |
| 机理推理 | 从性质反推该避开或该改什么 | 高压与常压跟 Tc 的关系；判该材料属不属于已知超导家族 | hERG 心毒高则避碱性氮；bbb 值定适不适合中枢药 |

三型统一成一句话：结构与性质之间的因果推理。ADR-0025 §5 用三类题分别测它的三个侧面：约束满足题测把科学目标翻译成可验证的性质判据，约束优化题测多个目标冲突时如何权衡，外推发现题测从一组同族分子的性质趋势归纳规律再外推。

外推型最能说明我方为什么不给编辑工具。它给若干同族分子及其实测值，要求顺趋势推出下一个。有编辑工具也没用，因为工具不告诉你方向，方向必须靠归纳得出。

## 1.3 acquire 的实际收缩：从 9 个减到 2 个

action 枚举列了 9 个 acquire 动作，ADR-0024 与 ADR-0025 逐条判掉了其中 7 个。这是枚举文档与现行 ADR 之间必须讲清的一处冲突：

| # | acquire 动作 | 枚举时的状态 | 现行裁定 |
|---|---|---|---|
| 29 | 查实体性质 `get_property` | 已上线 | 保留（做实验）|
| 31 | 查文献 `literature_search` | 已上线 | 保留（查资料）|
| 30 | 查实体结构或存在 `get_entity` | 已上线 | ADR-0025 删：返回的规范写法、分子式、原子数全能从 SMILES 确定性算出，属机械计算 |
| 32 | 查存在性 `check_molecule_exists` | 已上线 | ADR-0024 删：内化进 `get_property` 兜底 |
| 33 | 改结构生成新实体 `edit_molecule` | 已上线 | ADR-0024 删：agent 自己改 SMILES 再查 |
| 34 | 规范化结构 `normalize_structure` | 已上线 | ADR-0024 删：内化进各工具，agent 不感知 |
| 35 | 查结构邻居或同系列 | 需新建（「顺藤摸瓜」那根藤）| ADR-0025 判不给：「下一个更可能的分子是谁」是科学家的判断 |
| 36 | 查结合亲和力 `predict_binding` | 待实现 | 未进当前工具集 |
| 37 | 查靶点身份或结构 `validate_target` | 待实现 | 未进当前工具集 |

收缩的后果得正面写。acquire 从 9 个减到 2 个（加上交卷动作共 3 个工具）之后，infer 的结构改动型失去了执行载体：agent 要改结构，但没有编辑工具，只能自己写 SMILES；改完要查性质，但库里没有新分子的性质。这正是 action 枚举登记的缺口一「结构改动后查不到性质」。

这条链的完整逻辑是：

$$\text{action 枚举列出能力} \ \to\ \text{ADR-0025 按判据砍工具} \ \to\ \text{部分能力暂时无载体} \ \to\ \text{ADR-0026 用三档套卷把砍掉的工具当消融变量收回}$$

被砍掉的那批工具（编辑、变体枚举、邻居检索、排序）正是 ADR-0026 便捷工具候选池的全部来源。它们在困难档被排除，因为它们替代推理；这个性质使它们成为低难度档的天然素材。砍工具与三档套卷不是两件事，是一件事的两半。

## 1.4 明确不列入的三类

owner 裁定有三类东西看似是 action，但不是 agent 在世界里做发现时迈的一步，不得当 action：

| 看似的 action | 为何不是 | 它实际是什么 |
|---|---|---|
| 轨迹诊断（读别人的轨迹挑错）| 把 agent 当评委，不是它自己做发现 | 另一类 benchmark（评判力），不在本项目范围 |
| 稳定性 pass^k（同题跑 k 次全过）| 是判分口径，套在评分外层，不是世界里的一步 | 评分机制的一部分 |
| 反应顺序推理（排基元步骤先后）| 要么是化学知识对不对（自然界客观顺序），要么已并进逆合成 | 不单列，属化学知识或逆合成的一个侧面 |

第一条排除了四家看起来最像的 benchmark。ProcessBench、PRM800K、TRAIL、Who_and_When 在判分机制上跟我方最像，都判中间步骤对错、都是强衡量正确性型。但它们全部是轨迹诊断：ProcessBench 从数学推理链里标出最早错误步，PRM800K 做了 80 万条人工步级标注，TRAIL 从冻结的轨迹里事后标注错误片段，Who_and_When 对多智能体失败轨迹做 (who, when, why) 三元组归因。

被测对象根本不同：它们测模型会不会挑错，我方测模型自己做得对不对。所以第三章统计出的 7 家强衡量正确性型里，只有 3 家（PowerAgentBench、LongProc、TRACER）与我方可比，而其中只有 PowerAgentBench 判的是科学结论本身。

第三条也有后果。我方 ADR-0021 的顺序判定判的是 agent 执行动作的先后（先查了性质才能筛选），不是化学反应的客观先后。FukuyamaBench 判的是后者，属化学知识题，与我方不是一回事。

## 1.5 能力覆盖的真实边界：29 个动作里只有 19 个有数据

这一节决定了论文能声称的覆盖范围。

| 领域 | infer 动作数 | 有数据支撑 | 缺口 |
|---|---|---|---|
| 材料（超导）| 8 | 8 | 无 |
| 药物（小分子）| 9 | 8 | 逆合成规划无反应数据库 |
| 跨领域 | 2 | 2 | 无 |
| 基因 | 10 | 1 | perturb-seq、表达谱、突变-表型全空，仅药物-基因关联勉强可做 |
| 合计 | 29 | 19 | — |

三条缺口得如实标注：

1. 基因领域 10 个动作里 9 个无数据。后端库 92,153 实体只覆盖超导材料与小分子药物两侧，基因一侧是空的。对外不得声称覆盖三领域，只能说两领域；
2. 逆合成规划无数据。它需要反应数据库（什么反应能把 A 变成 B），现有后端没有，因此无法与 URSA、RetroAgent 在同一任务上对比；
3. 结构改动后查不到性质。编辑工具能改结构，但改完的分子性质库里没有，除非补一个现场算性质的 oracle，或者限定改动结果落在库内已有实体上。这一条直接关系到 ADR-0026 §9 登记的困难档可解性风险：如果外推题要求 agent 提出库外新分子，它永远拿不到性质反馈。

# 第二章 四维坐标系：一个 benchmark 必须做的四个选择

## 2.1 为什么恰好是这四维

一个 benchmark 的设计者，从头到尾只需要回答四个问题：

$$\text{范式} = \langle V,\ P,\ M,\ T \rangle$$

其中：

- $V$（Verification）怎么确认答案对了。机器能独立判定，还是得请人或大模型来看；
- $P$（Paradigm）答案从哪来。题目给一份候选名单让 agent 挑，还是让它从零构造；
- $M$（Measurement）判几个点。只判交卷那一下，还是中途也设关卡；
- $T$（Tools）给几件工具。工具越多，agent 自己要想的越少。

这四个问题相互不能替代：知道了怎么判终答，不等于知道要不要判中途；知道了给多少工具，不等于知道答案空间是开的还是闭的。所以它们是四个独立的选择维度。

$$\text{全部可能的范式数} = |V| \times |P| \times |M| \times |T| = 2 \times 2 \times 4 \times 3 = 48$$

其中 $|M|=4$，是因为强衡量还要再分两型（进度型与正确性型，见 §2.4），这一层是 owner 原定义里缺的，也是我方的落点。实测 65 家只占了这 48 格里的一小部分（§3.2 给出空格清单）。

四维之外还有第五件事：题目会不会被作弊、被背出来。它不影响怎么判，只影响判出来的分可不可信，属效度问题而非范式问题，单列在第五章。

## 2.2 维度一 · 结果验证强度

owner 原定义是「强＝代码、真值；弱＝看最终状态跟最初状态的 diff（搬箱子、GUI 购物）」。这个分界得改：真正的分界不在看不看状态差异，而在有没有唯一的、机器可判的目标状态。

反例就在图鉴里：tau-bench 的判分方式恰恰是比数据库最终状态跟初始状态的差异，属于看 diff，但它是完全确定性的 0/1 硬判，因为标准操作序列执行后的数据库状态是唯一确定的。可见看 diff 不等于弱。

修正后的判据：

$$V = \text{强} \iff \exists\, g \text{ 使得 } \text{score} = \mathbb{1}[f(\text{产出}) = g] \text{ 可由确定性程序计算}$$

其中：

- $g$ —— 唯一的目标（一个数值、一个集合、一组必须通过的测试、一个确定的数据库状态）；
- $f$ —— 从 agent 产出到可比对形式的确定性变换（跑测试、算性质、读数据库）；
- 右侧的指示函数由确定性程序算出，不含大模型打分、不含人工评审，重跑结果不变。

强验证有四种真值载体，图鉴里都有实例：

| 载体 | 怎么判 | 代表 |
|---|---|---|
| 测试用例 | 跑 pytest，两组测试全过记 1 分 | SWE-bench：`FAIL_TO_PASS` 打补丁后必须全过、`PASS_TO_PASS` 必须保持过 |
| 数值断言 | 拿预存标准输出比，容差内相等 | SciCode：338 个子问题各配 assert，标准答案是出题人跑通后存下的 `target` |
| 集合比对 | 交上来的 ID 集合跟真值集合逐项比 | SpatialBench-Long：终答限定在受控词表内，跟金标准逐项比对 |
| 物理测量 | 真做实验看物理结果 | ABC-Bench：agent 写的脚本驱动 OpenTrons 机器人，看 DNA 有没有按预期序列组装出来 |

弱验证有三种形态：

| 形态 | 为什么硬不起来 | 代表 |
|---|---|---|
| 无唯一答案 | 任务本身就没有标准解 | ChemCrow：测能不能自主完成化学任务，判分靠 GPT-4 对比带工具与不带工具两份答案；论文自己发现 GPT-4 当裁判时分不清明显错误的输出和正确输出 |
| 靠分布定位 | 好坏取决于跟别人比 | MLE-bench：0.87 准确率是好是坏脱离竞赛无法判断，所以把 agent 成绩放进当年真实参赛者分布里看落在哪、按 Kaggle 奖牌线报 |
| 靠评分量表 | 要求本身是自然语言 | PaperBench：489 个节点拆到 361 个叶子，每条由 o3-mini 判是或否，96% 的分给的是过程做没做而非结论对不对 |

强验证便宜、可重现、能横向比，代价是只在题目形态允许时成立。SEC-bench Pro 从规则判分主动转向 LLM 裁判，理由是漏洞利用的成功形态太多、规则穷举不完，换到那类任务上强验证就做不了。

## 2.3 维度二 · 问题范式

生成式是题目不给候选范围，agent 自由构造答案；判别式是题目给定候选集合，agent 从里面挑最合适的。

owner 原表述叫它「问题范式难度」，暗示生成式比判别式难。这不是难度阶梯，是一对取舍。图鉴的反例：SpatialBench-Long 明确给了一份候选程序清单（判别式），最好的三个模型-harness 对只有 8/72 即 11.1%。给了名单但名单里有作者特意留下的干扰项（胶原沉积、肌生成、血管程序、泛转移特征，生物学上都说得通但对这道题问的那个结论是错的），照样极难。

准确的关系是：

$$\text{判别式} \Rightarrow \text{答案空间闭合} \Rightarrow \text{判分易做硬}，\quad \text{但也} \Rightarrow \text{存在蒙对基线}$$

$$\text{生成式} \Rightarrow \text{答案空间开放} \Rightarrow \text{无法蒙对}，\quad \text{但也} \Rightarrow \text{判分需专门造判等器}$$

生成式加强验证这一格靠专门造一个判等器才能成立。图鉴里做到的三家，各自造了不同的东西：

- SWE-bench 造的是测试用例：同一个 bug 有很多种改法，比对补丁文本没法判对错，改成跑测试后 agent 怎么写都行、只要行为对；
- NewtonBench 造的是符号等价检查：agent 交一个数学表达式，检查它跟隐藏真公式是否数学等价，且故意忽略量纲补偿常量的取值；
- URSA 造的是先例库：一个叫 ChemCensor 的评估器查反应先例库给每步打 0–5 分，任何一步为 0 整条路线不算过，判分侧另配 25.5 万个市售可得原料库。

## 2.4 维度三 · 中间过程衡量程度

这一维分三档，也是我方战场所在。

| 档 | 定义 | 判据 |
|---|---|---|
| 不衡量 | 只看交卷那一下 | 分数只是终态产出的函数 |
| 弱衡量 | 终态拆成若干子分数 | 分数是多个子项的加权和，但每个子项都落在终态上 |
| 强衡量 | 设了必须经过的锚点 | 存在只能从中间记录取值、无法从终态反推的子项 |

弱衡量与强衡量的分界，用一个可操作的问法：把 agent 的中间过程全部丢掉、只留最终产出，这个分还算不算得出来？算得出来就是弱衡量，算不出来才是强衡量。

- TravelPlanner 把预算不超标、餐厅不重复等约束平铺逐条判，共两类约束两个脚本，微观通过率＝通过的约束数除以约束总数。只看最后那份行程就能全算出来，属弱衡量。它自己也承认这些约束是平铺的，查不出 agent 是不是跳步；
- Commit0 的分是单元测试通过率，过了七成就是 0.7。只看最后那份代码就能算出来，属弱衡量（虽然每个测试像个渐进关卡）；
- SUPER 的过程分要拿正则去 agent 的执行日志里搜路标。日志丢了就算不出来，属强衡量。

强衡量还要再分两型，这是 owner 定义里缺的一层：

$$\text{强衡量} = \underbrace{\text{进度型}}_{\text{数走到了第几步}} \ \cup\ \underbrace{\text{正确性型}}_{\text{判每一步做对没有}}$$

区别在一种具体情形下彻底暴露：agent 把该走的步骤完整走了一遍、每一步该调的工具都调了，但每一步的科学结论都错了。进度型会给它高分，AgentBoard 数满足了几个目标谓词（子目标用正则匹配环境返回的观测文本，达成一个加 1/n），SUPER 数日志里搜到几条路标（45 题平均每题只有 2.7 条），ColorBench 数到达了几个里程碑（判的是有没有到达某个屏幕状态而非内容对不对），三家数的都是往前走了多少。正确性型会给它零分，每一关判的是那一步产出的内容对不对。

图鉴里做到强衡量的 17 家（逐行统计见 §3.2），过半是进度型。正确性型的现存做法只有两条路：

1. 拆成子题各自断言。SciCode 请科学家把 80 道大题拆成 338 道小题，每道配存档代码与测试用例，判分时拿标准输入跑 agent 写的函数比输出。它判的是正确性，但卡点是题目专属的，不能跨题比较；
2. 靠 LLM 裁判打量表。MDArena 全库 243 条人工写的过程判据（每题中位数 4 条、最多 16 条），用 Claude Opus 当裁判看 agent 的完整执行轨迹，限时 300 到 600 秒给分。SpatialBench-Long 的中间卡点也是 rubric 交 LLM 判，且明确声明不进主分、只当诊断。

MDArena 把为什么必须软判写得很直白：分子动力学没有唯一正确答案、仿真本身带随机性，中间那段没法确定性判定。这不是能力问题，是任务形态问题。

顺序也算强衡量的一部分，但几乎无人做。图鉴里 17 家做到强衡量的 benchmark，只有 ToolMATH 一家把执行顺序本身当成判据（三轴诊断之一 Tool Connectivity 测链拉长后正确率掉多少，带工具链顺序约束）。其余 16 家都只数达成了几个不管先后，AgentBoard 明说三条子目标之间是集合关系。

把顺序当判据的成熟做法全在业务流程管理领域（叫符合性检查，拿实际执行记录核对它有没有遵守既定流程），分三类：

| 类 | 做法 | 代价 |
|---|---|---|
| 日志重放 | 把记录拿到流程模型上模拟走一遍，看缺了多少剩了多少 | 粒度粗，只知道走得通走不通 |
| 轨迹对齐 | 逐个动作找偏差，每处配一个代价，求总代价最小的对齐 | 诊断最细，计算量大得多 |
| 约束式 | 把要求写成一条条声明式规则，判记录满不满足 | 给不出偏离多远的连续度量，但便宜好解释 |

AI benchmark 里把顺序做成判据的只有 ToolMATH 一家。另有两家把顺序做成了题目而不是判据：Desktop-Delta 从真实 Linux 操作记录里抽三帧截图打乱让模型排回原序（463 道这种题，其中 105 道掺了诱饵帧，最好的模型精确排对 65.1%）；FukuyamaBench 判化学反应的基元步骤序列，要求整条路径逐步完全对上才算对，最好的模型只有 8.3%。这两家考的是模型懂不懂顺序，不是模型做事时守不守顺序。

## 2.5 维度四 · 工具供给程度

这一维 owner 的洞察最深，而且图鉴里有直接的实证支持。

| 档 | 给什么 | agent 要自己做什么 |
|---|---|---|
| 强推理 | 只给读写文件、执行代码 | 全部推理 |
| 弱推理 | 基本工具加若干做实验或验证型工具 | 决定测什么、怎么解读、怎么权衡 |
| 强工具 | 再加上能直接把答案搜出来的工具 | 只需知道调哪个工具 |

核心判据是：

$$\text{一个工具属于强工具档} \iff \text{它替代了 agent 本该自己完成的推理步骤}$$

弱推理是最合理的评测范式，因为它对应真实科研分工。科学家也不是什么都在脑子里算，他得去查文献（知识不在脑子里）、得动手做实验（答案不在纸上）；但决定测什么、改哪里、怎么权衡、怎么归纳外推，全在书桌上完成。给工具的位置，就是科学家离开书桌的位置。这条判据写进了 ADR-0025，叫科学家代入法。

三条实证支持这一维真实存在：

1. 工具不是越多越好。ChemToolAgent 拿同一批化学题让带 29 个化学工具的 agent 和不带工具的纯 LLM 各做一遍：专门任务上工具大幅提升（名称转 SMILES 从 0.0 涨到 70.0，逆合成从 0.0 涨到 42.0），但通用化学题上工具反而拖后腿（MMLU-Chemistry 从 80.5 降到 71.0）；
2. 工具到了一定量再加就没用。InfoMosaic-Bench 做了两种设定，只给 web-search 与给该域专用工具，换域工具平均只涨 0.4 到 0.9 点，所以瓶颈不是有没有工具、是工具用得对不对；
3. 强工具档确实会把推理替换掉。URSA 让 17 个前沿 LLM 不给任何工具纯 prompt 进路线出（强推理档），另有 14 个传统 CASP 配置自带单步反应预测模型、市售原料库、路线搜索（强工具档）。结果传统专用系统全面赢过 LLM：expert 集上 RetroChimera-MCTS 的 Solv-2 通过率 32%、GPT-5.5 只有 21%。

文献检索类工具单独摘出。owner 判断它是双刃剑、不参与本维讨论，本文认同并补上理由：它不返回本题真值，只返回领域知识。所以它既不减少本题的推理量（还得自己判断查到的东西有没有用），也不构成答案泄漏通道。这和按性质反查分子那种直接返回本题答案成员的工具是两类东西。图鉴里 OpenBioRQ 是个旁证：它给十个生物医学检索工具，却发现最难的题上 agent 反而停用工具直接硬答（论文叫 agentic collapse），说明检索工具的边际价值随题目变难而下降。

这一维在动作级上就是第一章的三分法：给工具的位置＝acquire 类动作的位置。判定一个 benchmark 落在哪一档，等价于问它把多少本属 infer 的动作交给了工具（逐条对照见 §1.3）。

## 2.6 四维不完全正交：三处真实耦合

owner 断言四个维度基本正交。基本正交成立，但有三处真实耦合得写明，其中第三条是我方设计的内在张力。

耦合一，判别式让强验证变容易。判别式把答案空间闭合成一份名单，逐项比对就能判，天然易硬。生成式要做到强验证得专门造判等器（§2.3 那三家）。所以生成式加强验证是稀疏格，不是因为没人想做，是因为要多造一个部件。

耦合二，强验证让强衡量变容易。中间关卡也要有真值才能判对错。所以弱验证加强衡量正确性型几乎不存在，终答都判不硬、中间步骤更判不硬。GUI 与具身类全部落在弱验证加强衡量进度型，正是这个道理：屏幕到没到可以硬判，但屏幕上的内容对不对判不了。

耦合三对我方最关键：工具给得越少，中间过程越无从衡量。

$$\text{中间过程可衡量的信息量} \propto \text{agent 经过网关的工具调用次数}$$

我方判分的全部真值都从网关记录里取，agent 交上来只有答案，判分器拿它回记录里查有没有真查过性质、当时返回什么值。工具砍得越狠，记录里剩的行数越少，能判的中间步骤就越少。ADR-0024 把工具从 9 个砍到 5 个、ADR-0025 再砍到 3 个（查文献、做实验、交卷），直接削弱了维度三的可衡量性：原来 cp2 认 `search_candidates`、cp4 与 cp5 认 `compare`，这三个工具现在都删了，对应的关也就没了取值来源（cp2 已随 ADR-0024 §8 从模板层删除）。

这是一个真实的、尚未解决的张力：ADR-0025 要测推理不测搜索所以砍工具，ADR-0026 又要强衡量中间过程所以需要记录，两者在拉锤。目前的处置是把中间判定集中到唯一剩下的信息工具 `get_property` 上，判 agent 测了哪些分子、测了哪些性质、测的顺序，这是做实验这个动作本身携带的信息，砍不掉。但这意味着可判的中间维度比原设计窄，得如实报告。

## 3.2 分档统计与空格分析

**各维度分档家数**（对 §3.1 表格逐行统计得出，65 家有坐标）：

| 维度 | 各档分布 |
|---|---|
| 一·验证 | 强 34 家 · 弱 21 家 · 混合 10 家 |
| 二·范式 | 生成式 55 家 · 判别式 7 家 · 混合 3 家 |
| 三·中间衡量 | 不衡量 30 家 · 弱衡量 18 家 · 强衡量 17 家（进度型 9 · 正确性型 7 · 顺序型 1）|

1. **判别式极少**（7 家 / 65），因为一旦给候选名单就要面对蒙对问题。Biomni 给 18 个候选基因、SpatialBench-Long 给受控词表，都是为了让终答能硬判才付这个代价；
2. **一半的 benchmark 完全不判中间过程**（30 家 / 65）。加上「弱衡量」那 18 家（子分数全落在终态上），**七成四的 benchmark 拿掉中间过程记录也照样算得出分**；
3. **做到强衡量正确性型的只有 7 家，而与我方可比的只有 3 家**。其中四家（ProcessBench、PRM800K、TRAIL、Who_and_When）靠人工步级标注，且全部属于轨迹诊断，把 agent 当评委去读别人的轨迹挑错，按 owner 裁定不属于本项目的 action（见 §1.4），因此不是我方同类；剩下三家（PowerAgentBench、LongProc、TRACER）是在线判 agent 自己的执行，但 LongProc 判的是算术合法性这类形式性质，TRACER 判的是溯源记录真伪，全市面上只有 PowerAgentBench 一家在在线硬判科学结论本身对不对；
4. **工具供给的强推理与弱推理两档人数完全相等**（各 26 家），说明这一维确实是设计者主动选择的结果，不是被任务形态锁死的——这也是它适合被做成受控变量的前提。

**空格清单（无人或极少人做的组合）**：

| 空格 | 为什么空 | 是否可做 |
|---|---|---|
| 弱验证 × 强衡量·正确性型 | 终答都判不硬，中间更判不硬（耦合二）| 结构性不可做 |
| 强验证 × 生成式 × **强衡量·正确性型** × 弱推理 | 要同时造判等器、造中间真值源、卡住工具供给三件事 | **可做，我方位置** |

把能力层叠上去看，空格更窄。第一章的三分法要求判的必须是 agent 自己做发现时的 infer 动作，不是读别人轨迹挑错。把这一条叠到上面的坐标上，满足在线硬判 agent 自己中间科学结论的全市面只有 PowerAgentBench 一家。我方与它的差别见 §4.3。

# 第四章 我方定位

## 4.1 我方四维坐标与能力覆盖

坐标是强验证 × 生成式 × 强衡量正确性型 × 弱推理，且三档全扫。能力覆盖是 29 个 infer 动作中有数据支撑的 19 个，实际覆盖超导材料与小分子药物两个领域，基因领域基本为空（见 §1.5）。两者合起来才是完整定位：坐标说的是怎么判，覆盖说的是判了哪些能力。

逐维说明我方具体怎么做：

维度一，强验证，靠查库不靠执行。真值预存在快照库里（92,153 个实体、240,467 行性质数据，`dag_poc/data/backend/CHECKSUMS.json` 实测），判分就是查表加比对，不需要沙箱执行。判据分三类：拿库里的真值跟题面约束做数值区间比对；比 ID 集合判筛选与排序；比证据出现的先后判依赖顺序。

跟别家的分野是硬的根据从哪来。SciCode、Commit0、SWE-bench 的硬靠执行，必须配沙箱；我方的硬靠查库。好处是判分便宜、可重现、同一条记录重判多少次结果都一样；坏处是真值只在库内成立，库外的分子无法判定，而 SciCode 那套判据对任何能跑的代码都成立。

与 ABC-Bench 的差距得正面承认：它比我方硬一整层。它的判据是 DNA 真的按预期序列组装出来了，属物理世界验证；我方的真值是数据库快照，属计算真值。

维度二，生成式，答案由 agent 自己提。按 ADR-0025，候选检索工具（`search_candidates`、`get_neighbors`）全部删除，候选完全由 agent 凭化学知识提出。这一维上我方从判别式退到了生成式，原设计里 `search_candidates` 返回候选池、等于给了名单，现在没有名单。

维度三，强衡量正确性型，真值从工具调用记录里取。agent 交上来只有答案，判分器拿它回网关记录里查：这个分子有没有被真的测过性质、测的时候返回什么值。判定一律用记录里的值，不采信 agent 正文里写的数。声称满足条件但记录里从来没测过它，这一关扣分。

网关记录长这样（取自 `dag_poc/traces/case_cns_metoprolol.jsonl`，长字段已截断）：

```
trace_id   case_cns_metoprolol
seq        4
tool       predict_admet
arguments  properties: "BBB,hERG,Caco2,F20"
           smiles: "CC(C)NCC(O)COc1cccc2ccccc12, ..."
result     total_evaluated: 5, passed: 0, failed: 5
latency_ms 19.6
```

维度四，弱推理，这一维是我方创新点的落点，见 §4.2。按 ADR-0025 的科学家代入判据，当前工具集是 3 个：`literature_search`（查资料）、`get_property`（做实验，一次只查一个性质、每次扣查证预算）、`submit_answer`（交卷）。被判不给的是分子编辑、变体枚举、邻居检索、排序、结构规范化，理由统一：化学家在纸上就能做，不需要外人代笔。

## 4.2 创新点：沿工具维做受控梯度

这是本文认为唯一站得住的方法学贡献，其余各维我方都只是占了一个空格。

做法（ADR-0026）是不造三套题，而是一套题跑三种工具配置：

$$\Delta_{\text{tool}} = S(q,\ T_{\text{易}}) - S(q,\ T_{\text{难}})$$

其中：

必须同题同真值：只有 $q$ 与判据都不变，$\Delta$ 才能归因到工具供给。若三档换了题或换了判据，差值就混进了题目难度差异与判据差异，归因失效。

便捷工具的定义是把一个推理过程变成一次工具调用。候选池是现成的，ADR-0025 按科学家代入判据判为不给的那批（分子编辑、变体枚举、候选检索、邻居检索、排序），它们在困难档被排除正因为替代推理，这个性质使它们成为低难度档的天然素材。

构建顺序是先难后易，档位不预先设计：

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 一 | 全量 150 题跑困难档（3 个基本工具）| 基线成绩＋完整轨迹 |
| 二 | 分析轨迹结构与出错点分布，**并把失败模式分成推理型与操作型两类** | 失败模式清单（分型标注＋各模式占比）|
| 三 | 针对占比高的失败模式各配一个便捷工具 | 每个工具对应一个实测失败模式，**且标明它打的是推理型还是操作型** |
| 四 | 同题重跑中等档与简单档 | 三档对比曲线，**推理型与操作型增量分开报** |

不预设档位的理由：预设的便捷工具可能替代的是 agent 本来就不出错的环节，那么 $\Delta \approx 0$，这一档白跑。由错误分析导出，能保证每个便捷工具都打在真实痛点上。

### 失败模式必须分两类，否则 $\Delta$ 不干净

这是阶段二的硬要求（owner 2026-08-12 裁定）。困难档的失败有两种成因，补工具后分数都会涨，但只有一种能算工具替代了推理：

| 失败类型 | 具体表现 | 补对应工具后 | 能不能计入 $\Delta_{\text{tool}}$ |
|---|---|---|---|
| **推理型失败** | 不知道该往哪个方向改分子、权衡错了、趋势归纳错了 | 分数涨 | ✅ **能**，这正是要测量的量 |
| **操作型失败** | SMILES 写错、原子数数错、分子式算错 | 分数也涨 | ❌ **不能**，这只是把噪声去掉了 |

$$\Delta_{\text{tool}} = \underbrace{\Delta_{\text{reason}}}_{\text{推理被替代，要报的}} + \underbrace{\Delta_{\text{noise}}}_{\text{噪声被消除，必须剔除}}$$

其中：

- $\Delta_{\text{reason}}$ —— 补上针对推理型失败的工具所带来的分数提升。它才是工具替掉了多少脑力，是论文要报的数；
- $\Delta_{\text{noise}}$ —— 补上针对操作型失败的工具所带来的提升。agent 的科学判断本来就对，只是手笨写错了，修好手笨不等于替代推理；
- 两者混在一起报，工具替代了 X% 的推理这句话就站不住。

这不是假设的风险，是已登记的事实。ADR-0025 §8 写明：删掉 `get_entity` 后 agent 需自己数原子，而 `atom_count` 是当前判分约束之一，数错即判错，属算术噪声而非推理能力差异。所以若简单档补一个帮你数原子的工具，分数一定涨，但涨的是 $\Delta_{\text{noise}}$。

处置分三条：

1. 阶段二的失败模式清单逐条标注型别，不得缺型；
2. 三档对比时 $\Delta_{\text{reason}}$ 与 $\Delta_{\text{noise}}$ 分开报，后者单独命名为去噪对照，不计入工具替代推理的结论；
3. 若某个便捷工具同时打两类失败（如结构编辑工具既帮他想改哪里、又帮他把 SMILES 写对），则拆成两个工具分别上；拆不开的在报告里标为混合型、$\Delta$ 不可归因。

> 本小节为 owner 本次口头裁定，需回写 ADR-0026 §3 的四阶段表（加「失败型别」列）与 §6（分数不可合成再加一条：$\Delta_{\text{reason}}$ 与 $\Delta_{\text{noise}}$ 不得相加）。已登记于第八章风险表。

**两种对比给两类结论**：

| 方向 | 比什么 | 得到什么 |
|---|---|---|
| 横向 | 同一档内不同模型 | 谁做科学家更强（能力排名）|
| 纵向 | 同一模型跨三档 | 工具替代了多少推理（能力构成）|

三档分数绝对不得平均成一个总分（ADR-0026 §6 硬约束）。工具集不同即任务定义不同，跨档平均无意义。对外只报三档各自的分加档间差值，且差值需按推理型与操作型拆开。

定位表述必须严格：主测是困难档，中等与简单档是消融对照，用于量化工具替代的推理量。不得说成我们有三档难度的题目，那等于承认也在测搜索能力，与 ADR-0025 冲突。低难度档的作用是标出靠搜索能拿到的天花板，从而证明困难档的分数来自推理。

## 4.3 与最近邻逐一对比

本节按维度组织，每条都说清是本质不同还是只是更粗或更细。

### 维度三上的最近邻

PowerAgentBench 跟我方语义完全一致，我方更粗。它把有没有证据拆成三个召回率，分母都是隐藏的高危案例集，差别只在分子：

$$R_{\text{sub}} = \frac{|\widehat{D} \cap O|}{|O|}, \qquad R_{\text{evid}} = \frac{|\widehat{D} \cap V \cap O|}{|O|}, \qquad R_{\text{found}} = \frac{|V \cap O|}{|O|}$$

其中：

- $O$ —— 隐藏的高危案例集，运行时不给 agent 看；
- $\widehat{D}$ —— agent 提交的集合；
- $V$ —— agent 真的调工具验证过的集合；
- $R_{\text{sub}}$ 只看交了什么，$R_{\text{evid}}$ 要求既交了又验证过，$R_{\text{found}}$ 只看有没有找到、即便没交也算。

三者放在一起能分辨两种完全不同的失败：找到了但没交（$R_{\text{found}}$ 高而 $R_{\text{sub}}$ 低，提交环节出问题），交了但没验证过（$R_{\text{sub}}$ 高而 $R_{\text{evid}}$ 低，是在编）。

它那个交了且验证过才算跟我方语义完全一致，而且它同样坚持核心分不用 LLM 裁判。它比我方细三处：一是我方只有一个覆盖率，分不开上面那两种失败；二是它对漏报高危项单独加重惩罚并按严重度加权，我方对该留没留与该去没去同等处理；三是它设了验证预算只准验 1035 个案例里的 80 个，所以能考出预算怎么花。第三处我方已由 ADR-0024 的查证预算机制补上（`get_property` 一次一个性质、每次扣预算），前两处仍是缺口，已登记。

TRACER 跟我方责任方相反，这是真正的本质不同。它要求 agent 每写一句话就同步产出一条溯源记录，说明这句话由哪一轮工具调用、哪个证据单元支撑，以及支撑关系属哪一类（直接引用、忠实压缩、有依据的推导），然后用四道检查验这条记录本身是不是真的：格式对不对、引的那轮调用存不存在、来源是否真实、关系类型合不合理（前三层硬，第四层由 Gemini-2.5-Pro 软判）。

我方不要求 agent 做任何声明，判分器自己回网关记录里查。两边各有得失：它能拿到更细的语义关系，但得先防记录本身被伪造；我方拿不到语义关系，但 agent 无从伪造，因为记录是网关写的、不经 agent 手。

SciCode 与我方同为正确性型，卡点来源相反。它 338 个卡点是按每道题的内容各自拆的，我方六关（现为五关，cp2 已删）所有题共用。后果是一对逆向取舍：它能定位到具体哪道子题错了，但卡点不能跨题比较；我方只知道候选集对了多少比例，但各关可以跨全库聚合。

AgentBoard 与 SUPER 不在同一型。它们判进度，我方判正确性。这两件事在一种情形下彻底分开：agent 把该走的步骤完整走了一遍、每步都调了该调的工具，但选错了候选、筛错了集合、排错了序，它们会给很高的进度分，我方给零分。

MDArena 与 SpatialBench-Long 的对比说明我方能硬不是因为更严谨。两家的过程分都靠 LLM 裁判，MDArena 把理由写得很清楚：分子动力学没有唯一正确答案、仿真本身带随机性，硬不了。我方能硬是因为任务形态允许，答案是库内实体、比对方式唯一。

### 维度三·顺序子项上的最近邻

卒中诊疗符合性检查跟我方没有本质不同。两边都是预设一套规则、拿实际执行记录去对、属同一类约束式符合性检查。差异在两处，都不是方法层面：一是领域，它把临床指南文本变成规则，我方把化学工作流的依赖关系定成边；二是结果用法，它按规则分开报符合率、不合成总分（实测 50 条规则、数百条记录，86% 符合），我方把结果并进一个门槛。

它那个三值判定顺带指出我方一个缺口：它对一条记录只返回三种结果，不适用（这位患者根本没做这项）、符合、不符合。我方的关是二值的，把不适用和做错了混为一谈。某道题若本来无文献可查，cp1 记 0，跟 agent 偷懒不查记 0，在我方这儿看不出区别。已登记待办。

BPOP 与我方方向相反，这是真正的本质不同。它不预设流程图，从记录里把图推出来：假设背后有一个隐藏的先后关系网，观测到的是若干条成功日志（每条来自不同 LLM 做同一任务），把它们看成那个隐藏关系网的一种展开，然后反推图长什么样。它绕过了枚举偏序图所有展开这个计数上极难的问题（论文用词 #P-hard），改用只看当前还有哪些动作可以马上做的概率模型近似。

**它推出图是为了编译执行器省 token，我方用图是为了打分。** 所以它不需要图是「对」的、只需要图能省时间；我方的图若定错了，判分直接就是错的。这也是为何边集还没逐条定过对我方是个真风险，对它不是。

它顺带给了我方一个现成工具：**偏序的传递归约**（把能由其他边推出来的边删掉之后剩下的最小边集）就是最简边集，所以删边这件事在数学上就是求传递归约。改完之后应该断言边集等于它自己的传递归约，否则就是写了冗余边、会让合法顺序白白变少。实测在链上多加一条 cp1 到 cp3 的边，合法顺序数会从 2 无声地掉回 1，不报错，只是变严。

我方顺序判定的现状与缺口：判定口径是取各关证据的首次出现时刻，逐条依赖边比对上游是否严格早于下游，结果并进门槛。ADR-0021 定的语义是偏序（只有真有依赖的边才约束，没依赖的两关先做哪个都行）。但两处未完成：一是当前边集实际上是一条链，实测只有一种合法顺序，偏序的设计意图还没落地；二是哪些边算真正的科学强依赖还没逐条定过，这件事流程挖掘的文献里拿不到答案，得懂化学的人来定。

### 维度四上的最近邻

ChemToolAgent 与我方同为同题变工具，我方是三档梯度、它是二值对照。它拿同一批化学题让带 29 个工具的 agent 和不带工具的纯 LLM 各做一遍，比准确率差。这跟我方 $\Delta_{\text{tool}}$ 的思路一致。

所以我方不能声称首创同题变工具。能声称的只有两条：一是三档梯度而非二值开关，且档位由实测失败模式导出而非预设；二是配合中间过程强衡量，所以能看出工具替代的是哪一个环节的推理，ChemToolAgent 只看终答、只能得出工具总体上帮了多少，看不出帮在哪一步。

GuacaMol、Tartarus、TDC-PMO 是我方主动避开的赛道。一旦提供分子编辑或变体枚举工具，最优策略立刻退化成爬山搜索：取当前分子，生成一批变体，逐个查性质，留最好的，再来一轮。这个循环不需要任何化学理解，遗传算法、强化学习、随机游走都能跑。

而这条赛道已有专门 benchmark，被测对象本来就是生成模型与优化算法。我方若进这条赛道必输：它们的 oracle 能给任意分子现场算分（RDKit 公式或物理模拟），我方的性质来自实验数据库、只能查表，库外分子返回未探测到。同一赛道上我方的可评分空间小若干数量级。反过来说，不给编辑工具，我方就站在另一条赛道：测从这个分子为什么有这个性质推出要那个性质该改成什么结构的因果推理，这条搜索算法做不了。

# 第五章 四维之外：题目防不防作弊

这一章讲的不是怎么判，而是判出来的分可不可信。它与四维正交，但得单列，因为我方在这里有一条已被 owner 裁定推翻的旧机制和一条得如实声明的边界。

## 5.1 我方现状：匿名化已取消，新机制未落地

曾经的做法已作废：不换题，换题面写法，把能让模型认出这是哪个分子的标识符抹掉，不给 InChIKey、不给真实 SMILES，元素符号换成匿名标签只保留数量。

取消的理由（ADR-0023，owner 2026-08-09 裁定）：

$$\text{测结构推理} \Rightarrow \text{必须给真结构} \Rightarrow \text{能认出分子} \Rightarrow \text{防不住背答案}$$

其中：

- 测结构推理是项目要测的核心能力（加一个原子、看性质怎么变）；
- 必须给真结构，因为没有真实拓扑，agent 无从推改了会怎样；
- 能认出分子，因为分子式加连接方式在化学里与身份一一对应，真结构即指纹；
- 防不住背答案，因为身份一交出，记忆型模型可直接命中。

四步是硬链，中间断不开。而且 ADR-0022 已实测证明旧机制名存实亡：全库 92,153 实体的标签频率有明显指纹（`[19*]` 占 43.5%、`[16*]` 占 36.0%），按有机分子常识可直接对应到氢碳氧氮；元素表被破解后再叠加拓扑即得完整结构。

改靠什么：任务设计层，答案不写在题面、必须靠多步推理加工具探索才能到达。答案不在题面时，背一个分子名也没用，因为不知道要背哪个。

必须如实声明的边界（ADR-0023 §3 原文要求）：任务设计层尚未落地，在它落地前，本 benchmark 不对外声称抗记忆污染。不能取消了旧机制、新机制没上，还宣称防住了。

## 5.2 别人怎么做防污染

**两条路：换题，或换写法。**

| 家 | 做法 | 代价 |
|---|---|---|
| EvoBrowseComp | 三个 agent 分工从活网现合成新题：一个检索新鲜知识合成问答对，一个**按可信度与流行度过滤把太出名的剔掉**，一个把问题形式化成推理图减少捷径。中英各 400 题 | 得常驻一条合成管线，题一直在变，没法横向比 |
| GSM-SEM | 现场生成语义变体：扰动实体、属性、关系，常真的改掉底层事实逼模型重算，但约束原计算过程与答案不变、难度相近。14 个 SOTA 模型平均掉 28% | 同样要维护、同样没法横向比 |
| NewtonBench | 反事实改写：把真实物理定律改成假的但自洽的版本（如 $r^2$ 改成 $r^{1.5}$，另塞一个自由常量吸收量纲不一致），agent 背书上公式蒙混不了 | 只适用于有解析形式的定律 |
| URSA | 用还没公开的合成路线出题，目标分子是新的、路线也没发表过 | 依赖公司私有数据，外部团队复现不了 |
| MetanymGame | 根本不预设内容：题目全部由参赛模型现场创造再互相评判，对评分矩阵做矩阵分解 | 没有固定测试集，也就没法做模型间横向比 |
| MatVQA | **改题面写法而不换题**：用迭代过程把题面里能直接读出答案的文字线索抽掉，逼模型必须真去看显微图和衍射图，共 1325 题 | 这层防护是一次性的 |
| SpatialBench-Long | 把题面与原始数据标签里能认出原研究的信息全洗掉，很多题考的干脆是未发表结果 | 依赖未发表数据，外部难复现 |
| PaperBench | 把原作者自己的代码仓库放进禁访黑名单 | 只挡直接抄，不挡背过 |
| Search-Time Contamination | 不建 benchmark 而是量污染：定义三级泄漏（元数据／题目上下文／直接给出答案），在六个公开基准上实测发现成绩最多虚高 4% | — |

**分野与取舍**：

$$\text{换题} \Rightarrow \text{永久有效但不可横向比}，\qquad \text{换写法} \Rightarrow \text{可比但一次性}$$

**一条我方明确不如人的**：EvoBrowseComp 会按知识流行度过滤、把太出名的剔掉，我方没做这一步。若某道题的数值条件组合只可能对应某个教科书级的明星分子（阿司匹林、青霉素这类），模型仍可能凭化学常识猜出来。已登记待办。

## 5.3 答案隔离：三种选法的取舍

**核心取舍：硬判定和绝对不泄漏，不能同时要。**

| 家 | 怎么选 | 代价 |
|---|---|---|
| OpenBioRQ | 选绝对不泄漏：用 12553 道尚未解决的生物医学研究问题出题，根本不存在答案。理由说得很直：一道题只要有固定答案，模型就能从答案反推出预期的来源，而不是真去核实来源支不支持结论 | 判分只能靠 LLM 裁判加评分量表 |
| SciDisco | 选完全隐藏：把一张隐藏的证据图编进任务环境（假设、数据集、证据图、验证器四件打包），证据图只给验证器看，agent 完全接触不到 | 它是 RL 训练框架不是 benchmark，藏图用于训练时分配 credit |
| PowerAgentBench | 藏的是**评分逻辑本身**：agent 只能拿到仿真器返回值和一份验证预算，交上报告后由一个它看不见的评估器重新算物理有效性再打分 | 防的是 agent 冲着判分器优化，与藏答案是两件可叠加的事 |
| **我方** | 选中间态：答案实体存在同一个库的另一侧，工具对这一侧只回答「在不在库里」、不返回任何性质值 | 这条通道理论上仍是一条极窄的侧信道 |

**我方的三层与两条待验证**：每道题配一份白名单视图（实测 37 份，统计 `dag_poc/data/backend/per_case_views` 下文件数得到），视图外的实体与库里根本没有的实体返回同一形状，所以 agent 无法从返回的差别里分辨「存在但你看不到」和「不存在」。工具契约明确声明存在性判定严格等价于「属于答案侧」。

两条必须标为待验证：一是此前文档写实测 30 道开放题泄漏为零，但代码里没有对应的测试脚本或验证日志，这句只能算设计目标；二是这条侧信道到底多窄没做过红队测试。

**与 PowerAgentBench 的差异**：它藏评分逻辑，我方藏答案数据。两者可以叠加，**我方目前只做了后者**，判分逻辑对 agent 并不保密。

**这一节我方没有任何方法贡献，判据全是别人的。列它是因为这是该做的功课。**

| 判据 | 我方结果 | 说明 |
|---|---|---|
| 答案可达性（能不能摸到答案，含从预训练里背出来） | **不通过** | 匿名化已取消（ADR-0023），任务设计层未落地，此条在新机制上线前不成立 |
| 答案格式歧义 | 通过 | 只交 SMILES |
| 蒙对漏洞 | 不通过 | 候选池小的题终答可能被蒙中，已登记 |
| 跑间方差 | 未验证 | 只跑 3 轮，方差没测过，已登记 |
| 判分器能力对等（静态判分器凭什么判一个会用工具的 agent） | 通过 | 库是闭合的，判分器不需要工具能力就能拿到完备真值 |

**两家审计方与我方的角色关系**：

**AgenticBenchFlaws** 基于一份 agent 评测检查表（任务有效性 10 条、结果有效性 20 条）筛出 11 条适合从记录里看的判据，把其中 4 条做成 AI 扫描器；扫描器先冻结，再在留出集上跑，最后跟人工的 0 到 3 级严重度评分对比。在五个广泛使用的 benchmark 里查出了经核实的问题，其中一部分靠人工随机抽检不太可能发现。

**BenchmarkingBenchmarks** 拿 496 条任务请专家逐条复核四个主流工具调用基准，发现 92 处评分器跟人工不一致占 18.5%；又在其中一个基准上同配置重复跑 23 次，分数从 57.9% 飘到 76.8%，归纳出确定性 benchmark 的五类失效模式。

角色是反的：它们拿判据去扫别人，我方拿同一套判据查自己。有一条上我方明确不如它严，就是方差：它重复跑了 23 次，我方只跑 3 轮，自己的方差到现在没测过。这不是设计差异，是我方没做到。

DeepResearchConsulting 是同一种习惯的另一个例子：它自己在论文里声明验证集上的指标反映的是 144 选 1 的选择偏差，只作可复现性报告用、不当结论。跟我方同属主动披露局限，差别只在披露的颗粒度。

# 第七章 不能声称的十件事

这一章给论文写作定红线，逐条都有依据。

1. **不能声称「抗记忆污染」**。匿名化已由 ADR-0023 取消，替代它的任务设计层尚未落地。ADR-0023 §3 明文要求在新机制落地前不作此声称。
2. **不能声称「同题变工具」是首创**。ChemToolAgent 做的就是同一批化学题带工具与不带工具对照。可声称的是三档梯度、档位由实测失败模式导出、且配合中间过程判定。
3. **不能说成「我们有三档难度的题目」**（ADR-0026 §5）。主测是困难档，中等与简单档是消融对照。说成三档难度等于承认也在测搜索能力。
4. **不能把三档分数平均成一个总分**（ADR-0026 §6 硬约束，须落成机器断言）。工具集不同即任务定义不同。
5. **不能把档间差值整体声称为「工具替代的推理量」**。差值里混着两东西：推理被替代（$\Delta_{\text{reason}}$）与操作噪声被消除（$\Delta_{\text{noise}}$）。**只有前者能这么说，两者必须分开报**（§4.2）。
6. **不能声称「按工作流正确性评估」这个观点是我方提出的**。FEV 那篇综述梳理了 109 个生信 agent 系统与 28 个评测资源共 128 篇论文，明确主张评估应看工作流正确性而不是只看终答。我方做的是把这个主张落成可执行判据。
7. **不能把我方分数解读为部署可靠性**。那需要盖住两类完全没测的东西：真实用户行为的野性（WildToolBench 实测 57 个 LLM 无一超过 15%）与故障鲁棒性（AgentChaos 注入 65 种故障后 pass@1 最多掉 50 个百分点）。**我方的分只能读作：任务说得清楚、工具也正常时，agent 的执行正确性。**
8. **不能声称覆盖三个科学领域**。action 枚举列了材料、药物、基因三领域，但基因领域 10 个动作里 9 个无数据（§1.5）。**只能声称两领域：超导材料与小分子药物。**
9. **不能声称与 ProcessBench / PRM800K / TRAIL / Who_and_When 同类或可比**。它们是轨迹诊断（把 agent 当评委），按 owner 裁定不属于本项目的 action（§1.4）。引用它们时只能作为「另一类能力的评测」提及。
10. **不能声称测了逆合成能力**。逆合成规划（action #44）无反应数据库支撑，因此无法与 URSA、RetroAgent 在同一任务上对比。

**另外三条任务边界须主动声明**（这三条是一大批 benchmark 的默认设定，多数人没把它当成需要写出来的选择）：单 agent 执行、不做多智能体协同；任务信息一次给全、执行过程中无额外交互（不含模拟用户对话也不含长期记忆检索）；中间卡点判定必须是硬的。写出来是为了交代分数的解读边界，不算贡献。

# 第八章 遗留风险清单

| 风险 | 具体内容 | 严重度 |
|---|---|---|
| **能力与工具对不上** | 结构改动型 infer 动作（材料 #1-4、药物 #9-11）失去执行载体：编辑工具已删，agent 自己写的新 SMILES 在库外又查不到性质（§1.3、§1.5 缺口三）| 高（直接影响困难档可解性）|
| 工具砍太狠削弱中间衡量 | §2.6 耦合三：`search_candidates`、`compare` 删除后 cp2/cp4/cp5 失去取值来源，可判的中间维度比原设计窄 | 高（触及核心卖点）|
| 基因领域无数据 | 10 个 infer 动作里 9 个无数据支撑，对外只能声称两领域（§1.5）| 高（限定论文覆盖范围）|
| 困难档可解性未验证 | 3 个基本工具下三类题是否都存在可行解法路径，尤其外推题的可见集须由题面给定（ADR-0026 §9）| 高 |
| SMILES 语法合法率未实测 | 若模型写 SMILES 的语法错误率过高，测得的低分主要来自语法噪声而非推理能力差异（ADR-0025 §9）| 高 |
| 偏序设计未落地 | 当前边集是一条链，实测只有一种合法顺序；哪些边算科学强依赖未逐条定过 | 中 |
| 跑间方差未测 | 只跑 3 轮，而 BenchmarkingBenchmarks 实测同配置 23 次能飘 18.9 个百分点；$\Delta_{\text{tool}}$ 的显著性依赖这个数 | 中 |

# 附：一个看似同类、不入四维表的平台

**The Playground**（play.bohrium.com，深势科技 Bohrium 旗下）在官方评分细则里写的是「结果分 + 轨迹 Trace 分双维度加权」，字面上看像维度三的同类。实地取证后确认它不是，故不列入总表，单记于此以免后人重复考察。2026-07-31 实地取证（注册后只读拉取）：全站 6,405 道题、13,774 次作答、695 个学科标签。

三条不列入的理由：一是它的检查点把终态字段拆细，不是判过程正确性，以那道 APOE 题为例，11 个检查点全部落在最终提交的字段上；二是它的轨迹分判的是记录真伪、不是功能实现效果，检查内容是类型合不合法、调用有没有配对、时间窗口对不对、文件修改时间是否合理、花费有没有低于下限，全部属防伪造；三是任务形态不同，它是在线赛事平台、题目由参赛者提交，跟固定题集加统一判分协议不是一类东西。

但有两处值得学。一是它用自洽校验代替顺序约束，不检查步骤先后，而是检查各项记录之间对不对得上（花费与调用次数、文件时间与声称的执行时间），思路上比硬性顺序约束更宽松、误杀更少；二是它的硬软分工清楚，能枚举的判据交机器、语义判断交 LLM，两者在报告里分开列，不混成一个数。

**根因是信任模型不同**：它面对的是公开赛事里可能伪造记录的参赛者，所以重点在防伪；我方面对的是自己跑的模型，记录由我方网关产生、不存在伪造问题，所以重点可以放在判对错。

判分机制拆解见 [`Playground平台造题与判分机制.md`](Playground平台造题与判分机制.md)。
