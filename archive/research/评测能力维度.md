# 长程 Agent 评测到底在测什么

## 结论先行

长程（long-horizon）Agent 评测，本质还是测**推理能力**，只是换了考法：不看某一步答得对不对，而看 agent 像不像一个靠谱的人干一件多步骤的大活——**想清楚、做得对、会应变、不跑偏**。

这对应四项可以分别评测的能力：

| 能力 | 通俗说法 | 发生在 |
|---|---|---|
| 1. 用对工具 | 做得对 | 干活中·每一步 |
| 2. 事前规划 | 想清楚 | 动手前 |
| 3. 反馈应变 | 会应变 | 干活中·反复 |
| 4. 目标维持 | 不跑偏 | 全程 |

下面逐项展开：每项先一句话，再说清楚"测什么、拿什么测"。

---

## 一、用对工具（做得对）

**一句话：该不该调工具、调哪个、参数填得对不对、结果读不读得懂。**

这是把"想法"变成"正确动作"的一步。工具用错——选错 API、填错参数、无视返回值——后面往往全盘皆错。

代表 benchmark：τ-bench（订票、退货等真实 API 调用）、AgentBoard 工具任务、SUPER（在真实代码仓库里跑命令）。

## 二、事前规划（想清楚）

**一句话：拿到任务先拆解、排顺序，而不是一头扎进去乱试。**

长任务常有几十步、彼此有先后依赖。好的 agent 会先把大目标切成有序子目标、规划好步骤，再动手。

代表 benchmark：TravelPlanner（在预算、交通、住宿约束下排多日行程）、SciCode（把一道科研题拆成十几个有依赖关系的子函数）。

## 三、反馈应变（会应变）

**一句话：每做一步都看环境的真实反馈，据此调整下一步；踩了坑能自己纠回来。**

这是长程任务和"一次性答题"最大的区别——边做边看边改。测试报错就改代码再跑，网页变样就换种点法，而不是卡死或将错就错。

代表 benchmark：SWE-bench（改代码 → 跑测试 → 再改的闭环）、AgentBoard 的"进展率"（把实际走的路和该走的路逐步比对）。

## 四、目标维持（不跑偏）

**一句话：任务再长、干扰再多，也始终记得并坚持最初的目标，不遗忘、不被带偏。**

这就是抵抗 task drift。上下文越滚越长，agent 容易慢慢偏离本来要做的事，甚至被中途冒出来的小目标带跑。**这是四项里最难、也是现有 benchmark 覆盖最少的一项**，属于前沿空白。

代表 benchmark：Goal Drift 评测（专门制造"竞争目标"看 agent 偏不偏）、METR 时间跨度（用"能稳定完成多长的任务"间接衡量抗漂移上限）。

---

## 一个共同特点：看过程，不只看结果

长程评测和普通评测最不一样的地方是——**它给"过程"打分**。不只判最后对错，而是用可自动执行的指标量化"走到了哪一步、有没有偏"：进展率、约束通过比例、测试通过数……这样才能看出 agent 在长任务里是稳步推进，还是中途跑偏。

## 一句话总结

> 长程 Agent 评测测的是"推理在长任务里稳不稳"，拆成四件事：**想清楚（规划）、做得对（工具）、会应变（反馈重规划）、不跑偏（目标维持）**。
