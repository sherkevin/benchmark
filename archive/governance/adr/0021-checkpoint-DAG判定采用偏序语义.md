## 1. 背景：外部批评是什么

`Benchmarking the Benchmarks: A Validity Audit of Tool-Calling Evaluation`（arXiv:2607.02577，2026-06-30）审计了 BFCL v4 / τ²-Bench / LiveMCPBench / MCP-Atlas 四大工具调用基准共 496 条任务，发现评分器与专家人工判断的不一致率为 **18.5%**（92 处）。该文把 **trajectory lock-in** 列为**确定性 benchmark 的五类典型失效之一**，定义为：

> 评测锁定唯一一条正确路径，agent 走另一条同样合理的路径也被判错。

监工据此提出质疑：我们强制 cp1(文献) → cp2(建池) → cp3(查证) → cp4(筛选) → cp5(排序) → cp6(答案) 的严格时序，而"先建候选池、再查文献确认方向"在化学上同样合理，可能属于该失效。

## 2. Owner 裁定

**顺序判定这条不构成设计缺陷。** 理由与判据语义如下：

### 2.1 DAG 表达的是偏序，不是全序

DAG 本身就能表示"非顺序"关系：两个节点之间**没有有向路径相连**时，它们的先后就是自由的（可并行、可任意先后）。我们真正要约束的只是**必须串行的那些依赖边**，而不是把所有卡点排成一条线。

### 2.2 一个 DAG 的拓扑排序有多解，合法 trace 是一个集合

设 checkpoint DAG 为 $G = (V, E)$，其中：

- $V = \{cp_1, \dots, cp_6\}$ —— 六个过程卡点；
- $E \subseteq V \times V$ —— 有向依赖边，$(u,v) \in E$ 表示 $u$ 必须在 $v$ 之前完成；

则合法执行序列的集合为该 DAG 的全部拓扑排序：

$$\mathcal{T}(G) = \{\, \pi \in \mathrm{Perm}(V) \;\big|\; \forall (u,v) \in E,\ \pi^{-1}(u) < \pi^{-1}(v) \,\}$$

其中：

- $\pi$ —— $V$ 的一个排列，代表一条候选执行顺序；
- $\mathrm{Perm}(V)$ —— $V$ 上全部排列构成的集合，共 $|V|!$ 个；
- $\pi^{-1}(u)$ —— 卡点 $u$ 在排列 $\pi$ 中的位置下标（越小越早）；
- 约束含义 —— 对每条依赖边，上游位置必须严格早于下游；
- $\mathcal{T}(G)$ —— **合法 trace 集合**，$|\mathcal{T}(G)| \geq 1$。当 $G$ 为一条链时 $|\mathcal{T}(G)| = 1$，边越稀疏则解越多。

### 2.3 判定方式：轨迹是否落在合法集合内

设 agent 实际跑出的执行序列为 $\hat{\pi}$（由网关录像的证据时间戳排序得到），判定为：

$$\mathrm{conformant}(\hat{\pi}) \;\Longleftrightarrow\; \hat{\pi} \in \mathcal{T}(G) \;\Longleftrightarrow\; \forall (u,v) \in E:\ \mathrm{evidence\_time}(u) < \mathrm{evidence\_time}(v)$$

其中：

- $\hat{\pi}$ —— 实际观测到的卡点达成顺序，取自 `evidence_time(cp)`（网关录像时间戳，非 agent 自述）；
- $\mathrm{evidence\_time}(cp)$ —— 该卡点被满足的证据时刻；
- **右侧等价形式是实际判据** —— 对每条依赖边逐条比对时间戳，复杂度 $O(|E|)$，**无需枚举 $\mathcal{T}(G)$**；
- 判定为真即无违规，不逐边穷举全部合法排列。

**这就避开了 trajectory lock-in**：只要 agent 的执行顺序满足 DAG 的偏序约束，无论它对应哪一条拓扑排序，都判为合法。

> **§7 修订说明**：本节原写作 $\mathrm{violation}(\hat{\pi}) = \min_{\pi \in \mathcal{T}(G)} d(\hat{\pi}, \pi)$（取与最近合法轨迹的距离）。该式**在一般情形下不可计算**，已更正为上式。详见 §7。

## 3. 落地现状核查（监工实测，2026-08-09）

**理念与当前代码存在差距，须记录在案。**

当前 `src/benchmark/evaluate.py` 的边集为：

```
CP_DAG_EDGES = [(cp1,cp2), (cp2,cp3), (cp3,cp4), (cp4,cp5), (cp5,cp6)]
```

实测该边集的拓扑排序数：

| 边集 | 边数 | $\|\mathcal{T}(G)\|$ | 说明 |
|---|---|---|---|
| **当前（链式）** | 5 | **1** | 唯一合法 trace = cp1→cp2→cp3→cp4→cp5→cp6，**事实上退化为全序** |
| 偏序示例（改 1 条边） | 5 | **2** | cp1 与 cp2 无序，两条均合法 |

**结论**：当前实现虽命名为 DAG，但因边集是一条链，$|\mathcal{T}(G)| = 1$，与 §2 的偏序语义**尚未对齐**。Owner 的裁定确立了语义，但边集本身需要按"哪些依赖是科学上必须的"重新界定，否则外部批评在当前实现上仍然成立。

## 4. 待办（不在本 ADR 内执行）

1. **重定边集**：逐条判定六个卡点之间哪些是科学强依赖（例如"未查性质则无法筛选"⇒ cp3 必须早于 cp4），哪些无强依赖（例如文献检索与候选建池）。无强依赖的边应删除。

## 7. 修订记录（2026-08-09，证伪复核后）

**触发**：Owner 质疑"这些不同点可能已被人做过"，监工执行反向证伪搜索（主动找反例、改用相邻领域术语），
详见 `research/差异点证伪复核-20260809.md`。

### 7.1 更正一处技术错误

原 §2.3 判据写作：

$$\mathrm{violation}(\hat{\pi}) = \min_{\pi \in \mathcal{T}(G)} d(\hat{\pi}, \pi)$$

**该式在一般情形下不可计算**。依据：BPOP（arXiv:2602.02806）明确指出
**对线性扩展（linear extension，即拓扑排序）做枚举/边缘化是 #P-hard 问题**。

- 本项目 6 个卡点时 $|\mathrm{Perm}(V)| = 720$，穷举勉强可行（已实测）；
- 但卡点增多即组合爆炸，且原文把它写成了**一般性判据**而未标注复杂度前提。

**已更正为** $\hat\pi \in \mathcal{T}(G)$ 的逐边检查（$O(|E|)$）。

**须记录的一点**：`src/benchmark/evaluate.py` 的实际实现**一直是逐边检查**
（`all(evidence_time(u) < evidence_time(v) for (u,v) in edges)`），
是本 ADR 文档把它"升级"成了一个更漂亮但不可计算的公式。
**代码是对的，文档错了** —— 形式化不等于更严谨，可能只是更容易错。

### 7.2 承认前置工作，撤回"新颖性"表述

原 §4.3 曾写"偏序 vs 全序这一区别恰是我们与 Desktop-Delta、SciDisco 的第三重差异"。
**该表述撤回**。经复核，"检查实际执行轨迹是否符合流程模型"是**业务流程管理（BPM）领域的成熟技术**，
名为 **conformance checking**，相关工作至少包括：

| 工作 | 关系 |
|---|---|
| **BPOP**（arXiv:2602.02806, 2026-02） | 把 agent 轨迹建模为图的**随机线性扩展**，MCMC 反推潜在偏序。**比本项目做得更深**（我们预设 DAG，它反推 DAG） |
| **LLM-Orchestrated Conformance Checking**（arXiv:2606.09489, 2026-06） | 抽轨迹 → 抽规则 → 翻译成可执行脚本 → 算 Trace Conformance Indicator。**与本项目流程同构**，领域为医疗 |
| **Skill Learning Using Process Mining**（ICPM 2024, arXiv:2410.12870） | 用 conformance checking 做技能检索，明确支持并行执行 |
| **EnvTrace**（arXiv:2511.09964, 2025-11） | execution trace alignment 评 LLM 代码语义等价 |

### 7.3 本 ADR 的有效结论（收敛后）

Owner 关于**偏序语义**的裁定**仍然有效且正确** —— 它是对 trajectory lock-in 批评的正确回答。
但其定位应为：

> **把 BPM 领域成熟的 conformance checking 适配到化学/材料发现任务上**，
> 而非"提出了一种新的顺序判定方法"。

**真正需要本项目原创的部分**：化学发现任务中**哪些卡点之间存在科学强依赖**
（例如"未查性质则无法筛选"成立，而"文献检索必须早于候选建池"不成立），
以及性质约束如何落成可执行断言。**这部分无法从 BPM 文献中拿到，必须由懂化学的人定。**

### 7.4 §4 待办不变

重定边集（删除无科学强依赖的边）仍须执行，且现在有了额外依据：
conformance checking 领域的标准做法就是**先有正确的流程模型**，模型错则符合性检查无意义。

## 8. 补充：本判据在 conformance checking 三分类中的位置（2026-08-09 读正文后补）

读 arXiv:2606.09489（`reference/ConformanceStrokeCare/`）正文查明，符合性检查在 process mining
文献里已有成熟三分类。**记录于此，是为了给本 ADR 的判据一个准确的学术归类，并解释 §7.1 那个错误公式的来源。**

| 类别 | 做法 | 代价 |
|---|---|---|
| **日志重放**（log replay） | 把每条轨迹拿到流程模型上模拟跑一遍。模型为 Petri 网时用 token-based replay，看最后缺了多少 token、剩了多少 token；一般情形用 fitness = 能成功重放的轨迹比例 | 粒度粗，只知道能不能跑通 |
| **轨迹对齐**（trace alignment） | 逐个活动找偏差：检测异步移动（轨迹与模型无法同时推进的那一步），每个偏差配代价，**算出总代价最小的最优对齐** | 诊断最细，但**计算量大得多**——可能的对齐数随日志规模快速增长 |
| **约束式**（constraint-based） | 把流程行为写成声明式规则，判轨迹满不满足这些约束 | 无"偏离多远"的连续度量，但便宜且可解释 |

### 8.1 本项目属于约束式

`no_path_violation` 把"cp3 必须早于 cp4"表述为一条声明式约束，逐边比对时间戳。
**这就是第三类。**

### 8.2 §7.1 那个错误公式的来源，现在能说清了

原写的 $\min_{\pi \in \mathcal{T}(G)} d(\hat\pi, \pi)$（取与最近合法轨迹的距离）**实质上是想做第二类（轨迹对齐）**。
而该类在文献中本就以计算量大著称，BPOP（arXiv:2602.02806）进一步指出枚举线性扩展是 #P-hard。

**教训**：写形式化判据前应先确认它属于哪一类既有方法 —— 若当时知道"取最优对齐代价"是 trace alignment
的标准形式且以计算量大闻名，就不会把它写成一般性判据。

### 8.3 一处可借的实现细节（来自同类工作）

[57] 把规则的判定结果设为**三值而非二值**：`not applicable`（该主体根本没做这项）/ `conformant` / `not conformant`。

**对本项目的含义**：我们当前的卡点判定是二值（达成 / 未达成），把"不适用"与"做错了"混为一谈。
例如某题若无文献可查，cp1 记 0 与 agent 偷懒不查记 0 无法区分。**建议后续引入 `not applicable` 档**，
使 open 类豁免等既有降级逻辑有统一表达。此项登记为待办，不在本 ADR 内执行。

## 9. 边集修订应加一条机器断言：边集须等于其自身的传递归约（2026-08-09 补）

**来源**：BPOP（arXiv:2602.02806）正文指出，偏序的**传递归约**（transitive reduction）
给出的就是 **Hasse 图** —— 即**无冗余边的最小边集**。

**含义**：§4 待办里的"删除无科学强依赖的边"，在数学上就是在求传递归约。
因此边集修订完成后，应加一条断言：

$$E = \mathrm{TransRed}(E)$$

其中：

- $E$ —— `CP_DAG_EDGES`，声明的依赖边集合；
- $\mathrm{TransRed}(E)$ —— $E$ 的传递归约，即逐条检查每边 $(u,v)$：若去掉它后 $u$ 仍可经其他路径到达 $v$，则该边冗余、应删除；
- 断言成立表示 $E$ 中**没有一条边是可由其他边推出的**。

**为何要断言**：写了冗余边不会导致判定出错，但会**白白缩小合法轨迹集合**
（多一条约束就少一批合法顺序），使 benchmark 比设计意图更严苛，
且这种收紧是**无声的** —— 不会报错，只会让某些本应合法的 agent 轨迹被判违规。

**实测验证（2026-08-09）**：

| 边集 | 边数 → 归约后 | 是否最小 | 合法拓扑序数 |
|---|---|---|---|
| 当前链式 cp1→…→cp6 | 5 → 5 | 是 | **1** |
| 偏序方案（cp1‖cp2 → cp3 → …） | 5 → 5 | 是 | **2** |
| 故意加一条冗余边 cp1→cp3 | 6 → **5** | **否**，冗余边 = (cp1, cp3) | 1 |

第三行说明该断言**确实能抓出冗余边**：加了 `cp1→cp3` 后边数变 6，但归约回 5，
且合法拓扑序数被无声地从 2 压回 1 —— 正是上面说的"无声收紧"。

**落地要求**：本断言应与 §4 的边集修订一并实现，归入项目既有的
"裁定类约束应落成测试机器断言"规范。
