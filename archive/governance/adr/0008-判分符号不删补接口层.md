## 背景

`template.json` / `case_001_cns.json` 的 checkpoint `logic` 里有一批符号跑不起来：`pool`、`pool ⊆ snapshot.universe`、`agent.value[c][p]`、`agent.pass_set/ranking/fail_property/best`、`grounded()`、`search_calls`、`history`，以及 `scoring.gate` 里的 `no_path_violation`。

此前的处理倾向是**删掉跑不起来的符号**（评审已删过一次"variables 字典"）。owner 2026-07-30 明确否定这条路径：

> "你做的事儿不是把它删掉、让它不存在、就当它没有了。你要正面面对这些问题，详细地解释它，把它的用处跟作用先明确下来，然后看看有什么比较好的解决方案。我觉得本质是因为你缺少了一个……"

排查结论：符号分三层——**世界层**（快照/case，已就绪）、**答卷层**（agent 交什么）、**录像层**（调了什么接口）。后两层**从未被定义过**，所以那些符号是悬空指针，不是错误符号。删一个 = 拆一道关卡（cp2–cp6 与路径验证各自依赖它们），直接撞红线 1。

## 决策

### 1. 一个符号都不删；补建「接口层」三件套

| # | 件 | 落点 | 解决的悬空符号 |
|---|---|---|---|
| ① | **取数网关**（4+1 工具、逐调用录像、查证预算） | `dag_poc/gateway.py`（待写） | `history` / `search_calls` / `grounded()` / 真值一致性 |
| ② | **答卷契约**（`submit_answer` 提交结构化 JSON） | 契约见 INTERFACE_CONTRACT §3.2 | `pool` / `agent.value` / `pass_set` / `ranking` / `reject_reasons` / `best` |
| ③ | **全局符号绑定表**（符号→层→类型→来源→缺失行为） | `dag_poc/docs/INTERFACE_CONTRACT.md` §3.3 | 全部符号的语义与求值口径 |

### 2. `pool ⊆ snapshot.universe` 改归属，不改存废

它的作用是**反幻觉**（禁止编造实体），不是"限制 agent 只能在我们清单里选"。因此：
- 对**答卷单**求值 = 反幻觉断言（保留计分，因为答卷是自由 JSON，可以塞假 ID）；
- 对**网关**求值 = 接口不变量（结构上恒真，违反即引擎 bug，不是 agent 失分项）；
- 追加更强伴生条件 `all(c in trace.queried for c in sub.pool)`：把候选池从"声称"钉到"录像"上。

### 3. variables 字典以「全局绑定表」形态复活

当初删它是因为**位置错**（塞在每个 template 里、随 case 复制、维护不起），不是因为**东西错**。符号是跨 template 通用的（任何发现类任务都有建池/查证/筛选/排序/提交），故绑定表提到全局一层、由引擎实现一次，template 只声明用到哪些符号。

**PR-02（logic 符号规范）标 CLOSED 是超前的**：它只覆盖了书写规范（`{}` 只包 JSON key），语义绑定这一半从未覆盖 → 新开 PR-15 承接，PR-02 记录保留并加覆盖面备注（销号制不改历史）。

### 4. 候选空间口径：v1 闭合宇宙（发现式开放），v2 留开放宇宙扩展

- **v1 = A 方案**：agent 不拿清单，必须通过 `search_candidates` 检索我们的实体表；真值一致性、录像可核、防污染、可复现四项由构造保证。
- **v2 = B 方案**（真实外部检索 + 身份解析）作为扩展；接入时只放宽两处语义（`universe` 外候选不计分也不罚；cp3/cp4 定义域收为 `sub.pool ∩ universe`），**符号表不动**。
- 因此 **PR-05「开放空间」的措辞收紧为「发现式开放」**，在 problems.md 留痕。

### 5. 禁止用 LLM 抽取器补答卷层

从散文里抽 `pass_set` 等字段 = 把 LLM judge 从后门放进来，且抽取错误会伪装成 agent 失分。答卷层**只走结构化提交**；缺字段即该 cp 判 0 并给 reason 码。

### 6. 顺带钉死四处修复（详见 INTERFACE_CONTRACT §6）

`first_failed_prop` 顺序敏感 → 改 `gold.failed_props[c]` 集合判定；排序并列 → 改 key 序列比对；`no_path_violation` → 由 `evidence_time(cp)` 定义（录像最晚事件时刻，逐边比较）；空池真空通过 → 显式加 `len(sub.pool) > 0`（否则空转轨迹能拿满分，破坏 GOAL §4.3 质量门）。

## 理由

1. **不删是硬要求**：五个 agent 侧符号 = 五道关卡的定义域，删任何一个都让 benchmark 向"只看终答"退化（红线 1）。
2. **`ACTION_RULES` §6 早已写死"所有性质数据均来自数据库查询接口，接口返回值即为真值"**——那个接口从未被实现，这就是缺失层最直白的证据；补上它，规范首次被落实。
3. **匿名化 × 开放空间在当前形态下互斥**（agent 在外部世界检索到 Metoprolol，我们的世界里它叫"分子A"，无身份解析层则两个命名空间无法比较）。闭合宇宙 + 网关是唯一让二者共存的形态。
4. **与既有决议全部相容**：GOAL §4.2「查产物不认动作」首次可执行；ADR-0004（不被实现绑架）——网关是我方出卷设施，与灵枢后端真假解耦，ADR-0003 的"药物线只能测编排诚实度"随之解除；ADR-0005「一个数不编」——网关只返回快照值。

## 后果

- ✅ cp2–cp6 全部可执行，且**路径验证第一次有了数据源**（此前 `scoring.gate` 依赖的 `no_path_violation` 无任何东西能算它）。
- ✅ 药物线不再受"灵枢药物后端是 mock"限制（网关就是真算的数据库）。
- ⚠️ **`get_property` 直接返回真值 ⇒ cp3 考的是"真查 + 如实转述"，不是预测能力**。难度责任转移到"宇宙规模 + 查证预算"两个旋钮。
- ⚠️ **当前 8 分子快照必须扩容**：8 × 3 = 24 次查询即可穷举，过程分几乎没有难度（红线 1 的软化版）。宇宙扩到 60–200 + 限查证预算（MADE 的 oracle 预算范式），新开 PR-17。
- ⚠️ **附加前提**：`smiles_masked` 掩码必须不可逆，否则 agent 反推出真实分子名即可绕过检索靠记忆作答，匿名化的防污染作用（红线 5）失效。
- 🟡 材料线快照（`supercon_mock_v0.2`）尚未走本契约：`condition`（常压/高压陷阱）为枚举型约束，需补枚举比较口径。

## 补强（2026-07-30 同日，owner 定性）· 缺的那一个 = 标准 LLM JSON 输出，template 本身不完整

owner 对本 ADR 的根因做了更精确的定性：

> "本质是因为缺少一个标准的 LLM JSON 输出——因为没办法确定 LLM response 里有没有类似 'agent.best' 的 JSON key，你现在写的 template 本身是不完整的。"

据此钉死三条（均已落地）：

1. **答卷格式是 template 的组成部分，不是引擎的实现细节**。template = query_template（题目）+ **answer_contract（答卷）** + checkpoint_template（关卡）+ slots（填充位）；缺 `answer_contract` 的 template 一律判为不完整，不得进入实例生成。已写入 `template.json`（含 JSON Schema、delivery、validation、derived_bindings）与 `case_001_cns.json`（enum 与条数物化 + 占位 ID 的 format_example）。
2. **"key 在不在"必须是结构性保证，不能靠题面叮嘱**。主通道 = API 侧 `response_format={"type":"json_schema","strict":true}`；备通道 = 网关 `submit_answer(payload)` 用同一 schema 校验；无结构化输出能力的 agent 走本地校验 + 一次语法层重交。**三条通道共用一份 schema，判分侧无分支**。引擎无条件本地再校验一次（各厂商 strict 支持度不一，不得让解码器差异污染模型间可比性）。
3. **答卷 schema 提到全局一层，且必须是真 template**（同日第二轮收敛，owner："schema 写得太复杂、泛化性不好；它的定位是抽指标的原料，要求只有两条：schema 泛化性好、checkpoint 涉及的 key 都能抽到"）：
   - 落点从 template 内联改为**全项目共用一份** `dag_poc/answer_schema.json`（与符号绑定表同一原则：跨 template 通用的东西不住在 template 里）；template/case 只保留引用。
   - **schema 与 case 解耦**：删掉 `enum`（性质名合法性交引擎按 `case.props` 校，码 `UNKNOWN_PROPERTY`）与 `minItems=约束条数`（"漏查性质"改由 cp3 的 `p in sub.value[c]` 拓住，更可归因）→ **case 不再物化 schema**。
   - **删冗余字段 `verdict`**：合格与否由 `reject is None` 单一表达；冗余会凭空造出"自相矛盾"这类与科学无关的失分模式，cp4 同步去掉自洽子条件。
   - 最终形状：**3 个顶层字段**（`candidates` / `ranking` / `answer`）+ **3 个候选字段**（`id` / `measurements[{name,value}]` / `reject`）；`value` 允许 `number|string` 以承载类别型真值（材料线 `condition=ambient` 无需改 schema）。strict 仍要求定长 key 数组表（动态 key 字典写不出合法 schema）。
   - **交圈验证（已实跑）**：logic 里出现的 6 个答卷侧符号 100% 可从三字段派生；金标准答卷 cp2–cp6 全过；空转答卷 cp2/cp3/cp4 全不过；case 的 `gold_expected` 与快照重算完全一致。

分工口径：**schema 拦格式（key 缺失/类型/enum/条数），绑定层改形（并保留 UNKNOWN_ID 不静默剔除），logic 拦科学正确性与内部一致性**（如 `verdict=pass` 却填了 `reject_property` → cp4 自洽子条件亮红）。
