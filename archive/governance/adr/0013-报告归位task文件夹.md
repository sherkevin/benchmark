# ADR 0013 · 报告归位 task 文件夹：一 task = 一份 task.md + 一份 report.md（修订 0007 §2/§7/§36）

| 字段 | 值 |
|---|---|
| **状态** | Accepted |
| **日期** | 2026-08-01 |
| **决议人** | jingwu（owner 直接指示） |
| **领域** | 仓库组织与文档规范 |
| **关联** | **修订** [[0007]] §2（research/ 平铺容纳一切调研报告）、§7（task/ 冻结不维护）、§36（新增调研报告→research/）；沿用 0010 的"改名保 git 血缘"做法 |

## 背景

owner 明确指示：

> "所有的报告要写到对应的 task 的文件夹下，一个 task 文件夹里包含一份任务说明，一份完成报告。"

这与 ADR-0007 的三条现行规定**直接冲突**：

| 0007 原条 | 原文 | 冲突点 |
|---|---|---|
| §2 | "`research/` = 调研文档，平铺…**一次深度调研的报告 = 一个平铺 `.md`**" | 报告归 research/，不归 task/ |
| §7 | "**`task/` 冻结**：业务方历史任务存档，暂不维护、不删除" | task/ 不该再动 |
| §36 | "新增文档对号：**调研报告/benchmark 解读 → `research/` 平铺**" | 同 §2 |

变更的直接动因：`task15` 的调研结论同时存在于 `task/task15/report.md` 与 `research/query构造与专业性保证.md` 两处，owner 需要单一入口。

## 决策

### 1. 硬规范：一 task = 一份 `task.md` + 一份 `report.md`

- `task.md` = 任务说明（上游诉求原话、对齐 GOAL、子目标与验收三要素）；
- `report.md` = 完成报告（结论先行、做了什么、结论是什么、证据在哪、遗留）；
- 二者**文件名固定**，不再使用 `goal.md` / `result.md` / `CONCLUSION.md` / `README.md` 等别名。

### 2. `task/` 解冻（撤销 0007 §7）

历史 task 不再是只读存档：**task1–task7 的旧命名一律改名归位**（`git mv` 保血缘）：

| task | 改名 |
|---|---|
| task1–4、task6 | `goal.md`→`task.md`，`result.md`→`report.md` |
| task5 | `goal.md`→`task.md`，`CONCLUSION.md`→`report.md`（`results.md` 为实测数据，保留） |
| task7 | `goal.md`→`task.md`，`README.md`→`report.md`（原为 POC 索引，实为完成汇总） |

`task/_templates/task_template/` 同步改名，使模板即规范。

### 3. `research/` 按归属拆分，不清空（修订 0007 §2/§36）

判据是**"该文档是否只服务于单一 task"**：

| 类别 | 处置 | 本次实际 |
|---|---|---|
| **单一 task 专属的调研报告** | 移入该 task 文件夹，与 `report.md` 并存作为调研附件 | **8 份**：task9 收 5 份（目标定义 v1、发现类任务构造方案、投稿策略、开源核验、四会横评）、task14 收 2 份（数据集分类详解、权威性总览）、task12 收 1 份（权威数据源与缺口指南） |
| **跨多个 task 共用** | 留 `research/`，由各 task 的 report 交叉引用 | INDEX.md、query 构造与专业性保证.md、query 写法调研报告.md、各 benchmark 造题法详解.md、benchmark 数据库调研报告.md 等 |
| **无 task 归属的主题知识** | 留 `research/` | 长程任务 Benchmark.md、评测能力维度.md、Goal-Drift.md、材料发现长程 Checkpoint.md、测试 Agent 调研总报告.md、实验矩阵.md 等 |

**理由**：全部清空 research/ 会迫使跨 task 的通用知识强行认领一个宿主 task，且需改写 114 处交叉引用；按归属拆分兼顾新规范与引用稳定性。

### 4. 引用一致性由脚本保证，不靠人工

搬移与改名后，**全仓 `.md` 的相对路径引用按新位置逐处重算**（`os.path.relpath`），并做断链核验。本次核验结果：与搬移/改名相关的断链**从 2033 处降至 0 处**（受管目录内；`.qoder/repowiki` 自动生成的 `file://` 伪链接不计）。

## 理由

1. **owner 的单一入口诉求**：找一个任务的结论时，只需进它的文件夹，不必在 research/ 里按主题猜文件名。
2. **`ACTION_RULES` §1.4 本就要求"task 完成时写 `task/{task_name}/report.md`"**——0007 §2 让报告落 research/ 与之矛盾，本 ADR 消除该矛盾。
3. **改名而非重建**：全部走 `git mv`，历史与 blame 完整保留（沿用 ADR-0010 的做法）。

## 后果

- ✅ 16 个 task 全部具备 `task.md` + `report.md`（task8/task13/task16 的 report 仍待补，见下）。
- ✅ `research/` 从 22 份精简至 14 份，留下的都是跨 task 或无宿主的通用知识。
- ⚠️ **三个 task 仍缺 `report.md`**：`task8`（判分符号接口层，未收口）、`task13`（SMILES 修复，暂停中）、`task16`（未开工）。按本 ADR 它们在收口时必须补齐。
- ⚠️ **`research/README.md` 与 `research/INDEX.md` 的清单需同步**（已随本次一并更新）。
- 🟡 后续新 task 一律先建 `task.md`（`ACTION_RULES` §1.2「无 task 不动手」），完成时补 `report.md`；调研中间产物若只服务该 task，直接落在 task 文件夹内，不再进 research/。
