# 决议(ADR)索引

> **定位(2026-07-26 起)**:本目录是**写文档的参考资料库**,不是呈阅文档。除项目级关键决议外,也收录**对话中共同商讨得到的及时性经验和规范**(如仓库组织、文档纪律),供最终写论文/报告时引用。

本目录存放**项目级关键决议**,遵循 ADR(Architecture Decision Record)模式:

- **一决议一文件**,按时序编号 `NNNN-slug.md`(4 位补零)
- **自包含**:每个 ADR 含状态 / 上下文 / 决策 / 不动的部分 / 触发动作 / 后续影响 / 相关
- **不静默改写**:原决议被超越时,**在原文件标注 `Superseded by NNNN` + 写新 ADR**,而非编辑老的——决策史本身有价值
- **目标长度**:~40–80 行,集中一个决定

## 写什么 / 不写什么

**写**:设计决策(选 X 不选 Y)、架构切分(归属层 A 不归属层 B)、范围声明(主轴 / 红线)、解决的权衡、不变量。
**不写**:实现细节(放代码)、单步任务进度(放 todo)、对话问答(留在 chat history)、PRD / 论文正文(各自有归属)。

## 写新 ADR 的流程

1. 取下一个空闲编号(本索引最大 ID + 1,4 位补零)
2. 起 kebab-case slug(短,描述决定本身而非领域)
3. 用 0001 的结构模板,~40-80 行
4. **追加一行**到本索引表(状态、日期、一句话)
5. 若 supersede 旧 ADR,**先去老 ADR 把状态改为 `Superseded by NNNN`**,再写新 ADR
