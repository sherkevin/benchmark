# ADR 0015 · 后端库与 A/B 隔离以 E1 的文件系统分层规格为准；E3 改 B 加载层适配

| **日期** | 2026-08-06 |
| **决议人** | 监工（跨线冲突裁定，报 owner 备案） |
| **领域** | 后端库布局与 A/B 物理隔离 |
| **关联** | 落实 [[0012]] §1 第二类的 A/B 分离 · 落实 `goal.md` §2b② 物理分层 · 裁定 E1（后端库规格契约）与 E3（`b_partition.json`）的冲突 · 同 [[0014]] 属跨线契约归属裁定 |

## 背景：E1 与 E3 对同一对象（B 侧数据）给出两套不兼容方案

| 维度 | **E1 的后端库规格契约**（15:29） | **E3 的 `b_partition.json`**（16:28） |
|---|---|---|
| A/B 隔离机制 | **文件系统隔离**：`<tool>_A.jsonl` 与 `<tool>_B.jsonl` 物理分离，读取层**不 open B 文件**即绝对隔离 | 单文件 `b_partition.json` 加载进内存后做集合判断 |
| 键空间 | **InChIKey + 规范化 SMILES 两列**（真实化学身份） | 扁平字符串（`ed:aa:add_atom:F`、`bm_placeholder_001`） |
| 分库粒度 | **每个 tool 一个子目录**（5 个需库的 tool 各一套 A/B + MANIFEST） | 全局单文件 |
| G_B 组织 | 按 case 组织，带 `case_ref` | 全局扁平列表，**无 case 维度** |

E3 的 gateway.py（16:28）晚于 E1 的契约（15:29），**有条件核对但未核对**；且其 report §5 称"E1 只需替换本文件即可，网关只读本文件、接口不变"——该表述不成立（数据布局、键空间、case 维度三处都要改代码），会误导 E1 按错误假设交付。

## 决策

### 1. 以 E1 的文件系统分层规格为准

三条理由：

1. **文件系统隔离强于查询过滤**。`goal.md` §2b② 要求的是**物理分层**——"A 的任何查询不得带出 B 内容"。E1 的"读取层不 open B 文件"是物理上不可达；E3 的"加载全部到内存再做集合判断"本质是查询过滤，一次代码疏漏（忘记过滤、日志打印、异常回显）即泄漏。
2. **真实化学身份优于合成字符串**。E1 用 InChIKey + 规范化 SMILES；E3 用 `ed:{anchor}:{op}:{detail}` 拼接串，无化学意义——这正是"grounding 条件③退化为入参拼接、鉴别力为 0"的根源（见 E3 验收意见致命 5）。改用真实化学身份后，`normalize(edit_op) == answer` 才有判别力。
3. **per-tool 分库符合 goal §6 步 4**（"每个 tool 有自己的子库，不共用大杂烩"）。

### 2. E3 的适配义务

| # | 动作 |
|---|---|
| 1 | **B 加载层改为按 E1 目录扫描**：`dag_poc/data/backend/<tool>/<tool>_B.jsonl`；**A 侧读取白名单只允许 `*_A.jsonl`**，B 文件不得进入任何查询路径 |
| 2 | `check_molecule_exists` 只读 `check_molecule_exists_B.jsonl` 的两列索引（InChIKey + 规范化 SMILES），**只返单 bool** |
| 3 | **G_B 改为 per-case**（`{case_id: {members, g_b}}` 或带 `case_ref`），以支撑多题的 `hit(G_B)` 判定 |
| 4 | **A 与 B 放进同一命名空间**（都用 InChIKey/规范化 SMILES）——否则隔离测试永远不可能失败，也就永远不能证明隔离有效 |
| 5 | 删除或改造 `b_partition.json`：可保留为**过渡期 fixture**，但须标注"占位、非交付形态"，且不得作为隔离已验证的依据 |

### 3. 结构规范化的归属（消除一处空档）

E1 契约称 `edit_molecule` / `normalize_structure` "无后端库需求（纯计算）"，而 E3 的实现只判字符串长度。**两边都对了一半**：它们确实不需要"库"，但需要**真实的化学规范化能力**。

**归属裁定**：
- **规范化算法归 E3**（属工具实现），须用 RDKit canonical SMILES 或 E1 约定的 InChIKey 口径，**不得用字符串拼接**；
- **匿名映射表归 E1**（属数据），E3 通过约定接口取用；
- 在真实化学表示就位前，E3 须在契约中把 grounding 条件③标注为"**占位、当前无鉴别力**"，**不得作为已实现判据宣传**。

### 4. 通用规则（承 ADR-0014 §4）

**同一对象的契约只能有一个所有者。** 后端库布局与 A/B 隔离机制的所有者是 **E1**；E3 按其规格实现读取层。**冻结前须由监工做跨线核对**——本次与 ADR-0014 是同一类漏检。

## 影响

| 对象 | 动作 |
|---|---|
| **E3** | 按 §2 五项改 B 加载层；改 `normalize_structure` 用真实化学规范化；report §5"接口不变"的表述须撤回；隔离测试重写（见 E3 验收意见致命 3） |
| **E1** | 后端库规格**维持不变**，按原契约交付；`check_molecule_exists_B.jsonl` 的两列索引与 G_B 的 `case_ref` 为 E3 的硬依赖，请优先交付 |
| **E5** | open case 的 `G_B` 按 per-case 组织，与 case 文件一同落盘 |
| **E6** | 隔离验证纳入跑测前置检查 |

## 备案

本裁定由监工做出以解除并行阻塞，**报 owner 备案**。若 owner 认为应以 E3 的单文件方案为准（实现更快、但隔离强度与化学判别力更弱），则本 ADR 需改为 Superseded。
