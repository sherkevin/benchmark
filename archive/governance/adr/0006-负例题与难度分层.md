# ADR 0006 · 构造规范:必须含负例题 + 每道题打难度标签

- **状态**:Active
- **日期**:2026-06-13
- **领域**:benchmark 题目构成
- **关联**:[[0005]](标准建题法)· [[0002]](5 步法)· 走偏类型学 D6

## 背景

构造到 Phase B,6 道模板都按"有正确答案=找到东西"设计。Owner 质疑:**"需要构建负例吗?需要区分难易吗?"** 这把两个**决定 benchmark 是否真正能测出 agent 水平**的设计问题逼上台面。

## 决策

### 1. 负例题(答案=没有/不行/不成立)占 15–25%

"负例"在我们语境里有三种,**别混**:

| 类型 | 是什么 | 要不要 |
|---|---|---|
| **A. 负例题目**(答案就是"没有") | Zn-Sn-O 这种真无稳定相的体系 / Open Targets 低分靶点-病对 / 无解逆合成 | ✅ **必须**(占 15–25%) |
| **B. agent 走偏轨迹** | A3 里手搓的那种"乱来"trace | ❌ **不要进正式题库**,只留少量做"判分器能分辨好坏"的校准集 |
| **C. 判分器反测** | 随机/偷懒能不能蒙过 | ✅ 属于 QA,已有 |

**为什么 A 必须有**:如果全是正例,benchmark 就只考"能不能找到东西",**考不出"该说没有时敢不敢说没有"**。一个只会报喜的 agent(D6 过度声称/不知停)在全正例集上反而高分——这正好是我们最不想放过的走偏。

**负例源**:现成免费——筛子丢掉的"0-1 个稳定相"体系、Open Targets 低分对、无解逆合成。

### 2. 每道题必须打难度标签,正式集按难度梯度配比

**没有难度梯度的 benchmark 区分不出 agent**(要么全对要么全错,排不出名次)。

我们有**现成的难度旋钮**(无需新造):

| 旋钮 | 怎么调 | 已就位? |
|---|---|---|
| **L0–L3 介入档**(主轴) | L0 只给目标 / L3 给完整参考路径 | ✅ |
| **链长 / 阶段数** | 步骤越多越难 | ✅ |
| **答案歧义度**(凸包贴脸) | 最稳与次稳能量差越小越难 | OQMD 现成可算 |
| **搜索空间 / 预算松紧** | 候选越多预算越紧越难 | 可调 |

每道题给 `difficulty` 字段(由上面四个旋钮算);分**易/中/难**几档;**最终难度用 baseline 实跑校准**(几个大模型跑下来,多少能过 = 经验难度,Phase E 做)。

## 理由

- 负例题考 agent 会不会瞎报成功(D6),这是科学 agent 最该有的素质之一;我们恰好有现成的免费负例源。
- 难度梯度让 benchmark 能**拉开 agent 排名**,而不是"要么全会要么全不会";旋钮现成,不增加工程量。
- A 类负例和难度标签**都不违背 ADR 0005**(GT-first 反向构建):负例就是答案=无的根,难度标签只是属性。

## 后果

- ✅ 实例化脚本增加 `label: positive / negative_control`,负例自动从"筛掉的体系"产出。
- ✅ 每道题 JSON 增加 `difficulty` 字段。
- ⚠️ 配比:正式集目标 **正例 75–85% / 负例 15–25%**,各难度档都有。
- ⚠️ 负例题的"科学类检查点":agent 应回答"无稳定相"——需补一条 `final_answer_none` 的 GT 字段,判分器加"答=无"的判定分支(Phase C 前加进 hard_verifiers)。
