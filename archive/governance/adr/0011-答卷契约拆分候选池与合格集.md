## 背景

2026-08-01 为回填《各benchmark造题法详解》§1（"我们自己的一条题从题面走到得分"）而核对 dag_poc 实跑数据，发现 5 个判分问题。其中 2 个是 T-37 立项时已知的，**另 3 个是本次诊断挖出的、且更根本**——最严重的一个使 5 道题里的 3 道**任何模型都不可能做对**。

触发点是一个可证伪的错误断言：文档原稿写"cp4 的 F1 是天花板，agent 永远拿不到 1.0"。核对 `src/benchmark/evaluate.py:109` 后确认 F1 = `2·tp/(|P|+|G|)`，agent 只提交 `{aa}` 即可得 1.0 —— 该断言错误，真问题在别处（见决策 1）。由此逐条回溯实现，才暴露出后面几个。

## 决策

### 1. 答卷契约拆分「候选池」与「合格集」为两个字段

**问题**：`ranked_candidates` 一个字段被两个 checkpoint 当成语义不同的东西用，互相拉扯：

| cp | 把它当什么 | 激励方向 |
|---|---|---|
| cp2 建池 / cp3 性质覆盖 | **候选池**（考察过的全部候选） | 交得越多越好（池越全，覆盖分越高） |
| cp4 筛选正确性 | **合格集**（判定为满足约束的） | 交得越多越差（F1 被假阳性拉低） |

因合格集 |G|=1，F1 = 2/(k+1)（k = 提交数）：实测 kimi/qwen 交 5 个 → 0.33，glm 交 6 个 → 0.29，与 `_all_results.json` 完全吻合。**这不是天花板（交 1 个就能满分），而是激励自相矛盾**——agent 无法同时最优化 cp3 与 cp4。

**决策**：答卷契约拆成两个字段，各自绑定明确的 checkpoint：

```json
{"candidate_result": {
  "screened_pool":     ["<考察过的全部候选ID（池，越全越好；cp2/cp3 按此评）>"],
  "ranked_candidates": ["<判定合格的候选ID，从优到劣；第一个为最终推荐（cp4/cp5/cp6 按此评）>"]
}}
```

向后兼容：旧答卷无 `screened_pool` 时自动回落为 `ranked_candidates`（`evaluate.py` 内 `pool = ... or list(ranked)`），历史 trace 仍可评分。

> 与 [[0008]] 的关系：0008 已把"池 vs 合格集"的语义分离写进全局 `answer_schema.json`（`candidates[].reject is None` 表达合格与否）。本 ADR 是把该分离**落到 dag_poc 的实际实现**——dag_poc 用的是简化版 `response_template.json`，此前只有单一 `ranked_candidates`，未跟上 0008 的语义。**0008 的设计是对的，缺的是实现。**

### 2. cp5 空答卷不得给分

原实现 `if set(ranked) == gps: 1.0` —— 空集等空集也判满分。实跑中 glm 在 4 道题上 `best=None`（根本没交答案）却 `cp5=1.0`，对应 process 被虚高到 0.17–0.20。

**决策**：`if not ranked: cp5 = 0.0` 前置。修后这 4 处均为 0.0，process 降至 0.067–0.10。此为 0008 §6 "空池真空通过"同类缺陷在 cp5 上的复发，口径统一为**空答卷在任何 cp 上均不得计分**。

### 3. mock 检索截断致 3 道题结构性无解（最根本）

`mcp_mock_server/mock_server.py` 的 `search_molecule_database` 在检索词匹配不上时 fallback 返回 `db.molecule_search_all()[:5]`。由于查询词是自然语言（如 `"cardiovascular hERG safe long half-life"`）、而库内只有 SMILES 与匿名 ID，**字面匹配恒为 0、恒走 fallback** → 20 个分子里只有 `aa`–`ae` 可被检索到，其余 15 个永不可见。

| case | gt | 修复前 | 修复后 |
|---|---|---|---|
| cns_metoprolol | `aa` | 可解 | 可解 |
| bronchodilator_theophylline | `ab` | 可解 | 可解 |
| cardiac_sotalol | `ba` | **结构性无解** | 可解 |
| anxiolytic_diazepam | `bb` | **结构性无解** | 可解 |
| antibiotic_sulfamethoxazole | `bc` | **结构性无解** | 可解 |

**决策**：fallback 返回全库（20 条），并在代码内留注释说明该截断的历史后果，防止回退。

这同时**推翻了 T-37 问题③ 的原归因**。原假设是"Metoprolol 太有名 → 匿名化被穿透 → 模型从常识反推"，修法是"打散 gt 的匿名 ID"。真因是：所有模型的候选池都只有 `aa`–`ae`，而 3 道题的 gt 在 `ba/bb/bc`，**gt 不在池中，必然答错**；qwen 在答错题上交 `aa` 只是因为池里没有别的可选。**若按原归因去改匿名化，会白改且掩盖真问题。**

### 4. 评分主流程必须读真实答卷，禁止从 trace 反推

`evaluate.py` 的 `__main__` 原先不读 `_response.json`，而是从 trace 的 `predict_admet` 入参"推断"一个假 response —— 推断出 `C0CC`、`Donepezil` 这类根本不是候选 ID 的值。**即 `_all_results.json` 里的历史分数并非真实答卷所得。**

**决策**：main 只读 `traces/<case>__<model>_response.json`；`response` 为 `None`（agent 未交卷）时如实传入并按缺字段判 0，不做任何补救推断。这是 [[0008]] §5"禁止用 LLM 抽取器补答卷层"的同类原则——**禁止用任何启发式补答卷层**，包括从 trace 反推。

同时补 `aggregate()` 输出 `process / gate / gate_failed_cps / task_score`，权重与阈值取自 `template.json` 的 `checkpoint_dag`，消除"过程分被当成最终分"的读数错误（真实情况：CNS 题三模型 process 0.846–0.867，但 cp4 未过阈 → gate 不过 → **task_score 全为 0.300**）。

### 5. 波次 0 的旧数据整批作废

现有 15 个实验点是在"检索截断"环境下跑出的，其中 3 道题不可能做对，**命中率 4/15 不反映真实能力，不得作为论文数据引用**。新开 PR-26 记录，重跑列为 T-43。

## 理由

1. **红线 1（不得向"只看终答"退化）**：cp4/cp5 两处口径错误都在虚高或压低过程分，直接损害过程判分的可信度——而过程判分是本项目相对 18 篇对照工作的全部增量。
2. **`ACTION_RULES` §6"接口返回值即为真值"**：若接口本身只暴露 25% 的宇宙，"真值"就是残缺的；截断使 GT-first 反查构造法的前提（答案在候选空间内可达）被破坏。
3. **诚实优先于结论好看**：修复后命中率仍是 4/15、门控通过 0/15、且暴露出"5/15 是 agent 压根没交卷"这一此前被假 response 掩盖的事实。这些数字比原先"过程分 0.85"难看得多，但它们是真的。

## 后果

- ✅ 3 道结构性无解的题变可解；cp2/cp3 与 cp4 的激励冲突解除。
- ✅ 判分链首次全程基于真实答卷，并输出 `gate` 与 `task_score` 全字段。
- ⚠️ **旧 15 点数据作废**，必须用修复后的 mock server 重跑（T-43）；重跑前任何基于 `_all_results.json` 的结论都不可引用。
- ⚠️ **候选池扩到 20 个后，各 case 的合格集 |G| 是否仍为 1 需重新穷举确认**。若 |G|>1，则 cp6 的"接近度衰减"分支首次可测（该分支至今无 case 触发，是 T-21 的立项理由），可关 T-21。
- ⚠️ **cp6 仍存在规格与实现不一致**：`template.json` 规格写"在合格集内但非最优按距离衰减"，`evaluate.py:121` 实现给常数 `0.5`。本次未改（改动会影响历史分数可比性），留待 T-43 重跑时一并对齐。
- 🟡 `screened_pool` 目前只有 dag_poc 简化契约支持；与 [[0008]] 全局 `answer_schema.json` 的 `candidates[].reject` 表达法尚未统一，后续应收敛为一套。
