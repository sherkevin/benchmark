# ADR-0027 · 预测型题目不得配通用 oracle；可测集必须闭合

- 状态：Accepted（Owner 2026-08-21 认可）
- 决策者：Owner
- 关联：为 [[0025]] §4「库外分子返 NOT_FOUND」补第二条独立理由 · 承接 [[0026]]（六配置矩阵）· 起因于第一组 `case_dr_qed_01·open` 的判据② 三档全不成立
- 起因：讨论"删掉 `list_pool`、改让 agent 生成分子再测"这个修法时，实测发现**只要 `measure_qed` 收任意 SMILES，agent 花一次调用测一个近似物就能拿到目标的精确答案**——问题不在预算，在题型与工具的不兼容

---

## 1. 决议（两句）

**当一道题要测的是"预测一个被扣住的数值"时，绝不能给一个能对任意结构现场算该数值的通用 oracle。**

**这类题的可测集必须闭合**：oracle 只对一个受控的、有限的实体集返回真值，集外一律返 `NOT_FOUND`／`probe_unavailable`，且这个"集内/集外"的边界**按结构定义、不按数据库成员定义**。

## 2. 为什么：数值是粗函数，答案落在一个大等价类里

`case_dr_qed_01` 要 agent 预测目标分子 `m05`（para-甲氧基苯甲酰胺，N-十一烷基链）的 QED，
真值 0.5545。把它的近似物在同一链长（n=11）逐个用 rdkit 算真值：

| 近似物（换头部，链长不变） | QED | \|Δ\| | 柯西分（尺度 0.041） |
|---|---|---|---|
| para-OMe（= 目标本身） | 0.5545 | 0 | 1.000 |
| **meta-OMe（间位异构体）** | **0.5545** | **0.0000** | **1.000** |
| **ortho-OMe（邻位异构体）** | **0.5545** | **0.0000** | **1.000** |
| para-Me（甲基替甲氧基） | 0.5534 | 0.0011 | 0.999 |
| para-F | 0.5659 | 0.0114 | 0.928 |
| 无取代苯甲酰胺 | 0.5689 | 0.0144 | 0.890 |

**10 个近似物里 6 个柯西分 ≥0.8；三个位置异构体给出的值到小数点后四位完全相同。**

根因是结构性的：**QED 是 8 个粗描述符（MW/ALOGP/HBA/HBD/PSA/ROTB/AROM/ALERTS）的几何加权，
它对取代位置完全不敏感、对小取代基替换几乎不敏感。** 所以"m05 的 QED"不是这个特定分子的
性质，而是**一整类分子的共同性质**。给了通用 oracle，agent 只要写一个间位异构体、
**花一次调用**就拿到精确答案——外推推理被完全绕过。

**预算防不住它。** 预算能压爬山搜索（需成百上千次求值），压不住"一次调用的近似物查表"。

反直觉的对照数：目标系列自己的 n=10 / n=12 只给 0.382 / 0.344 分（链长真的影响 QED），
**比近似物差得多**——所以"造 n=10/n=12 内插"反倒是小威胁，真正的洞是近似物等价类。

## 3. 由此得到的架构不变量

> **凡"预测被扣住的量 y(m)"的题，其可测集 M 必须满足：agent 无法通过测 M 内任一实体
> 直接得到 y(target)。**

实现该不变量的两条路（本项目取前者）：

| 路 | 做法 | 代价 |
|---|---|---|
| **闭合可测集**（本项目） | oracle 只认受控集，集外返 NOT_FOUND | 需保证 target 及其近似物都在集外 |
| 让 y 对结构敏感到无等价类 | 换一个不是粗描述符的目标量 | QED/ADMET 这类天然是粗函数，做不到 |

**"集内/集外"必须按结构判，不按数据库成员判。** 现行 `ws_mcp_server_qed01_open.py:125`
是 `if mid not in POOL or not rec["measurable"]`——挂在池记录上。一旦允许生成分子，
agent 可构造一个不在池里的近似物，它 `not in POOL` ⇒ 现行代码会走 NOT_FOUND 分支
（碰巧安全）；但若哪天可测性改成"查到就返"，就会泄漏。**故边界须显式写成结构判据**
（如"目标骨架 + 链长 n≥7 一律 probe_unavailable"），不依赖"恰好不在池里"。

## 4. 与 ADR-0025 §4 的关系：这是第二条独立理由

ADR-0025 §4 已论证"库外分子返 NOT_FOUND"是为了**不掉进爬山搜索赛道**（GuacaMol/TDC-PMO）。
本 ADR 补一条**独立且更硬**的理由：

> 即使不考虑赛道，**闭合可测集本身就是"预测型题目能成立"的前提**——
> 可测集一开，预测题的答案就能被近似物查表绕过，与搜索无关。

两条理由指向同一个实现（闭合可测集），但适用面不同：§4 针对"优化搜索"，本 ADR 针对
"数值预测"。**以后每设计一道预测型题，都要过这道不变量。**

## 5. 对"生成式 open"的直接结论

删掉 `list_pool`、让 agent 生成分子再测——这个修法（Owner 提出）**方向正确，但不能用在
预测数值的题上**，因为它与本 ADR 冲突。

生成式 open 的正确形态是 **`goal.md §2b` 已写好的那套**：agent 推理出一个**分子**（而非数值），
存在性接口**只返 bool、绝不返性质**，判分看是否命中落盘的合格集 `G_B`。
**答案形态是"一个分子"而不是"一个数值"，所以不存在近似物泄漏**——这正是本不变量说的
"y 对结构敏感"的合法版本：命中判定是精确的集合成员判断，不是粗函数。

⇒ 生成式发现需要一道**为它设计的新母题**，见 `task/.../生成式open母题设计要点.md`。

## 6. 不动的部分

- `case_dr_qed_01` 的 **fixed 三格不受影响**（fixed 从来就给闭候选池，本就满足不变量）。
- 该母题 **open 侧保持闭候选集**（`list_pool` 枚举 33 个）；其判据② 在本题型上**记为不成立
  并说明原因**（候选池小到可枚举 + 任务所需测量数 < 预算 ⇒ 可见性不构成难度），
  不视作缺陷、不重跑。fixed/open 两类分数本就"不可加不可平均、分列两栏"（goal §6 步 6）。
