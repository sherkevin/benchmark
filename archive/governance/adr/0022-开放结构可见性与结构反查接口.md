# ADR-0022 · 开放结构可见性与结构反查接口

- 状态：**已撤销（Superseded by ADR-0024，2026-08-09）**
- 撤销理由：本 ADR 新增的 `resolve_structure`（拿结构串换实体 ID）是为了给“agent 改出新结构后拿不到 ID、无法查性质”搭一座桥。ADR-0024 把工具的 key 直接改成 SMILES（`get_property`/`get_entity` 都收 SMILES），**agent 改完结构得到新 SMILES 直接查即可，这座桥不再需要**。`resolve_structure` 与 `get_entity` 的结构串字段随之作废。下文保留作决策史。
- 决策者：Owner
- 起因：agent 做不了分子层面的外推推理

---

## 1. 问题：链条从源头就断了

Owner 提的场景：agent 查了两个分子的性质（比如 aab 和 abb），想再查一个跟它们结构接近的（aabb），但**拿不到 aabb 对应的实体 ID，所以查不了性质**。

实证下来，断的不止一处。

**第一处断在拓扑不可见。** `get_entity` 只返三样：`formula`（如 `[16*]13[19*]10[22*]4[81*]2`，只有各标签的个数）、`masked_structure`（同一份信息的另一种写法，注释明确写"掩码规则不可逆"）、`atom_count`（原子总数）。agent 知道某分子有 13 个标签16、10 个标签19，**但不知道这些原子怎么连接**，所以构造不出任何合法结构串。

**第二处断在没有反查。** `get_property` 只认实体 ID，`search_candidates` 的 `keywords` 只按 ID 或关键词匹配。即便 agent 手里有结构串，也没有入口把它换成 ID。

**实测佐证链条确实没在用**：既有 61 个 trace 里，`edit_molecule` 与 `check_molecule_exists` 的调用次数为 0（TODO T-75 亦记录过后者）。抽查一道 sotalol 题的 50 条记录，全是 `literature_search` 与 `search_candidates` 反复检索。

后果是 agent 只能在检索给出的候选集里做筛选和排序，**做不到"看到两个结构的性质、推测第三个、造出来查证"**——也就是化学推理里最核心的那一步。

## 2. 裁定

Owner 定两件事，一起做：

**一、`get_entity` 增加返回匿名域结构串**，保留拓扑（哪个原子连哪个、成不成环），元素符号仍为占位标签。

**二、新增一个接口，输入结构串、输出短 ID**，供 agent 拿到 ID 后正常调 `get_property`。

## 3. 为什么不挂在 `normalize_structure` 上

该工具已在做「任意写法 → 唯一标识」，看似天然落点，但它当前声明为 `budget: free`、`source_tier: none`、行为说明写"纯计算不查库"。

反查是查库操作，**必须计费**（理由见 §4 第二条）。免费与计费两种语义无法共存于一个工具，故新增独立接口，不破坏 `normalize_structure` 的纯计算语义。

代价是 MCP 暴露面从 9 个变 10 个，`_assert_tool_surface()` 的断言基准需同步（该函数注释为"校验 MCP 对外暴露面恰为 9 个契约工具，多一个都算破窗"）。

## 4. 三条约束（须落成机器断言）

**第一，只做精确匹配，不做相似度检索。**

Owner 场景里的 aabb 是 agent 自己推理出的确切结构，精确反查即可满足。若支持"给我找像这个的"，等于工具替 agent 完成结构设计这一步，判分就测不出推理能力了。

**第二，计入查证预算。**

不计费则 agent 可无限次反查，把该接口当成免费的库内存在性探测器，穷举结构空间试探哪些实体存在。参照现有口径：`get_property` 有查证预算、`check_molecule_exists` 有尝试次数上限，本接口须并入同一预算池。

**第三，只对可见侧生效，答案侧一律返回"不在"。**

答案侧的存在性只能走 `check_molecule_exists`（只回真假、不给性质、有次数上限）。若反查接口能命中答案侧，答案隔离当场失效。

## 5. 实现基础：数据已就位

网关内已有 `smiles_map`，是「实体 ID → SMILES」的映射，覆盖 74,941 个分子实体。当前 `_a_smiles_universe()` 用它构造集合时只取值、丢弃键：

$$U = \{\,\mathrm{canonical}(\mathrm{smiles\_map}[e]) \;:\; e \in E_{\mathrm{mol}}\,\}$$

其中：

- $E_{\mathrm{mol}}$ —— A 侧全部分子实体的 ID 集合，实测 74,901 条；
- $\mathrm{smiles\_map}[e]$ —— 实体 $e$ 的匿名域 SMILES（dummy atom 载体形态）；
- $\mathrm{canonical}(\cdot)$ —— RDKit 规范化，把同一分子的不同写法归一到唯一形式；
- $U$ —— 规范化结构串的集合，仅用于判定"某结构是否属于 A 侧"。

反查所需的是同一次遍历的逆映射：

$$R = \{\,\mathrm{canonical}(\mathrm{smiles\_map}[e]) \mapsto e \;:\; e \in E_{\mathrm{mol}}\,\}$$

其中 $R$ 是「规范化结构串 → 实体 ID」的字典。**同一份数据、同一次规范化、同样约 3.6 秒的构建耗时，只多存一个字典**，无额外数据依赖。

规范化不可省：注释记录实测有 6 条非规范写法落盘，裸字符串比对会漏。

## 6. 必须承认的代价：泄漏面扩大

给出拓扑等于把可见信息从"各元素有几个"扩到"完整连接方式"。

已实测的相关风险：全库 92,153 个实体的标签频率分布有明显指纹（`[19*]` 占总原子数 43.5%、`[16*]` 占 36.0%、`[22*]` 9.2%、`[81*]` 4.1%），按有机分子常识可直接对应到氢碳氧氮。**元素表被破解后再叠加拓扑，即得到完整结构，反推真实分子的难度显著下降。**

缓解现状：单题白名单视图实测仅 14 到 30 个实体（37 份视图中 24 份为 28 个），且 agent 无法跨题累积样本，故单题内做频率分析的样本量有限。

**这是"能测化学推理"的必要代价**——不给拓扑，agent 永远只能在检索结果里筛选排序。Owner 已确认接受。

## 8. 本 ADR 不裁定的事

**判分不动。** 是否新增"外推准确度"类卡点（比较 agent 推测的性质值与查出的真值）属于判分设计变更，须另行立项。本 ADR 只开通链条。

**既有矩阵结果不受影响**，因为工具增加不改变既有 trace 的判分口径；但新链条启用后跑出的结果与旧结果**不可直接对比**（agent 可用能力变了）。

## 9. 待验证

1. 新链条端到端跑通一道现有题（`edit_molecule` → 反查 → `get_property`），确认 agent 真能用起来。
2. 泄漏面量化：在单题仅 28 个可见实体的条件下，给出拓扑后反推真实分子的难度。此项未做，**不得据此声称泄漏风险可控**。
