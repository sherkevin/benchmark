# ADR 0016 · 专家背书执行方案：每题背书出处 100% + 分层抽审 ≥30%

| 字段 | 值 |
|---|---|
| **状态** | Accepted |
| **日期** | 2026-08-06 |
| **决议人** | 监工（应 E2 请求裁定，报 owner 备案） |
| **领域** | 题目质量门（专家背书的执行口径） |
| **关联** | 把 [[0012]] §2 的原则落成可执行比例 · 约束 E5 造题与 E6 跑测前置检查 |

## 背景：E2 请求裁定是否升格为 ADR

ADR-0012 §2 的三条原则是：query 须基于专业论文/咨询报告、术语与风格与领域专家一致、需要一轮全面调研。**原文没有规定审题比例**。

E2 在规范 §7 提出执行方案「**每题背书出处 100% 记录 + 专家按类型×领域分层抽审 ≥30%**」，并主动报监工裁定是否升格为 ADR（未自行立 ADR，符合并行纪律）。

## 决策：升格为本 ADR

**三条理由**：

1. **这是判据的实质变更，不只是细化**。ADR-0012 的字面要求是每道 query 都要"与领域专家一致"；本方案把"专家逐题把关"改为"背书出处全量 + 抽审 30%"，**放宽了 70% 题目的专家介入**。放宽须留痕。
2. **它是跨线约束**，不是 E2 内部事务：E5 造题时每题必须落 `provenance`；E6 跑测前须校验抽审覆盖率。写在 E2 的规范里，下游没有约束力。
3. **吞吐核算支持这个放宽是必要的**：按 §7.3 每批 ≤20 题，150 题需 **8 批**专家往返；ICLR 摘要约第 6 周，要求单批 lead time ≤ 约 4 天。**全量逐题审在排期内不可行**，抽审是被排期逼出来的合理妥协——正因如此更要显式记录，而不是悄悄降标准。

## 执行口径（写死）

| 项 | 规定 |
|---|---|
| **背书出处** | **100% 覆盖**。每道题的 `provenance` 必须指向一篇真实论文/报告（含标题 + DOI 或 URL），**不得只写数据来源**（如"mock_db.admet"不算背书——现有 37 case 的 `provenance` 全属此类，37/37 不合格） |
| **抽审比例** | **≥30%**，按 **类型 × 领域** 分层抽取（不得集中抽某一格） |
| **抽中题** | 走完整背书三问（术语是否符合实际用法 / 约束是否科学合理 / 交付形态是否合理） |
| **未抽中题** | 以 **背书出处 + `query_lint.py` 脚本断言** 兼核 |
| **升级条件** | 若抽审发现**系统性问题**（例如某子领域术语整体偏离），该层**升为全审** |
| **降级方案** | 若排期不允许，抽审比例可降至 **≥15%**（背书出处 100% 不可降），未审题标注"背书出处已录、抽审未中"进入第二版补审清单 |

## 影响

| 对象 | 动作 |
|---|---|
| **E2** | 规范 §7 引用本 ADR 替代自造表述；`query_lint.py` 增 `provenance` 形态断言（须含论文标题 + DOI/URL，不接受纯数据来源） |
| **E5** | 每道新题必须落合格 `provenance`；现有 37 case 迁移时须补齐（37/37 当前不合格） |
| **E6** | 跑测前置检查加"抽审覆盖率 ≥30%"与"背书出处 100%"两项断言 |
| **owner** | 需人工发出审题邀请（agent 无法执行），这是全链路 lead time 最长一环 |

## 备案

报 owner 备案。**若 owner 要求全量逐题专家审**，则本 ADR 改为 Superseded，同时须相应延长排期或下调题量——两者不可兼得。

## 修订 R1（2026-08-06，owner 决议）：改为 **100% 覆盖 + 分级审**，抽审比例条款作废

**owner 明确表示"我们有足够的专家"**，故原"抽审 ≥30%"的排期妥协不再必要。**§「执行口径」中的抽审比例条款作废**，改为下表。

### 为什么原方案必须改（而不只是提高比例）

监工曾提出"LLM 预审全量 + κ 校准 = 等效全量覆盖"以消除 70% 未审的代价，**该方案经独立审查判定不成立**：

1. **κ 在 150 题规模数学不可行**：要把"LLM 漏检率 ≤5%"压到 95% 置信，需观察约 60 个缺陷样本 ⇒ 需专家标注 **≈300 题 > 全部 150 题**。用 κ 省专家带宽自相矛盾。低患病率还会触发 κ 悖论（一致率 90%+ 而 κ≈0）。
2. **违反已冻结的更严口径**：E2 规范 §2.2 **N9** 原文"本规范在 goal 基础上收紧：**第一版不启用该例外，全部交付要求必须可规则化判分**"。
3. **规则化覆盖不到核心**：9 条人工条目中，能规则化的（N3 泛指、M4 单句、N8 裸答基线、N7 真名断言、N1 口语词表）**都不是专家审的核心**；抽审三问里"术语是否符合专家实际用法"与"约束是否科学合理"**本质不可规则化**（分布性判断，无封闭词表）。

### 修订后的执行口径

| 项 | 规定 |
|---|---|
| **背书出处** | **100% 覆盖**（不变）。须指向真实论文/报告（标题 + DOI 或 URL），**不得只写数据来源** |
| **专家覆盖率** | **100%** —— 全部 150 题均过专家 |
| **组织方式** | **多专家并行**（建议药化 2 位 + 材料 2 位），每人 ≤40 题；8 批串行压缩为 2 轮并行，lead time 约 8–10 天 |
| **分级审** | **一级（全量 100%）**：术语与约束扫读，每题 2–3 分钟；**二级（≥30%）**：背书三问深审（术语实际用法 / 约束科学合理 / 交付形态合理），按类型 × 领域分层抽取 |
| **升级条件** | 一级扫读发现某层系统性问题 ⇒ 该层全部升二级 |
| **κ 校准** | **不启用**（全量覆盖后无需用统计推断补覆盖率） |
| **LLM 的角色** | **仅可作召回器**：全量预审只输出"送审优先级 + 可疑点提示"，**无放行权**，所有题仍进一级队列。若报数据只报"LLM 提示被专家采纳率"作辅助指标并明示非质量门。**LLM 说"没问题"不得成为任何题的放行依据**（否则违 N9 与 goal §5 红线 3） |

### 同时要做的规则化补强（与专家审并行，不互相替代）

把下列 5 条从人工清单移入 `query_lint.py` 断言，让专家注意力从"体检"转向"三问"：

| 条目 | 断言 |
|---|---|
| **N7** | 题面**及 case 元数据**不含 gt 真名 / CAS / InChIKey / 原始库 ID（造题侧已知这些值，可直接断言；现存 `case_id` 带真名正是此项漏检） |
| **N1** | 口语替代词黑名单（"能进入大脑" → BBB permeability 等） |
| **N3** | D 段泛指短语黑名单（"输出你认为最优的" / "the best answer you think"） |
| **M4** | 末句句末标点计数（单句收尾，纯文法） |
| **N8** | 裸答基线 k=10（§6.2 B3/B4 已是可执行断言，本不该占专家带宽） |

### 滚动学习的边界（防止与 M9 冲突）

每批专家反馈可模式化成新 lint 规则，但：

- **只许是禁止式（黑名单），不许是必须式（白名单句式）**——否则压缩表达空间，与 M9 的"变体率 ≥0.3"反向；
- M9 的变体率校验从库级挪到**每批冻结时**执行，任一批变体率下降即冻结该类新规则。

**注意规范内部已有一处未爆矛盾**：§5.4 要求类型1"沿用已落盘句式、只填 slots 不改骨架"，而 M9 要求变体率 ≥0.3。60 道 type1 若全以 `Identify a/an …` 开头，变体率 ≈ 2/60 = 0.033 ≪ 0.3，**必然违 M9**。当前只有 2 个 case 掩盖了该矛盾（ratio=1.0）。此项归 E2 在造题放量前解决。
