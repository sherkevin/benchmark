# ADR 0002 · benchmark 构造路线:从"找现成 trace"转向"造 trace"

- **状态**:Active
- **日期**:2026-06-12
- **领域**:benchmark 数据集构造方法学
- **关联**:`longhorizon/定义_长程任务与桩点.md`(模具)· `construction_methodology.md`(Phase 2 逐题构造)· memory `benchmark-target-nobelclaw-longhorizon` · [[0001]]

## 背景

业务定调(2026-06-12 已确认,前置共识):benchmark **唯一目标 = 评测 NobelClaw 平台跑长程任务的能力**;NobelClaw 为材料 + 医学长程任务而设计 → **30 题必须全是长程任务格式**。

此前调研(task6 ~30 张 benchmark 卡 + POC1–4)隐含一个假设:**去找一条现成的、能直接用或稍加改造就能用的 trace**。事实是:**没有这种高价值数据集存在**。owner 把这件事定性为:

> "我们寄希望于找到完全可用的 trace 或者稍加改造就能用,但是我们并没有找到如此高价值的数据集。**这不是错误,是没调研、想当然的偏见。** 第一,我们没确定具体构造 trace 的方法;第二,我们寄希望于找现成的。认清事实之后,路线反而明确了。"

## 决策

**放弃"找 trace",改为"造 trace"。** 构造按 owner 给的 **5 步法**:

1. **定类别(抽象层)**:判定一共有几类不同形状的长程任务,**每类手工构造一条 case 做示例**。类别越多越好,给后面留容错。**好示例 = 整个工程的地基。**
2. **抽象 → 实例**:每个类别是无数条真实 trace 的抽象;落到真实数据上会展开成很多条(抽象定义与具体实例的关系)。
3. **汇总全局 ckpt 清单**:从所有类别示例里,汇总出一张"我们到底要哪些 ckpt"的表单。
4. **填 GT**:按 ckpt 清单,针对每类 ckpt 去找真值来源,把表单**填满真实 GT**。
5. **组合出量**:一条 trace 有 x 个 ckpt,每个 ckpt 有各自可选集 → 组合出可用 trace;不够就扩 ckpt 集合。(放大模型经审查须修正,见后果 ⚠️。)

## 理由

- 既然现成 trace 不存在,唯一可行路线就是自己构造;构造必须有方法,5 步法给了方法。
- 先定类别 + 示例(地基),再汇总 ckpt、再填 GT —— 顺序保证"每个 ckpt 都有真值兜底",契合 `goal.md` 红线"无 GT 不硬判"。
- **故意多设计类别**:ckpt 数据调研尚未开展,无法预知哪类填得满真值,**多备类别 = 容错**,死掉几类不至于崩盘。

## 后果

- ✅ 路线从"碰运气找数据"变成"工程化造数据",可执行、可分工。
- ✅ 类别 + 示例先行,后续 30 题有统一模具(`longhorizon/定义_长程任务与桩点.md` + case1/2/3)。
- ⚠️ **Step 5 的 ∏mᵢ 组合公式经红队审查不成立**:长程 ckpt 强依赖,定上游即锁下游,下游 GT 只对"真实跑过的那条上游"存在 → 真实规模 ≈ **Σ(独立真锚)× L0–L3 × 反事实变体 × 重复跑**,不是连乘。待 owner 确认后写 ADR-0003 修正。
- ⚠️ **GT 调研须前置成"建题前的闸门"**:case2/case3 已暴露 GT 欠锚(Tier1 仅 60%/56%,3+ ckpt ⬜待锚),只有 case1(压一篇把全过程实验表都发出来的 Nature 论文)满锚。每个候选类别先做 GT 可得性 spike,填不到 ≥70% ckpt 真值 → 改判 process-only 或不立题。
- 🔴 **前置 blocker(方法之外):NobelClaw 预测后端多为 mock/坏**(据 2026-06-04 侦察:仅 `literature_search` 真可用,`generate_drug_report` 对任意输入字节相同,`crystal_*`/`predict_admet` mock 或连不上)。后端不真算 → 现在建题测的是 **LLM 记忆 + agent 编排,而非科学**。**建题前必须:① 探活后端逐工具分类;② 书面明确测的是"科学正确性"还是"编排诚实度"。**
