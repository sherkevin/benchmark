2. 说清一下"一组 case"是什么，因为我之前理解错过一次。

一组不是一道题。是一道母题配六种配置跑六遍。两个变量：候选集给不给（给的叫 fixed，不给、让 agent 自己去查的叫 open），工具给多少（只给最基本的、给一部分便捷工具、给全套便捷工具）。2 乘 3 就是六格。

这么设计是为了做归因。同一道题、同一份真值、同一个判分器，只换配置，那六格之间的分数差就能干净地算到"工具供给"这个变量头上，不会跟别的因素混在一起。

现在药物侧有 3 道母题，材料侧 8 道。真正跑完六格并且封存的只有第一组，是药物侧的 case_dr_qed_01。第二组 edit_01 卡住了，试跑 3 个 run 全是满分，题太简单，等裁定怎么改。第三道 qedgen_01 是让 agent 自己生成分子的，防背测试过了（不给工具的时候一个也答不对），但给了工具 agent 也 3 个全没命中，难度还没调好。材料侧那 8 道是前几周探索留下的，多数已经退役。

3. 第一组这道题具体是怎么攒出来的。这段写细一点，后面几道题都要照这个路子。

池子里放 33 个分子。每个分子给它的编号、SMILES（分子结构的一种文本写法）和五个描述符：分子量、脂水分配系数、极性表面积、可旋转键数、芳环数。这五个都是不用做实验、拿结构直接算就有的数。唯独不给 QED。

QED 是个 0 到 1 的打分，衡量一个分子"像不像药"。选它当考察目标有个好处：它是用 rdkit 这个化学库算出来的，同一个分子每次算的结果分毫不差，所以真值本身没有噪声，不用担心判分的时候被测量误差干扰。

真正花心思的是往池子里埋规律。做法是把分子按同系列分组，一个系列里骨架完全相同，只有 N-烷基那条链的长度 n 在变。同一个系列里，QED 会随着 n 增大先升后降：链太短的时候分子修饰不充分，评分上不去；链太长了又会被分子量、脂水分配、可旋转键数这几项一起拖累。所以每个系列都是一条先升后降的曲线。

关键在于峰出现在哪、降得多快，取决于骨架是什么，每个系列各有一条自己的曲线。比如那个多羟基系列全程又平又低，联苯系列起点最高但掉得最快。这么一来，要拿到某个分子的 QED，就只能去拟合它自己所在那条系列的趋势，拿别的骨架的数值往上套会差很远。

目标分子挑的是 m05，属于甲氧基苯甲酰胺系列，链长 n=11，真值 QED 是 0.5545。它没被合成过，所以调用测量工具的时候会返回"没有这个样品"，而且不扣预算。它同系列里能测的有 5 个（m15、m17、m22、m24、m28），agent 得把这几个测出来、看出曲线形状、再外推到 n=11 那个点。

第二件事是挑一个先导化合物，要同时满足三条：QED 不低于 0.6、极性表面积不低于 40、不能跟 m05 属于同一个系列。33 个分子里同时过这三条的只有 m02 一个。我特意把它做成唯一解，这样判分就没有蒙对的空间。如果合格答案有好几个，agent 随便报一个都可能对，那这一关就废了。QED 那条还额外要求工具调用记录里必须有真实的测量记录，防止它拿描述符估一个数直接填上。

预算给 12 次测量，池子是 33 个，明显测不完，agent 得自己判断先测哪些。

4. 六格是怎么从这一道题变出来的。

关键改动是题面只写一份。原来六个 runner 各自抄了一份题面构造函数，靠人眼保证六份一致，结果出事了：open 那三格被加了"枚举补偿"预算，给 17 次，而 fixed 是 12 次。加的理由听着还挺合理，说 open 侧还得翻页读目录、多给点补偿。但这样一来两侧就不是同一道题了，六格之间的分数差再也没法归到"候选集给没给"这一个变量上。实测的后果是 fixed 该比 open 容易那条完全测不出来，三档差值分别是 −0.014、+0.037、+0.007，等于全平。

改成题面收敛到一个生成器文件，只开两个参数：候选目录给不给、追加哪些便捷工具的说明。别的一切都由这个文件产出，调用方改不了。预算取自真值文件里的那个字段，而六格的真值又由同一个脚本写入并且断言逐字节一致，所以预算再也漂不了。

工具的三个档位是这么搭的。fixed 侧基本档只给一个测量工具；部分便捷档 3 个；全便捷档 4 个。open 侧因为不给候选目录，多一个翻页读目录的工具（每页 4 条，翻一页扣 1 次预算），所以对应是 2、4、5 个。加进去的便捷工具是骨架分组（省掉自己判断哪些分子同系列）、趋势拟合（省掉自己算曲线）、QED 分量拆解。

题面里刻意不给任何解题指引。不提示 QED 和链长的关系是线性还是非线性、不给步骤、不点明这是道外推题。这些都属于"怎么解"，写进题面等于把一半答案送出去。

先看最基本的：工具给得越多分越高，fixed 和 open 两侧都是这个走势，说明工具档位这个设计确实在起作用。

再看 fixed 是不是真比 open 容易。三档的差分别是 +0.212、+0.398、+0.354，都是正的。检验方式用的是置换检验，把两组数据的标签随机打乱几千次，看看"随机打乱也能出现这么大差距"的概率有多少，最大那个概率是 0.0016，也就是千分之一点六，这个差距不太可能是碰巧。因为一次做了三个比较，还做了多重比较校正（同时比多次的时候，碰巧出现显著结果的机会会变大，得把标准提严），校正之后仍然显著。换一批重跑第二遍，三档的差是 +0.163、+0.441、+0.398，方向和量级都对得上。

回头看第 4 条那个 17 次预算的事，其实这是个挺有意思的反证。同一道题、同一个判分器，只把 open 的预算从 17 改回 12，三档就从"全平"变成"全显著"。也就是说当初那个"补偿"正是把信号毁掉的东西。

第三个结果是我觉得这周最有用的一条：能区分模型的只有 open 侧。open 三档的差是 +0.169、+0.650、+0.508，都显著；fixed 三档的 p 值在 0.48 到 0.98 之间，六个模型的分数基本挤在一起，谁强谁弱看不出来。这意味着后面要拉开模型差距，只能靠 open 配置，fixed 侧现在这些模型都做得差不多。

还有两条判据没这么顺。"发现得多的分数应该更高"这条没能检验成立。我一度报成"方向反了"，后来撤回了。真实情况是唯一一档数据干净的样本太少，另外两档因为有便捷工具帮着分组，"发现"这个动作被搅乱了，压根构不成对照。这不是多跑几个 run 能解决的，得专门设一个对照组。"答案不可背"这条成立：空着工具调用记录交卷得 0 分，完全不给工具得 0 分，直接抄最近邻的分子得 0.048。

两批都复现之后把参数冻结了。预算、每页几条、题面生成器、真值、判分器、失败分类的口径全部锁死，25 个文件算 sha256（一种文件指纹，内容改一个字节指纹就变）存成清单，开批前的检查脚本加了一道闸门逐个核对，改一个字节就拒绝开跑。

另外量到一个反直觉的现象：给了便捷工具之后，模型反而少翻页了。把目录翻满 9 页的比例，基本档是 86%，部分便捷掉到 44%，全便捷只有 33%；同时测量次数的中位数从 3 次升到 6 次。原因是骨架分组那个工具省掉了穷举目录的必要，省下来的预算转手花在测量上了。

7. 后半周查出方向上有问题，这条影响后面所有题怎么造。

一句话说：预测一个分子的性质，本身就是做一次实验、调一次工具拿一个结果。测这个只是在测工具调用能力，不是我们想测的。我们要测的是长程任务。给一个高层目标，agent 自己想清楚该做哪些实验、按什么顺序做、结果怎么解读、怎么一步步逼近目标。

按这条标准回头看，药物侧折腾的几个版本都错在同一处：交上来的答案是一个性质值。第一组的第一件事报目标分子的 QED 就是这样，后来换成 logS 报溶解度数值也是，Job2 那部分改了三版还是。反过来材料侧的 constraint_02 和 satisfy_02 是对的，它们问的是"在这些约束下把那个材料找出来"，答案是"找到了什么"，agent 必须把一串实验组织起来才能得到。这周把这两道提成了正面样板。

药物侧下一道题据此改向，做成目标级的先导筛选，照材料侧的骨架搬过来：答案是报出满足溶解度窗口加结构约束的完整化合物集合，真最优那个挖掉逼它外推，性质查询降级成过程中调的工具。数据这边的可行性已经实跑验过，logS 这套系列跨溶解度窗口能选出特定链长（醇是 n=8、酯 n=6、脂肪酸 n=7 或 8），logS 和血脑屏障穿透两个性质都有实测值的分子有 254 个，够支持两条实测约束。
