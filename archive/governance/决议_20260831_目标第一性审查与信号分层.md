## §0 owner 原话（2026-08-31）

> 我们本质上是要构造一个 benchmark，这个 benchmark 的领域是制药，测试的主体是 agent，
> 那么就是要测试 agent 在制药相关领域上的任务完成情况，同时我们还想把这个 benchmark
> 做成是 RSI 自进化的，也就是测出来之后通过一些训练手段把我们的 agent 在这个 benchmark
> 上产生的 loss 消掉，让他在这个 benchmark 表现的效果更好。
>
> 那么这里就有几个基本事实：
> 1. agent 的能力维度包括**推理、记忆和工具调用**三个维度，我们要测试的能力必然包含在这三个维度的框架下；
> 2. **制药 topic 是题眼**，我们设计的问题必须是针对于制药来的，所完成的任务必须对制药这个 topic 有帮助；
> 3. 需要有一个**可以细粒度判分的规范**来衡量 agent 完成任务的效果从而当做 agent 的能力指标；
> 4. 我们的题目的**得分应该是不能太好的**，留给 RSI 一定的空间；
> 5. 我们的 **RSI 所需要的信号是要在本 benchmark 上跑 agent 测试之后就可以提供的**。
>
> 所以归纳下来我们现在的做法是：
>
> 1. basic、some、enough 三层 × open/fixed 来做难度区分，给 agent 留出 RSI 的空间并考察
>    agent 在相同题目的不同外部环境下的表现差异，从而衡量其记忆（背题）、推理、调工具的能力。
> 2. **做长任务而不是短任务**，短任务因为已经有很多人在做，本身的价值在迅速衰减，而且对于
>    agent 测试来说我们也更关注他的长任务的能力。那么定了这个决定之后就连带出现了一些问题：
>    首先是如何衡量这个任务的长短，其次是如何对长任务打分。现在先说任务长短的衡量——衡量长短
>    这件事是和题目难度直接关联的，我的想法是**如果一个问题可以被拆分为两个问题，那么他的难度
>    就是 2，如果子问题还可以继续拆分为两个问题，难度就是 4，也就是其难度的衡量值就是原子问题
>    的数目**。那么问题变为了如何定义一个原子问题，我认为一个原子问题首先是**不能再分**的，
>    其次是**最多包含一步 tools 调用**的，最重要的是**没有任何任务依赖前置，所有信息都在 query
>    里给出**。这里是需要拍一个难度值出来的，**这个是我们的第一个超参数**。
> 3. 关于结果的打分逻辑，这是重中之重，是问题能否立住的根本。从第一性原理出发是因为我们需要
>    一个信号来衡量 agent 做任务的好坏，所以需要一个具体的数值来做评判，那么这个数值必须是
>    **可信**的，所谓可信就必须：**可重复性**（运行多次结果一致，那么首先排除 llm-judge）、
>    **可比较性**（使用同一套量纲，并且同题目中如果有细粒度的指标衡量的话，也要是同量纲的，
>    **这是第二个超参**）。同时一个好的信号我们期望其具有以下性质：**稠密**（希望其不只是给出
>    一个最终的得分，也有辅助得分来衡量其方案的质量而不是只衡量结果——举个例子如果两个 agent
>    都完成了一件事，但是方案不同，有优有劣，那么自然有区分；所谓辅助得分可以是过程分来衡量
>    关键步骤，可以是 token 消耗，总之是衡量方案效果的一个信号）、**连续**（一个连续的可比分数
>    要比离散的分数更平滑，携带更多的可比较信息，粒度会更细）。那么如何实现上述目标就要求我们：
>    **agent 的结果要是结构化的**（非结构的话难以用 hard-code 来做 verify）、**辅助信号必须明确**、
>    **量纲必须统一**——这要求我们定义一套不偏的分数归一化标准，但是该标准肯定是取决于我们的
>    辅助信号的定义的。
> 4. 这里有一个需要着重讨论的问题：辅助信号中的**中间过程量信号**是一个很特殊的信号，他在衡量
>    trace 的正确性，也就是方案本身的正确性，但是我们没有很好的方案来说明哪些方案是好的、哪些是
>    坏的，这个信号的产生是一个困难，所以只能采取退而求其次的方案，比如人为定义方案、直接写在
>    提示词里让其去做——但是这其实考察的是 agent 的指令遵循能力而不是自己执行方案的能力，与
>    原始目的有很大差距。目前的一些主流方案对此也有争议：所谓方案本身的衡量价值是否是必要的和
>    重要的？如果其可以完成任务那么是否证明其方案本身就是优秀的，而完成任务的手段可以做忽略？
>    我认为是有道理的。但是这里有一个前提，就是我们希望考察的 agent 的能力是**无偏**的，也就是说
>    agent 不能通过作弊来得到最终答案，那么剩下的方案都是其探索出来的有效方案，本质上都可以
>    解决问题，那么其实**只需要衡量 token 消耗这个指标就可以判别方案的优劣**，因为其衡量的 agent
>    的能力是基本一致的。那么这样就要求我们定义一套防作弊的机制——这里又牵涉出来了一个新问题：
>    **什么是作弊？作弊指的是调用本身可以直接获得答案的工具来绕过多轮推理，这是我认为的作弊，
>    也是唯一类型的作弊。我认为猜出来、也就是所谓的凭借记忆预训练进去的知识来直接写答案并不能
>    算是作弊，因为记忆本质上也是 agent 的能力的一部分**，所以我们只需要保证 agent 无法通过
>    工具调用直接获取答案，这在测试中是可以实现的。
> 5. 关于 rsi 这件事其实是两个解决思路，首先是常见的 GRPO 类思路，其本质取决于原 agent 的能力，
>    是在原本的探索空间里做偏移，还是没逃出原本的能力空间，只是往 good trace 上做了偏移，但是能力上线是定死的，包括 prompt-fine-tune 本质上也是一样的，另一种解决思路是提升能力上线的思路，直接找到标准的满分答案做 gt，这个标准答案是原来的 agent 达不到的，这就要求我们去做标准答案的构建，但是这显然是很困难的，所以更一般的做法仍需要讨论，但是首先排除的方案是用 teacher，因为我们是 rsi，只能是自己做错之后总结经验来迭代，如果我们设计一套标准可以自动定义某个问题的最优解法或者找到当前 trace 的非最优部分，那么这其实是开创了一个全新的领域出来，是非 GRPO 类的真正可以自主提升模型能力上线的方案，并且全程不需要 llm-judge 而可以自动构建 train dataset，甚至可以写一套适配于该方案的新的训练方式出来，这是很令人兴奋的工作

## §1 决议一：目标拆解按上述五条基本事实执行

五条原样生效，不作改动。以下只补每条的**可操作口径**，即"怎么算满足了这一条"。

| # | 基本事实 | 可操作口径（本决议补充） |
|---|---|---|
| 1 | 能力三维度：推理 / 记忆 / 工具调用 | 每道题**必须显式声明主测维度与另两维度的贡献**，见 §3.1 |
| 2 | 制药是题眼，任务须对制药有帮助 | 题目的产物必须是制药流程里真实存在的中间产物或结论；判据见 §4 清单第 2 项 |
| 3 | 需可细粒度判分 | 细粒度的最低要求是**每个子问题独立可判**，且逐子问题分数须落盘（不只落总分），见 §3.2、§3.4 |
| 4 | 得分不能太好，留 RSI 空间 | 这是**上限**约束，与 08-30 裁定的"不设下限（不设判死线）"并存、不冲突，见 §1.1 |
| 5 | RSI 信号跑完即可提供 | **分两条路线看**，两条对信号的要求不同，见 §3.6；共同底线是判分产物必须同时满足判分与训练两种消费方式（§3.4） |

### 1.1 "得分不能太好"是上限，与"不设判死线"（08-30）并存

两条容易被读成互相矛盾，此处明确：

- **不设下限**（08-30 裁定）：不因为区分度不够、判别力不足而判死一道题；如实报分即可。
- **设上限**（本决议）：若一道题上所有 agent 都接近满分，则该题**没有 RSI 空间**——不是它不合格，
  而是它对"消 loss"这个目的没有可用信号。

⇒ 处置差异：判别力不足的题**留档报分**；接近满分的题**不能作为 RSI 的训练目标**，但仍可作为
能力上限的参照。二者都不触发"废题"。

## §3 本次审查的六条修正（3.1–3.5 为审查所得，3.6 对应 owner 08-31 新补的第 5 条）

### 3.1 记忆的地位改变：从"作弊"改为"合法能力维度"，连带推翻一条已生效判决

**owner 新口径**：唯一的作弊是"调用本身可以直接获得答案的工具来绕过多轮推理"。
凭训练记忆直接写答案**不算作弊**，因为记忆是 agent 能力的一部分。

#### 3.1.1 与现状的冲突（两处，都必须处置）

**冲突一：`case_sc_explore_01` 的判死理由失效。**

该题 08-19 被判死，原始理由是"**分数是化学记忆挣的，不是探索能力挣的**"。
实测依据是等价匿名变换（元素符号换代号、临界温度数值一个不改）后重跑：
两个模型归零、最强模型 0.9 → 0.658。

按新口径，"靠记忆得分"本身不构成判死理由。⇒ **原判死理由作废。**

**但该题仍不合格**，理由须改写为：

> 这道题的三个能力维度配比失衡——**记忆维度独占，推理与工具调用两个维度被短路**。
> 匿名变换的实测正是这一点的直接证据：把记忆通路掐断后，剩余两维度贡献接近 0
> （两个模型归零）。若我们的设计意图是测推理与工具，它测不到；若意图是测记忆，
> 它是合格的纯记忆题。

⇒ 处置：**从"判死"改为"归类为纯记忆题"**，进 §4 清单第 1 项的对照样例。
不复活为主力题（我们要测的是另外两维度），但其匿名变换实测数据**成为衡量"记忆维度占比"的方法学样板**——
这是目前唯一一个能定量拆出记忆贡献的手段。

**冲突二：`goal.md` 红线 5 的表述与新口径直接矛盾。**

红线 5 现行原文：

> 入题必经的防污染门：答案不写在题面、必须靠多步推理 + 工具探索才能到达，性质与真实世界
> 保持一致，**否则 agent 可靠训练记忆直接蒙对**。

这句把"可靠记忆蒙对"当作不合格判据，与"记忆是合法能力"冲突。

⇒ **修正后的表述**（本决议给出，待落进 `goal.md`）：

> 若一道题的设计意图是测**推理**或**工具调用**维度，则其答案不得可由训练记忆直达——
> 否则该题实际测到的是记忆维度，与设计意图不符。
> 判据是**记忆维度占比**（用等价匿名变换的分数落差定量，见 3.1.1），而非"是否用到记忆"。

同一处的"时间差声明"（`benchmark 不对外声称抗记忆污染`）也须同步改写：
不再声称"抗记忆污染"，改为声称"**每道题的记忆维度占比可定量披露**"。这是更强也更诚实的说法。

#### 3.1.2 由此产生的一条正面要求

三维度既然都合法，那么每道题**必须显式声明它测什么**，不能笼统说"测科学推理能力"。
声明格式（进题目定义文件）：

| 字段 | 含义 | 怎么验 |
|---|---|---|
| 主测维度 | 推理 / 记忆 / 工具调用，三选一 | 设计时声明 |
| 记忆维度占比 | 掐断记忆通路后分数落差 | 等价匿名变换实测 |
| 工具维度占比 | 不给工具时分数落差 | 裸答基线实测（已有机制） |
| 推理维度占比 | 余量 | 由上两项推出 |

**注**：材料侧已明确不做匿名变换（owner 前定：一匿名就变成数学题）。
制药侧是否可做等价变换（如骨架保持、取代基换位），须实测确认是否破坏化学语义——列入 §5 待裁。

### 3.2 难度不能只在设计时数，必须配事后校验

**owner 定义**：难度 = 原子问题数目。原子问题 = ①不可再分 ②最多一步工具调用
③无任务依赖前置、所有信息在 query 里给出。这是第一个超参数。

**这个定义本身清楚可用，本决议不改。** 但它有一个已被实测暴露的漏洞：

#### 3.2.1 冲突证据：名义难度 ≠ 实际难度

`case_dr_cns_01` 名义上有四条要求（形式上是 4 个子问题）。逐轴拆开实测
（依据 TODO T-269，只算结构合法的答卷：有工具 13 条、无工具 9 条）：

| 子问题 | 计算属性 | 有工具组通过率 | 无工具组通过率 |
|---|---|---|---|
| 分子量 ≤ 360 | 纯算术 | 13/13 = **100%** | 9/9 = **100%** |
| 氢键给体 = 0 | 计数 | 77% | **89%**（反而更高） |
| 极性表面积 40–90 | 片段加和，纸上可算 | 77% | 67% |
| **油性 ≤ 3** | **需 Crippen 加和模型，脑内算不出** | **2/13 = 15%** | **0/9 = 0%** |

⇒ **名义难度 4，实际只有 1 个子问题在筛人**。另三条不是"简单子问题"，而是**根本不构成子问题**——
它们对任何受测 agent 都是白给。四轴总过关条数均值 2.69 vs 2.56，两组差距小的真因不是
"工具没信息"，而是**两组都倒在同一条轴上**。

#### 3.2.2 修正：难度是"声明值 + 实测值"两个量，不是一个

| 量 | 何时产生 | 用途 |
|---|---|---|
| **声明难度** | 设计时数原子问题个数 | 组织题库、排难度梯度。这是 owner 说的那个超参数 |
| **实测难度** | 跑完后统计"有几个子问题的通过率真正落在中间区间" | 判断这道题是否名副其实 |

**硬要求**：任何题在正式开跑前，必须落盘一张**逐子问题通过率表**（格式同 3.2.1）。
两个量不一致时，以实测值为准，并在题目定义里记下差异原因。

**为什么这条必须落成硬要求**：3.2.1 那张表是花完机时之后才拆出来的。
在那之前我们只看总分，看到的是"两组差 0.06、分不开"，得出的解释是错的
（曾报成"AI 闭着眼也能造出一样好的分子"，见 TODO T-268 → T-269 的更正）。
**逐子问题拆开是零成本的**（离线重判即可），却决定了对整道题的判断是否成立。

### 3.3 token 消耗作为方案质量信号，需两个前置门槛

**owner 推论**：若 agent 无法作弊，则剩下的方案都是有效方案，只需衡量 token 消耗即可判方案优劣。

**这个推论的前提是"两个 agent 都完成了这件事"（owner 原话）。** 本决议接受该推论，
但必须补上前提的守卫——因为在已落盘数据里，**该前提大面积不成立**。

#### 3.3.1 冲突证据一：绝大多数答卷并未完成任务，此时低消耗不是"方案好"

`case_dr_cns_01` 无工具臂 12 条答卷（TODO T-269 原始留痕）：

- **11 条自报"四条全过"，实算无一条到 4 条**；
- 其中 **2 条交上来的分子 RDKit 根本读不出来**（价键非法），仍自报满分；
- 9 条结构合法的答卷，油性实测值全部落在 3.26–3.85（限值 ≤3.0）——方向都对、都差一点、都以为过了。

这类答卷的 token 消耗可能很低（猜一个即交），**低消耗在此处等于"放弃得早"，不等于"方案高效"**。

#### 3.3.2 冲突证据二：token 的内部结构会随配置变化，总量不可跨配置比较

第四周六格实测（阶段 4）：给了便捷工具之后，模型**反而少翻页**——
把候选目录翻满 9 页的比例：基本档 86% → 部分便捷 44% → 全便捷 33%；
同时测量次数中位数从 3 升到 6。

⇒ 省下的"翻页 token"转成了"测量 token"，两者单价与信息量都不同。
**只比 token 总量会把这种结构性转移误读成效率差异。**

#### 3.3.3 修正：token 消耗只在满足两个条件时可用作方案质量信号

1. **仅在"任务完成"的子集内比较**。完成的判据须是判分器可机械判定的（不是自报）。
   未完成的答卷不参与 token 比较——它们的低消耗没有方案含义。
2. **必须拆分口径落盘**，至少分成"探索/检索类调用"与"测量/计算类调用"两类计数，
   不允许只报总量。跨配置比较时只比同类。

### 3.4 判分信号与 RSI 信号必须分层，不是同一个量

这是本次审查提出的**新的结构性区分**，owner 原文中未显式区分，但两处需求对信号的要求不同。

#### 3.4.1 两种需求的要求不一样

| | 判分需求 | RSI 需求 |
|---|---|---|
| 要回答的问题 | 谁强谁弱 | **哪一步错了、该怎么改** |
| 最低够用的信号 | 一个可排序的总分 | 能**定位到具体步骤**的误差 |
| 对连续性的要求 | 越连续越好（区分度） | 连续性有帮助但非必需 |
| 对可重复性的要求 | 必须（排除 LLM judge） | 必须 |

#### 3.4.2 由此得出：token 消耗能满足判分，不能满足 RSI

token 消耗**可以排序**（谁省谁费），但**完全不能定位**——
无法从"token 用多了"推出"该改哪一步"。

⇒ 所以 owner §4 那个结论（不用过程量、只看 token 就够）**对判分成立，对 RSI 不成立**。

#### 3.4.3 这解释了 owner §4 那个纠结为什么难解

owner 在"过程量能不能公正判分"这个问题上纠结，两条路都有硬伤：
自己定义方案写进提示词 ⇒ 变成测指令遵循；不定义 ⇒ 无法说哪个方案好。

**本决议的解法是把这个问题移出判分**：

> 过程量**不进总分**，只作为 RSI 的训练信号单独落盘。
> 判分侧只用"产物是否达成 + token 消耗（受 3.3 两个门槛约束）"。

这样两条硬伤同时消失：判分不需要评判方案好坏（所以不必人为定义方案），
而 RSI 需要的定位信息仍然拿得到（逐子问题分数 + 逐步骤操作记录）。

**注**：这与既有做法是一致的、不是新增负担——已有机制里判别性检查关就是
"只记录、不进总分"（`NOT_IN_MEAN` 声明），本决议把它从个例上升为规格。

#### 3.4.4 落地要求

| 落盘物 | 服务对象 | 内容 |
|---|---|---|
| 总分 + 逐子问题分数 | 判分 + RSI | 逐子问题必须独立落盘，不只落总分 |
| 逐步骤操作记录 | 仅 RSI | 已有（工具调用账本），不进判分 |
| token 分类计数 | 判分（受 3.3 约束） | 至少分探索类 / 测量类两类 |

### 3.5 量纲统一是必要条件，不是充分条件

**owner 定义**：可比较性要求同一套量纲，同题目内细粒度指标也要同量纲，这是第二个超参。

**这条成立且必须做。** 但本决议要标出它的作用边界，因为已有实测显示它救不了信号本身的缺陷。

#### 3.5.1 冲突证据：三把尺子实测，换归一化方式无效

同一批答卷离线重判（TODO T-268，零机时）：

| 判分方式 | 两臂差 | 精确检验 p | 效应量 d | 需每臂 run 数 |
|---|---|---|---|---|
| 现行 (过关条数−2)/2 | +0.056 | 0.859 | 0.185 | 462 |
| 改成原始计数 n/4 | +0.028 | 0.859 | 0.185 | **462（与上行逐位相同）** |
| 改成论文连续合意度（19 个取值） | **−0.034（无工具臂反超）** | 0.601 | 0.121 | **1070（更差）** |

**前两行逐位相同不是巧合，是数学**：两者都是"过关条数"的单调线性变换，
秩不变 ⇒ 秩和检验 p 值相同；均值差与合并标准差同比例缩放 ⇒ 效应量相同。

⇒ **推论：凡是"过关条数"的单调函数，判别力完全一样。** 想改判别力只能去读另一个量。

第三行是更值得注意的一条：**它真的更细了**（刻度从 3 个变 19 个）**但更差**。
说明连续化本身不保证改善——归一化做不对会比离散更糟。

#### 3.5.2 修正：加两条执行顺序上的约束

1. **先确认原始信号在筛人，再谈归一化。** 若各子指标本身没有区分度（如 3.2.1 中三条白给、
   一条全卡），任何归一化与权重配比都造不出区分度。归一化是把已有信号变可比，**不能无中生有**。
2. **权重必须在看到结果之前定，依据只能是题目本身的科学含义。**
   3.2.1 暴露了一个诱惑：既然只有油性那条在筛人，是否该给它更高权重？
   **不可以**——那是先看到结果再回去调权重，调到“看起来能区分”为止。
   那个区分是调出来的，不是量出来的。这属于 `DECISIONS.md §6` 已登记的坑
   （按结果回调参数）。

#### 3.5.3 补：还有一道比归一化更靠前的关——跑间方差（云端 08-31 实测，本决议纳入）

写本决议同日，云端补上了一个挂了 19 天的数：**跑间方差**
（同一模型、同一配置、同一批次，重跑一次分数飘多少）。零机时，从已落盘 run 现算。

| 题 / 配置 | 跑间标准差 |
|---|---|
| `qed_01` 六格 | 0.176 – 0.230 |
| `cns_01` 两条臂 | 0.250 / 0.289 |

拿它去量三档工具阶梯，**四个跳里只有一跳站得住**（判据：档间差 ÷ 跑间标准差）：

| 档间跳 | 差值 | 比例 | 结论 |
|---|---|---|---|
| fixed basic→some | +0.345 | 1.70 | 过 |
| fixed some→enough | +0.037 | 0.18 | 不过 |
| open basic→some | +0.111 | 0.58 | 不过 |

**这条比 3.5.1 那三把尺子更靠前，必须插到归一化之前：**

> 执行顺序固定为三步：
> **第一步** 量跑间方差（这是噪声底）→
> **第二步** 确认各子指标在筛人且差值超过噪声底（3.2.1 + 本节）→
> **第三步** 才谈量纲统一与权重。
> 前两步不过就去调第三步，是把功夫花在噪声上。

同时这条给 §1.1 那条“不设下限”补一个**报告义务**（不是验收线，不违 08-30 裁定）：
凡报一个差值，必须同时报出当前配置的跑间标准差，让读者自己判断那个差值是不是在噪声里。
本决议 §3.2.1 与 §3.5.1 引用的所有差值（+0.056 / +0.028 / −0.034 等）
**均小于 0.25 的跑间标准差**，因此那几个数只能读作“没量到差异”，
**不能读作“两把尺子实际上一样”**——后者靠的是“单调变换不改秩”这个数学事实，与噪声无关，那一条仍站得住。

### 3.6 RSI 分两条路线，而路线二对本 benchmark 提出了一条新的落盘义务

本节对应 §0 第 5 条（owner 08-31 补）。

#### 3.6.1 两条路线的分界（owner 定）

| | 路线一：GRPO 类 | 路线二：提升能力上限 |
|---|---|---|
| 做什么 | 在原有探索空间里往 good trace 上做偏移 | 直接找到标准的满分答案当真值，而这个答案是原 agent 达不到的 |
| 能力上限 | **定死的**——没逃出原本的能力空间 | 可以抬高 |
| prompt-fine-tune | 本质上属于这一类 | — |
| 难处 | 相对成熟 | 要构造标准答案，**很困难**，更一般的做法仍需讨论 |

#### 3.6.2 两条硬排除（owner 定，不得绕）

| 被排除的 | 理由 |
|---|---|
| **用 teacher** | 我们做的是 RSI（递归自改进），**只能是自己做错之后总结经验来迭代**。引入更强的外部模型当老师，那不是自改进 |
| **用 llm-judge** | 全程不需 llm-judge（owner 原话）。本决议 §1 基本事实 3 已从**可重复性**角度排除过它，此处是第二个独立理由：训练集要能**自动构建** |

两条合起来造成一个硬问题：

> **既不能问老师、也不能问大模型裁判，那“哪一步不是最优”这件事，靠什么判？**

#### 3.6.3 本 benchmark 手里有五个“自己跟自己比”的切口（以下为执行方推论，待验）

排除外部权威之后，可用的参照只能来自**同一个 agent 在不同条件下的表现**，或者**我们作为出题人掌握的真值**。
现有机制里能直接拿来用的有五个，按“多大程度上不依赖任何外部判断”排序：

| # | 切口 | 参照从哪来 | 能定位到什么 | 现状 |
|---|---|---|---|---|
| 1 | **最优路径长度反算** | **题是我们出的、真值是我们算的** ⇒ “最少几步能到”在造题时就知道 | 超出最少步数的那些调用全是冗余 | **未落盘**，本决议新增义务（3.6.5） |
| 2 | 逐子问题分数 | 真值 | 哪一步没过 | 本决议 §3.2 已定为硬要求 |
| 3 | 预算冗余 | 同题内比 | 同样达成目标，多花的那几步 | 需 §3.3.3 的分类计数先接通 |
| 4 | 三档工具供给的纵向对比 | 同一 agent 不同配置 | enough 档做得到而 basic 档做不到的那段，就是 basic 档绕的远路 | 两道新题尚未跑三档（见另一份 08-31 决议 §1 第 6 条） |
| 5 | 同题多次答的横向对比 | 同一 agent 重跑 | 高分那次做对了什么、低分那次在哪卡了 | 有数据（已落盘 run），但**受跑间方差 0.18–0.29 限制**，单次差异可能全是噪声（3.5.3） |

#### 3.6.4 切口 1 与“原子问题数目”那个超参直接咬合

owner 定的原子问题有三条：不可再分、**最多一步工具调用**、无任务依赖前置。
由第二条直接得到：

$$L_{\min} \le N$$

其中：
- $L_{\min}$：完成这道题所需的**最少工具调用次数**（单位：次），由真值与题目结构在造题时确定性算出，不由任何模型产生；
- $N$：该题的**原子问题个数**（声明难度，就是 owner 说的第一个超参数）；
- 不等号取到等号的条件：每个原子问题都真的需要一次工具调用；若某些原子问题能纯推理解决（如 3.2.1 里那三条白给的轴），则 $L_{\min} < N$。

⇒ **原子问题数目不只是难度标签，它同时是最优 trace 长度的上界，也就是路线二的参照基线。**
这把那个超参从“组织题库用的标签”提升为“训练信号的锚”，它定得对不对直接影响 RSI 能不能用。

**已有实例**（`cns_01`）：四条轴里三条 agent 自己能算（算术/计数/纸上加和）、只有油性必须调工具
⇒ $L_{\min} = 1$，而 agent 手里有 **8 次**化验额度。超出 1 次的部分全是可优化空间，
**而这个判定不需要任何外部权威**。

#### 3.6.5 由此新增的落盘义务（零机时，造题时就能算）

每道题在造题阶段必须一并算出并落盘：

| 字段 | 含义 | 用于 |
|---|---|---|
| `L_min` | 最少工具调用次数 | 路线二的参照基线；也是冗余度的分母 |
| `L_min_path` | 那条最短路径具体调了哪几次、每次拿什么 | 定位“哪一步本来可以不做” |
| `L_min_derivation` | 这个数是怎么算出来的（哪几条子问题可纯推理、为何） | 防止事后改这个数去凑结论 |

❗ **禁止事后调 `L_min`。** 它必须在看到任何 run 结果之前定死，理由同 §3.5.2 第 2 条（按结果回调参数属 `DECISIONS.md §6` 已登记的坑）。
若跑完发现 `L_min` 算错了，得当作题目缺陷登记、而不是静默修正。

#### 3.6.6 两条路线对信号的要求不同（这是 §3.4 那条分层的直接后果）

| | 路线一（GRPO 类） | 路线二（抬上限） |
|---|---|---|
| 够用的信号 | 一个可排序的总分（区分 good / bad trace 就行） | **必须能定位到步**：哪一步非最优、应该是什么 |
| 逐子问题分数 | 可选 | **必选** |
| `L_min` 与最短路径 | 不需 | **必需** |
| token 消耗 | 能用（排序用） | 不够——能排序但不能定位（§3.4.2） |

⇒ **若选路线二，本 benchmark 的落盘产物必须比现在多两样：逐子问题分数、`L_min` 与最短路径。**
两样都是零机时的（前者离线重判、后者造题时算），所以**不必等路线选完再做**——
先做了不会白做，而不做则路线二直接无法启动。

#### 3.6.7 owner 对路线二价值的定位（原话要点，不是执行方加的）

若能设计出一套标准，自动定义某个问题的最优解法、或找到当前 trace 的非最优部分，则：

- 开创了一个全新领域，是**非 GRPO 类、真正能自主提升能力上限**的方案；
- 全程不需 llm-judge，可**自动构建训练集**；
- 甚至可以配套写一套适配该方案的新训练方式。

⇒ 本决议把它登记为**项目的高价值候选主线**，但路线选择本身列入 §5 待裁（新增第 6 项）。
