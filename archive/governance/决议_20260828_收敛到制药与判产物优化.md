## §2 决议二："纯 benchmark 不够"——判分口径从"命中答案"转向"产物优化"

owner 说"纯做制药 benchmark 也不太够"。**这句话不只是"再加点东西"，它正好指向本项目
反复撞死的那一处。**

### 2.1 全库每一次判死都是同一个形状

| 题 | 死法 | 实测 |
|---|---|---|
| `layer_01` | 闭眼背书赢过全部真实模型 | 裸答 0.952 vs 真跑 0.602 |
| logS/#12 | 裸答≈做完全部实验 | 裸答 0.680 vs 诚实天花板 0.877 |
| `sarflip_01` | 花 1 次预算 + 免费列做算术 | 免能力天花板 21.89%（判死线 5%） |
| Job 2 第二/三版 | 一律猜某个链长就够 | 猜 n=6 → 0.934 |
| `qed_01` 的两关 | 一半权重压在同一个二值协议门上 | 54/54 run 完全共线 |

**共同形状：题有一个固定答案，而某条便宜的路也到得了那个答案。**
于是我们只能不停地把答案藏得更深（挖洞、抹除、隐藏规律），而**藏答案这件事没有下限**——
这正是 08-19 以来打转的机械原因。

### 2.2 换口径：**不判"你交的是不是那一个"，判"你交的比给你的起点好多少"**

把判据从 `命中(答案)` 换成 `我们的 oracle 打出的分(你的产物) − 同一 oracle 打出的分(题面给定的起点)`。

**这一换直接消掉上面那一列死法**：
- **背不出来**：没有固定答案可背。要拿分必须交一个**真的更好**的分子。
- **裸答基线依然要跑，而且这次它量的是有意义的东西**：不做任何实验能改进多少。
- **判据零超参、离散可验证**：分差是我们自己的 oracle 算出来的一个数，不是我拍的常数。

**这不是提案，底层能力今天就在**（本轮实测）：拿一个库里不存在的新分子
`CCCCCCCCCCCOc1ccc(C=O)cc1CN2CCOCC2`（已逐行核对不在 74,901 个 A 侧实体里），
RDKit 离线算出 QED **0.3291**、MW 375.6，确定性、可复跑、零 API。
⇒ **judge 侧对任意新产物打分的 oracle 是现成的。**

### 2.3 这与 ADR-0027「不配通用 oracle」冲不冲突？——不冲突，但必须说清

ADR-0027 定的是"**预测型题不配通用 oracle、可测集须闭合**"，本轮实测确认它被严格执行：
- `predict_admet` 是**查表**，库外一律 `NOT_IN_DATABASE`，且**已从 MCP 工具表摘下**
  （`mock_server.py:385` 注释"不进 list_tools、不下发给 agent"）；
- `measure_qed` 有可测集白名单，新设计的分子一律 `probe_unavailable`。

**ADR-0027 约束的是 agent 能测什么，本决议用的是 agent 调不到的 judge 侧 oracle。**
两件事。⇒ **不改 ADR-0027，也不给 agent 加通用 oracle。**

### 2.4 三条必须先过的关（不过就不建，一条都不许放）

写在这里是为了**不重犯坑①**（臆想一个"必须"就往前冲）。

1. **免能力天花板必须先离线算**（`BENCH_SPEC.md §4.1` 闸4 第二必答，本决议不给它开例外）。
   具体问题：**只用免费描述符、不花任何实验预算，爬 oracle 能拿到多大改进？**
   已知不利证据：QED 是若干免费描述符压成的平滑函数（T-223 实测：4-烷氧基苯甲醛整条断崖
   完全由 rdkit 的 ALERTS 计数一个开关决定）⇒ **拿 QED 直接当 oracle，极可能是一条免费梯子。**
   ⇒ 天花板 >5% 就不是能力题，**换 oracle，不许调分差阈值**（那是坑⑨）。
2. **必须有多目标张力**。单轴爬坡不是药物优化。至少两个互相拉扯的量
   （活性↑ 常伴脂溶性↑ ⇒ 溶解度↓），否则"改进"退化成把一个数往一个方向推。
3. **起点必须由题面钉死，不许 agent 自选**。
   ⚠️ 这是本决议自己引入的新旋钮风险，必须当场堵掉：起点若可选，**故意挑个烂起点、随便改
   一下就"进步很大"** ⇒ 分差成了选起点的技巧，正是坑⑨的形状。

### 2.5 决议

**"判产物优化"立为药物侧判分口径的候选主线，按 §2.4 三条关逐条实测；三条全过才建题。**
第一步是**零机时**的：离线算免能力天花板。**不过关就换 oracle，不许调阈值救。**

## §3 决议三：与 RSI 的关系——登记为第二阶段方向，本轮不启动

owner 的话是"**看看能不能**跟 rsi 结合一下"，是探索，不是指令。下面把两种读法摊开，
**并明确指出其中一种与现行封存规则直接冲突**。

| 读法 | 具体是什么 | 需要什么 | 判定 |
|---|---|---|---|
| **甲：benchmark 自我进化** | 把跑批产出的分子和实测结果**回灌成新题、新数据**，题库随跑越长越难 | 一条从 run 产物到题库的回灌链 | ⚠️ **与 `DECISIONS.md §2.4` 封存规则正面冲突**：题库随上一批跑出来的东西漂移 ⇒ **两批分数立刻不可比**，而封存规则存在的全部理由就是保住可比性 |
| **乙：agent 在链上自我改进** | agent 在一条链里"改结构 → 验证 → 修正认知 → 再改"，**改进量既是分数也是学习信号** | judge 侧产物 oracle（**§2.2 已实测在手**） | ✅ **与现有资产同形**：`长程任务_路线图.md` 的 C 链站 4→5→6 就是"改 → 验 → 修正 → 定下一轮"，站 4（A-Edit）**已测完封存** |

**推荐先做乙，理由是它不需要新基础设施**：口径就是 §2 那一条（判产物比上一轮好多少），
把它从"一轮"扩到"多轮"即可；而甲要先解决可比性，那是个规则级冲突，不该在题都还没立住时动。

**决议**：
1. **RSI 登记为第二阶段方向**（读法乙优先），本轮**不启动、不写代码、不进闸1**。
2. ⚠️ **不许把它升级成当前阶段的规矩** —— 08-28 刚撤销的坑③ 就是"一句正确的话被连升两级"
   造成的（正确的判分口径 → "整个阶段不许有 checkpoint"），把第二阶段的想法写成现在的禁令
   或必须，是同一个错。
3. 甲、乙谁先做**属 owner 裁定，不由执行方定**；本文只给推荐与依据。已同时登记进
   `DECISIONS.md §3 待裁定`。

追不完的赛跑，而 judge 侧给任意新分子打分的能力**今天已实测在手**；
