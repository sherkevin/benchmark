| 决议 | 日期 | 权威落点 |

| **「比对藏起来的标准答案」这个判分范式作废，改为「跑一个打分函数看产物比钉死的起点好多少」；同时 RSI 必须含模型训练（owner 2026-08-28 两条裁定，本节最高优先）**。owner ### 2.6 当前阶段的设计范围与造题路线（owner 2026-08-23）

| 决议 | 说明 |
|---|---|
| **不测"做实验"，测"长程任务"（最根本，owner 2026-08-23）** | **"预测 / 测一个分子的性质"本身就是做一次实验 = 调一次工具拿一个结果**——测这个只是测工具调用能力，**不是我们要测的**。我们要测的是**更高维度的长程任务**：给一个高层目标，agent 自己想清楚该做哪些实验、按什么顺序、结果怎么解读、怎样一步步逼近目标。⇒ **答案不能是"某分子的性质值"（那是实验级、= 只做一次实验），必须是目标级的产物**（找到 / 选出 / 设计出的分子、发现的结构-性质关系……）；性质查询/预测只是过程里调的工具，不是要交的答卷。**反例（都错在实验级）**：`qed_01` Job1 报目标 QED、logS 报数值、三版 Job2——答案都是一个性质值。**正例（目标级）**：材料 `constraint_02`/`satisfy_02`——"在约束下找出那个材料"，答案是"找到什么"，得把一串实验组织起来才能得到。 |

## §5 维护规则（owner 2026-08-21 立）

1. **决议一达成就落盘，在同一个工作单元内完成**——不许"下次再补"。
2. 落盘 = **本文件追加一行** + 原文进权威落点（ADR / `实验规范.md` / `ACTION_RULES.md`）。
   本文件只放**一句话 + 出处**，论据留在原文档。
3. **重大设计决策写 ADR**（设计取舍、架构切分、范围声明、不变量）；流程与判分细则进规范文档；
   单步进度进 `TODO.md`。三者不混。
4. **决议被推翻时，把旧的冲突原文从生效区删除，只在 §4 留一行"废了 + 为什么"**（owner 2026-08-23）。§4 有"不得复活"标注、不会被当现行；而把过期原文留在生效区（§1/§2/§3 及其他文档正文），会被后来人反复**误检索成现行内容**。决策史的价值靠 §4 一行 + `TODO.md` 留痕保住，不靠在生效区留全文。
5. 每条须能回答：**谁定的、什么时候、管什么、原文在哪。** 缺一项就不算落盘。
6. **新日期与旧日期冲突，以新的为准，旧的按第 4 条清理**——不允许两条矛盾的决议同时躺在生效区。
