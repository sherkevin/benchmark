# 手写 case 操作规程 v1（草案，待 owner 过目）

> **这份规程解决一件事**：150 道题由工程师手写时，"什么样算合格"要有统一标准，否则工程师写的和监工审的对不上，返工代价最大。
>
> 所有判据的数值都来自库的实测分布（见 §7 附录），不是拍脑袋定的。

---

## 速读：一道题的诞生流程

```
工程师定 4 样          机器核 4 样           监工过 1 遍
────────────────      ────────────────     ────────────
领域（考什么）    →    标准答案             →   六条自检
约束（条件）      →    合格候选池               全过才收
说明（给 agent）  →    可解性验证
题面（怎么问）    →    格位（查重用）
```

**分工的道理**：设计意图必须人定，因为脚本不懂化学；答案必须机器算，因为人算不了 92,193 个实体的穷举。

---

## 一、工程师要填的四栏

### 1.1 领域（`target_domain`）

**要求**：写出**这道题在科学上问的是什么**，不是笼统的类别名。

| 不合格（现状） | 合格 |
|---|---|
| `small-molecule drug candidate` | `血脑屏障穿透型抗抑郁候选` |
| `superconducting crystal material` | `常压下可工作的铜氧化物超导体` |

**判据**：把领域名单独拿给一个化学背景的人看，他能说出"这题大概在找什么样的分子/材料"。做不到就不合格。

**为什么**：现在 150 道题的领域名一字不差，审稿人一眼能看出是批量生成的。

### 1.2 约束（`constraints`）

**要求**：约束组合必须在**化学上说得通**，而不是数值区间的机械组合。

**格式**（不变）：每条约束是"性质名 + 比较符 + 阈值"三件套，如 `logS >= -3.5`。

**能用哪些性质**（实测库内可查的；**「适用侧」一栏是硬要求**）：

| 性质名 | 大白话 | 库内条数 | 值域 | 适用侧 |
|---|---|---|---|---|
| `logS` | 水溶性（越大越好溶） | 2,299 | −10.10 ~ 1.63 | 药物 |
| `atom_count` | 分子里有多少个原子 | 74,941 | 1 ~ 801 | 药物 |
| `element_count` | 用了几种元素 | 药物 74,901 / 材料 17,252 | 1 ~ 9 | **药物禁用 · 材料推荐** |
| `bbb` | 能不能进大脑（0/1） | 757 | 0 / 1 | 药物 |
| `logD` | 油水分配（脂溶性） | 604 | — | 药物 |
| `half_life` | 半衰期（药效持续多久） | 523 | — | 药物 |
| `tc` | 超导临界温度（K） | 13,870 | 0 ~ 185 | 材料 |
| `family` | 材料族（Cuprate 等） | 13,870 | 10 类 | 材料 |
| `condition` | 测量条件 | 13,869 | — | 材料 |

**只能用来筛选、不能查具体值的三个**：`mw`（分子量）、`logp`、`tpsa`。可以写进约束，但 agent 用 `get_property` 查不到数值。

#### `element_count` 为什么药物禁用、材料推荐

**判据是科学含义，不是统计分布。**

| | 药物侧 | 材料侧 |
|---|---|---|
| 这个数在科学上意味着什么 | **几乎什么都不意味着**。有机分子基本都是 C/H/O/N + 少量 S/P/卤素，"用了几种元素"不携带独立信息——**没有药物化学家会说"这分子用了 5 种元素所以怎样"** | **就是二元/三元/四元化合物的分类**，材料学的基本维度：合成难度、相稳定性、掺杂策略都跟它直接相关 |
| agent 能做什么推理 | 做不出化学推理，只能当查表条件用 | 能推理"元素越多相图越复杂、合成越难" |
| 实测分布 | 4 种占 **42%**（集中） | 2~6 种较均匀（3048 / 3544 / 2914 / 4568 / 2310） |
| 现有题用法 | **0 道用** | **45 道在约束里、71 道在格位** |

**注意**：即使把药物侧的分箱调均匀，它仍然禁用——因为 agent 面对"元素种类数必须是 4"这个条件**做不出任何有意义的化学推理**，那正是我们要避免的"测不出能力的题"。

反过来，材料侧现有那 45 道用了它的题是**对的**，不该改。

### 1.3 说明（`domain_knowledge`）

**要求**：把约束翻译成 agent 能懂的判据描述，**并明确每条判据能不能通过工具查**。

必须包含三件：

1. 每条约束的**含义与单位**（如"logS 是摩尔水溶性的常用对数，单位 log10 mol/L"）
2. 该判据**从哪查**（性质接口 / 实体记录）
3. 若合格者可能多于一个，**平手怎么办**（如"多个合格时答 logS 最高的那个"）

**第 3 条不能漏**：现有题里有 18 道多成员格的类型1 题一开始漏了这句，后来才补。

### 1.4 题面（`query`）

**要求**：每道题的题面**必须不同**，且带专业含义。

**不合格的写法**（现状，150 道一字不差）：

> Identify a small-molecule drug candidate that satisfies all required aqueous-solubility and molecular-size criteria.

**合格的写法**（举例）：

> 为口服抗抑郁项目筛一个先导化合物：既要能穿过血脑屏障，又不能因为太难溶而影响吸收。候选库里符合条件的可能不止一个，取溶解度最好的那个。

**判据**：把 150 道题面并排看，**不能有两道读起来一样**。

## 二、机器核的四栏（工程师不要手填）

| 字段 | 机器怎么算 |
|---|---|
| `gt` 标准答案 | 在库里穷举出满足全部约束、且目标量最优的那一个 |
| `s_feasible` 合格候选池 | 穷举 92,193 个实体，列出全部满足约束者 |
| `solvability_verified` 可解性 | 确认答案唯一（不能有并列第一） |
| `grid_key` 格位 | 用于跨题查重，防两道题撞车 |

**工程师的动作**：定完前四栏后，跑核算工具；**若返回"无解"或"答案不唯一"，回到 §1.2 调约束**，不要手动改答案。

## 三、化学合理性怎么判（三条硬线）

这是这份规程的核心 —— **脚本造出"原子数 ≤4 且几乎完全不溶"这种题，就是因为没有这三条。**

### 3.1 分子大小的下限

**药物分子的原子数不得低于 10。**

**理由**（库内实测分布）：

| 原子数区间 | 库内有多少 | 占比 |
|---|---|---|
| 0 ~ 4 | 163 个 | **0.22%** |
| 5 ~ 9 | 361 个 | **0.48%** |
| 15 ~ 19 | 13,048 个 | 17.41% |
| 20 ~ 24 | 14,106 个 | 18.82% |
| 25 ~ 29 | 11,163 个 | 14.90% |

原子数 ≤9 的只占 0.7%，且**那个尺度的分子（比水或甲烷大不了多少）不是药物候选**。在那里出题，测的不是化学能力。

### 3.2 相容性检查

**约束之间不能互相矛盾。** 至少查这两对：

| 组合 | 为什么要查 |
|---|---|
| 分子大小 × 溶解度 | 极小的分子不可能极难溶（`cs_drug_01` 犯的就是这个错：原子数 ≤4 且 logS ≈ −10） |
| 脂溶性 × 血脑屏障 | 能进大脑通常要求一定脂溶性，两者反向组合要有理由 |

**做法**：定完约束后，工程师自己回答一句"符合这组条件的分子，现实中是什么样的"。答不出来就是组合有问题。

### 3.3 材料侧的族选择

**不要用「未知」族出题。**

**理由**：材料库 17,252 条里，族标为「未知」的有 **11,481 条（66.5%）**，那是 UCI 数据集没有族标注的部分。用它出题，题面无法写出专业含义。

**可用族**（占比 ≥0.4% 的）：`Other`(20.5%)、`Cuprate`(5.07%)、`Ferrite`(3.00%)、`Oxide`(1.85%)、`Chevrel`(0.43%)。

**注意**：材料侧实际可用的只有 **5,771 条（33.5%）**，出题空间比药物侧窄。若某类题凑不够数量，如实报，不要退回用「未知」族。

## 四、候选池下限（推理空间）

**合格候选池的成员数，是这道题"有多少推理空间"的直接度量。**

| 题型 | 下限 | 理由 |
|---|---|---|
| **类型1 约束满足** | **≥ 3 个** | 现在 37%（22 道）只有 1 个成员——agent 筛出来就赢，不需要比较 |
| **类型2 约束最优** | **≥ 5 个** | 它的任务本身是"从合格者里挑最好的"，池子太小挑不出名堂。现有类型2 中位数是 21，做得对 |
| **open 发现类** | 不适用 | 答案不在可查库里，走另一套（A/B 配对 + 推理梯度，见 ADR-0018） |

**上限也要注意**：候选池超过 200 个时，穷举成本会让题变成"耐力测试"而非"推理测试"。**建议控制在 5~100 之间。**

## 五、文献怎么挂（`provenance`）

**要求**：文献要针对**这道题的科学问题**选，不是按性质类型套模板。

| 不合格（现状） | 合格 |
|---|---|
| 所有 logS 题都挂 Yalkowsky 1980（讲溶解度的经典文章） | 抗抑郁题挂血脑屏障穿透的相关研究；超导题挂该族材料的原始报道 |

**必须有**：真实的 DOI 或明确出处，**不许编造**。

## 六、提交前的六条自检（工程师自己过）

每道题提交前逐条打勾，**有一条不过就不要提交**：

| # | 自检项 | 怎么验 |
|---|---|---|
| 1 | 领域名有专业含义 | 单独拿给人看，能说出"在找什么" |
| 2 | 约束在化学上说得通 | 能用一句话描述"符合条件的分子现实中什么样" |
| 3 | 分子原子数下限 ≥10（药物侧）/ 未用「未知」族（材料侧） | 查约束区间 |
| 4 | 候选池成员数达标（类型1 ≥3、类型2 ≥5、上限 100） | 跑核算工具 |
| 5 | 说明里写了判据来源与平手规则 | 通读 `domain_knowledge` |
| 6 | 题面与已有的所有题都不一样 | 与已提交题面比对 |

**另外两条由工具自动查**（跑 `query_lint.py`，退出码必须为 0）：格位不与已有题撞车、答案唯一。

## 七、附录：库的实测分布（选约束时用来查"这里有没有货"）

### 7.1 药物侧

| 项 | 数据 |
|---|---|
| 实体总数 | 74,901（`z` + 6 位数字） |
| `logS` 有值 | 2,299 条，范围 −10.10 ~ 1.63 |
| `atom_count` 有值 | 74,941 条，范围 1 ~ 801，主流集中在 15~30 |
| `element_count` | 17,252 条，1~6 种；分布 3种 18.0% / **4种 42.0%** / 5种 30.7% / 6种 7.9% |

### 7.2 材料侧

| 项 | 数据 |
|---|---|
| 实体总数 | 17,252（`c` + 5 位数字） |
| **可用（有族标注）** | **5,771 条（33.5%）** |
| 「未知」族 | 11,481 条（66.5%）—— **不要用** |
| `tc` 范围 | 0 ~ 185 K |
| 族分布 | Other 20.5% / Cuprate 5.07% / Ferrite 3.00% / Oxide 1.85% / Chevrel 0.43% / Carbon 0.17% |

### 7.3 一个反面教材（现有题，已列入删除清单）

```
题目：cs_drug_01
约束：logS ∈ [−10.5, −9.5]     ← 几乎完全不溶
说明：原子数必须在 [0, 4]       ← 比水还小的分子
候选池：1 个
```

**三条硬线全违反**：原子数低于下限、两条约束互相矛盾、候选池只有 1 个。

**它是怎么产生的**：脚本把原子数按每 5 个切一格，格 0 就是 `0~4`；脚本不知道这个尺度的分子不是药物，只知道这个格里有 163 个成员、够出一道题。

## 八、判据分两类：四条红线无例外，四项默认值可带理由偏离

**分类的依据**：违反它是"逻辑上不可能"还是"经验上不推荐"。

### 8.1 红线（无例外，碰到就必须改题，不用问监工）

| 判据 | 为什么无例外 |
|---|---|
| 约束不能互相矛盾 | 矛盾了就无解，题做不了 |
| 答案必须唯一 | 不唯一则判分无法进行 |
| 格位不能撞车 | 撞了等于同一道题出两次 |
| 文献不许编造 | 学术诚信，没有讨论空间 |

### 8.2 默认值（可偏离，但理由要写进 case 文件）

| 判据 | 默认值的来历 |
|---|---|
| 药物原子数 ≥ 10 | **10 是从库分布推的经验值**，不是化学定理 |
| 类型1 候选池 ≥ 3 | 3 是经验值 |
| 类型2 候选池 ≥ 5 | 5 是经验值 |
| 材料不用「未知」族 | 经验判断（用了难写出专业含义，但若工程师真能写出来，不应硬拦） |

**偏离的做法**：不用停下来问监工，**把理由写进 case 的 `deviation_note` 字段**，随题一起交审查。

`deviation_note` 要写三件：①偏离了哪条默认值 ②实际取了什么值 ③**为什么这道题必须这样**（要能被审查）。

**举例**：「偏离类型1 候选池 ≥3，实际取 2。理由：本题考的是常压下高 Tc 铜氧化物，库内同时满足两个条件的天然只有 2 个——这个稀缺本身就是该科学问题的真实约束，不是题目缺陷。」

### 8.3 为什么这么分

| 好处 | 说明 |
|---|---|
| 不成瓶颈 | 150 道题若每道遇到冲突都停下来问，监工就是瓶颈 |
| 理由留痕 | 审查时能看到，事后能追溯 |
| **对论文是加分项** | 审稿人看到"这道题候选池只有 2 个，因为该科学问题在库内天然只有两个候选，已记录"——比盲目套规则更显专业 |

### 8.4 什么情况要报监工

**只保留给一种：工程师认为某条红线本身错了。** 那是要改规程，必须在明处改。

## 九、这份规程本身的边界

**规程管什么**：一道题合格的最低标准。

**规程不管什么**：具体每道题考什么科学问题 —— 那是工程师的专业判断，规程不替代。
