## 2. 每道题怎么配（核心方法）

### 2.1 五步

| 步 | 动作 |
|---|---|
| ① | 从全库选定 gt，**放进 B**（该 case 的 A 可见集里不得出现） |
| ② | 选一组与 gt **同族**（除某一元素外组成相同）、目标性质**单调有序**的分子放进 A —— 这是 agent 的推理素材 |
| ③ | 混入**干扰项**（非目标族的分子），数量 K |
| ④ | 跑质量门两条（见 §3），任一不过即换 gt 重配 |
| ⑤ | 落盘该 case 的可见集白名单 + 梯度参数 + `G_B` |

### 2.2 梯度三参数（ADR-0018 §3）

| 参数 | 含义 | 取值 |
|---|---|---|
| **n** | A 里同族、性质有序的样本数 | **3～5**（≥6 趋势一目了然=送分；≤2 两点定不了趋势） |
| **d** | gt 距 A 内最近同族样本的步数 | **1～2**（≥3 已被 goal §2b④ 禁止） |
| **K** | 干扰项数量 | **20～30**，**硬下限 K ≥ 10** |

**三个值必须逐 case 显式落盘**，供复核与论文附录引用。

### 2.3 一个实测可用的族（直接可作首个 case 的原型）

监工在 A 侧实测扫出的族（16 号=C、19 号=H、22 号=O、81 号=N，映射表 agent 不可见）：

```
族「变动 16 号元素，其余固定 {19:22, 22:1, 81:2}」
  z002886   16号×14   logS = -1.780
  z002972   16号×15   logS = -1.990
  z002890   16号×17   logS = -2.820
  z017986   16号×19   logS = -3.089
  → 斜率 -0.954/原子；外推 16号×21 时 logS ≈ -7.098   ← gt 候选
```

这是 n=4、d=1（若 gt 取 16号×20 则 d=1）的形态。**全库共 124 个这样的天然族**（药物侧），可作起点，但按 ADR-0018 你**不受限于**这 124 个——A 的内容可按需组织。

## 3. 质量门两条（任一不过则该 case 废弃）

### 3.1 第一条：A 内无替代解

在**该 case 的可见集**内穷举题面目标，须证**不存在满足全部硬约束且目标量不劣于 gt（容差 δ）的分子**。

**⚠️ 这条最容易写成重言式。** ADR-0018 §3.2 已定：**K = 0 时这条自动成立、零过滤力**——因为 A 里除目标族没别的分子。goal §2b④ 原文就警告过"不能写成'仅穷举 A 拿不到 gt'"。**所以干扰项是强制的。**

K 的取值有实测依据（ADR-0018 §3.1）：以 gt 的 logS ≈ −7.098 为例，全库 2,299 条中 44 条（1.9%）不劣于它 ⇒

| K | A 内混进更优解的概率 | 含义 |
|---|---|---|
| 10 | 17.6% | 门的过滤力偏弱 |
| **30** | **44.0%** | ✅ 有真实过滤力，判废率可接受 |
| 50 | 61.9% | 判废过半 |

**预期你会遇到约四成的 case 在这一步被判废**——这是正常的，不要为了通过而调小 K。

### 3.2 第二条：线索可达

case 须声明 `anchor ∈ A` + `edit_op ∈ 封闭算子集` + **跳数 ≤2** + `evidence_set`（A 内 ≥k 条同向证据），并脚本校验：

- `edit_op(anchor)` 的**组成变换结果与 gt 的分子式多重集相等**（ADR-0018 §5.3，不是结构比对）；
- `evidence_set` 每一条都能由 A 侧接口查得。

## 4. 同分异构的判法（ADR-0018 §8）

实测药物侧 124 个族中 **91 个**含"同组成不同分子"，例如 `19号×23` 对应 logS = −2.000 与 −1.910 两个分子。因为 agent 提交的是**组成**：

| 情形 | 处置 |
|---|---|
| 同组成的多个 B 侧分子**全部满足**题面目标窗口 | 全部纳入 `G_B`，命中任一即算命中 |
| **部分满足、部分不满足** | **该 case 废弃** —— 组成分不开它们，判分会变运气 |
| 同组成分子仅在 A 侧出现 | 存在性接口按 ADR-0018 §4.1 返"不存在"，不影响判分 |

## 9. 追加项（ADR-0018 修订 R1，2026-08-07）—— E6 实跑时报出、监工已裁定

E6 在跑裸答基线时发现两处缺口归你，**都不是你做错，是我规范写得不到底**。

### 9.1 把 15 道 dh open 的 `g_b` 注册进 `b_partition.json`

**现状**：`g_b` 只写在 case JSON 里，`b_partition.json` 的 `cases` 里没有 ⇒ 判分时 `hit_gb` **回落到顶层 `g_b`**，那不是本 case 的合格集，**命中与未命中都不可信**。

**我的表述问题**：ADR-0018 §9 项 4 只写了「`G_B` 落盘」，没写「注册进 `b_partition`」。这两件其实是一件事的两半。

**要做**：`b_partition.json` 的 `cases[<case_id>].g_b` 作为该 case G_B 的**唯一来源**；顶层 `g_b` 只留作 fixture。判分若回落到顶层**应当报错，不得静默降级**——这条请在交付说明里点明，E3 那边照此实现。

### 9.2 复算每个 fixed case 的可行集大小

**背景**：goal §2b 给 fixed 类定的裸答判据是「以同 case 候选池内随机抽样命中率为基线，超 2× 即废弃」，但我在 E6-03 任务书里**没定"候选池"是什么**。E6 实测三种口径后果完全不同，已裁定取**完整过滤邻域**（见 ADR-0018 R1-③）。

**要做**：为每道 fixed case 落盘 `|S_feasible|` = 满足题面全部硬约束的候选集合大小（类型1 为合格者集合，类型2 为筛选后待排序的集合），按**当前库快照**复算。

**注意 `co` 系列（类型2）目前无成员名单** —— 要么补齐名单，要么明确该 case 只能做 best-ID 单点判并在 report 写明理由。**不要为了省事一律走单点判。**
