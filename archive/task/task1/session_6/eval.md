# Session 6 评估 · 长依赖链传播测试（用户提出的构造）

**用户的方法**：把任务拆细 = 长程任务（分步=逐条发）；合并成一条 = 全量。用这个构造做真正的**长链错误传播**测试。

**设计**：用平台上唯一有真实、逐次变化数值的工具（crystal_predict）取 6 个真值
`A=MgB₂.Tc, B=Nb₃Sn.Tc, C=MgB₂.λ, D=Nb₃Sn.ω_log, E=MgB₂.形成能, F=Nb₃Sn.形成能`，
再接一条**每步依赖前一步结果**的级联（共 9 步，compute 步**禁止调用任何工具**，强制凭上下文记忆）：

```
S1 = A ÷ B
S2 = S1 + C
S3 = S2 × D
S4 = S3 − (E × 1000)
S5 = S4 ÷ B
S6 = S5 + F
S7 = round(S6, 3)
```

- 全量(A)：一条消息含 P1,P2,S1–S7（`all` 模式 + "连续执行不要停顿"）
- 分步(B)：9 条消息（预测2 + 计算7），第 k 步在独立一轮，必须回忆前几轮的值
- **传播通道**：S3 错则 S4–S7 全错 → 若分步会污染，长链必现。
- **客观核验**：对每个 run 用它自己的真实预测值算出正确级联，逐步对比 agent 报告值（`verify6.py`），区分 OK / 新计算错误 / 传播错误。

## 结果（A×5，B×3，均完整跑完）

| 条件 | 整条 9 步链全对 | 每步最大相对偏差 | compute 步是否凭记忆 |
|------|----------------|-----------------|--------------------|
| A 全量 | **5/5** | ≤ 0.003% | —（单轮）|
| B 分步 | **3/3** | ≤ 0.019% | ✅ 全部 0 次工具调用（纯回忆）|

- **跨轮回忆 + 长链算术：A、B 全部正确。** 分步即使在第 9 轮仍能精确回忆前 8 轮的值并算对。
- **未观察到错误传播**（无"错一步、后面全崩"的现象）。
- 唯一可测差异：**分步数值漂移略大（~0.01–0.02% vs 全量 ~0.003%，约 6×）**，原因是跨轮转述时中间值被轻微四舍五入；但绝对可忽略，最终答案 2–3 位有效数字仍正确。**这是良性精度损耗，不是"错误污染"。**

## 判定

**用户假设的"分步错误传播导致最终更差"，在长达 9 步的真实依赖链上仍未出现。** 现代 Claude 把每轮工具输出与中间结果完整保留在上下文，跨轮回忆与级联计算不退化。分步唯一的代价是**极微小的精度漂移**（因转述舍入），远不足以使结果变差。

> 方法学注记：首版 verify6 因把 agent 的 **Unicode 减号 `−`(U+2212)** 当成正号、又误取了表格"说明列"里的数字（如公式中的 1000、"3 位"中的 3），一度误报"S4 符号错误传播"。修正解析器（归一化减号 + 只取纯数字单元格）后，A、B 全部为正确链。**这恰好印证：判定"错误传播"必须逐位严格核验，否则极易把解析假象当成模型错误。**
