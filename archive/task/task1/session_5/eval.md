# Session 5 评估 · 错误传播压力测试（材料定量对比，3 步）

**目的**：专门检验用户假设——「分步喂入时每步看不到全局，可能出错，错误进入上下文污染后续，使最终结果不如一次问完」。

**设计**：制造一个**真实的跨轮数值依赖**通道：
- 步骤 1：预测 MgB₂ 的 Tc 与形成能（crystal_predict，真实模型，逐次有 ~1% 随机波动）
- 步骤 2：预测 Nb₃Sn 的 Tc 与形成能
- 步骤 3：**禁止调用 compare_materials / 任何预测工具**，要求 agent 仅凭前两步已得到的数值，亲自计算 Tc 比值、形成能差、排序，并写明所用每个数值。
- 全量(A)：以上合并为一条消息（+"连续执行不要停顿"）；分步(B)：三条消息，第 3 步在独立一轮、必须从上下文回忆前两轮数值。

**关键点**：crystal_predict 每次数值都不同 → 若分步在第 3 轮记错/漂移，立刻可被发现；这是本平台上唯一能真正诱发"传播错误"的通道。

|-----|------------|--------|---------|----------------|

## 判定

- **跨轮数值回忆：8/8 全部精确**。分步(B)在独立的第 3 轮里精确回忆出前两轮工具返回的**全精度**数值，**没有任何漂移或污染**。
- 算术：A 4/4 精确；B 3/4 精确 + B_r4 一次末位四舍五入小瑕疵（3.36 vs 3.37）。这是**单次计算的通用舍入误差**，输入数值本身回忆无误 → **不是"上下文污染/错误传播"**。
- **结论：用户假设的"分步错误传播"机制在本平台未出现。** Claude 模型把工具输出完整保留在上下文，跨轮回忆+计算不退化。

> 局限:本测试链路为中等长度(2 个真实数值、3 步)。平台上唯一的长链路(药物 7 步)因后端 `generate_drug_report` 等为**固定输出**而无法承载真实的长链传播测试(详见 `../analysis.md`)。
