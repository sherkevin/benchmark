## 1. 先解决"完成率"混淆

只需在全量 prompt 里加一句「**请连续执行完所有步骤，中途不要停顿、不要等待确认**」，全量即可**单轮完整跑完**（实测材料任务 A×4 全部一轮完成，无截断）。
→ 完成率混淆是**可消除的 prompt 工程问题，与"哪种方式质量更好"无关**。两者都能完整跑完后再比，才公平。

> 附带教训：若强行喂"继续"驱动，反而会让已完成的 agent **无中生有**去做多余工作（实测它去触发了慢的 crystal_generate）。所以正确做法是用指令让它一轮跑完。

## 2. ⚠️ 决定性发现：本平台后端大量是「固定输出」，导致最终交付物在两种方式下**收敛甚至完全相同**

我审计了"完整跑完"的 run，发现：

| 证据 | 结论 |
|------|------|
| drug 任务 A、B 的 `generate_drug_report` 输出 **逐字节完全相同**（3575 字符 identical） | 药物最终报告与提问方式无关 |
| 把靶点换成 **PCSK9**，`generate_drug_report` 仍返回标题"GLP-1R"、NC-Pep-003、score 0.94、Kd 0.06 | 该报告是**写死的固定模板**，连真实靶点都不反映 |
| 材料 crystal_predict 有真实计算（逐次 ~1% 随机波动），但后续 compare_materials **重新取数**，不依赖 agent 记忆 | 材料链路上数值始终自洽，无漂移 |

**含义**：在这个平台上，"完整跑完后的最终结果质量"在全量 vs 分步之间**几乎无法产生差异**——因为决定性内容由固定/受工具约束的输出决定，agent 主要是"叙述者"。
> 这其实是对"测试方法有没有问题"的最深回答：**问题不在我怎么问，而在被测系统本身是确定性的**，它把两种提问方式的输出都"夹"到了同一答案上。

## 3. 直接检验用户的「错误传播」假设（session_5）

为了给该假设**最大机会**，我专门设计了一个**强制跨轮数值依赖**的任务（材料是平台上唯一有真实、逐次变化数值的链路）：
- 步骤1 预测 MgB₂ 的 Tc/形成能 → 步骤2 预测 Nb₃Sn → 步骤3 **禁用一切预测/对比工具**，要求 agent 仅凭前两步记忆的数值亲自算 Tc 比值、形成能差、排序。
- 分步(B) 的步骤3 在**独立一轮**，必须从上下文回忆前两轮数值——若会污染，此处必现。

**结果（A×4 + B×4，全部完整跑完）：**

| 指标 | A 全量 | B 分步 |
|------|--------|--------|
| 跨轮数值回忆准确 | 4/4 精确 | **4/4 精确**（能回忆出全精度 32.1750373840332 等）|
| Tc 比值正确 | 4/4 | 3/4（B_r4 末位舍入 3.36 vs 3.37）|
| 形成能差正确 | 4/4 | 4/4 |
| 违规重调工具规避记忆 | 0 | 0 |

**判定**：
- **跨轮回忆 8/8 全部精确，零污染、零漂移。** 分步并没有因为"看不到全局"而记错前面的数值。
- B 唯一的瑕疵是 1 次**末位四舍五入**（输入值回忆完全正确），属单次计算的通用误差，**不是上下文污染**。
- → **用户假设的"分步错误传播"机制，在本平台未观察到。** 原因：现代 Claude 模型把工具输出完整保留在上下文，跨轮回忆+计算不退化；且平台工具会在后续步骤重新取数，结构上进一步阻断传播。

## 4. 盲评（完整跑完后的报告质量，session_2）

用 2 个独立子 agent 对 A、B 的最终材料报告做**盲评 + 呈现顺序对调**（控位置偏置）：
- Judge 1：判 **B（分步）更好**；Judge 2：判 **基本相当、略偏 B**。
- 两位都在 **A、B 两份里发现相同的内容瑕疵**（负带隙、ω_log 参照值偏小）——属平台工具 artifact，与提问方式无关。

→ 完整跑完后，质量**基本相当**；该对样本里分步反而略详尽（每段紧贴工具输出，信息更全）。但这随 run 波动，不足以断言分步系统性更优。**与"分步更差"的预期相反。**

## 5. 修正后的结论

1. **完成率不是质量**：全量"停在 Stage 1"是编排假象，加一句"不要停顿"即可消除；不应计入质量对比。（纠正 v1）
2. **在 NobelClaw 这个平台上，两种提问方式"完整跑完后的最终结果质量基本无差异"**——因为后端大量为固定/工具约束输出，最终交付物收敛（药物报告甚至逐字节相同）。
3. **用户的"分步错误传播"假设方向上是合理的通用担忧，但在本平台未发生**：专门设计的跨轮依赖压力测试中，分步 8/8 精确回忆前序数值、无污染；盲评也未显示分步更差（反而略好或相当）。
4. **若一定要排序**：完整跑完的前提下，
   - 质量：≈ 平局（盲评微偏分步，因逐段更忠实工具输出）；
   - 全量优点：单轮、更快；
   - 分步优点：每段紧贴工具结果、可控、可纠错，且**未见**理论上担心的传播退化。

## 6. 长依赖链传播测试（session_6）—— 采纳用户的构造方法

> 用户指出：v2 §6 旧版说"长链测不了"是错的——把任务**拆细就是长程**，合并就是全量。此说成立，旧局限**已撤销**。

**做法**：用 crystal_predict 取 6 个真实数值，接一条**每步依赖前一步结果**的 9 步级联（S1→…→S7，compute 步禁用工具，强制凭记忆），全量=一条消息、分步=9 轮。S3 错则 S4–S7 全崩 → 长链能否传播，此处必现。逐步客观核验（`verify6.py`）。

**结果（A×5，B×3，均完整跑完）**：

| 条件 | 9 步链全对 | 每步最大相对偏差 | compute 步凭记忆 |
|------|-----------|-----------------|-----------------|
| A 全量 | **5/5** | ≤ 0.003% | —（单轮）|
| B 分步 | **3/3** | ≤ 0.019% | ✅ 全 0 次工具（纯回忆）|

- **A、B 都正确走完长链**；分步即使在第 9 轮仍精确回忆前 8 轮的值并算对。
- **没有错误传播**（无"错一步后面全崩"）。
- 唯一差异：分步**数值漂移略大（~0.01–0.02% vs ~0.003%，约 6×）**，因跨轮转述时中间值被轻微四舍五入——**良性精度损耗，绝对值可忽略，最终答案 2–3 位有效数字仍正确**，不是"错误污染"。

> ⚠️ 方法学教训：verify6 初版把 agent 的 **Unicode 减号 `−`** 当正号、又误读表格"说明列"里的数字，一度**误报**"S4 符号错误并传播"。严格逐位核验后证实为**解析假象**，A/B 全为正确链。判定传播必须逐位核验，否则极易把解析 bug 当成模型错误。

|---|---|---|---|

### session_8 · 纯叙述链（不调任何工具，最易出传播的场景，A×3 + B×3）

任务：先写 MgB2 科普 → 自由列 3 个常见误解 → 写澄清短文必须针对那 3 个误解（不可换）。

子 agent 盲评（顺序对调）：

| Run | 真实身份 | 第 3 步是否针对第 2 步那 3 个误解 |
|---|---|---|
| A_r1 / r2 / r3 | 全量 | 3/3，3/3，3/3 |
| B_r1 / r2 / r3 | 分步 | 3/3，3/3，3/3 |

**6/6 全部 3/3 完美传承**——即使在 NobelClaw 上最有利于"传播假设"的纯自由生成场景下，分步也没有"换误解/漏误解/扭曲误解"的传播错误。

## 8. 仍然诚实的局限

- 已能在本平台测的：纯数值依赖链（session_5/6）、自由解读+工具混合链（session_7）、纯自由叙述链（session_8）——**全部未观察到误差累积**。
- 仍未测的：**超长开放生成链**（如 20+ 轮自由叙述/写作累加），可能在某个长度阈值后才显现微小漂移。本次最长 9 轮（session_6）、纯叙述 3 轮（session_8）足以否证"短/中长链有传播"，但不能否证"超长链有传播"。

## 10. 一句话总回答

在 NobelClaw 上，我已在**数值依赖链（9 步）+ 工具混合链（4 步）+ 纯自由叙述链（3 步）**三种最可能出现"误差累积"的场景下分别测过——**全部未观察到分步比全量更差的传播错误**，分步唯一代价是 ~0.01% 的可忽略数值漂移。两种提问方式完整跑完后**质量等价**，主要差异在效率（全量快 ~40%）和工具调用经济性。
