### 子目标 2 · 权威性核查（核心任务）

对每个数据集的承载论文查**被引用情况**，多源交叉：

- **OpenAlex**（`api.openalex.org`，免费无 key，✅实测可达）——主源
- **CrossRef**（`api.crossref.org` 的 `is-referenced-by-count`，✅实测可达）——期刊类准
- **Semantic Scholar**（CS 论文覆盖最好，⚠️实测 429 限流，需加延迟重试）

**已实测的方法学限制，必须在文档中声明**：
1. OpenAlex 同一论文有多条记录会**分裂引用数**（实测 SciCode 出现 cited_by=3 与 4 两条），须合并或取最大；
2. CrossRef 对会议论文与 arXiv 预印本覆盖差；
3. 因此**引用数只作权威性的下界参考，不作精确指标**。

**判定口径**：
- 引用数高 / 中了顶会顶刊 → 权威性成立，记录证据；
- 引用数低或查不到 → **上网确认**（官方主页、机构背书、是否被其他 benchmark 采用），并明确标注「机构权威但引用少」或「权威性不足」，不含糊过去。

### 子目标 3 · 专家参与核查（解决 owner 的质疑）

逐个核查每个 benchmark 的**题目/query 是怎么来的、有没有专家参与**，分类到：

| 类 | 含义 |
|---|---|
| A | 论文明写领域专家参与构造/审核（给出人数、轮次、改动量） |
| B | 由领域研究者团队构造但未明说「专家」字样 |
| C | 从已发表论文/真实数据反向抽取（专家性来自原论文） |
| D | 众包/标注员构造 |
| E | 程序自动生成 |
| F | 论文确实未说明 |

产出必须能回答 owner 的原问题：**「如果不是专家写的，怎么证明 query 符合专家使用习惯」——别人是怎么解决这个问题的、我方该采用哪条路径。**
