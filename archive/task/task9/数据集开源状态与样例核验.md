### 0.3 一道完整的 InfoMosaic 题，从头走到尾（论文附录 Table 10 原文）

**① agent 读到的题目（Query，原文）**：
> Identify a publicly traded technology company satisfying: (1) 总部在 Austin, Texas；(2) 2025 Q1 净利润为正、Q2 净利润为负；(3) 截至 2025-09-19 的年内股价涨幅在 10%–20% 之间、且 beta > 5.0；(4) 2025 Q2 营收在 7000 万–8000 万美元之间。这家公司的股票代码是什么？

**② agent 要自己拆成 4 个子条件，每个用一个金融工具查真值（这就是 testcase）**：

| 子条件（agent 要自己想到要查什么） | 工具查出的真值（ground_truth） |
|---|---|
| 总部在 Austin, Texas | Austin, Texas |
| Q1 2025 净利润为正、Q2 为负 | Q1 +$580,693,000；Q2 −$936,799,000 |
| 截至 2025-09-19 年内涨幅 10–20%、beta>5 | YTD +15.68%；beta 6.6067 |
| Q2 2025 营收 7000 万–8000 万美元 | $78,628,000 |

**③ 唯一同时满足 4 条的公司 = 最终答案（GT）**：股票代码 **CORZ**（Core Scientific）。

**④ 为什么这是「长程 / 大海捞针」而不是一次搜索能解的**：没有任何一次网页搜索能同时命中这 4 个约束；agent 必须**逐条调不同的金融工具查真值、再求交集**才能锁定 CORZ。这正是论文标题「多源信息搜寻」的含义。

**⑤ 这对我们意味着什么（一句话）**：把上面「Query + 4 条件 + 每条真值 + 最终答案」换成「为某适应症找一个分子 + 4 条性质约束 + 每条数据库真值 + 目标分子」，再把 4 个条件**埋进一篇长文档让 agent 去捞**，就是我们的 open 类——差别只是我们把「4 个条件」从**生成题面用**升级为**逐条判分的 checkpoint**。

## 3. 三条最有价值的观察（真实样本读出来的，非二手）

### 3.1 InfoMosaic 的 testcase 就是「证据闭包」的已发表实例

真实样本（`reference/ICLR-InfoMosaic-Bench/sample_gt_answer_5.jsonl` 第 0 条）：答案实体「峨眉山冰雪大世界」，配 3 条 `testcase` 条件（行政区划隶属 / 结构化地址 / 公交信息缺失），**每条都是一个可被工具查询验证的原子命题**。这与我们要做的「证据闭包 + 最小充分集」几乎同构——差别在于它把这些条件用作**答案的充分刻画**（题面生成用），而我们要把它们升级为**逐条判分的过程 checkpoint**。**这是"open 埋线索类可做"的最强外部证据。**

### 3.2 NewtonBench 的 GT 是可执行代码，不是数据行

真实样本（`sample_m0_gravity_laws.py`）：GT 定律直接写成 Python 函数 `F = C·m1·m2/r^1.5`，反事实改写通过改算子/指数实现，`HIDDEN_CONSTANT` 承担量纲补偿。**启示**：我们的 fixed 类真值来自数据库查询（数据行），但**发现类/受控反事实完全可以走"GT=可执行函数 + agent 只能观测输入输出"的路线**，天然免疾于记忆污染。

### 3.3 Toolathlon 的判分脚本证实了「终态执行式二元」的天花板

真实样本（`sample_eval_main.py`）：判分 = 读 agent 产出的 `record.csv` 按 0.1% 容差比对 + 检查 GCS bucket 是否存在，**全程无中间步骤分**。一个 20-turn 任务错在第 3 步和第 19 步同样得 0。**这正是我们过程 checkpoint 要填的缺口，且它来自 ICLR 2026 最新标杆。**

### 5.2 NewtonBench（GT = 可执行代码，不是数据行）

`reference/ICLR-NewtonBench/sample_m0_gravity_laws.py` 的重力域 v0 三档定律（原文）：

```python
# --- Environment Constants ---
HIDDEN_CONSTANT = 6.674e-5

# --- v0 laws ---
def _ground_truth_law_easy_v0(mass1, mass2, distance):
    """Easy law: F = C * m1 * m2 / r^1.5"""
    return (HIDDEN_CONSTANT * mass1 * mass2) / (distance ** 1.5)

def _ground_truth_law_medium_v0(mass1, mass2, distance):
    """Medium law: F = C * (m1 * m2)^2 / r^1.5"""
    return (HIDDEN_CONSTANT * (mass1 * mass2) ** 2) / (distance ** 1.5)

def _ground_truth_law_hard_v0(mass1, mass2, distance):
    """Hard law: F = C * (m1 + m2)^2 / r^1.5"""
    return (HIDDEN_CONSTANT * (mass1 + mass2) ** 2) / (distance ** 1.5)
```

**怎么读**：GT 定律直接是 Python 函数（真牛顿引力 `F=C·m1·m2/r²` 被反事实改写成 `r^1.5`、`(m1·m2)^2`、`(m1+m2)^2` 等），`HIDDEN_CONSTANT` 承担量纲补偿。**但 agent 看不到这段代码**——它看到的是下面这段 prompt，只能通过反复做实验反推这个隐藏函数。

**agent 实际读到的题面**（`reference/ICLR-NewtonBench/` 对应仓库 `modules/m0_gravity/prompts.py` 原文节选）：

```
**Experimental Apparatus:**
You have access to a device that can position two objects and measure the force acting on
the second object (mass2) by the first object (mass1). You have precise control over:
- Mass of the first object (`mass1`)
- Mass of the second object (`mass2`)
- Distance between the objects' centers (`distance`)

你提交实验请求（一次可批量给多组参数）：
<run_experiment>
[ {"mass1": ..., "mass2": ..., "distance": ...} ]
</run_experiment>
系统返回测到的力：
<experiment_output>[6.673e-05, 6.675e-04]</experiment_output>

最终你要提交你发现的定律函数：
<final_law>
def discovered_law(mass1, mass2, distance):
    C = 8e-8
    return (C * mass1 * mass2) / (distance ** 2)
</final_law>
```

**一整道题走完**：agent 读到上面题面 → 自己设计实验（如固定 mass2/distance、扫 mass1 看力怎么变）→ 从输入输出对里拟合出函数形式 → 提交 `discovered_law`。判分：把 agent 交的函数与隐藏 GT 函数做**符号等价**比对（忽略常量取值）。**启示：发现类真值可以是"可执行函数 + 只暴露输入输出"，agent 背不到，只能真推。**

```python
def validate_record_data(actual_records, expected_records, tolerance_pct=0.1):
    # 逐场景比对 agent 产出的转化率 vs 期望值，超出容差即记为 error
    for scenario in expected_scenarios & actual_scenarios:
        diff_A = abs(actual_records[scenario]['A'] - expected_records[scenario]['A'])
        if diff_A > tolerance_pct:
            validation_errors.append(f"Scenario '{scenario}' Version A: expected ...±{tolerance_pct}%, got ...")
        # B 同理
    if validation_errors:
        raise ValueError(...)   # 任一场景不达标 → 整题失败

# 主流程：先跑完成度检查，再读 agent 的 record.csv 与 groundtruth 比对(0.05% 容差)，

```

### 5.9 ScienceAgentBench（判分脚本，无单行 case）

`reference/ScienceAgentBench/` 本地存的是判分脚本（`grading.py` / `compute_scores.py` / `calculate_metrics.py`），非单行数据 case。一条题的构成（据 REPO_README 与阅读报告）：指令 + 数据集信息 + 输入数据 + **标注参考程序** + 成功判据（可执行评测程序）+ **逐题 step-by-step rubric**；产物是一个可执行程序，指标 VER(能跑)→SR(输出满足判据)→CBS(与参考程序相似)→Cost。**对我方意义：rubric 部分分 + 从论文反查任务，是我方过程分与 GT-first 的先例（但它掺了 GPT-4o judge，我方不掺）。**
