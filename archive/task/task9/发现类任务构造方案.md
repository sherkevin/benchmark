# 发现类任务构造方案：从"反向造一条 trace"到"证据闭包 + 大海捞针"

> **一句话结论**：把"反向构造一条 trace"升级为**反向构造一个证据闭包（evidence closure）**——不造路径，造"哪些原子事实凑齐了就足以推出结论"的多个**最小充分集（MSS）**；把这些原子打散埋进可控长度的合成长上下文（haystack）并配四类干扰项；判分用**四道门**（结论 / 证据覆盖 / 落地 / 抗诱导），其中"证据覆盖"是连续部分分且天然允许多解。
>
> 这样做同时解决了"反向造一条 trace"的四个致命缺陷（唯一路径、判形式不判内容、跳步可蒙、无法造干扰），并让发现类任务与 checkpoint 类任务共享同一套形式化骨架。
>
> 状态：2026-07-31 首版设计 ｜ 上游：[`task/task9/task.md`](task.md) ｜ 对标证据：[`目标会议长程benchmark横评.md`](目标会议长程benchmark横评.md)

## 1. 先说清楚"反向造一条 trace"到底哪里不够

owner 的判断是对的：现在手上只有"反向造一条 trace"，这个方案撑不起一个发现类任务。四个缺陷：

| # | 缺陷 | 具体后果 |
|---|---|---|
| D1 | **唯一正确路径** | 一条 trace 就是一条金标准序列。agent 用另一条同样正确的推理顺序到达同一结论，会被判错。ColorBench（WWW 2026）正是因为"离线静态 benchmark 只能验一条 golden path"才发明图结构（见其阅读报告 §3） |
| D2 | **判的是形式不是内容** | 与 trace 对齐 = 检查"步骤序列像不像"，而不是"知道的东西对不对"。agent 学会模仿流程即可拿分 |
| D3 | **跳步可以蒙对** | 若 agent 靠记忆/猜测直接给出结论，再倒推补一条"看起来对"的 trace，现有判分无法识别（GOAL.md §4.2 的"工具落地检查"只覆盖数值产物，不覆盖"它到底读到了哪条线索"） |
| D4 | **无法系统性造干扰** | 一条 trace 没有"错误分支"的位置。而**干扰项才是发现类任务难度的真正来源**——没有干扰，"大海捞针"退化为"关键词检索" |

**另有一个更根本的问题**：反向造 trace 隐含地把"发现"定义为"复现一条已知推理链"，这是**retrace 而非 discovery**。NewtonBench（ICLR 2026）在这一点上说得很直白：把发现建模成静态函数拟合（或既定链条复现）"背离了真实科学过程"（其阅读报告 §0）。

## 2. 新方案：证据闭包（Evidence Closure）

### 2.1 形式化

给定一个 gold 目标（分子 / 材料）`M*` 与它从科学数据库反查出的性质 `P₁..P_k`：

- **原子事实集 `A`**：把"为什么 `M*` 是答案"分解成一组**最小、可机器判定的命题**。每个原子 `a ∈ A` 形如
  `a = (subject, property, relation, value, provenance)`
  例：`(MOL_017, logD7.4, =, 2.69, admet_gt§2.2)`、`(适应症 Y, 要求 logD, ∈, [1,3], task_spec)`、`(MOL_023, hERG, =, blocker, tdc_herg)`。
  **每个原子的真值来自数据库接口返回值**（ACTION_RULES §6：接口返回值即真值）。

- **结论 `C`**：待发现的命题，形如"在给定约束下，`M*` 是（唯一 / 最优）候选"。

- **蕴含关系与最小充分集 `𝒮`**：
  ```
  𝒮 = { S ⊆ A : S ⊨ C  且  ∀a∈S, S∖{a} ⊭ C }
  ```
  即所有"凑齐了就足以推出 C、且一个都不能少"的原子子集。**我们刻意构造多个 MSS**（`|𝒮| ≥ 3`），例如：
  - `S₁` = 直接路线：查到 `M*` 的三项性质全部落在窗口内；
  - `S₂` = 排除路线：证明其余所有候选各自违反至少一项约束（鸽笼式）；
  - `S₃` = 混合路线：排除掉大部分 + 直接验证剩下两个。

  **`𝒮` 是我们造题时算出来并落盘的，不是让 agent 猜的。** 判分只问"它凑齐了哪一个 MSS"。

- **`⊨` 怎么实现**：每个 case 配一个手写的布尔判定函数（与 Toolathlon 每题一个评测脚本、ScienceAgentBench 每题一个成功判据程序同级的工程成本，见二者阅读报告）。**不用 LLM 判蕴含。**

### 2.2 这一步就解掉了 D1 与 D2

- D1（唯一路径）→ **任一 MSS 都算数**，等价推理路线不受罚；
- D2（判形式不判内容）→ **判的是"知道了哪些事实"**，与步骤顺序无关。

## 3. Haystack：把原子埋进长上下文

### 3.1 haystack 是什么

一个**程序化生成的语料包**，模拟"一堆内部研究报告 / 实验记录 / 筛选日志 / 会议纪要"，长度可调（预设四档：**10k / 50k / 200k / 1M tokens**）。

**为什么自己生成而不用真实文献**（三个理由，写论文时要主动交代）：
1. **防污染**：真实论文在 LLM 训练分布内，答案会被背出来（GOAL.md 红线 5）；
2. **可控性**：干扰项位置、线索跨度、上下文长度必须是能拧的旋钮，真实文献不可控；
3. **无版权风险**。
**但数值全部是真实数据库值**——承载文本是模板，事实是真的。这是"合成但不虚构"的关键区分，也是抵挡"synthetic toy task"批评的答复。

### 3.2 埋线索的三个技术要点

| 要点 | 做法 | 目的 |
|---|---|---|
| **跨文档分散** | 同一个 MSS 的原子必须散落在**≥3 个不同文档**、彼此相距 ≥ L/4 的位置 | 让"长"真正生效；单文档可读完即不构成长程 |
| **术语不一致（别名层）** | 同一实体在不同文档里用不同指称（内部编号 `MOL_017` / 项目代号 `CMP-A3` / 描述式"三号系列的第二个类似物"），必须做**共指消解**才能把原子连起来 | 这是最便宜也最有效的难度来源；纯关键词检索会失效 |
| **单位与口径不一致** | 同一性质在不同文档用不同单位/不同测定条件（logD vs logP、室温 vs 77K 的 Tc、PBE 带隙 vs 实验带隙） | 直接复用 `src/tasks/*.json` 里已积累的"口径陷阱"（如 PBE 系统性低估 30–50%），零额外成本 |

### 3.3 四类干扰项（难度的真正来源）

| 类 | 定义 | 抓什么失败模式 |
|---|---|---|
| **D-near**（近似原子） | 数值接近但落在阈值外（logD 3.4 vs 窗口 [1,3]） | 不做数值比较、只做语义匹配 |
| **D-super**（被修正原子） | 文档 A 给值 `v₁`，更晚的文档 B 明确修正为 `v₂` | 不看时间戳 / 不做冲突仲裁 |
| **D-decoy**（诱导性伪结论） | haystack 里存在一段**读起来就是结论**的话，指向错误分子（"综上，CMP-B7 是本轮最优候选"） | **"读到就抄"**——这是发现类任务里最重要的一类作弊 |
| **D-contra**（矛盾对） | 两条原子互斥，必须用第三条原子仲裁 | 不做一致性检查 |

**硬约束（必须自动验证）**：加入干扰项后，**不得产生新的 MSS**。即干扰原子集合 `A_d` 必须满足 `∀S ⊆ (A ∪ A_d), S ⊨ C ⟹ S ⊇ 某个原 MSS`。造题管线必须跑这个检查，否则题目会有第二个"正确答案"。

## 4. 判分：四道门 + 连续部分分

### 4.1 四道门

| 门 | 名称 | 判据 | 形态 |
|---|---|---|---|
| **G-concl** | 结论门（终态） | agent 交出的 `C` 是否正确（匿名分子 ID / 结论命题的结构化字段，走既有 `answer_schema.json`） | 二元 |
| **G-cover** | **证据覆盖门（过程，核心创新）** | `cover(τ) = max_{S∈𝒮} \|S ∩ cited(τ)\| / \|S\|` —— agent 在答卷中引用的原子对**某一个** MSS 的最大覆盖率 | **连续 ∈ [0,1]** |
| **G-ground** | 落地门（反编造） | agent 引用的每个原子，必须能被其**真实读取记录**支撑（录像层：它确实读到了 haystack 中承载该原子的片段）。未落地的引用不计入 `cited(τ)` | 逐原子二元 |
| **G-trap** | 抗诱导门 | 是否把 `D-decoy` / `D-super` 的旧值 / `D-near` 当成支撑证据 | 罚分 / 封顶 |

### 4.2 reward 表达式（沿用 ADR-0009 的 `reward ∈ [0,1]` 形态）

```python
# 伪代码：发现类任务的 reward
cited   = [a for a in answer.citations if grounded(a, trace)]        # G-ground
cover   = max(len(set(cited) & S) / len(S) for S in MSS)             # G-cover
concl   = (answer.conclusion == C_gold)                              # G-concl
n_trap  = count_trap_citations(cited, distractors)                   # G-trap

if not concl:
    # 答错封顶 0.3（沿用既有口径），但仍按覆盖率给过程分
    reward = 0.3 * cover
else:
    reward = 0.4 + 0.6 * cover          # 结论对 + 覆盖越全越高
reward *= (0.7 ** n_trap)               # 每命中一个干扰项打七折
reward = 0.0 if cover < 0.5 else reward # 覆盖不过半视为"蒙对"，不给分
```

**最后一行是本方案的灵魂**：**结论对但证据覆盖不过半 → 0 分**。这就是"猜对不算发现"的机器化表达，直接把 D3（跳步蒙对）掐死。

### 4.3 与横评暴露的四个缺口对齐

| 横评缺口 | 本方案如何吸收 |
|---|---|
| **G1 未执行到 vs 执行了但错** | 每个原子报**条件命中率**：`P(命中 a \| agent 读到了承载 a 的文档)`；分母排除"从未读到该文档"的情况（照抄 ColorBench 的 AC 条件化分母） |
| **G2 捷径过滤** | 见 §5 闸门 ①（trivial baseline 不得解掉） |
| **G3 无回归约束** | 新增 `D-super` 类干扰的对偶检查：agent 一旦引用了被修正的旧值，即使后来引用了新值，也算 `n_trap += 1`（不许"两个都引用蒙一个"） |
| **G4 开放类客观标尺** | 开放发现变体里，把 agent 候选放进已知分子性质分布报分位（照抄 MLE-bench 的排行榜分位） |

## 5. 造题管线（六步，可实现）

```
① 选 gold                ← 复用 GOAL.md 第 1 步：数据库选定 M* 并反查 P₁..P_k
② 原子化 + 枚举 MSS       ← 把"M* 为何合格"拆成命题集 A；用集合覆盖/蕴含检查枚举 𝒮（要求 |𝒮| ≥ 3）
③ 生成干扰项 + 唯一性检查  ← 四类干扰各若干；自动验证"不产生新 MSS"
④ 渲染 haystack           ← 模板 + 别名层 + 单位口径扰动；按 (L, 跨度 D) 参数分散布点
⑤ 五道闸门               ← 见下
⑥ 落盘 case JSON          ← haystack 指纹 + 原子表 + 𝒮 + 干扰标注 + reward 表达式
```

**第 ⑤ 步五道闸门（缺一不可）**

| 闸 | 检查 | 不过怎么办 |
|---|---|---|
| ①**捷径闸** | "全文正则检索 + 单次排序"的 trivial baseline 不得解出 | 淘汰或升难度（借 InfoMosaic 的 shortcut filtering） |
| ②**金标准闸** | 金标准轨迹（按某个 MSS 逐一读取）必须 reward = 1.0 | 判分器有 bug，修 |
| ③**decoy 闸** | 只读 `D-decoy` 就交卷的轨迹必须 reward = 0 | 干扰项设计失效，重造 |
| ④**空转闸** | 不读任何原子直接猜的轨迹必须 reward = 0（由 `cover < 0.5` 保证） | 覆盖阈值设置有问题 |
| ⑤**唯一性闸** | 全库穷举验证：满足题面约束的分子只有 `M*`（或已知的等价合格集 G） | 补约束收紧 |

## 6. "长"体现在哪（本任务的长程宣称）

发现类任务用与 checkpoint 类**不同的**两条"长"来源（这个差异本身是论文的一个卖点，见横评 §4 规律 2）：

| 旋钮 | 符号 | 取值 | 度量 |
|---|---|---|---|
| **上下文长度** | `L` | 10k / 50k / 200k / 1M tokens | `cover@L` 曲线（覆盖率随上下文长度的衰减） |
| **线索跨度** | `D` | MSS 原子间最大距离 / 跨文档数（≥3） | 按 D 分层的成功率 |
| **推理深度** | `H` | MSS 的蕴含层数（2/3/4 层） | **Horizon Length `H_s`**：能以概率 s 完成的推理深度（借 ICLR 2026《Illusion of Diminishing Returns》的 H_s 定义） |
| **干扰密度** | `ρ` | 干扰原子数 / 真原子数（1× / 3× / 10×） | 按 ρ 分层的 `n_trap` 均值 |

**四个旋钮 × 四档 = 一张完整的难度地形图**，这是 benchmark 论文最有说服力的实验章节（NewtonBench 靠"内在×外在复杂度"两维拿下 ICLR 2026，我们有四维）。

**另一条免费的分析章节**：《Illusion》发现的 **self-conditioning**（上下文含自己先前的错误会加剧后续犯错）在本任务上可以直接检验——agent 若在前半程引用了一个 `D-super` 旧值，后半程是否继续沿错误值推理？这是一个新颖、便宜、结论清晰的 analysis。

## 7. 两类任务，一个骨架：VIS-DAG

**checkpoint 型与发现型不是两个独立 benchmark，而是同一形式化的两个实例。** 这个统一是论文叙事的主轴（避免被审稿人说"两个东西硬拼在一起"）。

**统一骨架：Verifiable Intermediate State DAG（VIS-DAG）**
一个 DAG，节点是**可验证的中间状态**，边是**真实依赖**；每个节点配一个可执行验证器与一个 `reward ∈ [0,1]`。

| | **checkpoint 型（procedural）** | **发现型（epistemic）** |
|---|---|---|
| 节点语义 | "做了什么"——流程步骤的中间产物（候选池、性质评估结果、排序） | "知道了什么"——原子事实 |
| 边语义 | 执行依赖（不可逆、不可跳） | 蕴含依赖（凑齐才成立） |
| 等价路径 | 无依赖可换序 | 任一 MSS 均可 |
| 主"长"来源 | 交互轮数 + 依赖链深度 | 上下文长度 + 推理深度 |
| 主失败模式 | 跳步 / 逆序 / 缺节点 | 大海捞针失败 / 被 decoy 诱导 / 蒙对 |
| 验证器 | 产物数值 vs 数据库真值 | 原子引用 vs 数据库真值 + 落地记录 |

**一句话表述（可直接进 Abstract）**：我们把长程 agent 评测统一为"在可验证中间状态图上的行进"，并给出它的两个正交实例——**过程型**（做对了吗）与**认知型**（知道对了吗）。

## 8. 已知风险与应对

| # | 风险 | 应对 |
|---|---|---|
| R1 | **"合成 haystack 太假"**（审稿人必问） | ① 数值全部真实数据库值，只有承载文本是模板；② 做一个小规模**真实文献版子集**（20 题）做外部效度对照，报"合成版与真实版的模型排序一致性（Spearman ρ）"；③ 明确论证防污染与可控性的必要性 |
| R2 | **原子化与 MSS 枚举的人工成本** | 每题 2–4 小时（对标 ScienceAgentBench 的专家标注成本）。先做 40–60 题，用模板 + slots 摊薄；MSS 枚举可程序化（约束求解） |
| R3 | **`⊨` 判定函数写错 → 题目无解或多解** | 闸门 ②⑤ 强制拦截；每题必须有"金标准轨迹全过 + 全库穷举唯一性"双证 |
| R4 | **反事实性质平移破坏物理自洽** | 只对**相对比较型**约束启用平移（"logD 在窗口内"可平移；"Tc 高于 77K 液氮温度"不可，因为 77K 是物理常量）。逐性质白名单，不做全局平移 |
| R5 | **1M token 档的评测成本** | 分档报告；1M 档只跑子集（20 题）+ 只跑前沿模型；成本必须公开（照抄 AstaBench 的 cost 报告要求） |
| R6 | **与 NewtonBench 的定位冲突** | 明确区分：NewtonBench 是"从实验数据里发现**方程**"（active experimentation，≤10 轮）；我们是"从长上下文里发现**已被记录但分散的事实链**"（needle-in-haystack，L 可达 1M）。两者的"发现"对象与"长"来源都不同 |
