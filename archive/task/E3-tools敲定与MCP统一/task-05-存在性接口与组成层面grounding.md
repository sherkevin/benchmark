## 1. 存在性接口三分支（ADR-0018 §4）

### 1.1 定义域（写死，不得配置化）

| agent 提交的分子 | 返回 |
|---|---|
| ∈ B（该 case 的 B 侧） | `true` |
| ∈ A（该 case 的可见集） | `false` |
| 库外（既不在 A 也不在 B） | `false` |

owner 原话："因为我们的数据库本身就是有限的，对于 agent 预测出来的或者要查询的不存在的分子我们直接返回不存在，请另选就好了。agent 也可以查 B 中的物质，但是只能查存不存在，查不到性质。"

### 1.2 三条硬约束

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **只返单个 bool** | 不带性质、相似度、距离、"接近了"之类任何提示 |
| 2 | **"不存在"的返回体逐字节相同** | A 内与库外两种情况若文案有任何差异，agent 可由差异反推"这个分子在 A 里"，从而缩小搜索空间。**这条要有断言** |
| 3 | `max_attempts ≤ 10` | 已在 `gateway.py:744` 写死 `max(1, min(int(max_attempts), 10))`，**确认它对 open 路径真正生效**，超限记 0 分且 attempts 计入指标 |

### 1.3 返"存在" ≠ 得分

评分依据是 `∈ G_B` 且经 B 侧性质复核满足题面目标窗口。接口返 `true` 只是**停止信号**。二者混用会构成自证循环并被暴力枚举攻破（goal §2b⑤ 原文警告）。

**请检查现有实现有没有把"接口返存在"直接接到得分上。**

## 2. grounding 条件③ 改组成层面（ADR-0018 §5）

### 2.1 口径变更

owner 反问"为什么需要拓扑结构"，裁定 **不需要**。goal §2b③ 举的线索例子就是「加上一个原子 a 就会增加 xxx 性质」，这在组成层面完全可表达：

```
[16*]15[19*]25[22*]3   →  加一个 22 号  →  [16*]15[19*]25[22*]4
```

不需要知道该原子加在哪个位置。

### 2.2 三条件的新判法

| goal 条件 | 判法 |
|---|---|
| ① `cited_value` 与 trace 中真实工具返回值在容差内一致 | **不变** |
| ② `anchor ∈ A` | **不变**（改为"∈ 该 case 的可见集"，走 E1-05 的视图） |
| ③ `edit_op(anchor)` 规范化后 == 所提交分子 | **改为组成比对**：把 anchor 的元素计数按 `edit_op` 变换后，与提交的分子式做**多重集相等**判定 |

### 2.3 `edit_op` 的封闭算子集

定义为**组成算子**：`{+n 个元素 e, −n 个元素 e}`，跳数 ≤2（沿用 goal §2b④）。

**注意**：你在 task-03 里已把 dummy atom 的结构规范化做通了（`[2*][1*]` → `[1*][2*]`），那部分**不要删**——B 侧成员存的是完整匿名拓扑（`[16*][16*]([16*])[81*]...`），身份键比对仍要用它。本次只是把 **grounding 条件③** 的判法从结构改为组成。

## 7. 追加项（ADR-0018 修订 R1-②，2026-08-07）—— 组成 ↔ 实体 ID 映射层

E6 实跑裸答基线时发现：**ADR-0018 有个漏洞是我留的**。

**缺口**：ADR-0018 §5 定了 agent 提交**组成串**（dummy-atom 分子式），§4.3 定了评分依据是 `∈ G_B`，但**没定 G_B 成员用什么表示**。实际 G_B 存的是**实体 ID** ⇒ 判分器没有组成↔ID 映射 ⇒ 「命中 G_B」这句话**字面不可执行**。

**裁定：映射层归你，放判分侧、不放 gateway 侧。**

为什么不放 gateway：gateway 是给 agent 用的工具面，**它不该持有 G_B**（持有即有泄漏风险）。判分侧本来就持有 G_B 与真实身份，且按 ADR-0018 §5.3 你已具备组成多重集比对能力。

**要做**：实现 `resolve(组成串) → 实体 ID 集合`，并按下式判命中：

`hit_gb = (resolve(提交组成) ∩ G_B) ≠ ∅`

**映射必须是一对多** —— 按 ADR-0018 §8，同一组成可对应多个实体（同分异构）。一对一会漏判。

**配套**：G_B 的唯一来源是 `b_partition.json` 的 `cases[<case_id>].g_b`（E5 正在注册，见其 task-03 §9.1）。**若该 case 未注册，应报错而不是回落顶层 `g_b`** —— 回落会让命中判定静默失真，这类静默降级是本项目已多次踩过的坑。

## 8. 追加项（E5 报出，监工裁定，2026-08-07）—— `answer_schema.json` 的 operator 枚举要改

**E5 发现的不一致**：`dag_poc/answer_schema.json` 的 operator 枚举是**结构算子五件套**（`add_atom` / `remove_atom` / `replace_substituent` / `substitute_element` / `ring_closure`），而 ADR-0018 §5 已把 open 的 `edit_op` 改为**组成算子** `{+n 个元素 e, −n 个元素 e}`。

**这是我改 ADR-0018 时的连带影响没走完** —— 我改了 `edit_op` 的语义，没同步答卷 schema。

**裁定：把 operator 枚举改为组成算子。** 理由：那是 **agent 要填的字段**，而 agent 只看得到组成（A 侧无拓扑结构），让它填 `replace_substituent` 这类结构算子，它无从判断自己做的是哪一种。

**但两件事不要动**：

| 不动的 | 为什么 |

| 你在 task-03 做通的 dummy atom **结构**规范化 | B 侧成员存的是完整匿名拓扑（`[16*][16*]([16*])[81*]...`），身份键比对仍靠它 |
| fixed 类既有 case 的答卷字段 | 本次只改 open 类 `edit_op` 的 operator 枚举，别牵连 fixed |

**要点**：改的是 **agent 可见的答卷字段枚举**，不是判分侧的比对能力。两者容易混，请在 report 里写清你改了哪一层。

### 9.2 要做什么

### 9.3 一条必须守住的边界

降级键的判别力**弱于**主键——同公式 + 同 tc 分档但不同空间群的晶体会被合并成同一个键。E1 已明确：**只可用于排除，不可用于唯一性判定**。

| 用法 | 降级键能否支撑 |

| 唯一性判定（判定"这个就是 gt 且唯一"） | ❌ **不可以** |
