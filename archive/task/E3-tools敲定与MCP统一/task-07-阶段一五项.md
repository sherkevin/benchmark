## 2. 第 2、3 项 · 补全工具说明书（两项同源，合并做）

### 2.1 实测的三个坑，agent 一个都不知道

| 坑 | 实证 |
|---|---|
| **同义词** | agent 写 `molecular_weight`（库里叫 `mw`）、`solubility`（库里叫 `logS`） |
| **有些性质只能过滤不能查值** | `mw`/`logp`/`tpsa` 可入筛选条件，但 `get_property` 查值被拒（F2 裁定）——**说明书一个字没提** |
| **参数结构** | `constraints` 要 `[{property, op, threshold}]`，agent 传了字符串数组；字段叫 `props` 不叫 `properties` |

后果：`UNKNOWN_PROPERTY` **418 次**（H1 342 + H2 76）、`INVALID_ARGUMENT` **54 次**，工具成功率仅 **48.7%**。

agent 甚至试了四种拼法（`aqueous solubility` / `logS` / `log_s` / `aqueous_solubility`）——**它在猜**。

### 2.2 要做的

| # | 动作 |
|---|---|
| 1 | **9 个工具的 schema description 写清三样**：①可查性质完整清单（并标明 `mw`/`logp`/`tpsa` 只能过滤不能查值）②参数的确切结构 ③每个工具一个可直接照抄的调用示例 |
| 2 | **错误信息带可用清单**：被拒时返回"性质 X 不存在，可用的有：…" |

库内实际性质名（供参考，请以实际库为准）：`tc` / `family` / `structure_in_db` / `condition` / `logS` / `bbb` / `logD` / `half_life` / `atom_count` / `element_count`。

## 5. PR-17 · 单题工具调用上限 50 次（owner 已拍定）

| 项 | 定值 |
|---|---|
| 上限 | **50 次**，超出即截断 |
| 依据 | 现有 trace 单题工具调用中位约 40 次；50 次能把"高效解题"与"暴力穷举"分开，又不卡死正常推理 |

### 5.1 与 `k=50` 的联动关系（这是两个数一起定的原因）

`k` 提到 50 后，agent 单次能看到 50 个候选。要穷举 92,193 个实体需翻页约 1,844 次，**远超 50 次调用上限** ⇒ **暴力穷举不可行，必须靠约束过滤**。这正是我们想考的能力。

若 `k` 定太小（如 10），agent 会把调用次数全花在翻页上；若上限定太大，暴力穷举又变得可行。**两个数必须同量级。**

### 5.2 截断的行为要定清

超限时**返回明确的错误信息**（如"已达单题工具调用上限 50 次"），不要静默失败——否则 agent 不知道发生了什么，trace 里也看不出是触顶还是别的错。

**触顶率统计归 E6**（跑矩阵时报有多少道题触顶）。

**结果（任务 #77 回写）**：✅ 已交付（随 c99a23f 检查点落盘）：上限 50 超限返 CALL_LIMIT_EXCEEDED 明确错误、不静默失败；与 k=50 联动（穷举需约 1,844 次翻页，远超上限 ⇒ 暴力穷举不可行）。
