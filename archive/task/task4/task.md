# Task 4 — 开源 agent 测评 benchmark 全景调研(尤其医疗方向)

## 1. 由来

task2 已结论:上海 AI Lab 的 MolBench(单轮 final-answer QA)无法直接满足我们对"过程量 / 人类介入度量"的需求。
为给我们的自主性度量基准(`prd/AI4S_agent_autonomy_metrics.md`)广寻底料,
本任务**广泛调研**当前所有开源的 agent 能力 benchmark 的做法,挑出其中已经做过**中间状态 / 过程量度量**的样本,
评估其 data 能否复用、构造方式能否借鉴。

## 2. 调研问题(GOAL)

**核心问题(具体到可被研究的颗粒度)**

> 现在所有开源的、测评 agent 能力的 benchmark 都是怎么做的?**尤其医疗 / 生物医学方向**——
> 它们当中**有没有真正测量"中间状态 / 过程量"**(轨迹、阶段 checkpoint、工具调用序列、推理链、人类介入、子目标完成度…)
> 而不仅是最终答案打分?如果有,**哪些数据能被我们复用作为 seed,哪些构造方式值得借鉴**?

**子问题**

1. **盘点**:列举主流开源 agent benchmark(通用 + 医疗/生物医学专用),给出它们的:
   - 任务范畴 / 长程程度 / 是否多步工具调用
   - **评分对象**:最终答案 vs 过程量(明确指出哪一类)
   - 数据规模、来源、是否带 ground-truth 轨迹
   - 数据获取方式与许可
2. **聚焦"过程量度量"**:把已经做过中间状态测量的 benchmark 单列,讲清:
   - 它们怎么定义"过程量"(checkpoint? 工具调用 rubric? 推理链? 子目标?)
   - 用什么 ground truth(金轨迹 / rubric / LLM-as-judge / 工具实算)
   - 任何关于"人类介入"或"自主性"的度量(目前预期极少,但要找)
3. **可复用性评估**:对每个候选 benchmark
   - 数据可否直接拿来当我们的 seed?(license / 格式 / 真实性)
   - 构造方式能否借鉴?(seed 来源、反污染、专家标注协议、process rubric 写法)
4. **医疗方向的特殊性**:
   - 是否有针对"医疗 agent"的 benchmark(临床推理、诊断、用药、多模态病历、药物发现…)
   - 它们是否避开了"只看最终答案"陷阱

## 3. 交付物
