## 三、核心工作机制：**agent 的回答是"测 template 好不好"的指标**

这是 owner 强调的关键机制——**不是造完就完，要用 agent 的真实回答反过来打磨 template**：

```
造 template → 造 case → 让 agent 跑 → 用 case 的 check 点验收回答
                ↑                              ↓
                └──── 反过来改 template ←── 发现问题
```

**哪三类现象说明 template 需要改**：
1. **agent 回复格式不符合预期** → 说明题面的 D 交付段没写清要交什么字段；
2. **某些 checkpoint 设置有问题** → 判分点不合理、判不出区分度、或误杀正确答案；
3. **整个 DAG 不妥当** → 依赖关系连错、有跳步空间、或路径过于唯一。

**这三类现象同时是"造 case 经验"的来源，必须逐条记录**，不能只在脑子里。

### open 类额外的硬门（`goal.md` §2b ④ 可发现性质量门）

两条**均为可执行断言**，任一不成立该 case **废弃**：

1. **A 侧无替代解**：A 全域穷举须证 **A 内不存在满足全部硬约束且目标量不劣于 gt（容差 δ）的分子**。<br>⚠️ **不能写成"仅穷举 A 拿不到 gt"**——那是"gt 在 A 中不存在"的**重言式、零过滤力**。真正要卡的是"A 内已有不劣于 gt 的合格解"，那会让题目**退化成 fixed 检索**。
2. **线索可达**：case 须声明 `anchor ∈ A` + `edit_op ∈ 封闭算子集` + **跳数 ≤2** + `evidence_set`（A 内 ≥k 条同向证据），脚本校验 `edit_op(anchor)` 规范化后 **== gt**。

**另**：open 类的线索**必须完全可由 A 内数据归纳得出**，不得依赖匿名映射之外的真实世界化学知识（gt 已匿名，agent 的外部先验已失效）。
