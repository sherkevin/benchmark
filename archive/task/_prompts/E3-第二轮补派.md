## 🔴 必修 1：`no_path_violation` 的判据方向是反的——会系统性误杀更强的 agent

**位置**：`gateway.py:729` `return (max(times), prio)`

你把 evidence_time 取成"支撑该 cp 的**最晚**录像时刻"。我实跑复现：

| agent 行为 | cp1 时刻 | 判定 |
|---|---|---|
| 查文献(t=1) → 建池(t=2) → **结论后回头再查文献(t=6)** | 取 max = **6** | cp1(6) > cp2(2) → **判路径违例** ✗ |
| 同一轨迹 | 若取 min = **1** | cp1(1) < cp2(2) → 通过 ✓ |

**"结论后回访文献"是真实 ReAct 轨迹的常态。现实现把迭代式探索判成违例，等于惩罚更会做事的 agent——判分方向与设计意图相反。** 而它已真接入总闸门（`evaluate.py:490` `gate = cp_gate and pv['gate_ok']`），切到 strict 会大面积误杀。

**为什么 31 passed 没抓到**：`test_gateway_isolation.py` 的 4 个路径测试（legal / without_compare / reversed / skipped）**全是线性轨迹，零回访用例**。绿灯掩盖了 bug。

**改**：
1. evidence_time 改取 **`min(times)`**——拓扑序问的是"依赖是否在**被使用前**先建立"，不是"最后一次碰它是什么时候"；或把判据改为"**存在一对合法先后即通过**"（`∃ t_u < t_v`），而非对聚合值比大小；
2. **必须补两个用例**：`test_path_revisit_passes`（结论后回访 cp1 应通过）、`test_path_interleaved_passes`（cp2/cp3 交错多轮应通过）；
3. `_all_results.json` 在 **strict 模式重跑一遍并公布 npv 分布**。

**另**：你 report §2⑥ 用"15 实验点零差异"论证无回归——我查了，那 15 点 `path_validation_mode` **全是 compat**，且 `gate_failed_cps` 本来就全非空（已被 cp 阈值卡死），加不加 npv 都不改变结果。**零差异是巧合，不构成安全性证据**，这条推论要撤回。

## 🔴 必修 3：A/B 隔离的验收断言恒真 —— 等于没验（已由监工裁定方案，见 ADR-0015）

`b_partition.json` 的 B 成员是 `["ed:aa:add_atom:F", "bm_placeholder_001"]`——**合成字符串，与 A 的匿名 ID 天然不在同一命名空间**，而 `gateway.py:159` 还在构造期就 raise 掉 B∩A≠∅。

所以 `test_a_source_exhaustive_isolation` **证明的是"两个不相交的集合不相交"**，零信息量。而你契约 §3.5 断言 A1 要求的是"构造穷举求解器 → 枚举 A 全域 → 按**题面目标**筛选排序 → 产出提交集 S → 断言 S ∩ G_B = ∅"——**测试没做这件事**。G_B 还只有 1 个成员、无 case 维度，结构上无法支撑多题。

**裁定结果**（[ADR-0015](../../governance/adr/0015-后端库与AB隔离以E1文件系统分层为准.md)）：**以 E1 的文件系统分层规格为准**（`<tool>_A.jsonl` / `<tool>_B.jsonl` 物理分离，读取层不 open B 文件即绝对隔离），因为它强于你的"加载进内存做集合判断"（后者本质是查询过滤，一次疏漏即泄漏），且用 InChIKey + 规范化 SMILES 而非合成串。

**你要改**：
1. B 加载层改为按 E1 目录扫描 `dag_poc/data/backend/<tool>/<tool>_B.jsonl`；**A 侧读取白名单只允许 `*_A.jsonl`**；
2. `check_molecule_exists` 只读 `check_molecule_exists_B.jsonl` 的两列索引，只返单 bool；
3. **G_B 改 per-case**（带 `case_ref`），支撑多题 `hit(G_B)`；
4. **A 与 B 放进同一命名空间**——否则隔离测试永远不可能失败，也就永远不能证明隔离有效；
5. 真写穷举求解器：读 open case 的 constraints → 遍历 `search_candidates` 全部返回 → `get_property` 全性质 → 按目标窗口筛 → 输出 S → 断言 `S ∩ G_B = ∅`；
6. `b_partition.json` 可留作过渡 fixture，但须标"占位、非交付形态"，**不得作为隔离已验证的依据**。

## 🔴 必修 5：grounding 条件③退化为入参拼接，可被直接骗过

`gateway.py:560`：

```
result = canonical_structure(f'ed:{anchor}:{op}:{detail or ""}')
return {'result_id': result, 'normalized_structure': result, 'applied': True}
```

grounding 条件③是 `normalize(edit_op) == answer`。既然结果就是三个入参拼串，**agent 只要提交 `answer='ed:aa:add_atom:F'` 再在 `edit_op` 回填同样三元组，条件③自动通过，不需要任何化学推理**。而 G_B 的唯一成员恰好就是这个模式（首个锚点 + 首个算子 + 最常见取代原子 F），**在 10 次预算内可被合理猜中**。

`applied` 恒 True、`normalize_structure` 的 `valid` 只判长度（`0 < len ≤ 500`），而你契约 §1.8/§1.9 写的是"结构上不可施加返 false"/"非法结构返 false"——**两条都未实现**。

**你的代码注释是诚实的**（标了"仅作测试口径，真实结构变换由 E1 的匿名化学引擎接管"），问题在于契约文档没标"当前无鉴别力"、report 当已实现宣传。

**改**（ADR-0015 §3 已裁定归属）：
- **规范化算法归你（E3）**，须用 RDKit canonical SMILES 或 E1 约定的 InChIKey 口径，**不得字符串拼接**；**匿名映射表归 E1**，你通过约定接口取用；
- 在真实化学表示就位前，契约中把条件③标为"**占位、当前无鉴别力**"，**不得作为已实现判据宣传**；
- `applied` / `valid` 要么按契约实现，要么从 schema 删掉（**恒真字段比没有更糟**）。
