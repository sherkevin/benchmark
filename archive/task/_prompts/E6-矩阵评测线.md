## 六、必须报的两个口径（**别漏，容易出错**）

### ① fixed 类的完整打分公式（**不可只引 gate 通过分支**）

```
task_score = gate ? 0.5*process + 0.5 : min(0.3, 0.5*process)
```

其中：
- `process`：各 checkpoint 的加权 reward 之和（∈[0,1]）；
- `gate`：门控是否通过（关键 cp 全过 + 无路径违规）；
- **只引前半段会被读成"gate 挂了也 ≥0.5"，恰好抹掉惩罚机制**——这是承 ADR-0009 的设计，报告须解释它，否则读者会误读为"模型太差"。

### ② open 类的总闸门（**不是纯命中率**）

$$\text{open\_score} = \mathbb{1}[\text{hit}(G_B)] \times \mathbb{1}[\text{grounding\_pass}]$$

其中：
- $\mathbb{1}[\cdot]$：指示函数，条件成立取 1、不成立取 0；
- $\text{hit}(G_B)$：提交的推断分子属于 **B 侧合格集 $G_B$**，且经 B 侧性质复核满足题面目标窗口；
- $\text{grounding\_pass}$：产物落地验证通过（`cited_values` 与真实工具返回值一致、`anchor ∈ A`、`edit_op(anchor) == 提交分子`）；
- **乘法关系意味着两者缺一则为 0**；预算耗尽未命中也记 0。

**统计量应称"grounding 条件命中率"**，并**附报 grounding 单独通过率与平均 attempts**——只报命中率会掩盖"蒙对但无依据"的情况。
