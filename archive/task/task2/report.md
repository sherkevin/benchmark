## 一句话结论

> 🟡 **MolBench 释放的数据不能直接改造成我们要的 benchmark(它是 190 条只评最终答案的单轮 QA,无任何过程量);但它配套的 MolClaw 仓库里的"过程脚手架"值得复用,能把我们最贵的一步(专家标注)成本大幅降低。推荐"种子复用 + 脚手架 + 过程量重建"路线,专家审核制下 8–11 周可出 30–50 题 MVP 核心集。**

## 1. 背景:被评估对象 + 本任务要回答什么(读懂本报告所需)

- **我们要建的东西**:一个评测 AI4S(AI for Science,如药物/材料发现)agent 的 benchmark,核心轴是**「人类介入程度」**——衡量 agent 在尽量少的人工干预下能多大程度独立完成长程科学任务。这需要数据里带**"过程量"**:带阶段 checkpoint 的金标准轨迹、L0–L3 分级 prompt(从只给目标到给详细步骤)、分级介入卡、介入-成功率曲线等。

## 3. 关键发现(自包含)

### 3.1 MolBench 释放的数据 = 190 条单轮「prompt→最终答案」QA

| 子集 | 任务类型 | 样本数 | 字段 | 一手来源 |
|---|---|---|---|---|
| MS-1 | 理化性质过滤(Lipinski+阈值,从候选里选满足者)| 50 | `prompt, answer` | CARA(源自 ChEMBL)|
| MS-2 | 二选一亲和力比较 QA(A/B 谁 Ki 高)| 37(33 靶点)| `question, answer, target` | ACNet(实验 Ki)|
| MS-3 | 排序/虚拟筛选(对 60 个候选排序)| 25 | `questions(含candidates[60]), answer, answer_score, n_active` | CARA(→ChEMBL),pChEMBL≥6 为活性 |
| MO-edit | 官能团 add/del/sub | 39 | `gt, meta, query, subtask, task` | ChemCoTBench(seed=42 采样)|
| MO-opt | 提升 QED/LogP/溶解度 | 39 | 同上 | ChemCoTBench |
| **合计** | | **190** | | |

数据全部从**已公开的二级 benchmark**(CARA、ACNet、ChemCoTBench)按 `seed=42` 采样而来,可复现、可重采样。

### 3.2 核心判定:不能从中提取过程量(回答"能否改造")

**实证(均来自仓库源码/数据,可复核):**
- 评测器只看最终答案:输出契约要求把答案包在 `<answer>...</answer>` 里,加载器"取 query 原样、抽 `<answer>` 出"。全文件搜 `trajectory / checkpoint / intervention / tool_call` → **0 命中**。
- 数据里**没有任何过程字段**:无轨迹、无阶段 checkpoint、无求助/介入信号。
- **唯一长程、且评分维度触及过程量的 E2E 子集(3 道端到端题)根本没有开源**——只在论文里,GitHub 上无数据无配置。
- **最有说服力的一条("冒烟枪")**:MO-opt 的 prompt 原文写着 *"…improve the QED property while **following a structured intermediate optimization process**"*——明确要求中间过程——但数据**只存/只评最终一个分子 SMILES**。MolBench 连自己 prompt 里要求的过程量都丢掉了。

**为什么 MS/MO 即便补轨迹也不理想**:这些任务太短(单步工具即可解,论文消融自承 vanilla agent 在这类题上≥96%、拉不开差距);且 prompt 已写得很详细(给输入、约束、强制输出格式),相当于我们分级里的 L2/L3 档,不是 L0——直接拿来会**系统性高估自主性**。

### 3.3 真正能复用的:不是数据,是仓库的"过程脚手架"

MolBench 的数据不能用,但 MolClaw **仓库**里有一套把专家过程知识写成文本的脚手架,对我们价值很高(已全部 clone 到本地):

| 资产 | 实数 | 对我们的用法 |
|---|---|---|
| **L2 工作流模板** ⭐ | 14 个 | 当**金标准轨迹/阶段 checkpoint/介入卡的草稿骨架**(自带 "CHECKPOINT after Step N"、成功判据、失败-恢复表)|
| **L3 方法论原则** | 26 条 | 转成**过程评分 rubric**(如"必须引用工具算出的数值而非编造")|
| **L1 工具技能** | 60 个 | 定义**合法工具调用动作空间**,用于轨迹级过程打分 |
| **种子原料** | MS-2 的 33 靶点、MS-3 的 25×60 候选+pChEMBL、MO 的 78 源分子 | 直接做 seed;也可绕过 MolBench 直接去一手源(ChEMBL/ACNet/ChemCoTBench)自取 |

> **关键洞察**:MolClaw 把专家过程知识**写成了文本**。我们项目最现实的瓶颈是"领域专家时间稀缺"。复用 L2/L3 当模板,相当于白捡一份高质量草稿,让专家从"创作者"降为"审核者"——**这是性价比最高的复用点,价值高于数据集本身。**

## 4. 结论与建议

### 4.1 判定

**🟡 有条件成立**:MolBench 数据**不可直接改造**(数据模型与我们正交);但**作为"构建底座"价值高**,需在其上新建全部过程量产物。差异化上,MolBench 占"能力评测(最终成功率)",我们占"自主性/人类介入度量"——**正交,无正面竞争**。

### 4.2 还需新建什么(MolBench 完全没有的)

长程任务集、per-instance 金标准轨迹+阶段 checkpoint、L0–L3 分级 prompt、分级介入卡、中断分类协议、反事实变体+污染探针、介入-成功率曲线评测回路、负对照 agent——这 8 类全部要我们自建。

### 4.3 下一步行动

| # | 动作 | 谁来做 | 何时 | 优先级 |
|---|---|---|---|---|
| 1 | 联系作者索取未开源的 **E2E 数据/评分 rubric**(论文承诺"will be released";E2E 是唯一长程部分,拿到省最大一块工作)| 维护者 | 阶段 0(1 周)| P0 |
| 2 | 抽 MS-2/MS-3/MO 的 seed 清单(靶点/分子/打分)落库,或直接对接一手源 | 维护者 | 阶段 0 | P0 |
| 3 | 用 L2 模板 + 强模型生成 30–50 题的 L0–L3 + 金标准轨迹 + 介入卡草稿,**专家只审核** | 维护者+专家 | 阶段 1(4–6 周)| P0 |
| 4 | 重写评测器(checkpoint 插桩→偏离/求助触发→喂介入卡→续跑)+ 容器化 harness | 维护者 | 阶段 2(3–4 周)| P1 |

**总工作量**:专家审核制下约 **8–11 周**出 30–50 题 MVP 核心集。

### 4.4 落地验证(已部分跑通,诚实校准)

本路线已在后续 task3 用真实数据做了 MVP 验证,三档边界如下(诚实交底,避免把"设计"当"已证明"):
- ✅ **已证明**:收敛型 checkpoint 上的"测量仪器"(分级评分+偏离检测+分级介入回路+介入-成功率曲线)在真实数据上跑通,且对模拟 agent 强弱有区分。
- 🟡 **仅模板化**:长程开放任务的金标准轨迹/介入卡写出了模板,但**未对真实 LLM agent 实测**。
- 🔴 **真正难**:开放式 L0 设计任务的"被动偏离判定"廉价裁判前提不成立——应对是把主指标先建在收敛型 checkpoint,开放任务用"主动求助 + 过程 rubric + 公开人机一致率"过渡。
