# `case_dr_triage_01` 方差诊断：为什么判据⑥ 不成立，以及"聚合"为什么救不了

> **一句话**：方差是**组内主导**（同模型 SD 0.151 > 模型间 SD 0.086），全部落在
> **候选选择**这一个环节；真实档间差稳定在 **+0.10** 左右，**小于组内离散**，
> 所以按 `goal.md §7.5` 噪声门不能声称区分度。**这不是统计方法问题，是效应本身就小。**

## 一、要回答的问题

正式批 A（120 run）测出：强弱档差 +0.069、组内离散 0.172，噪声门不过。
上一轮的结论是"池子设计让正确/错误策略收益差太小"。**但闸门5 校准后否掉了这个归因**
——收益差其实有 0.417（真实上界 0.833 vs 线索中位 0.417），够大。
所以真正要查的是：**方差从哪来，能不能治。**

## 二、方差是组内主导，不是模型间差异

| 模型 | n | 均值 | 组内 SD | 范围 |
|---|---|---|---|---|
| DeepSeek-V3-671B | 20 | 0.525 | 0.142 | 0.33–0.83 |
| bailian-glm-5.2 | 21 | 0.444 | 0.119 | 0.17–0.67 |
| deepseek-v3.2 | 21 | 0.437 | 0.150 | 0.17–0.67 |
| qwen3-coder-plus | 20 | 0.375 | **0.223** | 0.00–0.83 |
| qwen3.5-plus | 20 | 0.242 | 0.153 | 0.00–0.50 |
| qwen3.7-max | 23 | 0.399 | 0.118 | 0.17–0.50 |

- **组内 SD 平均 = 0.151**（同一模型自己就抖这么多）
- **组间 SD = 0.086**（模型均值之间的离散）

⇒ **同一个模型自身的不稳定，比模型之间的差异还大。**

## 三、方差全落在"候选选择"这一个环节

`（测中几个合格者，召回）` 的联合分布几乎一一对应：

| 测中合格者数 | 召回 | run 数 |
|---|---|---|
| 1 | 0.167 | 19 |
| 2 | 0.333 | 30 |
| 3 | 0.500 | **53** |
| 4 | 0.667 | 10 |
| 5 | 0.833 | 3 |

（另有 6 个 run 报漏：测中了但没报进答案，如 (3, 0.0) 1 个、(4, 0.167) 1 个。）

⇒ **召回几乎完全由"8 次预算里撞中几个合格者"决定**，报答案那一步几乎不丢分。

**同一模型不同 run 选的候选重合度**（Jaccard，1 = 每次都选一样的）：

| 模型 | Jaccard |
|---|---|
| qwen3.7-max | 0.659 |
| qwen3.5-plus | 0.632 |
| bailian-glm-5.2 | 0.628 |
| deepseek-v3.2 | 0.627 |
| DeepSeek-V3-671B | 0.450 |
| qwen3-coder-plus | **0.348** |

⇒ 每次挑的分子有三到六成不一样。**预算 8 只能覆盖 20 个候选的 40%，
单次抽样的运气成分因此很大** —— 这就是方差的来源。

## 四、"多 run 聚合"是假解（实测验证过，别再试）

设想：既然单 run 抖，把同模型多次取均值再比，是否能过噪声门？实测：

| 聚合粒度 | 强档 | 弱档 | 差 | 组内离散 | 噪声门 | 置换 p |
|---|---|---|---|---|---|---|
| k=1（单 run） | 0.453 | 0.352 | +0.101 | 0.196 | 不过 | **0.0014** |
| k=3 | 0.450 | 0.363 | +0.087 | 0.128 | 不过 | 0.0212 |
| k=5 | 0.453 | 0.350 | +0.103 | 0.115 | 不过 | 0.0223 |
| k=10 | 0.458 | 0.347 | +0.111 | 0.092 | **过** | 0.0522 |
| k=20 | 0.456 | 0.353 | +0.103 | 0.083 | **过** | 0.2027 |

**两个指标在打架**：k=10 时噪声门过了，但置换 p 反而升到 0.0522。
原因是聚合**减少了样本数**（强档从 64 个降到 6 个），检验功效掉下来。

**关键观察：真实差值从 k=1 到 k=20 一直稳定在 +0.087 ~ +0.111，没有变大。**
聚合没有增加任何信息，只是把同一批数据换个算法呈现。

⇒ **"换聚合粒度让判据通过"是自欺**。若采纳，等于按结果挑口径（`实验规范 §10` 明令禁止）。

## 五、诚实的结论

1. 强弱档**确实差约 +0.10**，单 run 层面置换 p=0.0014 显著；
2. **但效应量小于组内离散**（0.10 vs 0.15），按 §7.5 噪声门**不得声称区分度成立**；
3. 这**不是统计方法问题**，是效应本身就小 —— 换算法救不了。

## 六、能治与不能治

| 方向 | 能不能治 | 理由 |
|---|---|---|
| 补样本 | ❌ | 差值不随 n 变大，只是置信区间变窄 |
| 换聚合粒度 | ❌ | 假解，见 §四；且属按结果挑口径 |
| **加大预算覆盖率** | ◐ 可能 | 预算 8/20 = 40% 是运气的来源。提到 12–15/20 能压低抽样噪声，**但同时压缩了"优先级选得好不好"的空间** —— 两者是同一个旋钮的两端，须实测取舍 |
| **缩小候选池** | ◐ 可能 | 池从 20 缩到 12、预算仍 8（覆盖率 67%），同理 |
| **让合格者更聚集在某条线索上** | ❌ 反向 | 那会让易想线索直接命中、题变白给（闸门5 第二条判据正是防这个） |
| **换一个方差本来就小的能力** | ✅ | 采样型任务天生方差大。若要单 run 稳定，得选**确定性推理**类任务（如材料侧那几道：答案由推理唯一确定，不靠抽样撞） |

## 七、下一步建议（未执行，待定）

**我倾向"换一个方差本来就小的能力"而不是继续调这道题的旋钮**，理由：

- 预算/池大小这个旋钮，两端分别是"抽样噪声大"和"优先级空间小"，
  本仓库在 `chain_01` 的 PAGE_SIZE 上已经证明过这类旋钮**两尺不可兼得**（扫过 2/3/4 都不行）；
- 而"预算受限筛选"这个能力**本质上就是采样过程**，单 run 方差是它的固有属性，不是缺陷。

若 owner 要继续救这道题，最小代价的一次实测是：**池缩到 12、预算保持 8**（覆盖率 40%→67%），
跑 3 run 探方向看组内 SD 是否明显下降。这属改设计 ⇒ 须新预登记。
