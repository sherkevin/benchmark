## 三、跑批（一次一批，跑完停）

### 唯一的批量入口

```bash
cd src/probe_headless
../../.venv/bin/python sweep_ws.py <runner脚本> <轮次数> <轮次前缀>
```

它会**先跑 preflight 四道闸门**，不过就拒绝开批（这是有意设计，别加 `--no-preflight` 绕过）。

### 现在要跑的那一批

```bash
cd src/probe_headless
../../.venv/bin/python sweep_ws.py ws_runner_dopant_open.py 5 c 2>&1 | tee /tmp/dopant_open_c.log
```

- 6 模型 × 5 轮 = **30 run**，并发 30，本机实测约 1–5 分钟
- 轮次前缀用 `c`（`a`/`b` 已占用，`b` 那批是本机全灭的空目录）
- 产物落在 `cases/materials/atom/open_basic_tools/case_sc_dopant_01/runs/`

### 为什么先跑这一批

`dopant_01·open` 当前只有 **8 个 run 且单批次**，是三个数据缺口里最小的一个，
而且 `ws_runner_dopant_open.py` 已就位、无需新写代码。

`dopant_01` 是覆盖最宽的一道题（测 4 个 infer action：#1 元素替换、#2 比例调整、
#3 掺杂、#5 趋势外推）。这批数据同时能验证尺子②（fixed 优于 open）
那个 +0.014 的差值是真的偏小，还是样本太少造成的。

## 六、判批次成败的口径（避免误判）

| 现象 | 含义 | 处置 |
|---|---|---|
| `returncode: -9` + 耗时 <15 秒 + `tool_calls: 0` | **claude 进程被杀**（本机就是这个） | 环境问题，不是能力失败，整批作废 |
| `api_error: true` | 限流/超时 | 判分时**剔除**，不计入分布 |
| `answer_exists: false` 但耗时正常（>60 秒） | agent 真的没交卷 | **计 0 分入分布**（口径 B） |
| 正常交卷 | — | 计分 |

**别把前两类当成"模型能力差"**——本项目已因混同这两类而伪造过 fixed>open 的假效应。

## 七、纪律（owner 定，务必遵守）

1. **一次只跑一批，跑完停下来讨论**，不要自主连着跑下一批。
   背景：此前连跑十余批，全项目累计 7321 run，其中大量作废。
2. **改任何参数后，先用 3 run 探方向**：`sweep_ws.py <runner> 1 probe --probe`，
   方向对了再上满批。
3. **preflight 不过不许开批**。四道闸门全是零 API 成本的离线检查。
