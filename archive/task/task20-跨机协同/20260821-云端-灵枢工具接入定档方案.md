## 一、先说清三层工具，别混

这三层此前反复被混为一谈，是"灵枢不可用 ⇒ benchmark 受阻"这个误判的根源。

| 层 | 是什么 | 谁在用 | 实测状态 |
|---|---|---|---|

## 二、25 个可用工具逐个定档

判据只有一条（[ADR-0025](../../governance/adr/0025-测推理不测搜索的科学家代入判据.md)）：

$$\text{给 tool} \iff \text{这一步是「查资料」或「做实验」}$$

其余一切——提候选、决定测什么、权衡取舍、归纳外推、排序、格式转换——都是科学家
在纸上和脑子里的活，不给 tool。

参数名以我本次 `list_tools()` 实读的 `inputSchema.required` 为准
（**不照抄文档、不猜**——此前两轮实测都因猜参数名差点误判"工具坏了"）。

## 三、一条会否掉整个 2.1 的理由：可重现性

**11 个公共库工具连的是实时外网真库。同一道题今天跑和下个月跑，返回可能不同。**

owner 已经为文献做过一次同样的裁定——《AGENT_TOOLS.md》记着：文献一律走本地 DOI 库、
**不接任何真实搜索 API**，三条理由是"无需凭证、不依赖外网、**结果可重现**（真搜索的返回
会随时间变，同一道题两次跑拿到不同文献，判分就不可重现）"。

**这条理由对另外 10 个公共库工具同样成立，只是当初只对文献说了。** 判分要可重现是本项目的
地基（规范 §6.3：判分器必须自己能跑出完整结果；§11.3：结论须在两个独立批次上复现）——
一个会漂移的数据源直接破坏这个前提。

⇒ **建议口径：灵枢公共库工具不进计分路径。** 两种正当用法：

| 用法 | 说明 |
|---|---|
| **造题期用**（推荐，立即可用） | 出题时用它们查证据、定真值、做污染体检。造题期允许人工与外部资源参与，产物冻结为确定性判据即可（goal §3 作用域说明） |
| **快照化后接入** | 把需要的子集离线抓成本地库（同 `literature_search` 的做法，构建脚本 + 增量缓存、重跑不联网），再作为工具接给 agent |

## 四、赛道风险：`predict_admet` / `crystal_predict` 不是普通工具

这两个是我方 `get_property` 的真实对应物——**我方查表，它们现场算**。

我方 `get_property` 对库外分子一律返 `NOT_FOUND`，这正是 ADR-0025 §4 押注"不进优化搜索
赛道"的地基：**可评分空间小，爬山无利可图**。一旦换成现场算的 oracle，任意分子都能打分，
**爬山搜索立刻变成有效策略**，直接把我们推回 GuacaMol / Tartarus / TDC-PMO 那条赛道——
而那条赛道上我方可评分空间小若干数量级，必输。

⇒ **接入与否需单独立 ADR，不能当作普通工具接入处理。** 本方案不建议接。

## 五、对第一组母题的污染体检（实测，不是推演）

AGENT_TOOLS.md 要求公共库工具"接入前必须逐题过一道污染体检：把题面字面丢进这些 tool，
看能不能直接撞出答案"。我对唯一已跑通的母题做了这道体检。

**探针**：用目标分子 `m05` 的 SMILES `COc1ccc(cc1)C(=O)NCCCCCCCCCCC` 调
`search_pubchem_compound`（该分子在案例里 `measurable: false`，`measure_qed` 返
`probe_unavailable`，必须靠外推）。

**结果**：**命中真实 CID 4219941**（`4-methoxy-N-undecylbenzamide`），返回

```
molecular_weight 305.5 | xlogp 5.1 | tpsa 38.3 | molecular_formula C19H31NO2
```

**判定：本次不构成泄漏，但差一步。** 逐项对账：

| QED 的 8 个描述符 | 案例是否已免费给 | PubChem 是否返回 |
|---|---|---|
| MW / ALOGP / PSA / ROTB / AROM | **是**（`pool.tsv` 五列，含目标行） | MW / XLogP / TPSA 三项 —— **与已给的重复** |
| HBA / HBD / ALERTS | **否**（真值里标为 `hidden_descriptors`，刻意不给） | **否**（该工具的 property 列表写死为 8 项，不含这三个） |

案例刻意隐藏 hba/hbd/alerts，是为了防"8 个描述符全给 ⇒ 退化成机械回归"。
PubChem 这一调没有捅破它。

**但风险是实打实的**：`HBondDonorCount` / `HBondAcceptorCount` / `RotatableBondCount`
都是 PubChem 的标准字段，**只是这个工具没去要**。也就是说，本案例的防退化设计
**依赖于一个上游工具的硬编码属性列表**——上游改一行，设计就破。

⇒ **两条应写进规范的结论**：
1. 污染体检要检的是"**它能不能补上我们刻意隐藏的那部分**"，不是"它返回了什么"。
   只看返回值会漏判——本次返回的三项全是已给的，看着无害。
2. 若将来接入任何公共库工具，**必须在我方网关层做字段白名单**（只透传题目允许的字段），
   不能依赖上游返回什么就是什么。

## 六、结论与建议

| # | 结论 | 依据 |
|---|---|---|
| 1 | **第一组不接灵枢任何工具** | 母题的观测需求只有 `measure_qed` 一项；灵枢工具面全在靶点/蛋白/晶体/临床，与考点零交集 |
| 2 | **公共库 11 个工具不进计分路径**，改作造题期工具或先快照化 | 可重现性（owner 已为文献做过同样裁定，理由同构） |
| 3 | **`predict_admet` / `crystal_predict` 需单独立 ADR** | 赛道选择，非普通接入（ADR-0025 §4） |
| 4 | **`validate_target` 若接必须加网关拦截** | 会闷声编数且不带提示，实测已出事实错误 |
| 5 | **`crystal_generate` 是便捷档的优质候选** | 有真后端，比我方自写 mock 可信；但只能进最低档，且档间差值须如实报告 |
| 6 | **Diamond 那 9 个维持现状** | 当前无 case 用到；要接需 owner 提供配置（含密钥密文，不宜在会话里经手）或云端装 `mw` |

**灵枢的真正价值不在第一组，在扩题**：当题型走到需要真实靶点、真实文献证据、
真实晶体结构时（第二组/第三组母题），它是现成的、有真后端的能力来源，
**比我方自己写 mock 更可信**。建议按第三节的"快照化后接入"路径逐步纳入。

## 八、复现命令

```bash
# 工具面与真实参数名（调任何灵枢工具前必做这一步）
cd /mnt/ai4sci_develop_fast/jingwu/lingshu-mcp
/mnt/ai4sci_develop_fast/jingwu/benchmark/.venv/bin/python -c "
import sys, asyncio; sys.path.insert(0,'.')
import server
for t in asyncio.run(server.mcp.list_tools()):
    print(t.name, (t.inputSchema or {}).get('required'))"
```

**纪律（两次踩过）**：调任何 MCP 工具前先 `list_tools()` 读 `inputSchema.required`。
灵枢的真实参数名与直觉差别极大——`query` 在不同工具里叫 `name_or_smiles` /
`condition_or_query` / `query_text` / `target_or_gene` / `gene_symbol` / `gene_or_accession`，
各不相同；且 `_tool_boundary` 会把 `TypeError` 兜成 `INTERNAL_ERROR`，更容易误判成"工具坏了"。
