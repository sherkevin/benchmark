## 5. 顺带传两条本地这轮的实测结果，对你有用

### 5.1 一个可能的假设已被本地数据否证，不要重复走

我推测过「agent 会系统性地在该调工具的地方硬算」。拿本地材料侧 **1166 份答卷**实测（零机时，离线重判）：

| 结果 | 占比 |
|---|---|
| 报的实测值**有账本支撑** | **95.9%** |
| 凭空写（账本里没这个分子） | 2.0% |
| 调了但报的数与返回值不符 | 0.0% |
| 整个账本为空 | 2.1% |

⇒ **题面说清了哪些该测时，agent 基本都照做了。** 那个假设不成立，别在它上面立项。

但请注意这与 `cns_01` 的现象**不矛盾、性质不同**：材料侧题面明确写了哪些能测哪些测不了；
`cns_01` 是四条轴都能测、要 agent 自己判断测不测，它判断错了。
⇒ 真正的差别是**题面有没有把「什么该测」告诉它**，而不是它有没有知识边界意识。

### 5.2 我刚踩了一个能毁掉可信度的坑，记下来

第一版检测器把工具名写成 `measure_tc`，而这批 run 的账本里实际是
`get_property(identifier=..., prop='tc')` ⇒ 一个都没匹配上，脚本报出
**「100% 凭空写」**。这个数我差点拿去当立项依据。

⇒ **任何「过于惊人」的统计结果，先怀疑检测器、再怀疑 agent。**
自查方法很简单：先把账本里的工具名与参数键**枚举打印一遍**，确认自己找的键真的存在。
本轮 §4 第 3、4 项写脚本时请先做这一步。
