## 1. 关键区分：口径变 ≠ 要重跑

判分器契约是"**只吃 `answer.json` + `tool_calls.jsonl` 两个路径**"（`judge_contract.py`）。
由此：

| 变了什么 | 处置 |
|---|---|
| **判分口径/给分公式**（如 cp3/cp4 移出总分、口径 B 失败分类） | **只需重判**，不必重跑——旧 run 的两个文件仍在 |
| **配置**（题面文字、工具语义、预算、真值 `ground_truth.json`） | **必须重跑**——agent 面对的题变了，旧 run 答的是另一道题 |
| **隔离机制**（`--allowedTools` 是否含 `Read`） | **必须重跑**——旧 run 可能读到过真值，数据不可信 |

这条区分是本评估的判据基础。

### 2.2 隔离机制：一个更严重的问题

`8eb52af` 对 `ws_runner_dopant.py` 的 diff 里有这一行被删除：

```
- ALLOW = "Read,Write,Edit,Grep,mcp__matlab__measure_tc"
+ MCP_TOOLS = ["mcp__matlab__measure_tc"]
+ # 给 Read 免批准就等于放开任意路径读取，实测会读到 ground_truth.json。
```

即 **`8eb52af` 之前，`Read` 在 `--allowedTools` 里**。而实验规范 §3 明确写着：

> 把 `Read` 放进 `--allowedTools` → Read 任何路径都免批准，**实测 agent 成功读到 `ground_truth.json`**

**所以 `8eb52af`（2026-08-19）之前产生的 run，全部存在真值泄漏敞口。**
文档里那 637 个 claude code run 都早于该 commit（它们是 08-19 那份分数分布文档的数据源）。
**这不是"可能有问题"，而是隔离地基在那之前是漏的**——规范 §0 铁律 2 正是为此要求
"开跑前先过 `verify_isolation.py`，19 项全过才能跑正式实验"。

## 3. 判分器口径变动（只影响重判，不影响是否重跑）

`8eb52af` 之后 dopant judge 又改了两次：
- `f863378`：cp3/cp4 移出总分（`total=(cp1+cp2)/2`）——**给分公式变更**
- `a53526a`：口径 B 落地（我改的，只动失败分类，不动给分公式）

所以文档里 dopant fixed 的 0.778 是**旧公式**下的数字，与现公式不可直接比较，
但这一项**只需重判**即可对齐。

- 不是"项目没跑过实验"（跑过 7000+，claude code 637+），

## 6. 对排期的影响

需重跑 8 题 × 6 模型 × 5 轮 = **240 run**（第二独立批复现再 240）。
按冒烟实测均耗 478s/run、并发 30 估算，单批约 1–2 小时，机时不是瓶颈。
ICLR 摘要剩 **29 天**、正文 **36 天**；真正的日历瓶颈仍是
**专家审题（U-1/U-6，lead time 8–10 天，只有 owner 能启动）**。
