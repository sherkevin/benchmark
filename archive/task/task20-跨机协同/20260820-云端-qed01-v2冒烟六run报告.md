## 一、中间值关达到了设计目的

v1 的第二关六个 run 全 1.0、白送 0.3；v2 换成"联合约束选型"后，cp_conditions
在真实 run 上取到了 1.0 / 0.5 / 0.0 三档，**不再免费**。

fixed 侧三个模型都做对了预期动作——**先测自己系列、再跨系列找先导**。以 qwen3.7-max 为例，
账本清清楚楚：

```
measure m15 m24 m28 m17 m22   ← 自己系列（甲氧基）5 个，用于外推
measure m09 → 0.5826          ← 硝基 n=2，不过 0.60 门
measure m02 → 0.6046          ← 硝基 n=3，过门 → 选它
measure m12 m14 m01 m33 m27   ← 继续验证其它候选都不合格
```

这正是枚举表 **#28 类比迁移**：把"峰在 n=3"从自己系列迁到硝基系列，找到唯一合法解。
三个模型 fixed 侧都选中 m02、三条件全过（c123=111）。

## 三、open 侧暴露的真实设计取舍（要 owner 定）

open 侧三个模型选型全错，但**错法不同、且都不是"没读懂题"**：

| 模型 | 选了谁 | 为什么错 | 是不是理解了约束 |
|---|---|---|---|
| deepseek | m09（硝基 n=2） | QED=0.5826 差一点没过 0.60 门；psa、系列都对 | 理解了，差在没测准/没换更长链 |
| qwen3.5-plus | 没填 | 预算烧在搜索上（14 次搜 + 5 次测、7 次撞到预算耗尽），放弃 Job 2 | 理解了，但没资源做 |
| qwen3.7-max | m24（自己系列的峰） | 明知违反 psa 和"非目标系列"两条，notes 里写"best available"硬选 | **完全理解，但找不到别的系列** |

qwen3.7-max 的 notes 是关键证据（这就是规范 §6.0 说的"诊断必须看思考过程"）：
它外推做得最好（0.889），也**明确写下** m24 违反两条约束，但它**搜不到硝基系列**——
账本显示它试了 `S(=O)(=O)N`、`c1ccncc1`、`C(=O)O`、`CC(=O)N` 四个子串，全部返回 0 命中，
最后预算耗尽（连找到 m02 后想测都 budget_exhausted 了）。

**根因**：fixed 侧把整张 `pool.tsv`（含所有 SMILES）直接给了，谁都能一眼筛出候选；
open 侧要靠 `search_pool` 用子串发现，而**"猜中硝基系列的 SMILES 片段"本身成了一道
隐藏关卡**。硝基片段是 `O=[N+]([O-])`，模型不会去猜这种写法。于是 open 的 Job 2 从
"会不会做联合约束筛选"退化成了"会不会猜搜索字符串"——**这偏离了我们要测的能力。**

三个处置选项，我倾向 B：

- **A. 接受为 open 的正当难度**。理由：open 本就是"自己发现"，发现不到是能力的一部分。
  代价：Job 2 的分数掺进了"猜字符串"的运气，判据⑤（答案不可背）受污染。
- **B. 给一个不泄答案的发现原语**（推荐）。加一个 `list_series()` 或让 `search_pool`
  支持"按芳香核 `c1ccccc1` 搜返回全部候选" —— 只降低"发现"成本，不改"筛选"这个考点。
  agent 仍要自己实测 QED、自己判 psa 与系列。
- **C. open 侧 Job 2 降为记录关**，只用 Job 1（外推）算分。代价：open 只剩一个考点，
  与 fixed 的可比维度变窄。

**注意这不影响 fixed 侧**——fixed 的题目和判分都工作正常，可以定稿。open 侧等 owner
定了发现原语再重跑。
