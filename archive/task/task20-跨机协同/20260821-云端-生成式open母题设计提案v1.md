> [ADR-0027](../../governance/adr/0027-预测型题不配通用oracle可测集必须闭合.md)（为什么必须换成"报一个分子"）。
> owner 已定：**替换现 qed01·open（旧批留档不干扰）+ 收紧约束 + 先推设计**。
> 本文给一个**用 rdkit 实算过、两道质量门都能过**的具体实例，供 owner 审方向。

## 1. 任务一句话

> A 侧可测：单环苯甲酰胺家族（多种对位取代基 × 多个链长）。你要**推理出一个 A 中不存在
> 的新分子**，使它 **QED ≥ 0.85**（A 内任何分子都达不到）且满足收紧后的约束。你不知道自己
> 造的分子是否真实存在，只能用 `check_molecule_exists` 验（**只回 yes/no，不回任何性质**）；
> 命中即结束，未命中据线索再推，预算 ≤10 次。

**它是生成式的**：答案是"报出一个分子"，不是"预测一个数值"⇒ 无 ADR-0027 的近似物泄漏。

## 2. A / B 怎么切（实算过的数字）

**A 侧可测（agent 能 `measure_qed`）= 单环苯甲酰胺 8 个头部 × 链长 n=2..8。**
实测 QED（n=3 处最高）：

| 头部 | n=3 QED | A 内该系列峰 |
|---|---|---|
| methoxy / cyano / carboxy | 0.792 / 0.784 / 0.786 | **A 的天花板 ≈ 0.792** |
| methyl / fluoro / hydroxy / unsub | 0.72–0.76 | |
| **nitro** | 0.605 | 被结构警报压低（**陷阱兼线索**） |

**A 内全域最高 QED = 0.792 < 0.85** ⇒ **质量门④ 第一条（A 内无不劣于 gt 的解）成立**。

**B 侧合格集 `G_B`（QED ≥ 0.85，都在 n=3，都由"给苯甲酰胺加一个环"得到）：**

| gt 候选（n=3） | QED | 由 A 锚点的编辑 |
|---|---|---|
| diphenyl-ether | 0.886 | unsub + 苯氧基 |
| biphenyl | 0.869 | unsub + 苯基 |
| phenyl-cyclohexyl | 0.857 | unsub + 环己基 |
| quinoline | 0.852 | unsub 芳环并环 |
| naphthyl | 0.834（**擦边，可能不纳入 G_B**） | unsub 并环 |

`G_B` 是**集合**（gt + 同等合格者），符合 goal §2b「不是命中 B 中任意分子」。

## 3. 线索可达性（质量门④ 第二条）

- **anchor ∈ A**：unsubstituted benzamide n=3（`c1ccc(cc1)C(=O)NCCC`，QED 0.723，可测）。
- **edit_op ∈ 封闭算子集**：`attach_aryl_ring`（给苯环挂一个芳环/脂环）+ `set_chain_len=3`。
- **跳数 ≤2**：加环（1） + 定链长到峰值（1）= 2 跳。规范化后 `edit_op(anchor) == gt`。
- **evidence_set（A 内 ≥k 条同向证据，均可查）**：
  1. **峰在 n=3**：8 个头部系列**每一条**都在 n=3 见顶（8 条同向样本，纯由 A 归纳得出）；
  2. **加大共轭/环体系抬 QED**：A 内 unsub(0.723) < methoxy(0.792)，示范"苯环上挂东西能抬分"。

⇒ agent 的正确推理链：**"A 里最高才 0.79、都卡在单环；峰在 n=3；要过 0.85 得在 n=3 上再加一个环"** → 生成 biphenyl/diphenylether n=3 → 存在性验证 → 命中。这条链**完全由 A 内数据 + 收敛的编辑算子支撑**，不需背任何具体药物。

## 4. 收紧约束（owner 指令）——把"靠记忆报个药"这条路堵死

旧约束 QED≥0.60 & psa≥40 太松（大量已知药满足）。生成式下把**目标 spec 收紧**为三条联合：

| 收紧后的约束 | 作用 | 实测依据 |
|---|---|---|
| **QED ≥ 0.85** | A 内全灭（峰 0.792）⇒ 必须生成、不能检索 | A 天花板 0.792 |
| **链长必须在峰位（n=3）** | 加了环但用长链也过不了 0.85（biphenyl n=8 会掉下来）⇒ 逼出"加环"与"取峰长"两跳都做 | 需补算 biphenyl 各链长确认 |
| **无结构警报（ALERTS=0）** | 堵掉"随手报个大共轭稠环"（很多高 QED 稠环带警报）；也呼应 A 内 nitro 被压的线索 | 需逐个验 G_B 成员 ALERTS |

**为什么这能堵记忆**：满足"QED≥0.85 + n=3 + 无警报 + 属苯甲酰胺家族"的分子不是任何知名药，
是一个必须由线索拼出来的特定同系物。**裸答基线 k≥10 命中 G_B 即判污染并废弃**（goal §2b）——
这条必须在落地时实跑验证，是否真的背不出来，用数据说话、不靠我断言。

## 5. 判分（goal §2b 唯一口径，不改写）

$$\text{open\_score}=\mathbb{1}[\text{hit}(G_B)]\times\mathbb{1}[\text{grounding\_pass}]$$

- `hit(G_B)`：提交分子规范化后 ∈ `G_B`，且经 B 侧 rdkit 复核 QED≥0.85、n=3、ALERTS=0；
- `grounding_pass`：答卷三字段 `anchor_molecules[]`(∈A) / `cited_values[{mol,prop,value}]` /
  `edit_op`，每条 cited_value 与账本真实返回值容差内一致、`edit_op(anchor)` 规范化后 == 提交分子；
- 存在性接口**只回 bool**，且**对 A 内分子必须回 false**（命门，goal §2b ⑤）。

## 6. 一个必须请 owner 拍板的结构性后果

替换 open 后，**"第一组 = 一道母题 × 六配置"这个说法要变**——因为：

- fixed 侧仍是**预测+选型**任务（评过程，判据是 cp_extrap 等）；
- open 侧变成**生成式发现**任务（评终态，判据是 `open_score`）；
- 两者 gt 不同、判分器不同 ⇒ **它们是两类任务（goal §1.5），不是同一道题的两个可见性配置。**

**这不是坏事，反而更贴 goal**：goal §1.5 本来就把题集分两类、§6 步6 明说两类分数"不可加不可平均、分列两栏"。工具供给轴（Δ_tool）的干净消融**在每一类内部各做一遍**：

| | basic | some | enough |
|---|---|---|---|
| **fixed（预测+选型）** | ✅ 0.503 | ✅ 0.847 | ✅ 0.894（已跑完） |
| **open（生成式发现）** | 待造 | 由 basic 失败模式导出 | 由 some 失败模式导出 |

即第一组从"2 可见性 × 3 工具的六格"改述为**"两类任务，各一条 3 档工具梯子"**。
**这需要 owner 认可，因为它动的是第一组的定义**——我不自行改（T-197 教训）。

## 7. 建议的落地顺序（owner 认方向后）

1. **先立 ADR-0027**（本设计的前提）+ owner 认可 §6 的定义改述；
2. 造 B 侧与 `G_B`：扩 `gen_qed_case_gt.py` 生成 A 家族 + B 合格集 + 诱饵，逐个验 QED/ALERTS；
3. 跑**两道质量门**（A 无更优解——已初验；线索可达——脚本校验 `edit_op(anchor)==gt`）
   + **裸答基线 k≥10**（命中即废，用数据定这道题成不成立）；
4. 写 `ws_mcp_server_qed01gen*.py`（含**结构化定义域**的 `check_molecule_exists`：按骨架族判、
   A 内返 false）+ runner + judge（open_score，复用现有隔离与口径 B）；
5. **旧 qed01·open 三格 runs 移入 `runs_discriminative_deprecated/` 并写 README 留档**
   （owner 要求"结果保存、不干扰"），不删；
6. preflight + verify_isolation 19/19 + `--probe` 冒烟核 §2b 各断言；
7. 预登记后上满批。
