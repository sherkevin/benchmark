## 二、每一档的工具都是"由错误导出"的，不是拍脑袋

这是 ADR-0026 §3 的核心要求，本轮完整走了两遍：

| 档 | 上一档的实测失败模式 | 据此配的工具 | 结果 |
|---|---|---|---|
| **some** | basic 档 **76%** 外推偏高（该用曲线时用了直线）；**21%** 没核对免费门槛 | `fit_trend`、`screen_candidates` | cp_extrap 0.300→0.621；违反率 21%→4% |
| **enough** | some 档 **33%** 把 SMILES 里的碳数数错（19 个低分 run 里 18 个把链长填成 12 或 13，真值是 11） | `describe_structure` | cp_extrap 0.621→0.910 |

## 三、`cp_extrap` 的双峰被逐档消解

低分簇（cp_extrap < 0.3）的个数：

| | basic | some | enough |
|---|---|---|---|
| fixed | 57 低 / 4 高 | 11 低 / 17 高 | **0 低 / 23 高** |
| open | 23 低 / 0 高 | 8 低 / 20 高 | **0 低 / 19 高** |

预登记 E1 命中：**低分簇完全消失**。这条曲线说明这道题的难度是**由三层能力叠成的**，
每层都能被对应的工具单独剥掉：

1. **结构读写**（数清链长）——enough 档剥掉，值 +0.09～0.15
2. **趋势建模**（该用曲线还是直线）——some 档剥掉，值 +0.25
3. **剩下的**（选对系列、约束核对、实测验证）——三档都没给，是这道题最后守住的部分

## 四、一个中途修掉的结构性错误

open 格曾被改成**另一道题**（纯外推、无先导选型），违反"同题只换配置"。根因是发现原语
选错：`search_pool(query,page)` 按子串搜索实际考的是"会不会猜中结构片段"。已改为
`list_pool(page)` 纯分页枚举，预算按公式 12→17。修完后 **open·basic 0.530 与
fixed·basic 0.529 几乎持平**，证明两侧确实是同一道题了。

## 五、口径守住了

- 六格**同题、同真值、同判据**：some/enough 的判分器一行逻辑没新写，整套转发 basic 档
  fixed 的 `judge.py`，并带 golden + lead_conditions 双重同源断言。
- 预算只在 open 侧因枚举成本按公式加（12→17），**档间预算不变**——变量只有工具供给。
- 便捷工具**都不发放 QED、不扣预算**，grounding 与账本证据规则全程不变。
- 统计一律走 `batch_rows`，限流按口径 B 剔除。

## 六、剩余尾巴（如实标注）

- enough 档 n 偏小（fixed 23 / open 20），本轮限流较重；若要更紧的置信区间需补批。
- open·enough 最后 1 个 run 仍挂着（glm 已知坑），落地后 glob 会自动纳入。
- 中段模型排序在各档间仍会换位，按 §11.2 只报强/弱趋势。
