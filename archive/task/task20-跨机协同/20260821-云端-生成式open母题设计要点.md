# 生成式 open 母题 · 设计要点（讨论稿，交 owner 定方向后再动代码）

> **一句话**：现在的 `qed01·open` 是"给 33 个候选让 agent 筛"——判别式，和 fixed 没区别，
> 判据② 三档全平。Owner 提出改成"agent 自己想分子、猜一个测一个"。这个方向对，但**不能
> 用在预测数值的题上**（[ADR-0027](../../governance/adr/0027-预测型题不配通用oracle可测集必须闭合.md)：
> 近似物一次调用即泄答案）。生成式发现需要一道**答案形态是"报出一个分子"**的新母题，
> 而这套机制 `goal.md §2b` 已经写全了——本文不重新发明，只把它对到药物 QED 场景上。

---

## 1. 为什么现在的 open 不成立（已实测，非推演）

| 证据 | 数值 |
|---|---|
| 判据② 三档差值 | −0.014 / +0.037 / +0.007，置换 p 全在 0.6–0.9 |
| open·basic 翻页行为 | 23/23 个 run 全翻满 9 页；翻页不是取舍，是人人照付的固定过路费 |
| 测量饱和点 | open 测 8 次即够（Job1 要 5 个同系物 + Job2 验证几个），fixed 测 12 次也不多拿分 |

⇒ `list_pool` 拿一次就把 33 个候选全交出来，任务从"生成式发现"塌成"判别式筛选"。
Owner 的诊断原话：**"一个生成式问题只用了一次工具就变为了判别式问题。"**

## 2. 为什么"删 list_pool + measure_qed 收任意分子"这条路在本题走不通

见 ADR-0027 §2 的实测表：QED 是粗描述符的函数，目标的**位置异构体给出完全相同的值**、
6/10 个近似物柯西分 ≥0.8。agent 花**一次**调用测一个近似物就拿到精确答案，外推被绕过。
**预算防不住一次调用。** 这不是参数问题，是"预测数值"与"通用 oracle"在原理上不兼容。

## 3. 正确形态：答案是"一个分子"，不是"一个数值"

把答案从**数值**换成**分子**，近似物泄漏就消失了——因为命中判定是**精确的集合成员判断**
（∈ 合格集 `G_B`），不是粗函数。这正是 `goal.md §2b` 定义的 open 发现探索类。

### 3.1 一句话任务形态（药物 QED 场景实例）

> 给定一个已知的先导分子及其若干性质线索（都在 agent 可查的 A 侧），
> **推理出一个 A 中不存在的新分子**，使它在某个目标性质上优于先导（如 QED 更高 / 亲脂性落回
> 最优区）。agent 不知道它猜的分子是否存在于答案库，只能通过**存在性接口**验证：
> 命中即结束，未命中则据线索重新推理，预算 ≤10 次。

### 3.2 三条硬约束（goal §1.5，缺一不可）

| 约束 | 在本场景怎么落 |
|---|---|
| **线索性联系** | 新分子必须能从 A 侧线索推导（如"这条同系列 n=3 处 QED 见顶、目标是把某支链换成环以降 ROTB"），保证有据可依、不是瞎猜 |
| **存在性查询接口** | `check_molecule_exists(smiles)` **只返单个 bool**，不带任何性质/相似度/距离 |
| **B 不可见** | agent 全程看不到 B 的内容，只能通过存在性接口验证 |

### 3.3 判分（goal §2b 唯一口径，不得改写）

$$\text{open\_score} = \mathbb{1}[\text{hit}(G_B)] \times \mathbb{1}[\text{grounding\_pass}]$$

- `hit(G_B)`：提交分子 ∈ 落盘的 B 侧合格集（gt + 同等合格者），且经 B 侧性质复核满足目标窗口。
  **不是"命中 B 中任意分子"**——否则循环猜常见分子即可刷分。
- `grounding_pass`：答卷三字段 `anchor_molecules[]`（∈A）/ `cited_values[{mol,prop,value}]` /
  `edit_op`，且每条 cited_value 与账本真实返回值在容差内一致、`edit_op(anchor)` 规范化后 == 提交分子。
- 乘法：两者缺一则 0；预算耗尽未命中记 0。

### 3.4 存在性接口的语义（goal §2b ⑤，写死，最易搞错）

| 概念 | 定义 |
|---|---|
| 停止信号 | 返"存在" → agent 可结束本轮 |
| **定义域（命门）** | 返值严格等价于 `m ∈ B`：**A 内分子与库外分子一律返"不存在"**。若对 A 内分子返"存在"，agent 直接交 A 中分子即过，**整个设计崩塌**（ADR-0018 / goal §7.1 已实测守住 30/30） |
| 评分依据 | 是否 ∈ `G_B`，**与存在性接口分离**——切勿把"接口返存在"直接当得分，那会构成自证循环、被暴力枚举攻破 |
| 尝试预算 | `max_attempts ≤ 10`，超限记 0，attempts 计入指标 |

## 4. 与 ADR-0027 不变量的一致性检查

ADR-0027 要求"agent 无法通过测可测集内任一实体直接得到 target 的答案"。
生成式 open **天然满足**：答案是"命中 `G_B`"这个布尔事件，存在性接口只返 bool、不返性质，
**没有任何数值可被近似物查表绕过**。这也是它比预测型题更适合生成式发现的根本原因。

## 5. 能复用什么（别重新发明）

| 已有资产 | 位置 | 状态 |
|---|---|---|
| `check_molecule_exists` 契约工具 | `dag_poc/mcp_mock_server/mock_server.py` | 9/9 实测可用；返 `{exists, attempt, attempts_remaining}` |

| `edit_molecule` / `normalize_structure` | 灵枢侧或契约层 | 生成 + 规范化，实测可用 |
| rdkit QED oracle | `tools/gen_qed_case_gt.py` | 造 B 侧真值与合格集用 |
| workspace 隔离 + 判分口径 B | `src/probe_headless/` | 现成 |

⚠️ **但第一组六格实际走的是 `ws_mcp_server_*.py`（stdio 直启），不是 dag_poc 契约层。**
生成式 open 若要进第一组的 workspace 范式，`check_molecule_exists` 需按 `ws_mcp_server_*`
的形态重写一个（就像 `measure_qed` 那样），不能直接调契约层。这是主要工程量所在。

## 6. 要 owner 定的三件事

1. **范围**：生成式 open 是**新母题**（第二组套卷的一格），还是**替换**现 `qed01·open`？
   我建议新母题——现六格 fixed 侧数据有效，且"闭候选集 open 判据②不成立"本身是个可写的
   负面结论（ADR-0027 §6），不必抹掉。
2. **合格集 `G_B` 的构造**：从哪个骨架/性质窗口反查？这决定题目难度与"线索可达性"，
   是造题的核心，需先定方向再落 `gen_*_gt.py`。
3. **Job2（联合约束选先导）留不留**：生成式下"报一个满足 QED≥0.6 且 psa≥40 的分子"会被
   大量已知药物满足、靠记忆即可 ⇒ 要么收紧约束到记忆不够用，要么 open 只做纯发现、
   把联合约束选型留在 fixed 侧（两类本就分列、不做尺子②，goal §6 步6）。
