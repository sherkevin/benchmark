## 0. 先纠正我上一轮报错的一件事

我上一轮登记 PR-53 说"**H2 参数被套三层壳，99% 的调用中招，是 bug**"。

**这个判断是错的，向你说明清楚**：

| | 实际 |
|---|---|
| CLI 发出的 | `{"arguments": "{真参数}", "session_key": ""}` —— **2 层，完全合规** |
| 为什么是 2 层 | 我们 MCP server 的工具签名就是 `def literature_search(arguments: str = "{}", session_key: str = "")`，**CLI 是照 schema 传的** |
| trace 里记的 | **3 层** |

**多的第 3 层是 adapter 记 trace 时加的，实际调用没问题。** 那 54 次 `INVALID_ARGUMENT` 的真实原因是 agent 不知道参数格式（已归 E3-07 补说明书解决），跟套壳无关。

**所以这条从"最高优先的 bug"降级为"日志冗余清理"。** 抱歉让你按错的定性看了一轮。

| 3 | **补一条 adapter 对账断言（R7）**：转换后的 `arguments` 嵌套深度 ≤1 |

### 1.1 为什么要加 R7

你 task-05 的 adapter 对账做了 10 项（R1 事件数相等、R2 id 无重复、R3 前缀剥除、R4 arguments 深比较、R5 tool_result 配对、R6 result），**全部通过**——但**没有一项校验嵌套深度**，所以这个冗余从检查里漏过去了。

R4 是"arguments 深比较全等"，它比的是转换前后一致，**而转换前后都是包裹形态时，深比较会通过**。加 R7 才能拦住。
