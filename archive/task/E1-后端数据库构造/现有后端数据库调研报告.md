## §0 核心结论（先看这三句）

1. **61 家中确实自带"后端库"的重点候选有 11 家**（tau-bench、TravelPlanner、TheAgentCompany、ToolBench、TDC_PMO、SciAgentArena、MatTools、PoseBusters/PoseBench、Tartarus、DiscoveryWorld；含仓库快照/服务态则共 15 行，见 §1 汇总），但**没有一家的库是"双领域（药物+材料）× 匿名分层 × 带 provenance"的查询后端**——全部绑定各自单一领域与任务形态，拿来用的改造代价（匿名化、A/B 分层、provenance 三元组、字段对齐到 9 工具契约）不低于自建。
2. **总体决策：退回自建，但四类成品资产直接借用**——①TDC ADMET 成品数据（get_property 药物线真值源，22 数据集、NeurIPS D&B 2021 背书）；②Zinc-250K 约 25 万分子（search_candidates 分子池源）；③tau-bench 的"dict 内存库 + 终态比对"工程范式（后端加载与 check_molecule_exists 的 B 库比对架构）；④PoseBusters 规则检查套件（评分侧结构合理性门，非 tool 后端）。已落盘的 3DSC（9.1 MB）/AqSolDB（4.1 MB）/PubChem 身份档（28 KB）继续作材料线与身份核验基座。
3. **"判分零联网 + 冻结快照"是领域标准做法而非妥协**：GuacaMol、SciAgentArena、MatTools、tau-bench、TravelPlanner、PoseBench、TDC_PMO、MADE 八家先例（§5.2），其中 SciAgentArena 明写 `AGENT4S_NO_NETWORK=1`、MADE 明写数据是 Materials Project 快照且过滤在 Environment 层做——后者正是我方 A/B 源物理分层的直接先例。

### 2.1 tau-bench——dict 内存库 + 终态比对（我方后端的工程模板）

- **①**：有。`tau_bench/envs/{retail,airline}/data/*.json` 在环境初始化时全量载入 Python dict，tools 是架在 dict 上的闭包函数（读操作查询、写操作改库）；判分 = 任务结束后比对**实际库终态**与 ground-truth actions 推出的目标终态。
- **②**：无公开数据集——官方 README《Mock Data Generation》明写：schema 人工设计，种子字段 GPT 生成，数值字段程序生成。
- **③**：数据权威性为零（合成）；机制权威性高（ICLR 2025，pass^k 指标被广泛引用）。
- **④**：JSON 三件套；体积实测（HTTP HEAD，2026-08-06）：retail 2.31 MB、airline 5.04 MB；读取＝启动全载 + 哈希 O(1)，无索引依赖、无第三方库。本地 `retail_tasks_test.py`【实测】169,476 B/3,358 行，0.34 ms。
- **⑤**：**数据不能用**（客服域、合成、无真值血缘）；**架构直接借用**——我方 mock 后端的最小实现就是同构的"JSON 全载 dict + 按契约 tool 闭包 + 匿名 ID 索引"。其终态比对思想对应我方 check_molecule_exists 的 B 库成员判定与评分期复核。

### 2.2 Tartarus——oracle + PDB 样本（"算"的代表，与"查"相反）

- **①**：半有。资产＝起始分子池+参考分 CSV（docking/hce/reactivity）+ 冻结靶点结构（1SYH/4LDE/6Y2F 的 pdbqt）；打分 oracle 现场调 QuickVina/Smina/xTB 二进制，**不是查库**。
- **②③**：PDB（RCSB，权威，2 家采用）；NeurIPS 2023 D&B。
- **④**：CSV 本地样本【实测】三份共 12,896 B、各 29 行，读取 ≤0.14 ms；完整 oracle 依赖外部二进制与化学计算环境，读取条件重。
- **⑤**：**不用**——它代表"真算"路线，与我方"发布 mock 不真算"的红线相反；可借：PAINS/mcf 过滤清单（入库校验负例）、"哨兵值 10000 表示失败"的错误口径（可参照我方统一错误码）。

### 2.3 PoseBench / PoseBusters——datasets_pdb.csv 与规则检查

- **①**：PoseBusters＝检查套件 + 基准清单 `datasets_pdb.csv`（本地【实测】424 B/4 行，0.05 ms，指向 PDB/SDF 文件）；PoseBench＝4 数据集 input CSV（本地 head【实测】1,584 B/11 行，0.11 ms）+ 终态内置 PoseBusters rescoring。
- **②③**：PDB（权威）；PoseBusters=Chem. Sci. 2024，PoseBench=NMI（venue 待复核，沿用底稿口径）；基准集 428 个无晶体接触复合物。
- **④**：清单 CSV 极小；实体是 PDB/SDF 文件集，Zenodo 8278563 实测 **54.96 MB**（zip 53.66 MB + results 1.30 MB）；读取依赖 RDKit/OpenBabel。
- **⑤**：**清单与结构数据不用**（结构预测域）；**PoseBusters 规则检查借用**——价态/键长/立体/蛋白碰撞等确定性检查，可作我方评分侧"结构合理性门"与 edit_molecule/normalize_structure 产物合法性校验的参照实现（以规则 config 形式，54.96 MB 完全在 10 GB 预算内）。

### 2.4 TDC_PMO——函数 oracle + ADMET 成品数据（唯一"改造"对象）

- **①**：有三层资产：ADMET 成品数据表（22 数据集随 PyTDC 缓存分发）；B 类 pickle 预测器；A 类 RDKit 公式 oracle（QED/SA/logP）。
- **②③**：TDC 汇编真实实验数据（ChEMBL 等）；TDC=NeurIPS D&B 2021，3+1 家独立采用（research 底稿 §1.2），**药物线最强背书**。
- **④**：单数据集 CSV 小表（数百~数十万行；TDC 全平台 66 集共 1591.9 万数据点、单集 200~200 万，TDC 论文口径）；读取条件＝`pip install pytdc` 后自动缓存，无重型依赖；本地 oracle.py 1266 行【实测】读取 <1 ms。
- **⑤**：**改造后借用**：ADMET 成品数据表 → get_property 药物线真值源（字段映射 + 匿名化 + provenance 三元组）；A 类公式 oracle 可作造题期反查工具；**B 类预测器禁止当真值**（仅预测器）。

### 2.5 SciAgentArena——ground_truth.csv（快照组织的模板）

- **①**：有。`scorers/data/*_ground_truth.csv` 每任务一张冻结真值表；C3 预算制 oracle 包装 PyTDC（超预算抛 `OracleBudgetExceededError`，与我方 verify_budget 同构）。
- **②③**：真值多为 RDKit 可复算量；论文为预印本（arXiv 2606.12736），权威性靠可复核性而非 venue。
- **④**：CSV 逐任务小表【实测】样例 29 B/1 行，0.06 ms；判分明写 `AGENT4S_NO_NETWORK=1` 离线执行。
- **⑤**：**表不用，范式借用**：①每 case 一张冻结真值 CSV；②禁联网判分环境变量；③预算制 oracle 报错口径。

### 2.6 MatTools——case_properties.json（case 级性质快照的形态样本）

- **①**：有（case 级）。每个 case 一份 `case_properties.json`，逐性质给 description/format/value 三字段。
- **②③**：第一性原理计算产物（缺陷能带等），pymatgen 生态；CoRR 2025 预印本。
- **④**：JSON【实测】1,071 B/2 键，0.06 ms；零依赖（标准 json）。
- **⑤**：**数据不用，形态借用**——我方"每 tool 一个子库"中 case 真值层的字段组织（name/value + 描述 + 格式声明）可照此三字段式。

### 2.7 TOMG-Bench——从 Zinc-250K 反推的冻结题集

- **①**：无查询库；test.csv 是"先有答案（Zinc-250K 真实分子）再反推指令"的冻结题集（每子任务 5000 题，Git-LFS）。
- **②③**：Zinc-250K（chemical_vae 2018，约 25 万分子，底稿 §2.1 已订正）；预印本。
- **④**：CSV（LFS 大文件，完整拉取属大体积，不在本阶段拉）；本地样例【实测】8 份各 ~4 KB/24~30 行，≤0.07 ms。
- **⑤**：题集不用（任务形态单轮）；**其数据源 Zinc-250K 是 search_candidates 分子池首选**（2 家背书、25 万级、体积 ~数十 MB 远低于 10 GB）。

### 2.8 MADE——Materials Project 快照 + 环境层过滤（A/B 分层先例）

- **①**：半有。Dataset 层＝`PhaseDiagramDataset`（配置明写 "RAW, UNFILTERED Materials Project data"）；**任务级过滤（SMACT/化学计量/能量阈值）全部在 Environment 层做**，过滤后即"effective ground truth"。
- **②③**：Materials Project（Berkeley Lab，APL Materials 2015；材料线唯一 benchmark 背书，底稿 §1.3）。
- **④**：无本地大样本（需 MP API key；task11 实测 MP API 403、OQMD 不可达，沿用底稿执行障碍结论）；本地 configs【实测】yaml 各 <1.4 KB。
- **⑤**：**数据暂不可取（API 不可达），范式直接借用**——"原始库全量快照 + 判分期在环境层过滤定义真值"正是我方 A 库（agent 可查）/B 库（评分侧复核）物理分层的先例；其 smact/min_distance 过滤器可作候选池入库校验参考。

### 2.9 GuacaMol——硬编码目标分子（零联网先例）

- **①**：无查询库；目标分子 SMILES 写死在 `benchmark_suites.py`（Celecoxib/Troglitazone 等，L64-L77，底稿 §一.4 已核验），分布基线用 ChEMBL 训练集。
- **②③**：ChEMBL（EMBL-EBI，2 家采用）；JCIM 2019。
- **④**：Python 常量 + RDKit 现场计算；零数据文件依赖。
- **⑤**：不用；**"真值写死在发布物里、判分零联网"的先例**。

### 2.10 DiscoveryBench——数据随任务冻结内嵌

- **①**：无统一查询库；每任务目录内嵌该任务的数据表（CSV/JSON）与 hypothesis。
- **②③**：真实论文开放数据（6 域）；ICLR 2025（我方目标会议）。
- **④**：【实测】capital_head.csv 3,961 B/30 行 0.08 ms、metadata_0.json 14,371 B/8 键 0.09 ms；零依赖。
- **⑤**：不用其数据；借"数据与任务绑定冻结"的发布形态（我方 case 的 gt 同样随 case 冻结）。

### 2.11 TravelPlanner——400 万条沙盒库（大库反例）

- **①**：有。flights/hotels/restaurants/attractions/city 五个按 tool 分文件的子库，6 个检索 tool 查询。
- **②③**：互联网爬取数据，无学术权威性——**恰好证明沙盒检索库不需要权威源，但我方性质真值需要**，两者定位不同。
- **④**：JSON/JSONL 分库，Google Drive 打包；论文口径约 400 万条（flights 约 383 万，转引 ACL 2025 表 4）【仓库文档】；本地样本【实测】35,875 B/2 条，0.07 ms。
- **⑤**：不用（域不符、无真值）；借"**每 tool 一个子库文件**"的物理组织（与我方硬指标"每 tool 一个子库"同名同构）。

- **⑤**：不用（与 ≤10 GB 静态离线库形态冲突）；借 checkpoint 谓词化验证函数写法。

### 2.13 MOSES（补充）——静态切分集

- **②③**：ZINC Clean Leads 459 万分子（底稿逐字核实）；Front. Pharmacol. 2020（venue 待期刊页复核，沿用底稿口径）。

## §3 每 tool 决策表（9 个契约工具 × 后端来源决策）

基线＝`dag_poc/tools_schema.json` v0.1.0-stub（含 alias 映射）。决策三档：**拿来用 / 改造 / 自建**；纯计算/收卷类工具无后端需求，单列"无需后端库"。

| # | tool | source_tier | 后端来源决策 | 理由（对应 §1/§2 证据） |
|---|---|---|---|---|
| 1 | literature_search（alias：fetch_bib_info 等 3 个） | A | **自建** | 61 家中无一家提供离线文献元信息查询后端（tau-bench/TravelPlanner 的库域不符；ToolBench 只有 API 元数据缓存）。自建冻结文献快照（doc_id/title/year/citation_count 四字段），造题期从权威数据库（DOI/PMID）采集后冻结，判分零联网 |
| 2 | search_candidates（alias：search_molecule_database） | A | **自建**（数据源借用 Zinc-250K） | 无现成双领域候选检索后端；TravelPlanner 证明"按 tool 分子库文件"组织可行但域无关。自建分子/晶体候选池：药物线以 Zinc-250K（约 25 万，2 家背书）+ PubChem 身份档扩当前 40 分子；材料线以 3DSC（9.1 MB 已落盘）；**严守 behavior_notes：无命中返 EMPTY_RESULT，禁 fallback 全库** |
| 3 | get_entity（alias：get_cif_by_formula 等 5 个） | A | **自建** | 无现成"匿名 ID → 结构身份"后端（tau-bench 的按 ID 取件模式可借架构）。分子身份用已落盘 PubChem 40/40 身份档（28 KB），晶体用 3DSC CIF；masked_structure 掩码规则自研（不可逆是契约前提） |
| 4 | get_property（alias：predict_admet、crystal_predict） | A | **改造**（本报告唯一"改造"决策） | TDC ADMET 成品数据（22 数据集、NeurIPS D&B 2021、3+1 家背书）是现成药物性质真值，但需：字段映射到我方 property_spec、匿名化、补 provenance 三元组、B 类预测器剔除（只取实测值数据表）。材料线无现成品（MP API 403），以已落盘 3DSC/SuperCon 快照自建。**当前 80.4% 填充率的缺口列（caco2/logS/logD 等）恰由 TDC ADMET 成品表补齐** |
| 5 | compare（alias：compare_materials） | none | **无需后端库** | 契约明写纯便利排序工具，输入必须是 agent 已触达实体，不触库 |
| 6 | submit_answer | none | **无需后端库** | 收卷工具，只做 answer_schema.json 校验；终态记录复用 tau-bench 式终态落盘思路 |
| 7 | check_molecule_exists | existence-only | **自建** | 61 家无存在性接口先例（最接近的是 tau-bench 终态比对）。B 源分子集 = 各 open case 的 gt 分子冻结集（评分侧持有），实现为独立 B 库文件，**物理隔离于 A 库**（goal §2b⑤：A 内分子与库外分子一律 false）；比对架构借 tau-bench dict 内存比对 |
| 8 | edit_molecule | none | **无需后端库** | 纯结构计算（RDKit 封闭算子集）；产物合法性校验参考 PoseBusters 规则 config |
| 9 | normalize_structure | none | **无需后端库** | 纯规范化计算（RDKit canonicalization 同口径）；同一性判定函数评分侧复用 |

**决策汇总：拿来用 0 ｜ 改造 1（get_property←TDC ADMET 成品数据）｜ 自建 4（literature_search、search_candidates、get_entity、check_molecule_exists）｜ 无需后端库 4（compare、submit_answer、edit_molecule、normalize_structure）。**

> 为什么"拿来用"是 0：所有自带库的 benchmark 都绑死单一领域与自身任务 schema，且**无一家做了匿名 ID、A/B 分层、provenance 三元组**这三件事——这三件是我方契约的硬前提，任何"拿来用"都绕不开重写，即改造代价 ≥ 自建。故唯一保留的"改造"只针对**数据本身权威、只差组织形式**的 TDC ADMET。

### 5.3 总体大概率结论

**各家均无可直接复用的双领域（药物+材料）查询后端，退回自建；自建时最大限度借用上述成品数据与范式。** 三条支撑：

1. **域不匹配**：自带库的 15 行里，客服（tau-bench）、旅行（TravelPlanner）、职场服务（TheAgentCompany）、代码仓库（SWE-bench 系）、Kaggle（MLE-bench）与药物/材料无关；结构预测（PoseBench/PoseBusters/Tartarus）只产结构不产性质查询。
2. **三件硬前提无人做过**：匿名 ID、A/B 源物理分层、provenance 三元组——61 家无一具备，"拿来用"必经重写，改造代价 ≥ 自建。
3. **唯一例外是数据级借用**：TDC ADMET 成品数据（数据权威、只差组织形式）按"改造"纳入 get_property；这是 owner"能拿来用就别自己造"要求的最大落实面。

### 5.4 遗留与下一步（供第二阶段）

1. TDC_ADMET 源目录为空、UCI_SuperCon zip 不完整、PubChem 缺 MANIFEST（progress.md 阻塞项 1）——补拉后方可启动 get_property 子库构造；
2. Zinc-250K 与 TDC ADMET 子集的实际拉取属第二阶段（本阶段只调研格式与读取条件，未拉大体积数据）；

4. A/B 源隔离测试（验收项 6）与入库校验门（验收项 7）设计在构造阶段落地，隔离机制参照 MADE 环境层过滤 + tau-bench 终态比对。
