**核心结论（三句话）**：

1. **存储格式唯一结论：全部子库统一 JSONL 全载（一行一记录），不用 SQLite、不分档**——实测 17 个本地样本读取全 <1 ms、拟引入资产总量 <0.5 GB，JSONL 在体积/读取/多行 CIF/md5 冻结/零依赖五项上全面够用且更优（§1）。
2. **A/B 隔离靠文件系统而非查询过滤**：每个子库目录下 `<tool>_A.jsonl` 与 `<tool>_B.jsonl` 各自独立成文件；读取层对 agent 会话只打开 A 文件，B 文件不进入任何查询路径；`check_molecule_exists` 是唯一允许触 B 的通道，且只读 B 侧两列索引、只返单 bool（§2）。
3. **需要后端库的 tool 共 5 个**（literature_search / search_candidates / get_entity / get_property / check_molecule_exists），逐库字段规格见 §3；compare、submit_answer、edit_molecule、normalize_structure 四个工具无后端库需求（纯计算/收卷），见 §3.6。

## §1 存储格式决策（含实测依据）

### 1.1 决策问题

原计划默认「SQLite，每 tool 一文件」。前置调研（`现有后端数据库调研报告.md` §4）给出两条关键实测：

- 17 个本地样本（含现有 `mock_db.json` 30 KB / 40 分子 / 17 晶体基线）读取**全部 <1 ms**（最大 0.71 ms，SUPER 271 KB 样本）；
- 拟纳入的全部资产（Zinc-250K 数十 MB + TDC ADMET 子集数十 MB + 3DSC 9.1 MB + 规则 config KB 级 + PubChem 身份档 KB 级）合计 **<0.5 GB**，距 10 GB 预算两个数量级。

据此重新定夺：**SQLite vs JSONL/JSON 全载**。

### 1.2 逐条决策依据

| 维度 | SQLite（每 tool 一 .sqlite 文件） | JSONL 全载（每侧一 .jsonl 文件） | 裁定 |
|---|---|---|---|
| **体积** | 页式存储有 header/空闲页开销，小库反而更大；<0.5 GB 总量下无优势 | 纯文本，最大单表（Zinc-250K 约 25 万行）估计数十 MB，远低于预算 | JSONL |
| **读取耗时** | 点查 O(log n)，需建索引；全表扫仍要读盘 | 启动全载 + dict 哈希 O(1)。实测外推：30 KB 全载 0.22 ms，100 MB 级全载约 1 s 内（调研报告 §4.2 已验证量级），完全在"本地可解析"红线内；且 tau-bench 全库 7.3 MB 同构架构已工程验证 | JSONL |
| **多行 CIF 解析** | CIF 多行文本需存入 TEXT 列，写入/导出仍需转义；且 3DSC CSV 实测教训（41,283 物理行含多行 cif 仅 5,771 记录）说明多行文本在表格格式中是持续踩坑点 | CIF 作为 JSON 字符串值嵌入，换行由 `json` 标准库自动转义（`\n`），一行仍是一记录，读取零解析坑 | JSONL |
| **md5 冻结友好** | **硬伤**：SQLite 文件含 header 计数、freelist、页对齐填充，同一逻辑内容经不同写入器/VACUUM 后字节流可变，md5 不稳定，冻结校验需额外"逻辑导出"环节 | 纯文本确定性序列化（`ensure_ascii=False` + 固定字段顺序 + UTF-8 无 BOM），字节流逐位可复现，md5 直接冻结（承记忆规范：Content-Length/md5 冻结断言） | JSONL |
| **依赖** | `sqlite3` 虽是 Python 标准库，但引入 schema 迁移/索引维护/CLI 工具链心智负担；跨环境二进制文件 diff 不可读 | `json` 标准库，**零第三方依赖**；文本可直接 diff/grep/head，审查友好 | JSONL |
| **A/B 物理分层** | 单文件内做表级隔离，隔离靠"查询时不查 B 表"，是**查询过滤**不是**文件隔离**，与 goal §2b② 的物理分层要求相悖 | 天然一文件一侧：`<tool>_A.jsonl` 与 `<tool>_B.jsonl` 物理分离，读取层不 open B 文件即绝对隔离 | JSONL |

### 1.3 唯一结论

> **全部子库统一采用 JSONL（一行一 JSON 记录，UTF-8 无 BOM，`ensure_ascii=False`），启动全载入 dict，不用 SQLite、不按大小分档。**

不分档的理由：最大单表（Zinc-250K 约 25 万行）全载仍在秒级与数百 MB 内存内，不构成升档 SQLite 的理由；统一一种格式使读取层只有一条代码路径（E3 照抄成本最低）、冻结校验只有一种断言形式。**格式红线：单文件、零第三方依赖、md5 冻结友好——JSONL 三项全满足。**

升档条件（写死，防日后拍脑袋）：仅当某单侧文件 >1 GB **或** 全载内存峰值 >2 GB 时，才允许该子库单独升档 SQLite，且须按 §7 修订流程留痕。当前无任一子库触发。

## §2 目录与 A/B 物理分层设计

### 2.1 目录树（精确定义）

```
dag_poc/data/backend/
├── MANIFEST.json                          # 全局冻结清单：逐文件 md5/bytes/行数/生成时间
├── literature_search/
│   ├── MANIFEST.json
│   └── literature_search_A.jsonl          # A 侧：冻结文献元信息快照
├── search_candidates/
│   ├── MANIFEST.json
│   ├── search_candidates_A.jsonl          # A 侧：agent 可检索的候选池
│   └── search_candidates_B.jsonl          # B 侧：open case gt 实体的结构/身份（评分侧持有）
├── get_entity/
│   ├── MANIFEST.json
│   ├── get_entity_A.jsonl                 # A 侧：匿名 ID → 结构身份（含完整 CIF）
│   └── get_entity_B.jsonl                 # B 侧：gt 实体的身份档（评分侧持有）
├── get_property/
│   ├── MANIFEST.json
│   ├── get_property_A.jsonl               # A 侧：A 池实体的性质快照真值
│   └── get_property_B.jsonl               # B 侧：gt 实体的性质真值（评分期复核用）
└── check_molecule_exists/
    ├── MANIFEST.json
    └── check_molecule_exists_B.jsonl      # 仅 B 侧：存在性索引（InChIKey + 规范化 SMILES 两列）
└── per_case_views/                         # v1.3 新增：per-case 可见集视图（open case 一 case 一文件）
    └── <case_id>.json                      # 视图白名单：该 case 下 A 侧四工具查询限域于此
```

### 2.2 文件命名规范

| 规则 | 定义 |
|---|---|
| 子库目录名 | ＝ tools_schema.json 中的规范 `name`（小写下划线），不用 alias 名 |
| 数据文件名 | `<tool_name>_A.jsonl` / `<tool_name>_B.jsonl`；**一侧一文件，禁止 A/B 混入同一文件** |
| 侧的取舍 | source_tier=A 的工具必有 `_A` 文件；`check_molecule_exists`（existence-only）**只有 `_B`**；B 文件仅在 open 类需要的四个库出现（search_candidates / get_entity / get_property / check_molecule_exists） |
| MANIFEST.json | 每目录一份，逐文件记 `{file, md5, bytes, record_count, generated_at, schema_version}`；根 MANIFEST 汇总全部文件——md5 冻结断言的可执行载体 |
| 编码 | UTF-8 无 BOM；一行一记录；字段顺序固定（按 §3 各表清单顺序）；`ensure_ascii=False` |

### 2.3 隔离机制（靠文件系统，不靠查询过滤）

goal §2b② 写死：「A 的任何查询不得带出 B 内容」，本契约的落地方式是**物理分层**：

1. **读取层白名单**：gateway（E3 实现）对 agent 会话初始化时**只允许 `open()` 路径匹配 `*/<tool>_A.jsonl` 的文件**；`check_molecule_exists` 是契约声明的唯一例外，且只允许打开 `check_molecule_exists_B.jsonl`（见 §6.5）。`_B` 文件不出现在任何 A 侧工具的加载代码路径中。
2. **不共享任何索引结构**：A 侧 dict 与 B 侧索引是两个独立载入的内存对象，不存在"A 查询顺手 join B"的代码形态。
3. **存在性接口只读索引列**：`check_molecule_exists_B.jsonl` 只含 InChIKey 与规范化 SMILES 两列身份键（+ provenance），**不含任何性质/相似度/距离字段**——结构上封死泄漏（对应 tools_schema 中该工具 output `additionalProperties=false` 的同口径设计）。
4. **per-case 可见集视图（v1.3，ADR-0018 §2.3）**：A/B 物理分层不动的前提下，在 **A 内部再切一层**——每个 open case 一份可见集白名单 `backend/per_case_views/<case_id>.json`，agent 在该 case 下的四个 A 侧工具（search_candidates / get_entity / get_property / literature_search）查询一律被限制在白名单内，gt 结构上不可达；视图不破坏物理分层（视图只在读取层生效，B 文件仍不经任何 A 侧路径打开）。视图格式/读取器/穷举接口/可执行断言见 **`per-case视图交接说明.md`**（唯一权威文档）；视图文件已纳入 CHECKSUMS 冻结主清单（E1-05 收口，Task #33），此后新增视图须走入库流程并统一刷新 CHECKSUMS（`入库操作手册.md` §8）。
5. **A 侧保留全表枚举接口**：`enumerate_A(tool) -> list[id]`（签名见 §6.6），供 open 类造题期「可发现性质量门第一条」（goal §2b④：A 全域穷举证无替代解）使用；该接口只在造题/评分进程可用，**不作为 agent 工具暴露**（9 契约工具清单中无此工具）。
6. **隔离验证**（Task #7 验收项 6 的可执行断言，此处先冻结判据）：
   - 断言一：对 tools_schema 中所有 source_tier=A 的工具，读取层源码中出现的 `backend/` 路径集合 ∩ `{*_B.jsonl}` ＝ ∅；
   - 断言二：任一 A 侧查询的返回对象序列化后，不含任何 B 侧独有实体 id；
   - 断言三：`check_molecule_exists` 对 A 内分子与库外分子一律返 false（goal §2b⑤ 接口语义写死）。

## §3 逐子库字段规格（5 个需要后端库的 tool）

> 通用规则：① 每条记录必带 provenance 三元组（格式见 §4）；② 实体 ID 为匿名域短 ID（两位小写字母风格，承现有 mock_db 的 aa…zz 约定，扩容后允许字母+数字后缀，永不暴露 PubChem CID/MP id 给 agent——真实 ID 只存在于 provenance 与 `_mapping_scoring_only`）；③ "记录数目标"是契约下限，构造阶段（Task #7）达标后以实测值回填 MANIFEST。

### 3.1 literature_search（自建；决策表行 1）

文件：`literature_search/literature_search_A.jsonl`（无 B 侧——文献不是 A/B 分层对象）。

| 字段 | 类型 | 含义 | 取值约束 |
|---|---|---|---|
| `doc_id` | string | 文献唯一 ID | DOI 或 `PMID:<数字>`；全局唯一 |
| `title` | string | 论文标题 | 非空 |
| `year` | integer | 发表年份 | 1900–2026 |
| `citation_count` | integer | 冻结时点引用数 | ≥0；采集时点写入 provenance |
| `keywords` | array[string] | 检索匹配用关键词 | 造题期人工/半自动标注，供 query 匹配 |
| `provenance` | object | 见 §4 | 非空 |

- **索引键**：`doc_id`（全载后建 dict）；检索匹配为关键词倒排（构造期内存中建立，不落盘第二文件）。
- **记录数目标**：≥300 条（现有 mock 仅 14 条，须扩容；覆盖药物线 + 材料线各 case 的 cp1 文献检索）。
- **数据来源**：自建冻结快照——造题期从权威数据库（CrossRef/PubMed 按 DOI/PMID）采集元信息后冻结，判分零联网（调研报告 §3 行 1）。输出字段与 tools_schema `literature_search.output.papers` 逐项对齐（doc_id/title/year/citation_count）。

### 3.2 search_candidates（自建，数据源借用 Zinc-250K / 3DSC；决策表行 2）

文件：`search_candidates/search_candidates_A.jsonl` + `search_candidates_B.jsonl`。

**A 侧记录字段**：

| 字段 | 类型 | 含义 | 取值约束 |
|---|---|---|---|
| `id` | string | 匿名实体 ID | 全局唯一；与 get_entity_A 同键对齐 |
| `entity_type` | string | 实体类别 | enum: `molecule` / `crystal` |
| `structure_hint` | string\|null | 检索可见的结构提示 | masked 化学式/结构片段；**掩码必须不可逆**（INTERFACE_CONTRACT §5 前提） |
| `smiles` | string\|null | 分子 SMILES（分子线） | RDKit 可解析；**仅约束过滤用，不进工具输出**（输出字段不含性质与完整结构，承 tools_schema behavior） |
| `formula` | string | 化学式 | 分子/晶体均必填 |
| `filter_props` | object | 约束过滤专用数值字段 | 药物线：`mw`/`logp`/`tpsa`（Zinc-250K 自带列）；材料线：`sc_class`（族标签）。**这些字段只驱动 constraints 过滤，永不出现在返回中**（性质一律走计费的 get_property，否则 cp3 无意义） |
| `provenance` | object | 见 §4 | 非空 |

**B 侧记录字段**：`id`（B 侧匿名 ID）/ `entity_type` / `smiles`（或 `formula`）/ `case_ref`（所属 open case 标识，评分侧索引用）/ `provenance`。**不含任何性质字段**——B 侧性质真值一律在 `get_property_B.jsonl`。

- **索引键**：A 侧 `id`；过滤在 `filter_props` 上做线性扫（25 万行级全扫毫秒~亚秒，实测外推成立）。
- **记录数目标**：A 侧药物线 ≤249,456（Zinc-250K 全量上限，实际以入库校验门通过率为准，下限 ≥10,000）+ 现有 40 分子身份档；材料线 **17,252**（v1.3：3DSC 全量 5,771 + UCI SuperCon 11,481，id c05772–c17252，见 §6.7）。B 侧 ＝ 各 open case gt 实体冻结集（随 E5 造题增长，每 case ≥1）。
- **数据来源**：药物线 Zinc-250K（2 家背书）+ PubChem 身份档；材料线 3DSC（已落盘 9.1 MB）+ **UCI ML Repo #464 SuperCon（Hamidieh 2018，v1.3 新增，URL/DOI/权威性依据见 `task-05-扩数据源调研.md`）**。
- **契约行为绑定**：无命中返 `EMPTY_RESULT`，**禁止 fallback 全库**（tools_schema behavior_notes 已写死，读取层不得实现任何默认集合返回）。

### 3.3 get_entity（自建；决策表行 3）

文件：`get_entity/get_entity_A.jsonl` + `get_entity_B.jsonl`。

**A 侧记录字段**：

| 字段 | 类型 | 含义 | 取值约束 |
|---|---|---|---|
| `id` | string | 匿名实体 ID | 与 search_candidates_A 同键 |
| `entity_type` | string | 实体类别 | enum: `molecule` / `crystal` |
| `formula` | string\|null | 匿名域化学式 | 对应 tools_schema output.structure.formula |
| `masked_structure` | string\|null | masked SMILES / CIF 键 | **掩码规则不可逆**；完整结构永不经工具返回 |
| `atom_count` | integer\|null | 原子数 | ≥1 |
| `inchikey` | string\|null | 分子身份键（分子线） | 27 位标准哈希；**仅评分侧/校验门用，不进 agent 可见输出** |
| `cif` | string\|null | 完整 CIF 文本（晶体线） | 多行文本以 JSON 转义存储；供评分侧与结构校验，agent 输出只见 masked_structure |
| `provenance` | object | 见 §4 | 非空 |

**B 侧记录字段**：同 A 侧字段集 + `case_ref`（B 侧 gt 实体身份档，评分侧持有）。

- **索引键**：`id`。
- **记录数目标**：与 search_candidates 同集 1:1（A 侧每个可检索实体必须可取件，否则 cp2→cp3 断链）。
- **数据来源**：分子身份＝PubChem 40/40 身份档（28 KB 已落盘）+ Zinc-250K 扩充；晶体＝3DSC CIF 列。masked 规则自研（不可逆是契约前提，规则细节属 Task #7）。

### 3.4 get_property（改造：药物线 ← TDC ADMET；材料线自建 ← 3DSC；决策表行 4）

文件：`get_property/get_property_A.jsonl` + `get_property_B.jsonl`。记录粒度：**一行一 (实体, 性质) 对**（非一行一实体），保证每行独立带 provenance。

**记录字段**（A/B 同构）：

| 字段 | 类型 | 含义 | 取值约束 |
|---|---|---|---|
| `entity_id` | string | 实体匿名 ID | 必须存在于对应侧的 get_entity 文件 |
| `prop` | string | 性质键 | 必须在 `dag_poc/properties/<domain>_v1.json` 清单内（drug_admet_v1：bbb/herg/caco2/logS/logD/half_life/binding_affinity/atom_count/element_count；materials_supercon_v1：tc/condition/family/structure_in_db/element_count；药物侧 atom_count 与材料侧 element_count 为 E1-05 §6 追加项补登（§6.7 行 5），药物侧 element_count 为 Task #38 监工裁定落地（§6.7 行 6）） |
| `value` | number\|string | 性质真值 | number 或 string（bool 用 1/0，category 用字符串，承 tools_schema output）；**缺失即无此行，禁止填 0/null 冒充真值**（承已知坑 4：全 0 陷阱） |

| `provenance` | object | 见 §4 | 非空 |

- **索引键**：`(entity_id, prop)` 复合键（全载后建 dict[(id,prop)] → value）。
- **记录数目标**：A 侧药物线 ＝ A 池分子数 × 6 性质（bbb/herg/caco2/logS/logD/half_life；binding_affinity 待 UniProt/PDB/BindingDB 拉取后另立项，见调研报告 §5.4）＋**每分子 1 行 atom_count**（实体记录原子总数直取，E1-05 §6）＋**每分子 1 行 element_count**（分子匿名式 label 种类数，确定性计算，Task #38 监工裁定；值域 1~8，档外 1,045 条按裁定口径 a 如实入库另册登记）；材料线 ＝ **17,252** ×（tc/family/condition/structure_in_db）＋**每晶体 1 行 element_count**（匿名组成元素种类数，确定性计算，E1-05 §6）（v1.3：字段规格不变，行数随材料容量同步，见 §6.7；v1.3.2 行数漂移注记：Task #38 补登药物侧 element_count 后实测 165,723 → **240,664** 行）。B 侧 ＝ 各 open case gt 实体 × 题面涉及性质全集。
- **数据来源**（逐性质绑定，承 task18 mock构造方案 §1.2/§2.1 与调研报告决策表行 4）：
  - `logS` ← AqSolDB `Solubility`（Sci Data 6:143，已落盘 9,982 条）；
  - `bbb` ← TDC ADMET (BBB_Martins)、`herg` ← TDC ADMET (hERG)、`caco2` ← TDC ADMET (Caco2_Wang)、`half_life` ← TDC ADMET (Half_Life_Obach)（TDC＝NeurIPS D&B 2021，唯一"改造"决策；**B 类 pickle 预测器严禁当真值**）；`logD` 来源待 TDC 拉取后在构造期锁定；

  - `condition` ← **人工标注，不得从 3DSC 推导**（见 §4.3 与已知坑 1）。

### 3.5 check_molecule_exists（自建；决策表行 7）

文件：`check_molecule_exists/check_molecule_exists_B.jsonl`（**只有 B 侧**——本工具定义域就是 m ∈ B）。

**记录字段（只许这些，多一个字段即违约）**：

| 字段 | 类型 | 含义 | 取值约束 |
|---|---|---|---|
| `inchikey` | string | B 侧 gt 分子 InChIKey | 27 位标准哈希；主查询键 |
| `canonical_smiles` | string | 匿名域规范化 SMILES | 与 `normalize_structure` 同口径规范化后的唯一形式；次查询键 |
| `provenance` | object | 见 §4 | 非空（source 记"open case gt 冻结集"） |

- **索引键**：`inchikey` 与 `canonical_smiles` 两个 set（全载后各建一个哈希集）。
- **记录数目标**：＝ 全部 open case 的 G_B 合格集分子并集（每 case ≥1，随 E5 造题冻结增长）。
- **数据来源**：各 open case 的 gt 分子冻结集（造题期由 E5 落盘、E1 入库，评分侧持有）。
- **语义绑定**：返值严格等价 `m ∈ B`——A 内分子与库外分子一律 false；只返单 bool + attempts 计数，output 不含任何性质/相似度/距离（goal §2b⑤、tools_schema behavior_notes 写死）。
- **`case_ref` 承载口径注明（v1.2，裁定二落地）**：ADR-0015 §2.3 要求 G_B per-case 带 `case_ref`，本库**不增字段**，`case_ref` 承载于 `provenance.note`（格式 `case_ref=<case_id>；…`）。理由：`case_ref` 属**评分侧元数据**、不进返回值，不触“存在性接口只返单 bool”红线；而增字段会动已冻结的契约结构，代价更大（task-03 §8 裁定二，实现口径澄清而非契约实质变更，无需另立 ADR）。

### 3.6 无需后端库的 4 个 tool（一句话）

`compare`（纯便利排序，输入必须是 agent 已触达实体）、`submit_answer`（收卷，只做 answer_schema.json 校验）、`edit_molecule`（RDKit 封闭算子集纯计算）、`normalize_structure`（RDKit canonicalization 纯计算）——四者均不触达任何子库，无文件、无字段规格（承调研报告 §3 决策表行 5/6/8/9）。

## §4 provenance 规范

### 4.1 字段格式（每条记录必带，缺省即拒收——见 §5 断言二）

```json
"provenance": {
  "source_db": "<来源库规范名，如 AqSolDB / TDC_ADMET:Caco2_Wang / 3DSC / PubChem / Zinc-250K / manual_annotation>",
  "source_url": "<可回查的真实 URL，如 https://doi.org/10.1038/s41597-019-0151-1>",
  "source_paper_doi": "<数据集/论文 DOI；无 DOI 的库填其权威页面 URL 并在此字段记 N/A 原因>",
  "note": "<可选：匹配键、所选记录 ID、采集时点等辅助信息>"
}
```

- 三元组 `{source_db, source_url, source_paper_doi}` 为硬前提（task.md §3）；`note` 为可选补充。
- 多源上游必须双标：如材料记录 `source_db: "3DSC"` 时，`note` 内注明「上游为 NIMS SuperCon 与 Materials Project，MP 溯源锚 material_id_2＝mp-xxxx」（承 task18 §3 口径）。

### 4.2 示例（三个典型来源各一）

**药物线 logS（AqSolDB）**：

```json
"provenance": {
  "source_db": "AqSolDB",
  "source_url": "https://doi.org/10.1038/s41597-019-0151-1",
  "source_paper_doi": "10.1038/s41597-019-0151-1",
  "note": "按 InChIKey 匹配；多源时取 Occurrences 高、SD 小者，所选记录 ID=AqSolDB-xxxx"
}
```

**材料线 tc（3DSC）**：

```json
"provenance": {
  "source_db": "3DSC",
  "source_url": "https://doi.org/10.1038/s41597-023-02721-y",
  "source_paper_doi": "10.1038/s41597-023-02721-y",
  "note": "上游双标：NIMS SuperCon（Tc）× Materials Project（结构）；material_id_2=mp-xxxx"
}
```

### 4.3 3DSC `condition` 人工标注的 provenance 写法（已知坑 1，强制）

3DSC 不含常压/高压列，`condition` **必须人工按文献标注**，且标注来源必须写入 provenance，格式写死：

```json
{
  "entity_id": "xd", "prop": "condition", "value": "high_pressure(~170GPa)",
  "provenance": {
    "source_db": "manual_annotation",
    "source_url": "https://doi.org/10.1038/s41586-019-1201-8",
    "source_paper_doi": "10.1038/s41586-019-1201-8",
    "note": "压力条件为人工标注（非数据库直取），依据文献：Drozdov et al., Nature 2019（LaH10 ~170 GPa）；标注人/日期见构造期留痕"
  }
}
```

**红线**：未完成文献标注的记录，`condition` 值记 `"未知"`（字符串），**不得默认 `ambient`**——默认 ambient 会把高压相伪造成常压合格解，直接毁掉 open 类陷阱题（LaH10 的 Tc=250 K 只在 ~170 GPa 成立）。

## §5 入库校验门规格（三道断言）

每行记录写入任一 `*_A.jsonl` / `*_B.jsonl` **之前**必须顺序通过三道断言；任一失败即**拒收该行**（该行不入库、记入拒收日志 `{文件, 行内容摘要, 断言编号, 原因}`，构造不得静默跳过）。

| # | 断言 | 判定逻辑 | 拒收行为 |
|---|---|---|---|
| 1 | **RDKit 身份校验** | 分子：RDKit 解析记录 SMILES → 算分子式，与来源库的权威分子式（PubChem `MolecularFormula` / AqSolDB 身份列）比对，**不一致即拒收**（该门已被验证有效——曾精确识别 15 条真错配，task18 §1.1）；晶体：CIF 解析出的化学式与 `formula_sc`/`pretty_formula_2` 双列交叉校验 | 拒收 + 记原因「身份不一致：<算出式> vs <权威式>」 |
| 2 | **provenance 非空** | `source_db`/`source_url`/`source_paper_doi` 三字段均非空、非占位符（禁止 `TODO`/`?`/空串）；`manual_annotation` 类必须带非空 `source_paper_doi` 与标注说明 | 拒收 + 记原因「provenance 不完整」 |
| 3 | **SA 红线（许可合规）** | 全库统计 `source_db ∈ {ChEMBL, SIDER}` 的记录数，**必须恒等于 0**——ChEMBL 为 CC-BY-SA，只存 ID + 查询配方、不 bulk dump（已知坑 5）；SIDER 同许可约束。该校验在单库写毕时整体执行 | 命中即整库冻结失败，删除违规行后重跑 |

**与 `src/benchmark/verify_snapshot_identity.py` 的关系（该脚本保持不动）**：

1. 该脚本是**既有 `dag_poc/data/mock_db.json` 快照**的身份复核门（断言一的同口径实现），2026-08-06 复跑退出码 0、0 项问题（progress.md 已记）——本契约**不修改、不复用其文件本体**作新库写入门；
2. Task #7 的构造脚本须实现**同口径**的断言一（RDKit 算式比对），并以"现有 40 分子全部通过、注入 1 条已知错配（aa 旧 SMILES）必被拒收"作回归测试；
3. `verify_snapshot_identity.py` 继续承担其原有职责：mock_db.json 演进时的身份回归；新旧两套门的判定逻辑必须一致，出现分歧以本契约断言一的口径为准并同步报备。

## §6 读取接口契约（供 E3 gateway 照抄）

### 6.1 通用约定

- 打开方式：**进程启动时一次性全载**（tau-bench 同构），标准库 `json` 逐行解析 JSONL 建 dict；运行期只读不写；
- 文件句柄白名单：agent 会话进程的读取层只允许打开 `*/<tool>_A.jsonl`（§2.3 规则 1）；
- 错误码一律映射 tools_schema `meta.unified_error_codes`，不得新增。

### 6.2 literature_search

```
load:   literature_search/literature_search_A.jsonl → dict[doc_id → record] + 关键词倒排索引
query(query: str, max_results: int) → {query, total_found, returned, papers[{doc_id, title, year, citation_count}]}
```
无命中返错误码 `EMPTY_RESULT`；计 search_budget。

### 6.3 search_candidates

```
load:   search_candidates/search_candidates_A.jsonl → list[record]（保序）+ dict[id → record]
query(constraints: [{property, op, threshold}], keywords: str|None, k: int) → {returned, candidates[{id, entity_type, structure_hint}]}
```
约束在 `filter_props` 上比较（op ∈ lt/le/gt/ge/eq/ne，口径由 property_spec 定）；返回字段**严格只有** id/entity_type/structure_hint 三键；无命中返 `EMPTY_RESULT`（禁 fallback）；计 search_budget。

### 6.4 get_entity / get_property

```
load:   get_entity/get_entity_A.jsonl  → dict[id → record]
        get_property/get_property_A.jsonl → dict[(entity_id, prop) → value]
get_entity(id) → {id, entity_type, structure{formula, masked_structure, atom_count}}
get_property(id, props[]) → {id, values[{name, value}]}
```
`id` 不在 A 侧 dict 返 `UNKNOWN_ENTITY`（不区分"不存在"与"不在本源"，防源探测）；`prop` 不在 case.props 清单返 `UNKNOWN_PROPERTY`；get_property 计 verify_budget。B 侧文件**不在此进程加载**。

### 6.5 check_molecule_exists（唯一触 B 通道）

```
load:   check_molecule_exists/check_molecule_exists_B.jsonl → set(inchikey) ∪ set(canonical_smiles)
exists(molecule_id: str) → bool     # 先经 normalize_structure 同口径规范化，再作集合成员判定
```
读取对象只有两个身份键集合，**无任何性质字段可读**；返回结构 `{exists, attempt, attempts_remaining}`；超限返 `ATTEMPTS_EXCEEDED`（该 case 记 0 分）。

### 6.6 A 侧全域枚举接口（造题/评分专用，不暴露为 agent 工具）

```
enumerate_A(tool: str) → list[id]   # tool ∈ {search_candidates, get_entity, get_property}
```
返回对应 `*_A.jsonl` 全部实体 id 的完整列表，供 goal §2b④ 可发现性质量门第一条（A 全域穷举证无替代解）与 open 类穷举质量门使用；**gateway 不得将其注册为 9 契约工具之一**（注册即违约，构成对 agent 的 B 侧探测捷径的对称漏洞——A 全域枚举若进 agent 手，fixed 检索类退化为白给）。
