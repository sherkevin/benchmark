# 入库操作手册 — open case gt → B 侧子库（面向 E5）

> 作者：E1-数据线｜2026-08-06｜依据：`后端库规格契约.md` v1.0（§3.5/§5）、ADR-0015、Task #17 全链路演练实测
> 本手册每一步均经 Task #17 演练实跑验证（可复跑证据：`src/data_build/_build_state/rehearsal_logs/`）。

## 0. 一句话流程

> E5 按 §1 格式落盘 per-case gt 文件 → E1 用 `ingest_open_gt.py` 过三道闸入库 → 刷 CHECKSUMS → 重跑隔离测试。**任何一步失败都不写盘/可回滚**，演练已证明清场后字节级恢复。

```
gt 文件 ──→ 闸0 字段白名单（契约 §3.5）
        ──→ 闸1 ingest_gate 三断言（契约 §5：身份/provenance/来源白名单）
        ──→ 闸2 身份键空间隔离闸（B ∩ A = ∅，ADR-0015 §2.4）
        ──→ 写 check_molecule_exists_B.jsonl + 刷目录 MANIFEST
        ──→ generate_checksums.py 刷新 → test_ab_isolation.py 重跑
```

## 1. gt 落盘格式要求（E5 交付物规格）

**结构**：per-case JSON（ADR-0015 §2.3：`{case_id: {members, g_b}}`）：

```json
{
  "schema": "open_case_gt_per_case_v1",
  "rehearsal": false,
  "cases": {
    "<case_id>": {
      "members": ["<InChIKey>", "..."],          // 候选空间标识
      "g_b": [                                    // G_B 合格集（评分依据）
        {
          "inchikey": "<27 位标准 InChIKey>",
          "canonical_smiles": "<RDKit canonical SMILES>",
          "provenance": {
            "source_db": "open_case_gt",
            "source_url": "<case 文件路径或冻结记录 URL>",
            "source_paper_doi": "<gt 身份来源 DOI/权威标识>",
            "note": "case_ref=<case_id>；<匹配键、冻结时点等>"
          }
        }
      ]
    }
  }
}
```

**硬性要求**（违反即过闸失败，演练实测逐项验证）：

| # | 要求 | 违反后果（实测） |
|---|---|---|
| 1 | 字段只许 `inchikey` / `canonical_smiles` / `provenance` 三个（集合口径，不约束 JSON 键书写顺序） | 闸 0 拒收「字段越界」（契约 §3.5 写死，多一个字段即违约；Task #21 起键序不再作要求，换序的合法 gt 不会被误拒） |
| 2 | **`case_ref` 写在 `provenance.note` 内**（格式 `case_ref=<case_id>；…`），不作独立字段 | 独立字段会被闸 0 拒；清场/索引靠 note 内 case_ref 解析 |
| 3 | provenance 三字段非空、非占位符（TODO/?/空串/大小写变体一律拦） | 闸 1 断言二拒收 |
| 4 | `source_db` 必须在白名单内（gt 用 `open_case_gt`，Task #17 演练后已加入 `common.py`） | 闸 1 断言三整库冻结失败 |
| 5 | **gt 分子不得与 A 池重叠**（InChIKey 或 canonical SMILES 命中 A 池即拦） | 闸 2 拒收（goal §2b⑤：A 内分子入 B 会让 agent 直接交 A 中分子即过） |
| 6 | SMILES 必须是 RDKit canonical 口径（规范化算法归属 E3，ADR-0015 §3；交付前用 RDKit `MolToSmiles` 归一） | 非规范化写法可能导致双键集匹配不上、隔离比对漏检 |

**造题期自查建议**：E5 冻结 G_B 前先自查第 5 条——A 池身份键空间可实测载入（`get_entity_A.jsonl` 的 inchikey 列 + `search_candidates_A.jsonl` 的 smiles 列）。演练实测：连 aspirin/metformin/ibuprofen/acetaminophen/sucrose/citric_acid 这类常识分子都在 A 池内（ZINC 74,901 条覆盖面极广），**不要凭直觉假设"常见分子不在 A 池"**。

## 2. 过门三道断言与失败常见原因

| 闸 | 内容 | 常见失败原因与处置 |
|---|---|---|
| 闸 0 字段白名单 | 三字段（集合比对，不约束键序） | gt 文件带了 `case_ref`/`name` 等附加字段 → 移入 provenance.note 或删除 |
| 闸 1 断言一（身份） | B 侧身份键走 `kind=none`（无权威式可比），SMILES 合法性由 RDKit 解析兜底 | SMILES 非法 → 修 gt；InChIKey 须 27 位标准格式 |
| 闸 1 断言二（provenance） | 三字段非空非占位符，casefold 归一拦大小写变体 | 漏填 DOI、填了 TODO/? |
| 闸 1 断言三（来源白名单） | `source_db` ∈ `common.DATA_FILE_ALLOWED_SOURCES`；且 `open_case_gt` 仅限 B 侧通道（`*_B.jsonl`），A 侧文件出现该来源一律拒收（Task #21 加固，selftest 含对应负例） | 新来源须先由 E1 修白名单再过门（不得自行绕过） |
| 闸 2 隔离闸 | B 双键 ∩ A 池身份键空间 = ∅（canonical 口径） | gt 选了 A 池分子 → **换 gt**，这是造题问题不是入库问题 |

拒收记录一律落盘 `_build_state/rejections_check_molecule_exists.jsonl`（含记录标识、闸名、原因），不静默跳过。

## 3. 入库与刷新步骤（E1 执行）

```bash
# 1) 干跑过闸（不写盘，先看拒收清单）
python3 src/data_build/ingest_open_gt.py --dry-run <gt_file.json>

# 2) 正式入库（追加式：与既有 B 记录按双键去重合并，刷新目录 MANIFEST）
python3 src/data_build/ingest_open_gt.py <gt_file.json>

# 3) 刷新发布快照基准
python3 src/data_build/generate_checksums.py

# 4) 隔离测试重跑（断言①/①b/②/③ 全绿，退出码 0）
python3 src/data_build/test_ab_isolation.py

# 5) 读取语义抽查：B 成员 exists=true、A 池分子 exists=false（backend_reader）
```

入库后检查点：B 文件行数 = 既有 + 新增接受数；目录 MANIFEST 的 `note` 内 case_ref 列表含新 case；CHECKSUMS 中 B 文件 md5 已变、其余 A 侧文件 md5 不变。

## 4. 清场 / 回滚

```bash
# 按 case_ref 前缀清出（演练清场、错入 gt 回滚均用此通道）
python3 src/data_build/ingest_open_gt.py --clean <CASE_REF_PREFIX>

# 清出后刷 CHECKSUMS 与隔离测试（同上 §3 第 3–4 步）
```

- 清场是字节级可验证的：Task #17 演练清场后 B 文件/MANIFEST/CHECKSUMS 三件 md5 与演练前基线逐一相同（`_build_state/rehearsal_backup/PRE_STATE.md5`）。
- 灾难回滚：演练期备份范式 = 动手前把将动文件复制到 `_build_state/rehearsal_backup/` 并记 md5 基线，清场后逐件比对。正式 gt 入库如需回滚，同样先备份再动。

## 5. 演练实测固化的三条教训（Task #17）

1. **ingest_gate 三断言不拦"A 池重叠"**——身份/provenance/来源都合法的 gt 仍可能与 A 池重叠；隔离闸（闸 2）是唯一拦截环节，入库管线不可省略。演练负例（A 池分子 aa）三断言全过、被隔离闸拦下，拒收清单留痕。
2. **新来源必须先进白名单**——`open_case_gt` 首跑即被断言三整库冻结，修 `common.py` 白名单后放行。E5 若引入新 provenance 来源，先找 E1 登记。
3. **隔离断言要防"恒真陷阱"**——B 为空时 A∩B=∅ 平凡成立；`test_ab_isolation.py` 断言①b（跨键空间，ADR-0015 §2.4）在 B 非空后转为实际比对，演练已用 BEFORE/AFTER 实跑输出证明转换生效。

## 6. 遗留依赖（知悉）

- **规范化算法归 E3**（ADR-0015 §3）：gt 的 canonical SMILES 口径最终以 E3 的 `normalize_structure` 实现为准；E3 就位后 E5 交付前应用其口径归一，E1 入库管线不改。
- **匿名映射表归 E1**：E3 需要映射表时按 ADR-0015 §3 约定接口对接（当前未立项）。
- **get_entity_B / get_property_B / search_candidates_B**：本手册只覆盖 check_molecule_exists_B（存在性索引）；gt 的身份档/性质真值入这三个 B 库的流程待 E5 真 gt 交付时按同范式扩展（字段规格见契约 §3.2–3.4，带 case_ref 独立字段）。

## 7. 口径说明与预登记约束（Task #21 评审补登）

1. **family 多标签的消费口径（E3 切真后端前必读）**：family 多标签为 `|` 分隔字符串（§2 口径定案）。E3 切换真实后端时，若用 `sc_class eq <单标签>` 精确相等过滤，**不会命中 `|` 多标签记录**（如 `Oxide|Heavy_fermion` 不等于 `Oxide`）；消费方须按成员包含判定（`split("|")` 后判包含）。此为 ADR-0015 读取器当前算子限制（只有 eq 类精确匹配，无包含/成员算子），预先登记，E3 接查询层时不得默认精确相等语义。
2. **`open_case_gt` 来源仅限 B 侧通道**（对应闸 1 断言三加固）：`open_case_gt` 已入全局来源白名单，但结构上它是 gt 真值，只应存在于 `*_B.jsonl`；`ingest_gate.assert_sa_redline` 自 Task #21 起带 `ab_side` 通道限定，A 侧文件出现该来源一律拒收（selftest 含负例），设计理由见 `ingest_gate.py` 注释留痕。
3. **清场字节级恢复范式**：演练/回滚前先备份将动文件（B 文件/目录 MANIFEST/CHECKSUMS）到 `_build_state/rehearsal_backup*/` 并记 md5 基线；`--clean` 清回空态时目录 MANIFEST 的 note/时间戳已可幂等恢复（Task #21 修复），但入库改写过的 MANIFEST 仍需从备份恢复（时间戳锚定只保空态）；CHECKSUMS 带 generated_at 时间戳，重跑 generate_checksums 后 md5 清单一致但文件自身时间戳翻新，恢复以备份为准。

## 8. 冻结静默窗约定（Task #28 评审修复新增，2026-08-07）
