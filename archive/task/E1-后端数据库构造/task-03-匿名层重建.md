## 2. 目标（GOAL）

### 2.1 建立匿名映射表（dummy atom 载体）

**为什么是 dummy atom**（ADR-0017 的实测依据）：RDKit 无法解析元素级匿名——`a2b` → None、`[Aa]CC` → None、`FFO` → None（真元素但价规则失败）；**只有 dummy atom 可 canonical**：`[1*]CC` → `[1*]CC`、`[2*][1*]` → `[1*][2*]`。

| 要求 | 规定 |
|---|---|
| 载体 | `[1*]`、`[2*]`、`[3*]` …（同位素编号即匿名标签） |
| 禁止 | **不得把元素映射到其他真实元素**（价规则会失败） |
| 生成 | **密钥派生的确定性置换**，seed 落盘但**不公开**，重跑不变 |
| 断言 | 映射**不得与元素周期序 / 字母序单调相关**（承规范 §6.1 R4，E2 的 lint 会实判这条） |
| 落盘 | `dag_poc/data/anonymization_mapping.json`（judge 侧持有，不进 agent 可见路径） |

### 2.2 重建 A 侧库：删除真实化学身份

| 字段 | 处置 |
|---|---|
| `inchikey` | **从 A 侧返回中删除**（judge 侧保留，供评分与穷举） |
| `formula` | 改为**匿名域分子式**（按 dummy atom 计数）或删除；**不得返回 `C15H25NO3`** |
| `masked_structure` | 只允许匿名域信息（原子计数、匿名骨架），不得含真实元素符号 |
| `cif`（材料） | 元素符号须匿名化后才可返回 |

**自检断言**（请自己写，E2 的 lint 也会独立查一遍）：A 侧任一返回值不匹配真实元素符号表、不匹配 InChIKey 正则 `[A-Z]{14}-[A-Z]{10}-[A-Z]`。

### 2.3 材料侧另定身份键（补 ADR-0015 §3 的缺口）

5,771 条晶体**无 SMILES**，canonical SMILES 与 InChIKey 对周期性晶体**无定义**。

| 项 | 口径 |
|---|---|
| 身份键 | `pymatgen` 的 `Composition.reduced_formula` + 空间群（或 `StructureMatcher`），**在匿名域计算** |
| 交付形态 | 供 E3 取用的接口或落盘键列（与分子侧的 InChIKey 位置对等） |

**注意**：你在 E1-02 已报"3DSC 的 cif 列只是路径引用、`atom_count` 全 null"。若空间群无法从现有快照取得，**如实报告并给出替代键**（如 `reduced_formula` + tc 分档），不要硬凑。

### 裁定二：契约 §3.5 与 ADR-0015 的 `case_ref` 口径冲突

**裁定：采纳你的兼容解，并据此澄清契约口径。**

你报的冲突：契约 §3.5 写死 `check_molecule_exists_B` 记录只许三字段（多一个即违约），而 ADR-0015 §2.3 要求 G_B per-case 带 `case_ref`。你用「`case_ref` 承载于 `provenance.note`（格式 `case_ref=<case_id>；…`）」兼容，不增字段、可解析。

**采纳理由**：存在性接口的红线是"只返单 bool、不泄漏任何其他信息"——`case_ref` 属**评分侧元数据**，放在 `provenance` 里不进入返回值，不触红线；而增字段会动已冻结的契约结构，代价更大。

**契约以你的实现为准**，无需另立 ADR（属实现口径澄清而非契约实质变更）。请在契约 §3.5 补一句注明该承载方式。
