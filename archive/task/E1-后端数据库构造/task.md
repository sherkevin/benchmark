## 1. 上游诉求（owner 原话）

> "将我们之前调研得到的数据库深入阅读一遍，首先看看数据量，别太大导致本地解析不动了，然后看看这些数据是否足以支撑我们 tools 的构造，并制定计划着手构造（这里的意思是说我们随之发布的应该是 mock 的离线数据库作为 tools 查询的后端数据库，而不是真实去算，我们之前调研过的一些论文也是这么做的，那么我们就需要发布一个 10G 以内的查询数据库来让 tools 去调用，每个 tools 都有自己的子数据库来作为查询的结果，这个构造是一个很复杂的工作，在做之前我希望你先去调研现在的 benchmark 的 dataset 里是否已经提供了有类似的这种数据库，给出一分调研报告，包括哪些 benchmark 里有这些后端数据库，这些数据库的构造是从哪些公开数据集里得到的，这些数据集的权威性，这些数据库本身的格式和读取条件等等，我们尽量拿来用，如果用不了我们再想办法改造或者直接从我们调研到的数据库文档里抽权威数据库来自己构造，然后为每一个 tool 形成自己的一份后端数据库配置报告，包括数据数量，功能，调用方式，出入参含义等等）"

## 2. 与 GOAL 的对齐

- **本 task 服务于**：**红线"判分零联网"的落地**——权威库只在造题阶段用，题集发布时必须冻结为**离线快照**。这不是妥协：task12 已核验 GuacaMol / SciAgentArena / MatTools **判分时全部不联网**，离线快照是该领域标准做法。
- **两类任务关联**（§1.5）：**open 发现类的"A 源/B 源"要落在库的物理分层上**——B 源库的内容不能被 A 源查询顺手带出。

## 3. 硬指标

| 指标 | 要求 |
|---|---|
| **总体积** | **≤ 10 GB** |
| **本地可解析** | 单库不能大到本地解析不动（读取时间与内存需实测并记录） |
| **每 tool 一个子库** | 每个 tool 有自己的查询后端，不共用一个大杂烩 |
| **provenance** | 每条记录带 `{source_db, source_url, source_paper_doi}` 三元组 |

## 4. 执行顺序（owner 明确要求：先调研再构造）

**第一阶段——调研（先做，不许跳过）**：调研现有 benchmark 的 dataset 里**是否已提供类似的后端数据库**，能拿来用就别自己造。

调研报告必须回答：
1. **哪些 benchmark 自带后端查询库**；
2. 这些库**从哪些公开数据集构造而来**；
3. 这些数据集的**权威性**；
4. 库本身的**格式与读取条件**（文件格式、索引方式、依赖的库、读取耗时）；
5. **能否直接拿来用**——能用则用，不能用则说明改造代价，或退回自建。

**第二阶段——构造**：拿不到就从步 1 调研到的权威库自建，为每个 tool 出一份配置报告。

## 5. 子目标与验收（三要素）

| # | 子目标 | 打勾通过标准 | 验证方式 | 红线 |
|---|---|---|---|---|
| 1 | 现有后端库调研 | 覆盖已落盘的 35+ benchmark，逐个答上述 5 问 | 报告有对照表 | 跳过调研直接自建 |
| 2 | 拿来用/改造/自建的决策 | 每个 tool 的后端来源有明确结论与理由 | 决策表 | 不做决策 |
| 3 | 数据量与可解析性实测 | 每个子库记录条数、体积、**读取耗时与内存峰值** | 有实测数字 | 只报条数不报可解析性 |
| 4 | 总体积达标 | 全部子库合计 **≤ 10 GB** | `du -sh` 实测 | 超标不报 |
| 5 | **每 tool 一份配置报告** | 含数据数量/功能/调用方式/出入参含义 | 每个 tool 一节 | 只给总览不逐个写 |
| 6 | A/B 源物理分层 | B 源内容不被 A 源查询带出（需给出隔离机制与验证） | 有隔离测试 | A 查询顺手返回 B 数据 |
| 7 | 入库即校验 | 每条入库时做身份校验（如分子用 RDKit 算分子式比对来源库），不一致则拒收 | 有校验门脚本 | 无校验直接入库 |

## 7. 已知坑

1. **3DSC 不含"常压/高压"列**——`condition` 字段**必须人工按文献标注**，不能从数据推导。这是 open 类陷阱题的核心字段（LaH10 的 Tc=250K 只在 ~170GPa 成立）。
2. **15 条 SMILES 错配未修**（T-55），影响 12/37 既有 case 的 gt。PubChem 40/40 身份已落盘，**数据已就位可直接修**。
3. **现有 9 个 tool 是硬编码假实现**（`predict_binding` 恒返 −8.5 等），这些 tool 的后端库要从零建。
4. **`crystal_generate` 的 tc/bandgap 全 0 需改为"未知/待评估"**，否则 agent 会把 0 当真值。
5. **ChEMBL 是 CC-BY-SA**，只存 ID + 查询配方，不 bulk dump。

## 8. 不做的事

- ❌ 不定 tools 数量与出入参（E3 定，本 task 按其清单建库）；
- ❌ 不写 query / template / case（E2、E5）；
- ❌ 不真算性质（红线：发布的是 mock 离线库，**不真实计算**）；
- ❌ 不引 DFT 预测值当真值。
