## 一、原先问的问题（问错了）

我问的是：**总库里存不存在**一对 (start, target)——start 有实测值但不满足画像、
target 是 start 的 ≤2 步编辑产物、在库内、满足画像，且 start 的全部产物中只有 target 一个满足。

**这个问法把静态总库当成了不可变前提**，等于用"库里现成有什么"倒推题面。
owner 原话：**"我们的数据库是完备的，如果不完美，你需要去补充一些数据。我们不能因为
数据库里哪些是唯一可查的，就把这个定为我们这批题面，因为本身我们是想批量构建题面的。"**

## 五、新方案要正面解决的那一条（依据③）

答案唯一**不能靠收窄数值窗口**（那是旋钮）。可走的两条，都是**离散、零超参**：

### ⚠️ 更正：本节初稿的"agent 交上可见集里那一个，判分会给分"是错的，实测已否证

初稿从"比对器说这俩组成相等"直接推出"照抄可见的那个就得分"——**推的，没量给分路**
（正是 `ACTION_RULES` 禁的以推代证，兼坑② 过度升级负面发现）。补量后：

判分不是只调 `composition_equal`。`evaluate._composition_index._lookup` 是
**精确键先查、查不到才走 ε 容忍扫描**，所以交库内精确式只会解到它自己：

```
case_dh_material_03  G_B=['c09642']
  交可见末位原式 Hg0.9Re0.1Ba2Cu1O4.41 → resolve=['c09641']  命中 G_B = False
  直接交实体 ID  c09641                                      命中 G_B = False
```

`material_11`（`Zr2Rh1H0.1`→`['c15680']`）、`material_13`（`Sr0.065Bi2Se3`→`['c12564']`）
同形，**都是 False**。隔离层没漏：照抄可见集判 0 分。

**真正的病是另一件，也是量出来的——题意外推步长 ≤ 判分容差 ε=0.02。**
交的组成只要不是库内精确键，就掉进 ε 扫描、连带命中 gt：

| 视图 | 步长 | 末位抹个零头 | 反方向外推 |
|---|---|---|---|
| `case_dh_material_03` | ΔO=0.01 | `O4.415`→`['c09641','c09642','c09643']` **命中** | `O4.43` 也**命中** |
| `case_dh_material_11` | ΔH=0.02（恰等于 ε）| `H0.09`→`['c15677','c15680']` **命中** | `H0.11` 不中 |
| `case_dh_material_13` | ΔSr=0.003 | `Sr0.064`→`['c12563','c12564']` **命中** | `Sr0.07` 也**命中** |

⇒ 这三题考的不是外推：**贴着可见末位随便写个库里没有的数就命中**，`material_13`
连方向搞反也给分。所以 #50 要处置的不是"把那个碰撞实体从可见集换掉"（换掉步长仍是 0.01），
而是**让题意步长大过 ε**。⚠️ 不许反过来收窄 ε——那是坑⑨ 调旋钮，且 ε=0.02 是 occupancy
小数口径（裁定 2），改了还会与判分器脱钩。

**已落地的修法**（改的是"用错了尺子/解析错了域"这个**错**，不是阈值——断言只变严不变宽，
证据：修完当场红了 3 个此前全绿的生产视图）：

1. 组成口径**只留一份实现**：`per_case_view.parse_anon_formula` / `composition_equal`
   直接借判分侧的 `_formula_composition` / `composition_equal`（两形态都认、ε=0.02）。
   判分模块**惰性**加载——本模块被 agent 面 MCP 工具服务 import，判分侧能力不进那条路
   （ADR-0018 修订 R1-②）；实测工具面 import 后 `src.benchmark.evaluate` 不在 `sys.modules`；
2. 加 `as_label_composition`：视图 gt 的键是 `str`、判分侧解析器出 `int`，
   `composition_equal` 按 `set(a)|set(b)` 逐键比 ⇒ 不归一就恒判不等（第三层假绿）；
3. **不空转自证写进断言**（新 `A1.gt_invisible_probe` / `A6.composition_probe`，38/38 绿）：
   把一个「组成与 gt 相同、可见集外」的真实库内实体注进可见集副本，这两道检查必须**当场变红**；
   变不红就判它空转。`check_gt_invisible` 另加第③条：比对器连 gt 自己都认不出就直接判不予采信；
4. `case_dr_aedit_01` 把 `gt.composition` 当答案计数用（`{"higher": 10, "lower": 10}`）——
   新 `A1.gt_comp_form` **明说**它组成口径不适用（只许 `entity_ref` 为空的库外形态这么填），
   不再静默当成"组成为空"；
5. `make_example_view.parse_formula` 是同一个死解析器的第三份拷贝 ⇒ `pick_series` 挑不出族序列、
   整份自检在末尾 `RuntimeError` 退出（§六之二 第 3 条）。改成走同一份实现后**自检第一次跑完**。

## 六之四、顺着那次更正往下查：照抄即得分的题真的有，但不在这三个（2026-08-28）

上一节的更正只否掉了"这三个材料题照抄得分"。既然错在**没走给分路**，就把给分路本身
全量扫一遍：37 个已注册 open case，逐个把**可见集每一个实体**当答案交给
`resolve(·) ∩ G_B`。

| 量到的 | 数 |
|---|---|
| 交 gt 组成命中（判分认得出正确答案，**本次扫查非空转**）| **36 / 36** |
| **照抄某个可见实体即命中 G_B** | **3 个 case**（`case_dh_drug_09` / `_10` / `_13`），每题**族内 3 个成员全中** |
| 反方向同步长外推也命中（方向不构成判别）| 4 个（上面两个 drug + `material_03` / `material_13`）|
| 只挪半步就命中（步长不构成判别）| 7 个（再加 `material_02` / `material_04` / `material_11`）|

**照抄得分的病根与 ε 无关，是另一条口径**：这三题的同系列递变轴就是**H 计数**
（`C10H14O3 → C10H12O3 → C10H10O3`，gt `C10H8O3`），而 `resolve` 对分子域
**剥 H 后补查**（R1-② 冻结口径，防"实体 formula 形态作答的 H 计数造成漏判"）
⇒ **整条同系列塌到 gt 上**，可见集里三个成员交上去全命中。

⚠️ 这三题此前 `A1.gt_invisible` **全绿**——因为它用的是 `composition_equal`（不剥 H，
组成差 2 ⇒ 判不等），而**判分不走这条**。所以：

> **通用教训（本节的真正产出）：断言必须走判分实际给分路。**
> 代理口径绿不算数——`composition_equal` 与 `resolve` 差着剥 H 和精确键两条分支，
> 上一节我用代理口径推给分结论错了一次，断言用代理口径同样漏了三题。
> 同类先例（有出处的）：任务 #40 那三条死解析器空转、
