# Checkpoint 按核验级别分档(= 数据集构造说明)

> **本文 = 数据集构造说明**:我们怎么把 checkpoint 分类(硬校验 / AI 判官 / 人工)+ 怎么把它们串成一条 trace(分类→找点→合成)。**第二步「找点」从哪些 benchmark 挖 cp,见解读卡索引** [`benchmark-cards-index.md`](benchmark-cards-index.md)(⚠️ 用 Obsidian 打开)。
>
> **一句话**:一个 checkpoint(cp)= trace 里的一个"中间检查点"。**好不好,看谁来判、能不能复现**——机器跑脚本就能判的最宝贵,必须人来判的最弱。我们设计题目时,**优先把 cp 做成硬校验**,把题目串成一条 trace。
>
> **本文只回答三件事**:每一类 cp 是什么 → 我们调研里有没有现成的真实 case → 怎么用到我们药物/材料题目上。
> 所有 case 都来自我们**亲核过**的数据集(指针见每条末尾),不引未验证的外部论文。

---

## 总览:三档,越往上越宝贵

| 档 | 谁来判 | 能复现吗 | 成本 | 该占多少 |
|---|---|---|---|---|
| **Tier 1 · 硬校验** | 机器跑脚本 | ✅ 完全可复现,跑一万次结果一样 | 几乎为零 | **主力,目标 70%+** |
| **Tier 2 · AI 判官** | LLM 当裁判,按细则打分 | 🟡 要做一致性校准才可信 | 中(每次都要调 LLM) | 少量,只放规则写不出来的 |
| **Tier 3 · 人工** | 领域专家看 | ❌ 主观、慢、贵、换个人就变 | 高 | **能不用就不用**,主要拿来给 Tier 2 当标尺 |

**核心原则一句话**:**能 Tier 1 就别 Tier 2,能 Tier 2 就别 Tier 3。**

---

## 方法主线:一个 case 怎么造出来(三步)

> **这是本文的使用方式**,也是我们后续造题的固定流程:**先给 cp 分类 → 再到现成数据集里挖具体 cp 点 → 最后把一串 cp 按科学流程串成 trace,一个 case 就成了。**

```
第一步 分类          第二步 找点              第三步 合成
(定模具)    ──→    (挖真实 cp)     ──→    (串成 trace)
按核验级别        到亲核数据集里挖,        挑真实科学任务,
分三档,           硬校验优先,            按 agent 真实阶段
逼自己往           每个 cp 记下           排开,每阶段挂
Tier 1 靠         判什么/校验/真值        1~N 个 cp = 一个 case
```

**第一步 · 分类(定模具)** —— 就是下面的三档 palette。拿到任何一个任务步骤,**按顺序问三句话**:这一步能不能机器跑脚本判(→ Tier 1)?不能,能不能让 LLM 按细则判(→ Tier 2)?还不能,才上人工(→ Tier 3)。这一步的唯一目的:**逼自己尽量把每个 cp 往硬校验靠**。

**第二步 · 找点(挖真实 cp)** —— 不凭空编 cp,从我们亲核过的数据集里挖现成的,硬校验优先:

| 想要的 cp 类型 | 去哪个数据集挖 |
|---|---|
| 数值 / 集合 / 排序(硬校验主力) | DO Challenge、Matbench·MPtrj、SEISMO/PMO |
| 结构 / 守恒 / 工具落地(硬校验) | PhysicianBench、AgentBoard、RDKit + 化学定律 |
| 实在硬不了的语义判断 | HealthBench 负分细则、MedHELM 三判官 |

每挖出一个 cp,记三件事:**判什么 · 用哪档校验 · 真值从哪来**。(真值越是"物理/规则自带、零人工"的,这个 cp 越值钱。)

**第三步 · 合成(串成 trace)** —— 挑一个真实科学任务(药物虚筛 / 材料弛豫 / 靶点设计),按 agent **真实会走的阶段**(读题 → 策略 → 探索 → 决策 → 提交 → 报告)排开,每个阶段挂 1~N 个 cp。这一串有序 cp = 一条 trace = **一个 case 就设计好了**。合成时守三条:**硬校验占 70%+ · 同一阶段叠不同类型 cp(防钻空子)· 部分得分不连乘**。

> 下面 Tier 1/2/3 三节是第一步的"模具明细";最后"一道题怎么串成 trace"一节是第三步的完整示例。

> **现实佐证(2026-06-09):χ-Bench 用的就是这套。** 同期医疗运营 agent benchmark **χ-Bench**(arXiv:2605.16679,actAVA + Eric Xing 等)的造题法与本文三步几乎一字不差:Step1 从终态反向生成 + **per-stage rubric**(= 第一步分类 + 第二步找点)→ Step2 标注员人工走查录轨迹当 GT → Step3 多人审核(= 第三步合成 trace);其打分用**复合验证器 = 确定性合约(= 我们的 Tier 1 硬校验)+ 多票 LLM judge(= 我们的 Tier 2 AI 判官)**。即:**我们这套"三档 + 三步法"不是凭空设计,已有 published 先例佐证**(也意味着这两点在论文里定位为"采用已验证范式"而非首创)。详见 [`result.md`](result.md) §A4 与 [`archive/survey_landscape.md`](archive/survey_landscape.md) C5。

## Tier 1 · 硬校验(最宝贵,机器自动判)

跑一段脚本,输出 pass/fail 或一个分数,**没有第二种解释,换台机器结果一样**。你说的"调用工具得到一个值、中间 check 这个值对不对"就是这一档。下面 6 种形式,**前三种(数值/集合/排序)是绝对主力**。

### 1. 数值校验 ⭐ 最宝贵

- **判什么**:agent 算出的数字,落在容差里没有。`|预测值 − 真值| < ε`,或落在某区间。
- **真实 case**:**Matbench Discovery 的 MPtrj**——158 万个 DFT 弛豫中间帧,每帧都有真实物理量(能量、每个原子受力、应力)。可以直接判"agent 跑到第 N 步后,平均原子受力是否 < 0.01 eV/Å"(物理上"接近收敛"的硬标准),真值来自 DFT 计算本身,**零人工标注**。
  - 指针:`~/papers/Matbench Discovery.md`(数据格式见卡)(MIT 协议,数据现成)
- **AI4S 怎么用**:agent 算分子 logP = 2.31,真值 2.28,容差 ±0.1 → pass;docking 算出结合能落在 [−12, −6] kcal/mol → pass;预测材料形成能,与 DFT 真值差 < 0.05 eV/atom → pass。

### 2. 集合校验 ⭐

- **判什么**:agent 给的一堆东西,和正确集合的交集有多大。`|提交 ∩ 真值| / |真值|`。
- **真实 case**:**DO Challenge**——100 万个候选分子里找出真正排前 1000 的。最终分 = `|你提交的 3000 个 ∩ 真前 1000| / 1000`。这是个纯集合交集运算,机器一秒判完。中途还能插集合 cp:"花掉 50K 预算后,已筛样本里前 1000 命中率有没有 ≥ 20%"。
  - 指针:`~/papers/DO Challenge.md`(数据格式见卡)(CC-BY-4.0,数据完全公开)
- **AI4S 怎么用**:agent 从数据库召回 20 篇相关文献,和金标准文献集求交集;agent 筛出 50 个候选材料,看有几个真在稳定相里。

### 3. 排序校验 ⭐

- **判什么**:agent 给的排序/曲线对不对,或"多快到达"。
- **真实 case**:**SEISMO/PMO**——分子优化,把"达到目标分所需的 oracle 调用次数"积分成一个 AUC 标量。**两个 agent 最终都到 0.9 分,但一个 20 步到、一个 200 步到,AUC 就不同**——这正是"过程量"最直观的硬指标。
  - 指针:`~/papers/SEISMO-PMO.md`(数据格式见卡)(MIT 协议)
- **AI4S 怎么用**:agent 给候选分子按预测活性排序,算和真值排序的 Spearman 相关;材料筛选算"加速倍数"(Matbench Discovery 的 DAF = 精度/基线命中率,DAF=6 表示比随机快 6 倍)。

### 4. 结构/语法校验

- **判什么**:agent 产出的中间物"长得对不对"——能不能被解析、字段齐不齐、代码对不对。
- **真实 case**:**PhysicianBench 的判定点 4**——agent 有没有在系统里下"冠脉 CT 血管造影"检查单,纯靠代码查:名称含 "coronary CTA"、CPT 代码 = 75573/75574、状态 = active,**全规则匹配,不要 AI**。
  - 指针:`~/papers/PhysicianBench.md`(详见卡)(670 个判定点,其中相当一部分是这种纯代码 grader)
- **AI4S 怎么用**:agent 写的 SMILES 能不能被 RDKit 解析;agent 给的靶点 JSON 里 UniProt ID / 序列 / 结合位点字段齐不齐。

### 5. 守恒/不变量校验(没有标准答案也能硬判)

- **判什么**:agent 不用给"对的答案",但必须遵守已知物理/化学定律。违反 = 错,机器一查便知。
- **真实 case**:这是软件工程里几十年的"无标准答案怎么测"的成熟答案(property-based testing),直接搬到化学。
- **AI4S 怎么用**:agent 提出的反应必须**质量守恒、电荷守恒、化学计量数为整数**;同一分子的 SMILES 规范化两次结果必须一样(幂等)。**对没有 ground truth 的科学任务尤其值钱**——这是我们材料/药物题目能大量造硬 cp 的关键。

### 6. 工具执行/状态落地校验

- **判什么**:agent 真调了工具、真改了环境状态,工具说成功就是成功。
- **真实 case**:
  - **AgentBoard 进度公式**——把任务拆成有序子目标,每个用正则匹配 agent 的环境观察文本(看到 "You put mug in microwave" → 子目标 1 完成),`进度率 = 完成子目标数 / 总数` 取历史最大值。和人类打分相关性 ρ > 0.95。
    - 指针:`~/papers/AgentBoard.md`(数据格式见卡)
  - **TheAgentCompany**——确定性 Python 检查环境状态(git 提交了没、文件改了没)。⏳ 注:源码层 P0 待亲核。
- **AI4S 怎么用**:agent 调 AiZynthFinder 跑逆合成,返回非空路线 → pass;agent 真跑了 DFT 且没发散 → pass。我们每道题拆成有序子目标(读对文献 → 调对工具 → 算对数值 → 得对结论),套 AgentBoard 进度公式。

## Tier 2 · AI 判官(只放规则写不出来的)

有些东西规则判不了——比如"这个分子结构算不算新颖""这段推理符不符合指南""报告里这句话有没有被前面的数据支撑"。这时让 LLM 当裁判,**但必须按预先写好的细则打分**,而且**必须做一致性校准**才可信。

### 1. 细则打分(rubric judge)

- **判什么**:专家写好一张细则清单(每条尽量写成"有没有 X"的近二值判断),LLM 逐条判 agent 的产出。
- **真实 case**:**HealthBench**——190 位医生写的评分细则,关键是**支持负分**:做对了加分(+8 提到要看是不是细菌感染),做了不该做的扣分(−10 直接开抗生素不评估病情)。最终分 = 拿到分 / 满分,截断到 [0,1]。
  - 指针:`~/papers/HealthBench.md`(数据格式见卡)(MIT 协议)
- **AI4S 怎么用**:agent 提出新分子,judge 判"和已知 chemotype 是否结构新颖""claim'DFT 确认稳定'前面是不是真有 DFT 输出"。每条细则一个近二值判断。
- **κ 校准一句话**:每条细则要跟人工抽样比一致性(κ),**κ < 0.7 的条目重写或降级到人工**;固定 prompt、固定模型版本、温度 = 0,换模型就重测。

### 2. 多判官投票(jury)

- **判什么**:一个 LLM 判不稳,就用 3 个不同的 LLM 各打分取均值。
- **真实 case**:**MedHELM**——GPT-4o + Claude 3.7 + LLaMA 3.3 各自按 3 个维度打分,9 个分取均值,和真实医生间一致性接近(ICC 0.47 vs 医生间 0.43)。
  - 指针:`~/papers/MedHELM.md`(数据格式见卡)(Apache-2.0,换轴即可用)
- **AI4S 怎么用**:把评分轴换成"科学严谨性 / 方法正确性 / 结果准确性",3 judge 投票。

### 3. 混合判官(代码 + AI 拼接)

- **判什么**:一半硬一半软——先用代码确认 agent 真调了工具(不是编的),再让 LLM 判产出的文字质量。
- **真实 case**:**PhysicianBench 判定点 1**——先代码确认 agent 真调了拉病人数据的工具,再让 AI 按细则判报告里有没有提到"70 岁女性""M-spike 1.8 g/dL"等具体事实点,打 PASS/PARTIAL/FAIL。
  - 指针:`~/papers/PhysicianBench.md`(详见卡)
- **注意**:它把 PARTIAL 压成了 FAIL,半对信息丢了——我们改造时要让 PARTIAL 透出来(部分得分)。

## Tier 3 · 人工(最弱,主要当标尺)

只有上面都做不到、且事情很关键时才用。**人工的主要价值不是大规模评测,而是给 Tier 2 的 AI 判官当金标准**——标 50–200 条,算 AI 判官和人的 κ,定期复测。

### 专家评分 / 整体复核

- **何时不得不用**:科学新颖性、机理创造性、报告整体连贯性——这些没有可机器化的标准答案,只能专家整体判断。
- **真实 case**:**AutoMat**——40 位材料专家盲评,和 LLM 判官算出 κ=0.69(substantial agreement),专家评分就是用来校准那个 LLM 判官的。⏳ 注:P0 待亲核。
  - 指针:`result.md` §A2
- **用法**:① 给 Tier 2 当 κ 校准的金标准;② 抽检 Tier 1 有没有被 agent 钻空子(形式上 schema 对了但内容是空壳);③ 给 Tier 2 重写细则提供样例。
- **不要拿来**:每条 trace 都人工打分(贵、慢、不可复现)。

## 一道题怎么把 cp 串成 trace(第三步完整示例,改造 DO Challenge)

这就是**第三步"合成"的样板**:把第二步挖到的一串 cp,按 agent 真实阶段排开,串成 trace = 一个 case。任务:**100 万候选分子里,在 10 万次实验预算内,提交 3000 个,命中真前 1000**。

| # | 阶段 | checkpoint | 档 | 形式 |
|---|---|---|---|---|
| 1 | 读题 | agent 给的靶点 JSON 字段齐全(UniProt/序列/位点) | **T1** | 结构校验 |
| 2 | 策略 | 前 50K 预算花完,已筛集前 1000 命中率 ≥ 20% | **T1** | 集合校验 |
| 3 | 探索 | 采样分子的 SMILES 全部能被 RDKit 解析 | **T1** | 语法校验 |
| 4 | 探索 | 候选打分曲线随预算单调上升(没瞎跑) | **T1** | 排序校验 |
| 5 | 决策 | agent 中途换策略的理由是否站得住 | **T2** | 细则判官 |
| 6 | 提交 | 最终 3000 个 ∩ 真前 1000 / 1000 | **T1** | 集合校验 |
| 7 | 报告 | 报告每条结论是否被前面步骤数据支撑 | **T2** | 细则判官 |
| 8 | 整体 | 专家给"这工作敢不敢只在终审复核"等级(仅 50 条样本) | **T3** | 当 κ 标尺 |

**硬校验占 5/8 ≈ 63%**,AI 判官 2 个,人工只做样本校准。每道题都按这个思路:**尽量多堆硬 cp,把软的挤到最少**。

## 4 条设计铁律

1. **能硬校验就别上 AI 判官**。没有标准答案 ≠ 必须人工——守恒律、幂等、单调、集合交集都是免费的硬 cp。
2. **每个 AI 判官 cp 必须配一个人工校准样本集**(50–200 条),定期重测 κ。**AI 判官不校准 = 自欺欺人**。
3. **部分得分,别全对全错**。一条 99% 正确的 trace 不该因为一步错就归零——各 cp 加权求和,不要连乘。(PhysicianBench 的 `通过 cp 数 / 总 cp 数` 已现成,升为主分即可。)
4. **同一阶段叠几个不同类型的 cp**。单一类型容易被 agent 钻空子(学会形式正确但内容空洞),叠正交的硬 cp 才稳。
