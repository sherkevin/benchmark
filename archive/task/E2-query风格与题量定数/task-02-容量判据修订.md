## 1. 改 §4.8 容量判据（主任务）

完整依据见 [`裁定-题量容量判据修订.md`](../_prompts/裁定-题量容量判据修订.md)。

### 1.1 问题：判据看的是实体数，真正的约束是可造题格数

E1 已交付 A 侧库，**按你 §4.8 的判据完全达标**：药物 **74,941**（≥10⁴，超额 7 倍）、材料 **5,771**（达标）。

**但性质覆盖没跟上**（监工实测 `get_property_A` 聚合）：

| 性质 | 有值分子数 | | 组合 | 同时有值 |
|---|---|---|---|---|
| logS | 2,311 | | bbb + herg | 50 |
| bbb | 757 | | **bbb + herg + caco2** | **14** |
| caco2 | **235** | | 按现有 case 约束 `bbb==1 AND herg==0` | 19 |
| herg | **104** | | 再加 caco2 有值 | **7** |

**14 个分子撑不起你冻结的 60 道药物题。** 这不是你的过失（E1 交付前无从得知），但判据必须改。

### 1.2 五处要改

1. **§4.8 判据替换**为「**可造题格数**」：
   - 类型1 可用格 = 切分后**格内目标量最优者唯一**的格数；
   - 类型2 可用格 = 格内成员 **≥3** 的格数。
   - **必须写明 `|G|=1` 的正确语义是"最优者唯一"，不是"候选池仅 1 个成员"**——按后者理解会把材料侧容量从 69 格误算成 10 格（**监工首次计算时就犯了这个错**，已纠正，请把这条澄清写显眼）。

2. **附实测容量表**（监工已跑，直接引用）：

   | 格 | 需要 | 类型1 可用格 | 类型2 可用格 |
   |---|---|---|---|
   | 药物 | 30+30 | **154** | **91** |
   | 材料 | 30+30 | **69** | **59** |

   切分参数：药物 `(atom_count//5, round(logS))` → 156 非空格；材料 `(family, tc五档, 元素种类数)` → 73 非空格。**四格全部达标，总 150 与药材 1:1 维持不变，不走变更 ADR。**

3. **M5 的药物侧示例更新**：从"bbb + herg + caco2 三性质"改为「**1 个密集性质 + 结构约束**」= `logS`（2,311 个有值）+ `atom_count`（92 种取值）；注明原三性质交集仅 14 个、不足以支撑配额。

4. **`query_spec.json` 增注记（不改任何数字）**：
   - `capacity_basis`：切分维度 + 四格可用格数
   - `material_constraints`：`exclude_tc_zero: true`、`condition_annotated_only: 16`

5. **保留原三性质题型为「第二版候选」**，待 ADMET 覆盖补齐后启用，**不要删除**。

### 1.3 材料侧两条硬性前置（实测得出，须写进规范）

1. **必须排除 `tc == 0`**——占 **1,764 / 5,771 = 30.6%**（3DSC 含非超导样本）。不排除会把非超导样本塞进"最大化 Tc"的排序题。
2. **题面不得限定"常压 / ambient"**——实测 `condition` 分布：`未知` **5,755** / `ambient` **15** / `high_pressure` **1**，**仅 16 条有人工标注**（3DSC 原始数据无此列）。限定常压则可用池只剩 15 个。替代写法：题面用 `in the candidate database` 限定范围，不声称常压。

### 2.2 `query_lint.py` 增 `provenance` 形态断言（ADR-0016 影响项）

**新增规则**：`provenance` 必须含**真实论文/报告标题 + DOI 或 URL**。

**不接受纯数据来源**——现有 37 case 的 `provenance` 全是 `mock_db.admet（真值来自…证据文档）`这类，**37/37 不合格**。注意区分：
- 后端库的 `provenance`（如 `TDC_ADMET:BBB_Martins` + Harvard Dataverse URL）是**数据溯源**；
- ADR-0016 要的是**题目背书**（这道题的科学依据出自哪篇论文）。
- **两者不是一回事，不能互相替代。**

断言建议：正则检测含 `10.\d{4,}/`（DOI）或 `https?://`，且字段长度 > 阈值、不匹配 `mock_db|snapshot|证据_` 等纯数据来源模式。
