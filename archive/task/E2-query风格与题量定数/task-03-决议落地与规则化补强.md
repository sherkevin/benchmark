## 3. 解决一处规范内部矛盾（造题放量前必须解决）

**§5.4 与 M9 冲突**：

- §5.4 要求类型1"**沿用已落盘 query_template 句式…只填 slots，不改句式骨架**"；
- M9 要求"开头两词模式种类 ÷ 该类题数 **≥ 0.3**"。

**实算**：60 道 type1 若全以 `Identify a/an …` 开头，变体率 = 2/60 = **0.033 ≪ 0.3**，**必然违 M9**。当前只有 2 个 case（`identify a` / `identify an`）使 ratio=1.0，把矛盾掩盖了。

**要做**：给出可执行的解法并写进规范。可选方向（你定，但须写清依据）：
- 为类型1 定义 **N 个允许的主句式骨架**（N ≥ 0.3 × 该类题数 ⇒ type1 需 ≥18 种开头两词模式），并给出骨架清单；
- 或把 M9 的变体率下限按"骨架数 / 题数"重新推导，并说明为何该下限仍能防"记住一题迁移全类"。

**同时**：按 ADR-0016 修订 R1，M9 的变体率校验从库级挪到**每批冻结时**执行（滚动新增规则只许黑名单、不许白名单句式，否则会持续压缩表达空间）。
