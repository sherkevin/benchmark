## 1. 上游诉求（owner 原话）

> "看看背书过的 benchmark，看看这些 benchmark 的 data 里的 query 是怎么写的，有哪几类（这一步说的背书指的是该 benchmark 的论文里说明了本 query 是怎么构造的，一般是被专家 check 过的，那么我们认为这就是比较好的 query，学习其风格，模板结构，同样产出一份 query 格式和风格的文档出来，标注出我们构造的 query 必须是什么风格的，模板有哪几类，每类数量是多少，这里的模板类别数和总数量取决于我们看到参考论文的 benchmark data，从中看看他们的数据集的数量和模板数量是多少，从而去找到一个合适的便于我们发布论文的数据量的数值）"

## 2. 与 GOAL 的对齐

- **本 task 服务于**：GT-first 反查法**第 2 步（构造专属 query）的规格制定**——不是自己造题，而是**先定下"题面必须长什么样、总共造多少题"这把尺**。
- **为何必须先做**：题量与模板数一旦开工后再改，E5 已造的 case 会大面积返工。**这是必须前置冻结的参数**。

## 3. 关键：本 task 的"背书"口径与步 1 不同

| | 步 1（E1）的背书 | **本 task 的背书** |
|---|---|---|
| 对象 | **数据集** | **benchmark 的 query** |
| 判定 | 该数据集被其他论文用于造 benchmark | **该 benchmark 论文里明确说明了 query 如何构造**（一般经专家 check） |

**只有论文交代了 query 构造过程的 benchmark，其 query 才被视为"好 query"、值得学风格。**

## 4. 子目标与验收（三要素）

| # | 子目标 | 打勾通过标准 | 验证方式 | 红线 |
|---|---|---|---|---|
| 1 | 背书 benchmark 的 query 原文汇编 | 每家 **≥10 条 verbatim 原文**（不是转述、不是自己编） | 逐条可回溯到原始文件 | 用自己的话概括代替原文 |
| 2 | 风格实测（不靠印象） | 四维**量化**：①口语 vs 术语 ②约束显式到哪一步（"常温"还是"26℃"）③是否"为了X满足Y做Z"模板 ④单 benchmark 是单模板还是多模板 | 有脚本+统计数字 | 凭感觉下结论 |
| 3 | **我方风格硬约束** | 明确写出我方 query **必须**满足什么、**禁止**什么（可被 E5 当检查表用） | 条目可逐条打勾 | 只描述别人不规定自己 |
| 4 | **模板类别数定数** | 给出我方模板分几类 + **每类的依据** | 每类有对标出处 | 拍脑袋定数 |
| 5 | **题量定数** | 给出总题量与每类题量，**依据是参考论文 benchmark 的实际规模统计** | 有"各 benchmark 题量对照表"支撑 | 无依据地报一个数 |
| 6 | 覆盖 fixed 与 open 两类 | 两类各自的题面风格与题量分别给出 | 文档有两节 | 只考虑 fixed |

## 6. 已有的关键实测结论（可直接采信，不必重测）

来自 task16 的 223 条样本实测（抽样口径：其中 Toolathlon 为 12/108 抽样、ScienceAgentBench 为 41/102 经专家改写）：

- **`D` 交付段是唯一 100% 必需段**（ScienceAgentBench 102/102 均有且压在题面末尾）→ 题面必须写出判分器要读的字段名；
- **主流是 `A动作 → D交付` 两段式**；
- **约束显式度低于预期**：只有 <17% 的 query 给出具体数值阈值，多数给定性描述；
- **题面长度差异极大**：中位数 31–177 词，跨 5.7 倍；
- **第一人称口语是可接受的**（ChemCrow/Toolathlon 实测使用），**并非必须客观书面语**；
- **RE-Bench 7/7 把评分公式写进题面**（适用于有优劣梯度的题）。

> 这三条曾推翻我方先前的猜测（"专家会给数值阈值""专家 query 都很长""题面必须客观书面"）。**认领者不要重复这些猜测。**
