## 2. 要补的四条规则

| 规则 | 判据 | 依据 |
|---|---|---|
| **梯度参数范围** | `n ∈ [3,5]`、`d ∈ [1,2]`、`K ∈ [20,30]`；三者缺一即违规 | ADR-0018 §3.2 |
| **干扰项硬下限** | `K ≥ 10`，**低于即违规**（K=0 会让质量门第一条退化为重言式） | ADR-0018 §3.2 强制项 |
| **`view_ref` 有效** | 非 null，且指向的文件在 `dag_poc/data/backend/per_case_views/` 下真实存在 | E1-05 交付格式 |
| **`g_b` 注册** | 该 case 的 `g_b` 在 `b_partition.json` 的 `cases[<case_id>].g_b` 中存在，且与 case JSON 内的值**一致** | ADR-0018 修订 R1-① |

### 2.1 三条实现要求

1. **只对 open 类 case 生效** —— fixed 类没有这些字段，不要误报。用现有的 open 类识别逻辑做前置过滤。
2. **`g_b` 一致性要双向查** —— 不只查"注册了没有"，还要查"注册的值与 case JSON 里的是否相同"。只查存在性会漏掉"注册了但内容不对"。
3. **`view_ref` 要查文件真的在** —— 只查字段非 null 不够，路径写错了一样跑不通。

## 3. 一条口径要改：M13 领域均衡

现在 M13 判「每类模板内药物与材料题量均分」，对 open 类实测报违规：`drug=15, material=0`。

**但这是硬前置条件导致的，不是缺陷**：材料侧受「E3 接口 B 扩展完成前不得按降级键造材料题」阻塞，31 达标族里只有 3DSC 的 5 个可用，本批最多出 3～4 道（见 E5-04 §2）。

**要做**：给 M13 加一个**分阶段口径** —— 允许 case 集声明"分批构造中"的状态（例如通过 `query_spec.json` 的批次字段），在该状态下 M13 降为**告警而非违规**，冻结批次时才升为违规。

**不要直接删 M13**——领域均衡是 goal §6 步 2 定的配比要求，只是判定时机要分阶段。
