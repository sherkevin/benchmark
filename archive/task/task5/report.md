# Task5 结论 — 分阶段(并行) vs 不分阶段(单步) 的效果区别

> 目标:验证「多步并行执行」与「一起做(单步顺序)」两种回答模式的效果差异。
> 方法:6 道多阶段 pipeline 题 × 两模式,全程 API 驱动,2026-06-04 实测。详见 `results.md`。

## 一句话结论

在当前 NobelClaw 平台上,**两种模式最大的、可复现的效果差别是"能不能把任务做完并交付一份完整答案":单步 6/6 全部跑完并产出完整报告;并行 0/6 能跑完——它每次都在最后"汇总"步骤之前卡死,交付不出成稿。** 答案数值精度上两者无法区分(平台预测工具停摆,两模式都只能凭记忆/文献作答)。

## 三条具体发现

1. **交付可靠性:单步完胜。**
   - 单步:**6/6 完成**,平均成稿 4157 字,完整走完 1–5 步、派生计算自洽。
   - 并行:**0/6 完成**,`synthesis_start`(汇总)事件 **一次都没出现**——多个子 agent 并行跑完后,后端在 join/汇总处挂起,连接永不关闭,用户永远等不到最终答案。交付物平均仅 2041 字,且是子 agent 的中途片段(SC-P1 只有 122 字、AD-P1 为 0 字)。

2. **稳健性:并行更容易出错。** 并行工具报错合计 24 次 ≈ 单步(13)的两倍,且有**并行独有**的工具名翻倍 bug(`crystal_predictcrystal_predict`,直接导致一次无效调用)。根因:并行模式给每个子 agent 灌入完整原题 + 各自子任务、彼此隔离、最后才由一个**独立 synthesizer**(只拿到各子 agent 截断到 3000 字的文本、拿不到工具原始输出)汇总——既冗余又易不一致,而且这一步实测会挂死。

3. **是否触发分解是随机的。** 同一道题不同次发送,有时弹"分阶段/不分阶段"、有时直接答(初始发送 12 次中 8 次触发;AD-P1 两次都没触发)。所以"必须先触发选择"这个前提**不是每次都满足**,实验时需重试到触发为止。

## 重要前提(诚实标注)

本结论是在**平台预测后端整体不可用**的状态下得到的:`crystal_generate`(DiffCSP)离线、`crystal_predict` 无可用 cif、`predict_admet` 是 mock 肽类过滤器(不产小分子 logS/logD/BBB/hERG)、半导体无带隙工具。因此:
- "数值正确性"上测不出模式差异——两模式都退化为 LLM 记忆+文献,易记事实(GaN 带隙、caffeine 溶解度、超导 Tc 排序)单步多数答对,难题(SMILES 识别)仍会错。
- 真正测到的差异落在**编排与交付**层面(完成率、报错率、是否产出成稿),而非科学预测精度。
- **若要纯粹比较两模式的"科学答案质量",需先恢复 DiffCSP/crystal 等真实预测工具**;在那之前,"并行模式跑不完、交付不出"这一条已是足够明确且可复现的效果区别。
