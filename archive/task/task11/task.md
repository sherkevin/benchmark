# task11 — 数据缺口盘点与权威数据源指南（frozen snapshot 构造指南针）

## 上游诉求（owner 原话）

> "去调研一下现在的数据库缺口，看看下一步要去找哪些数据库，注意我们之前说过的 mcp server 的数据库也要算进去，最终给出一份报告，写权威数据库，来源，被引的论文，方向。这份文档很重要，是我们后续的指南针，决定了我们自建的 mock 数据的构造（也就是你说的其余论文里都用的不查在线全离线存的逻辑）"

## 目标

产出一份可执行的指南针文档，包含四要素：**权威数据库 / 来源 URL / 被引论文（venue 背书）/ 服务方向**，并覆盖灵枢 MCP server 全部 23 个工具的数据需求。该文档决定后续 frozen snapshot（离线快照）的构造规格。

## 方法与约束

- 缺口以**实测**为准：读 `mock_db.json` 逐字段统计非 null 覆盖率，不引用既有报告的二手数字。
- SMILES 身份用 **RDKit 分子式 + 公开权威分子式**交叉核验，不凭记忆判断。
- 数据源可达性**当场 curl 实测**，不沿用历史 spike 结论（历史结论已部分失效）。
- venue 承 task10 口径：以 DBLP / 官方 proceedings 为准（ACTION_RULES §4）。
- 不重复 `reference/NobelClaw/ckpt_gt_binding.md` 已有的 19 源地址簿，本 task 做增量：按**工具维度**重组、补缺口等级、补正确性核验、补当前可达性。

## 关键发现预告（详见 report）

1. 首要问题不是「缺数据」而是「**有错数据**」：40 条 SMILES 中 15 条与其声称药物的分子式不符，且 `aa`(gold answer) 与 `bh` SMILES 完全相同。
2. 网络可达性已变化：Materials Project 仍 403、**OQMD 已不可达**（历史文档推荐的替代失效）、**BindingDB 已恢复**、3DSC/UCI 可达。
3. 自我纠错：本 task 初次统计误将「key 存在」当作「有值」，得出 ADMET 40/40 全满的错误结论；改按非 null 统计后为 80.4%，与既有报告一致。
