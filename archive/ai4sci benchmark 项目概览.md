> 一句话说明我们在做什么：
我们希望做一份专门测试 agent 在制药领域任务完整效果的 benchmark，并期待以这个 benchmark 为基础探索出一些 agent 在制药任务上的 general 的性质，最终改善 agent 在制药任务上的完成能力
## 任务目的
我们本质上是要构造一个 benchmark，这个 benchmark 的领域是制药，测试的主体是 agent，那么就是要测试 agent 在制药相关领域上的任务完成情况，同时我们还想把这个 benchmark 做成是 RSI 自进化的，也就是测出来之后通过一些训练手段把我们的 agent 在这个 benchmark 上产生的 loss 消掉，让他在这个benchmark 表现的效果更好
领域调研

## 基本事实
1. agent 的能力维度包括推理，记忆和工具调用三个维度，我们要测试的能力必然包含在这三个维度的框架下；

## 任务要求
基于任务目的和基本事实，我们自然产生出该项目的如下要求：
1. 制药 topic 是题眼，我们设计的问题必须是针对于制药来的，所完成的任务必须对制药这个 topic 有帮助；
3. 需要有一个可以细粒度判分的规范来衡量 agent 完成任务的效果从而当做 agent 的能力指标；4. 我们的题目的得分应该是不能太好的，留给 rsi 一定的空间；5. 我们的 rsi 所需要的信号是要在本 benchmark 上跑agent 测试之后就可以提供的

## 目前做法
1. basic，some，enough 三层 * open fixed 来做难度区分，给 agent 留出 rsi 的空间并考察 agent 在相同题目的不同外部环境下的表现差异，从而衡量其记忆（背题），推理，调工具的能力
2. 做长任务而不是短任务，短任务因为已经有很多人在做，本身的价值在迅速衰减，而且对于 agent 测试来做我们也更关注他的长任务的能力，那么定了这个决定之后就连带出现了一些问题：首先是如何衡量这个任务的长短，其次是如何对长任务打分，长任务打分这件事很重要，后续在下面单独说，现在先说任务长短的衡量，衡量长短这件事是和题目难度直接关联的，我的想法是如果一个问题可以被拆分为两个问题，那么他的难度就是 2，如果子问题还可以继续拆分为两个问题，难度就是 4，也就是其难度的衡量值就是原子问题的数目，那么问题变为了如何定义一个原子问题，我认为一个原子问题首先是不能再分的，其次是最多包含一步 tools 调用的，最重要的是没有任何任务依赖前置，所有信息都在query 里给出，这里是需要拍一个难度值出来的，这个是我们的第一个超参数
3. 关于结果的打分逻辑，这是重中之重，是问题能否立住的根本，从第一性原理出发是因为我们需要一个信号来衡量 agent 做任务的好坏，所以需要一个具体的数值来做评判，那么这个数值必须是可信的，所谓可信就必须：可重复性（运行多次结果一致，那么首先排除 llm-judege），可比较性（使用同一套量纲，并且同题目中如果有细粒度的指标衡量的话，也要是同量纲的，这是第二个超参），同时一个好的信号我们期望其具有以下性质：稠密（希望其不只是给出一个最终的得分，也有辅助得分来衡量其方案的质量而不是只衡量结果，举个例子如果两个 agent 都完成了一件事，但是方案不同，有优有劣，那么自然有区分，所谓辅助得分可以是过程分来衡量关键步骤，可以是 token 消耗，总之是衡量方案效果的一个信号），连续（一个连续的可比分数要比离散的分数更平滑，携带更多的可比较信息，粒度会更细），那么如何实现上述目标就要求我们：agent 的结果要是结构化的，非结构的话难以用 hard-code 来做 vertify，辅助信号必须明确，量纲必须统一，这要求我们定义一套不偏的分数归一化标准，但是该标准肯定是取决于我们的辅助信号的定义的
4. 这里有一个需要着重讨论的问题，辅助信号中的中间过程量信号是一个很特殊的信号，他在衡量 trace 的正确性，也就是方案本案本身的正确性，但是我们没有很好的方案来说明哪些方案是好的，哪些是坏的，这个信号的产生是一个困难，所以只能采取退而求其次的方案，比如人为定义方案，直接写在提示词里让其去做，但是这其实考察是 agent 的指令遵循能力而不是自己执行方案的能力，与原始目的有很大差距，目前的一些主流方案对此也有争议，所谓方案本身的衡量价值是否是必要的和重要的，如果其可以完整任务那么是否证明其方案本身就是优秀的，而如何完整任务的手段可以做忽略，我认为是有道理的，但是这里有一个前提就是我们希望考察的 agent 的能力是无偏的，也就是说 agent 不能通过作弊来得到最终答案，那么剩下的方案都是其探索出来的有效方案，本质上都可以解决问题，那么我可以其实只需要衡量 token 消耗这个指标就可以判别方案的优劣，因为其衡量的 agent 的能力是基本一致的，那么这样就要求我们定义一套防作弊的机制，这里又牵涉出来了一个新问题，什么是作弊，作弊指的是调用本身可以直接获得答案的工具来绕过多轮推理，这是我认为的作弊，也是唯一类型的作弊，我认为猜出来也就是所谓的凭借记忆预训练进去的只是来直接写答案并不能算是作弊，因为记忆本质上也是 agent 的能力的一部分，所以我们只需要保证 agent 无法通过工具调用直接获取答案，这在测试中是可以实现的
5. 关于 rsi 这件事其实是两个解决思路，首先是常见的 GRPO 类思路，其本质取决于原 agent 的能力，是在原本的探索空间里做偏移，还是没逃出原本的能力空间，只是往 good trace 上做了偏移，但是能力上线是定死的，包括 prompt-fine-tune 本质上也是一样的，另一种解决思路是提升能力上线的思路，直接找到标准的满分答案做 gt，这个标准答案是原来的 agent 达不到的，这就要求我们去做标准答案的构建，但是这显然是很困难的，所以更一般的做法仍需要讨论，但是首先排除的方案是用 teacher，因为我们是 rsi，只能是自己做错之后总结经验来迭代，如果我们设计一套标准可以自动定义某个问题的最优解法或者找到当前 trace 的非最优部分，那么这其实是开创了一个全新的领域出来，是非 GRPO 类的真正可以自主提升模型能力上线的方案，并且全程不需要 llm-judge 而可以自动构建 train dataset，甚至可以写一套适配于该方案的新的训练方式出来，这是很令人兴奋的工作
