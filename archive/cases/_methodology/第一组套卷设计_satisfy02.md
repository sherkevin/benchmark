# 第一组套卷设计 · 母题 satisfy_02(few-shot 基准)

> **定位**：这是第一组 few-shot 范例的权威设计。一道母题 × 多配置,示范"同题同真值、
> 只变工具供给"如何跑出符合预期的相对分数序。错了会被批量复制放大,故先定死设计、再动代码。
> **状态**:🔒 待 owner 过目(母题与工具分档已口头批准 2026-08-20)。
> **依据**:goal §1.5 两类任务、ADR-0026 三档套卷、ADR-0025 科学家代入判据、实验规范 §11。

---

## 0. 一句话

用 **satisfy_02**(约束满足:恰好 4 元素且 Tc∈[90,100]K,报完整满足集)作母题,
**query / 真值 / 判分五关一份不动**,只变两根轴——**候选可见性(fixed/open)× 工具供给(basic/some/enough)**
——跑出各配置**各自的平均分**,验证它们的**相对序**成立、**各自落在预期区间**。

**分数不合成总分**(ADR-0026 §6 硬约束):只报各配置的分 + 档间差 Δ。

## 1. 母题:satisfy_02(内核与真值)

### 1.1 内核(所有配置不变)

> 在一个超导体候选库里,找出**同时满足两个硬约束**的**完整集合**:
> ① 恰好含 **4 种**不同化学元素;② Tc 落在 **[90, 100] K**。

真值(权威 = `ground_truth.json`,非 README):

| 项 | 值 |
|---|---|
| 全库候选 | **65**(可测 61 / 不可测 4) |
| 满足集 `satisfying_set` | **7 个**(3 可测 + 4 不可测),全为 Hg-1201 系 `O4.xCu1Ba2Hg1` |
| 4 元素合法集 `ec_legal_set` | 33 个(占全库约一半——**逐个筛才有意义**,不是全抄) |
| 实测排除集 `excluded_measurable_by_tc` | 26 个(可测的 4 元素 La 系,Tc 22–39K 全越界) |
| 实测锚点 `measured_max_legal_id/tc` | `O4.220Cu1Ba2Hg1` / 97.0K |
| 满足集平均 Tc | 95.17K |
| 测量预算 | fixed 56(< 可测 61,**逼排序**) |

> ⚠️ **待清理的文档不一致**:judge docstring 与 MCP 注释写"9 个满足者全部不可测",
> 真值实为 **7 个(4 不可测 + 3 可测)**。判分读真值、不受影响,但文档要改对(并入 task#13)。

### 1.2 判分五关(等权,`total = Σcp/5`;所有配置同一套,不改)

| 关 | 量 | 形式 | 测的能力 |
|---|---|---|---|
| `cp_ec_set` | 4 元素合法集 | F1 | **#6 约束推理**(筛元素数) |
| `cp_excluded` | 实测排除的越界项 | 覆盖率 | **#29 acquire**(实测 La 系才知越界) |
| `cp_sat_set` | 满足集 | F1 | **#8 family 归类**(归纳 Hg 系高 Tc) |
| `cp_sat_mean` | 满足集平均 Tc | 柯西平滑(尺度 0.25σ) | **#5 趋势外推**(定量不可测者)**← 判别性主关** |
| `cp_measured` | 实测锚点 id+tc | id 0.5 + tc 0.5(容差 2K) | **grounding**(防背:值须来自真调用) |

**判别性主关 = `cp_sat_mean`**:其余四关是 F1/覆盖率式,对现代模型易饱和(实测池扩到 65 后
fixed 均值升到 0.899);唯 `cp_sat_mean` 需把含 4 个不可测者的满足集逐个定量后再算,天然连续、
难满分、不可背。**判据⑥(区分度)定稿时须指名 `cp_sat_mean` 为本题判别性检查点。**

## 2. 配置矩阵(两根轴)

```
              basic            some                 enough
           ┌──────────────┬────────────────────┬──────────────┐
  fixed    │ ① 现造        │ ③ 待 basic 导出     │ ⑤ 待导出      │  给 65 候选清单
           ├──────────────┼────────────────────┼──────────────┤
  open     │ ② 现造        │ ④ 待 basic 导出     │ ⑥ 待导出      │  不给,search_db 分页发现
           └──────────────┴────────────────────┴──────────────┘
```

**本批只造 ① ②(basic 两档)。** some/enough 按 ADR-0026 §3 **不预设**——必须先跑 basic、
分析失败模式、再针对实测痛点导出便捷工具(owner 2026-08-20 选 A 守序)。

### 2.1 工具分档(owner 已批:get_element_count 从 basic 降为 some)

| 档 | 工具集 | 理由 |
|---|---|---|
| **basic** | `measure_tc`(+ open 侧 `search_db` 分页发现) | ADR-0025 最基本工具。**数元素归 agent**(化学式 `O4.047Cu1Ba2Hg1` 可解析),真测 #6 |
| **some** | basic + `get_element_count`(待导出确认) | `get_element_count` 把"数元素"这一推理步变成一次调用,是标准便捷工具;Δ(some−basic) 量化"数元素能力值多少分" |
| **enough** | some + ?(待失败分析导出,候选:family 分组 / 同系 Tc 回归) | 不预设 |

> **为何 `get_element_count` 必须降档**:它替代了 agent 本该自己做的"数元素"推理。
> 留在 basic 会让 #6 只测"会不会调工具"而非"会不会推理"(ADR-0025 科学家代入判据)。
> 它精确对应一个可替代推理步,是本套卷 some 档的天然素材——这也是选 satisfy_02 的理由之一。

### 2.2 fixed ↔ open 的唯一合法差 = 候选可见性

| | fixed·basic | open·basic |
|---|---|---|
| 候选清单 | 题面给全 65 个(`data/candidates.txt`) | **不给**,`search_db` 分页发现 |
| 工具 | `measure_tc` | `measure_tc` + `search_db`(PAGE_SIZE=4,**每页扣 1 预算**) |
| 真值/判分/内核 | ——完全相同—— | ——完全相同—— |

> **search_db 必须分页且扣预算**(open 三铁律第 1 条,dopant 刚踩过坑):否则一次枚举全库、
> 发现步白给、open 退化成 fixed、尺子② 失效。

### 2.3 一个待定点(请 owner 定或纳入预登记)

**open·basic 的预算怎么定?** fixed 是 56(< 可测 61)。open 要额外花预算翻页发现,两种取法:

- **方案 Y(建议,更简)**:open 与 fixed **同为 56**。翻页从 56 里扣,open 因此可测次数自然少于
  fixed → 天然更难,直接体现"发现有成本"。风险:若 agent 把预算耗在翻页上导致大量不交卷
  (协议失败),需按 ADR-0026 精神在 basic 失败分析后再补偿。
- **方案 X**:open = 56 + 翻页补偿(如 +⌈拿全 17 页/2⌉=+9 → 65)。修协议失败、不伤 open 效应,
  但要改 open 的 `measurement_budget`,且要论证补偿量只看题目结构、不看结果。

我倾向 **Y**:最简、最能体现 open 更难,且符合"先跑 basic 看失败模式再调"的守序原则。

## 3. 每个配置预设测什么能力 + 预期分数

### 3.1 能力预设(跑出来要对得上,否则改设计)

| 配置 | 预设主要考察 | 机制 |
|---|---|---|
| fixed·basic | #6 筛元素(自己数)+ #29 实测排除 + #8 归类 + #5 外推,**全靠推理** | 给候选,但数元素/排除/归纳/外推都归 agent |
| open·basic | fixed·basic 的全部 + **额外考发现**(在预算约束下 search_db 找候选) | 不给候选,发现要付预算,逼"发现完整性 vs 测量完整性"取舍 |
| some(将来) | 同上,但 `get_element_count` 卸掉"数元素" | 用于量化 Δ:数元素值多少分 |

### 3.2 预期分数序与区间(尺子①②,来自实验规范 §11.1 + 历史实证)

**相对序(硬,尺子②)**:`enough > some > fixed·basic > open·basic`,相邻差建议 ≥0.10。

**各自区间(参考、不阻断,尺子①)**:

| 配置 | 预期均值带 | 依据 |
|---|---|---|
| fixed·basic | **0.60–0.70** | 历史实证 satisfy_02 fixed=0.677(但那含 get_element_count,去掉后应略降) |
| open·basic | **0.50–0.60** | 历史实证 open=0.554,差 0.123、置换 p=0.0060(★ 唯一两侧都落带内的题) |

> **重要限定**:上面 0.677/0.554 产自 08-19 前(有真值泄漏敞口 + 含 get_element_count 的旧 basic),
> **只作设计参考,不作达标证据**。新分档下的基线要重建。

## 4. 四条硬判据如何在这组套卷上验(实验规范 §11.1)

| 判据 | 在本套卷怎么验 | 通过条件 |
|---|---|---|
| **② fixed 优于 open** | 同母题 fixed·basic vs open·basic 的均值 | 置换 p<0.05(Bonferroni 按批校正),**两个独立批方向一致** |
| **④ 发现有后果** | open·basic 侧,按 search_db 发现覆盖率分组 | 覆盖率**非恒 1.0**,低覆盖组分数显著低于高覆盖组(dopant 就栽在恒 1.0) |
| **⑤ 答案不可背** | 无工具裸答基线 k≥5 | 裸答均值明显低于 with-tools;尤其 `cp_measured`/`cp_sat_mean` 裸答拿不到 |
| **⑥ 模型区分度** | **逐检查点**看 `cp_sat_mean`(不看聚合总分) | 该关最强−最弱跨度大、至少一对模型显著(Fisher/置换 p<0.05) |

**定稿(§11.3)**:②④⑤⑥ 在**两个独立批次**都成立 → 参数冻结,套卷定型。

## 5. 运行与隔离要求(每个 run 都必须满足,实验规范 §2/§3)

owner 强调的"独立、互不干扰、看不到别的、拿不到答案"逐条落地(已验 `verify_isolation` 19/19):

1. **每个 run 一个独立 workspace**:`<临时目录>/bench_runs/<随机12位id>/ws`,`mkdir(exist_ok=False)` 撞名即报错。
2. **workspace 在仓库外**:claude code 原生拦 cwd 外路径 → 真值 `ground_truth.json`、别的 run、AK、判分器**全部不可达**(零 deny 规则)。
3. **工具面隔离**:`--tools` 限定内置工具暴露集(5 个),`--allowedTools` 只放本配置的 MCP 领域工具——**Read/Write 绝不进 allowedTools**(否则能读真值)。不同配置 = 不同 MCP server(basic 的 server 不注册 get_element_count,做到"不存在"而非"deny")。
4. **拿不到真答案**:真值只交给 MCP server 子进程(不受 agent 权限约束),按题意返回受控信息(measure_tc 只对可测样品返 Tc;search_db 只返组成不返 Tc)。判分不信 agent 自报,数值逐点比离线真值、测量次数从账本数。
5. **模型池固定 6 个**(§1.1,不为调均值增删),每题 ≥5 轮取均。
6. **run 目录名无意义随机串**(不含模型名/轮次),避免暗示 agent"你在被评测"。

## 7. 为什么是 satisfy_02(存档,便于回看决策)

对比四道候选母题后选定(详见对话记录 2026-08-20):

- **satisfy_02 ✅**:唯一同时满足"尺子② 显著(p=0.0060)+ 两侧都落预期区间";五关**加法**结构与 open 兼容(乘法 grounding 会双重惩罚,constraint_02 因此掉到 0.287);要求报完整满足集、不可背;`get_element_count` 是干净的便捷工具样本,支撑 some 档。
- constraint_02 ✗:乘法 grounding 与 open 不兼容,open 掉出区间。
- chain_01 ✗:有"从自己发现的集合选最优"终选关,撞反例铁律(奖励发现不全);尺子② 6 模型全池不显著。
- dopant_01 ✗:cp3/cp4 移出总分后判别性关太少;是曲线回归、题型分类有争议。

**唯一权衡**:satisfy_02 的区分度集中在 `cp_sat_mean` 一关(§1.2)。§11.2 只要求"存在判别性硬关",达标,但不如 chain 的"真 3 档"漂亮——作为 few-shot 第一范例,稳定性优先于漂亮。
