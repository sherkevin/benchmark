# 好 case 的标准（GOOD CASE STANDARD）

> 本文件是 benchmark 造题的验收标准。**任何 case 必须四条全过才算"好 case"，否则回炉重造。**
> 依据：Owner 2026-08-12 定的四条要求 + 前期实测教训（case3/case4 均因太易被判不合格）。

---

## 一、四条硬标准（缺一不可）

一句话：**一道好题必须能把不同水平的 agent 分出高下，且考什么、属哪类都写得清清楚楚。**

### 标准 1 · 有区分度：不同 agent 结果不一样

同一道题，用**至少 3 个不同模型**跑，得分不能都一样。若所有模型都满分或都零分，则此题**无区分能力**，判不合格。

- 验证方式：多模型实测，不接受"设计上应该能区分"的空口推断。
- 反例（实测）：case4 单峰 dome，qwen3.7-max 与 glm-5.2 **都拿 1.0** → 不合格。

### 标准 2 · 分数落在 0.5~0.9，成梯度

被测模型的得分应主要落在 **[0.5, 0.9]** 区间，且彼此拉开。

$$\text{合格} \iff 0.5 \le \bar{s} \le 0.9 \ \text{且}\ \max_m s_m - \min_m s_m \ge 0.2$$

其中：$s_m$ 是模型 $m$ 的得分，$\bar{s}$ 是均值，$m$ 遍历被测模型集。

- 下限 0.5：太低说明题超纲/有 bug，测不出能力只测出"都不会"。
- 上限 0.9：太高说明题太易，被秒解。
- 极差 ≥ 0.2：至少能把模型分成两档。
- **判分必须是梯度分**（按接近最优的程度连续给分），不能只有 0/1，否则天然做不出梯度。

### 标准 3 · 考察能力明确

必须写清这道题考 agent 的**哪个/哪几个 action 能力**，逐条对到
`research/agent_action_全量枚举.md` 的编号（如 #5 趋势外推、#2 比例调整、#8 family 归类）。
每个 checkpoint 对应一个能力，说明"为什么这题非考它不可"。

### 标准 4 · 四维归类清晰

必须按下面四个正交维度说明本 case 属于哪一类（Owner 的 benchmark 全域框架）：

| 维度 | 取值 | 本 case 取哪个、为什么 |
|---|---|---|
| ① 结果验证强度 | 强可验证（真值/代码）/ 弱可验证（前后 diff） | 须填 |
| ② 问题范式 | 生成式（不给候选，自由推断）/ 判别式（给候选，选最优） | 须填 |
| ③ 中间值衡量 | 不衡量 / 弱衡量（子分数）/ 强衡量（必过锚点） | 须填 |
| ④ 工具越狱度 | 强推理（只给基本工具）/ 弱推理（配诊断工具）/ 强工具（退化为搜索） | 须填 |

## 二、造题必须避开的陷阱（实测教训）

| 教训来源 | 现象 | 结论 |
|---|---|---|
| case3 单调序列（ρ=1.0） | agent 秒解、满分 | **完美单调 = 秒解**，趋势太明显不考推理 |
| case4 单峰 dome | 前沿模型都会自适应采样、都命中峰 | **单峰 dome 骗不过前沿模型**，它们天然铺开采样 |

**推论**：要区分前沿模型，难度必须上到"贪心/直觉会掉坑、只有系统性探索才对"的层级。候选设计方向：
- **双峰/多峰**：局部最优诱饵（易找但非最优）+ 全局最优（要多探一步）——贪心 agent 栽在局部最优。
- **候选空间远大于预算**：逼真正的优先级推理，但须保证"好策略能覆盖到最优"，避免退化成运气（否则落进 #40 决定优先级，那是不测项）。
- **多条交织序列**：#8 family 归类变难，认错序列就外推错方向。
- **带噪声的趋势**：拟合难度上升，但答案仍可硬判。

## 三、验收流程（每个 case 出厂必走）

1. **数据地基**：答案与干扰全部来自真库穷举/还原，无编造；组成式规范化、唯一。
2. **可解性自证**：金标准解法路径存在且可达（金标准轨迹回放能满分）。
3. **判分器可执行**：`judge.py` 硬判定、梯度分、无 LLM judge、真值从 tool call 反查。
4. **多模型实测**：≥3 模型跑，记录各自得分。
5. **对照四条标准逐条核**：标准 1、2 看实测得分分布；标准 3、4 看文档齐否。
6. **不达标 → 调难度 → 回到第 4 步**，直到四条全过。
