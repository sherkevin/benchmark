## 〇、当前状态总览（2026-08-21 修订）

### 先钉死"第一组"的分母

**第一组 = 一道母题 × 六种配置。** 六格 = 候选可见性（fixed / open）× 工具供给（basic / some / enough）。

依据是 [ADR-0026](../../governance/adr/0026-三档套卷同题同真值只变工具供给.md) §1 原文：
「**不是造三套题，而是一套题跑三种工具配置**」。同题、同真值、同判据，只变工具面——
这是 $\Delta_{\text{tool}}$ 能归因到工具供给的唯一前提，换了题或换了判据，差值就混进
题目难度差与判据差，归因失效（ADR-0026 §2）。

> **一次已作废的定义，留痕以免重犯**：2026-08-20 的 T-188 曾把第一组自行改写成
> 「药物 3 道原子题 × basic 档，当前 1/3」。那是执行方自造的、非原定义，owner 于
> T-197 纠正并作废。**按错误定义时"1/3"，按 ADR-0026 原定义则是 6/6。**
> 教训与 §11.4 同型：分母是治理层的事，执行方不得自行重定义。

### 一组 case 的定义（owner 2026-08-22 最终裁定，覆盖此前所有表述）

> **一组 case = 同一个题面。fixed 与 open 的唯一区别，就是给没给对应的候选集。**

推论，全部按此执行：

| 项 | 规定 |
|---|---|
| 题面 | 六格**逐字相同**，只允许两处差异：①候选集给不给（可见性轴）②便捷工具说明（工具供给轴） |
| 真值 | 六格**同一份**，逐字节一致（`tools/gen_qed_case_gt.py` 统一写入并 assert） |
| **预算** | 六格**必须相同**。预算属题面的一部分，两侧不同就等于两道题 |
| 答卷契约 / 判分器 | 同一份（some/enough 判分器整套转发 basic 档 fixed 的 judge） |

**题面不同 ⇒ 就是另一组 case。** 生成式发现那道题（agent 自己想分子、存在性接口验证）
题面与本组不同,**属另一组、是未来要做的事**,不计入第一组;已做的工程与实验**留档不干扰**
（见 `cases/drug/atom/open_basic_tools/case_dr_qedgen_01/`、ADR-0027）。

> **一次被推翻的表述留痕**：2026-08-21 我曾把第一组改述为"两类任务（fixed 预测 / open 生成式）
> 各一条工具梯子"。owner 2026-08-22 纠正:**那是两个题面、就是两组 case**。本组仍是
> 一道母题 × 六配置,只是"open"的正确含义是**同题面但不给候选集**,不是换成生成式发现。

### 机制：翻页行为随工具档变化（本轮最有价值的发现）

| 档 | 翻满 9 页 | 翻页中位 | 测量中位 |
|---|---|---|---|
| open·basic | **18/21（86%）** | 9 | **3** |
| open·some | 12/27（44%） | 5 | 6 |
| open·enough | 9/27（33%） | 5 | 6 |

**basic 档 86% 的 run 把目录全翻完、只剩 3 次测量**——这是 P1 被否证的地方，也是 open·basic
分数低的直接原因（`cp_extrap` 仅 0.150：3 个点拟合不出趋势）。**模型不会按预算调整策略。**

**而给了便捷工具后，模型反而学会了少翻页**：`group_by_scaffold()` 直接给出骨架分组，
**省掉了穷举目录的必要**，腾出的预算转成测量（3 → 6 次）。

⇒ **在 open 配置下，便捷工具的价值是双重的**：既替代推理（`fit_trend` 帮拟合），
**又省掉发现成本**（`group_by_scaffold` 免去穷举）。这一点与 fixed 侧不同（fixed 本就不用翻页），
**故 open 的 Δ_tool 不可与 fixed 的 Δ_tool 直接比较归因**——两者的成分不一样，须分开解读。

**另一条如实标注**：open 侧 `fit_trend` 的收益受限于"买得起多少数据"——basic 档只有 3 个测量点，
工具再好也拟合不出曲率，这解释了为什么 open 的 some−basic（+0.158）远小于 fixed 的（+0.344）。

### 四条硬判据的实测状态（§11.1，2026-08-22 零机时算自现有 run）

| 判据 | 结论 |
|---|---|
| ② fixed 优于 open | ✅ **三档全成立**：差 +0.212/+0.398/+0.354，Bonferroni(m=3) 0.0049/0.0001/0.0001 |
| ④ 发现有后果 | ⚠️ **未能检验**（覆盖率非恒 1.0 ✅，但方向那一半功效不足 + 被工具混淆），见下 |
| ⑤ 答案不可背 | ✅ 成立（裸答不给任何工具，预算变更不影响）：空账本 0.000 / 零工具 0.000 / 抄最近邻 0.048 / 认错系列 0.03–0.06 |
| ⑥ 模型区分度 | ✅ **只有 open 侧成立**（逐档控住后 open 三档全显著、fixed 三档全不显著），见下 |

#### ④ 未能检验（2026-08-22 自我纠正：先前写"方向反了"是过度解读）

④ 原文要求"open 侧覆盖率非恒 1.0，**且低覆盖组分数显著低于高覆盖组**"。
覆盖率非恒 1.0 ✅（翻页 1–9 页都出现）。但**方向那一半，用现有数据无法判定**。

**先前的错误结论**：曾报"少翻页组反而高 +0.501、r=−0.802、模型内 +0.320 ⇒ ④ 精神成立、
字面方向相反"。**该结论已撤回**，原因是两处混淆：

| 档 | r(翻页, 总分) | 少翻页(<9页)的 run 数 | 问题 |
|---|---|---|---|
| **basic**（唯一干净条件） | **−0.297** | **只有 3 个** | 功效不足，p=0.20 **不显著** |
| some | −0.818 | 15 | **27/27 个 run 都调了 `group_by_scaffold`** |
| enough | −0.842 | 18 | 同上 |

1. **basic 档才是能干净测这件事的条件**（没有便捷工具，翻页与测量纯粹争同一份预算）。
   那里相关只有 −0.297、少翻页的仅 3 个 run、置换 p=0.20 ⇒ **证不出来**。
2. **强相关全部来自 some/enough**，而那两档 **27/27 都调了 `group_by_scaffold`**——工具直接给出
   骨架分组，它们**本来就不需要翻页**。所以那里的"少翻页"主要是**工具替它省了翻页**，
   不是"它会分配预算"；且"用了工具"与"少翻页"在数据上共线，**无法分离**。
3. **先前那个"同一模型内部也成立（+0.320）"的检验混了档位**：同一模型的少翻页 run 大多落在
   some/enough，而那两档本来分数就高（0.449 / 0.540 vs basic 0.291）⇒ 那个差值很可能
   **只是档位效应**，不是翻页效应。

⇒ **④ 的状态：与预算 17 时一样仍是"未能检验"**，只是原因变了——当时是覆盖率恒 1.0 没有变异，
现在是有变异但**唯一干净的档样本太少、另两档被工具混淆**。

**待检验的机制假设（尚未证实，不得当结论引用）**：open 侧翻页与测量共用 12 预算，
读满 9 页只剩 3 次测量，而看出曲线弯曲约需 5 个同系物 ⇒ 过度翻页会饿死测量、外推偏高
（实测那些 run 普遍报 0.68–0.76，真值 0.5545）。**实测确有 86% 的 run 一上来就读满 9 页**，
但"少读的人是否因此更高"证据不足。

**要检验它需要什么**：在 **basic 档**加大样本，看少翻页组能否累积到可检验的规模；
或专门设计对照（如固定翻页预算 vs 自由分配）。**不在本轮改任何参数。**

**教训**：这与 `problems.md` PR-36 记的老毛病同型——**用未控混淆的简化分析验复杂现象，
会得出反向结论**。下结论前必须先控住档位/工具这类分层变量。

#### ⑥ 只有 open 侧能区分模型（已控档位，结论站得住）

身份先验分档（旗舰 = qwen3.7-max / glm-5.2，与本次分数无关，§11.2 防循环论证）。
**先前只报了三档合并的数字，而④ 的翻车说明合并会引入档位混淆——故这里逐档单独检验**：

| 侧 | basic | some | enough |
|---|---|---|---|
| **fixed** | −0.021 (p=0.80) ✗ | +0.040 (p=0.53) ✗ | +0.066 (p=0.53) ✗ |
| **open** | **+0.169 (p=0.047)** ✓ | **+0.650 (p<0.0001)** ✓ | **+0.508 (p=0.0003)** ✓ |

**逐档控住后 open 三档全部显著、fixed 三档全部不显著** ⇒ 结论不是合并造成的假象。
三档合并的信噪比：fixed 0.36–0.42、open 1.23–1.47。

**fixed 把候选池直接给了、预算够用，强弱模型都能做完 ⇒ 区分不出。open 逼 agent 自己决定
"花多少预算去找、留多少去测"，这件事强弱模型差别很大 ⇒ 区分得很干净。**

⇒ **这条轴的真正价值由此确定**：不是"让题变难"，而是**它是本套卷里唯一能区分模型的配置**。
对后续造题有直接指导——**若目的是测模型能力，就得用 open 配置**。

**两档便捷工具都由上一档实测失败模式导出**（ADR-0026 §3 走了两遍，不是预设）：
some 打 basic 的"外推偏高 85% + 测量花错系列 53%"配 `fit_trend` / `group_by_scaffold`；
enough 打 some 的"自己跑出几个拟合却挑错"配 `qed_components`。

### 核心结论：工具梯子到头了

$\Delta$ 从 +0.344 塌到 +0.047，且 `qed_components` 只有约一半 run 去调
（fixed 15/29、open 11/24）。**剩下的推理不是缺工具，是缺不了的。** 两条硬证据：

1. **统计学工具帮倒忙**：LOO-CV 在真值上推荐 degree=1（错的那个，柯西分 0.078），
   因为测量窗口 n=2..6 内关系本就近似直线、曲率只在外推段显现。
2. **真正的坎是领域知识，而供给它就会泄答案**：QED 分项显示 ALOGP 项 n=2→6 还在
   变好（+0.124）、n=6→11 反转崩塌（−0.509）。拐点从 5 个 QED 值看不出来。

⇒ **不可再分内核 = "识别出外推段会发生机制反转"**，这是本题真正在测的科学能力。

**反向验证**：enough 档把六个模型基本拉平到 0.94–0.96，说明 basic 档测出的差距
确实来自被工具替代掉的那些推理步骤。

### `cp_focus` 拆细推翻了一个失败模式（2026-08-21）

旧 `cp_focus` = 实测分子 ∩ 目标同系列 / 实测分子。**该定义把 Job2 强制要求的测量算成"偏离"**
——Job2 明确要求挑一个**非目标系列**的先导并实测它。于是实测值只有 0.391（fixed）/ 0.612（open），
当时被读作"模型把测量花错了系列 53%"。

按母题的两个 Job 拆开重算（**总分逐格逐 run 完全未变**，属"只需重判"）：

| 分量 | 分母 | fixed basic / some / enough | open basic / some / enough |
|---|---|---|---|
| `cp_focus_job1` 趋势数据覆盖 | 5 个可测同系物 | 0.852 / 0.992 / 0.979 | 0.922 / **1.000** / **1.000** |
| `cp_focus_job2` 选型测量精度 | 它测过的非目标系列分子 | 0.994 / 0.979 / 0.991 | **1.000** / **1.000** / 0.969 |
| 掉进联苯陷阱的 run | — | 1/24 / 3/27 / 2/29 | 0/23 / 0/27 / 2/25 |

⇒ **"测量花错系列 53%"不成立**，那是旧指标分母造成的假象；模型一直在正常做 Job2。

**连带后果（如实记录）**：`group_by_scaffold` 这个便捷工具当初正是照着这个失败模式配的
（T-203）。**它打的是一个不存在的痛点。** 这不影响 Δ_tool 的诚实性（工具确实给了、分数确实
这么变），但意味着 **Δ(some−basic)=+0.344 应主要归因于 `fit_trend`**；两工具各自贡献未做
拆分实验，**不得声称 `group_by_scaffold` 有效**。

**方法论教训**：ADR-0026 §3 要求便捷工具由**实测失败模式**导出——这一条守住了，
但没人验证"那个指标是否真的在测它声称在测的东西"。**导出工具之前，先校指标的分母。**

### preflight 报 `cp_lead_value` 饱和 —— 误报，不是缺陷（2026-08-21 更正）

闸门2（样本 ≥6 才判饱和）在 **fixed·some（26/26 满分）与 open·enough（25/25）** 报了
`cp_lead_value` 饱和。**这不是题目缺陷，也不需要任何裁定。**

**`cp_lead_value` 是门，不是关。** 它的职责是**堵背答案**：报的 `lead_qed_measured` 必须与
真值一致——老实测过分子的人报得出这个数，猜的人报不出。**诚实作答者接近 100% 通过，
正是一个防作弊检查该有的样子。** preflight 自己的注释写着同一句话：

> 乘性门…职责是防瞎报，**能力模型 100% 通过是它应有的样子，不算缺陷**；
> 只有进入均值的"关"饱和才是真问题。

**它为什么还是被报出来**：preflight 的门识别是**启发式**——只认"取值只有 0/1 两档、
且在判分器源码里以乘法出现"的关。`cp_lead_value` 是**柯西平滑给分、以加法进总分**，
启发式认不出它是门，于是按"关"去判饱和。⇒ **属 preflight 识别能力的边界，工具侧的已知限制，
不阻塞开批，判分公式不动。**

#### 这次误判的教训（留痕，比结论更重要）

执行方（我）看到闸门打出 FAIL，**直接进入"怎么改判分"**，算了一版"把这一关移出总分会怎样"
并写成"待 owner 裁定"。**这是自己发起的判分口径改动**——§10 第 4 条明令禁止"改判分权重"，
ADR-0026 的同题同判据前提也全靠这条不被破坏；性质与 T-186 / T-197 里被叫停的发散相同。

**根因不是不守规矩，是没回去查决议**：`cp_lead_value` 的职责（堵背答案）与 owner 定的
"中间值"（`cp_conditions`：query 里三个小限制条件，用最终答案反推逐条核）是**两回事**，
而这层归属只写在 TODO.md 一个巨型单元格里（T-184），不易检索。

**固化为纪律**：**任何机械闸门报警，都必须先查清"这一关当初是为什么设的、谁定的"，
再谈要不要动。** 查不到出处就是决议没落盘 ⇒ 先补决议台账（`governance/DECISIONS.md`），
不得先改判分。

## 二、新题型：全库普查（census）

### 设计原理

基于前序约 1952 个 run 的失败证据设计：

| 旧题的病 | census 的对策 |
|---|---|
| satisfy_02：只有一关依赖发现 → 效应小（0.084）| **每一关都是全库统计量**，漏一个材料 count/mean/median 同时偏 |
| constraint_02：二值/全或无 → 强模型白送、天花板破 | **每关连续部分分**（按相对误差衰减）|
| chain_01：step D 奖励发现不全 → 效应≈0 | 统计量只会因漏样本变差，不存在奖励漏发现的结构 |

产物：`total_count` / `high_count`（Tc≥90K 的个数）/ `mean_tc` / `median_tc`，四关等权平均。
另一关键机制：**测量预算(40) < 库规模(70)**，逼模型抽样估计，抽样质量直接决定误差。

fixed 与 open **共用同一份 harness 文件**（`src/probe_headless/census_runner.py`），
仅"题面是否给候选清单"一处分支；turn 上限、预算、真值、判分全部相同。
open 侧 judge 是薄壳，代码级 `import` fixed 版的 `validate/score`。

### 九个版本的完整记录

## 三、方法论突破：协议失败必须计 0 分，不能剔除

此前所有结论都建立在"协议失败的 run 被剔除"上 —— 而协议未完成本身就是能力不足，

| A：失败剔除（旧）| 0.674 | **−0.061**（反序）| 0.026 | ✗ |
| **B：失败计 0 分（新）** | 0.338 | **+0.212** | **<0.0001** | ✓✓ |

口径 B 下三道题的尺子②结果（Bonferroni ×4）：

| case | fixed 均 | open 均 | 差 | Bonf p |
|---|---|---|---|---|
| satisfy_02 | 0.693 | 0.274 | **+0.419** | **<0.0001 ★** |
| constraint_02 | 0.844 | 0.308 | **+0.537** | **<0.0001 ★** |
| census_01 | 0.550 | 0.338 | **+0.212** | **<0.0001 ★** |

"open 更难 → 更多模型完不成 → 均值更低"确实是真实的配置难度差异、符合尺子②定义，

## satisfy_02 三次尝试的统计证据与根因（goal (d) 取代设计）

已先修好测量系统（并发 4、search 扣预算、两侧 turn 统一 100），在此前提下三次尝试：

| 尝试 | 配置 | fixed 均值 | fixed 最强 | open 均值 | 尺子② 差 | 覆盖率中位 |
|---|---|---|---|---|---|---|
| 1 | 池 24、四关 | 0.728 ✗ | 0.864 ✗ | 0.672 ✗ | 0.044 ✗ | 1.00 |

| 3 | 池 65 + **第五关（满足集平均 Tc，连续，容差 0.25σ）** | — | gpt 单次 **0.973** | — | — | — |

**根因（有数据支持，不是推测）**：
1. 四关全是 **F1/命中式**判据，而它考察的动作——“用 element_count 筛合法项 + 比 Tc 窗口”——
   对现代模型是简单任务，因此分数天生靠近满分；
2. **扩池无法压分**：池从 24 扩到 65 后 fixed 均值反而从 0.728 升到 0.899。
   因为满足集变小（7 个）使 F1 更容易拿高，而筛选动作并未变难；
3. **加连续关也不够**：gpt 能从同系列可测材料外推出不可测者的 Tc，
   cp_sat_mean 拿到 0.865（误差仅 ~1.3K），总分仍 0.973。
4. **覆盖率中位始终是 1.00**：只有 24–65 个候选、预算又够，强模型能全发现全测完，
   open 与 fixed 退化为等价（差 0.044）。

**参照：census_01 为何能稳定落带**——它的四关**全部是全库统计量的精确数值**
（库规模/子集计数/均值/中位数），且**预算 < 池规模**强制抽样：漏一个样本就同时拉偏
多个统计量，误差连续且不可通过“仔细筛选”消除。这是结构差异，不是参数差异。

**结论与取代设计**：“集合筛选型”（报满足集/合法集）在当前模型池下**无法落入 [0.60,0.70]**，
不应继续靠调参抢救。第一组应以 **census 式“全库统计量 + 预算<池规模”结构**为主干；
satisfy_02 的三版数据均已留档（runs_pool24_final / runs_pool65_4gate / runs_turn40_open_unfair），

| 1 | 24/20（58%）| 命中式 | 0.710 ✗ | 0.993 ✗ | 0.587 ✓ | 0.169 / 0.124 ✗ |
| 2 | **68/35（26%）** | 命中式 | **0.974 ✗** | 0.993 ✗ | 0.749 ✗ | 0.269 / **0.0050 ★** |
| 3 | 68/35 | 连续关（含字段名 bug，meas 恒 0）| 0.577 ✗ | 0.744 ✓ | 0.433 ✗ | 0.164 / **0.0182 ★** |
| 4 | 68/35 | 连续关（bug 修好）| 0.809 ✗ | 0.994 ✗ | 0.613 ✗ | 0.212 / **0.0241 ★** |

**尺子② 已稳定成立**：四个配置下方向一致，差 0.164–0.269，三个配置 Bonferroni 后显著；
发现有后果也稳定（覆盖<85% 均 0.272 vs ≥85% 均 0.534，**p=0.0008**）。

**尺子① 压不住的根因（逐关数据）**：
```
fixed 逐关均值: gate=0.900  count=0.886  mean=0.532  obj=0.991  meas=0.900
open  逐关均值: gate=0.818  count=0.568  mean=0.280  obj=0.991  meas=0.712
```
问题在 **obj（目标达成）两侧都是 0.991**。该关是约束优化题的**科学内核**（选出 Tc 最高的合法项），
但汞系材料的 Tc 集中在 95–98K，模型随便选一个就接近满分——这不是判分实现的缺陷，
而是**题型内核本身对强模型不难**。继续降 obj 权重可以把分数调进带内，
但那属于“按结果调判分”（goal⑥ 禁止），故停手。

**与 satisfy_02 合并的结论**：两道题的共同点是判分依赖**“找对那一个/那一群”**；
census_01 的判分依赖**“把整个分布估准”**。前者扩池后分数上升（0.710→0.974、0.728→0.899），
后者扩池后下降并落带。**第一组应以 census 式结构为主干**，该结论由四道题、
六个配置的实测支持。

**本轮又找到并修好的 bug**：judge 读 `measured_max_legal_id/tc`，而 harness schema
交的是 `measured_max_id/tc` —— 字段名不匹配使该关**恒为 0**，两侧各白掉 1/4 权重
（把 fixed 压到 0.577、open 压到 0.433）。教训：改判分字段后必须逐关打印均值核对，
任何一关恒 0 或恒 1 都是字段名/实现错位的信号。

### 判分口径统一（验收项⑦）

原来两侧的判分是"半复用"：open 侧 `import judge.py` 拿 `score`，但自己写了一份放宽的
`validate`，而 fixed 侧用的是另一个文件 `judge_ws.py`（读 `answer.json`）。三处不一致：

1. **答案来源不同**：fixed 读 `answer.json`、open 读 `tool_calls.jsonl` 里的 `submit_answer`；
2. **协议门槛不同**：fixed 要求 `predictions` 覆盖全部 10 个不可测材料，open 不要求；
3. **协议失败处理不同**：两侧都是"整条剔除"，即口径 A。

现已统一为：

- 答案唯一来源 = `tool_calls.jsonl` 的最后一次 `submit_answer`（两侧都有、且不可被 agent
  事后改写；`answer.json` 只作留档）；
- 两侧都不要求 `predictions` 覆盖全，缺的由 `score` 自然按未命中计 0（cpC = 命中数/10），

  若只给 open 放宽，两侧难度就不可比；
- **口径 B**：`api_error.json` 存在 → 基础设施失败、剔除；`never_submitted` / 字段缺失
  → 能力失败、计 0 分。
- `judge_chain_open.py` 现在不含任何自己的判分逻辑，`validate / score / collect / report`
  四者全部 `import` fixed 侧的 `judge_ws.py`，并在模块加载时 `assert` 两侧 golden 真值相同。

### chain_01 卡在哪：尺子①与尺子②合起来只有一个角点解（结构性，可算）

把两把尺子的约束写在一起（open 均值记 `o`、fixed 均值记 `f`）：

```
尺子①:  0.60 ≤ f ≤ 0.70      0.50 ≤ o ≤ 0.60      max_model < 0.85
尺子②:  f − o ≥ 0.10
```

**可行域是一个角**：`o ≤ f − 0.10 ≤ 0.60`，所以只有当 `f` 贴近上界 0.70 时，
`o` 才有整条 [0.50,0.60] 可用；`f` 每低 0.01，`o` 的可用区间就窄 0.01。

chain_01 实测 `f = 0.614`（fixed 侧的分数**对预算不敏感**：预算 45 而可测材料只有 29 个，
fixed 侧无论怎么调预算都能测完，所以 0.61 是这道题的固有难度，不是可调参数），于是
`o` 的合法窗口只剩 **[0.500, 0.514]，宽 0.014**。而 n=30 时单批均值的标准误约 0.035
——**窗口宽度只有抽样噪声的 0.4 倍**。这意味着即使把真实均值精确调到 0.507，
两个独立批次同时命中的概率也不到一半：**这不是参数没调好，是无解。**

唯一正当旋钮（降低两侧共用预算，goal (a) 指定的那个）在这道题上的传导是单调且捆绑的：

- 预算 ≥29 时 fixed 恒能测完 → `f` 平坦；
- open 要先花约 10 个单位翻页 → 预算每降 1，open 少测 1 个 → `o` 单调下降。

所以 `f − o` 与 `o` 是同一个量的两面：**差值增大只能靠 `o` 下降**，而 `o` 下降就会跌出
尺子① 的下界。降预算到 29（= 可测材料数，一个不看结果的自然取值）预计把 `o` 压到
0.44–0.48，差值升到 ~0.15：**②过①破**，与现在的 **①过②破** 正好互换，仍不能同时成立。

**这与 census_02 的权衡曲线是同一类现象、但机制不同**：census_02 是"均值落带"与
"最强模型 <0.85"对立；chain_01 是"open 落带"与"两侧差 ≥0.10"对立。census_01 之所以
能同时过，是因为它恰好落在这个角点附近（fixed 0.635 / open 0.532 → 差 0.103，
刚过 0.10 线 0.003）。**五道题里只有一道能进这个角，本身就是对尺子的一个发现：
"两条相邻的 0.10 宽带" + "差 ≥0.10" 是一个角点约束，而不是一片可行域。**

### 一次被自己数据否证的尝试：加"过程量"第五关 cpE

**假设**：原四关全是终值关，"有没有把目标族测全"这个实验完整性只能通过 cpB/cpD 间接反射。
补一个直接计分的过程量关 `cpE = |实测过的 family B| / 14`（从工具账本反查，不靠自报、
不需改题面），预期 **fixed 有清单能测全、open 要先发现所以测不全 → 差值被拉大**。
这个理由独立于分数，且与 census_01 能同时过两把尺子的机制一致（它的四个产物全部直接
依赖发现完整性）。

**批 A 实测（同一批数据、只换判分关数）**：

| 关数 | fixed 均 | open 均 | 差 |
|---|---|---|---|
| 四关（原设计）| 0.614 | 0.541 | **0.073** |
| 五关（+cpE）| 0.685 | 0.618 | **0.066** |

**预测被否证**：两侧同幅上抬 0.07，差值没变大反而略缩，且 open 冲出 0.60 上界。
原因是 open 侧在预算 45 下把 family B 测得**跟 fixed 一样全**（候选发现覆盖率
0.77–1.00、中位 0.89）。故 `GATES` 已回退为 4，cpE 代码保留在 `judge_ws.py` 里
作为这次否证的证据，并写明纪律：**它是看到批 A 后加的，若要启用必须在未看过的新批上复验。**

**这次否证反而定位了真根因**：不是"发现完整性没被计分"，而是
**预算 45 对 open 太宽裕**——翻页花掉 6–12 个单位后，剩下的仍够测完全部 29 个可测材料，
两侧的信息获取量几乎相同，所以差值天然小。**正当旋钮因此正是 goal (a) 指定的那个：
降低两侧共用的测量预算**（29–30 时 fixed 刚好测完、零冗余，而 open 要先扣掉翻页，
只能测约 2/3）。下一步就做这个，而不是继续动判分结构。

### 【跑数之前登记】chain_01 预算旋钮：45 → 34，两批复验，之后不得回改

这条是在 **看到任何 34 预算的结果之前** 写下的，用于满足验收⑥"预定轮次一次性检验"、
并杜绝"按结果挑参数"的嫌疑。

**取值规则（不看结果、只看题目结构）**：

```
可测材料数        = 29
拿全 35 个候选所需页数 = ⌈35/PAGE_SIZE⌉ = ⌈35/4⌉ = 9
预算 = 29 + ⌈9/2⌉ = 34
```

**为什么是这个规则**：批 A 的诊断结论是"预算 45 让 open 在付完 6–12 个单位的翻页成本后
**仍够测完全部 29 个可测材料**，于是两侧的信息获取量几乎相同"（cpE 那次否证给出的直接
证据：open 把 family B 测得跟 fixed 一样全，覆盖率中位 0.89）。取 34 之后：

- **fixed 侧**：29 个必测 + 5 次冗余 → 仍能测完，`f` 应保持在 0.60–0.70（这条同时是一个
  **可被否证的预测**：若 `f` 明显掉出下界，说明"fixed 对预算不敏感"的判断错了）；
- **open 侧**：想把 9 页翻全，就只剩 25 次测量（86%）；想测全 29 个，就只能发现一半候选
  ——**被迫在"发现完整性"与"测量完整性"之间做真实取舍**，这正是 open 配置要考察的能力。

**同步改动（防止题面/harness 不一致这个老坑）**：
`prompt_case9.txt` 里原来硬编了 `up to 45 ... (enough to measure every measurable material)`，
现改为占位符 `{BUDGET}` 由 `case9.json` 注入，且删掉了"够测完所有材料"这句已不成立的话。
两侧三个配置文件（`case9.json`、fixed `ground_truth.json`、open `case9_open.json`）
的 `measurement_budget` 同步为 34。

**预登记的检验方案**：批 M（m1–m5）与批 N（n1–n5），两侧各 6 模型 × 5 轮 = 每批每侧 30 run，
总并发 4。**两批都要过①②才算达标**；Bonferroni 取 m=2（两批同时检验）。
若批 M 过、批 N 不过 → 记为过拟合，按验收(d) 写根因，不得改参再试。

**@45 的数据已归档**：两侧 `runs_b45_4gate`（fixed 71 个 run：c1–c8 全 + k1–k5 部分；
open 30 个 run：h1–h5）。批 A 结论（①三项全过、②差 0.073 不过）出自其中的
fixed c1–c5 / open h1–h5，可回查。

### bug 11（最严重的一个）：API 限流伪装成"模型不作答"，被当成能力失败计 0 分

**症状**：把预算从 45 改到 34 后，`qwen3.5-plus` 在 fixed 侧 **5/5 全部 0.000**
（`never_submitted`），而同一模型在预算 45 下能拿 0.639。若照旧口径落档，就会得出
"plus 在紧预算下完全不会做这道题"的能力结论。

**真相**（靠本轮新加的 `messages.json` 轨迹留档才看见）：idealab 网关在限流时
**不返回 HTTP 错误码**，而是在 SSE 流里把错误文本当成 assistant 的 `content` 发回来：

```
模型提供方限流, data: {"code":"Throttling.BurstRate",
  "message":"Request rate increased too quickly...","request_id":"6952a39d-..."}
```

旧代码把它当成"模型说了句话但没调工具"→ 催交卷 → 仍是限流文本 → `break`
→ `never_submitted` → **计 0 分**。而 `urlopen` 没抛异常，所以 `api_error.json`
永远写不出来。**这正是 goal 明令禁止的"把 API 异常与能力失败混同"**，
而且它是从**内部**绕过了 api_error 机制，不是机制没写。

该 run 的真实轨迹：它已经正常做了 6+5+6 = 17 次 `tool_call`，只是每轮都被限流打断。

**修复**：两侧 runner 统一加 `_looks_throttled()` 识别 + 退避重试（5s/15s/45s，共 4 次），
仍失败则抛 `ApiThrottled` → 写 `api_error.json` → 判分时整条剔除。
**验证**：同一模型同一配置重跑 → `measurements=25, submitted=true`（原为 0/5 全不交卷）。

**对已有结论的影响**：

- 批 A（fixed c1–c5 / open h1–h5）**协议失败 0/30、0/30**，即那批没有被限流吃掉整条 run，
  ① 的三项结论仍可引用；
- 但凡出现 `never_submitted` 的批次都必须重新怀疑一遍。历史上被我归因为
  "弱模型能力不足/早退"的零分里，至少有一部分其实是这条 bug。
- open 侧请求数比 fixed 多（还要翻页），受限流影响更重 → 这条 bug 会**系统性压低 open**、
  虚增尺子②。与 bug 10 同向，性质相同。

**顺带加的轨迹留档**：两侧每个 run 现在都落盘 `messages.json`（完整对话）。
这不只是调试便利——本项目要测的是**过程量**，"模型为什么停下来不交卷"这件事
只能从对话里看出来，此前只能靠猜（bug 11 就是靠它才抓到的）。

# ⛔ 撤回：census_01 的「两批达标定稿」结论不成立

这是本轮最重要的发现，而且它推翻的是**我自己此前唯一宣称达标的那道 case**。

## 怎么发现的

去跑 census_01 自己的判分器复现那组数字时，**两侧判分器都直接崩了**：

```
judge_census.py     → KeyError: 'max_id'      （__main__ 里还在打印早已删除的 max/min 关）
judge_census_open.py → KeyError: 'cp_max'     （同上）
```

也就是说，此前落档的「fixed 0.635 / open 0.532 / 差 0.152 / Bonf 0.0008」**从来无法由

修好崩溃后又发现第二件事：两侧 `__main__` 都是 **口径 A**——`if bad is not None: continue`，

**即口径 B 只写在 validate 里，聚合时没用上。**

| 批次 | fixed 均值 | open 均值 | 最强 | 差 | 置换 p / Bonf(m=2) | 反序 |

## 【跑数之前登记】census_01 下一步：预算 42→35、PAGE_SIZE 3→5，一次定死

取值规则（只看结构，不看分数）：

```
预算 = 池规模的 50% = 35        （census 的设计原则是"预算 < 池规模强制抽样"，取一半是最自然的刻度）
PAGE_SIZE = 5 → 拿全 70 个需 14 页（原 3 → 24 页）
```

**为什么两个一起动、而且这不是"凑两个旋钮"**：
现在 `PAGE_SIZE=3` 时 open 要花 24 页 = 预算的 **57%** 去翻页，于是 open 的分数
主要由"翻页成本"决定，而不是由"信息可见性"决定 —— 这让 fixed↔open 的差异
混入了一个与题意无关的量。改成 14 页后翻页占 40%，**差异重新主要来自"看不看得见清单"这一个变量**。
预算降到 35 则同时压低两侧的绝对分数（fixed 从 60% 覆盖降到 50%）。

**方向预测（可被否证）**：fixed 应从 0.736 降向 0.66±；open 因"预算降、但翻页成本也降"
应大致持平或略升，落在 0.50–0.56。若 open 反而跌破 0.50，说明"翻页成本主导 open 分数"
这个判断错了，须记为否证、不得再改参数硬凑。

**检验方案**：批 r（r1–r5）与批 s（s1–s5），两侧各 6 模型 × 5 轮，总并发 4，
Bonferroni m=2，**两批都过①②才算达标**。@42/PAGE3 的这两批已归档为
`runs_b42_p3_fixedsystem`（两侧各 60 / 60 个 run，可回查）。

**根因（量化后确认是功效问题）**：
- 轮间标准差 σ=0.236（大），模型间信号 0.121，信噪比 0.51
- 合并两批 n≈10 时，**0/15 模型配对在 Bonferroni(m=15) 后显著**
- 连最强 qwen3.7-max(0.916) vs 最弱 V3-671B(0.582)、差 0.335，Bonf p=0.34 也不显著

**功效计算**（σ=0.236, Bonferroni m=15, power=0.8）：
| 要检出的差 d | 需要轮数/模型 |
|---|---|
| 0.335（最强vs最弱）| 16 |
| 0.25 | 29 |
| 0.15 | 79 |
| 0.10（相邻）| 178 |

当前仅 10 轮 → 只够点估计，不够显著性判定。

**这与既有方法论一致**：单题单硬关只能可靠分 2 档（强/弱）；要分更多档必须靠
依赖链不同硬关各自分档，不能靠总分名次。之前记的"模型区分度✓极差0.555"是
**点估计极差，非可靠区分**，据此更正。

**剩余噪声主要来源**：交卷硬要求把未交卷从 7/57 降到 ~2/27（deepseek 系两模型
偶尔做了 10–18 次测量却仍不写 answer.json，属模型自身指令遵循差异）。

# 【跑数之前登记】2026-08-29 · `case_dr_cns_01`：按已发表 CNS 要求单做先导优化

### 新发现：2/9 交的是**不可解析**的 SMILES，且都出在最激进的改造上

两条不可解析都是 **kekulize 失败**（RDKit：`Can't kekulize mol`）——
写出了芳香标记的原子却凑不出合法的交替键，本质是稠环/杂芳环的环闭合写错：

- DeepSeek-V3-671B：想把苯环换成吡啶、二甲胺换成吗啉（**化学方向是对的**），
  但 `c3ccccn32` 那个氮同时闭两个环、把芳香氮接到了桥氮上。
- qwen3.7-max：想稠一个亚甲二氧基（benzodioxole），`c3` 那个芳香碳落在了
  O-C-O 六元环里、不在任何芳环上。

**这两条恰好是九条里结构改造最大胆的两条** —— 想动骨架外的环系、而不只是挂取代基。
意思是：裸答臂不是"不敢改"，是**改了写不对，而且自己不知道写错了**（两条都自报 4/4）。

# 【工具臂跑数之前登记】2026-08-29 · `case_dr_cns_01` 过程判据：平均领先量

## 为什么加这一条

## 定义（三样输入全部来自别处，执行方一个数都不定）

    参照线[j]   = 盲抽 j 次后，最好那个的期望过关条数（解析式，非采样）
    历史最好[j] = 这条 run 前 j 次化验里最好的过关条数
                  提前收工按最后成绩补齐到 BUDGET（历史最好单调不减，少化验不该占便宜）
    领先量[j]   = 历史最好[j] − 参照线[j]
    平均领先量  = 领先量在 BUDGET 步上的均值
    百分位      = 同一个盲抽者的平均领先量分布里，这条 run 排第几百分位
                  （蒙特卡洛 N=200000、种子 20260829，只影响小数位，不影响方向）

落在 `src/probe_headless/trajectory_score.py`。三样输入的来源：

| 输入 | 来自 | 为什么不是执行方定的 |
|---|---|---|
| `BUDGET = 8` | `artifacts/start.json` | 题目本来就有 |
| 合法候选集 2304 个 | `probe_cns_brief.enumerate_repairs` | 定天花板时本来就要枚举，不是为这条新建的集合 |
| 化验序列 | workspace 的 `tool_calls.jsonl` | 工具本来就在写，不用改接口 |

**没有阈值、没有及格线、没有权重。** 报的是原始数字加它在盲抽分布里的百分位。
本题参照线（实算）：`1.875 2.283 2.503 2.651 2.763 2.853 2.929 2.994`；

# 【正式批开跑之前登记】2026-08-30 · 骨架门的层次纠正、口径变更、批量裁定

## 1. 业主纠正：骨架门不是"额外约束"，是"答对"的定义

业主 2026-08-30 原话：「**如果 agent 最后的答案去掉了骨架，那么最后的结果根本就不对，
就没有后面比较同样对但是方案不同的衡量了。**」

执行方此前把三道门（合法 / 保骨架 / 已化验）当成"可以追认或撤销的约束"在讨论，
**层次错了**。它们是**入场判据**：不过门 ⇒ 答的不是这道题 ⇒ 没有答案 ⇒
不进"同样答对、比谁答得好"那个池子。平均领先量衡量的是**过了门的答卷之间**的差别，
与门本身不在同一层。

**据此撤回执行方两条错话**（原文留在上一节，不删）：

| 撤回的话 | 为什么错 |
|---|---|
| 「骨架门一票归零太粗，跟 `cp_axes` 三档是同一个病」 | 答案不对就该 0，这不粗。且死因没丢：`details.gates.keeps_scaffold=false` 与 `n_axes_ok_recomputed` 同时在输出里（已实测验证） |
| 「`assay` 不检查骨架是设计缺陷，应让它返回保骨架与否」 | 骨架 SMILES 印在题面第 1 条硬规则里，"我这分子算不算合法答案"是 agent 自己能算的。`qwen3-coder-plus` **真算了**（notes 原文："achieved 3/4 criteria but didn't preserve the required Murcko scaffold"）然后没交它。这是题的一部分，且有判别力 ⇒ **`assay` 不加骨架检查** |

**同时撤回一个已提议的实验**：「删掉题面第 1 条硬规则跑 3 run 做对照」。
撤掉骨架门不是"同一道题少一条约束"，是**换了一道题**，对照无意义。

业主 2026-08-30 追问「不让改骨架是谁规定的」，查证结果：

### 10.4 冻结指标与裁决

覆盖率。每模型取五轮均值；不确定性按实验标签分层做 10,000 次分子 bootstrap，同一

为 95%，分位数用 nearest-rank ceiling。
