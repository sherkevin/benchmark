# ADR-0002: Step 1 工具表 schema——一行一个工具、输出性质类型为必填列、可用性作主表门槛

- 状态：Accepted
- 日期：2026-09-03
- 决策人：jingwu（对话中三次裁定，逐步收敛）

## 背景

第一版调研表（`docs/step1_tool_inventory.csv`，7 列）被否决，问题有四：
1. 粒度混乱——benchmark、数据库、工具端点子行（如"ADMET-AI bBBB"）与工具混排；
2. 缺少"输出是什么"的系统描述——读表人无法从表中得知一个工具的用处、输入与输出；
3. 没有可用性门槛——已下线/无法部署的工具与可用工具混在一起；
4. 版本混写——v1/v2 等权重不同的版本被当成一个工具。

## 决策

新表（`docs/step1_tool_inventory_v2.csv` + `docs/Pharma_Tools_Survey_v2.md`）采用以下 schema：

1. **一行 = 一个工具**。版本拆分遵循 [ADR-0001](0001-tool-identity-version-lineages.md)
   （权重/训练数据/端点定义有变的版本是不同工具，如 ADMET-AI 1.4.0 与 2.0.1、
   Vina 1.0 与 1.2.7、Epik 经典与 Epik 7、Protenix v0.5 与 v2、NetMHCpan 4.1 与 4.2）。
   **通用平台的端点不拆子行**，并入父工具行的输出枚举。
2. **12 列固定**：类别 / 工具（含版本）/ 工具是什么·功能 / 输入 /
   输出性质类型（分类逐点）/ 输出数值形态 / 发版时间 / 发布方（机构）/
   来源文献·DOI / 权威性依据 / 部署方式 / 可用性核验（2026-09-03 方法与结果）。
3. **输出性质类型为必填列**，使用受控词表（代码见文档 §二）：
   R 连续回归值、C 分类标签、P 概率/置信度/适用域、Q 参考分位/旗标、
   S 3D 结构/坐标/pose、M 原子/残基级映射、A 结构警示/规则、G 生成式输出。
   一个工具输出多种性质时逐点全部列出——这是后续数据构造（冲突诊断）的关注点。
4. **主表只收真实可用的工具**：2026-09-03 逐条核验（GitHub/PyPI JSON API、
   HTTP 开页、官方发布页）。确认死亡或本地无法验证者移入独立剔除清单，
   附证据与恢复路径，不与可用工具混排。
5. **benchmark、数据库、框架不进主表**，各占辅助章节。理由：它们不是
   "对分子/蛋白给出预测输出的模型工具"，而是主表工具的评测协议、
   训练数据来源或运行底座。

## 理由

1. 数据构造阶段需要按"输出性质类型"组织冲突对（二分类端点与回归端点
   的计分口径不同），输出类型必须显式在表，不能靠读论文反推。
2. 一行一个工具 + 可锁版本标识，保证后续每条 benchmark 记录能回溯到
   唯一权重（与 ADR-0001 一致）。
3. 不可用的工具写进主表会污染选型：提案若选中一个已下线的 web 服务器，
   整组数据无法复现。

## 后果

1. 旧表 `docs/step1_tool_inventory.csv` 作废，仅保留作历史参考，不再维护。
2. `docs/Pharma_Tools_Survey.md`（v3）的事实核验结论全部被 v2 继承，
   附录三的更正记录继续有效；v2 在其上叠加可用性核验与 schema 重排。
3. 后续新增工具必须同时提供 12 列全部信息与当日核验证据，否则不进主表。
