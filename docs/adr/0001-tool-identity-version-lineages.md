 # ADR-0001: 工具同一性以"模型权重+训练数据+端点定义"为准，重训版本是不同工具

 - 状态：Accepted
 - 日期：2026-09-03
 - 决策人：jingwu（对话中明确裁定）

 ## 背景

 Step 1 制药工具调研（`docs/Pharma_Tools_Survey.md`、`docs/step1_tool_inventory.csv`）
 中，部分工具存在大版本跨越。典型案例：ADMET-AI v1.x（Chemprop-RDKit，TDC 旧版数据）
 与 ADMET-AI v2（Chemprop v2，PyTDC 1.1.15 从头重训，2026-02-17 发版）。
 两者同名、同仓库、同入口，但模型权重和训练数据完全不同，
 官方 release notes 明确写明"v2 的预测值不会等于 v1 的预测值"。

 ## 决策

 调研、清单与 benchmark 数据构造中，**工具同一性 = 名称 + 模型权重 + 训练数据 + 端点定义**。
 凡版本升级涉及模型重训或训练数据更换，新旧版本视为**两个独立工具**，
 各自占一行、各自锁版本；不得混为一谈，不得共用文献与指标。
 不改变预测值的变更（打包修复、设备格式修复等，如 v2.0.0→v2.0.1 的
 MPS→CPU checkpoint 修复）属于同一工具的补丁，不构成新工具。

 ## 理由

 1. 本 benchmark 测量的对象是"工具输出与实验真值的偏差"。权重不同 ⇒ 输出不同
    ⇒ 冲突模式与对错判定全部不同，混用会使记录表失去可复现性。
 2. "同一个工具"的说法在入口不同（pip 默认 vs 官方 web 服务器）时可能指向
    不同权重，歧义必须在数据构造阶段消除。
 3. 同名工具的版本漂移本身是一类天然冲突源，属于 benchmark 应测量的对象，
    而不是应在清单里抹平的噪声。

 ## 后果

 1. `docs/Pharma_Tools_Survey.md` §三与 `step1_tool_inventory.csv` 中的
    ADMET-AI 行应拆分为两行（v1 系、v2），并分别标注各自文献：
    v1 系对应 Bioinformatics 2024 btae416；v2 无独立论文，权威来源为
    官方 release notes 与仓库内置端点表。（待办）
 2. step1 记录表的工具字段必须含可锁定的版本标识（PyPI 版本或 git commit）。
 3. 讲解、引用任何工具时，一次只讲一个版本谱系。
