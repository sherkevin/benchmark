# ADR-0006: 训练目标以「判断这组预测能不能用」为准，选工具偏心降为评测目标

- 状态：Accepted
- 日期：2026-09-13
- 决策人：jingwu（owner 显式授权「按照这个目标，你去自己裁决一下」后，由执行方代裁并落盘）
- 裁定对象：`docs/目标.md`「一处待裁的目标冲突」登记的冲突——[ADR-0028](../inherited/0028-calibration管线v1四方评审裁决.md) D1 与 `docs/Proposal.md` §3.7 对训练目标给出不同说法
- 取代范围：`docs/Proposal.md` §3.7 的训练目标表述「矫正训练诱导的工具偏好过拟合」**仅在训练目标这一处**被本 ADR 覆盖；其 §1–§3.3 评测层、§2 文献表、§3.4 判分损失式不受影响

## 背景

`docs/目标.md` 的「一处待裁的目标冲突」登记了一处未裁冲突，裁定前第三层往后的训练设计全部停摆、不申请 GPU。冲突的实质是：agent 要被训练去做的那件事，到底是「在多个工具里挑出更可靠的那个」，还是「判断这组预测能不能拿去做决策」。

两份在役文档各执一词：

- **ADR-0028 D1**（状态 Accepted，2026-09-02，决议人 jingwu，综合方法论/文献/RL 稳定性/devil's advocate 四方评审）：可训练主任务从「选哪个工具」改为「这组预测能不能拿去做决策」+ 选择性作答（answer/abstain/escalate）；「选哪个工具」只保留作评测目标，取消它的训练地位。
- **`docs/Proposal.md` §3.7**（已提交在役，2026-09-09 入库）：训练目标写为「矫正训练诱导的工具偏好过拟合」，即让 agent 按「这个工具对当前任务有多大帮助」选工具。这正是 D1 取消训练地位的那一档。

时间线关键事实（查证见 `docs/inherited/README.md`）：ADR-0028 落盘于 09-02，但只存在于 git 未跟踪的 `archive/` 目录，`git clone` 看不到；`docs/Proposal.md` 入库于 09-09，晚七天。两者互不引用。

## 决策

**可训练主任务定为「判断这组预测能不能拿去做决策」（分子主效应 α_i 驱动）+ 选择性作答（answer/abstain/escalate），即维持 ADR-0028 D1。「选哪个工具 / 纠正选工具偏心」降为评测目标，不进入训练环。**

连带裁定 `docs/目标.md`「需 owner 裁的四件事」：

1. **现行权威以七步稿为骨架**（`docs/inherited/提案_20260902_七步v2_未入库稿.md`），把 358 行入库版的 §3.4.1 方差分解推导与 ADR-0028 D2-⑤ 纯采样基线 pass@k 并进去。`docs/Proposal.md` 仅在训练目标一处被覆盖，其余部分（§1–§3.3 评测层、§2 文献对照表、§3.4 判分损失式 `L = I(答错) + c·I(弃答)`）仍有效。
2. **`docs/Proposal.md` §3.7 判定为未吸收的回退，不是有意推翻。** 处理是补吸收，ADR-0028 维持 Accepted，不标 Superseded。依据是它入库时 ADR-0028 只在未跟踪的 `archive/` 里、clone 不可见，知情可能性低。
3. **七步稿两处缺口（D2-⑤ pass@k、§3.4.1 方差分解推导）由本地补齐，且必须在任何 GPU 申请之前完成**——ADR-0028 D2 明写五条检验顺序不可颠倒。
4. **owner 工作区那批未提交删除：内容安全，删除动作归 owner。** `governance/提案_20260901_...` 与 `governance/讨论_20260901_...` 已逐字复制进 `docs/inherited/`、md5 与原件核过一致，提交删除不丢内容；但它们属 owner 工作区状态，本 ADR 只登记「内容安全」，不替 owner 执行删除提交。

## 理由

**一、这一条是「按照目标」裁，不是违背目标。** `docs/目标.md`「一句话」写明的失败模式是「工具正常返回了结果，但结果不可靠，而 agent 察觉不到，还照着它继续往下做决策」。要纠正的是「察觉不到 + 照着决策」这个动作。能直接对上它的可训练能力是「判断这组预测能不能拿去做决策」，而不是「在 K 个等价工具里挑哪个」。`目标.md` 里「纠正选工具偏心」那句是更窄的表述，下面第二条证明它在定义层站不住。

**二、§3.4.1 的方差分解是定义层的不可能性，不是经验问题。** 把工具 k 在分子 i 上的误差分解：

$$e_{ik} = \mu + \alpha_i + \beta_k + \gamma_{ik} + \varepsilon_{ik}$$

其中 α_i 是分子主效应（这个分子对所有工具都难预测的程度），β_k 是工具主效应（工具全局精度），γ_ik 是交互项（这个工具在这类分子上特别偏），ε_ik 是含实验噪声的残差。

- 「从 K 个预测里选最准的」（argmin_k e_ik）这个答案由**交互项 γ_ik** 决定，而 γ_ik 绑定具体工具，换一套工具就失效。
- 「判断这组预测能不能拿去做决策」这个答案由**分子主效应 α_i** 决定，α_i 是分子属性，换工具仍然有效。

二难是硬的：若困难真是分子属性（α_i 主导），则所有工具一起变差、argmin 不动，对选工具**零信息量**；若选工具确实有信号，信号只能来自 γ_ik，而它按定义绑定工具。**「能迁移」与「任务有信号」对选工具任务在定义层互斥**，不是实验能裁定的。而第三层 Step 6/7 的核心主张恰是迁移（leave-one-tool-out 工具泛化、跨领域零样本）——选一个定义层不可迁移的训练目标，会亲手砸掉项目要主张的泛化能力。α_i 路线则天然跨工具。

**三、§3.7 是没吸收，不是推翻。** ADR-0028 状态 Accepted、未作废，落盘早七天，但物理上只在 git 未跟踪的 `archive/` 里，远程 clone 看不到。`docs/Proposal.md` §3.7 写回纠偏心，最合理解释是撰写时不知情。对「不知情」的正确处理是补吸收，不是把先决议标 Superseded。

## 后果

1. **GPU 闸门保持关闭。** 本 ADR 不解锁任何训练侧机时。裁定后仍须先过 ADR-0028 D2 的五条零机时检验（①方差分解 α_i 占比 + 标签噪声翻转率；②裸答检索天花板 + 恒答基线；③经典方法擂台，同表随机森林/conformal；④scalar-only 与 content-shuffle 消融；⑤纯采样基线 pass@k），顺序不可颠倒，全部通过前不申请 GPU。
2. **判分损失式不变。** `L = I(答错) + c·I(弃答)`、弃答作为输出选项、c 绑行动配 Brier proper scoring rule、有效区间 (0.157, 1.59]，全部按 ADR-0028 D4 保留，`docs/目标.md` 上文照写不动。
3. **C 信号降级为取证触发与审计字段**，不再是监督目标（ADR-0028 D1 末句）。
4. **作废清单维持**（ADR-0028 D3）：property rotation、训练面遮蔽工具身份（遮蔽移到评测侧）、离散 accept/verify/arbitrate 三动作 RL 奖励表、GRPO，均不得复活。
5. **文档动作以指针为主，不改写台账原文。** 本 ADR 是这条决策的唯一权威出处；`docs/目标.md`、`docs/Proposal.md` §3.7、`docs/任务清单.md` 的相关条目改为指向本 ADR，冲突登记段保留作历史。
6. **七步稿补缺口前不得申请 GPU**，缺口为 D2-⑤ pass@k 与 §3.4.1 方差分解推导（推导原文在 358 行入库版 §3.4.1，本 ADR「理由」二已引）。
