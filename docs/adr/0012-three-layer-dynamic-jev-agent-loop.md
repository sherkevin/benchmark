# ADR-0012：动态工具适应、动态 Jev 与 Agent 可靠调用的三层闭环

日期：2026-09-24

状态：Accepted（研究主线与系统分层）；具体网络结构、损失、实验参数与投稿贡献仍待验证。

## 背景

前一版把在线模块主要写成“收到功能请求后选择具体 provider”。Owner 进一步明确，工具选择只是底层动作，论文要解决的是 Agent 面对正常返回但可能错误的工具证据时，能否主动复核、验证、拒答并可靠完成调用流程。

Owner 同时明确三项交付：面向工具调用的动态适应模块；高效、实时学习的动态 Jev 方法；以及由该模块增强的 Agent 工具调用能力。

## 决定

采用三层闭环作为当前主线：

1. **动态工具适应模块**维护任务状态、候选工具、已见工具输出、反馈历史和预算。它负责选择具体模型、估计验证收益与风险、管理工具版本和反馈时钟，并向主 Agent 提供结构化建议。
2. **动态 Jev**作为该模块的结构化决策核心。它接受状态与候选选项，回答工具选择、证据是否可信、是否需要复核、是否应作答或拒答等 typed decisions。预训练判别表示负责冷启动，在线小型头/adapter或后验根据真实反馈持续更新。Laya是可复用的Jev类实现与表示起点，不是已确定的最终模型。
3. **主 Agent 能力提升**把动态 Jev 的结构化状态和决策接回 Agent 的调用轨迹，使 Agent 学会请求、读取、交叉验证、复核、作答和拒答。最终收益以 Agent 的错误、覆盖、调用预算和校准共同衡量。

工具选择、工具复核和拒答属于同一条可靠证据链的不同动作。模块估计和建议这些动作，主 Agent policy 决定是否执行复核、作答或拒答；不能只报告 provider 命中率而宣称完成了 Agent 能力提升。

## 反馈与学习边界

工具返回可以立即被 Agent 看到，但“返回是否可靠”通常要等任务终止和外部真值到达后才能判断。动态 Jev 只能用已经观察到的反馈更新，未调用工具不补负标签，未知真值进入 pending。首版冻结预训练主体、更新轻量决策头并保留探索；后续再评估更新 adapter 或骨干。

选择概率、工具正确率、证据可信度和探索不确定性分别建模。Jev 的 Choice 分布或熵集中度不能直接当作任一工具的正确概率。

## 研究判据

先分别验证动态 Jev 的冷启动与在线适应，再验证动态工具模块的选择、复核和拒答策略，最后做端到端 Agent 交互实验。所有阶段都要与静态 Jev/Laya、标准 contextual bandit、已有预训练路由＋在线反馈方法、规则流程和固定工具比较，并记录先决策后更新的日志。

若预训练表示没有冷启动信息，不能保留冷启动主张；若在线更新不能改善后期决策，不能保留实时学习主张；若动态模块不能改善 Agent 的错误率、覆盖率或调用效率，不能保留综合能力提升主张。

本决定细化并扩展 [ADR-0011](0011-pretrained-discriminative-online-decision.md) 的方向，不把其候选实现或“足够一篇论文”判断视为已证结论。Task38 数据资格、Task42 反馈协议和当前训练暂停继续有效。
