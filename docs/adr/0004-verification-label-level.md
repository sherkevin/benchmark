# ADR-0004: 核验准入判标签级，概率漂移只记账

- 状态：Accepted
- 日期：2026-09-04（2026-09-13 独立成文，原为 [ADR-0003](0003-step1-verification-protocol.md) 文末修订节）
- 决策人：jingwu
- 取代范围：ADR-0003 §一 L3 准入第 3 条原文「同输入同版本跑两遍，结果逐位一致（漂移为 0）」

## 背景

ADR-0003 定的 L3 准入第 3 条要求逐位一致。B3clf 把它逼停了。

B3clf 的特征由 PaDEL 计算，PaDEL 是一个 Java 描述符程序，它对同一份固定几何重复算会给出不同描述符，于是概率在小数点后第四位抖动：咖啡因在八次重放里取 0.9317634105682373 与 0.9326184391975403 两个值。抖动幅度约 0.0009，从未跨过 0.5 判定线，标签始终是「能透过」。

逐位一致这条线会把 B3clf 挡在判分列外，而它的判定其实是稳定的。挡掉一个判定稳定的工具，等于把工具的真实分歧当成工具故障处理。

## 决策

L3 准入第 3 条改为：**同输入同版本跑多遍，标签跨轮稳定即可准入；概率漂移只记录、不拦截。**

默认重复轮次从 2 提到 8。

两个量分别记账，落在 `verify_runtime.py`：

| 字段 | 级别 | 用途 |
| --- | --- | --- |
| `label_stable_across_runs` | 准入用 | 为真才进判分列 |
| `deterministic_across_runs` | 观测用 | 为假说明概率在抖，记下来，不拦 |

逐轮取值见 `data/bbb_census_v3/runtime_verification/<tool_id>.json` 的 `value_spread`。

## 理由

**标签级与普查的原生口径一致，逐位一致反而比普查本身更严。** 普查判分歧只看标签：`tool_conflict_census.pair_is_stable` 逐轮比的是 label，不是概率。概率漂移没有被丢弃，而是由 `summarize_model_runs` 的 `maximum_probability_drift` 逐模型记账。既然下游消费的是标签，准入门槛就该设在标签上。

**旧口径一度显得成立，是因为重复轮次太少。** 两遍重复对抖动工具的检出率低：B3clf 的低值八次里只出现两次，跑两遍有很大概率两次都抽到同一个值，于是误判成「逐位一致」。提到八轮后抖动稳定暴露。这说明逐位一致不是更严格，是更不可靠——它的结论取决于运气。

## 后果

1. ADR-0003 文末的 2026-09-04 修订节保留原文不改写，改为指向本 ADR。
2. 任何工具下「标签稳定」结论时，须同时检查是否存在恰好落在阈值上的输出。这条来自 DeePred-BBB 的实测教训：氟西汀被 NaN 污染，概率从 0.371 变 0.500，但两值落在 0.5 同侧，标签始终不变，标签稳定性闸门判它稳定，而模型那一次实际吃进去的是 NaN。这类污染闸门看不见，只能在注册表一层记账。见 `docs/计划_全工具远程跑批与结果库.md` §六。
3. 概率漂移进入数据集时保留原值，不平均、不舍入。BayeshERG 是现行案例：730 个概率对两轮全部不同，最大绝对差 0.15455221000000002，已原样进交付。
