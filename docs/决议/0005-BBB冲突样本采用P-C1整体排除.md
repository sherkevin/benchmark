# 0005 BBB 冲突样本采用 P-C1 整体排除

- 状态：生效
- 确认日期：2026-09-29
- 决策来源：用户授权 Codex 自行裁定 benchmark 分母、冲突处理和运行合同等技术细节；Codex 完成审计后生效
- 适用范围：TDC BBB 主开发 benchmark、未来 BBB confirmation 候选和所有依赖该 truth 的 routing replay
- 替代关系：无

## 背景

TDC `BBB_Martins` 的 canonical audit 发现 10 个同时包含标签 0 和 1 的冲突组：train/validation 8 组，official test 2 组。当前公开文件没有逐行 assay provenance、测量条件或时间顺序，无法证明某一行比另一行更权威。

项目不能用第一行、多数票或模型预测静默修正标签，也不能让被评价的 provider 或 selector 决定 benchmark 真值。旧 development panel 与官方 test 还存在 canonical/scaffold overlap，因此 confirmation 必须另建清单。

## 决定

1. 采用 **P-C1：canonical-conflict exclusion**。冲突组中的所有行整体排除，不修改原始 TDC 文件，不选择其中一条作为真值。
2. 每个派生 manifest 必须保存冲突收据 SHA、冲突组数量、排除行数和清洗前后分母；主结果使用排除后的 molecule-level 分母，附录保留原始行级统计。
3. 当前 BBB development manifest 使用版本化文件 `task49-bbb-authoritative-development-v1`；它保留原有 722 条已通过历史 unresolved 过滤的 development rows，并显式绑定 10 组冲突收据。此次没有新增删除，因为这些 10 组已不在该 development cache 中。
4. 已生成的 157 条 scaffold-disjoint confirmation candidate manifest 继续作为候选；方法、provider menu、epoch、threshold、baseline 和评估器冻结前不得打开 confirmation。
5. hERG 和 AMES 必须分别完成 canonical conflict、duplicate、endpoint semantics 和 provider lineage 审计，不能未经审计直接复制 BBB 的清洗结果。

## 理由

整体排除是当前唯一不引入额外标签先验、模型循环论证或文件行序假设的可审计规则。它牺牲少量潜在样本，换取 truth 独立性、分母稳定性和重复运行一致性。

## 后果

- 历史使用 `truth_unresolved_bbb.json` 的结果继续保留，但从本决议起，新 baseline 和新方法必须指向带 P-C1 receipt 的 manifest。
- 旧结果不能被重新命名为 P-C1 结果；若需要正式主表，必须用新 manifest 重新生成统一事件日志。
- P-C1 不证明 TDC 标签没有实验噪声，也不授予 hERG/AMES 资格；它只规定 BBB canonical conflict 的处理方式。
