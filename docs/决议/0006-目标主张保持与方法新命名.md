# 0006 目标主张保持与方法新命名

- 状态：生效
- 提出日期：2026-09-29
- 生效确认：用户于 2026-09-29 明确确认“不能直接叫 JEV”“目标 claim 不能降”，并要求继续修 bug、改方法和迭代实验
- 适用范围：故事线、方法论、论文写作、实验计划和方法命名
- 替代关系：对 `docs/adr/0045-direct-dynamic-jev-information-boundary.md` 中“暂停 direct 动态主创新声明”的**主张降级部分**作替代；该 ADR 的负结果、信息边界和“不靠调参挽救”的证据仍然保留

## 背景

本轮 development 结果没有证明当前实现版本有效，主要暴露了 Best Fixed 很强、selected-only 反馈可识别条件不足、selector 与 verifier estimand 混淆、provider lineage 和 benchmark contract 未闭合等问题。此前审查把这些问题转成了“暂时不写动态方法主张”，这会把实现版本的失败误读成研究目标被取消。

用户明确确认：研究目标仍是完成一个面向科学工具调用的动态适应模块、一个能从延迟 outcome feedback 实时学习的高效方法，以及对 Agent 可靠工具调用能力的整体提升。当前负结果用于定位 bug 和修改方法，不用于自动降低目标 claim。

## 决定

1. **目标 claim 保持不降。** 论文目标仍包含：工具选择、调用后验证/复核/拒答、selected-only 延迟反馈下的实时状态更新，以及在相同信息和预算下提升可靠性、风险覆盖或调用效率。当前结果不足以证明目标已完成，但不能据此把论文改成只报告负诊断的论文。
2. **证据状态与目标状态分开。** 主线文档可以同时写“这是我们要完成的中心方法”与“当前实现尚未通过 Gate”；前者是研究目标，后者是实验事实。禁止把未完成的结果写成已验证事实，也禁止把目标本身降为协议或负结果。
3. **论文和方法统一使用新名称 `MIRA`。** 工作全称为 **MIRA: Menu-aware Incremental Reliability Adaptation for Scientific Tool Calls**。MIRA 覆盖调用前选择、调用后验证/升级/拒答和延迟 outcome 更新；不再把 JEV 作为论文方法名。JEV 只在相关工作、历史记录或代码兼容说明中作为功能参照出现。
4. **MIRA 不是换名字就算创新。** 必须继续完成信息边界、状态更新、不变量、integration gain、最强 matched baseline 和独立 confirmation；名称只解决论文对象的一致性，不替代方法证据。
5. **迭代路线保持开放。** 允许在现有算力和时间预算内修复实现、修改更新目标、增加合法探索/先验、改进状态参数化和重新跑 CPU/A800；每一轮都必须先记录问题根因、改动、最近邻、预期改善和 kill criterion。
6. **当前负候选不等于 MIRA 被否定。** Online-SGD、Replay、Greedy、PILOT、BayesianRouter、provider-transfer、context-memory 和 dynamic verifier 的失败只停止对应实现版本或候选，不自动停止 MIRA 总体目标。

## 执行约束

- 先补 Gate 0/1 的 scope、benchmark contract、baseline fidelity 和信息泄漏检查，再进入新的主效果实验。
- 每个新候选必须有独立 method card；不允许用多候选中最好的结果拼出 MIRA。
- 目标 claim 可以写入故事线和方法路线，但摘要、主结果和结论中的“已提升/已验证”必须等待匹配实验和 confirmation。
- 每次负结果都要回答：是代码 bug、数据/lineage 问题、信息不可识别、预算不公平，还是机制本身被反例推翻；只有最后一种才提交创新点修改讨论。
- 方法名在投稿前做一次外部 prior-art/name collision audit；若发现同名，另起新名，但不改变本决议的目标 claim。

## 后果

- `docs/研究主线/生效/01-故事线与创新.md`、`02-方法论.md` 和 `03-Benchmark与Baseline.md` 后续版本把 MIRA 作为目标方法名，同时保留当前负结果和未完成闸门。
- `docs/adr/0045` 的“暂停 direct 动态主创新声明”不再作为目标降级依据；它的具体负结果和安全实验闸门继续有效。
- 研究计划的下一步是“修复并验证 MIRA”，不是“把论文改写成 protocol/negative diagnosis”；如果最终所有合法候选都失败，再由双方单独讨论是否修改主张。
