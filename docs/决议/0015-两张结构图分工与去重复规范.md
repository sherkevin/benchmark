# 0015 — 两张结构图分工与去重复规范

- 状态：生效
- 日期：2026-10-07
- 关联：0012、0013、0014

## 背景

用户指出 Figure 1 v07 的画面更干净，Figure 2 从 v23 起开始重复 Figure 1 的架构，多个模块直接写 `A/B/C` 或重复 provider 身份，削弱了两张图各自的作用。

## 决议

1. Figure 1 负责方法架构：展开冻结分数、在线残差/状态、合成、选择和 selected-only 更新；以 v07 的紧凑视觉密度作为参考，但必须重新对齐当前方法。
2. Figure 2 负责单次事件时间线：只表达 `decision → call → terminal → judge → pending → release → later decision`，不再重复 Figure 1 的 features、scorer、residual、counter register 或完整候选菜单。
3. Figure 2 默认不在模块上重复写 provider 字母；使用 `selected call`、`selected result` 等自然短标签和单个事件 token 表达身份。
4. Figure 1 也不把 `A/B/C` 作为多个模块标题；provider 示例只保留必要的一个 selected token、一个高亮行或图标。
5. 共享色板和箭头语法，但两图必须有不同的视觉中心：Figure 1 是结构合成，Figure 2 是时间延迟。
6. 新版本仍按 0013 保存原图、prompt、manifest、审查和失败现场；用户偏好的 v07 只作为视觉基线，不能未经方法核对直接覆盖主版。

## 理由

两张图必须形成互补证据：第一张解释“方法是什么”，第二张解释“反馈何时可见”。重复同一架构会浪费版面，也会让审稿人误以为方法只有静态模块拼接，没有独立的延迟事件语义。

## 后果

- `paper/aamas2027/figures/figure_role_contract_20261007.md` 成为后续两图 prompt 和审查的约束。
- Figure 1 v07 保留为视觉参考；Figure 2 从 v26 起重新设计为去架构重复的时间线。
- 当前 `figures/qa/main.pdf` 不自动改变，待新版本审查并由用户选择后再按 0014 同步。
