# 论文叙事范式作为写作评审基准

## 背景

项目需要持续打磨 AAMAS 医药工具选择论文的故事线、方法论证和文字表达。用户提供并确认将《Story Is All You Need：扒透35篇顶会最佳/杰出论文的叙事密码，我们找到了六大范式》作为后续写作参考。该材料的完整整理稿位于 [`research/2026_AI顶会最佳杰出论文叙事范式_六大范式_阅读整理.md`](../../research/2026_AI顶会最佳杰出论文叙事范式_六大范式_阅读整理.md)。

该材料的事实来源和其中列出的会议奖项尚未独立核验，因此本决议采纳的是它提出的研究叙事与审稿方法，不把文章中的论文、数字或奖项自动当作项目事实。

## 决定

1. 后续论文写作、故事线讨论和段落审查，以“叙事是研究论证的外显结果”为基本原则。先明确任务、失败现象、可检验根因、机制、证据和反证条件，再优化表达。
2. 使用以下六类叙事范式作为候选检查框架；一篇论文可以命中多类，但必须明确一条主线：
   - **根因手术刀**：先解释现有方法为什么失败，再提出针对性机制。
   - **反直觉重构**：挑战默认设定，并证明更简洁或更合适的替代。
   - **理论照亮经验**：用定理、形式化分析或可推导机制解释经验结果。
   - **新基准暴露失效**：用更锋利的任务、指标或数据揭示系统性漏洞。
   - **社会价值叙事**：把技术贡献连接到真实的应用痛点、可靠性或治理价值。
   - **极简统一美学**：用统一接口、表征或机制覆盖多个职责，并证明不是模块堆叠或调参偶然。
3. 每轮写作审查至少回答六个问题：
   - 现有方法具体在哪里翻车？
   - 失败背后的根因或被忽视的漏洞是什么？
   - 本文的方法为什么正好针对该根因？
   - 哪个设定、接口或阶段关系被重新定义了？
   - 哪些实验能区分机制有效与调参、数据或实现偶然？
   - 什么结果会证伪当前故事，或迫使我们收窄主张？
4. 后续 Codex 在本项目中承担两种写作协作角色：
   - **写作打磨者**：改善结构、段落顺序、术语一致性、标题、摘要和句子表达，但不通过修辞掩盖证据缺口。
   - **审稿 reviewer**：从问题重要性、根因可信度、机制必要性、实验因果链、最近邻差异、可解释性和主张边界提出质疑，并明确指出需要补证据、收窄主张或重写的位置。
5. “只报 SOTA”“跟风裁缝”“把包装话术当叙事”视为高风险写作信号。出现这些信号时，优先回到问题定义和证据链，而不是继续润色措辞。

## 理由

- 在指标差距小、审稿时间有限的环境里，审稿人需要一条快速但可核验的因果链来判断贡献。
- 根因、机制和反证条件比泛泛的“效果更好”更能区分真实贡献与常规工程叠加。
- 将六类范式作为检查框架，而不是硬套模板，可以同时保留理论、基准、社会价值和统一设计等不同类型贡献。
- 把写作打磨与 reviewer 质疑放在同一协作流程里，可以避免语言优化先于科学主张收敛。

## 后果

- 后续主线文档、论文草稿和研究报告中的故事线审查，应引用本决议，而不是各自重新定义“好故事”。
- 每个候选主张都要说明主叙事范式、最近邻差异、支持证据和否定条件；如果没有这些内容，不能只靠增加 SOTA 表格来补强。
- 文章中未核验的 35 篇论文、奖项和数字只能作为启发或待核验线索，不能直接写入论文事实陈述。
- 如果后续用户与 Codex 形成新的写作原则，应新建决议并在本文件标记替代关系，不静默改写本决议。
