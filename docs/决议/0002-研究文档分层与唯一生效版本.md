# 0002 研究文档分层与唯一生效版本

- 状态：生效
- 提出日期：2026-09-28
- 生效确认：用户于 2026-09-28 明确要求按三份主线文档、三份评价标准和小决议治理；Codex 已完成文件复核并落地
- 替代关系：替代 0001 中“把完整评价原则放进决议”的组织方式；不删除 0001 的历史内容

## 背景

项目同时有故事线、方法候选、benchmark 合同、审稿标准、实验报告和许多旧方案。它们都写“当前”会造成同一问题出现多个口径，也会让一次实验失败被误读成单方面改掉已确认的创新点。

## 决定

### 1. 六份主文档是唯一研究入口

当前只维护以下六类生效文档：

1. 故事线与创新点；
2. 方法论；
3. Benchmark 与 Baseline（包含要做的实验）；
4. 故事线评价标准；
5. 方法论评价标准；
6. Benchmark 与 Baseline 评价标准。

它们统一放在 `docs/研究主线/生效/`，版本放在 `docs/研究主线/版本/`。每类同时只能有一个生效版本。

### 2. 主文档和证据分工

主文档写研究口径、约束、评价方式和当前边界；`task/`、`research/`、`experiments/logs/` 写实验细节、来源、原始结果和失败现场。主文档引用证据路径，不复制一份容易过期的数字。

### 3. 决议只保存小而关键的共识

`docs/决议/` 只记录双方已经确认、之后容易重复争论的取舍、约束、争议裁定和不可逆边界。某个模块的实现、超参、一次回放结果和仍在比较的方案，留在方法文档或 task 文件，不塞进决议。

### 4. 版本变更要可追溯

新版本先进入 `版本/`，双方确认后才成为生效版；旧版不静默覆盖，继续保留并在索引中说明状态。若后来推翻一项小决议，另写编号更高的新决议，并在旧决议上写替代关系。

## 后果

- 读者从 `docs/研究主线/README.md` 就能知道当前唯一口径；
- 实验失败会先更新证据和候选状态，不会自动改写故事线或创新点；
- 旧文档仍可追溯，但不再因为文件名里写了“当前”就拥有主线权威；
- 以后新增内容必须先判断它属于主文档、证据文件还是小决议。

## 当前落地

六份 `v001` 文档已建立并相互链接。原 `0001-研究故事线与评价标准.md` 保留为历史记录，其完整原则已拆入三份评价标准和故事线文档；从本决议生效后，不再向 0001 追加主线内容。
