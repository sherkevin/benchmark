# AAMAS 2027 长期任务与推进原则

状态：生效的执行总则。  
日期：2026-09-29

## 长期目标

在题目 **After the Decision: Learning to Adapt from Delayed Outcomes** 下，完成一篇故事线、方法论、benchmark、baseline 和实验彼此闭合的 AAMAS 2027 论文。

方法目标是把 MIRA 做成面向科学工具调用的动态适应模块：它能从延迟的 selected outcome feedback 中实时更新，在工具版本或可靠性发生变化时安全调整选择，并把可信调用、失败处理和验证边界写进同一个可复现协议。

这条目标由 [决议 0006](决议/0006-目标主张保持与方法新命名.md) 保护。当前负结果只能触发定位问题、修方法和补实验，不能直接把目标改写成较弱的负诊断论文。

## 每一轮工作的固定顺序

1. 先读三份生效主线文档和对应评价标准，确认这一步服务哪个验收项：故事/创新、方法论、benchmark/baseline。
2. 写候选卡：要解决的具体失败、最近邻对照、可观测信息、数学更新、预期改善和停止条件。
3. 先做 CPU 或静态合同检查；没有通过就不申请 Nebula 效果任务。
4. 只运行一个边界清楚的小批次。配置、代码 commit、输入 hash、硬件、每条事件、失败现场和独立核验都落盘。
5. 用独立 replayer 或 verifier 复核结果，再做机制归因；生产日志本身不能充当自己的证明。
6. 把结果写入 task 报告和 `experiments/logs/`，在 `TODO_LOG.md` 留索引，然后回看是否仍在主线内。

## 不变原则

- **目标不降，证据不越界。** 目标 claim 保持；已经验证的结果、候选假设和最终论文 claim 分开记录。
- **一次只改一个关键机制。** 不能用堆 baseline、换表示或调阈值掩盖根因。
- **信息边界真实。** selector 只能读当时的分子、菜单、fit-only 先验和已释放 selected feedback；未选输出、当前真值、未来反馈和 post-call confidence 不能偷渡。
- **失败保留。** 失败实验不删除、不覆盖、不改写成成功；修复后使用新目录和新版本。
- **动态必须有事件。** 没有 arrival、retirement、drift 或 provider-version 事件，只能支持 fixed-pool online scope，不能支持 dynamic claim。
- **公平比较。** baseline 必须使用同一输入、菜单、延迟、预算、表示和 feedback contract；适配版与原论文差异单独写清楚。
- **不提前消耗昂贵资源。** 新方法先过数学、CPU、合同和独立回放闸门；Nebula 一次只跑一个任务。

## 停止与转向

出现以下任一情况，就停止当前变体并写报告：独立 replayer 不一致、决策前读到越界信息、no-event 超出预先 ROPE、controlled event 不能在至少两个 delay 恢复、收益来自额外调用/标签预算，或结果无法按 fold/scaffold 配对复现。

停止一个候选不等于停止长期目标。下一候选必须指出新增的信息来源或机制差异，不能只是换一个普通 online head、后验或阈值。
