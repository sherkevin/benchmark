# 制药科学预测冲突诊断与恢复 Agent Benchmark：Proposal

## 1. 研究动机

当前制药 Agent 已能调用大量分子性质、对接、亲和力、ADMET、蛋白结构和成药性预测工具。但这些工具多为统计学习或模拟计算，即使正常返回、格式正确、数值看似合理，也会因训练偏差、适用域变化、构象与参数假设等产生误差。多个工具可能对同一性质给出矛盾结论，甚至在错误方向上形成“伪共识”。

真正关键的问题不是 Agent 能否处理超时或异常，而是：**当科学工具正常工作但结果不可靠时，Agent 能否利用同功能工具和其他相关性质发现异常、定位可疑属性、选择更可靠的结果，并恢复后续研发决策。** 这直接影响虚拟筛选、先导优化、蛋白/抗体设计和候选优先级判断的可信度。

## 2. 相关工作及不足

已有工作分别覆盖了这一问题的部分环节：

*   **Mind the Tool Failures**^\[1\]^：在医学影像中研究多个诊断工具的实例级互补与仲裁，但不涉及分子或蛋白计算。
    
*   **Verify-or-Trust**^\[2\]^：测试 Agent 是否应验证有时会自信犯错的生物基础模型，但主要是“预测器—实验数据复核”，不是多个同功能工具间的科学仲裁。
    
*   **Protein-Structure Trust-Routing**^\[3\]^：测试是否应相信 Boltz-2 的结构置信度，并以实验结构为真值，但主要围绕单一预测器。
    
*   **BioDesignBench**^\[4\]^：证明蛋白设计 Agent 的主要短板之一是评价维度不足和过早停止，强制进行结构、界面、物理和亲和力多指标评价可以提升表现；但全部为 in silico，也没有控制性冲突标签。
    
*   **MolBench/MolClaw**^\[5\]^：覆盖长程小分子多工具工作流和质量检查，但主要评价任务完成度，没有单独评价“发现冲突—定位错误—选择替代工具—恢复决策”。
    
*   **TxBench-PP**^\[6\]^：使用真实的小分子临床前药理数据评测 Agent 的证据分析和研发判断，但不直接测试多个科学预测工具之间的冲突诊断与恢复。
    
*   **ToolBench-X**^\[7\]^与 **MemToC**^\[8\]^：分别研究不可靠工具环境中的冲突恢复，以及模型记忆与工具返回冲突后的仲裁；但缺少制药知识、真实科学模型误差和实验真值。
    

因此，目前仍缺少一套面向制药场景、以真实科学模型误差为冲突来源、同时评价跨性质诊断和同功能工具替换，并由实验数据提供隐藏真值的 Agent Benchmark。

## 3. 我们要做什么

### 3.1 核心任务

首版同时覆盖小分子与蛋白/抗体，设置四类递进任务：

1.  **同性质冲突识别**：多个 docking、affinity、ADMET 或结构预测工具给出不同结果，Agent 判断是否存在实质冲突。
    
2.  **跨性质异常诊断**：利用构象合理性、相互作用、置信度、溶解性、聚集、稳定性等互补性质，判断哪个属性或工具最可疑。
    
3.  **预算约束复核与仲裁**：Agent 在有限成本下选择同功能替代工具或正交验证工具，并选出更可信的结果。
    
4.  **下游决策恢复**：在修正错误后，重新完成 hit 排序、lead 选择、蛋白设计筛选或 go/no-go 决策。
    

超时、空返回和异常可作为次级鲁棒性测试，但不作为主要研究动机。

### 3.2 数据收集

**小分子数据**

*   **Hit 发现与湿实验验证**：CACHE^\[9\]^ 提供面向真实靶点的候选提交、实验测定和公开结果，可构造虚拟筛选排序、错误共识和命中恢复任务。
    
*   **物化性质与自由能**：SAMPL^\[10\]^ 提供 pKa、logD、溶剂化及结合自由能等盲测数据，适合比较多个性质预测或自由能工具的系统误差。
    
*   **对接、构象与亲和力**：D3R^\[11\]^ 和 CASF-2016^\[12\]^ 提供蛋白—配体 pose、affinity ranking、scoring 与 screening 数据，可构造 docking/affinity 冲突。
    
*   **活性和 ADMET 扩展数据**：ChEMBL^\[16\]^、BindingDB^\[17\]^ 和 Therapeutics Data Commons（TDC）^\[18\]^可补充大规模生物活性、结合常数、吸收、分布、代谢、毒性等 endpoint，用于训练、校准和外推测试。
    
*   对同一分子—靶点运行多个真实计算工具，保存原始输出、置信度、参数、软件版本、运行日期和失败日志，形成可复现的“工具—预测—实验真值”三元组。
    

**蛋白与抗体数据**

*   **抗体亲和力与成药性**：AIntibody^\[13\]^ 提供盲测设计、实验 affinity 以及表达、热稳定性、聚集和多反应性等 developability 测量，适合构造跨性质冲突。
    
*   **蛋白结构与复合物界面**：CASP^\[19\]^、CAPRI^\[20\]^ 和 FoldBench^\[14\]^可用于结构、蛋白—蛋白/抗体—抗原界面及 all-atom 预测冲突；RCSB PDB^\[21\]^提供实验结构真值。
    
*   **突变效应与蛋白适应度**：ProteinGym^\[15\]^ 汇集深度突变扫描数据，可测试 Agent 是否能在多个 fitness/stability 预测器不一致时进行复核和恢复。
    
*   对相同序列或复合物运行 AlphaFold、Boltz、Chai、ESMFold、Rosetta 及界面、稳定性、聚集和成药性工具，并保存模型置信度、构象、输入模板与 MSA 条件。
    

**统一与切分原则**

*   统一实体、质子化状态、构象、单位、实验条件和 endpoint 定义，避免把“定义不同”误标为“工具错误”。
    
*   不以随机篡改数值为主，而从真实工具残差中抽取自然分歧、错误共识、OOD、活动悬崖和高置信度错误；必要的受控注入也应按真实误差分布生成。
    
*   按 scaffold、蛋白家族、靶点和时间进行开发集、校准集、冻结测试集和隐藏外推集划分，实验真值只保留在私有 grader 中。
    
*   对每个来源记录许可证、可再分发范围和下载日期；无法公开再分发的数据只发布构建脚本、样本标识及评测接口。
    

### 3.3 测评框架与实验设置

Agent 在可执行沙箱中获得初始预测和工具目录，可自主调用同功能或互补工具；每个调用有成本，且不能访问隐藏实验真值。系统记录完整工具回执、参数、证据引用和决策时间。

评价分为：

*   冲突发现率与误报率；
    
*   错误属性/错误工具定位准确率；
    
*   复核工具选择质量与验证预算效率；
    
*   最终仲裁准确率及相对“实例级理想选择器”的 regret；
    
*   相对最佳固定单工具、多数投票和简单 ensemble 的 recovery gain；
    
*   恢复后的排序、筛选或 go/no-go 决策正确率；
    
*   置信度校准、合理拒答和证据可追溯性。
    

基线包括：始终相信首个工具、最佳固定工具、多数投票、平均/排名融合、传统 ensemble、不确定性路由、规则化一致性检查、领域专家和实例级 oracle。实验需比较小分子/蛋白、同性质/跨性质、不同冲突强度、自然误差/受控误差及不同预算，并进行多次重复和分组 bootstrap。

### 3.4 从评测到能力提升：训练闭环（2026-09-02 新增）

> 本节把 §6 八个未来方向里的**第 1、2、5、6 四条上收为主线**（第 3 条作配套；第 4、7、8 条保留为未来），
> 并给出从评测到训练的完整 pipeline。**§1–§3.3 原文一字未动。**
>
> **本节区分三类叙述**：① 已核实的事实（标出来源）；② 逻辑推理（写出推理链）；③ **待验假设（明确标"待验"）**。
> **本节不含任何未跑出的效果数字。**

#### 3.4.1 可训练的主任务须从"选哪个工具"改为"这组预测能不能用"

**这是本节最关键的一处调整，理由是一条逻辑约束，不是工程偏好。**

把工具 $k$ 在实例 $i$ 上的误差做方差分解：

$$e_{ik} = \mu + \alpha_i + \beta_k + \gamma_{ik} + \varepsilon_{ik}$$

其中：
- $e_{ik} = |\hat{y}_{ik} - y_i|$，工具 $k$ 对实例 $i$ 的预测与实验真值的偏差（单位随性质而定）；
- $\alpha_i$：**分子主效应**——这个分子对所有工具都难预测的程度；
- $\beta_k$：**工具主效应**——这个工具的全局精度；
- $\gamma_{ik}$：**交互项**——"这个工具在这类分子上特别偏"；
- $\varepsilon_{ik}$：含实验测量噪声的残差。

由此得到一个**不可绕的二难**：

| 若任务是 | 答案由哪项决定 | 换一套工具后 |
|---|---|---|
| 从 $K$ 个预测里选最准的（$\arg\min_k e_{ik}$） | **交互项 $\gamma_{ik}$** | **失效**（交互项绑定具体工具） |
| **判断"这组预测能不能拿去做决策"** | **分子主效应 $\alpha_i$** | **仍有效**（$\alpha_i$ 是分子的属性） |

❗ **若坚持第一种任务，则"能迁移"与"任务有信号"不能同时成立**：
假如困难真是分子属性（$\alpha_i$ 主导），则所有工具一起变差、$\arg\min_k$ 不动，对选工具**零信息量**；
假如选工具确实有信号，则信号只能来自 $\gamma_{ik}$，而它按定义绑定工具。
这是定义层的排斥，**不是实验能裁定的经验问题**。

⇒ 故本项目的可训练主任务定为第二种。**§3.1 四类任务仍全部保留作评测用**（它们能量出模型的失败模式），
但**进入训练环的只有第二种**。

**两个附带好处**：
1. 不再取 $\arg\min$——该统计量在各工具误差接近时完全由 $\varepsilon_{ik}$ 决定，对实验噪声极不稳健；
   而"整体水平高不高"是均值型量，稳健得多。
2. 与制药真实需求更贴——研发人员通常只有一个工具，他要问的不是"三个里哪个准"，
   而是"**这个数能不能拿去决策**"。

#### 3.4.2 Agent 相对经典方法的差异必须落在"主动取证"上

**必须先承认一件事**："给分子和一个预测值、判断可不可信"这个**静态**任务，
在药物化学里叫适用域判定（applicability domain），有四十年文献（相似度法、conformal prediction、
集成方差、高斯过程方差等）。**同一张误差表上训一个随机森林只需几分钟、零 GPU。**

⇒ **本项目不在静态判断上与之竞争。** 差异必须落在经典方法做不了的那一步：

| | 能做什么 | 做不了什么 |
|---|---|---|
| 随机森林 / conformal 等经典方法 | 对**给定的**特征输出一个可信度分数 | **不能决定去查什么**——它只能被动打分 |
| **Agent** | 判断"我现在信息不够"，并**选一个动作去补**（换方法重算 / 查相关性质 / 查文献 / 建议直接做实验） | 在静态判断上大概率输给专用模型 |

**所以要训的不是"判得准"，是"知道自己缺什么、并能用最少的代价去补"。**
这正是 §6 第 2 条（预算感知的主动复核）的内容，故将其上收为主线。

#### 3.4.3 真值只作验证器、不作模仿对象（这决定了是否蒸馏）

同一张真值表有两种用法，很容易混，但后果完全相反：

| 用法 | 具体做什么 | 能力上限受谁限制 |
|---|---|---|
| 当**标签**用（不可） | 离线算出最优路径，让模型模仿 | **就是那段穷举代码**，训了也超不过；且部署时可直接跑穷举，模型无必要性 |
| 当**验证器**用（本方案） | 模型自己搜索输出，真值只回答"对/错" | **不受验证器限制**——验证器只会判断、不会生成 |

两条支撑这个区分：
1. **部署时穷举不了**——穷举需要 $y_i$，而部署环境没有真值。故"直接跑 for 循环就行"对本方案不成立。
2. **文献依据**：已有用完美验证器（形式化定理证明器）做定向强化并报告大采样区间提升的工作
   （arXiv:2506.02355），它被归入"有正面证据抬上限"那一类。验证器不等于 teacher。

#### 3.4.4 训练闭环：五阶段 pipeline

| 阶段 | 做什么 | 成本 | 前置条件 |
|---|---|---|---|
| **阶段 0·造误差表** | 取有实测值的分子，用多种**原理不同**的本地估算方法各算一遍，得 $e_{ik}$ | 零机时 | 无 |
| **阶段 1·三条前置检验** | 见 3.4.6 | 零机时 | 阶段 0 |
| **阶段 2·评测** | §3.1 四类题 + 三条参照线，量出失败模式 | 少量机时 | 阶段 1 全过 |
| **阶段 3·训练** | 冷启动用**拒绝采样自举**（不用 teacher）；强化阶段做**抗锐化改造**，定向强化"模型很少产生但确实正确"的取证序列 | 要机时 | 阶段 2 有可用信号 |
| **阶段 4·泛化验证** | 换一套估算方法重测，**同时报两套方法的残差相关系数** | 中等 | 阶段 3 |

**阶段 3 为何要"抗锐化改造"而不是普通强化学习**：
文献上纯用"答对给奖励"的强化学习**抬不了上限**（arXiv:2504.13837 为 NeurIPS 2025 口头报告，
另有 arXiv:2507.14843、2510.15990 两篇独立工作同向证否）。唯一有正面证据的一类是修正优化偏差
（arXiv:2506.02355 诊断出常见强化算法只强化高概率轨迹，arXiv:2510.11686 用表征多样性做定向探索）。

**而本项目在这条路上有一个特殊优势**：数学题上无法知道哪条罕见推理是对的；
而有了误差表，**"模型极少产生但确实正确"的样本可被无歧义标定**。这是方法层面的可能贡献点，**待验**。

| 2 预算感知的主动复核 | **主线** | 即 3.4.2 的差异位；agent 对经典方法的唯一优势 |

#### 3.4.6 三条前置检验（顺序不可颠倒，均零成本或近零）

| 顺序 | 验什么 | 不通过意味着 |
|---|---|---|
| **1** | **方差分解**：$\alpha_i$ 占比够不够大；以及扰动 $y_i$ 后分类翻转率 | $\alpha_i$ 占比低 ⇒ 没有"分子难度区"可学，**主任务不成立**；翻转率高 ⇒ 标签在拟合实验噪声 |
| **2** | **裸答检索天花板 + 恒答基线**：模型能不能背出 $y_i$；以及"一律说不可信"能拿多少分 | 能背 ⇒ 测到的是记忆检索加一次减法；恒答得分高 ⇒ 必须同时报弃答率，否则分数无意义 |
| **3** | **经典方法擂台**：同一张表上训随机森林，比静态判断准确率 | 随机森林打平或更好 ⇒ 不得在静态判断上宣称贡献，差异只能落在 3.4.2 的主动取证上 |

**另有一条报告硬约束（文献给的）**：阶段 3 的任何提升必须同时报
**"不训练、只加大采样量"的基线**。已有工作（arXiv:2510.14901）发现纯采样即可匹配强化学习效果，
不带这条基线的提升数字**无法区分锐化与真实增益**。

且 400 个可复现跨体系冲突意味着 3.4.6 第 1 条检验（方差分解）**现在就能零机时跑**。

**仍适用的历史事实**（与上述不矛盾，分属两套设施）：
现行 benchmark 运行面仍是**单一真值表架构**——只有一个 `get_property` 工具、从预存文件查表返回，
无工具分歧、无置信度字段。⇒ **上述误差表尚未接进 agent 的工具面**，这是阶段 2 的工程前置。

**尚未解决的风险（不粉饰）**：
1. **四个模型中三个同属 DeepPurpose 体系**，误差可能高度相关。普查已区分“跨体系 / 体系内”冲突，
   但阶段 4 的“换工具仍有效”仍**必须与分数同时报出残差相关系数**，否则不可证伪。
2. **BBB 是二分类标签**（透/不透），不是连续值 ⇒ 3.4.1 的 $e_{ik}$ 在本数据上退化为对/错，
   方差分解需改用适合二值响应的形式（或改用预测概率而非硬标签）。**这一步尚未做。**
3. **“困难区”可能是公共训练语料的稀疏区**，而非分子本身的物理难度；
   四个模型若共享 MoleculeNet 谱系训练集，该风险升高。
4. **有实验值的分子不是随机样本**（是人类认为值得测的），存在选择偏差。
5. **训练栈尚未就位**：本仓库无 `trl/peft/vllm` 依赖、无 GRPO/PPO/DPO 实现代码。
6. **730 行的量级对训练偏小**。评测够用，强化阶段的 rollout 需量远高于此，需先确认普查能否扩量。

❗ **本节不宣称任何效果数字。** 阶段 1 三条检验全部通过前，“能抬高能力上限”只是待验假设。

## 4. 期望结论与分析

以下为待验证假设，而非预设结论：

1.  更强的通用 Agent 未必更谨慎，可能更稳定地盲从专业工具。
    
2.  单一置信度不足以判断预测是否正确；工具分歧、适用域和跨性质约束联合使用更有效。
    
3.  实例级工具选择有望超过最佳固定工具，但多数投票在工具误差高度相关时可能失效。
    
4.  强制多指标评价可提高恢复率，但验证越多不一定越好，存在明显的准确率—成本权衡。
    
5.  确定性校准门控、Agent 推理与二者组合可能分别适用于不同风险和预算场景。
    
6.  Agent 即使得到正确最终答案，也可能经历错误诊断或幸运恢复，因此必须同时评价过程和结果。
    

## 5. 对制药领域的贡献

本项目不是再做一个新的 docking、ADMET 或蛋白结构模型，而是建立这些工具之上的**可靠性评测层**：

*   提供首套系统化的制药科学预测冲突诊断与恢复任务；
    
*   量化不同 Agent 在真实模型误差下的可信工具使用能力；
    
*   为小分子和蛋白药提供可复用的自然冲突数据、实验真值和评测协议；
    
*   帮助研发团队判断何时可以相信计算结果、何时必须复核、应调用什么工具；
    
*   推动制药 Agent 从“会调用工具”走向“会质疑、会验证、会恢复科学决策”。
    

## 6. 未来可继续推进的方向

> ⚠️ **2026-09-02 更新**：下列八条中的**第 1、2、5、6 条已上收为主线**（第 3 条降为判分侧配套），
> 见 §3.4。本节原文保留不动，仅作方向清单与出处。第 4、7、8 条仍为未来方向，
> 其中第 4 条与本项目「单 agent」硬边界冲突、第 8 条与 08-28「收敛到制药」裁定冲突，**本轮不启动**。

1.  **学习实例级工具可靠性**：为每个工具建立随分子 scaffold、蛋白家族、任务 endpoint 和适用域变化的正确率模型，而不是使用固定工具排名；重点优化高置信度错误和错误共识的识别。^\[1–3\]^
    
2.  **预算感知的主动复核**：将工具调用视为有成本的信息获取问题，让 Agent 学会选择预期信息增益最高的同功能或正交工具，并研究准确率、时延和算力之间的 Pareto 前沿。
    
3.  **跨性质约束推理**：建立制药知识图谱或可执行约束层，把结构、亲和力、物化性质、ADMET、稳定性和成药性联系起来，帮助 Agent 区分真实矛盾、单位/定义差异和合理的条件依赖。
    
4.  **规划—执行—审计分工**：探索 planner、tool executor 和 scientific auditor 的多角色架构；审计角色专门检查证据来源、参数一致性、未验证假设和替代解释，降低过早停止和工具盲从。^\[4–5\]^
    
5.  **面向恢复过程的训练**：利用自然冲突轨迹和受控反事实样本进行监督微调、偏好优化或强化学习；奖励应同时覆盖正确诊断、合理复核、成本控制、校准和最终决策，而不只奖励最终答案。^\[7–8\]^
    
6.  **动态工具生态与漂移监控**：允许工具新增、升级或版本变化，评测 Agent 能否重新校准可靠性并发现性能漂移，避免把历史经验永久固化为错误先验。
    
7.  **人机协同与湿实验闭环**：在高风险或不可判定情形下允许 Agent 向专家升级，进一步开展隐藏靶点、前瞻性盲测或小规模湿实验验证，比较纯 Agent、Agent+规则和 Agent+专家三种模式。
    
8.  **跨模态与跨研发阶段扩展**：从小分子和蛋白/抗体进一步扩展到 RNA、PROTAC、细胞与组学工具，并研究上游冲突如何传播到候选排序、安全性和 go/no-go 决策。
