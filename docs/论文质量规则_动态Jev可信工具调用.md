# 论文质量规则：动态 Jev 与可信工具调用

日期：2026-09-24

状态：作者侧审稿规则。它不是 AAMAS 官方评分表，而是按照 AAMAS 2027 的公开投稿要求和本项目已经确定的故事线制定的内部准入标准。

## 一、这篇论文究竟要证明什么

论文的中心问题是：**科学工具正常返回但结果可能错误时，Agent 能否根据当前证据选择工具、判断可信度、主动验证或复核，并在证据不足时拒答？**

对应的系统由三层组成：

1. 动态工具适应模块维护工具版本、候选动作、已见输出、反馈队列和预算，并估计工具可靠性与追加验证价值。
2. 动态 Jev 是结构化在线决策核心，用预训练判别表示帮助冷启动，在题内看到新证据后更新决策状态，在题间收到真实或终止反馈后更新轻量决策头、adapter或后验。它统一处理工具选择、证据风险、验证/复核和终止动作。
3. 主 Agent 读取动态 Jev 的结构化状态，学习请求、读取、检查、复核、作答和拒答，最终以完整调用轨迹承担系统结果。

工具选择是第一个可测动作，不是论文全部目标。论文至少要明确自己主张的是哪一层，不能用第一层的 provider 选择命中率替代第三层的 Agent 可靠性提升。

## 二、真正的研究难点

这篇论文最难的部分不是把 Laya 接上一个在线分类头，而是让“可信调用”在部分反馈、延迟真值和多层策略下可识别、可学习、可归因：

1. **反馈是选择性的和延迟的。** 只看见被调用工具的结果，未调用工具的反事实结果不可见；真值还可能在 episode 结束后才到达。在线更新、离策略评价和复核价值都必须处理这个缺口。
2. **工具返回的语义要拆开。** 正常返回、格式有效、化学性质正确和最终决策有用是不同事件。把它们合成一个未经说明的 reward，会让方法无法解释。
3. **复核价值是条件效应。** 第二个工具的价值取决于第一个工具返回了什么、Agent 当前准备做什么以及两个工具错误是否相关。单独比较工具准确率不能代替复核价值。
4. **动态更新会改变自己的数据分布。** 先验可能锁死探索，工具版本变化会使旧后验失效，真值缺失会诱发错误更新。题内状态更新和题间参数更新必须分别定义。
5. **最终错误需要跨三层归因。** 错误可能来自 provider、Jev 的风险判断、Agent 没有复核、Agent 误读结果或合理拒答阈值。没有结构化轨迹和交叉消融，就无法知道收益或失败来自哪里。

审稿人会用以下反事实问题压测方法：打乱工具名和版本描述后，冷启动收益还在吗？首个工具错而第二个工具对时，Agent 是否会复核？所有工具共同错时，Agent 是否能拒答？新增 provider 能否获得探索机会？没有真值时，参数是否保持不变？如果论文回答不了这些问题，它描述的是一个路由器，而不是可信工具调用学习。

## 三、AAMAS 审稿人会先看的门槛

AAMAS 2027 公开指南把技术贡献的原创性、意义、正确性、可复现性、清晰度、与会议的相关性、呈现质量和对现有工作的理解列为评估基础。[Reviewer Guidelines](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/reviewer-guidelines/)还列出超页数、超出范围、技术内容严重不足、格式或匿名违规等 desk reject 情形。[Submission Instructions](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/instructions/)要求主轨正文最多 8 页，核心评价信息必须出现在正文，补充材料不能承担论文的核心论证。

因此审稿人的第一轮判断通常是：

- 这是一个 agent learning / adaptation 问题，和 AAMAS 读者有关吗？
- 贡献是一条清楚的科学命题，还是三个模块的工程拼接？
- 动态 Jev 是否真的随反馈改变，还是静态 Laya 加一个离线路由器？
- 工具反馈、真值到达和 Agent 可见信息是否满足因果顺序？
- 结果能否区分 Jev、工具适应模块和主 Agent 各自的作用？
- 是否正面比较了已有的预训练路由、在线 Bandit、序列验证和拒答方法？
- 医药结果、模型资格、真值独立性和训练重叠是否可信？

以当前方案看，问题重要且有 AAMAS 相关性；方法方向有潜力，但在没有动态更新证据、合法反馈合同和 Agent 端到端结果以前，审稿结论会是 **Major Revision，严重时 Reject**。

## 四、审稿重点与必须回答的问题

### 1. 中心命题是否只有一个

正文开头必须用一句话写出：状态是什么、动态更新是什么、比较对象是谁、改善的结果是什么。例如：

> 在带隐藏真值和延迟反馈的科学工具调用任务中，动态 Jev 能否利用预训练表示与已观察反馈，改进 Agent 对工具证据的选择、验证和拒答决策，同时控制调用预算？

审稿人会检查每个实验是否回答这句话。若论文同时声称新模型、新 Bandit、新数据集、新 Agent 训练和跨领域泛化，却没有一个主命题，通常会被认为贡献分散。

### 2. “动态 Jev”是否是一个真正的方法

论文必须给出完整状态、动作、反馈和更新算子，而不是只写“实时学习”：

```text
s_t = (task, function, candidate tools, observed outputs,
       history, budget, posterior_t)
u_t ∈ {call(a), inspect, verify, answer, abstain}
F_{θ_t}(s_t) → {choice, risk, verification gain, final action}
```

至少要回答：

- 题内看到工具输出后，哪些状态立即改变？
- 题间真值到达后，哪些参数或后验改变？
- 更新一次需要多少计算和存储？是否需要重训整个 Jev？
- 新工具版本加入时如何初始化，错误先验如何恢复？
- Choice 概率、工具正确率、证据风险和探索不确定性分别是什么？
- Agent 实际动作和 Jev 建议不一致时，系统如何记录和学习？

如果只有“冻结 Laya 编码器＋在线线性头＋UCB/Thompson sampling”，审稿人会把它视为已有路线的组合。论文需要给出明确的任务条件、反馈限制、效率优势或可复现的科学发现，并与最接近方法在相同信息权限下比较。

### 3. 反馈合同是否合法

工具输出可以即时看到，工具是否正确通常要等任务终止和外部真值到达后才知道。论文必须把下面几类事件分开：

- 工具返回或失败；
- Agent 是否请求验证；
- 外部真值何时到达；
- 哪个动作实际被观察并得到标签；
- 哪些动作保持未知并进入 pending。

未调用工具不能自动标成负例。只调用了 A，不能据此把 B、C 的正确性设为 0。复核收益不能由单调用准确率直接推导，需要带正选择概率的随机成对探测、逐次日志和选择倾向记录。自适应策略的离策略比较要报告 IPS/DR 或等价方法的支持范围和方差。

### 4. Agent 是否真的学会了可靠调用

动态 Jev 输出建议，主 Agent 执行动作。论文必须记录：

- Jev 建议了什么；
- Agent 实际做了什么；
- Agent 是否采纳或覆盖建议；
- 最终工具输出、验证结果、作答/拒答和真值。

只展示外挂模块的选择准确率，不能证明 Agent 学会了复核或拒答。至少需要固定 Agent 比较不同模块、固定模块比较不同 Agent 策略，并报告三层交互。若主 Agent 没有训练，论文应把结果称为“系统增强”或“决策辅助”，不能声称 Agent 已学会该能力。

### 5. 最近邻和原创性是否站得住

审稿人会主动寻找以下已有路线：预训练路由先验加在线反馈、NeuralLinear/Thompson Bandit、见到首个结果后选择第二个工具、价值信息和序列分类器、风险覆盖与拒答策略。论文必须逐项说明：

- 对方观察到什么反馈；
- 对方更新哪些参数；
- 对方是否处理延迟真值、相关错误和新工具；
- 我们增加了什么可检验机制；
- 同样的预算、标签、候选工具和输入下，结果是否仍有增益。

“第一次把 Jev 用在医药工具上”“把 Bandit 接到 Agent 上”“实现实时学习”单独都不足以构成方法原创性。若方法创新不成立，论文可以转向一个有识别度的资源、基准、负结果或实证贡献，但必须如实收窄主张。

### 6. 医药证据是否足够可信

审稿人会查：

- 每个具体模型/版本的权重、训练数据和发布时间是否可核验；
- 外部真值是否独立于模型训练和调参；
- 训练、开发、在线适应和测试分子如何划分；
- 同一家族多个版本是否被错误地算成独立来源；
- 工具失败、缺失真值、标签冲突和版本漂移如何处理；
- 结果是否来自真实可复核输入，而不是事后挑出的有利子集。

“模型之间有分歧”只能证明有不一致，不能直接证明谁错。事后逐题挑出最优工具只能说明上界，不能当作可学习效果。

### 7. 实验是否能把三层贡献拆开

最少需要三组结果：

1. **动态 Jev 层**：冷启动早期错误、在线累计错误、后期错误、校准、反馈样本效率、推理和更新开销。
2. **动态模块层**：工具选择、证据风险、验证/复核命中、拒答风险覆盖、调用次数和延迟。
3. **Agent 层**：最终错误率、拒答质量、风险覆盖、复核收益、调用预算、轨迹质量和校准。

推荐使用固定 Agent × 动态模块、固定模块 × Agent 策略的交叉实验。首轮“最多两次调用”可以作为 pilot 协议，不能把它写成整个方法的边界。

强制对照至少包括：固定工具、静态 Laya/Jev、无预训练在线头、标准 contextual Bandit、直接性质预测器、随机/规则验证、已有预训练路由＋在线反馈方法，以及相同信息权限下的序列验证方法。报告累计曲线和后期曲线，不能用期末模型回填早期决策。

### 8. 指标是否体现可靠性

单独的 provider accuracy 不够。至少报告：

- 最终错误率和有效返回错误率；
- risk-coverage 或 abstention 曲线；
- 验证带来的条件减错收益；
- 平均和分位调用次数；
- 反馈数量、标签延迟和更新开销；
- 概率校准与不确定性质量；
- 不同工具家族、难度和共同错误区域的分层结果。

调用惩罚、拒答惩罚和错误损失必须预先说明，不能为了让某个方法获胜临时调节。若现实中没有价格或时间数据，就报告实际调用数与延迟，不虚构经济结论。

## 五、好论文的硬规则

下面每条都需要在论文正文或可复核材料中有证据。

| 编号 | 规则 | 通过证据 |
|---|---|---|
| G1 | 有一个中心命题，三层系统围绕它服务 | 引言、方法、实验中的主张逐一对应 |
| G2 | 动态 Jev 的状态、动作、更新和复杂度可复现 | 算法、伪代码、更新事件和时间/空间开销 |
| G3 | 明确区分题内适应和题间反馈学习 | 逐次日志、参数版本和反馈时钟 |
| G4 | 反馈权限合法，没有真值泄露或未调用负标签 | 信息可见性表、pending 规则、审计日志 |
| G5 | Jev 建议与 Agent 实际动作可归因 | recommendation/action/override 三列日志和交叉实验 |
| G6 | 最近邻被同信息、同预算、同反馈合同复现或公平适配 | 基线实现卡、版本、输入和选择概率记录 |
| G7 | 冷启动、在线适应和端到端 Agent 各有独立结果 | 三层主表和机制消融 |
| G8 | 结果包含失败条件、负结果和敏感性分析 | 预登记反证条件、不同先验/探索/延迟/工具池结果 |
| G9 | 医药模型资格、真值独立性和分子划分可核验 | 权重、数据来源、快照哈希、污染审计 |
| G10 | 评价同时覆盖错误、拒答、验证收益、覆盖和调用成本 | 风险覆盖曲线、调用预算和置信区间 |
| G11 | 结论范围不超过实验范围 | 明确 BBB、工具池、真值和版本限制；不把单性质称跨领域 |
| G12 | 论文可在 8 页正文内自洽理解 | 核心定义、主算法、主实验和关键限制都在正文 |
| G13 | 所有实验可复现且原始轨迹可追溯 | 配置、随机种子、环境、原始逐题日志和结果脚本 |
| G14 | 贡献定位诚实 | 方法未超过近邻时改称实证/基准/资源，不强行命名新算法 |

如果论文声称“主 Agent 学会了可信工具调用”，G5 还必须满足两个条件：Agent 在独立 held-out 任务上出现可重复的行为变化，并且这种变化改善了验证、复核或拒答结果。只有外挂建议被执行而 Agent 参数和策略没有改变时，主张应写成“系统能力提升”或“决策辅助”，不能写成 Agent 学会。

## 六、看起来像论文、实际上不够好的写法

| 反模式 | 审稿人会怎样理解 |
|---|---|
| Laya 输出一个 Choice，再接一个 Bandit，就称动态 Jev | 静态路由器和标准在线读出，方法增量不清楚 |
| 只证明选到了更准的 provider | 没有证明 Agent 会验证、复核或拒答 |
| 把工具分歧当作错误标签 | 真值识别非法，结论不可解释 |
| 把未调用工具当负例 | 反馈机制被错误改成全信息监督 |
| 用缓存逐题揭示真值，声称现实系统实时学习 | 只证明 prequential 回放，未证明真实延迟反馈适应 |
| 只报告期末准确率 | 看不出在线更新是否真的改善了后续决策 |
| 不记录行为概率和成对探测 | 复核价值与离策略比较不可识别 |
| 只和随机策略比较 | 没有回答是否超过最强固定、监督和已有在线路由方法 |
| 三层模块一起变化，所有增益都算给动态 Jev | 无法归因，系统论文的科学结论不成立 |
| 只在一个容易的 BBB 子集上取正结果 | 选择偏差、污染或题目难度可能解释全部收益 |
| 把 provider 版本、家族和独立来源混用 | 动作池和样本量被夸大 |
| 只写“实时、高效、可信”，不给更新耗时、标签延迟和风险覆盖 | 口号无法审查 |
| 把三篇半成品论文装进八页正文 | 贡献边界模糊，任何一层都不够深 |

## 七、审稿决定规则

### 主轨论文的通过条件

主轨版本需要同时满足：

1. 有清楚且与 AAMAS agent/adaptation 相关的中心命题；
2. 动态 Jev 有可复现的在线更新机制，且相对强近邻有明确增量或重要新实证；
3. 反馈合同、数据资格和信息隔离经得起审计；
4. 至少一组结果证明动态适应模块改善了可靠工具调用；
5. 端到端结果能说明主 Agent 的复核、验证或拒答能力是否提升；
6. 主要结论在独立分子或独立工具/版本上有确认，或清楚说明它是有限范围贡献；
7. 所有关键证据、定义和主表在正文中可理解。

### Findings 级别的合理定位

AAMAS 2027 的 Findings 与主轨使用同一投稿流程和格式。官方说明允许一篇论文因为范围、一般性、验证广度或预期影响较窄而进入 Findings，只要它科学上可靠、相关、贡献可识别且证据足以支撑主张。[Findings 说明](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/findings/)

因此，只有动态 Jev 的一个可靠切片、一个经过严谨验证的负结果、一个资源/基准贡献，也可以成为合格论文；前提是贡献边界收窄，不能用不完整的端到端结果包装成完整系统论文。

### 直接拒稿信号

出现以下任一项，论文的核心结论通常不成立：

- 动态 Jev 没有真实反馈后的参数或后验更新；
- 真值泄露、未调用负标签或不合法的离策略比较；
- 没有强近邻，或只与随机/多数类比较；
- 只报告 provider 选择，不报告 Agent 可靠调用；
- 医药模型资格、真值独立性或分子划分无法核验；
- 论文把静态回放、人工合同测试或事后最优上界当作在线效果；
- 三层组件无法归因，核心结果无法复现；
- 结论明显超出单一性质、单一工具池或当前反馈条件。

### 内部评分与硬闸门

下面是作者侧内部评分，不冒充 AAMAS 官方分数。每项 0–4 分：

| 维度 | 权重 | 4分标准 |
|---|---:|---|
| 问题与 Agent 意义 | 15% | 可信证据问题清晰，主Agent行为是中心结果 |
| 动态 Jev 原创性与最近邻定位 | 20% | 有明确新设定或强实证增量，比较公平 |
| 反馈与更新的正确性 | 20% | 延迟、选择性、反事实和更新时钟完整可审 |
| 在线与因果实验 | 25% | 有 prequential、独立 holdout、随机探测和统计不确定性 |
| 端到端可靠性与实际成本 | 15% | 选择、验证、复核、拒答和调用代价都改善或有清楚边界 |
| 复现、写作与范围 | 5% | 正文自洽，日志、版本、数据和限制可复核 |

五个硬闸门必须全部通过：真实在线更新、合法反馈权限、Agent 端点指标、强近邻基线、无信息泄漏。任一闸门失败，当前版本暂不投稿；总分达到 3.2/4 且无闸门失败，才具备主轨投稿条件；2.5–3.19 应改成更窄的实证/系统或 Findings 定位；低于 2.5 应停止当前叙事并重新选题。

## 八、投稿前作者自检卡

提交前必须能在一页纸回答：

1. 我们唯一的中心命题是什么？

3. 哪个反馈会更新哪个参数？标签延迟多久？
4. 为什么未调用工具没有被当成负例？
5. Agent 是否真的做出了复核/拒答动作？如何证明？
6. 与 PILOT、BayesianRouter、NeuralLinear、序列验证和固定策略相比，新增量在哪里？
7. 如果结果不支持冷启动、在线收益或 Agent 增益，论文会删掉哪条主张？
8. 读者只看 8 页正文，能否复现核心方法和判断主结果是否可信？
