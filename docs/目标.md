# 目标：学会选择医药工具，并从结果反馈实时更新

## 当前目标（2026-09-26）

给定一个分子性质请求和候选工具，JEV 类判别模型直接选择一个具体 provider。工具调用终止后，独立参考标签给出这次选择的 0/1 对错反馈，模型更新后服务后续请求。要回答的是：这种在线学习能否在有限反馈和计算下改善未来选择，相比现代近邻到底多解决了什么。

# 目标

这份文档回答一个问题：我们到底在做什么，做到什么算成。

怎么干写在 [计划_全工具远程跑批与结果库.md](计划_全工具远程跑批与结果库.md)，为什么这么设计、有哪些前人工作和我们的差别写在 [Proposal.md](Proposal.md)。本文件不复制它们的内容，只把目标钉住，并给出每层终点的验收边界。专用词的定义见 [../CONTEXT.md](../CONTEXT.md)。

## 一句话

**造一套基准，用来评测和纠正 agent 在使用科学工具时的一个具体失败模式：工具正常返回了结果，但结果不可靠，而 agent 察觉不到，还照着它继续往下做决策。**

配套的训练目标是让 agent 学会**判断「这组预测能不能拿去做决策」**，并据此选择性作答（作答/弃答/上报）。「在多个工具里挑出更可靠的那个 / 纠正选工具偏心」保留作**评测**目标，不进入训练环——理由见 [ADR-0006](adr/0006-training-goal-decision-usability.md)（维持 [ADR-0028](inherited/0028-calibration管线v1四方评审裁决.md) D1）。

**最终产出不是数据集，是一套 benchmark 加配套训练。** 第一层（离线结果库）与第二层（工具冲突数据集）只是数据地基；第三层——能评测并训练 agent「识别工具正常返回但结果不可靠、并据此做出可信赖决策」的基准——才是终点。判这套基准成不成，看的是 agent 学到的判断力能不能**跨工具、跨领域迁移**（由分子主效应 α_i 驱动、不绑定具体工具），而不是数据集本身有多大。下文任何一步若开始为「把数据集做大」而牺牲「判断力可迁移」，即为跑偏，以本段为准纠回。

> **2026-09-13 裁定。** 本段训练口径原与一份已生效的决议（ADR-0028 D1）冲突，登记在「一处待裁的目标冲突」一节。owner 授权「按照这个目标自己去裁决」后，已由 [ADR-0006](adr/0006-training-goal-decision-usability.md) 裁定：可训练主任务为「判断这组预测能不能用」，选工具偏心降为评测目标。该冲突登记段保留作历史台账，下文据此更新。冲突只落在训练闭环，不落在本轮交付的离线结果库。GPU 闸门保持关闭，仍须先过 ADR-0028 D2 五条零机时检验。

> **2026-09-15 题集构造要求已落。** 第三层「题目怎么出才算达标」的要求由 [ADR-0007](adr/0007-benchmark-task-requirements.md) 钉死（owner 给出两个量化口径：题量下限 5000、易分子占比上限 30%）：R1 现象 / R2 取舍 / R3 量级 / R4 可训练 / R5 防伪五组不变量，每条带「为什么必须 + 验收判据」。该 ADR 落的是**要求不是现状**——现状不满足某条时以要求为准去达成。选族判据从「覆盖率」换成「现象密度 × 真值可接 × 源干净」（R2.1）；裸答天花板被证明是难度配比的函数，故易分子占比 ≤30%（R5.2）是显式设计要求，连带化解 USER_TODO U-8 的「任务作废」疑虑。

## 要解决的问题

问题的根子不在制药，在 agent 本身。分三层说，A 是根子，B 是它在行为上留下的痕迹，C 是痕迹里可计数的部分。

**A 本质问题：训练后 agent 的工具偏好分布不等于任务最优分布。** agent 对训练时见过的工具过度自信，对功能等价的新工具系统性回避。这个现象叫工具过拟合。一个工具的价值本应取决于它对当前任务有多大帮助，与 agent 训练时是否见过它无关；两者的落差就是损失。机制上我们假设训练时的工具面与部署时的工具面往往是同一套，模型因此把训练环境里那几个工具当成了工具使用的默认形态。这条只是假设，本项目不以它成立为前提。

**B 外显行为：在 K 个功能重合的工具之间，agent 偏向更熟悉的那个。** A 不可直接观察，B 是它在单次决策上的投影。

**C 可计数信号：偏心选出的工具一旦判错，就留下一个能自动算出来的信号。** 判错的依据是工具输出与实验测定值不符，由记录表按规则算出，不需要人来判。

三层连起来就是技术路线：A 是根本问题但没法直接优化，只能顺着外显往下走一层——把 C 写成损失项，降低这个损失来纠正 B，从而缓解 A。

**范围边界。** 工具超时、报错、返回格式不合法属于另一类问题，不在本项目范围内。本项目只关心工具**正常工作但结果不可靠**这一种情况。

## 终点分三层

三层是递进的，每层有自己的验收，不能混着做。本轮只交第一层。

**第一层（本轮交付）：离线结果库建成。** 清单内全部工具在远程服务器独立部署并验证，预测结果、失败记录、版本信息完整留存，每工具交一份 CSV。验收口径：每个工具要么有双轮全量结果，要么有可核对的失败回执，不存在无归属的工具；每份表的分子集合与冻结输入一致；主表每一个空格在失败清单里有且仅有一条对应记录。

**第二层（紧接下一阶段）：工具冲突数据集建成。** 在第一层之上确认哪些工具测的是同一种性质，再挑出答案不一致的分子。**这一层只报「工具互相不一致」，不判谁对谁错。** 判对错要接实验真值，那是 Step 2 真值清洗的活，不混进本层。

**第三层（单独设计，不混入本轮）：可评测 agent 的 benchmark。** 题目、agent 可用工具集、标准答案、评分方法另立设计。第一二层是它的数据地基，不是它本身。

为什么必须分层：第三层一旦提前设计，就会反过来决定第一层收集什么数据，结果是数据集变成题目的附庸。现在先把工具的真实输出原样存住，第三层才有选择余地。

## 为什么选制药域

不是因为它重要，是因为它可测。三条理由，每条都有出处。

**一，工具之间的冲突是天然的，不是人为注入的。** 化学信息学的工具生态极度碎片化，同一功能有一堆互不兼容的实现，差异大到有文献专门做过系统比较。最典型的是 logP：Mannhold 等在九万余个化合物上逐一比较过各家方法；Plante 与 Werner 在同一个外部测试集上报出的均方根误差从 JPlogP 的 1.04 到 MLogP 的 1.95 个 log 单位；SAMPL6 盲测 11 个分子 91 份提交，均方根误差从 0.74 排到 4.00，其中一个分子上不同方法给出的 logP 相差 4.6 个 log 单位。这个量级直接决定一个分子被判成药性好还是差。现有多工具冲突基准的冲突大多是人工注入的，与真实工具的天然结果分布不符——这是本项目的第一个空白。

**二，有实验测定值作锚，能算对错。** 制药性质有大量公开实验数据集，工具输出与实验值不符可以按规则判，不需要人裁。多数 agent 基准只有「任务完成度」或「标准答案精确匹配」，拿不到工具层面的对错信号，也就做不出 C。

**三，工具残差的形态本身就构成难度分层。** 工具在自己训练分布内准、出了适用域就漂，这让「这道题难不难」有了不依赖 agent 自报的客观刻画，可以拿来锚定弃答代价。

## 六步路线

详细设计在 Proposal §3，这里只列每步要产出什么、判什么算成。第 5 步的训练口径原与已生效的 ADR-0028 冲突，**已于 2026-09-13 由 [ADR-0006](adr/0006-training-goal-decision-usability.md) 裁定**：可训练主任务为「判断这组预测能不能用」，选工具偏心降为评测目标。下表第 5 步的旧表述（「矫正工具偏好过拟合」）以 ADR-0006 为准。冲突不影响第 1、2 步，也就是本轮要交的第一层与紧接的第二层。

| 步 | 名称 | 关键输出 | 算成的标志 |
| --- | --- | --- | --- |
| 1 | 多工具基准数据集构建 | 每个分子逐行记下结构、各工具预测值与判定、实验测定值、两个不同来源是否给出相反结论 | 结果库与冲突集建成，即第一层与第二层 |
| 2 | 真值清洗与分子难度标注 | 清洗后的带标注分子库 | 同一分子在源文件里有相反标签的，逐行裁决取哪条或整行剔除，裁决留依据 |
| 3 | 训练与评测任务集构造 | 训练任务集、测试任务集、评价指标体系 | 每个（分子，工具子集）构成一道独立任务，题面只给分子结构和工具目录，预测值要 agent 自己调用才拿得到 |
| 4 | Prompt 基线消融 | Prompt 基线模型、纯提示的效果边界 | 分离出「思考格式对齐能解决的」与「必须靠轨迹损失训练矫正的」 |
| 5 | 双置信度轨迹训练 | 训练完成的校正 agent | 可训练主任务为「判断这组预测能不能用」+ 选择性作答（[ADR-0006](adr/0006-training-goal-decision-usability.md) 裁定，维持 ADR-0028 D1）；选工具偏心只作评测目标。SFT 灌输流程、RL 校准置信度；SFT 阶段工具选择随机化且不标注任何工具优劣。**GPU 闸门保持关闭，须先过 ADR-0028 D2 五条零机时检验** |
| 6 | 泛化与有效性验证 | 工具泛化结论、跨领域迁移结论、捷径行为验证 | 见下 |

**判分口径。** 答错罚一分，弃答付代价 c，总损失 `L = I(答错) + c·I(弃答)`。c 有理论有效区间：低于下界，最优策略退化为全部弃答；高于上界，永不弃答。正式实验在有效区间内取低、中、高三档对比。三条规则式基线作参照：从不弃答、多数投票、Oracle-yield（只在标记为「该弃答」的样本上弃答，理论上界）。四个评价指标：多余弃答率、工具调用偏好度、检验阶段触发率、置信度校准误差。

**Step 6 的三个子实验各自要排除一种「假成功」。** 工具泛化测试排除「能力绑定在训练见过的那几个工具上」：测试阶段放进从未见过的新工具，指标维持稳定才算过。跨领域零样本测试排除「只学会了制药这一套表面形式」：换完全不同领域的同功能多工具场景，行为模式保留才算过。捷径行为诊断排除最危险的一种作弊——agent 只在看到工具输出分歧时才进检验：筛两组样本，控制输出离散程度一致，一组是简单正确样本、一组是工具全错的伪共识样本，伪共识组触发率显著更高，才说明触发开关锚定的是任务难度而不是工具分歧。

## 分工与停机

**一切工具安装与预测运行归远程工程师。** 包括本地此前已跑通的工具也要在远程独立部署验证，本地跑出的结果只作对照用的历史输入，不替代远程部署——这样整套结果在一台机器上就能完整复现。

**本地只做四类事：文档与清单、判据规格、分析脚本、结果整形。** 四类都不调用任何预测工具，不产生新的预测值。牵涉运行环境验证的代码改动也归远程，因为判据改得对不对必须拿真实批次验证，而真实批次只在远程机器上。

**四条停机条件，撞上就停下交 owner，不自行推进：** 任何工具需要改动官方程序才能出数；任何配对核不到官方定义但从名称看似应当配对；任何工具需要追加安装预算；任何已定判据需要再次修改。

## 本轮明确不做的事

写下来是为了防止范围悄悄扩大。

1. **不做多角色分工。** 让一个角色专门审计证据来源与未验证假设，与本项目「单个 agent」的硬边界冲突，本轮不启动。
2. **不接人、不做湿实验。** 高风险或确实判不了的情形允许 agent 向专家求助，会破坏可重复性；湿实验目前没有条件。本轮只保留弃答作为一个输出选项。
3. **不扩到其他模态与研发阶段。** 从小分子和蛋白抗体扩到核酸、蛋白降解剂、细胞与组学工具，与「本轮收敛到制药」的裁定冲突，本轮不启动。
4. **跨性质约束推理只作判分侧配套。** 把结构、亲和力、物化性质、代谢与毒性、稳定性、成药性连成一个可执行约束层，用来校验 agent 给出的理由是否成立，不作为提示喂给 agent——否则测的就变成指令遵循了。

## 期望验证的结论

这五条是 Proposal §4 的假设，也是 Step 4 到 6 要给出证据的东西。写在这里是为了让后面的实验知道自己要回答什么。

1. 通用能力更强的 agent 不一定更谨慎。它可能更稳定地盲从专业工具，因为工具在它看来比自己专业。
2. 只看一个工具自报的置信度不足以判断它这次对不对。把工具之间的分歧、分子是否落在工具擅长的范围内、以及其他相关性质放在一起看，应该更有效。
3. 工具难度对整体结果影响很大。一个工具若太简单或已被训进模型参数里，进入校验的比率会下降。
4. 复核不是越多越好。多调一个工具能提升准确率，但存在一个拐点，过了拐点只增加成本。
5. 规则型门控、agent 自己推理、以及两者结合，可能各自适合不同的风险与预算场景，不存在一个通用最优。
