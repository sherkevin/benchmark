## 当前投稿切片

长期故事仍然是：让 agent 更聪明地选择、验证、互补或拒答，从而提高科学任务的能力上限。当前论文只验证其中最小且可审计的一段：在 TDC BBB 的四个 fresh providers 上，调用前选择一个 provider；只把已选结果的 correctness 按 $D\in\{0,1,4\}$ 释放；用 provider-local residual 改变后续选择；在预登记 evaluator-side correctness drift 下检验恢复。

当前稿不声称已经完成 post-call verifier/refusal、VOI、hERG/AMES、自然 lifecycle drift 或完整 33-provider model-fresh。它们仍是后续扩展，不应在摘要、贡献列表或验收表中被读成已完成实验。

当前可写的证据是：自然 fresh menu 上 MIRA-Relay 与 Frozen 均为 89.81%，controlled drift stress 上 MIRA-Relay 为 87.56% 对 Frozen 73.38%。前者是稳定性/null 结果，后者是受控机制结果；不能合并成 generic online improvement。

## 一句话判断

Agent 的能力上限不只由模型本身决定，也由它能不能把工具用在正确的地方决定。我们的任务是让 agent 学会把多个重叠工具当成可理解、可验证、可组合的证据源：调用前根据工具过去的工作范围选择最合适的工具，调用后解释结果并决定相互验证、互补调用、拒答或继续获取证据，再用延迟到达的真实 outcome 反馈更新后续决策。

## 问题从哪里来

现有医药结果库里，同一个分子和性质常由多个具体 provider 给出不同结果。格式正常不能说明结果可靠；而且不同 provider 的错误可能重复，也可能互补。真正的困难有四个：

1. 选择发生在结果返回前，未选 provider 的当前输出不能偷看；
2. 对错反馈只在调用结束并可能延迟后到达，更新不能假设同步标签；
3. 选对工具和发现当前结果不可靠是两个时点，不能用调用后的 confidence 冒充调用前信息。
4. 工具不是只有一个全局准确率。每个工具都有更适合和更不适合的输入区域；拿到一个结果后，下一步调用应该根据当前证据判断是验证同一结论、寻找互补信息，还是停止。

因此论文的总问题是“agent 如何通过更聪明的工具调用提高可靠任务能力”，医药 provider 路由是一个有独立真值、可复核输出、明确调用成本的具体实验切口。

## 论文故事链

1. **能力上限问题**：agent 遇到科学问题时，答案质量受它能否找到、判断和组合外部工具证据限制。
2. **真实失败**：多个同类型 provider 对同一分子和端点给出分歧；工具即使正常返回，也可能在当前分子上超出自己的工作范围。
3. **现有方法缺口**：固定赢家只记平均表现；一次性 selector 不会解释当前结果；独立验证假设又无法处理共享错误和互补证据。
4. **核心 insight**：一次工具调用不是终点，而是下一次证据决策的输入。agent 需要同时维护工具的历史工作范围和当前任务的证据状态。
5. **方法切口**：MIRA 在调用前选择工具，调用后根据当前输出与已有常识/证据判断验证、互补、拒答或继续，并在 delayed outcome release 后更新工具工作范围。
6. **能力提升路径**：先证明首次调用选得更合适，再证明后续证据决策减少错误或控制风险，最后证明这套状态能跨任务实时适应；每一层都有 matched baseline 和独立证伪条件。
7. **论文结论**：只有在相同菜单、信息权限、反馈时钟和调用预算下，MIRA 同时改善可靠答案、错误交付、拒答和调用成本，才主张它提高了 agent 的工具调用能力上限。

## 创新点：当前怎样表述

当前要完成的中心方法命名为 **MIRA（Menu-aware Incremental Reliability Adaptation for Scientific Tool Calls）**。历史讨论中的 JEV 只作为功能参照，不作为论文方法名。MIRA 的目标不是只做一个 selector，而是一个**面向能力上限的 evidence-aware tool-calling loop**：

- 选择器在调用前只使用分子、端点、菜单和已释放的历史；
- provider 返回后把输出当成当前任务证据，结合工具历史工作范围、运行状态和已有常识估计结果风险；
- 根据证据关系选择相互验证、互补工具、拒答或继续调用，而不是固定追加一个工具；
- 终止后的 selected-only correctness 按延迟队列更新工具工作范围和后续选择状态；
- 选择、验证、更新各有独立日志，可以单独证伪。

这里的目标创新是把“工具工作范围建模、当前证据解释、后续调用价值和 delayed outcome adaptation”连成一个可审计的整体机制。联合可靠性模型是其中一个候选支撑组件，用来表示重复错误和互补证据；它不是论文目标本身。LinUCB、SGD、Bayesian posterior、PILOT、Laya 以及其他现成表示本身都是比较对象或可复用组件；MIRA 是否形成整体贡献，仍由 integration gain、最强 matched baseline、能力层级实验和 confirmation 验证。

## 能力层级与实验切口

论文把“大目标”拆成三个递进层级，但不把它们混成一个指标：

| 能力层级 | agent 要学会什么 | 最小可检验任务 |
|---|---|---|
| 工具适配 | 根据分子、端点、菜单和历史表现选择最合适的 provider | 一次调用 direct selection，primary E2a |
| 证据决策 | 解释当前工具结果，判断验证、互补、拒答或继续调用 | 两次调用 sequential evidence extension |
| 持续适应 | 用 delayed selected-only outcome 更新工具工作范围，适应版本、分布或可靠性变化 | delayed replay + controlled shift/lifecycle stress |

这里的“最合适”不是全局平均准确率最高，而是对当前任务、当前证据和调用成本的预期最终损失最低。实验必须分别报告首次选择、后续证据决策和持续适应，不能用第二次调用的收益冒充第一层 selector 提升。

## 证据边界

已经观察到的证据：

- 722 条 BBB development replay 上，静态 representation diagnostic 的 Best Fixed accuracy 为 `0.915512`；该实验只说明直接选择的难度，不是最终动态方法结果。见 `task/task49-pharma-benchmark-baseline-freeze/fingerprint_diagnostic_v1/report.md`。
- 调用后 numeric confidence 对 correctness 有 held-out 信号；固定阈值的第二工具复核开发结果为 `0.923823` accuracy、平均调用数 `1.206`。这是开发证据，不是 confirmation 结果。见 `task/task49-pharma-benchmark-baseline-freeze/confidence_escalation_v1/report.md`。
- development master table 已补齐 Matched SGD、PILOT、BayesianRouter 和 Greedy；Best Fixed `0.9155` 仍高于当前所有动态 selector 结果。selected-only 的若干在线 head、transfer、memory 和动态 risk gate 没有通过预注册闸门。它们是实现版本的停止和边界证据，不等于 MIRA 目标被单次实验推翻；当前只是不能把“MIRA 已有效”写成已经验证的结果。

尚未成立的部分：MIRA 的最终状态、更新规则、provider 资格和独立 confirmation 仍未冻结。因此本文件保留目标 claim，同时明确“MIRA 已有效”尚未被当前证据证明。

## 主张纪律

论文只允许在证据满足对应闸门后使用以下主张：

| 主张 | 必须有的证据 |
|---|---|
| 任务真实且有难度 | 公共 truth、provider 分歧、无泄漏的信息合同 |
| 调用后验证有用 | 预登记阈值、匹配调用成本、独立恢复和 confirmation |
| 动态更新有用 | 延迟反馈回放、最强 matched baseline、跨 seed/端点结果 |
| 方法可推广 | 至少一个未参与开发的端点或 scaffold-disjoint confirmation |

若某个候选失败，先检查实现、数据资格、信息边界和预算是否正确；只有在这些都通过后，才讨论是否修改创新假设。重大修改要先形成双方确认的决议。

## 论文应该怎样把这条故事讲完整

这里写的不是“录用公式”。AAMAS 没有规定每篇论文必须使用同样的段落数；我们要保留的是一条在代表性论文中反复出现的论证行为：**具体现实问题 → 可复现失败 → 失效原因 → 只针对该原因的 insight → 可执行机制 → 匹配证据 → 适用边界**。这条行为逻辑是本项目写作时的硬约束。

### 一句话主张轴

整篇论文必须能用一句话回答：

> 在科学工具的适用范围和错误结构未知时，agent 能否根据工具历史和当前证据选择、验证、互补或拒答，从而在相同信息与预算下提高可靠任务能力？

这句话同时限定了愿景、机制和评价对象。Introduction 建立能力上限问题，Method 把工具工作范围、当前证据状态和动作集合写成接口，Experiments 逐层检验它，Discussion 解释它在哪些条件下失效。不能在不同章节把主线偷偷换成“更大的 backbone”“一个通用 router”或“只做联合概率拟合”。

### 引言的段落顺序

| 段落 | 这段只做什么 | 本项目的内容 | 下一段接什么 |
|---|---|---|---|
| P1 | 说明领域为什么在意 | 科学工具已经成为 agent 的可调用能力，同一性质由多个 provider 估计 | 正常返回不等于可用 |
| P2 | 给出真实失败 | 同一分子/端点的 provider 结果可能分歧，格式正常但结论错误；给一个可复核例子 | 选择时还不知道谁会错 |
| P3 | 解释旧方法为什么不够 | 未选 provider 输出不可见；correctness 只对已选工具产生且可能延迟；post-call confidence 不能回填 pre-call selector | 需要明确的信息时序 |
| P4 | 给出全文最重要的 insight | 把调用前选择、调用后验证/升级和 delayed update 放进同一个事件合同；MIRA 是可恢复的动态状态 | insight 必须进入形式模型 |
| P5 | 一两句说方法 | 选择器、验证器、更新器各自的输入输出、状态和开销 | 下一节定义对象和执行步骤 |
| P6 | 列出可验证贡献 | 每项写主张、最近邻、证据和失败条件；没有结果时不写“提升” | 后文用 RQ 和表图回答 |

正文不写“我们先试了 A，再改成 B”的编年史。失败尝试留在消融、错误分析或附录；主文先给读者最终的问题、机制和比较边界。

### 每个段落的内部结构

每个段落默认由三步组成：

1. **Topic sentence**：第一句说清本段要证明、定义或区分的关系；
2. **支持句**：给事实、反例、公式、引用或结果；新符号先解释，再给具体 case；
3. **桥接句**：说明这段为什么把问题交给下一段。

一段只完成一个动作。问题重要性、方法定义、实验结果和局限不能挤在同一段里。把所有段落第一句抽出来后，应该仍能读出：`真实分歧 → 选择时序 → 旧方法缺口 → MIRA insight → 接口 → 证据 → 边界`。

### 各章节的行为逻辑

- **Abstract**：现实实践 → 具体失败 → 命名对象 → 机制改变了什么 → 覆盖的任务/反馈/对照 → 真实 headline result → 机制性边界 → 持久教训。没有 confirmation 数字时，不能用 development replay 数字冒充方法效果。
- **Related Work**：按冲突关系写，不按年份堆。至少区分 static/offline routing、contextual online provider selection、delayed/partial feedback 和 dynamic pool。P04/P06 已覆盖 contextual provider selection，本文必须说明自己增加了什么约束。
- **Problem/Method**：每个小节先用一两句说明本节目标；然后按“输出接口 → 输入与信息边界 → 执行步骤 → 公式/伪代码 → 替代方案为什么不够”的顺序展开。
- **Experiments**：按研究问题组织，不按执行顺序。RQ1 测 direct selection，RQ2 测 post-call verification，RQ3 测 provider/version event 后的 recovery，RQ4 测 delay、failure、menu、endpoint 和 scaffold 边界。主表回答主问题，消融解释机制，错误分析说明边界。
- **Discussion**：解释结果意味着什么，不重复表格数字；把结论限制在真实 provider 资格、数据端点和反馈合同覆盖的范围内。
- **Conclusion**：只留一条持久教训，不引入新方法、数据或未来工作清单。

### 行文风格

- 一个概念只用一个术语：MIRA、selector、verifier、updater、provider 不互换叫法；JEV 只用于历史参照；
- 先用日常语言解释，再给术语和正式定义，再给例子；
- 公式前先说它要算什么，公式后说明如何由日志恢复；
- 主动语态、短句、具体动词，少用“显著”“有效”“创新”等没有证据的形容词；
- 每条引用都要完成对比工作，不能只挂在句末；
- 用绝对差、区间和分母表达结果，不用过多小数位制造确定性；
- 强主张必须有对应证据，证据不够就缩小主张；负结果保留在能解释机制边界的位置。

## 故事线的写作验收

### 1. Topic-sentence 检查

只读引言、方法、实验、讨论的第一句，陌生读者应该能复述：问题是什么、旧方法为什么不够、我们改变了什么、哪张图/表能推翻它、何时不工作。

### 2. Claim–evidence 检查

每个贡献写成四列：`claim / 最近邻 / 证伪实验 / 当前证据状态`。当前候选主张分别对应 direct selected-only selection、delayed online update、post-call verification/escalation。若一条证据被拿来同时证明三件事，默认不通过，除非实验中有三个独立 intervention。

### 3. Reviewer 五问

给审稿人标题、摘要、引言和主图，他应该能回答：

1. 具体失败是什么？
2. P04/P06 等最近方法为什么不够？
3. 新机制改变了哪个信息或计算？
4. 哪张图/表能推翻它？
5. 在什么条件下不工作？

答不出来时，不增加泛背景；先修 P2–P5 的转接或收窄主张。

### 4. 这套规则的边界

这套规则是本项目的内部写作与论证标准，不是 AAMAS 的官方模板，也不保证录用。它不要求每篇论文必须六段引言或四个 RQ；它要求本论文的故事、方法、实验和文字遵循同一条可检查的因果链。真正能否投稿，仍取决于问题重要性、方法 soundness、最近邻差异、真实证据和可复现性是否同时成立。
