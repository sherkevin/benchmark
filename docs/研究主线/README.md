## 研究与写作过程标准

[论文研究与写作流程](../论文研究与写作流程.md) 是本项目从 idea、文献和多 agent debate，到 benchmark/baseline、真实实验、结果回填、论文写作和投稿前红队审查的统一过程标准。它约束如何推进工作，不替代上面的三份主线文档，也不把 debate 共识当成科学证据。

## 版本规则

1. 新版本先写入 `版本/` 对应类别目录，再经过双方确认；确认后把它复制到 `生效/`，旧生效版保留在版本目录。
2. 不在原文件上悄悄改口径。每个版本头部写版本号、状态、生效日期和职责。
3. 六份文档之间要互相引用，不重复维护同一条实验数字。数字和运行细节放在 `task/` 或 `experiments/logs/`，主线只写结论和证据路径。
4. 旧的 `docs/` 文档、`docs/adr/` 和继承材料保留作历史证据；除非本页明确链接，不视为当前主线。

## 决议和证据怎么放

- `docs/决议/` 只保存双方确认的关键取舍、约束和争议裁定，例如某个模块是否进入主线、某个数据口径是否冻结。
- `task/` 保存实验卡、预注册、报告和恢复脚本。
- `research/` 保存来源审计和专题研究。
- `experiments/logs/` 保存原始 JSONL、配置、哈希和失败现场。

如果问题属于“这篇论文要讲什么、方法怎么定义、要做哪些实验”，先改对应的三份主文档；如果只是一次实现选择或有争议的小口径，才考虑新建决议。
