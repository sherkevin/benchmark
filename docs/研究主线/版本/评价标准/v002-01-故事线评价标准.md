## 先说结论

一篇论文只有在读者能迅速说清“真实失败、技术原因、方法改变了什么、哪个实验能推翻它”时，故事线才算过关。背景重要、系统很大或结果很高，不能替代这条因果链。

## 1. 先过硬闸门

下列任一项为“是”，直接不通过，不进入分数汇总：

| 编号 | 硬闸门问题 | 不通过例子 |
|---|---|---|
| H1 | 是否超出所选 AAMAS area 的对象范围，或 agent 的作用无法定位？ | 论文实际只改一个分子预测器，却把 tool use 作为标题包装 |
| H2 | 是否存在一个具体、可观察、可复现的失败场景？ | 只有“工具越来越多、选择很困难”这类泛背景 |
| H3 | 是否能指出最近邻工作为什么在该场景下不够？ | 只列引用，不说明差异和失效条件 |
| H4 | 创新是否只是换 backbone、换 loss、把标准 bandit/SGD 改名？ | 机制、信息和目标都与已有方法相同 |
| H5 | 是否有与每个核心主张对应的实验或理论证据？ | 只写“提升可靠性”，没有可靠性的可计算指标 |
| H6 | 是否存在信息泄漏、选择性报告或事后改 benchmark 的叙事？ | 用 post-call confidence 解释 pre-call selector |
| H7 | 核心论证是否依赖 reviewer 未必阅读的补充材料？ | 正文没有任务定义、关键算法或主结果 |
| H8 | 是否把开发结果、探索结果写成 confirmation 或普遍结论？ | 722 条 development replay 被称为 untouched test |

H1–H8 任何一项成立，标准结论只能是“重写或补证据”，不能靠润色通过。

## 2. 十项评分

每项按同一标准打分：

- `0`：缺失、矛盾，或只能靠口头解释；
- `1`：有描述，但证据不完整，审稿人仍需猜；
- `2`：正文给出明确对象、最近邻、证据位置和适用边界。

| ID | 检查项 | 2 分必须看到什么 | 证据记录 |
|---|---|---|---|
| S1 | 切口锋利 | 一句话只包含一个核心失败和一个核心能力；删掉背景段后主问题仍成立 | 引言第 1–3 段 |
| S2 | 失败真实 | 有真实数据/部署场景/可复现案例，说明为什么正常返回仍可能错 | 数据审计或案例 |
| S3 | 因果链 | 失败原因 → 形式化困难 → 方法机制 → 指标，四步一一对应 | story-to-method map |
| S4 | AAMAS 相关性 | 明确 agent 在选择、学习、验证或决策边界中的作用；不是把 agent 当装饰 | area fit 段 |
| S5 | 创新必要性 | 说明新机制使用了什么已有方法没有的信息/结构/目标，并给出没有它会失败的对照 | novelty table + ablation |
| S6 | 最近邻定位 | 至少列出 3 个最近工作，每个写“它做了什么、我们差在哪、为何不能直接解决” | related-work matrix |
| S7 | 主张可证伪 | 每个 contribution 都有一个会让它失败的实验、理论条件或边界 | claim–test map |
| S8 | 证据不越界 | 主张范围不超过数据、端点、provider 资格和 confirmation 支持范围 | claim ledger |
| S9 | 边界和失败 | 主动报告不工作、成本上升、分布变化和不适用条件 | error/limitation section |
| S10 | 叙述清楚 | reviewer 不看附录也能复述问题、方法、主结果和限制 | 盲读测试记录 |

### 通过阈值

- H1–H8 全部为“否”；
- S1–S7 每项必须为 `2`；
- S8–S10 至少 `2` 项为 `2`，其余不得为 `0`；
- 总分至少 `17/20`；
- 提交一张 claim–evidence 表和一张 nearest-work 表，缺一不通过。

这是一道内部拒稿线。分数达到阈值只代表故事具备送审条件，不代表 AAMAS 会录用。

## 3. Reviewer 五问

在提交前找一个不了解项目的人，只给他标题、摘要、引言和主图，要求回答：

1. 我们到底解决哪个失败？
2. 为什么现有方法在这里不够？
3. 我们的机制改变了什么计算或信息使用？
4. 哪张表/图能证明核心主张？
5. 在什么情况下方法不工作？

五问有一问答不出来，S1、S3、S7 或 S9 不得给 2 分。

## 4. 评价标准的来源

- **O 官方要求**：AAMAS 2027 统一评价 originality、significance、soundness、reproducibility、clarity、relevance、presentation 和 state of the art；正文必须能独立理解核心贡献。见 [Main Track Call](https://warwick.ac.uk/fac/sci/dcs/aamas2027/calls/call-for-main-track/)、[Reviewer Guidelines](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/reviewer-guidelines/) 和 [Submission Instructions](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/instructions/)。
- **P 代表性规律**：AAMAS 2023–2026 近邻论文反复出现“具体困难—形式化—对应机制—对照—边界”的结构；详见溯源矩阵，不把它当统计定律。
- **C 项目加严**：S1–S10 中关于信息边界、provider 资格和 confirmation 的部分，是我们为了让本文主张可审查而加的内部门槛。

## 5. 不通过后的动作

- H1–H4：停止写实验结果，先重写问题、最近邻和创新边界；
- H5–H8：停止投稿构建，补齐证据隔离和 claim ledger；
- S1–S7 不足：不能用增加模块或增加 benchmark 掩盖；
- S8–S10 不足：缩小主张并补边界分析，保留负结果。

## 6. 评分执行规则

评分由写作者和一名未参与该段实现的人分别完成。两份评分不取平均：有证据支持的较低分生效。评分表必须附证据路径；“作者解释过”不能替代正文、代码或日志证据。
