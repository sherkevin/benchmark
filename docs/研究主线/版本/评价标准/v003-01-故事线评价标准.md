## 1. 这份标准审什么

这份标准同时审两件事：

1. 论文是否有一条可证伪、和最近工作有清楚边界的故事线；
2. 论文是否按顶会审稿人实际阅读的顺序组织全文，让每一段都完成明确的论证动作。

它不是“写得顺不顺”的风格检查，也不是把六段引言当成固定模板。六段引言、各章节顺序和下面的段落规则，是从 AAMAS 2023–2026 代表性论文与本项目已有结构审计中提炼出的默认组织方式；如果偏离，作者必须写出理由，并证明读者仍能沿着同一条因果链复述全文。

## 2. 来源层级和证据原则

| 层级 | 含义 | 在本标准中的作用 |
|---|---|---|
| O | AAMAS 官方明确要求：originality、significance、soundness、reproducibility、clarity、relevance、presentation、state of the art，以及正文独立可理解 | 决定硬门槛和最低合格线 |
| P | 近年 AAMAS 代表性论文的反复结构：具体困难 → 形式化 → 针对机制 → 对照证据 → 边界 | 决定段落和论证的检查方式，不声称是统计定律 |
| C | 本项目的 selected-only、延迟反馈、provider lineage、confirmation 隔离和 agent 作用边界 | 防止本项目特有的过度主张和信息泄漏 |

每一个分数都必须能回到正文段落、图表、代码、原始日志或研究审计。作者在口头答辩中的解释不能替代缺失证据。

## 3. 硬性淘汰条件

下列任一项为“是”，直接不通过，不进入分数汇总。修复后必须重新评分。

| 编号 | 硬门槛问题 | 触发例子 |
|---|---|---|
| H1 | 对象是否属于选定 AAMAS area，且 agent 在选择、学习、验证或决策边界中有不可替代的作用？ | 只改一个分子预测器，却用 tool-use 包装标题；agent 不影响任何动作或信息流 |
| H2 | 是否存在一个具体、可观察、可复现的失败？ | 只有“工具变多所以选择困难”这种泛背景 |
| H3 | 是否指出最近邻方法在同一失败场景中的明确失效条件？ | 只列引用，不写它们能看到什么、不能看到什么 |
| H4 | 创新是否改变了问题中的信息、状态、目标或机制，而不只是换 backbone、loss 或名称？ | 标准 bandit/SGD 加一个新名字就称为动态 JEV |
| H5 | 每个核心主张是否都有独立的实验、理论或构造性反例？ | “提升可靠性”没有可靠性的定义和可反驳测试 |
| H6 | 是否存在信息泄漏、选择性报告或事后修改叙事？ | 用完整输出面板证明 pre-call selector；把 development 结果写成 confirmation |
| H7 | 正文是否自洽地包含问题、方法、主要证据和限制？ | 关键定义或主结果只放补充材料 |
| H8 | 是否把候选、探索或开发结果写成已确认结论？ | provider 资格未定，却声称模型泛化到真实工具 |
| H9 | 文章的章节或段落顺序是否阻断因果链？ | 先报结果，后补任务定义；引言没有从失败过渡到方法 |
| H10 | 是否有系统性的段落失职？ | 大量段落没有 topic sentence，或一段同时塞入问题、方法、结果和局限而没有桥接 |

## 4. 评分方法

### 4.1 统一计分

12 个评分项各取 $q_i\in\{0,1,2,3,4\}$，权重合计 100。总分为

$$
S=\sum_i w_i q_i/4,
$$

其中 $w_i$ 是百分比权重，因此 $S$ 的满分为 100。评分不是印象分：每项都必须填写分数、证据路径、一个具体缺口和下一步动作。

- **4 分**：正文、证据和边界完整，陌生复核者可独立重建，不需要作者补口头前提。
- **3 分**：主张和证据完整，只有不改变结论的局部清晰度或呈现问题。
- **2 分**：有方向但缺关键证据、转接或边界；需要作者解释，不能作为投稿稿状态。
- **1 分**：只有断言、口号或零散材料，审稿人必须猜测因果关系。
- **0 分**：缺失、互相矛盾、越过信息边界，或证据明确推翻该项。

### 4.2 通过条件

同时满足以下条件才算“故事线通过”：

1. H1–H10 全部为“否”；
2. S1–S6（核心故事和创新）每项至少 3 分；
3. S7–S12 每项至少 2 分，且 S7–S10 的平均分至少 3 分；
4. 总分 $S\ge 85$；
5. 具备一张 claim–evidence–falsification 表和一张 nearest-work 对照表，二者都能追到正文、代码或日志。

80–84 分只能进入“返工”；低于 80 分或任何硬门槛触发，结论为“不通过”。85 分以上也只表示“达到内部投稿审查线”，不表示 AAMAS 会录用。

分数还要分级使用：

- **FAIL**：任一 H 触发；或总分低于 80；或核心段落通过率低于 90%；
- **REWORK**：无 H、总分 80–84；或 S1–S6 任一只有 2 分；
- **STORY READY**：无 H、总分至少 85、S1–S10 全部至少 3 分、核心段落通过率至少 95%，陌生读者盲读五问全部答对；
- **SUBMISSION REVIEW READY**：无 H、总分至少 90、S1–S12 全部至少 3 分、至少 6 项为 4 分、引言核心段落 100% 通过，两名独立读者盲读五问全部答对。

这四个等级都是内部工作状态，不是 AAMAS 分数或录用预测。

## 5. 逐项评分表

| ID / 权重 | 4 分 | 3 分 | 2 分 | 1 分 | 0 分 | 必须保存的证据 |
|---|---|---|---|---|---|---|
| **S1 切口与重要性 / 10** | 一句话同时限定对象、失败和受损决策；给出真实后果和可计算指标 | 失败和后果清楚，指标或范围有小缺口 | 背景充分但失败仍可换成泛化口号 | 只有“大模型/工具多/可靠性重要” | 没有可识别问题或与 agent 无关 | 引言 P1–P3、任务合同、失败案例 |
| **S2 任务与 agent 角色 / 8** | 明确 pre-call 选择、post-call 反馈/验证和 agent 的具体动作，读者能画出信息流 | 动作和角色清楚，个别边界需补一句 | 角色存在但可被普通预测器替代 | 只把 agent 当背景词 | agent 不参与问题或动作 | problem statement、时序图、area-fit 段 |
| **S3 因果链 / 10** | 真实失败 → 根因 → 数学困难 → 机制 → 指标逐段一一对应，删掉任一环都会破坏论证 | 链条完整但一处桥接较弱 | 机制与问题都在，但中间因果靠推测 | 先讲方法再找问题 | 结论与证据无因果关系 | story-to-method map、段落首句抽取 |
| **S4 创新必要性 / 12** | 明确新增的信息/状态/目标和机制，给出最近邻不能处理的反例及对应消融 | 新增机制和差异清楚，反例或消融有一项较弱 | 只有模块差异，必要性未证 | 只是 backbone/loss/命名变化 | 被最近邻完全覆盖且无反例 | novelty table、机制消融、构造反例 |
| **S5 最近邻边界 / 8** | 至少 3 个最近邻逐个写出输入、反馈、目标和失效条件，并说明公平比较方式 | 最近邻充分，个别信息合同未量化 | 有引用但只写“不同/更强” | 文献堆砌或只引综述 | 关键最近邻遗漏或错误描述 | related-work matrix、原文页码 |
| **S6 可证伪主张 / 10** | 每条 contribution 都有唯一主指标、最强对照、会推翻它的条件和结果位置 | 主张可测，某条反事实条件未登记 | 主张可测但多个主张共用一个不能区分的结果 | 使用“有效/显著/可靠”等无操作定义词 | 任何结果都无法推翻主张 | claim ledger、RQ–table map、预注册 |
| **S7 引言漏斗 / 8** | 背景、具体失败、根因、insight、方法、贡献按读者认知顺序各自成段，段首可独立读懂 | 六个功能齐全，有一处段落合并但逻辑不损失 | 功能齐全但转接需要作者解释 | 背景或方法占满引言，问题很晚才出现 | 无法从引言复述故事 | 引言段落编号、topic-sentence audit |
| **S8 章节和 RQ 结构 / 8** | Abstract/Related Work/Method/Experiment/Discussion/Conclusion 各自回答规定问题，RQ 与表图一一对应 | 章节齐全，个别 RQ 有冗余 | 章节存在但按执行顺序堆结果 | 主要靠附录补逻辑 | 读者无法知道下一节为何出现 | section map、RQ–figure/table map |
| **S9 段落单位与转承 / 8** | 每段只有一个动作，首句是 topic，支持句给证据，末句完成桥接；抽取首句仍保留因果链 | 少数段落缺桥接或过长，不影响主线 | 多段需要重写，读者需回看上下文 | 段落是材料堆，无主题句 | 系统性无法定位论点 | 段落审计表：topic/support/bridge |

| **S11 边界和主张校准 / 6** | 明确端点、provider、延迟、分布和失败边界；负结果放在能解释机制的位置 | 边界齐全，少一个非核心维度 | 只写笼统 limitations | 用有限实验推出普遍结论 | 隐瞒失败或把开发当确认 | claim ledger、error/limitation section |
| **S12 语气与呈现 / 6** | 主动语态、具体动词、少空泛形容词；引用完成对比工作；数字含分母和区间 | 个别修辞问题，不影响审稿判断 | 有明显模板化表达或过度小数位 | 口号、广告语、结果先于定义 | 夸大、攻击近邻或用语混淆范围 | 全文语言审计、引用表、数字核对 |

## 6. 文章组织的强制检查表

这是 S7–S12 的操作化版本。每一项都必须在审稿前填写“段落号—证据—缺口”。

### Abstract

单段完成六个动作：现实场景与失败、形式化对象、机制改变、评测范围、已确认 headline result、边界/教训。没有 confirmation 数字时只能写已完成的 development 事实，不能用开发结果冒充最终效果。

### Introduction

默认采用六段漏斗，允许合并但不允许缺功能：

1. 为什么科学工具调用的结果可信度是 agent 决策问题；
2. 一个可复现的“正常返回但错误”的具体案例；
3. 选择前不可见、反馈延迟和验证时点造成的根因；
4. 为什么 static routing、普通 contextual bandit 或离线 JEV 不够；
5. 方法接口和信息边界如何改变计算；
6. 贡献按“主张—最近邻—证据—边界”写，不提前写未确认数字。

核心段落逐段检查 topic sentence → support → bridge。缺任一步，该段最高 2 分；引言 P1–P6、每个方法小节首段和每个 RQ 首段必须全部通过。把所有核心段落第一句抽出来后，仍应读出“分歧 → 时序 → 缺口 → 动态 JEV insight → 接口 → 证据 → 边界”。

### Related Work

按冲突关系而不是按年份堆文献：static/offline routing、contextual online selection、delayed/partial feedback、dynamic provider/version pool。每一组结尾必须有一句“已有方法的输入/反馈/目标”和“一项本文新增约束”的对比。

### Method

每个小节按“本节要解决的困难 → 输出接口 → 合法输入和禁止输入 → 执行步骤 → 公式/伪代码 → 为什么替代方案不够”展开。公式前解释要算什么，公式后给一条可从日志恢复的 case。

### Experiments

按 RQ 而不是按代码执行顺序组织：直接选择、调用后验证、动态 provider/version 事件、延迟/失败/分布边界。主表回答主问题，消融解释机制，错误分析说明何时失败。主表不能只是运行日志的拼接。

### Discussion and Conclusion

Discussion 解释结果意味着什么，并限定在真实 provider 资格、端点和反馈合同覆盖范围内。Conclusion 只保留一条可迁移的教训，不引入新数字、新方法或未来工作清单。

## 7. 双人评分和复核规则

只对当前生效故事线文档和标明版本/commit 的论文草稿评分。作者与一名没有参与当前段落实现的复核者独立填写：

ID | 维度 | 作者分 | 复核分 | 生效分=min | 证据路径 | 可审查摘录 | 缺口/修复动作

复核者必须能在 10 分钟内从证据路径找到原文、图表、代码或日志；找不到就不能给 3 或 4 分。若两人对同一项相差 2 分以上，先补证据再重评，不允许用讨论把分数调高。分数必须绑定论文 draft 的版本、日期和 commit；重大改动后不能沿用旧分数。

提交物至少包括：story_scorecard.md、段落审计表、claim–evidence–falsification 表、nearest-work 表、五问盲读记录和评分证据 hash。标准通过后，任何新增主张或新增实验都必须重新检查受影响项。

## 8. 五问盲读

给陌生读者标题、摘要、引言和主图，不给口头补充，要求其回答：

1. 具体失败是什么？
2. 最近邻为什么在这里不够？
3. 新机制改变了哪个信息或计算？
4. 哪张图或表可以推翻核心主张？
5. 在什么条件下方法不工作？

五问有一问答不出来，S1、S3、S4、S5、S6 或 S11 不得给 3 分以上。

## 9. 评分结果的动作

- 硬门槛触发：停止写结果，先修问题边界、信息合同或证据隔离；
- S1–S6 任一低于 3：重写故事或缩小创新主张，不靠增加背景和模块补分；
- S7–S10 低于 3：重排段落、补 topic/support/bridge 和 RQ 映射；
- 总分 80–84：只允许内部返工，不进入 confirmation；
- 总分 ≥85 且门槛全过：可进入三份标准的联合复核，但仍不构成录用预测。
