## 先定任务，再谈算法

### 目标方法名

本文将目标方法统一命名为 **MIRA（Menu-aware Incremental Reliability Adaptation for Scientific Tool Calls）**。它覆盖调用前 provider 选择、调用后验证/升级/拒答和 selected-only 延迟反馈更新。JEV 仅作为历史功能参照，不作为论文方法名。当前实现候选没有通过主闸门，不改变 MIRA 的目标，只决定下一轮如何修复和证伪。

### 三种状态要分开

- **已确认约束**：动作先于当前结果；只释放已选 provider 的反馈；延迟队列和失败语义必须逐事件记录。
- **当前候选**：调用后 confidence 风险门、追加第二工具、selected-only 延迟状态。
- **未决项**：最终 backbone、状态参数化、探索规则和是否把 verifier 与 selector 联合训练。当前所有普通 selected-only selector 更新候选都没有通过 development 主闸门，不能把某个候选默认写成 Proposed。

一条 episode 的输入是分子 $x_t$、性质端点 $e_t$ 和可用 provider 菜单 $A_t$。选择器在调用前选一个 $a_t\in A_t$。provider 返回预测和运行状态；只有在终止后，系统才产生该次选择的 correctness $r_t\in\{0,1\}$，并在预登记延迟后释放给后续 episode。

符号的具体案例：$x_t$ 是输入表中的 BBB 分子 `z000282`，$e_t=	ext{BBB}$，$A_t$ 是该题可用的 33 个 provider id，$a_t=	ext{b3clf_dtree_common}$，$r_t=1$ 表示该 provider 的二元预测与冻结真值一致。这个案例只解释接口，不宣称该分子在最终 confirmation 中使用。

选择前的合法历史记为 $H_t$，它只包含已经释放的事件：

$$H_t=\{(x_s,e_s,a_s,r_s,	au_s):s<t,\ 	au_s\le t\}$$

其中 $	au_s$ 是反馈释放时刻。案例中，若 `z000282` 的反馈在第 5 个 tick 才释放，那么第 2 个 tick 的选择只能使用更早释放的事件，不能读取 `z000282` 的未选 provider 输出。

选择器和验证器必须分开：

$$a_t=\pi_{\mathrm{sel}}(x_t,e_t,A_t,H_t),\qquad v_t=\pi_{\mathrm{ver}}(o_t,c_t,s_t)$$

$a_t$ 是调用前动作；$o_t$ 是被选 provider 的返回；$c_t$ 是返回后的 numeric confidence（可缺失）；$s_t$ 是运行状态；$v_t$ 是直接接受、追加工具或拒答。案例中，selector 先选 `b3clf_dtree_common`，拿到 confidence 后 verifier 才能决定是否追加第二工具；confidence 不能提前喂给 selector。

## 动态状态和更新

方法要维护一个可快照的状态 $S_t$。状态更新只接收已释放的 selected-only 事件：

$$S_{t+1}=U(S_t,x_t,e_t,a_t,r_t,	au_t)$$

案例中，`r_t` 未释放时，状态不变；释放后只增加一次该 provider 的观测，不补写未选 provider 的标签。$U$ 的具体形式目前仍是候选，必须在实验卡中固定后再跑确认。

一个最小的风险门写法是：

$$q_t=g(S_t,o_t,c_t,s_t),\qquad v_t=egin{cases}	ext{accept},&q_t<\eta\	ext{escalate},&q_t\ge\eta\end{cases}$$

$q_t$ 是调用后错误风险，$\eta$ 是训练区固定阈值。案例中 confidence 缺失时不把它当作低风险；可先走预登记的 fallback，再决定是否追加工具。这个式子定义接口，不代表当前已通过的最终算法。

## 模块边界

| 模块 | 只读什么 | 产出 | 当前状态 |
|---|---|---|---|
| Pre-call selector | $x_t,e_t,A_t,H_t$ | 一个 provider id | MIRA 的调用前模块；当前实现候选尚未成立，保留为 benchmark 主任务 |
| Provider adapter | 分子、端点、provider 版本 | 原始输出、confidence、状态 | Task36 回放可用，正式 provider 资格仍需冻结 |
| Post-call verifier | 被选输出和调用后状态 | accept/escalate/refuse | confidence escalation 是当前最有信号的候选 |
| Delayed updater | 已释放 selected-only 事件 | 新状态快照 | 更新规则待定，必须有延迟队列收据 |
| Agent interface | selector/verifier 的结构化结果 | 工具调用、复核、拒答轨迹 | 属于后续 agent 能力评估 |

## 计算与实时性要求

- 单条反馈更新要是事件级操作，不能重跑全部历史；报告 p50/p95 更新时间和内存。
- 状态必须可序列化，恢复后能重算每个动作和聚合指标。
- 延迟 $d\in\{0,1,4\}$ 在同一输入流上预登记；方法不能按结果选择 delay。
- 未知真值、provider failure 和未释放事件分别记账，不静默填成正确或错误。
- 冷启动、共同 warm start、在线更新三种信息权限分开做实验。

## 与 baseline 的关系

Frozen、Best Fixed、Online/Replay SGD、Greedy LinUCB、PILOT-adapted 和 BayesianRouter-adapted 是合法对照。它们帮助回答“表示、普通在线更新、现代 router 先验和延迟本身各贡献多少”。如果 Proposed 只是把标准 ridge 或 posterior 换一个名字，不能写成创新。

当前 MIRA 的实现候选仍处在迭代阶段：direct selected-only head、provider transfer、context memory 和普通动态 verifier risk gate 均没有超过 Best Fixed 或对应强对照。旧 prior-specific Matched receipt 曾出现小幅相对改善，但当前通过 v2 fail-closed verifier 的 strict common receipt 中，Online-SGD pooled=`0.892198`，低于 Frozen=`0.901662`；Greedy/PILOT/BayesianRouter 也没有形成稳定正收益。这些结果定位了待修复的问题，不降低 MIRA 的目标。下一候选必须有新的可观测反馈、明确的结构理由和独立 method card；不靠调参把负结果改成正结果。

这里的“旧 prior-specific”必须保留 lineage 语义：当前 strict Matched 使用
`common-direct-prior`，历史 Matched/Replay 使用旧 BT `score.weight`。两套 prior 的最大绝对
差为 `0.2243737`、相对 L2 约 `0.9938`，所以历史 Replay 的正点差不能直接支撑当前
common-direct-prior 的在线收益 claim。若后续比较 Replay，必须先登记同一 prior、同一
warm-start 和同一事件合同的回放。

2026-10-02 的逐样本审计进一步把候选机制收窄为 **incumbent-safe switching**。在当前
common-stratum 中，FamilyGuard 离开 fit-only `admetlab_3_0` 的 3,619 次选择带来 222 次
误伤，同时救回 188 次固定赢家错误；误伤中 212 次是错误标签，10 次是 runtime failure。
第一版 SafeSwitch 用 provider 边际 Beta 账本和路径依赖的 current incumbent 做了 5 个
CPU 收据。双侧门在 fold0 完全不切换；放宽到单侧 LCB 后，只有一次相对上一动作的切换，
随后 143 个动作继续使用同一 challenger，结果 126/145，低于 fit-only Best Fixed 的
130/145。收据和独立复核见 `task/task49-pharma-benchmark-baseline-freeze/mira_safe_switch_v1/report.md`。

这个负结果把下一候选的必要条件说清楚：状态必须分成 correctness evidence 和 runtime
hazard 两条账本，但 correctness 还必须是 **context-conditioned posterior predictive**；
不能用 provider 边际正确率代替当前分子上的可靠性。fit-only Best Fixed 要作为显式 fallback
reference，不能让一次 challenger 选择永久改变比较锚点。SafeSwitch v1 是负对照和问题定位，
不是已经通过的 Proposed；下一轮先验证 context-conditioned incumbent shield，再决定是否
继续 full common-stratum receipt。

## MIRA v1：面向能力上限的可实现方法合同

本节把 0009 决议中的总故事落成一个可以实现、可以回放、可以逐层验收的目标规格。它是 MIRA 的目标实现版本，不把尚未通过 CPU 或 confirmation 的部分写成实验事实。

### 0. Label contract：每个模块到底学什么

每个 fit molecule/endpoint/provider 三元组都有四个不同对象：

| 对象 | 定义 | 用途 |
|---|---|---|
| 独立真值 $y_i$ | benchmark 的 endpoint truth | 训练 answer posterior、计算 provider correctness |
| 工具输出 $o_{i,a}$ | provider $a$ 的 0/1 预测或原始结构化结果 | 当前任务证据 |
| 运行状态 $s_{i,a}$ | `ok` 或 `error` | 训练 runtime hazard；失败不改写成化学错误 |
| 化学正确性 $r^{\mathrm{chem}}_{i,a}$ | 仅当 $s_{i,a}=\mathrm{ok}$ 时，$\mathbf{1}[o_{i,a}=y_i]$ | JEV correctness head 和 delayed feedback |

当 $s_{i,a}=\mathrm{error}$ 时，$r^{\mathrm{chem}}_{i,a}=\mathrm{null}$，而不是 0；另定义运行标签 $r^{\mathrm{run}}_{i,a}=\mathbf{1}[s_{i,a}=\mathrm{ok}]$。provider 的当前输出和这些标签在 evaluation policy 中不能被提前读取。

JEV 判别式实现至少有两个输出头：

$$q_\theta(a\mid h_i,E_i,L_i)=P(r^{\mathrm{chem}}_{i,a}=1\mid h_i,E_i,L_i),$$

$$p_\psi(y_i\mid h_i,E_i,L_i)=P(y_i\mid h_i,E_i,L_i).$$

$q_\theta$ 用来选择候选工具，$p_\psi$ 用来判断当前答案能否接受或需要拒答。runtime head 单独预测 $r^{\mathrm{run}}$。JEV 的 pair/joint 结构通过 $E_i$ 中已观测 provider 的输出进入；不额外制造一个没有 ground truth 的“验证/互补 label”。

bandit 在决策时没有即时监督 label，它接收的是 selected provider 的 delayed reward：

$$R_t=\mathbf{1}[r^{\mathrm{chem}}_t=1]-\lambda\mathbf{1}[r^{\mathrm{chem}}_t=0]-\kappa_{a_t},$$

并在对应 correctness release 后更新。最终答案的 correctness、refusal 和调用成本是 episode-level evaluation labels，不反向填充未选 provider。

### 1. 两个状态，不混在一起

方法维护两个状态：

- **工具工作范围状态** $S_t^{\mathrm{scope}}$：每个 provider 在什么输入区域容易正确、容易失败，以及运行失败风险；只能由已经 release 的 selected-only outcome 和合法 paired audit 更新。
- **当前证据状态** $E_t$：本题已经调用的 provider、原始输出、运行状态、confidence（若存在）、来源和当前答案后验；它只记录当前任务，不会因为未来 truth 提前改变。

输入表示固定为 $h_t=\phi(x_t,e_t)$。第一版使用冻结的 Morgan fingerprint 与 endpoint id 拼接，在线只更新低维 provider adapter；不在实时循环中重新训练分子 backbone。

符号实例：$x_t$ 是 BBB 分子 `z000282`，$e_t=\mathrm{BBB}$，$A_t$ 是 33 个 provider 菜单，$h_t$ 是该分子的 1024 位 Morgan 表示与 BBB 标记。`b3clf_dtree_common` 的历史状态属于 $S_t^{\mathrm{scope}}$；它在本题返回的 0/1 预测和 `ok/error` 状态属于 $E_t$。

### 2. 工具工作范围模型

对每个 provider $a$，scope adapter 给出当前任务上的正确性和运行风险：

$$p_a^{\mathrm{correct}}(t)=\sigma(h_t^\top w_a+b_a),\qquad p_a^{\mathrm{fail}}(t)=\sigma(h_t^\top u_a+c_a).$$

$w_a,b_a,u_a,c_a$ 从 fit-only 的公共 truth 和 provider 结果初始化；后续只在 selected outcome release 后做事件级更新。这里的“工作范围”不是一句解释性标签，而是一个能被验证的条件概率。

### 3. 当前证据模型

provider 输出统一编码为 $o_a\in\{0,1,\bot\}$：`0/1` 是结构化预测，$\bot$ 是 runtime failure、不可用或没有有效输出。failure 不改写成化学错误。

对已经调用的 provider 集合 $C_t$，候选联合证据模型为：

$$P(o_{C_t}\mid y,h_t,S_t^{\mathrm{scope}})=\sum_{z=1}^{K}\pi_z(h_t)\prod_{a\in C_t}P(o_a\mid y,h_t,z,a).$$

第一版固定 $K=2$，限制为小型共享 latent error mode。它只用于表示重复错误与互补证据，不把 $z$ 解释成真实化学机制。$\pi_z$ 不能直接接收真实 $y$，避免决策时标签泄漏。运行时真值 $y$ 未知，因此对 $y=0,1$ 分别计算 likelihood，再与 fit-only 的 endpoint prior 合成：

$$P(y\mid E_t)\propto P_0(y\mid h_t,S_t^{\mathrm{scope}})P(o_{C_t}\mid y,h_t,S_t^{\mathrm{scope}}).$$

若当前只调用了一个 provider，模型退化成该 provider 的证据更新；只有在第二个 provider 返回后，相关性和互补性才影响后验。

### 4. 首次调用：先选最合适的工具

在 $E_t=\varnothing$ 时，selector 对每个候选 provider 估计调用后的预期终止损失，选择：

$$a_t^*=\arg\min_{a\in A_t}\;Q_0(a\mid h_t,S_t^{\mathrm{scope}}).$$

第一版 $Q_0$ 使用 provider 的 scope posterior、failure cost 和 endpoint prior；不能读取当前分子的未选 provider 输出。这个动作对应 primary E2a，回答“工具适配”这一层能力。

### 5. 返回结果后：验证、互补、拒答或继续

定义当前证据 $E_t$ 下的停止损失：

$$R_{\mathrm{stop}}(E_t)=\min\left\{\rho,\;1-\max_yP(y\mid E_t)\right\},$$

其中 $\rho$ 是拒答成本。对候选 provider $b$，在最多再调用一次的 extension 中计算：

$$Q_1(b\mid E_t)=\kappa_b+\sum_{o\in\{0,1,\bot\}}P(o\mid E_t,b)R_{\mathrm{stop}}(E_t\cup\{(b,o)\}).$$

动作是：

$$u_t^*=\arg\min\left\{R_{\mathrm{stop}}(E_t),\;\min_{b\notin C_t}Q_1(b\mid E_t)\right\}.$$

更长视界不额外训练一个黑盒策略，而是使用有限视界递归：

$$V_0(E)=R_{\mathrm{stop}}(E),\qquad Q_h(a\mid E)=\kappa_a+\sum_oP(o\mid E,a)V_{h-1}(E\cup\{(a,o)\}),$$

$$V_h(E)=\min\left\{R_{\mathrm{stop}}(E),\min_{a\notin C(E)}Q_h(a\mid E)\right\}.$$

第一版只实现 $h\leq1$ 的 exact enumeration；$h>1$ 暂不进入主实验。因此“最合适”被定义为：在当前任务、当前证据和调用成本下，使期望最终损失最低的 provider。

- 直接选择停止项，对应直接回答或拒答；
- 选择某个 $b$ 且它的预期输出主要用于确认当前答案时，记录为 **verification**；
- 选择某个 $b$ 且它的价值主要来自可能改变当前答案或减少不确定性时，记录为 **complementary evidence**。

验证和互补不是两个任意的分类器标签；它们是同一个 value-of-information planner 对同一个 provider call 的两种可审计解释。主指标看最终 utility，不看标签数量。

### 6. 延迟更新

provider 终止时记录 output、status 和 pending event；真实 correctness 只在 release tick $\tau_t$ 到达后更新 scope state：

$$S_{t+1}^{\mathrm{scope}}=U\left(S_t^{\mathrm{scope}},x_t,e_t,a_t,r_t,\tau_t\right).$$

单个 selected outcome 可以更新 provider scope 和 runtime hazard。联合 error mode 的参数只有在预登记的 paired audit 同时获得两个 provider 输出时才更新；普通一次调用不能凭空学习 provider pair dependence。paired audit 的调用成本、propensity、覆盖率和 delayed release 必须单独记账。

这形成两个时间尺度：每个已 release 的单工具结果都能改善工作范围；只有付出额外调用成本的 paired audit 才能改善工具之间的关系模型。这样不会把静态 full-panel cache 偷换成在线 paired feedback。

完整运行状态记为 $S_t=(L_t,E_t,b_t,\mathrm{clock}_t)$：$L_t$ 是跨任务长期状态，$E_t$ 是当前任务证据，$b_t$ 是剩余调用预算，`clock` 保存 pending/release 事件。每条 decision receipt 都要保存这四部分的可恢复内容或 hash。

### 7. 训练和运行流程

1. **Fit-only warm start**：在每个训练 fold 中，用完整 provider panel 和 truth 拟合 scope、endpoint prior 和 joint evidence model；失败状态保留为 $\bot$。这里的“常识”具体化为 fit-only endpoint prior 和可审计的 domain constraints，不使用不可复现的自由文本判断。
2. **Calibration**：只用 fit/validation 区校准 $P(y\mid E_t)$，固定 calibration 后再进入 evaluation；不使用 evaluation 选择阈值或 latent mode 数量。
3. **Primary replay**：一次调用，只运行 $Q_0$；反馈按 $D\in\{0,1,4\}$ release，比较 Frozen、Matched Online、MIRA scope update。
4. **Sequential extension**：固定最多两次调用，运行 $R_{\mathrm{stop}}$ 和 $Q_1$；比较 Independent Evidence、Joint Evidence、Frozen Joint、matched fixed cascade 和 Best Fixed。
5. **Controlled adaptation**：在 provider version、可靠性或输入分布发生预登记变化的 stress 中，比较 online 与 no-update；没有变化的 delay replay 不能单独支撑 nonstationary claim。
6. **Agent interface**：将结构化结果输出为 `answer / verify(provider) / complement(provider) / refuse / continue`，连同理由、证据来源、成本和 pending 状态交给主 agent；主 agent 不能读取未选 provider 的当前输出。

### 8. 最小可实现模块

第一版代码按以下边界拆分：

| 模块 | 输入 | 输出 | 在线是否更新 |
|---|---|---|---|
| `ScopeAdapter` | $h_t$、$S_t^{\mathrm{scope}}$ | provider correctness/failure posterior | release 后更新 |
| `JointEvidence` | $h_t$、$E_t$、scope state | $P(y\mid E_t)$、候选输出分布 | paired audit 后更新 |
| `VOIPlanner` | posterior、候选菜单、$\rho$、$\kappa$ | answer/refuse/call + relation audit | 不直接改参数 |
| `DelayedLedger` | terminal event、release clock | pending/released event | 事件级更新 |
| `AgentAdapter` | planner action、provider result | 结构化工具调用轨迹 | 记录，不偷看 |

这五个模块先用 CPU replay 验证状态转移、exact enumeration、read-set、failure/unknown 和恢复一致性；通过后再提交单条 A800 任务。
