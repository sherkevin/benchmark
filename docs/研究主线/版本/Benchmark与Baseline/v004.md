## 当前投稿切片（规范范围）

本稿的 primary slice 是：公开 TDC BBB truth、四个 checkpoint-bound fresh providers、157 个 scaffold-disjoint confirmation molecules、一次调用、selected-only delayed feedback、$D\in\{0,1,4\}$，以及预登记 evaluator-side controlled correctness drift。Stage-B gate v3 只对这一切片给出 `PASS_FOR_DECLARED_ONE_CALL_DYNAMIC_SCOPE`。

33-provider Task36 面板是 development replay 和方法诊断，不是当前 paper 的 fresh confirmation 菜单。hERG、AMES、post-call verifier/refusal、自然 lifecycle drift 和完整 33-provider model-fresh 保留为 extension，不作为本稿未完成的主结果。

当前 fresh baseline 表中的 evaluator-only 控制统一称 **Retrospective Best Fixed**：它在 confirmation truth 上选择一个固定 provider，不是逐分子 Oracle，也不参与可部署排序。论文主结果使用 Random、Best Fixed、Frozen、Matched Online-SGD、Greedy LinUCB、BayesianRouter 和 MIRA-Context；PILOT、GraphRouter、Direct Predictor、Evidence/Refusal 只保留为 audit-only 或 out-of-scope，并需在 baseline contract 中记录原因。

## Benchmark 由两层组成

### 三种状态要分开

- **已确认约束**：本项目的唯一主 benchmark 是“公共 TDC truth + Task36 provider routing protocol”。公共 truth 负责答案语义和可追溯性；Task36 负责具体 provider、selected-only 反馈、延迟和失败事件。选择前不能读未选输出；每个实验保存可恢复的逐事件日志。
- **开发层候选**：TDC BBB 与 Task36 的 33-provider 菜单用于 development replay；当前投稿 confirmation 只使用四个 fresh providers。TDC AMES 和 hERG 只有在端点语义、覆盖和 provider lineage 审计通过后，才能进入后续扩展。
- **当前投稿已确认**：BBB 采用 P-C1，canonical conflict group 整体排除并保留原始收据；四个 fresh provider checkpoint、157 个 scaffold-disjoint confirmation molecules 和 release contract 已冻结，natural/stress receipts 均通过 contract/replay verification。
- **后续待审计**：provider arrival/version migration、hERG/AMES、post-call verifier/refusal 和完整 33-provider model-fresh 不进入当前投稿切片，另建 extension 合同。

本收敛把 ADR-0021 的多端点目标拆成阶段：BBB 四-provider fresh slice 是当前投稿主结果；hERG 和 AMES 只有在各自端点语义、覆盖、冲突和 provider lineage 资格通过后，才进入后续 evaluation 或 confirmation。

这里的 routing protocol 是基于公开 truth 和实际 provider 输出构建的项目评测协议，不把它称作已有社区 benchmark。LLMRouterBench 和 ASlib SAT12-ALL 不再属于本项目的主 benchmark；如果后续需要证明跨任务迁移，只能作为单独的外部 transfer/appendix 实验，不能和医药主结果混成一张主表。

### Truth layer：公共数据和固定切分

当前开发 truth 使用 TDC ADMET 的 BBB；AMES 的官方 archive 虽已完成版本和切分审计，但仍要等端点语义、覆盖、冲突和 provider lineage 资格通过后，才能进入最终多端点 evaluation 或 confirmation。已冻结的官方 Group archive SHA-256 是 `bd0005246cb6f1672333c28ad202112a8bf071ab65d847848715030308faf1f1`。审计得到：BBB `train_val/test` 为 1,624/406 行、1,581/394 unique；AMES 为 5,821/1,457 行、5,802/1,453 unique。两端点的官方切分 canonical 和非手性 Bemis--Murcko scaffold 均不交叉。

BBB 仍有 10 个 canonical 冲突组（`train_val` 8、`test` 2），同一 canonical 同时出现 0 和 1。按生效决议 `docs/决议/0005-BBB冲突样本采用P-C1整体排除.md`，主 development/confirmation manifest 整体排除 conflict group，保留原始冲突收据，并同时报告 raw 与 cleaned molecule-level 分母。当前 722 行 development manifest 没有新增删除，是因为历史 unresolved 过滤已经移除了这些行；这不等于原始 TDC 无冲突。

旧 722 条 development panel 与官方 BBB test 有 147 条严格 canonical、235 条 scaffold 重叠。因而旧开发结果不能直接使用官方 test 作 untouched confirmation。方法冻结后，confirmation 至少使用 molecule-disjoint 候选；若声称结构独立，使用审计剩余的 scaffold-disjoint 候选并重新生成 provider outputs。

### Provider layer：具体工具菜单

每个 provider 记录源码 commit、checkpoint hash、端点、阈值、训练来源、运行环境、失败语义、原始输出和生成时间。Task36 的 730×33 BBB 缓存用于 development replay 和压力测试；它不是公认社区 benchmark，也不把 24 个 B3clf 变体当成 24 个独立模型家族。

provider 训练成员审计目前把资格分成 lineage-aware 等级：GraphB3 为 G3，ADMET-AI/DeepPurpose/LGBM-BBB/24 个 B3clf 为 G2，FP-ADMET/ADMETlab 为 G1。正式 model-fresh 结果前，要么在公开 train split 重新拟合并绑定 checkpoint，要么把 lineage 限制写入结论。

## 统一任务合同

每题输入是 $x_t,e_t,A_t$ 和已释放历史 $H_t$。选择前不能读取当前真值、任何未选 provider 输出或当前题目的完整输出面板；调用结束只释放被选 provider 的状态、预测和 correctness；反馈按 delay 释放。失败、缺失和未知真值单独记账，不把 unknown 自动改成 0 或 1。

每次 run 保存逐事件 JSONL：输入 hash、菜单、动作、可见历史、释放时刻、provider 输出、状态、reward、更新耗时和错误。方法冻结后才打开 confirmation；confirmation 的标签不能用于选 epoch、调阈值或修改菜单。

## Baseline 集合

| 角色 | baseline | 作用 |
|---|---|---|
| 下界 | Random provider | 检查任务是否比盲选有信号 |
| 强固定 | fit-only Best Fixed | 只用训练区完整标签选一个固定 provider |
| 评估器控制 | Retrospective Best Fixed | confirmation 上选定的固定 provider；不可部署，不是逐分子 Oracle |
| 静态路由 | Frozen static selector | 检查表示和静态映射能力 |
| 匹配在线 | Online SGD、Replay SGD | 分离普通持续学习和回放的贡献 |
| 现代在线 | Greedy LinUCB、PILOT-adapted、BayesianRouter-adapted | 代表近期在线/先验 router 思路；当前 development 均保留为负或不足结果 |
| 现代静态 | GraphRouter（实现可审计后） | 检验图结构静态路由；不得用 confirmation 选 epoch |
| 验证控制 | 固定 confidence threshold、随机同成本 escalation | 检查调用后 verifier 是否真的有用 |
| 任务控制 | direct-property predictor | 检查收益是否只是恢复端点真值，而非学习 provider 差异 |

每个 baseline 都固定论文版本、源码 commit、许可证、适配差异、初始化权限、特征、反馈延迟、预算和随机种子。没有可审计实现的项目只能作为论文行为审计，不能写成已运行 baseline。

## 实验矩阵

| 阶段 | 要回答的问题 | 关键对照 | 通过条件/产物 |
|---|---|---|---|
| Gate 0 | truth、重复、冲突、训练成员和 confirmation 是否合格 | 独立脚本与清单 | 资格报告；不过不开放 confirmation |
| 静态开发 | 分子表示是否能超过固定赢家 | Best Fixed、Frozen、Retrospective Best Fixed | OOF accuracy、fold 明细、失败计数 |
| 在线开发 | 延迟 selected-only 反馈能否改善后续选择 | SGD、Replay、LinUCB、PILOT、BayesianRouter | delay 0/1/4，累计错误、反馈数、时间、内存 |
| 安全切换诊断 | 动态模块的损失来自错误切换还是工具本身失败 | fit-only Best Fixed、Frozen、MIRA-FamilyGuard | harmed/rescued、switch-away、runtime failure、provider/family 分解、scaffold-cluster CI |
| 菜单/家族 | 结果是否被相关 provider 重复放大 | 33-provider 与 family-balanced 菜单 | family macro、provider exposure、敏感性报告 |
| 调用后验证 | confidence 是否能在相同成本下减少错误 | fixed threshold、random matched、always/never | accuracy、平均调用数、fallback rate、风险覆盖 |
| 独立确认（当前投稿 E6） | 四-provider fresh slice 上的声明机制是否成立 | Random、Best Fixed、Frozen、Matched SGD、LinUCB、BayesianRouter、MIRA-Context、Retrospective Best Fixed | 157 scaffold-disjoint molecules；自然 null 与 controlled drift 分开；不回流任何标签 |

主指标在开跑前固定为未来 episode correctness；同时报告累计 regret、相对 Best Fixed 的差值、延迟、更新 p50/p95、峰值内存、调用次数和失败率。按 endpoint 和 provider family 分开报告，不能只报 pooled accuracy。

## 当前实验边界

已经恢复的 fingerprint diagnostic、统一 online adapter、Greedy 全量 replay、PILOT/BayesianRouter/SGD development replay 和 confidence escalation 是开发证据，分别回答“任务难度”“实现时序”“现代近邻表现”和“调用后信号”。当前投稿的 fresh confirmation 已完成：自然 270 streams 上 MIRA-Context 与 Frozen 均为 89.81%；controlled correctness-drift stress 的 MIRA-Context 为 87.56%，Frozen 为 73.38%，提升 14.18 pp。前者是 null，后者是 evaluator-side 受控机制结果，不能写成 generic online gain 或自然漂移泛化。统一 development 汇总见 `task/task49-pharma-benchmark-baseline-freeze/development_master_table_v1/report.md`，Stage-B gate 见 `task/task49-pharma-benchmark-baseline-freeze/stage_b_scientific_submission_gate_v3/`。

在 Gate 0、provider checkpoint 绑定和方法冻结前，不追加新的 A800 训练。每个新实验先写 claim、最近邻 comparator、预算和 falsification condition，再写 config、原始 JSONL、恢复脚本和报告。

当前 baseline 成本账本为 `task/task49-pharma-benchmark-baseline-freeze/baseline_cost_budget_v1/table.json`
（`baseline_cost_budget_contract_v2`）。它把严格 raw receipt 的证据指针和成本字段放在同一张
机器表中：Matched/Frozen 指向 `full_v6/verification_v2.json`；Bayesian native-BT 行仍保留
自己的 native-prior receipt，另以 `provenance_repaired_v1/verification_v2.json` 作为
direct-prior raw-contract 审计证据。后者不能改名为 native prior，也不能把不同 likelihood
stratum 的数字混排。

2026-10-02 又修正了两条账本口径。Replay-SGD 的 selection/update p95 只统计
`replay_sgd_matched` 的 30 条 stream（`50,713.9/149,029.45 ns`），不再把同源回执中的
Frozen/Online 事件混入；机器表保存 source scope `30/90`。FamilyGuard 的 family macro
则改用运行配置声明的 `external_qualification.json` 做只读重聚合，旧 registry 导致的
`UNKNOWN` 归类只保留为历史审计现场。两项修正均不改变事件、task success 或方法角色，
也不允许跨 prior 或跨 registry 口径拼接排名。
