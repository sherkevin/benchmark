# 研究迭代规范：故事线先行，小批证据驱动

状态：Owner于2026-09-22明确的长期工作方式；研究对象与权限仍见 `目标.md` 和具名Owner裁定。本规范只规定怎样推进，不重新定义医药主线或预先宣布方法有效。

## 目标与优先级

最终目标是提高投稿成功的可能性；可执行目标是形成重要、原创、论证可靠、可复现且叙述清楚的论文，而不是追求实验数量、代码量或单个漂亮分数。不能承诺或虚构中稿概率。

每项工程、查证或实验必须说明：它消除哪条主张的哪一个疑问，会改变下一步什么决定。无关的工具扩量、重复验签和大系统开发不占当前主迭代资源；必要的泄漏、反馈和来源核验必须保留，但以影响本轮判断的最小范围为限。

## 五步闭环

| 步骤 | 要回答的问题 | 最小产物 | 进入下一步的条件 |
|---|---|---|---|
| 1 故事线 | 什么真实问题值得解决？已有解决方式留下什么缺口？为何与Agent有关？ | 一段问题—缺口—关键判断—预期价值 | 事实有来源；缺口若未证实明确标假设，不用模块堆砌代替问题 |
| 2 创新点 | 相比最接近的已发表方法，究竟新增什么？ | 一项核心候选贡献及其最近邻差异 | 区分新机制、资源和应用贡献；标准Bandit、共享表示或双层结构不自动算新颖 |
| 3 方法论 | 新机制怎样解决故事中的缺口？ | 输入→状态/估计→决策→反馈→更新→输出及必要假设 | 每个模块对应主张；信息权限、训练/推断、成本和Agent/选择器职责自洽 |
| 4 审查 | 最强反对意见是什么？什么结果会让我们改变判断？ | 主张—baseline—指标—消融—否定条件表 | 最近邻、泄漏、公平信息预算、数据资格与可实现性检查；明确Go/修订/阻塞 |
| 5 快速验证 | 这个特定机制是否有值得投入的实际信号？ | 小批真实数据、原始日志、配对对照与结果解释 | 按已登记协议执行；做出继续/修订/缩小主张/停止该构造/证据不足的决定 |

顺序是科学推理的顺序，不是要求每次等待所有基础设施全完工。查证、实验卡和实现准备可并行；新结果返回后明确回到哪个步骤，不能只说“继续调参”。

创新在实验前是候选，不是已证定理；方法允许被数据修正，故事也必须可被推翻。“确定”表示本轮固定可检验版本，不表示永远不改。

## 每批最小实验卡（沿用task，不新增长期日志）

每批开跑前在对应 `task/<任务>/` 中记录：故事版本、唯一主假设、机制、最接近的已发表baseline及具体实现、冻结的模型/快照/划分、特征与反馈白名单、样本规模、固定种子、算力/调用预算、主要指标、最小有意义改进及失败处置。缺项写未定，不凭聊天推测为已冻结。

基线要同时覆盖“有没有上下文价值”和“候选创新有没有额外价值”；只击败固定工具不证明新机制优于已有条件选择。全反馈监督方法与少反馈Bandit的信息量必须分栏，不制造假公平。

快速阶段优先复用已核缓存和最小实现；同一输入划分与反馈条件下比最接近方法及必要消融。缩小计算规模不能靠挑容易样本、挑赢家工具、丢失失败任务或反复查看最终测试集。

候选模块只保留直接影响主假设的部分。先固定主Agent比较选择器，再固定选择器比较Agent训练，最后验证组合；该拆分是归因顺序，不取消主Agent SFT/RL工作。

## 结果如何影响下一轮

| 观察 | 可以支持的结论 | 下一步 |
|---|---|---|
| 优于合法基线，关键消融使增益消失 | 对该批/该条件下的机制假设提供支持 | 检查重复种子、样本/家族边界，冻结方法后做独立确认 |
| 比固定工具好，与已有条件选择无差别 | 条件选择有价值，新增机制未有证据 | 回步骤2，收窄或撤回新算法贡献，不包装标准方法 |
| 候选与基线都不能利用上下文 | 当前数据/表示/反馈下无充分可学证据 | 查表示、样本量、信息语义与资格；不直接放大LLM或GPU |
| 有提升但消融仍同样好 | 方法整体有信号，原解释未成立 | 回步骤2/3核清真正来源，不能称预设机制获证 |
| 正负变化混合、区间很宽 | 证据不足，非成功也非整个方向被否定 | 判断补样本是否有信息价值；报告不确定性 |
| 增益来自污染、额外反馈或错误分母 | 比较不成立 | 修协议/实现，保留旧结果，具名新版本重验 |

小批正结果不是“证明整篇故事正确”或“保证中稿”。探索阶段允许迭代，但最终主张需要未用于选机制或调参的确认数据。已有全表被用于主线选择须留痕；不得将同一已看数据重新命名为未触碰的确认集。

负结果先查实现与协议，再查假设；不能以“结果不好”自动换benchmark、指标、工具池或种子。只有明确的新科学理由才创建新任务/协议版本；原始失败与修改理由必须保留。

## 投稿视角与一手依据

2026-09-22本轮核读AAMAS 2027官方Main Track及Reviewer Guidelines。官方评价包括原创性、重要性、可靠性、可复现性、清晰度、会议相关性、表达及对已有工作的理解；技术内容严重不足或不在会议范围内存在desk-reject风险，核心贡献不能依赖审稿人必读附录。
