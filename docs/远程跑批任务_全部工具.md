# 远程跑批任务：全部工具的安装与批量预测

这份文档写给在远程 Linux 服务器上执行跑批的同事。读完这份文档不需要看别的资料。

## 你要做的事

把下面列的工具**全部**装好，拿我们给的一批分子（730 个）喂给每个工具，把结果存成文件带回来。

之前发过一批只含 10 个难装工具的清单。这次范围扩大了：**不是只装那 10 个，是要装全部**。我们本地已经装好了一批，但那是在苹果电脑上装的，跟远程不是一回事——远程要从头到尾自己装一遍，这样整套结果在一台机器上就能完整复现，不靠我们这边装好的任何东西。

## 最重要的三条规矩

**一，每个工具一个独立环境，不许共用。**

这些工具互相之间依赖冲突得厉害——一个要老版本的 numpy、另一个要新版本的 TensorFlow，装到一个环境里会互相顶坏。所以**每个工具单独建一个虚拟环境**（conda 或 venv 都行），一个工具一个，互不干扰。宁可多建几个环境，也不要图省事共用。

**二，每一次运行的结果都要留下来，不许覆盖。**

同一个工具跑两遍，两遍的结果分开存，都留着。我们要靠对比两遍来判断这个工具的输出稳不稳定。文件名里带个标记区分（比如加 run1、run2），别用同一个文件名覆盖。

**三，装不上就如实记录，不要硬修。**

某个工具装不起来，把完整的报错信息抄下来、记清楚卡在哪一步，然后跳过它装下一个。**装不上这件事本身是有用的信息**，不要为了让它跑起来去改它的代码或者编一个结果。一个工具花两小时还装不上就放弃，记下原因。

## 输入

分子清单文件 `molecule_pool.json` 会单独给你，730 个分子，每个是一条化学结构（SMILES 格式，一种用文字表示分子结构的写法）。每个工具都跑这一批。

## 输出

每个工具一份结果文件，CSV 格式，一行一个分子。至少包含这几列：分子编号、输入的分子结构、工具给出的预测值。多跑一遍就多存一份。

## 工具清单（38 个要装的）

每个工具给出：代码在哪、怎么装、我们在苹果电脑上验证过它装得好不好、它测什么。

### 第一组：本地已验证装得好的（照这个方法装就行）

这一组我们已经在苹果电脑上装通并跑出了数，安装方法是验证过的。

**ADMET-AI 1.4.0** — `pip install admet-ai==1.4.0`。一个工具测 49 个性质。

**ADMET-AI 2.0.1** — `pip install admet-ai==2.0.1`。和上一个同一家，是不同版本，装成两个独立环境。

**B3clf** — 克隆 https://github.com/theochem/B3clf 。注意它的模型是用老版本 scikit-learn（0.24.2）存的，要装 1.0.1 来读（这两个版本读出来的数我们验证过是一样的）。许可证 MIT。

**DeePurpose** — `pip install DeepPurpose`。测药物和靶点结合。

**graphB3** — 克隆 https://github.com/dhanjal-lab/graphB3 （血脑屏障专用，图神经网络）。

**LGBM-BBB** — 克隆 https://github.com/Rajnishphe/LGBM-BBB 。注意：作者手写的特征名单和模型权重里记的顺序对不上，我们已经验证过要按权重自报的顺序来。

**SolTranNet 1.0.0** — `pip install soltrannet==1.0.0`。测溶解度。

**FPADMET** — 克隆 https://gitlab.com/vishsoft/fpadmet 。需要装 R 语言和 Java，R 的四个包可能要源码编译。

**Toxtree** — https://toxtree.sourceforge.net/ 下载压缩包。需要 Java，命令行批量跑用 `-n`（不开图形界面）。注意它的输出文件只认 .txt 后缀。

**DILI Predictor** — `pip install dilipred`。测药物性肝损伤。注意它内部用多进程，得从脚本文件跑、不能从标准输入喂。

### 第二组：本地装不上、靠远程 Linux 装

这一组在苹果电脑上装不起来，原因写在每个后面。远程是普通 Linux 服务器的话应该能装。

**OPERA** — https://github.com/kmansouri/OPERA 。装时要联网下载 MATLAB 运行库，装完完全离线。MIT。

**EPA TEST** — https://github.com/USEPA/test-app 。Java。官方标注当前版本有已知问题。

**VEGA QSAR** — https://www.vegahub.eu/download/vega-qsar-download/ 。需要 Java 17+，第一次运行必须联网。GPL 3。

**TRIDENT** — https://github.com/StyrbjornKall/TRIDENT 。主干模型权重在 HuggingFace 上，拿不到就用 Docker 镜像。MIT。

**CONCERTO** — https://github.com/bowang-lab/CONCERTO 。先确认它依赖的 GROVER 预训练权重能下载再动手。MIT。

**CypReact** — https://github.com/Le0nT1/CypReact 。Java + Maven 自行编译。

**CardioTox** — https://github.com/Abdulk084/CardioTox 。按仓库 environment.yml 建 conda 环境。

**BayeshERG** — https://github.com/GIST-CSBL/BayeshERG 。按 environment.yml 建环境。**注意权重只能研究用不能商用**（CC-BY-NC-4.0）。

**CYPlebrity** — https://github.com/molinfo-vienna/cyplebrity 。不在 PyPI，克隆后 conda 装。BSD-3。

**CYPstrate** — https://github.com/molinfo-vienna/cypstrate 。`pip install cypstrate` 即可，权重在包里。BSD-3。

### 第三组：单一用途的小工具（装起来最省事）

**XLogP3**、**JPlogP**、**KowWIN v4.11**、**SILICOS-IT logP** —— 测亲脂性（logP）。

**QupKake** — https://github.com/Shualdon/QupKake 。**Uni-pKa** — https://github.com/dptech-corp/Uni-pKa 。测酸解离常数 pKa。

**XenoSite** — 测代谢位点。**PKSmart 3.0.1** — 测清除率、分布容积、游离分数。

**SAI BBB Predictor v3.0.0** — 测中枢神经相关性质。**注意**：我们核实过它声明 12 个端点但实际只有 7 个训练过，别按 12 个算。

**SolPredictor** — 测溶解度。**QED、SA score、TPSA** — 这三个是 RDKit 自带的直算，装 RDKit 就有。

**DeePred-BBB**、**DeepB3**、**BBBper** —— 这三个是血脑屏障专用工具。注意 DeepB3 的权重被作者从仓库里删了、只有历史版本里有，BBBper 的网站目前打不开。**如果找不到就标"装不上"。**

### 四个接口工具（不用装，但要单独跑）

这四个不是装在本机的，是通过网络接口调用的，单独处理：

**ADMETlab 3.0**、**Deep-PK**、**OCHEM**、**ALOGPS 2.1**。

它们不用装，但要注意两点：一是有调用频率限制（ADMETlab 建议每秒不超过 5 次，SwissADME 禁止并发）；二是每次调用要把原始返回整份存下来，连时间戳一起存，这样将来服务端升级了我们有据可查。

## 装完怎么算装好

每个工具装好以后，先拿这三个分子试，确认它出数：

- 咖啡因：`CN1C=NC2=C1C(=O)N(C)C(=O)N2C`
- 地西泮（一种安眠药）：`CN1C(=O)CN=C(c2ccccc2)c2cc(Cl)ccc21`
- 蔗糖：`OC[C@H]1O[C@H](O[C@]2(CO)O[C@H](CO)[C@@H](O)[C@@H]2O)[C@H](O)[C@@H](O)[C@@H]1O`（2026-09-10 修正：此处先前写的是只有 12 个重原子的半个分子，现换为与 PubChem CID 5988 规范结构逐位一致的完整蔗糖，23 个重原子）

能出数、数的方向合理，再跑全部 730 个。

## 带回来什么

每个工具一个结果文件（CSV），加上一个说明文件，写清楚：装上了没有、装的什么版本、什么时候跑的、跑了几遍、装不上的话卡在哪一步的完整报错。

## 正式跑批派发（2026-09-10）

你们在《十个药物预测工具安装与批量预测准备进展》§9 里说，启动前还差三个值。现在三个都给齐，可以开工。

**1. 正式输入文件**：`data/tool_results/molecule_pool.csv`（仓库里就有，拉最新 master 即可）。730 行，顺序不要动。同目录下的 `molecule_pool.json` 是同一份内容的 JSON 版，以 CSV 为准。

**2. 列名**：ID 列是 `entity_id`，分子结构列是 `canonical_smiles`。

**3. 修正后的糖类 SMILES**：`OC[C@H]1O[C@H](O[C@]2(CO)O[C@H](CO)[C@@H](O)[C@@H]2O)[C@H](O)[C@@H](O)[C@@H]1O`。这是完整蔗糖，23 个重原子，与 PubChem CID 5988 的规范结构逐位一致（我们本地用 RDKit 规范化后比对过）。本文档上文「装完怎么算装好」一节里的旧写法是错的，只有半个分子，以本节为准。另外注意：本地早期探针文件里出现过一个叫 `sucrose_real` 的写法，它有一个手性中心画反了，是蔗糖的立体异构体，已作废，不要用。

输入到手后按下面顺序做，每步的产物都保留、不覆盖：

**任务一：绑定输入**。用你们控制层已有的输入冻结功能绑定上面这份 CSV，校验 730 行、ID 非空唯一、SMILES 非空，冻结哈希。绑定失败就停下报错了再来问，不要手工修输入文件。

**任务二：三分子冒烟**。咖啡因、地西泮、蔗糖（上面修正后的结构），对 5 个已装成工具的 42 个冻结端点（CYPstrate 18、TRIDENT 9、CypReact 9、CYPlebrity 5、BayeshERG 1）各跑一遍。冒烟只查输出可解析、数值有限、分类值合法，不拿生物学方向筛工具。

**任务三：双轮全量**。冒烟通过的工具对全部 730 个分子跑 `full-r1` 和 `full-r2` 两个独立进程、独立目录。两轮结果分别保留、逐端点比较，不取平均。非法 SMILES 不预筛，让它成为逐分子失败行。

**任务四：数值工具补跑**。资格验证已过的 8 个数值工具里，本地已有全量结果的不要重跑：`soltrannet_1_0_0`、`rdkit_tpsa`、`rdkit_qed`（见上一节的对照要求）。需要在远程跑 730 全量的是：`pksmart_3_0_1`、`silicos_it_filterit_ad480780`、`kowwin_1_68_epi_1_1_0`、`rdkit_sa_score`（本地没跑过这个端点）、`openadmet_cdf3e9f7`（只跑已冻结的端点；余下卡 Zenodo 限流的模型仓继续按退避重试，补不上就在报告里如实列缺口）。同样双轮、保留两轮。

**保持闭账、不要动的**：OPERA、CONCERTO、CardioTox、EPA TEST、VEGA 五个安装失败工具不要重试，除非我们另批预算；rowan、qupkake、unipka、xenosite、solpredictor 五个数值工具的未过资格原因已冻结在注册表里，也不要再投入时间。

**结果回传**：每工具一份 730 行宽表（行=分子、列=性质端点、值=工具原始输出，形状对齐 `data/tool_tables/` 里的表），加 verification.json 和 manifest.json。和本地表有重叠的端点，逐位对一遍，不一致的分子列成清单带回来——这些不一致正是我们要的考题素材，不要为了对齐而改数。

## 补充工具安装派发（2026-09-10 第二批）

这 12 个工具是新一轮调研找到的，目标是补齐 9 个凑不够两个独立来源的性质族。每个工具我们都核过四件事：仓库活着、许可证允许学术使用、训练好的模型制品能直接拿到、能批量无界面跑。权重位置和已核事实写在每条里。

老规矩不变：每个工具独立环境，安装累计 2 小时封顶，装不上就如实闭账留证据、不硬修；装完先跑三分子冒烟（咖啡因、地西泮、蔗糖，结构见上文修正版），过了再双轮全量 730，结果形状对齐 `data/tool_tables/`。

**1. chemperium** — https://github.com/mrodobbe/chemperium ，MIT。补：沸点、蒸气压。训练好的 .keras 模型和 scaler 随仓库（在 test_data/ 下，22MB 级）。Keras 版本按仓库 pyproject 钉死。

**2. AI-ThermPpt** — https://github.com/bounac80/AI-ThermPpt ，GPL-3.0。补：沸点。成品 joblib 模型在 example/ 目录（04_modele_final_NBP 是沸点）。joblib 模型对 scikit-learn 版本敏感，按仓库要求钉版本。

**3. GRAPPA** — https://github.com/marco-hoffmann/GRAPPA ，MIT。补：蒸气压。权重 models/GRAPPA_state_dict.pt 随仓库。

**4. UManSysProp** — https://github.com/loftytopping/UmanSysProp_public ，GPL-3.0。补：蒸气压。规则模型，没有权重文件，直接 Python API 调。

**5. PODUAM** — https://github.com/kejbo/PODUAM ，MIT。补：慢性毒/最大耐受剂量（预测非癌 POD，即剂量-效应起点），附带生殖/发育毒性子模型。final_models/ 里有训练好的 pkl（18-23MB）。官方跑过 10 万级分子批量。

**6. MolGpKa** — https://github.com/Xundrug/MolGpKa ，MIT。补：pKa（质子化态的核心量）。权重 models/weight_acid.pth、weight_base.pth 随仓库。

**7. pkasolver** — https://github.com/mayrf/pkasolver ，MIT。补：pKa。注意：官方只公开了不带 Epik 迁移学习的 lite 权重（在 trained_model_without_epik/），报告里如实标注证据等级。

**8. dimorphite_dl** — https://github.com/durrantlab/dimorphite_dl ，Apache-2.0。补：质子化态/互变异构（按指定 pH 直接输出质子化形式）。**冒烟时先核实：仓库自带的参数能不能直接推理。如果需要我们自己训练模型才算出数，按失败闭账，不要训练。**

**9. FAME3R** — https://github.com/molinfo-vienna/FAME3R ，代码 MIT。补：UGT 底物（I/II 相代谢位点，含葡萄糖醛酸化）。权重在 Zenodo（records/17294556），权重本身标注"非商业研究免费"——和 BayeshERG 一样处理：只用于内部评估，不转发权重文件。

**10. BioTransformer 3.0** — https://github.com/Wishartlab-openscience/Biotransformer ，LGPL-2.1（商用要作者单独许可，我们内部研究可用）。补：UGT 底物（phaseII 代谢产物）。**优先用官方成品 jar**（biotransformer.ca/download），不要从源码 Maven 构建——EPA TEST 就是死在 Maven 依赖上。

**11. Mitochondrial-Toxicity** — https://github.com/PharminfoVienna/Mitochondrial-Toxicity ，MIT。补：线粒体毒。仓库带 5 个训练好的神经网络（Model_best.hdf5）和一个梯度提升模型 zip。**风险：仓库里有 KNIME 工作流文件（.knwf），特征化步骤可能依赖 KNIME。装的时候先确认能不能纯命令行无界面跑通；KNIME 必须用它自己的无界面批处理模式，跑不通就如实闭账。**

**12. Fraunhofer PLD** — https://github.com/Fraunhofer-ITMP/PLD ，MIT。补：磷脂毒。models/final_model_PLD_XGBoost.pkl 随仓库。注意：配套论文目前只是 bioRxiv 预印本，期刊版在排印，报告里标注这个证据等级。

**另外两件不用装的：**

**13. DeepPurpose 加端点**：DeepPurpose 已在本地跑通（血脑屏障）。它的官方预训练 DTI 模型（DeepPurpose.models.model_pretrained 里可下载的清单）能预测药物-靶点结合亲和力，输入只要 SMILES + 固定靶点序列，不需要蛋白结构。任务：枚举官方可下载的预训练 DTI 模型清单并冻结，靶点序列集合从模型的官方示例里取并冻结，然后对 730 个分子双轮跑。**靶点序列不确定就报回来，不要自己编。**

**14. Deep-PK 接口跑 730**：接口工具，不用装。官方有 API 文档，提交后返回 job_id 取结果；注意我们 9 月初实测取结果接口连续返回过 500，先三分子冒烟确认服务恢复了再跑全量。原始响应整份存档带时间戳。

**15. OpenADMET 补模型仓**：余下 7 个卡在 Zenodo 限流的模型仓继续按退避重试补齐，补不上就在报告里如实列缺口。

这批装完后，9 个缺口族预计能补上 6 个（熔点/沸点、慢性毒、蒸气压、质子化态、UGT 底物、生殖/线粒体/磷脂毒），加上 DeepPurpose 的靶点亲和力共 7 个；皮肤通透、CNS 通透、熔点三族调研没找到合格工具，先挂账。

## 一、先改一处判据，改完才能跑

**问题**：冒烟这道闸门比正式跑批本身更严。代码要求三个探针分子在每个端点上全部成功（`src/probe_headless/drug_prediction_campaign.py:718` 与 `:549`），而正式跑 730 个分子时只要求记录失败、并不要求全部成功。结果是 CypReact 被永久挡住——它的解析器不认蔗糖，九个端点全判失败，即使它对另外 728 个分子都能正常出数。

**改成端点级判据**：

1. 每个端点至少有一个探针分子出数，且所有出了的值都合法（数值有限、分类值在合法集合内）。
2. 某个探针分子在某端点出不来数，记录该分子该端点失败，**不阻塞**进入全量。
3. 某个端点在全部探针分子上都没出数，这个端点仍然拦下——说明该端点根本不工作。
4. 全部端点都没出数，整个工具拦下。

**要补的测试**：

- 一个探针分子失败、其余出数，工具仍能进入 `full-r1`。
- 某端点在三个探针分子上全部无值，该工具被拦下。
- 现有 20 项批次测试与 32 项运行时核验测试不回归。

**验收判据**：上面三项测试通过，并在真实批次上复现一次「单分子失败仍可进全量」。这一步由你们实现，因为判据改得对不对必须拿真实批次验证，而真实批次和已装工具都在你们机器上。
