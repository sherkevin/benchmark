# EvoBrowseComp · 用"活网合成"做免污染的演化式基准

> **原文**：EvoBrowseComp: Benchmarking Search Agents on Evolving Knowledge
> **作者**：Yunhan Wang, Jiaan Wang, Lianzhe Huang, Xianfeng Zeng, Fandong Meng（腾讯微信 AI）
> **出处**：arXiv:2606.13120，2026-06-11，14 页，under review
> **阅读方式**：基于完整摘要与元数据

## 0. 一句话

**它和我们解决同一个问题（防污染），但走的是完全相反的路**——

| | EvoBrowseComp | 我们 |
|---|---|---|
| 思路 | **让题目一直变新**（定期自动重新合成） | **让题面对不上预训练语料**（标识符匿名化） |
| 靠什么保证不污染 | 时效性：题目比模型训练截止时间更新 | 结构性：匿名标签在任何语料里都无对应 |
| 会不会失效 | 不会，但**需要持续维护**（要一直重新合成） | 不会，且**一次性有效**（不需维护） |
| 代价 | 依赖活网可达、需要合成管线常驻运行 | 失去真实标识符的可读性（人看不出这是哪个分子） |

## 2. 它对现有基准的批评（这段直接可引用）

摘要原文批评 BrowseComp 这类基准：

> `rely on static knowledge, making them vulnerable to test-set contamination and parametric memorization. Consequently, models can achieve high scores through fact recall rather than genuine retrieval, obscuring true browsing competence via reasoning shortcuts.`
>
> （依赖静态知识，因而易受测试集污染与参数化记忆影响。结果是**模型可以靠事实回忆而非真正检索拿到高分**，用推理捷径掩盖了真实的浏览能力。）

**对我们的意义**：这段话把"答案可被记住"和"能力被高估"的因果链说清楚了。我们的匿名化设计正是切断这条链——匿名标签无法被"回忆"出来。

---

## 3. 核心机制：三 agent 协作合成

| Agent | 职责 |
|---|---|
| **QA synthesis agent** | 从活网检索新鲜知识，合成问答对 |
| **information filtering agent** | 按**可信度与流行度**过滤检索到的知识，**堵住参数化捷径**（太流行的知识模型可能已记住，要剔掉） |
| **high-level guidance agent** | 把问题**形式化成推理图（reasoning graphs）**，减少逻辑冗余与捷径 |

**第二个 agent 的思路很聪明**：不只是"用新知识"，而是**主动剔除太出名的知识**——因为出名的东西模型很可能背过。

**第三个 agent 与我们相关**：它用"推理图"来保证题目没有捷径。我们的格位切分 + 歧义格剔除起的是同一作用（保证答案唯一且必须走完流程才能得到）。

## 5. 对我方：可借 / 可打点

### 可借（一条重要）

**"按流行度过滤"这个动作我们没有做，但应该做。**

我们的题目取自真实库（92,153 实体），其中有些分子/晶体是**教科书级别的明星分子**（如阿司匹林、青霉素）。虽然我们把标识符匿名化了，但如果某题的约束条件（分子量区间 + 溶解度区间 + 元素计数）**只可能对应某个著名分子**，模型仍可能凭化学常识猜出来，绕过检索。

**建议自查**：抽查 gt 分子里有多少是"著名分子"，以及其约束组合是否具有唯一可推性。这与待办第 14 项（可蒙对概率）是同一族问题。

### 可打点（一条，对我们有利）

**它的方案需要持续维护，我们的不需要。** 这是我们相对它的一个实质优势，可写进对比文档：

- 演化式基准（EvoBrowseComp）：防污染有效期取决于"合成管线是否还在跑"；
- 匿名化基准（我们）：防污染是**结构性**的，题目冻结后仍然有效。

代价也要如实说明：我们失去了标识符的可读性，人工审题时看不出"这是哪个分子"，只能靠性质数值判断。
