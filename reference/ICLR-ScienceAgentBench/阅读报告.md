# ScienceAgentBench 阅读报告（ICLR 2025）

> **一句话**：从 44 篇同行评审论文反构造 102 个科学任务，每题由 9 位领域专家逐题验证，agent 要交付一个可执行程序并满足该题的判据——最强 agent 只解出约三成。
> **为什么对我们重要**：它是"科学发现 agent benchmark"的直接前辈，它的 **9 专家逐题验证**和 **rubric 部分分**是我们 query 专家背书和 checkpoint 部分分的最强先例。

## 二、核心做法：一道题怎么造出来

**步骤**：论文 → 提取任务 → 专家验证 → 写判据 → 写 rubric → 定稿。

1. **从论文提取任务**：从 44 篇同行评审论文中提取 102 个数据驱动的科学任务（生物信息 32 题、计算化学 26 题、地理信息 22 题、心理与认知神经 22 题）；
2. **9 位领域专家逐题验证**：每位专家检查任务的科学合理性、数据可获得性、判据可执行性；按反馈修订了 41 条 rubric；
3. **写判据**：每题在标注阶段就把"成功判据"实现成一个可执行的评测程序（不是自然语言描述）；
4. **写 rubric**：每题手写 step-by-step 打分表，给部分分——因为"所有步骤都对但输出格式错，终态判分会给 0"太严苛；
5. **定稿**：102 题全部通过专家验证后定稿。

**一道题的完整内容**：

| 组成 | 说明 | 类比 |
|---|---|---|
| 任务指令 | 从论文提取的自然语言描述 | "复现 Figure 3 的分析" |
| 数据集信息 | 输入数据文件的路径和格式说明 | "数据在 data.csv，列 A 是时间，列 B 是浓度" |
| 标注参考程序 | 专家写的标准答案代码 | 老师的参考答案 |
| 成功判据 | 可执行的评测程序 | 自动阅卷脚本 |
| 逐步 rubric | step-by-step 打分表 | 部分分给分细则 |

**agent 要交付什么**：一个**可执行 Python 程序**（不是自然语言答案），程序要能在动态生成的 conda 环境里跑通并满足判据。

## 三、判分机制（对我们最有价值的部分）

| 指标 | 说明 | 硬/软 | 类比 |
|---|---|---|---|
| **VER** | 程序能无错执行且以正确文件名保存输出 | 硬（二元） | "程序能跑" |
| **SR** | 输出满足成功判据（测试集性能/预测匹配/可视化质量） | 硬（二元） | "跑出来的结果对" |
| **CBS** | 生成程序与标注程序的 CodeBERTScore 相似度（F1） | 软 | "代码写得像不像" |
| **Cost** | 完成一题的平均 API 花费（USD） | 硬 | "花了多少钱" |
| 图像评估 | 输出是图时用 GPT-4o judge 与真值图比对，采样 3 次取均值 | **软（LLM judge）** | "图画得像不像" |
| **Rubric** | 逐题手写 step-by-step 打分表，给部分分 | 半软 | "步骤对了多少" |

**两个必须记住的点**：
1. **它承认"只判终态太严苛"**——所以引入 rubric 部分分。这为我们"必须有中间 checkpoint 部分分"提供了来自 ICLR 2025 的正当性背书；
2. **但它的 rubric 和图像评估都掺了 LLM judge**——我们不用 LLM judge，改用可执行断言，这是明确的方法学优势。

## 五、对我们的意义

### 可借鉴

1. **"从论文反查任务"的数据来源路径**：他们从 44 篇论文反构造任务，我们从数据库反查分子——同一个"答案先于题目"的逻辑，且他们的做法已被 ICLR 2025 接受；
2. **专家验证的写法**：9 位专家 + 问卷 + 按反馈修订 41 条 rubric，这套"人工质量保证的可审计描述"必须照抄进我们的论文（审稿人非常吃这一套）；
3. **报 Cost**：直接抄；
4. **VER/SR 的分层**（先看"能不能跑"再看"跑对不对"）：映射到我们的 checkpoint 就是先判"产物是否存在且格式合法"（cp2/cp3），再判"数值是否与真值一致"（cp4/cp5/cp6）。

### 我们的优势

| 维度 | ScienceAgentBench | 我们 |
|---|---|---|
| 部分分来源 | 手写 rubric + LLM judge | **可执行 checkpoint 断言**（无 LLM judge） |
| 过程 | 只看最终程序与输出 | **看工具调用轨迹的拓扑序**（cp1-cp6 逐步打分） |
| "发现" | 复现已发表分析流水线 | **在匿名化宇宙里找出满足性质窗口的分子** |
| 抗污染 | 未处理（论文任务可能在训练集里） | **分子匿名化 + mock 数据库** |
| 交付物 | 可执行 Python 程序 | **结构化 JSON（ranked_candidates）+ 工具调用轨迹** |

## 六、query 写法分析（对我们 query 撰写的参考）

**ScienceAgentBench 的 query 长什么样**：

> "Generate a report of model evaluation results from a prediction, task instance, and the provided dataset. The report should include: (1) a bar chart comparing the accuracy of each model, (2) a table summarizing the precision, recall, and F1-score for each model, and (3) a brief discussion of which model performs best and why."

**特征**：
- **从论文提取**：任务直接来自已发表的同行评审论文，术语与论文一致；
- **交付物明确**：报告+图表+讨论，不是"给出答案"；
- **判据可执行**：每题在标注阶段就写好了判分脚本；
- **rubric 给部分分**：步骤对了多少给多少分，不是全对或全错。

**对我们的 query 撰写的启示**：
- 每道 case 的 query 必须写清楚"基于 xxx 论文/数据集"，术语与来源一致；
- 交付物要明确（"给出排序名单+性质数据"），不只是"给出答案"；
- 判据要可执行（我们的 checkpoint 已经做到了）；
- 部分分要有（我们的 checkpoint 也给部分分）。
