## 0. 一句话

让 agent 用 XML 标签显式声明自己每一步的认知类型（planning / explore / reflection / monitor），再对这些**元推理行为**给规则化、可程序验证的稠密奖励，与稀疏终态奖励一起用 critic-free 策略梯度优化；7B 模型在 ALFWorld 最难的未见任务分割上做到 83.6% 成功率。

## 1. 数据量

它是**算法论文**，不是 benchmark 论文，用的是现成 benchmark：

| 项 | 内容 |
|---|---|
| 环境 | **ALFWorld** + **ScienceWorld**（两个经典长程 embodied/科学文本环境） |
| 难度分层 | L0 / L1 用官方 split；**L2 是作者自己按任务类别重切的"完全未见任务类别"分割** |
| 模型 | Qwen-7B 主实验（另有更小规模对照） |
| 关键结果 | ALFWorld seen 91.4%、ScienceWorld seen 67.2%；ALFWorld Unseen-L2 83.6%（超过次优的 GiGPO）；L1 上 7B 模型超过 GPT-4o |

## 2. 数据集形态（这里更该问：奖励形态）

**四个元推理标签**（每个都是 XML 标签，动作单独放 `<action>`）：

| 标签 | 语义 | 何时用 |
|---|---|---|
| `<planning>` | 把任务分解为高层步骤，形成整体策略 | 任务开始或需要重规划时 |
| `<explore>` | 生成假设/选项以应对不确定或瓶颈 | 遇到卡点 |
| `<reflection>` | 复盘历史、分析错误、给出纠正动作 | 连续失败后 |
| `<monitor>` | 对照计划跟踪进度，确认动作仍对齐子目标 | 常规执行中 |

**规则化奖励（全部可程序判定，无 LLM judge）**：
- `r_planning`：若该 `<planning>` 步所在轨迹最终成功则给奖励；
- `r_explore`：**若当前动作指向一个新的物体或位置**（即真的探索了未访问状态）则给奖励——这是纯状态比对，完全 verifiable；
- `r_reflection`：若一个 `<reflection>` 步在连续失败之后**后接了一个纠正动作**则给奖励；
- `r_format`：输出不符合 `<tag>…<action>…</action>` 结构则罚 −λ_format；
- 总步级奖励 `r_t = r_t^MR + r_t^format`，再与稀疏终态奖励 `R(τ)` 合成。

**算法：GRPO-MR**。两级优势相加：
1. 轨迹级相对优势 `A_k^traj = (R(τ_k) − μ_R)/σ_R`；
2. **元推理级相对优势**：把 batch 内**同标签**的步骤分为一组，在组内做标准化 `A_t,tag^MR = (r_t,tag^MR − μ_tag)/σ_tag`。
   （即"explore 步只和 explore 步比"，避免不同认知类型之间的奖励尺度串扰。）

**冷启动**：先 SFT——收集成功轨迹（只有 obs-action 对）→ 用更强教师模型（GPT-4）**回标**元推理标签 → 微调。

## 3. "长"体现在哪

- ALFWorld / ScienceWorld 本身是多步 embodied 任务（论文举例："把两个钥匙链放进保险箱"，到第 7 步才出现关键错误）；
- 论文定义的"长程失败模式"是 **inefficient exploration**：只优化终态会让 agent 学会"能做对但推理路径混乱"，表现为**重复动作率高、错误恢复能力差**；
- 因此它衡量"长"的方式是**过程质量指标**：redundant action 减少、error recovery 增强。

## 4. 判分粒度

**过程级 + 终态级双层**，且过程级奖励是**规则可验证**的（这是标题里 "Verifiable" 的确切含义）。
⚠️ 但注意其"可验证"的强度：`r_explore` 是硬的（状态比对），`r_planning` / `r_reflection` 带有启发式（"最终成功了才给 planning 分"是延迟归因，"reflection 后接纠正动作"是模式匹配）。**它比 LLM judge 硬，但比我们的 checkpoint 断言软**。

## 5. 对我方：可借 / 可打点

**可借**

1. **这是我们"备用方案 → 完整方案"升级路径的现成模板**：benchmark（现成）+ 过程级 verifiable reward（新）+ GRPO 变体（新）= ICLR 2026 poster。**我们要做的 RL 部分可以完全对标它的结构**，而我们的优势是奖励来自 checkpoint DAG，比它的启发式更硬。
2. **同标签分组标准化（group-relative within cognitive type）**这个技巧可以直接搬到我们的 checkpoint 上：**同一 checkpoint 节点的步骤分为一组做优势标准化**，天然解决"不同 checkpoint 难度不同导致奖励尺度失衡"。这是一个我们独有的、更自然的分组依据（他们用认知标签，我们用 DAG 节点）。
3. **SFT 冷启动用教师模型回标标签**：我们可以用"金标准轨迹 + DAG 节点标注"生成 SFT 数据，且**标注是规则给的不是 LLM 给的**，比它更干净——这是一个明确的方法学卖点。
4. **过程质量指标**（重复动作率、错误恢复率）值得我们照抄进 analysis。

**可打点**

| 维度 | RLVMR | 我们 |
|---|---|---|
| 过程奖励来源 | agent 自己声明的认知标签（可能作假/凑格式） | **checkpoint 的中间产物与真值比对**（查产物不认动作，编造可被工具落地检查抓出） |
| 领域 | ALFWorld / ScienceWorld（玩具科学） | 真实材料/药物数据库 |
| checkpoint 依赖结构 | 无（标签无拓扑序） | DAG（依赖不可逆、不可跳） |
| 是否自带 benchmark | 否（用现成的） | **是**（这是我们相对它的增量） |

**关键洞察**：RLVMR 说明 ICLR 完全接受"过程级 verifiable reward"这个卖点——但**它缺一个原生支持过程奖励的 benchmark**，只能在 ALFWorld 上打补丁。我们的 benchmark 天生产出过程奖励，这就是"benchmark + RL 一体"叙事的立足点。
