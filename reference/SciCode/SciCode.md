# SciCode 怎么测（事前规划）

**一句话：科学家把一道科研编程题拆成十几个有依赖的子函数，每个子函数配一组可执行断言测试，逐个子问题判过没过。**

## 一个真实 case（Berendsen_thermostat，分子动力学）

- **主问题**：实现 Berendsen 恒温器（分子动力学模拟）。
- **拆解**：被科学家分解为 **12 个子问题**，按依赖链渐进——后一个函数要调用前面写好的函数。
- **每个子问题带**：`step_description_prompt`（子任务描述）、`function_header`（函数签名）、`test_cases`（若干条 `assert np.allclose(f(x), target)` 式可执行断言）。

## 判分机制（怎么算对）

- **子问题通过率**：某子问题的全部断言测试通过，该"卡点"才得分——这就是过程分。
- **主问题解决率**：全部子问题都通过才算解决主问题。
- 效果：SOTA 模型主问题解决率仅 14%–28.5%，但子问题通过率远高于此，**能精确定位"从第几步开始偏"**。
- 全程 hard：Python `assert`，无 LLM、无人工主观判定。

## 属于哪种考法

**单元测试即卡点**：由领域专家在出题时就把长任务拆成"带可执行测试的子问题链"，拆分粒度天然（依赖链）。
