# HarnessOpt-Bench · 评测 LLM 优化 harness 的能力

> **原文**：HarnessOpt-Bench: Evaluating LLMs at Harness Optimization
> **出处**：arXiv:2608.06301，2026-08-06
> **阅读方式**：基于完整摘要与元数据

## 0. 一句话
**它把 harness（提示、工具、控制流、记忆、编排代码）本身当作被优化对象**，并指出一个我们必须注意的事实：**agent 的能力不只取决于模型权重，也取决于包在它外面的 harness**。

## 1. 关键数字
| 项 | 内容 |
|---|---|
| 被测 | 5 个前沿 LLM 作为 optimizer |
| 下游任务 | 4 个 |
| 计分运行 | **111 次** |
| 评测设置 | 共享 coding harness 与各自的原生 harness 两种条件 |
| **关键发现 1** | **optimizer 模型之间的差异大于它们所用 coding harness 之间的差异** |
| **关键发现 2** | **原生 harness 并非一贯更优** |
| 关键发现 3 | 增益在不同任务与种子条件间**差异很大** |
| 保障机制 | 可信执行环境守住评测边界、计量目标 agent 资源用量、**保留候选版本以供审计** |

## 2. 机制与判分
归一化增益（相对种子 harness）在**保留的测试划分**上评分，该划分在搜索全程不可访问。**判定是硬的**。

## 3. 对我方
**可借（对我们的双 harness 设计是直接支撑）**：

**"agent 能力 = 模型 × harness"这个论点，正是我们设计 H1（自写）+ H2（商用 CLI）双 harness 矩阵的理由。** 本篇的两个发现给了我们具体的预期：

| 它的发现 | 对我们矩阵的含义 |
|---|---|
| optimizer 模型差异 > harness 差异 | 我们的 4 模型间差距应大于 H1/H2 间差距；**若反了，需怀疑 harness 实现有问题** |
| 原生 harness 并非一贯更优 | 不能假定 H2（商用 CLI）一定优于 H1（自写）；**两者互有胜负是正常的** |

**这两条可作为我们矩阵结果的合理性检验（sanity check）**，写进结果分析。

**可打点**：它优化的是 harness 本身（元任务），我们固定 harness 只换模型。归入"harness 方法论"类。
