## 0. 一句话

466 道需要多步推理 + 多模态 + 工具使用（浏览器、代码解释器、文件读取）的真实助理型问题，答案是唯一、事实性、可自动核验的短串；人类做到 92%，带插件的 GPT-4 只有 15%。

## 1. 数据量

| 量纲 | 数值 |
|---|---|
| 总题数 | **466** |
| 公开 developer set | **166** 题（含标注） |
| 保留答案的评测集 | **300** 题（只放题不放答案） |
| 难度层 | **3 层**（Level 1/2/3），按解题所需步数与工具数划分 |
| 人类基线 | **92%** 成功率 |
| GPT-4 + 插件 | **15%**（最简单一层也不超过 30%，Level 3 为 0%） |

## 2. 数据集形态

一条样本 = **（一句自然语言问题，一个唯一且事实性的短答案，标注者的元数据）**。

- **答案设计原则："唯一、事实性、简洁"** —— 所以判分可以是纯字符串/数值比对，**不需要 LLM judge**。这是 GAIA 最重要的工程决策。
- **附带元数据**（本项目应重点关注）：标注者记录了**需要哪些工具、走了哪些步、花了多长时间**。这就是一条"人类金标准轨迹"的雏形，但**只用于难度分层，不用于判分**。
- 部分题带附件（文件、音频、图片），构成多模态入口。

## 3. "长"体现在哪

**GAIA 用"标注者步数 + 工具数"作为"长"的代理指标**，并据此定义三层难度：

| 层级 | 步数 | 工具 |
|---|---|---|
| **Level 1** | ≤ 5 步 | 无工具或至多 1 个 |
| **Level 2** | 约 5–10 步 | 需组合多种工具 |
| **Level 3** | **任意长的动作序列** | 任意数量工具 + 需要接触真实世界 |

注意它明确说明分层不是纯机械按步数：一道 <10 步但需要复杂网页导航的题会被划为 Level 3 而非 2。

另一个设计原则值得记住：**Non-gameability**——"回答需要成功完成若干步骤"，即答案无法靠猜或靠单次检索命中。

## 4. 判分粒度

**纯终态、纯字符串/数值精确匹配**。无过程分、无部分分。
其代价论文自己也承认：Level 3 上所有系统都是 0%，**benchmark 完全无法区分"走对了 8 步的系统"和"第 1 步就跑偏的系统"**。

## 5. 对我方：可借 / 可打点

**可借**
1. **"唯一、事实性、简洁的答案"是免 LLM judge 的根本手段**。我们的答卷 schema（`dag_poc/answer_schema.json`）方向完全一致，应在论文里把这条原则显式引 GAIA 作为依据。
2. **难度分层用"人类步数 + 工具数"**：这是一个已被广泛接受的代理指标，我们可以直接用"专家需要的数据库查询次数 + checkpoint 数"做同构的三层难度。
3. **人类基线 vs 模型基线的强反差**是最有说服力的 Figure 1 素材（92% vs 15%）。我们应当**跑一个领域专家/规则化基线**做同样的反差图。
4. **答案保留机制**（公开 166 / 保留 300 答案）是防榜单过拟合的低成本做法，建议我们照做：公开一部分带答案的 dev set，隐藏 test set 答案。

**可打点**
- GAIA 收集了人类步骤元数据却**只用来分难度、不用来判分**——这正是"过程量被浪费"的最早案例。我们的 checkpoint DAG 就是把这份元数据升格为判分对象。可以在 Introduction 里用一句话点出这个历史遗留。
- 领域是通用助理任务（红线 2），不能作为任务来源。
