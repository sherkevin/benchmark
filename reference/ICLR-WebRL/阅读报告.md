## 0. 一句话

在 WebArena-Lite 上把 Llama-3.1-8B 的成功率从 4.8% 训到 42.4%、GLM-4-9B 从 6.1% 训到 43%：靠**用失败尝试自动生成新任务的自演化课程** + **自研的结果监督奖励模型（ORM）** + **KL 约束 & 带 actor 置信度过滤的经验回放**来稳住在线 RL。

## 1. 数据量

它是**方法论文**：

| 项 | 内容 |
|---|---|
| 评测环境 | **WebArena-Lite**，覆盖 5 类网站 |
| 训练任务 | **原本几乎没有**——这正是它要解决的问题之一（现有 web agent benchmark 只给测试集） |
| 训练任务来源 | **自演化课程自动生成**：每个训练阶段从上一阶段的失败尝试里生成新任务 |
| 骨干模型 | Llama-3.1-8B、GLM-4-9B |
| 关键结果 | 4.8% → 42.4%（Llama-3.1-8B）；6.1% → 43%（GLM-4-9B） |

## 2. 数据集形态（方法形态）

三个组件：

1. **自演化在线课程**：把探索中的 trial-and-error 变成任务生成器。每阶段结束后，挑出"失败但接近成功"的尝试，据此合成新的、难度适配当前策略的任务指令。
2. **ORM（outcome-supervised reward model）**：新训练的一个奖励模型，用来判断一条网页操作轨迹是否达成目标。**注意：这是"结果监督"，不是过程监督**——它只判终态成败，用于给在线 RL 提供可扩展的奖励信号（替代人工标注与规则判定）。
3. **自适应 RL 策略**：
   - 策略更新时加**较大的 KL 散度约束**（对参考策略），抑制课程学习引起的分布漂移；
   - **经验回放缓冲 + actor 置信度过滤**：只回放当前策略仍有较高置信度的经验，防止过拟合到旧经验。

它明确列出的三大障碍（我们要照抄进自己的 RL 章节）：
1. **训练任务稀缺**（benchmark 只给测试集）；
2. **反馈信号稀疏**（终态成败，一条轨迹一个 0/1）；
3. **在线学习的分布漂移**。

## 3. "长"体现在哪

- WebArena 任务本身是多步网页操作（点击、填表、跨页面导航），单任务十几到几十个动作；
- **"长"的代价在 RL 侧最明显**：一条长轨迹只有末尾一个 0/1 信号，credit assignment 极难——这就是 WebRL 要造 ORM + 课程的根本原因。

## 4. 判分粒度

**终态二元（WebArena 自带判据）+ 训练时用 ORM 近似终态判据**。
⚠️ **完全没有过程分**。它对"反馈稀疏"的解法是**造更多任务 + 造更好的终态判别器**，而不是把反馈变稠密。

## 5. 对我方：可借 / 可打点

**这是我们 RL 章节最重要的对照**，因为它把"长程 RL 的三个障碍"讲得最清楚，而**我们的 benchmark 对其中两个有结构性优势**：

| WebRL 遇到的障碍 | WebRL 的解法 | 我们的解法（结构性优势） |
|---|---|---|
| 训练任务稀缺 | 从失败尝试自动生成新任务 | **模板 + slots 可批量实例化**（GT-first 反查天然可规模化）→ 我们不需要造课程也有任务 |
| 反馈稀疏 | 训一个 ORM 近似终态奖励 | **checkpoint DAG 直接给稠密、可验证的过程奖励**，无需训奖励模型（也就无需承担奖励模型误判风险） |
| 分布漂移 | KL 约束 + 置信度过滤回放 | 同样需要，直接沿用它的做法 |

**可借（工程细节，直接采纳）**
1. **较大的 KL 约束**：课程/多阶段训练下必需，不要省。
2. **actor 置信度过滤的经验回放**：便宜且有效，避免长程 RL 过拟合旧经验。
3. **"从失败中生成新任务"仍然有用**：我们可以把它改造成 **"从 agent 卡住的 checkpoint 处生成同类新实例"**——这是 checkpoint 结构带来的更精确版本（知道它卡在哪一步，就针对那一步造题）。

**可打点**
- WebRL 必须训一个 ORM 来造奖励，等于**引入了一个可能出错的学习型判别器**；我们的奖励来自可执行断言，**天然免疫奖励模型误判（reward hacking 的一大来源）**。这是我们 RL 叙事里最强的一句话。
- 领域是网页操作（撞红线 2），只能作方法参照。
