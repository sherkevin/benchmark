## 0. 一句话

短任务 benchmark 造成了"scaling 收益递减"的错觉：单步准确率的边际提升会**双曲式**放大可完成任务的长度；而 LLM 在长任务上的失败主要来自**执行**而非推理，并且存在 **self-conditioning**——上下文里出现自己先前的错误会让它更容易继续犯错。

## 1. 数据量

**它不是一个大规模数据集，而是一个可任意合成的受控探针（probe）。**

- 任务生成器：一个 key–value 字典检索–合成任务。每一步给模型若干 key，要求它取出 value 并合成，从而维护一个不断更新的状态；任务长度 = 步数，可无限延伸。
- 因此"数据量"这一维度上它给出的答案是：**长程评测不必靠题量，靠可控的长度轴**。
- 度量口径：每个长度点上取多个样本估计 task accuracy，再求 H_s。

## 2. 数据集形态

- 一条样本 = **（计划已给定的一串 retrieve-then-compose 步骤，一本 key→value 字典，期望的最终状态）**。
- **关键设计：显式把 planning 和 knowledge 都喂给模型**（"provide the knowledge and plan needed"），只留 execution 给模型做。这样测出来的就是纯执行能力，排除"不会规划"这一混淆。
- 每一步两个原子操作：**retrieve**（按 key 取值）+ **compose**（把取到的值并入当前状态）。
- 可调旋钮：Turn Complexity K = 每个 turn 里塞几步（用来分离"单 turn 内多步"与"跨 turn 多步"）。

## 3. "长"体现在哪

这篇论文把"长"拆成了四个可分别测量的量，这是它最大的贡献：

| 指标 | 定义 |
|---|---|
| **Step Accuracy** | 从第 i−1 步状态到第 i 步状态更新正确的比例（**不管** i−1 步本身对不对） |
| **Turn Accuracy** | 同上但以 turn 为单位（一个 turn 可含多步） |
| **Turn Complexity K** | 每个 turn 内需执行的步数 |
| **Task Accuracy** | 长度为 i 的任务全程无错完成的比例 |
| **Horizon Length H_s** | 使 task accuracy 首次跌破阈值 s 的步数（默认 s=0.5，与 METR 口径一致）——**"模型能以概率 s 无错完成的任务长度"** |

理论结果（Proposition 1）：假设步准确率 p 恒定且无自纠正，则 `H_s(p) = ln(s)/ln(p)`，在 p>0.8 之后 H_s 急剧上升。这解释了为什么 METR 观测到"前沿模型 H_0.5 指数增长"可以与"步准确率收益递减"同时成立。

实证发现（三条，都对我们有用）：
1. 大模型在小模型单步已近满分时仍能多执行显著更多轮；
2. **步准确率随步数增加而衰减**（不是恒定的）；
3. **self-conditioning**：上下文含自己的历史错误会提高后续犯错率，且**不随模型规模缓解**；thinking（长思考/序列化 test-time compute）能缓解它，并大幅延长单 turn 内可执行长度。

## 4. 判分粒度

**天然是过程级的**——step / turn 级正确性逐步判定，且刻意设计成"不管前一步对不对"，从而把误差传播和单步能力解耦。判分完全确定性（字典比对），无 LLM judge。

## 5. 对我方：可借 / 可打点

**可借（强烈建议全部吸收）**

1. **直接采用 H_s 作为我们 benchmark 的一级指标**："在我们的材料/药物发现 checkpoint DAG 上，模型的 horizon length H_0.5 = 多少个 checkpoint"。这比"成功率 38%"信息量大得多，且已被 ICLR 2026 背书。
2. **"错在第几步"必须可测**——这正是我们 checkpoint DAG 的天然产出。我们可以直接报"逐 checkpoint 的条件通过率"，等价于他们的 step accuracy 曲线。
3. **self-conditioning 是我们可以顺手检验的现象**：长程发现任务里 agent 前面查错了一个性质值，后面会不会继续沿错误值推理？这是一个便宜且新颖的 analysis 章节。
4. **"把 plan 和 knowledge 给全，只测执行"**是一个很干净的消融设计。我们可以做对照组：给全流程模板 vs 不给，量化"规划贡献"与"执行贡献"。

**可打点**

- 它的任务是**合成的字典检索**，没有科学语义、没有真实工具、没有领域真值。审稿人对它的主要保留必然是 "toy task"。我们正好补上"真实科学领域 + 真实数据库真值 + 真实工具调用"的那一半。
- 它只有单一线性链，没有 DAG 依赖、没有等价路径。我们的 DAG 支持"无依赖可换序"，是它的严格推广。
