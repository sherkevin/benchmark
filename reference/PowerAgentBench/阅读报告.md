# PowerAgentBench-SS · 带"可审计证据链"的工程工作流评测

> **原文**：PowerAgentBench-SS: A Benchmark for Agentic AI in Power System Steady-State Studies
> **作者**：Costas Mylonas, Magda Foti, Andrea Pomarico, Matheus Duarte, Qian Zhang, Emmanouel Varvarigos
> **出处**：arXiv:2606.18789，2026-06-17，eess.SY
> **阅读方式**：基于完整摘要与元数据

---

## 0. 一句话

**它是本轮调研里"取证机制"设计得最完整的一篇**——不但要 agent 产出结论，还要产出 **auditable evidence trail（可审计证据链）**，并由一个**隐藏的评估器重新计算物理有效性**来判分。

**它与我们的机制几乎同构**，只是领域从化学换成电力系统。

---

## 1. 它要求 agent 完成的工作流

摘要列出七步：**查看电网案例 → 选择工具 → 调用仿真器 → 筛查故障场景 → 提出可行的缓解措施 → 验证结果 → 产出可审计的证据链**。

**与我们的六卡点对照**：

| PowerAgentBench 步骤 | 我们的卡点 |
|---|---|
| 选择工具 + 调用仿真器 | cp1 / cp3（调工具取证） |
| 筛查故障场景 | cp2 建池 + cp4 筛选 |
| 提出缓解措施 | cp5 排序 + cp6 答案 |
| **产出可审计证据链** | **我们的取证机制（真值反查）** |

---

## 2. 判分机制：隐藏评估器 + 风险敏感指标

**核心设计**：`a hidden evaluator recomputes physical validity and scores the submitted report`（一个**隐藏的**评估器重新计算物理有效性，并给提交的报告打分）。

**"隐藏"这一点与我们的 B 侧隔离同理**：评估逻辑不暴露给 agent，避免它针对判分器优化。

**它定义的指标里有几个直接对应我们的关切**：

| 指标 | 含义 | 对应我们 |
|---|---|---|
| **evidence-backed recall** | **有证据支撑的**召回率 | **这就是我们的 cp3** —— 声称的东西有没有真查过 |
| submitted recall / found recall | 提交的 vs 找到的召回 | 我们的 cp2 建池覆盖 |
| **false-safe penalties** | 误报"安全"的惩罚 | 我们尚无对应项 |
| severity regret | 严重性遗憾 | 我们的 cp5 排序质量 |
| **tool-use efficiency** | 工具使用效率 | 我们的 token/调用次数留痕 |
| **validation budget** 使用情况 | 验证预算用了多少 | 我们尚无预算约束 |

---

## 3. 它的核心论断（可直接引用）

> `The results show why solver-only or answer-only evaluation is insufficient: agents are distinguished not only by top-contingency discovery, but also by validation-budget use, explicit submission, type coercions, duplicate validations, evidence-backed reporting, and mitigation behavior.`
>
> （结果说明为何**只评求解器或只评答案是不够的**：区分 agent 的不只是找到了哪些最严重故障，还有验证预算怎么用、是否显式提交、类型强转、**重复验证**、有证据支撑的报告、以及缓解行为。）

**这是"只判终态不够"的又一条独立证据，且来自电力工程领域**——说明这不是化学域的特殊问题。

---

## 4. 对我方：可借 / 可打点

**可借（三条，都很具体）**：
1. **`evidence-backed recall` 这个指标名可以直接用来重命名我们的 cp3**，比"性质覆盖性检查"清楚得多。
2. **`false-safe penalties`（误报安全的惩罚）我们缺**。类比过来：agent 声称"该候选满足所有约束"但实际不满足，应比"漏掉一个候选"罚得更重。目前我们的 cp4 对这两类错误同等处理。
3. **`validation budget`（验证预算）我们没有**。我们不限制工具调用次数，因此考不出"预算意识"。这是范围选择，但应在文档里明确声明。

**可打点**：它是电力系统域，与我们无竞争关系，属于**跨域方法论同构**的最佳案例——引用它可以说明"过程级取证不是化学域自娱自乐，工程领域也在这么做"。
