# URSA · 一条完整真实的例子

> **论文**：URSA: Chemistry-Aware Benchmark for Utilitarian Retrosynthesis Assessment
> **arXiv**：2607.04688v1 [cs.LG]，2026-07-06，Insilico Medicine（22 页，含附录 A–M）
> **本次取证**：PDF 全文（arXiv）+ GitHub API（`insilicomedicine/URSA`、`insilicomedicine/ChemCensor`）+ Zenodo `10.5281/zenodo.20810716`（判分产物）+ PubChem PUG REST（分子身份核验）
> **拉取时间**：2026-08-12

---

## 0. 一句话

给一个**目标分子 SMILES**，让系统产出最多 10 条回溯到市售原料的合成路线；URSA 先做形式检查（能不能到市售原料 + 图结构自洽），再用 **ChemCensor** 给**每一步反应**打 0–5 的"有无合成先例"分，**任何一步为 0 就整条路线不算过**。

## 1. 测什么

| 项 | 内容 |
|---|---|
| 任务 | 多步逆合成 / 合成规划（multistep retrosynthesis, MSRS） |
| 输入 | 单个目标分子，**默认 SMILES 格式**（附录 I：`We used the SMILES molecular format by default`） |
| 输出 | 每个靶点**最多 10 条**路线；超过则按模型自带分数截断，无分数则随机抽样 |

## 2. 真实 query 原文

URSA 对 LLM 用 **10 个 Jinja2 自然语言模板**，每个靶点发 **10 次查询、每次随机抽一个模板**（附录 H.5：`we issued 10 queries per target molecule, randomly sampling a prompt template at each query`）。

**模板 1 原文（附录 I，逐字）**：

```jinja
Please propose a plausible synthetic route for the target molecule
<{{input_format}}>{{query}}</{{input_format}}>. The route must converge to
commercially available starting materials (purchasable building blocks).
```

**模板 3 / 7 / 4 原文（体现约束措辞的变体）**：

```
Please propose a convergent retrosynthetic pathway for the target molecule
<{{input_format}}>{{query}}</{{input_format}}>. It is mandatory that the route ends on
commercially available starting materials, not bespoke intermediates.

Please perform retrosynthetic analysis and propose a synthetic route for the molecule
<{{input_format}}>{{query}}</{{input_format}}>. The route is acceptable only if every
terminal precursor can be sourced as a commercially available building block.

Design the entire synthetic route to reach the target molecule
<{{input_format}}>{{query}}</{{input_format}}> from catalog chemicals. Explicitly ensure
the retrosynthesis bottoms out in commercially accessible building blocks.
```

（10 个模板全文见 `artifacts/ursa_paper_pdftotext.txt`，附录 I。）

### 一个具体靶点填进去 → 完整 query

选 **URSA-drugs&clinicals-2026** 里的 **Icotinib**（埃克替尼，已上市 EGFR-TKI）。

- SMILES：`C#Cc1cccc(Nc2ncnc3cc4c(cc23)OCCOCCOCCO4)c1`
- PubChem 反查结果（实测）：`Icotinib` / CAS `610798-31-7` / 代号 `BPI-2009` / UNII `9G6U5L461Q`
- IUPAC 风格别名：`N-(3-ethynylphenyl)-7H,8H,10H,11H,13H,14H-1,4,7,10-tetraoxacyclododeca[2,3-g]quinazolin-4-amine`（即"6,7-苯并-12-冠-4 稠合的 4-苯胺基喹唑啉"）

**实际发给模型的 query（模板 1 渲染后）**：

```
Please propose a plausible synthetic route for the target molecule
<SMILES>C#Cc1cccc(Nc2ncnc3cc4c(cc23)OCCOCCOCCO4)c1</SMILES>. The route must converge to
commercially available starting materials (purchasable building blocks).
```

> **诚实标注**：模板是论文附录 I 的原文，`{{query}}` 位置填的 Icotinib SMILES 来自 Zenodo 判分产物的文件名（实测该分子在 100 个靶点里）。**两者的拼接是我做的**——论文没有逐字印出"某个具体分子的完整 query 字符串"。
>
> **另一个卡点**：论文说"LLM 路线按 prompt 指定的格式解析（`parsed from the prompt-specified format described in Appendix I`）"，但附录 I 印出来的 10 个模板里**没有任何输出格式说明**（没有 JSON schema、没有示例）。这个输出格式约定在正文和附录 I 中缺失，我没找到。

## 3. 预期答案（一条路线长什么样）

**URSA 没有单一 ground truth 答案**——这是它的设计核心。所谓"预期答案"只能是"一条能通过判分的路线"。

下面是 **Zenodo 判分产物里真实存在的那条路线**：Icotinib，由本榜单最强系统 **RetroChimera-MCTS** 产出并被 URSA 选为 best route，带逐步 ChemCensor 分数。

来源文件：`URSA-Drugs&Clinicals-2026.zip → RetroChimera_mcts_schemes.zip → C#Cc1cccc(...)c1__r7.cdxml`
（已存为 `artifacts/icotinib_cdxml/RetroChimera-MCTS__r7.cdxml`）

**正向 4 步：**

| # | 反应物 | 产物 | CC |
|---|---|---|---|
| 1 | `O=C(O)c1ccc2c(c1)OCCOCCOCCO2`（冠醚稠合苯甲酸）+ `CCI`（碘乙烷） | `CCOC(=O)c1ccc2c(c1)OCCOCCOCCO2`（乙酯） | **4.00** |
| 2 | 乙酯 + `O=[N+]([O-])O`（HNO₃） | `CCOC(=O)c1cc2c(cc1[N+](=O)[O-])OCCOCCOCCO2`（硝化产物） | **2.00** |
| 3 | 硝基乙酯 + `NC=O`（甲酰胺） | `O=c1[nH]cnc2cc3c(cc12)OCCOCCOCCO3`（喹唑啉-4(3H)-酮） | **2.00** |
| 4 | 喹唑啉酮 + `O=P(Cl)(Cl)Cl`（POCl₃）+ `C#Cc1cccc(N)c1`（3-乙炔基苯胺） | **Icotinib** | **2.00** |

**判定结果**：4 步全部 CC > 0 → **Solv-2 通过**；`Av. CC = (4+2+2+2)/4 = 2.50`。

**叶节点（必须全在 CABB 库里）**：冠醚稠合苯甲酸、碘乙烷、硝酸、甲酰胺、POCl₃、3-乙炔基苯胺。

**化学上读得通**：酯化 → 硝化 → 甲酰胺环化建喹唑啉酮（Niementowski 型，硝基还原被并进这一步）→ POCl₃ 氯化后与 3-乙炔基苯胺 SNAr。第 3、4 步各自压缩了两个操作，这正是 URSA **subtree generation**（把多步塌缩成单步以对齐 USPTO 里"多步存成一条记录"的粒度）要处理的情形。

### 同一分子，三个系统的对照（这才是判分机制的真面目）

| 系统 | 步数 | 逐步 CC | Av. CC | Solv-2 |
|---|---|---|---|---|
| **RetroChimera-MCTS** | 4 | 4 / 2 / 2 / 2 | 2.50 | ✅ 过 |
| **Gemini 3.1 Pro** | 3 | 5 / 1 / 2 | 2.67 | ✅ 过 |
| **GPT-5.5** | 3 | 4 / **0** / 2 | 2.00 | ❌ **挂** |

**Gemini 3.1 Pro 的路线**（3 步）：
1. `COc1cc2nc[nH]c(=O)c2cc1OC`（6,7-二甲氧基喹唑啉酮）→ `O=c1[nH]cnc2cc(O)c(O)cc12`（脱甲基得儿茶酚）— **CC 5.00**（满分＝规范化反应 SMILES 在先例库里精确命中）
2. + `ClCCOCCOCCCl`（三乙二醇二氯）→ 冠醚成环 — **CC 1.00**
3. + `C#Cc1cccc(N)c1` → Icotinib — **CC 2.00**

**GPT-5.5 的路线**（3 步，第 2 步吃 0 分）：
1. `Nc1cc(O)c(O)cc1C(=O)O` + `NC=O`（甲酰胺）→ `O=c1[nH]cnc2cc(O)c(O)cc12` — **CC 4.00**
2. + `Cc1ccc(S(=O)(=O)OCCOCCOCCOS(=O)(=O)c2ccc(C)cc2)`（三乙二醇二对甲苯磺酸酯）+ `POCl3` → `Clc1ncnc2cc3c(cc12)OCCOCCOCCO3` — **CC 0.00** ← 把"双 O-烷基化大环化"和"4 位氯化"**并成一步**，反应中心在先例库里找不到，直接 0 分
3. + `C#Cc1cccc(N)c1` → Icotinib — **CC 2.00**

**这就是 URSA 想抓的东西**：三条路线都终止于市售原料（都过 Solv-0），三条路线化学思路都"看着像对的"，但 GPT-5.5 有一步没有任何合成先例支撑 → 只有它挂在 Solv-2。

## 4. 怎么判分

### 4.1 Solv-N 层级（论文 §3 定义 + GitHub README 的可执行定义）

Solv-N 形式体系本身来自引文 [14]（Morgunov et al., *The syntax of matter*, ChemRxiv 2026），URSA 是使用方。**所有层级都额外要求路线终止于市售 building blocks（`[task]` 约束）**。

| 层级 | 论文定义 | README 里的**可执行**定义（更硬） |
|---|---|---|
| **Solv-0** 句法 | 路线中所有分子串是合法 SMILES | 树结构自洽（SMILES 合法、无断裂）**且每个起始原料都在 catalog 里** |
| **Solv-1** 拓扑 | 每步对应合法反应模板 / 有效反应中心变换 | 存在某个 variant，其**每一步** ChemCensor 得分 `> 0`，**关掉官能团匹配** |
| **Solv-2** 选择性 | 加上化学合理性：反应先例、化学/区域/立体选择性一致性 | 存在某个 variant，其**每一步** ChemCensor 得分 `> 0`，**开启官能团匹配** |
| Solv-3 可执行性 | 条件、纯化、收率 | **URSA 不做** |

关键实现细节（README）：
- **variant** = 原始路线 + `PathCollapser` 产出的所有合法塌缩形式；**每个层级独立挑最优 variant**，任一 variant 过则该层级过。
- 每个 `StepResult` 同时带 `score_without_fg`（喂 Solv-1）和 `score_with_fg`（喂 Solv-2）。
- 指标是 `routes_passing / total_molecules`——**没出路线的靶点直接拉低分数**，不是只在有输出的子集上算。
- 目标分子本身就是 building block 的情况标 `is_no_synthesis`，**任何 Solv 层级都不算过**。

### 4.2 ChemCensor 怎么判（评估器）

不是 LLM 判官，是**确定性、基于合成先例**的打分器（独立论文 arXiv:2602.03554 / GitHub `insilicomedicine/ChemCensor`）。

流程（附录 L）：标准化输入 → 校验 SMILES → **RxnMapper** 做原子映射 → 推断动态原子 → 立体校验（允许 SN2 反转、合法立体中心生成；静态部分反转判错）→ **SeAr annotator** 处理亲电芳香取代的区域选择性 → 反应中心抽取，得到 **RC1–RC4 嵌套家族**（外围上下文逐级变大）→ 每个中心标注**不参与反应的官能团**（**516 个 FG**，SMARTS 表示）→ 与先例库比对，子签名匹配即接受。

**分数刻度（ChemCensor README 原文表格）**：

| 分值 | 含义 |
|---|---|
| `5.0` | **精确命中**——规范化反应 SMILES 就在库里 |
| `4.0` | RC4 反应中心匹配 |
| `3.0` | RC3 匹配 |
| `2.0` | RC2 匹配 |
| `1.0` | RC1 匹配（也包括 SIS / 互变异构反应） |
| `0.0` | 默认——**无中心匹配** |
| `-1.0` | 失败——反应无法处理 |

判"不合理"的逻辑：**反应中心不在参考库里 → 判不合理；该反应中心从未观察到过的官能团 → 否决合理性**。两者都有先例支撑才算合理。

先例库两档配置：
- `URSA-minor-1.1.0-U2`（**开放**，主结果）：ChemCensor v1.2.0 + **U2** 库 ≈ **1.4M** 条 USPTO-full 反应
- `URSA-major-1.1.0-U2P2`（**闭源**）：U2 再叠 **Pistachio 2023Q4** ≈ **+3.5M** 条先例

### 4.3 best route 选择（每靶点只留一条，§4.2 原文顺序）

1. 优先 **Solv-2 = 1**（每步都过合理性）的路线；
2. 若多条 Solv-2 路线，取 **Av. CC 最高**；
3. 若没有 Solv-2 路线，取 **Av. CC 最高**；
4. Av. CC 相同则取**最短**。

### 4.4 CC\*（公式 1）

$$\mathrm{CC}^* = \frac{1}{M}\sum_{t=1}^{M} \frac{1}{|r^*(t)|}\sum_{i \in r^*(t)} \mathrm{CC}_i$$

M＝靶点数，$r^*(t)$＝靶点 t 的 best route，$\mathrm{CC}_i \in [0,5]$。即"先在最佳路线内按步平均，再跨靶点平均"。

### 4.5 CABBs 是什么（starting-material stock）

**255,365 个化合物**，共享给所有被测系统。构成：

1. **Enamine** building blocks
2. **ASKCOS "buyables"** 集
3. **常见小分子试剂/溶剂**——论文明说这类东西"常被供应商库漏掉，但真实的 stock termination 需要它们"

其中 buyables 部分额外与 **eMolecules ready-to-purchase Tier 1 + Tier 2** building blocks 做过交叉核对。

发布在 `huggingface.co/datasets/insilicomedicine/URSA-BBs`（CSV，单列 `smiles`；URSA 也接受自定义 `.smi` / CSV）。

## 5. Agent 工具（装备）

**先说清楚定位**：URSA 是**评测框架**，不是 agent，也不给被测方发工具。被测方分两类，装备完全不同。

### 被测 LLM 的装备：**只有 prompt，没有工具**

- 纯自然语言 in / 自然语言 out，**没有工具调用、没有 RDKit、没有反应数据库检索、没有 BB 库查询权限**——模型只能靠参数里的化学知识猜"这个原料买得到吗"。
- 每靶点 10 次查询，每次随机抽 10 个模板之一；最多留 10 条路线。
- 用各家**默认 reasoning-effort 设置**（`using their default reasoning-effort settings`）。
- 通过公开 API 访问（Table 3：xAI、Google Gemini API、Azure OpenAI、Anthropic API、Azure AI Foundry、OpenRouter、阿里云百炼）。
- 输出由 **RetroCast 适配器**解析成统一路线对象。

> 这解释了 Table 6 里的 `BB` 列为什么那么低（最好的 GPT-5.5 也只有 0.54，Gemini 0.51，多数 LLM ＜0.4）——**让 LLM 裸着判"市售可得"是它掉分的大头**。

### 传统 CASP 的装备：自带单步模型 + 搜索算法

- 端到端方案：Retro\*、DMS-Wide/Flash/Explorer-XL、ASKCOS、TTLA、DreamRetroer
- 组合方案：单步策略 **LocalRetro** + 规划算法 **Retro\*-0**，经 **Syntheseus** 编排
- **AiZynthFinder v4.4.0**：Retro\* 和 MCTS 两种 planner，**max route depth = 10**
- **RetroChimera**：经 Syntheseus 接口，Retro\* 和 MCTS 两种 planner
- **SynPlanner**：MCTS planner，**max route depth = 10**

### URSA 判分管线自己用的组件（Figure 1B 六段）

`Integrity validation → Stock termination check → Subtree generation → ChemCensor scoring → Best route selection → Metrics calculation`

- **RetroCast**（路线格式统一层，引文 [12]，`github.com/ischemist/project-procrustes`）；支持 11 个适配器：`aizynth, askcos, dms, dreamretro, multistepttl, paroutes, retrochimera, retrostar, synplanner, syntheseus, synllama`
- **RDKit**：解析所有分子串
- **RxnMapper**（引文 [54]）：原子映射
- **SMARTS**（引文 [53]）：516 个官能团模式
- **ChemCensor v1.2.0** + SQLite 先例库（U2 / U2P2）
- **PathCollapser**：subtree / collapsed variant 生成
- 输出：**CDXML** 文件，每步标注 CC 分数（可在 ChemDraw 里打开人工复核）

**关于恢复出的 CSV，两点如实说明**：
1. 100 行里有 **2 行 SMILES 里带 `_`**（`CC(C)(C)_C=C(_C#N)...`、`N#C_C=C_c1ccc2...`），RDKit 解析不过。原因是文件名把顺反键符号 `/` 和 `\` 都替换成了 `_`。**这是文件名编码导致的失真，不是数据集本身的问题**；其余 98 行 RDKit 全部解析通过。
2. 这个列表是**从判分产物反推的**，不是官方 CSV 本身——官方 CSV 在 HuggingFace 上（见下）。它缺官方的 `Structure ID` 列。
