## 0. 一句话

把真机交互中观测到的有限状态建成一张强连通图（节点 = 手机屏幕状态，边 = 动作转移），从而用静态图**模拟动态行为**，在图上标里程碑，得到 175 道复杂长程手机任务：支持多条正确解、子任务完成率统计、15 类原子能力细分诊断。

## 1. 数据量

| 量纲 | 数值 |
|---|---|
| 任务数 | **175**（**74** 单应用 + **101** 跨应用） |
| 平均任务长度 | **13+ 步** |
| 每题路径 | **≥2 条正确路径** + 若干条典型错误路径 |
| 原子能力类别 | **15** 类（从所有里程碑点抽取共性归纳而来） |

## 2. 数据集形态

一条样本 = **（任务指令，一张状态转移图，图上标注的里程碑集合，多条正确路径 + 典型错误路径）**。

- **图结构**：节点 = 手机屏幕状态（screen list），边 = 动作转移关系；整张图是强连通的，因此 agent 走错也能"回来"，形成**准动态交互**（quasi-dynamic）。
- **里程碑（milestone）**：图上打的红旗，每个里程碑 = 一个子任务完成。
- **任务构造手法**：**故意用"部分含糊（partially ambiguous）"的指令**来制造多解——这是它得到"多条正确路径"的关键技巧。
- **任务组织**：一个复杂任务由多个原子子任务按**顺序、并行、递归**三种模式组合，论文明确说这正是"图结构 benchmark 天然适配"的理由。

## 3. "长"体现在哪

1. **步数**：平均 13+ 步；
2. **跨应用**：101/175 是跨 app 的，涉及状态在不同应用间传递；
3. **子任务组合结构**：顺序 / 并行 / 递归三种模式的组合深度；
4. **多解**：长程任务的正确解不唯一，这本身是"长"带来的必然后果（他们用此批评离线静态 benchmark 只能验一条 golden path）。

## 4. 判分粒度（本文最值得学的部分）

三个指标：

| 指标 | 定义 |
|---|---|
| **SR**（Success Rate） | 所有里程碑都达成 → 成功，否则失败 |
| **CR**（Completion Rate） | **达成的里程碑数 / 总里程碑数** —— 即部分分 |
| **AC**（Atomic Task Capability，本文新提出） | `AC = 达成的该原子任务里程碑数 / 评测中该原子任务被执行的次数`；**分母刻意排除"因前序子任务失败而从未被执行到"的子任务** |

**AC 的分母设计极其关键**：它解决了"级联失败污染能力诊断"的问题——前面挂了导致后面没机会执行，不能算后面能力差。论文举例：GLM-4.5V 的 SR/CR 都高，但 "save" 能力得分为 0；另一模型 filter 只有 22.22，一眼定位瓶颈。

⚠️ **这正是我们 checkpoint 判分必须处理的同一个问题**，而我们目前的 `reward` 表达式尚未显式定义"未执行到"与"执行了但错"的区分。**这是必须立刻补上的设计缺口。**

## 5. 对我方：可借 / 可打点

**可借（三条，其中第 1 条是刚性缺口）**

1. **AC 的条件化分母**（排除未执行到的子任务）必须搬进我们的 checkpoint 指标体系：每个 checkpoint 要报**条件通过率** `P(cp_i 通过 | cp_i 的前置全部通过)`，而不是无条件通过率。这同时也正是 ICLR《Illusion of Diminishing Returns》的 step accuracy 定义（"不管前一步对不对"）的对偶形式——两篇论文从不同方向指向同一个度量原则。
2. **"部分含糊指令 → 多条正确路径"**：我们的 DAG 已允许等价路径，但题面构造还没有主动利用"含糊性"来制造多解。可以引入一个受控的模糊度旋钮。
3. **图结构静态模拟动态**：他们用有限状态图把"真机不可复现"变成"静态可复现"。我们的 mock 数据库快照是同一思路的数据版本，可以在论文里引它作为方法学同盟。

**可打点（必须写清楚的差异）**

| 维度 | ColorBench | 我们 |
|---|---|---|
| 领域 | 手机 GUI 操作（**通用 agent 任务**） | 材料 / 药物发现 |
| 里程碑语义 | **屏幕状态**（到达某个界面） | **科学中间产物 + 数值真值比对**（性质值、候选池、排序） |
| 里程碑真值来源 | 人工在图上标 | **科学数据库反查值**（可复核、不可协商） |
| 依赖结构 | 图（状态转移图） | DAG（判分依赖图，与状态图不同层） |
| 抗污染 | 未处理 | 分子匿名化 |
| RL | 无 | 有（完整版） |

**关键区分句（建议写进 Related Work）**：ColorBench 的里程碑判定的是"agent 是否到达了某个界面状态"，是**过程的位置**；我们的 checkpoint 判定的是"agent 产出的中间科学结论是否与数据库真值一致"，是**过程的内容**。前者可以靠遍历界面达成，后者必须真的做对科学判断。
