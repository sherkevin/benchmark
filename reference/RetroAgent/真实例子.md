## 1. 测什么

**任务**：多步逆合成规划（multi-step retrosynthesis planning）。给一个目标分子，把它逐步拆解成**市售可购买的原料**（building blocks），每一步反应必须由**已验证的反应模板**支撑。

**它不是**单步逆合成预测（不是 USPTO-50K top-k 那种），**是长程规划**：论文原话——"decisions made early constrain downstream options, and a suboptimal choice can lead the search into regions where no feasible route exists."

**搜索空间的形式化**：AND-OR 图 `G=(V_M ∪ V_R, E)`
- 分子节点 `V_M` = **OR 节点**：任一子反应 solved → 该分子 solved
- 反应节点 `V_R` = **AND 节点**：**所有**子分子 solved → 该反应 solved
- 根节点 = 目标分子 M1；状态自动向上传播；根 solved = 路线找到

**两个测试集**（论文 §3.1 Datasets）：

| 测试集 | 规模 | 来源 | 性质 | 有无参考路线 |
|---|---|---|---|---|
| **USPTO-190** | **190** 个 challenging 目标分子 | USPTO-Full 抽取（Chen et al. 2020，即 Retro*） | **分布内**（in-distribution），标准基准，平均深度 **6.0** | **有**参考路线 |
| **ChEMBL-1000** | **1,000** 个 drug-like 分子 | ChEMBL 数据库（Liu et al. 2023，即 PDVN） | **分布外**（out-of-distribution），测泛化 | **无**参考路线 |

> 注意：**不是** Pistachio，**不是** n1/n5（那是 PaRoutes 的划分）。原始阅读报告里没写测试集，这里补齐。

**训练集**：从 USPTO-Full 抽 **20,626** 个目标分子，过滤为**深度 > 4** 的路线，平均深度 **5.93**。

**原料库**：eMolecules 的 **23,081,633** 个市售分子（来源 https://downloads.emolecules.com/）。

**分布内外的量化证据**（附录 H，Table S4 及正文）：
- 骨架新颖度（Murcko scaffold 不在训练目标中）：ChEMBL-1000 **96.2%** vs USPTO-190 **74.8%**
- 到训练集的最大 Tanimoto 相似度（Morgan r=2, 2048 bits）：ChEMBL-1000 **0.345** vs USPTO-190 **0.483**；85% 的 ChEMBL-1000 目标低于 USPTO-190 的中位数
- 平均环数：ChEMBL-1000 **3.18** vs USPTO-190 **3.55**
- 在 962 个 scaffold-novel 的 ChEMBL-1000 目标上：**73.8%** pass@1、**84.2%** @N≤500（与整体几乎无衰减）

## 2. 真实 query 原文（具体目标分子）

论文附录 J「Example Transcripts」给了 **2 个 solved + 2 个 failed** 的 USPTO-190 真实评测 episode，**带目标分子 SMILES 和逐轮工具调用**。下面这条是 **Solved example 1**。

### 2.1 系统提示词（附录 A 原文，与代码 `slime_retro/prompts.py` 逐字一致）

```
You are an expert retrosynthesis planner. Decompose a target molecule into commercially
available building blocks through valid reactions.

You search over an AND-OR graph. Molecules (M1, M2, ...) are OR nodes: a molecule can be
decomposed in multiple ways, and any one successful decomposition suffices. Reactions
(R1, R2, ...) are AND nodes: all reactants must be solved for the reaction to succeed.
Status propagates automatically up the tree.

Core loop:
1. predict_templates(molecule_id): get candidate reactions (P1, P2, ...)
2. expand(molecule_id, prediction_id): apply predictions to the graph. Use comma-separated
   IDs (e.g., "P1,P3") to expand multiple at once.
3. get_frontier(): see which OPEN molecules still need decomposition.
4. Repeat until the route is solved (automatic detection).

Maximum route depth: 30 reaction steps.
```

### 2.2 用户提示词（每个目标一条，`{target_smiles}` 是唯一变量）

```
Plan a retrosynthesis route for: {target_smiles}

The target is M1. The graph tools (predict_templates, expand, inspect_node) use molecule
IDs (M1, M2, ...). The chemistry tools (get_molecule_info, search_building_blocks,
calculate_synthetic_accessibility, calculate_scscore) use SMILES strings. Start with
predict_templates("M1").
```

## 3. 预期答案

**答案形式不是一个字符串，而是「AND-OR 图上根节点变成 SOLVED」的搜索过程**。所以「预期答案」= 一条从 M1 到市售原料的完整路线。

论文给的这条 episode 的**真实完整轨迹**（附录 J 原文，`Tn` = 第 n 轮，`w=k` = 单次 expand 施加的预测数）：

```
Solved: 11 turns, 4 predictions, depth 4        目标: CC(C)c1ccc(-n2nc(O)c3c(=O)c4ccc(Cl)cc4[nH]c3c2=O)cc1

T1 : predict_templates(M1)          -> 20 predictions
     P1: 2 reactants (1 BB), P2–P20: 1 reactant each (0 BB)
T2 : expand(M1, [P1,P3,P5,P7,P11])  w=5
T3 : get_frontier()                 -> [M2, M3, M4, M5, M6]
T4 : predict_templates(M2)          -> 20 predictions
     P6: 2 reactants (1 BB), P10: 2 reactants (1 BB), P12: 2 reactants (1 BB)
     P1–P5, P7–P9, P11, P13–P20: 1 reactant each (0 BB)
T5 : expand(M2, [P6,P10,P12])       w=3      // 恰好选中全部 3 个带 BB 的
T6 : get_frontier()                 -> [M9, M10, M11, M12]
T7 : predict_templates(M9)          -> 20 predictions
     P1–P20: 1 reactant each (0 BB)
T8 : expand(M9, [P17,P20])          w=2
T9 : get_frontier()                 -> [M13, M14]
T10: predict_templates(M13)         -> 20 predictions
     P1: 2 reactants (1 BB), P2: 2 reactants (1 BB), P14: 2 reactants (2 BB)
     remaining: 1 reactant each (0 BB)
T11: expand(M13, [P1,P14])          w=2      -> root SOLVED
```

**终局状态**：11 轮、**4 次** `predict_templates` 调用（即预算 N=4）、路线深度 **4**、图里 **18 个分子节点**、根节点 M1 = SOLVED。

**论文自己对这条的解读**（原文）："The agent selects predictions with building block reactants: at T5, it picks exactly the 3 predictions with BB annotations out of 20 candidates. At T11, it picks P14 which has 2 BB reactants, completing the route."

**对比 Solved #2 的行为**（说明 agent 学到的是自适应策略而非固定宽度）："wide (w = 5) at the root where many predictions have BB reactants, narrow (w = 1) when only one prediction has BBs, and moderate otherwise."

> **诚实边界**：论文**没有**印出这条路线上每个中间体（M2/M9/M13/…）的 SMILES，也没印所用的具体反应模板。所以「预期答案」能拿到的最细粒度就是上面这张逐轮调用表 + 终局统计，**中间体 SMILES 不可得**（要复现需自己跑那个单步模型）。

## 4. 怎么判分

### 4.1 什么叫「路线有效」——硬判定，无 LLM judge

论文附录 D 原话：**"a route is considered valid if every step applies a verified reaction template and all leaves terminate at purchasable building blocks."**

三条硬约束（§2.1）：
1. 路线是从 m0 到原料的**有向无环图**
2. 每个非原料分子**至少有一个**有效分解
3. **目标分子绝不能作为反应物被消耗**

判定实现：原料判定 = 在 23M eMolecules 库里做**精确 canonical-SMILES 查表**（代码 `bb_checker.check(smiles)`）；模板应用与校验用 **RDChiral**（Coley et al. 2019）。所以是**可执行的硬判定**，不是模型打分。

### 4.2 两个主指标（§3.1 Metrics，沿用 Retro-R1 的定义）

**① Pass@1**：单条轨迹内解出的目标占比。衡量「不重试」的决策质量。

**② Success rate at budget N**：在 **N 个 unique 单步模型调用**预算内解出的目标占比。
- 关键细节：预算计的是**去重后**的单步模型调用数（repeated predictions 不计入）
- 关键不对称（论文自己点出的）：搜索类方法一次确定性运行就能吃满预算；LLM 方法因长上下文限制吃不满，所以按 **iterative protocol** 对每个目标发起**多条独立轨迹**直到解出或预算耗尽
- **公平性自陈**（论文原话）：搜索类方法每次 expand 施加**全部**候选（up to 50），而 RetroAgent 在 USPTO-190 上平均只施加 **1.71** 个反应/次 expand。"At the same budget N, search-based methods thus explore a substantially larger portion of the search space, which gives them an inherent advantage at high budgets."

**③ 辅助指标 "Shorter Routes"**（消融表用）：190 个目标中，找到的路线**严格短于参考路线**的个数（多次运行取均值）。

**评测协议**（附录 F）：greedy decoding（temperature **0**），每 rollout 上限 **120 轮 / 120K token**；每个目标跑 **10 次独立实验**报 mean±std；**随机性完全来自 tool server 对预测和 frontier 的洗牌**，不来自 LLM 采样。

rollout 终止条件：根节点解出 / 达到最大轮数 / 连续若干轮无成功 expand（no progress）/ frontier 耗尽（dead frontier）/ token 预算耗尽 / 单轮超 8,192 token（重复退化）。达到最大深度 30 只**封掉当前分支**，不终止整个 rollout。

## 5. Agent 工具清单（8 个，含记忆结构）

论文附录 B + 代码 `tools/memory.py`、`tools/ml_retro.py` 实拉。**所有图相关工具用符号 ID（M#/R#/P#）而非裸 SMILES，明确目的是"prevent copying errors"**（防 LLM 抄错 SMILES）。

### 5.1 Memory tools（4 个，操作 AND-OR 图，输入=节点 ID）

| 工具 | 行为 | 关键细节 |
|---|---|---|
| `predict_templates(molecule_id)` | 查单步逆合成模型 | 取 **top-50** 得分预测 → **洗牌** → 截断到最多 **k=20** 个候选，编号 P1..P20；每个候选列出反应物 + **逐反应物的 `building_block: true/false` 标注**。会**自动过滤**成环（反应物是该分子的祖先）和重复反应。同一 rollout 内重复调用**复用缓存、零预算成本** |
| `expand(molecule_id, prediction_id)` | 施加一个或多个预测，建反应/分子节点 | **可逗号分隔多个**（`"P1,P3,P5"`）→ 一次调用建多个 OR 分支（**multi-expand**，最大功臣）。返回展开结果 + 父节点状态 |
| `get_frontier()` | 返回当前 Open 叶子分子集合 | 也负责**通报根节点是否已 solved**。返回项**被洗牌**以消除位置偏置 |
| `inspect_node(node_id)` | 任意节点详情 | 返回 SMILES、status、building block 状态、父节点、子节点 |

### 5.2 Chemistry tools（4 个，启发式，输入=SMILES 字符串）

| 工具 | 返回 |
|---|---|
| `get_molecule_info(molecules)` | 分子量、logP、原子数、环数 |
| `search_building_blocks(molecules)` | 是否在 23M 原料库中 + 可得性状态 |
| `calculate_synthetic_accessibility(molecules)` | SA score（Ertl & Schuffenhauer 2009），**1（易）–10（难）** |
| `calculate_scscore(molecules)` | SCScore 合成复杂度（Coley et al. 2018），**1（简单）–5（复杂）** |

### 5.3 结构化记忆到底存什么字段（代码 `tools/memory.py::GraphMemory`，networkx DiGraph）

**分子节点（OR 节点）**：
```python
type="molecule", id="M#", smiles=<canonical>, status="OPEN"|"SOLVED",
bb_status="building_block"|"not_building_block", depth=<int>
```

**反应节点（AND 节点）**：
```python
type="reaction", id="R#", status="OPEN"|"SOLVED", rationale=<agent 给的理由, 可空>,
product_id="M#", product_smiles=<...>, reactants=[<canonical smiles>...],
reactant_ids=["M#"...]
```

**图级索引**：`smiles_to_mol_id`（canonical SMILES → M#，实现同分子节点复用/合并）、`reaction_index`（`reaction_key = "{product}|{sorted reactants join '.'}"` → R#，用于查重）、`ml_predictions`（分子 → 缓存的候选，保证 P# 编号在整个 episode 内稳定）、`next_molecule_id` / `next_reaction_id`、`root_id`、`max_route_depth=30`。

**`inspect_node` 返回的观测字段**：`{id, status, parents:{id:smiles}, children:{id:smiles}}`，分子节点额外加 `{SMILES, building_block: bool}`。

**环境自动做、agent 不用管的事**（"the agent never needs to reason about graph consistency"）：状态传播（AND/OR 语义，`propagate_status`）、深度传播（BFS，发现更短路径就更新后代 depth，`propagate_depth`）、环检测（`find_cycle_reactants`，且在 **expand 时二次校验**，因为缓存候选取出后图可能已变）、重复反应检测（`would_duplicate_reaction`）、frontier 计算。传播只访问变更节点的祖先，**O(d)** 时间；路线完成判定是根节点的 **O(1)** 查询。

### 5.4 单步模型与训练（不是判分，但决定成绩可复现性）

- **单步模型**：template-based MLP（沿用 Chen et al. 2020），在 **381,302** 个 USPTO 反应模板上分类，输入 Morgan 指纹，模板应用/校验用 **RDChiral**；**权重取自 DESP**（Yu et al. 2024）
- **明确拒用的东西**（重要的可比性声明）：不用 Retro-R1 的 V2/V3 权重（"may produce chemically unrealistic reactions"）、V4 未公开；不用其"按预测概率重排的双分支策略"，因为目标是测 agent **学到的搜索能力**；训练和评测**全程洗牌**预测与 frontier 顺序，让 agent"evaluates candidates by content rather than positional bias"
- **基座**：Qwen3-4B-Instruct-2507，**故意选小且无 thinking 能力**的模型，以证明"the structured memory interface, rather than raw model capacity, drives planning performance"
- **RL**：GSPO（序列级 clip），slime + Megatron + SGLang，**8×H200**；奖励是可验证的 outcome-based：

```
r = 1.0 − δ_N − δ_D + p    若路线完成
  = −1.5                    若整条轨迹从未发出合法 tool call（纯格式失败）
  = −1.0                    其他

δ_N = min(0.3, 0.02·max(0, N−20))   N = 单步模型调用次数
δ_D = min(0.3, 0.02·max(0, D−20))   D = 从根算起的最大路线深度（反应步数）
p   = 每个有 tool error / 无合法 tool call 的轮次累计 −0.05
```
**完成路线才有正奖励，不完整路线零部分分**。训练 episode 上限 90 轮 / 56K token / 深度 30；batch 32 目标 × G=8 rollouts = 256 episodes；lr 1e-6 常数，GSPO clip ε=3.5e-4，KL β=0.001。

## 6. 局限（论文自陈，附录 D）——对判分有效性的边界

论文自己承认判分**只到「模板有效 + 叶子可购买」这一层**，**没有**建模：反应产率、区域/立体选择性、反应条件、保护基策略。原话：**"a shorter or template-valid route is not necessarily the most practical one in the laboratory."** 且这些信息"absent from the benchmarks, which provide only target molecules and, for USPTO-190, reference routes"。

对生成路线的化学合理性，只做了**定性专家咨询**："A consultation with expert chemists found the generated routes generally reasonable, but a systematic, large-scale assessment of practical utility, ideally with experimental validation, remains an open problem."（**没有给专家评分数字、没给专家人数**）

另一条：推理成本远高于传统搜索——"A single planning trajectory issues tens of LLM calls and consumes thousands of tokens, whereas a classical planner evaluates its scoring function in milliseconds."
