## 0. 一句话

**它的 Graph of Trace 与我们的 checkpoint DAG 是同一类结构**——一份可审计记录，**把 subgoals（子目标）、tool use（工具调用）、evidence（证据）、claims（结论）四者链接起来**，让研究者能顺着看、能查。

区别：它用来**给人看**（专家介入点），我们用来**给判分器算**。

## 1. 系统规格

| 项 | 数值 |
|---|---|
| 定位 | **完全开源**的多 agent 系统 |
| 组织方式 | 一个 PI agent 协调若干专家 agent |
| 知识库 | **7,233** 条已索引条目 |
| 技能库 | **72** 个可复用方法学单元，覆盖 **7 个**研究领域 |
| 审计机制 | **Graph of Trace** + 一个 **Auditor agent**（把造假检查集成进工作流） |
| 自建评测 | **BrainPilotBench-v0** ｜ 另跑 Agents' Last Exam 的三个脑科学任务 |

---

## 2. 它列举的 agent 四类失效（与我们的六维评测能力对得上）

摘要指出当前 agent 在脑科学上的毛病：**缺领域专长 · 可能编造结论（fabricate claims）· 多步推理中漂移（drift）· 几乎没有可供专家介入的定义点**。

| 它列的失效 | 我们的对应判据 |
|---|---|
| fabricate claims（编造结论） | 真值从 tool call 反查，自报数值不采信 |
| **drift during multi-step reasoning**（多步推理漂移） | 卡点 + 偏序判定（ADR-0021） |
| 无专家介入点 | 我们的 cp1–cp6 即为定义好的检查点 |
| 缺领域专长 | 属模型能力，非评测机制 |

## 3. 判分粒度

它自建的 BrainPilotBench-v0 细节未在摘要展开。可确认的是：**Auditor agent 做造假检查**属于 LLM 裁判类（软判定）。

---

## 4. 对我方：可借 / 可打点

**可借**：
1. **"Graph of Trace" 这个命名与四元链接（subgoal-tool-evidence-claim）值得借鉴**。我们目前的 trace 记录了工具调用与卡点达成，但**没有显式记录"哪个结论由哪条证据支撑"**这条边。若要补，正好对应 TRACER 的 provenance 思路。
2. **"可供专家介入的定义点"这个提法**可用于说明我们卡点的第二重价值：卡点不只是打分位置，也是人工复核的切入点。

**可打点**：它是 agent 系统（要跑得好），不是 benchmark（要判得准），且判定含 LLM 裁判。引用时归入"同类系统的审计机制"，不进 benchmark 对照表。
