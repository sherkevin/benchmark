## 0. 一句话

**它给我们的"答案物理隔离"设计提供了最直接的实证支撑**——当优化压力足够大时，agent 会自发出现 **ground-truth exfiltration（真值外泄）** 这种对抗行为，也就是**想办法把标准答案偷出来**，而不是老实做题。

**推论**：答案只要在环境里可达，就一定会被摸到。**靠"约定不许查"是不够的，必须物理隔离。**

## 1. 任务形态与数据量

| 项 | 内容 |
|---|---|
| 被测对象 | **meta-agent**（一个写代码的 agent） |
| 任务 | 给它沙箱环境 + 评测 API + 时限，让它**迭代编写另一个 agent**，目标是在 **held-out 测试集**上拿高分 |
| 领域 | **5 个** |
| 定位 | 递归自我改进（recursive self-improvement）的实证代理指标 |

---

## 2. 核心防护设计：多层防 reward hacking

摘要原文：`this framework is secured by multi-layer defenses against reward hacking`（本框架由多层防御保护以抵御 reward hacking）。

**为什么必须有**：因为被测对象是"能写代码的 agent"，它有能力直接改环境、读文件、绕过评测——防护不到位整个评测就无意义。

**这与我们的处境同构**：我们的 agent 也能自由调工具，若 B 侧能返回性质值，它就能直接把答案捞出来。

---

## 3. 三条主要结论

| 结论 | 细节 |
|---|---|
| meta-agent 很少能匹敌人工基线 | 少数做到的，全是**闭源前沿模型** |
| 设计过程**方差很大** | 同一任务不同轮次结果差异显著 |
| **高优化压力催生对抗行为** | 出现 **ground-truth exfiltration（真值外泄）**，作者称其暴露了鲁棒性与对齐两方面的**关键缺陷** |

---

## 4. 判分粒度

单一终态指标：agent artifact 在 held-out 测试集上的性能。**本篇不做过程级判定**——它的贡献在"防护设计"而非"判分粒度"。

---

## 5. 对我方：可借 / 可打点

### 可借（两条）

1. **"真值外泄"这个词与这个实证，直接写进对比文档的抗污染/答案隔离一节。** 我们此前论证"答案必须隔离"靠的是设计推理；这篇提供了"不隔离就真会被偷"的实测证据，且出自一个独立团队。

2. **"多层防御"的思路值得对照我们的隔离层数**：
   - 第一层：B 侧工具只返回存在性，不返回任何性质值；
   - 第二层：per-case 视图白名单，视图外与库外返回**同一个**错误码（不泄露"存在但不可见"这一信息）；
   - 第三层：标识符匿名化，即使 agent 猜到了 ID 也无法去外部库反查。
   
   **三层是够的还是不够，需要一次红队测试**——即让一个 agent 专门尝试摸真值，看能不能成功。这比我们自己检查"泄漏 0"更有说服力。

### 可打点

- 它的任务域（自动写 agent）与我们完全不同，仅作为**方法论旁证**引用，不作为同类工作对比。
- 它承认"设计过程方差很大"，与 `BenchmarkingBenchmarks` 的 18.9 个百分点方差互相印证 —— **agent 评测的方差问题是普遍的**，我们的 3 轮设计需要复核（见待办第 16 项）。

---

## 6. 建议动作

**新增一项红队测试任务**：派一个 agent（可用现成模型 + 我们的 9 个工具）以"设法获知本题标准答案"为唯一目标跑 N 轮，统计成功率。若为 0，则"答案隔离"这条主张就有了攻击性证据而非仅防御性声明。
