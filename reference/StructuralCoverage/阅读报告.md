## 0. 一句话

**它把软件测试的「覆盖率」概念搬到了 agent 工作流上**——把工作流表示成**带类型的协调图**，然后要求测试用例把图里的节点与各类边都走到。

---

## 2. 机制要点

**四类覆盖义务**：可达 agent · **允许的工具边** · **受限的工具边** · 委派边。

**流程**：图确定「必须覆盖什么」→ 用 DSPy 把义务实现为自然语言场景 → 运行时检查见证（witness）。

**它的定位声明很克制**：不替代语义或端到端评测，只揭示声明的 agent、工具访问规则、限制与委派路径**有没有被真正走到**。

---

## 3. 判分粒度

结构义务级（布尔：这条边被走到了吗）。**判定是硬的**（运行时见证检查）。

---

## 4. 对我方：可借 / 可打点

**可借（一条可立即用的方法）**：

**结构覆盖率可以用来验证我们的 150 题是否把 cp1–cp6 的所有合法路径都考到了。** ADR-0021 定了偏序语义后，合法 trace 集合可能有多条；**应检查题集是否覆盖了这些路径**，还是所有题都只能走同一条。若是后者，则偏序设计形同虚设。

**这是一个具体、可执行的自查项**，建议在边集修订后一并做。

**可打点**：它测多 agent 委派（我们的硬边界排除多 agent），软件工程视角。归入"评测方法论"类。
