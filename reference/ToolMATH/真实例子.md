## 1. 测什么

把 MATH 数据集的**逐步解题过程转成可复用的 Python 工具**（隐藏代码，只暴露 name/description/typed schema），
每道题配一个工具环境，考察**长程工具链**：顺序调用 · 复用中间输出 · 形成逻辑相连的调用链。

**规模**（论文 §3.1 + HF croissant.json 双向印证）：
- 主集 **12,369 个工具 / 7,699 道题**
- `ToolMATH-Hard`：**329 道题 / 362 个人工撰写 gold 工具**（自动抽取工具跑不出合格 trace 的难题）
  → 我下载的 `ToolMATHHard.jsonl` 实测正是 **362 条记录 / 329 个 unique source_problem**，完全吻合。

**三种工具目录条件**（论文 §4.1，这是它的核心设计）：

| 条件 | 工具环境 $\mathcal{S}(p)$ | 考什么 |
|---|---|---|
| **Gold-only** | $\mathcal{G}(p)$ | 基线能力 |
| **Gold-present** | $\mathcal{G}(p)\cup\mathcal{D}_{\ell,k}(p)$ | 冗余/干扰下的稳定性 |
| **Distractors-only** | $\mathcal{D}_{\ell,k}(p)$（**移除 gold**） | 能力缺失（missing-capability）下的适应 |

外加一个 **No tools baseline**（不给任何工具）——论文明确说这是 baseline，不是工具目录条件。

**干扰项分 5 级相似度**（$\ell\in\{1..5\}$）× 4 档预算（$k\in\{5,10,20,50\}$）：

1. Level 1 = 不同 category 随机
2. Level 2 = 纯随机
3. Level 3 = 同 category 随机
4. Level 4 = description embedding 相似度检索
5. Level 5 = 关键词重叠 + embedding 打破平局（**最难**）

**嵌套保证**：对每个 $(p,\ell)$ 预计算 100 个干扰项的有序表，$\mathcal{D}_{\ell,k}(p)$ 取前 $k$ 个，
因此 $k_1<k_2 \Rightarrow \mathcal{D}_{\ell,k_1}(p)\subseteq\mathcal{D}_{\ell,k_2}(p)$——**加预算只加噪声，不换噪声**，这样 $k$ 才是干净的自变量。
另有**重名安全阀**：全局工具名唯一，撞名时加后缀（原文例：`solve_linear_a`、`solve_linear_b`…）。

## 2. 真实 query 原文

### 2.1 主例：Level 5 Geometry，4 个 gold 工具组成真实依赖链

**来源**：`CHJ0417/ToolMATH` → `ToolMATHHard.jsonl`，`source_problem` 相同的 4 条记录聚合而成。

**题面（原文，LaTeX 原样）**：

```
In right triangle $ABC$, $AB=9$, $BC=13$, and $\angle B = 90^\circ$.  Points $D$ and $E$ are
midpoints of $\overline{AB}$ and $\overline{AC}$ respectively; $\overline{CD}$ and $\overline{BE}$
intersect at point $X$.  Compute the ratio of the area of quadrilateral $AEXD$ to the area of
triangle $BXC$.
```

- `level`: **Level 5**（MATH 最高难度档）
- `type`: **Geometry**

**它被转成的 4 个 gold 工具**（模型只看到 name + description + inputs，**Python 代码隐藏、由环境执行**）：

```json
[
  { "name": "midpoint_of_two_points",
    "description": "Return midpoint of two points. Inputs: x1,y1,x2,y2.",
    "inputs": {"x1":"float","y1":"float","x2":"float","y2":"float"},
    "function": "qw7b3p.py" },

  { "name": "triangle_centroid",
    "description": "Return centroid of triangle vertices A,B,C. Inputs: ax,ay,bx,by,cx,cy.",
    "inputs": {"ax":"float","ay":"float","bx":"float","by":"float","cx":"float","cy":"float"},
    "function": "dkhx4p.py" },

  { "name": "polygon_area",
    "description": "Compute area of a polygon given vertices in order. Inputs: points is list of [x,y].",
    "inputs": {"points":"list[list[float]]"},
    "function": "y8gpan.py" },

  { "name": "ratio_of_two_numbers_b",
    "description": "Return a/b for real numbers with b nonzero.",
    "inputs": {"a":"float","b":"float"},
    "function": "0rlyke.py" }
]
```

**隐藏的真实实现**（`function` 字段指向 `function_ToolMATHHard.tar.gz` 里的独立 `.py`）：

```python
# qw7b3p.py
def midpoint_of_two_points(x1: float, y1: float, x2: float, y2: float):
    """Return midpoint (x,y)."""
    return [(x1 + x2) / 2.0, (y1 + y2) / 2.0]

# dkhx4p.py
def triangle_centroid(ax: float, ay: float, bx: float, by: float, cx: float, cy: float):
    """Return centroid (x,y)."""
    return [(ax + bx + cx) / 3.0, (ay + by + cy) / 3.0]

# y8gpan.py
def polygon_area(points):
    """Return polygon area by shoelace formula."""
    if len(points) < 3:
        return 0.0
    s = 0.0
    for (x1,y1),(x2,y2) in zip(points, points[1:]+points[:1]):
        s += x1*y2 - x2*y1
    return abs(s) / 2.0

# 0rlyke.py
def ratio_of_two_numbers_b(a: float, b: float):
    """Return a/b."""
    if b == 0:
        raise ValueError("b must be nonzero.")
    return a / b
```

**注意这里的"隐藏中点"设计**：题面说 $X$ 是 $\overline{CD}$ 与 $\overline{BE}$ 的**交点**，
但工具箱里**没有"求两直线交点"的工具**，只有 `triangle_centroid`。
模型必须自己推出「两条中线的交点 = 重心」这一数学事实，才能把 `triangle_centroid` 接进链子。
这正是它所谓 tool description 与 problem 之间的 **logical hop**。

### 2.2 次例：Level 5 Geometry，5 个 gold 工具（更长的链）

```
A triangle has vertices $P=(-8,5)$, $Q=(-15,-19)$, and $R=(1,-7)$. The equation of the bisector
of $\angle P$ can be written in the form $ax+2y+c=0$. Find $a+c$.
```

5 个 gold 工具（严格串行，每一步吃上一步的输出）：

| # | 工具 | inputs | 作用 |
|---|---|---|---|
| 1 | `unit_vector_from_points` | `px,py,qx,qy` (float) | $P\to Q$ 单位向量 |
| 2 | `add_vectors` | `v1,v2` (list[float]) | 两单位向量相加 = 角平分线方向 |
| 3 | `line_coefficients_from_point_direction` | `x0,y0,vx,vy` (float) | 点+方向 → $[A,B,C]$ |
| 4 | `scale_line_to_y_coefficient` | `A,B,C,target_B` (float) | 缩放使 $B=2$，对齐题目要求的 $ax+2y+c=0$ |
| 5 | `sum_two_numbers_a_b` | `a,b` (float) | $a+c$ |

**交叉印证（有意思的一点）**：`line_coefficients_from_point_direction` 在论文附录 K 的**两条** trace 里
都是作为**干扰项**出现的。说明干扰项确实从**同一个全局工具池** $\mathcal{U}$ 里采样——
某题的 gold 工具就是别题的干扰项。这是"分级干扰项"能造得"plausible 而非 trivially irrelevant"的根本原因。

## 3. 预期答案

### 3.1 主例

MATH 官方解法（数据集 `source_solution` 字段原文，含 asy 画图代码）的关键论证：
> "Since $D$ and $E$ are midpoints, $\overline{CD}$ and $\overline{BE}$ are medians. ... The three
> medians cut triangle $ABC$ into six smaller triangles. These six smaller triangles all have the same
> area. ... Quadrilateral $AEXD$ is made up of two of these small triangles and triangle $BXC$ is made
> up of two of these small triangles as well. Hence they have the same area (and this will hold true no
> matter what type of triangle $\triangle ABC$ is). Thus, the ratio ... is $1/1=\boxed{1}$."

**gold answer = `1`**

**我本地实际执行了官方 4 个 Python 实现，逐步输出**（不是推演，是跑出来的）：

```
放坐标 A=(0,9), B=(0,0), C=(13,0)
1) midpoint_of_two_points(0,9,0,0)          -> D = [0.0, 4.5]
2) midpoint_of_two_points(0,9,13,0)         -> E = [6.5, 4.5]
3) triangle_centroid(0,9,0,0,13,0)          -> X = [4.333333333333333, 3.0]
4) polygon_area([A,E,X,D])                  -> 19.5
5) polygon_area([B,X,C])                    -> 19.5
6) ratio_of_two_numbers_b(19.5, 19.5)       -> 1.0
```

→ `1.0` == gold `1` ✅ **工具链闭合，可判分**

### 3.2 次例

官方解法结论原文：
> "$PP'$ has slope $\frac{-11}{2}$, from which we find the equation to be $11x + 2y + 78 = 0$.
> Therefore, $a+c = \boxed{89}$."

**gold answer = `89`**

我本地执行官方 5 个实现的逐步输出：

```
1) unit_vector_from_points(-8,5,-15,-19)              -> [-0.28, -0.96]
2) unit_vector_from_points(-8,5,1,-7)                 -> [0.6, -0.8]
3) add_vectors([-0.28,-0.96],[0.6,-0.8])              -> [0.32, -1.76]     # 角平分线方向
4) line_coefficients_from_point_direction(-8,5,0.32,-1.76)
                                                      -> [-1.76, -0.32, -12.48]
5) scale_line_to_y_coefficient(-1.76,-0.32,-12.48, 2.0)
                                                      -> [11.0, 2.0, 78.0] # 正是 11x+2y+78=0
6) sum_two_numbers_a_b(11.0, 78.0)                    -> 89.00000000000001
```

→ 第 5 步精确复现官方的 $11x+2y+78=0$ ✅

⚠️ 第 6 步得到 `89.00000000000001` 而非 `89`。论文的判分口径是
**"exact-match answer accuracy after standard normalization"**（§4.4），
浮点尾差必须靠 normalization 吃掉——**这就是它"数学域可确定性判分"的实际代价**，值得我方留意：
浮点工具链 + exact match 的组合天生需要一层归一化，否则会误判。

## 4. 怎么判分

### 4.0 基础判分

- **Accuracy** = exact-match answer accuracy after standard normalization（§4.4）
- 终止条件：模型输出单行 `ANSWER: <numeric answer>`
- 另分析 tool-call counts 与 tool identity distributions

### 4.1 行为条件化指标（behavior-conditioned metrics，§4.4 原文定义）

| 指标 | 定义（原文） |
|---|---|
| **Tool-call rate** | "the fraction of examples with at least one valid tool call" |
| **Tool-Acc** | "accuracy conditioned on executing at least one valid tool call" |
| **NoTool-Acc** | "accuracy conditioned on producing an answer without any valid tool call" |

> "When a conditioning denominator is zero, the corresponding metric is omitted."

作用（原文）："two models can have similar accuracy while differing substantially in whether they solve
directly, use tools selectively, or over-call tools in distractor-heavy environments."

### 4.2 三轴：共用一个 PRR 母公式

论文 §5.2 定义**性能保持率 PRR**（performance retention ratio）。
对每个模型、干扰相似度 $\ell$、目标条件 $C$：

$$
\mathrm{PRR}^{C}_{\ell}=\frac{\bigl|\{q:\mathrm{Correct}_{\mathrm{Gold}}(q)=1 \wedge \mathrm{Correct}_{C,\ell}(q)=1\}\bigr|}{\bigl|\{q:\mathrm{Correct}_{\mathrm{Gold}}(q)=1\bigr\}|}
$$

即：**在 Gold-only 下答对的题，工具环境变化后还有多少仍然答对**（分母是 Gold-only 答对集，不是全集）。

由此派生三轴：

| 轴 | 公式 | 原文定义 |
|---|---|---|
| **Adaptability** | $\mathrm{PRR}^{\mathrm{DO}}_{1}$ | "measures the retention of model performance when gold tools are replaced entirely by distractors (i.e., the **Level 1 Distractors-only** condition). Higher Adaptability indicates the model can compensate for missing gold tools via internal reasoning or alternative tool paths." |
| **Robustness** | $\mathrm{PRR}^{\mathrm{GP}}_{\ell}$，$\ell=1..5$，另报 mean±std | "measures success retention when distractors are added as a noise (i.e., the Level $\ell$ **Gold-present** condition). Higher Robustness indicates less disruption from distractors." |
| **Tool Connectivity** | **无闭式公式**：accuracy 作为 *number of executed tool calls* 的函数（曲线，图 2） | "whether models can preserve correctness as the executed tool-use trajectory becomes longer ... the ability to chain tool calls, reuse intermediate observations, and maintain a coherent execution path across multiple dependent steps." |

**⚠️ 重要修正（对我方原阅读报告）**：Tool Connectivity **不是一个标量指标，是一条曲线**
（横轴 = 已执行工具调用数，纵轴 = accuracy；设置：Plan+ReAct、$k=5$、Level 3）。
论文还专门强调了曲线的**读法陷阱**：竖虚线标的是"该模型最后被观测到的调用数"，
**不代表之后 accuracy 归零**。这个约定很关键，见 4.4。

### 4.4 四种模型画像——数字怎么支撑的

1. **工具回避 / tool avoidance（GPT-5）**：Distractors-only 下 Tool-call rate **0.3%**，Tool-Acc 100.0%。

   > "GPT-5 is the most extreme case of this distinction. Its observed curve stays at ceiling-level
   > performance, but **this does not necessarily mean that GPT-5 is the best model at executing long
   > connected tool chains.** Rather, GPT-5 appears to adopt a highly conservative tool-use policy:
   > when a problem would otherwise require a longer sequence of tool calls, it often solves the problem
   > directly or minimizes tool use instead of extending the tool-call trajectory. Thus, the absence of
   > later observations should be read as part of the model's behavior—a tendency to avoid long tool-use
   > chains—rather than as evidence that it would maintain the same accuracy if forced to execute them."

2. **可靠工具使用（Claude-4.6）**：tool-forward，Gold-only/Gold-present 下 Tool-call rate 65.6/67.8%，Tool-Acc 仍 96–98%。

3. **适应性替换（Qwen2.5-7B）**：Adaptability 最高 65.12%，即 gold 工具全撤后仍保住 2/3 的原有成功。对应 §2.3 那条"凑参数"trace。

4. **不可靠工具目录的伤害（Llama3-8B）**：
   > "it calls tools in over 90% of Distractors-only instances, yet its Tool-Acc remains below 10%."
   （实测 92.9% vs 8.7%）——**过度调用 + 完全无效**，Adaptability 仅 8.63%。

### 4.5 其他判分相关结论

- **难度主轴是 logical hop，不是干扰项**：
  > "Accuracy decreases with logical-hop count even when gold tools are available... Thus, logical-hop
  > complexity is the dominant intrinsic difficulty axis, while distractor similarity acts as an
  > amplifying catalog-level factor."
- **hop 的定义方式**（附录 E.3）：先让模型抽 linearized solution steps，再逐步判断能否与已有 hop group **并行**；
  能并行则并入该组、**hop 不加一**，否则新建组、hop +1。绘图时报 hop 1–7，$\ge 8$ 归入 `hop8+`。
- **失效分类法（§5.5 / 附录 J）**，非互斥 9 类：planning、tool selection、tool hallucination、
  parameterization、formatting、reasoning、observation use、repeated calls、incomplete execution。
  核心发现："**tool selection errors become more broadly coupled with other errors** when distractors
  are introduced or when gold tools are removed"——工具目录质量会改变失效模式的**耦合结构**，不只是频率。
- **ToolMATH-Hard 的作用**：Gold-only 与「No tools / Distractors-only」之间的 gap **显著更大**，且**在高 hop 处尤其明显**。
  反过来说，主集"许多实例仍可通过内部推理或替代工具路径解出"——**这是它自己承认的主集判别力局限**。
- **框架敏感性（§5.6）**：Gold-only 下比较 No tools / ReAct / DFSDT / Plan+ReAct，
  "controller differences are modest at low hops but become clearer at higher hops, where explicit
  planning more consistently preserves accuracy."

## 5. agent 装备（论文附录 H，逐字）

**评测模型**（§4.2）：GPT-5、Claude-4.6、Gemini-3.1-Pro、GPT-4o-mini、Llama 3-8B、Qwen 2.5-7B。

**主协议 = Plan+ReAct**（另比较 ReAct-only、DFSDT）。

**Planner system prompt（逐字）**：
```
You are an expert planner for competition-math problems.
Given the problem and available tools, write a concise, structured step-by-step
    plan.
Use a numbered list (1-7 steps). If a tool is needed, mention its exact name.
Do not solve the problem or compute final values.
Do not include any numeric answers or intermediate calculations.
Do not include explicit numbers, computed values, or worked examples; refer
    abstractly to the needed computations.
```

**Solver system prompt（逐字）**：
```
You are an expert competition-math solver.
For every turn output *exactly one* line beginning with "Thought: ...".
If your next action or tool choice deviates from the provided plan, include the
    token <PLAN_CHANGED>
in the Thought line for that turn (only when a deviation happens).
If you need a tool, follow IMMEDIATELY with ONE line:
Action: { "name": "<tool>", "arguments": { ... } }
Then WAIT for the Observation line before thinking again.
Never call a tool with the same arguments twice - reuse the prior Observation.
If you have already called a tool with the same name and identical arguments, DO
     NOT call it again; reuse the cached Observation verbatim and move forward.
Finish with:
ANSWER: <numeric answer>
```

> `<PLAN_CHANGED>` 这个 token 很值得注意：**它把"偏离计划"变成了可在 trace 里 grep 的显式信号**，
> 而不是靠事后 LLM 判断。这是低成本拿到"计划-执行一致性"信号的一个具体做法。

**工具接口约定（附录 H.1）**：
- Tool visibility：只给 name + description + typed input schema，**"Tool implementations are hidden and executed by the environment."**
- Action 格式：单行 `Action:` + JSON `{ "name": "<tool_name>", "arguments": {...} }`；
  **"The environment rejects malformed JSON or schema-invalid arguments."**
- Observation：必须等环境返回 `Observation:` 行才能继续
- **Duplicate-call guardrail**：禁止重复完全相同的 `(name, arguments)`；
  "This is enforced both as an instruction and by a trace-level cache used in evaluation."
- 终止：单行 `ANSWER: <numeric answer>`

**预算与守卫（附录 H.5 / H.6）**：

| 项 | 值 |
|---|---|
| Step budget（ReAct / Plan+ReAct） | **16 model steps**，因每步最多 1 个 Action，故工具调用数也 ≤16 |
| 每题 wall-clock timeout | **120 秒** |
| 单次工具执行 timeout | **60 秒**（超时→observation 置为错误信息，run 继续） |
| Duplicate-call cache key | `(name, arguments)`，参数做 canonical serialization（sorted keys + normalized numeric forms） |
| 重复调用处理 | 返回缓存 observation + 显式提醒；多次重复后**忽略**并要求推进或输出 ANSWER |
| Action 解析失败 | 返回显式 error observation 并继续；非进展步骤会注入格式提醒 |
| LLM 调用重试 | 最多 **5 次**，指数退避（base 0.8）+ jitter；耗尽则终止该 episode |
| Decoding | solver **temperature = 0.0**；Plan+ReAct 的 planner **temperature = 0.2** |

## 6. 构造流水线（值得借的部分）

**工具抽取 prompt（附录 E.1，逐字节选）**：
```
You are a Python function-generator for a math-solver system.

**Task**
Extract every *reusable* helper function that appears implicitly in the
following solved problem. Each function should capture a general
mathematical operation. Aim for **multiple small functions** if the
solution has several distinct steps.

**Output format**
Return a **JSON array**. Each element is an object with **exactly** these keys:
- "name"        - concise snake_case identifier
- "description" - what the function does and parameter informations.
- "inputs"      - dict {"param": "<python_type>"}
                  allowed types: <WHITELISTED_TYPES>
- "function"    - full Python 'def' (no explanations)
...
If **no reusable function** can be identified, output an *empty array* '[]'.
Do NOT wrap the JSON in markdown fences.
---
Problem:
{problem}

Solution:
{solution}
```

**实测到的类型白名单**（`<WHITELISTED_TYPES>` 的真实取值，从 362 条记录统计）：
`dict`, `float`, `int`, `list[float]`, `list[int]`, `list[list[float]]`, `list[list[int]]`, `list[string]`, `str`, `string`
（注意 `str` 与 `string` 并存——白名单本身不够干净）

**三段式验证与修复（§3.3.2 + 附录 F）——这套是它"benchmark 噪声不与模型错误混淆"的核心**：

1. **Tool-wise validation**：每个工具用 rule-based generator 生成 **5 个 schema-valid 测试输入**
   （覆盖 nominal / boundary / random），执行拿到实际输出，交给 **3 个 validator（GPT-4o、Llama 3-8B、Qwen 2.5-7B）**
   判断"实际输出是否符合 description 语义"。每个 case **多数投票**，**5 个 case 全过**才算通过。
   > "validators do not generate replacement answers, but instead judge whether the implementation
   > output matches the natural-language specification." ← 判断而非生成，降低单一 judge 依赖。

2. **Question-wise validation（trace-based）**：用**与正式评测同一套 Plan+ReAct**跑，
   validator set $M$ = {GPT-4o-mini, Llama 3-8B, Mistral-7B, Qwen2-7B, Qwen 2.5-7B, Phi-3 Medium, Yi 1.5-9B}。
   工具 $t$ 通过 iff 存在某 validator **既答对 $p$ 又在 trace 里成功调用过 $t$**；
   题 $p$ 保留 iff $\mathcal{G}(p)\cap T_{qw}\neq\emptyset$。
   $$T_{qw}=\bigcup_{p}\ \bigcup_{m\in M,\ \mathrm{Correct}(p,m)=1} C(p,m)$$

3. **人工定向审计与修复**：被拒 episode 人工看；可解则恢复，否则改 description/实现后**重跑 1、2 两步**；
   修不好的**踢出 release**。→ 修不好的那批题就成了 **ToolMATH-Hard**（329 题 / 362 人工工具）。

## 8. 对我方的可借与可打点

**可借**：
1. **嵌套干扰项**（前 $k$ 个取自固定 100 项有序表）——让"干扰强度"成为干净的单变量，加量不换质。我方候选池注入近邻实体时可直接照抄这个结构。
2. **`<PLAN_CHANGED>` token**——把"偏离计划"做成 trace 里可 grep 的显式信号，零成本拿计划-执行一致性。
3. **PRR 母公式（分母 = Gold-only 答对集）**——比"绝对准确率下降"更能分离"本来就不会"和"被环境搞坏了"。我方 cp 链判定可引入同构的"保持率"。
4. **两段式验证里的 trace-based question validation**——用**与正式评测同一套协议**做数据集准入，保证"题目至少有一条可达的工具路径"。这条正对我方 cp 链的可达性校验。
5. **判断而非生成的多模型 validator + 多数投票 + 全 case 通过**——降低单 judge 依赖的具体配方。

**可打点（引用时的边界）**：
- 它是**数学域**，工具由解题步骤**合成**，非真实科学 oracle；论文自己在 Limitations 里承认
  "emphasizes symbolic tool use rather than interaction with real-world APIs, services, or dynamically
  changing environments"。→ 不满足我方"工具需覆盖真实科学接口"这条边界，归入"工具调用评测"类。
- **Tool Connectivity 是曲线不是标量**，且论文承认它与"工具回避"混淆（GPT-5 那段自我限定）。
  我方若借用这个名字对外表述，需要自己补一个标量化定义，否则不可比。
- 主集判别力有限：论文自承主集 "often shows a smaller Gold-only vs. Distractors-only separation,
  suggesting that many instances can still be solved through internal reasoning or alternative
  tool-consistent paths"。真正有区分度的是 329 题的 Hard 集。
- 三轴的真实数字**只覆盖 GPT-4o-mini / Llama3-8B / Qwen2.5-7B 三个弱模型**（表 2），
  三个前沿模型（GPT-5 / Claude-4.6 / Gemini-3.1-Pro）在 Gold-only 就已 98–99% 饱和，**Adaptability/Robustness 无从测起**。
  引用"三轴"时不要暗示它已在前沿模型上验证过。
