# Desktop-Delta Bench · 离线 step-level 评测，含 463 个时序排序题

> **原文**：Desktop-Delta Bench: Do Computer-Use Models Understand Desktop GUI Transitions?
> **作者**：Abhishek Pillai, Samir Kumar Nayak, Yuan Chen
> **出处**：arXiv:2607.26041，2026-07-28（v2 07-29），cs.AI / cs.CV
> **阅读方式**：基于完整摘要与元数据

---

## 0. 一句话

**它是"顺序"这个维度里少见的显式评测**——463 个**三帧时序排序**实例，直接测"模型能否重建某个动作所产生的因果转移"。

**但它是离线出题（让模型给帧排序），不是判 agent 自己执行的顺序**（详见 §4）。

---

## 1. 数据量与成绩

| 项 | 数值 |
|---|---|
| 总实例 | **2,013 条**，全部人工验证 |
| 来源 | 全新的多应用 Linux 轨迹，约 **15 个应用**、**50 个任务域** |
| **时序排序子任务** | **463 条**三帧排序实例，其中 **105 条含跨轨迹诱饵**（decoy） |
| 前后对照子任务 | **1,550 条** before-after 配对，标注自 5 类动作 + 载荷 |
| 被测 | 8 个闭源与开源模型族，32 种排序设置 + 16 种单动作设置 |
| **排序最佳成绩** | 非诱饵 **65.1%** · 诱饵 **65.7%**（作者称"未饱和"） |
| 单动作 | click F1 **0.96** vs drag **0.76**（推断动作类型比定位更难） |

**一个有意思的错误模式**：`error analysis reveals systematic copying of the presented A-B-C order`（模型系统性地照抄题面给出的 A-B-C 顺序）。

---

## 2. 它针对的三个失效维度

**state verification（状态验证）· source tracking（来源追踪）· context-aware control（上下文感知控制）**

它指出的根因很值得记：**推理、远程输入、应用渲染、截图捕获是异步的**，所以下一帧观测可能延迟、被遮挡、短暂出现或干脆无关，**然后被误读为"有进展"并带入后续规划**。

---

## 3. 它的定位

> `DDB, thus, complements end-to-end benchmarks by filling the missing diagnostic layer between GUI grounding and final task success.`
>
> （DDB 填补了 GUI grounding 与最终任务成功之间**缺失的诊断层**。）

---

## 4. 与我们的准确差异

| | Desktop-Delta | 我们 |
|---|---|---|
| 判谁的顺序 | 让**模型**给三帧排序（模型是答题者） | 判 **agent 自己执行轨迹**的顺序 |
| 形式 | **离线**、静态题目 | **在线**、从实跑轨迹取证据时间戳 |
| 真值来源 | 人工标注的帧序 | 网关录像时间戳 |
| 允许多解 | 不允许（帧序唯一） | **允许**（拓扑排序多解，见 ADR-0021） |

---

## 5. 对我方：可借 / 可打点

**可借**：①"填补缺失的诊断层"这个定位表述好用；②它的 **decoy（诱饵）设计**值得借——在候选池里塞入跨题的干扰项，看 agent 会不会误用（与 ToolMATH 的分级干扰项同理）。

**可打点**：它是 GUI 域、离线题、单模态判定，不满足我们的长程边界。但因为它是"显式判顺序"的少数工作，在对比文档的顺序一节必须列出并说清差异，否则会被认为遗漏同类工作。

## 6. 证据锚点

- 2,013 条 / 15 应用 / 50 域：摘要第 4 句 ｜ 463 + 105 诱饵 + 1,550 配对：摘要第 5 句
- 65.1% / 65.7%：摘要第 7 句 ｜ 照抄 A-B-C：摘要第 8 句
