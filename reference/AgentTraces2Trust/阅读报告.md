## 0. 一句话

**它把我们做的这件事给了一个正式定义**：

- **execution provenance（执行溯源）** = 一次 agent 执行的**带类型的图**（typed graph）；
- **evidence tracing（证据追溯）** = 该图在**证据-支撑关系**上的投影。

**我们的 checkpoint DAG + 真值反查，正好就是这两者的一个具体实例。**

---

## 1. 它列出的"终态准确率解释不了"的五件事

摘要原文指出，仅凭终答准确率**无法说明**：

1. 这个输出是**怎么产生**的；
2. **哪条证据支撑了哪个断言**；
3. **工具调用是否合理**（whether tool calls were justified）；
4. **记忆如何影响了后续决策**；
5. **失败源自哪里**。

**这五条可以直接作为我们对比文档"为什么只判终态不够"那一节的骨架**——比我们自己列的理由更系统。

## 2. 它的分类维度（六个）

**trace sources（轨迹来源）· evidence and execution units（证据与执行单元）· provenance relations（溯源关系）· tracing granularity and timing（粒度与时机）· representation forms（表示形式）· trust functions（信任函数）**

**覆盖的方法方向**：溯源表示 · 证据归因 · 工具使用溯源 · 运行时护栏 · 带溯源的记忆 · 可观测性 · 失效诊断。

## 3. 对我方：可借 / 可打点

**可借（这是本篇最大价值——给我们的机制一个学术定位）**：

我们此前描述自己的机制用的是工程语言（"per-case 视图""从 tool call 反查"）。这篇提供了学术表述：

| 我们的说法 | 学术表述 |
|---|---|
| checkpoint DAG + 证据时间戳 | **execution provenance**（带类型的执行图） |
| 真值从 tool call 反查 | **evidence tracing**（证据-支撑关系的投影） |
| 未查证就声称则 cp3 记 0 | **evidence attribution**（证据归因）失败 |
| 卡点 + gate | **trust function**（信任函数） |

**写论文时应采用这套术语**，能让评审立刻定位我们在文献中的位置。

**可打点**：它是综述（cs.CR 视角，偏安全审计），不含题集与判分协议。归入"方法论框架"类。
