## 0. 一句话

用 32 个真实软件、604 个 MCP 工具搭一个"真办公/真运维"考场，108 道题平均要跨多个应用做约 20 轮工具调用，每题配一个人工写的确定性评测脚本，最强模型（Claude-4.5-Sonnet）只有 38.6%。

## 1. 数据量

| 量纲 | 数值 |
|---|---|
| 任务数 | **108** 道（人工搜集或人工编写） |
| 应用数 | **32** 个软件（Google Calendar、Notion、WooCommerce、Kubernetes、BigQuery、Canvas…） |
| 工具数 | **604** 个（大部分基于团队自己修订/实现的高质量 MCP server） |
| 平均交互 | **约 20 turns**（最优模型实测 20.2 次工具调用） |
| 评测脚本 | 每题 **1 个**专属、确定性的 evaluation script |
| 评测口径 | 每模型跑 3 次，报 pass@1（均值±std）、pass@3、pass^3 |

**关键读数：108 道题就能中 ICLR 2026。** 数据量不是这条赛道的门槛，**环境真实度 + 判分可靠性**才是。

## 2. 数据集形态

一条样本 = **（自然语言任务指令，初始环境状态快照，专属评测脚本）** 三元组。

- **任务指令**举例（论文 Figure 2 原文）："检查邮箱里的 homework2 提交，把 Python 附件下载到本地 workspace、逐个在终端执行查错，无错的在 Canvas 上打 10 分，否则……" —— 一句话里串了邮件 / 文件系统 / 终端 / Canvas 四个系统。
- **初始状态是真的**：不是空环境，而是从真实软件导出的状态——"含几十名学生的 Canvas 课程"、"真实财务电子表格"。论文明确把这点作为对前人的主要改进（前人只保证 functional realism，环境状态多样性不足）。
- **形式化**：每个任务被写成一个 POMDP。
- **可复现工程**：所有服务在评测前重置（他们批评前人"只用只读任务绕开重置问题"）。

## 3. "长"体现在哪

1. **turn 数**：平均 ~20 轮工具调用，是主指标层面明确写进 Abstract 的"长"来源；
2. **跨应用状态耦合**：一个任务的后续动作依赖前面动作在**另一个系统**里留下的副作用（下载文件 → 执行 → 回写成绩）；
3. **工具选择空间**：604 个工具里选对的那几个，长上下文里的工具检索本身构成难度。

## 4. 判分粒度

**执行式二元判分，无部分分、无过程分。**

- 每题一个手写脚本，比对最终环境状态与静态或动态生成的期望结果；
- 指标只有 pass@1 / pass@3 / pass^3；
- **没有中间 checkpoint**：一个 20 步任务错在第 3 步和错在第 19 步得分完全一样（都是 0）。

⚠️ **这就是我们要打的点。** ICLR 2026 的长程 benchmark 标杆本身承认"任务很长"，但判分依然是 all-or-nothing，因此**无法区分"接近成功"与"完全跑偏"，也无法给 RL 提供 dense signal**。我们的 checkpoint DAG + reward∈[0,1] 正好是这个缺口的解。

## 5. 对我方：可借 / 可打点

**可借**

1. **规模标定**：108 题 / 20 turns 就是 ICLR 2026 的合格线。我们不需要造几千题，**把 100–200 道题的环境真实度与判分可靠性做到位更重要**。
2. **"每题一个手写确定性脚本"是可以被接受的成本**——不必追求全自动生成判分器。我们的 `reward` 表达式 + `property_spec` 已经比手写脚本更结构化，是加分项。
3. **环境重置 + 状态快照**做法可直接映射到我们的 mock 数据库快照机制。
4. **pass^3（三次全对才算过）**是一个便宜且有力的稳定性指标，建议我们也报。

**可打点**

| 维度 | Toolathlon | 我们 |
|---|---|---|
| 判分 | 终态二元 | checkpoint DAG + 部分分 + 路径闸门 |
| 领域 | 通用办公/运维 | 材料 / 药物发现（撞我们红线 2 的反面：他们正是"通用 agent 任务"） |
| 对 RL 的可用性 | 只有稀疏终态奖励 | 天然提供过程级 verifiable reward |
| 抗污染 | 未处理（真实软件状态） | 分子匿名化 |

**引用姿态建议**：把 Toolathlon 作为"长程但只评终答"的代表证据写进 Introduction 的 gap 段落——它是最强的、最新的、来自同一会议的证人。
