## 0. 一句话

把科学研究 agent 的评测从"各家自造题、各家自带工具"收敛为一个受控套件：2400+ 题覆盖科学发现全流程，配**第一个自带生产级检索工具的科研环境**（保证工具可及性一致、可复现），并附 9 类 Asta agent + 大量 baseline；结论是 AI 距"解决科研助理"仍很远。

## 2. 数据集形态

- 每个子 benchmark 保留原有样本形态（QA / 选择题 / 造表 / 代码 / 数据分析 / 端到端），但**统一被"Asta 环境"包住**：
  - **Asta Scientific Corpus**：通过 MCP 暴露 8 个检索工具（`snippet_search`、`search_papers_by_relevance`、`get_paper`、`get_paper_batch`、`get_citations`、`search_authors_by_name`、`get_author_papers`、`search_paper_by_title`），并**按题设定语料日期截止**（exclusive），从根上掐死"用未来文献作弊"。
  - **Computational Notebook**：一个有状态的 Jupyter 内核，可执行 Python 与 IPython magic。
- 原始数据集被**过滤**过：只保留"在本环境工具下确实可答"的题。

## 3. "长"体现在哪

AstaBench 的"长"是**流程链条长**，不是单题步数长：

1. **跨阶段串联**：文献检索 → 文献理解 → 代码执行 → 数据分析 → 端到端发现，覆盖"科学发现全流程"；
2. **E2E-Bench 是真正的长任务**：一题要求 agent 从头做完一个小型研究（提出方法、写代码、跑实验、给结论）；
3. **成本也是一条"长"的轴**：论文把 **model cost 与 tool access 明确列为混淆变量**并加以控制——这是很少有 benchmark 做的，也是"长程 agent 评测"的隐藏成本维度。

## 4. 判分粒度

各子 benchmark 沿用自身判分（execution-based 为主，报告类用评分标准）。**AstaBench 的贡献不在判分粒度，而在"控制混淆变量"**：
- 工具必须来自统一环境（否则不可比）；
- 必须报告 cost；
- 必须有 comprehensive baseline 才能识别真实进步。

它列出的现有 benchmark 五大缺陷（可直接作为我们的自检清单）：
1. 缺可复现的 agent 工具，无法做受控比较；
2. 未控制 model cost 与 tool access 这类混淆变量；
3. 没有标准化接口便于快速原型与评测；
4. 缺乏"产品化视角"的整体度量（不贴真实使用场景）；
5. 缺乏充分的 baseline agent 以识别真实进展。

## 5. 对我方：可借 / 可打点

**可借（这是一份免费的审稿人 checklist，务必逐条落实）**

1. **统一环境 + 工具随 benchmark 出厂**：我们的取数网关（`dag_poc/docs/INTERFACE_CONTRACT.md`）正是这个东西，但要**明确写成"工具是 benchmark 的一部分，不是被测方自带"**，并强调这保证了可比性。
2. **报告成本**：我们必须报每题 token/API 花费。ScienceAgentBench 也这么做。
3. **数据截止 / 防污染要写成机制不是声明**：他们用"语料日期截止"，我们用"分子匿名化 + mock 数据库"。这一栏必须在对比表里显式打勾。
4. **必须给 comprehensive baseline**：不只是 GPT/Claude 直接跑，还要给"我们自己实现的若干参考 agent（含金标准回放、空转、陷阱）"——我们四档轨迹实跑已具备雏形，要写进论文。
5. **端到端类只有 40 题**——可以直接引用作为"我们 100+ 题不算少"的论据。

**可打点**

| 维度 | AstaBench | 我们 |
|---|---|---|
| 过程 | 无中间 checkpoint 判定（各子集沿用终答/执行判分） | checkpoint DAG |
| 领域 | 以 CS + 生物文献为主，**没有分子/材料性质发现** | 材料 + 药物分子发现 |
| "发现"的定义 | 数据分析式发现（DiscoveryBench 式：从数据里找关系） | 分子级发现（找到满足性质窗口的具体分子） |
| 真值 | 论文/数据集既有答案 | 科学数据库反查值 |
