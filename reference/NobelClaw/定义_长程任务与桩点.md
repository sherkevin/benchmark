## 0. 一句话

> **长程任务 = 一句科研目标,agent 必须走完一条「多阶段、强依赖、状态累积、误差会放大、奖励在末端」的链才能交付。桩点 = 这条链上一个个可机器测量的中间检查点,专门用来抓 agent 在哪一步「走偏」。** 只看最终答案在长程任务里是失效的——这正是本 benchmark 要评过程量的根本理由。

---

## 0.5 白话词典(术语先读这个,后面就不卡了)

> 这些词在本文和三个 case 里反复出现。先扫一眼。

| 术语 | 一句话白话 |
|---|---|
| **trace(轨迹/录像)** | agent 干活的**全过程录像**:每一步调了什么工具、得到什么数、说了什么话,全记下来。我们就是对着这份录像打分。 |
| **桩点 / ckpt(检查站)** | 录像里的一个"检查站"。agent 走到这儿,我们量一个具体的东西,看它有没有走偏。 |
| **GT(真值 / 标准答案)** | 这一步的标准答案,用来对照 agent 对不对。必须来自真实实验 / 已发表论文 / 公开数据库,**不许我们瞎编**。 |
| **rubric(评分细则)** | 一张"打分清单",像老师评分标准:"答到给 1 分,答一半 0.5,没答到 0"。用在脚本判不了、得靠 AI 按清单打分的检查站。 |
| **人编细则**(= 我们手写的) | "作者 / 制作方" = **我们这些搭 benchmark 的人**(不是论文作者)。有些东西没有现成真实答案可对(如"策略好不好"),只能我们手写一张打分清单。 |
| **交叉验证** | 不光听 agent 嘴上说,还**回头核对它前面到底做没做**(报告说的数,回查录像是不是真算的)。 |
| **可转硬判** | 本来要 AI 打分的"软"检查站,换个问法变成脚本能判的"硬"检查站。例:"反应合理吗?"(软)→"凋亡升还是降?"(硬,看正负号)。 |
| **Tier 1 / 2 / 3(三档)** | 谁来判:T1=脚本判(最好,跑一万次都一样);T2=AI 按细则判(要校准);T3=人工判(最贵,尽量不用)。 |
| **走偏 D1–D7** | agent 跑歪的 7 种方式(见 §4):方向错 / 数值飘 / 漏步 / 前后接不上 / 瞎编 / 吹牛不收手 / 犯规。 |
| **加权不连乘** | 算总分时各站分数**加起来**(带权重),不是相乘——一步偏不会清零整题,还能看出偏在哪。 |

## 1. 长程任务的 6 条判定性质(必须同时成立)

一道题是不是"长程",不看步骤数表面多少,看下面 6 条是否**同时**成立:

| # | 性质 | 反面(短程) |
|---|---|---|
| 1 | **链长**:目标到答案隔着多阶段,不能一步/一次工具调用解决 | 一次调用即得("预测 MgB₂ 的 Tc") |
| 2 | **强依赖不可并行**:后一阶段吃前一阶段的产出,断了走不下去 | 子任务相互独立、可并行 |
| 3 | **状态跨步累积**:必须记住并整合一路中间产物,长上下文不丢 | 无状态,单轮 |
| 4 | **误差沿链放大**:早期一个小错会逐级传导,终点看不出错在哪 | 错就错在当步,一眼可见 |
| 5 | **奖励稀疏 / 延迟**:走到很后面(甚至要等实验/文献验证)才知对错 | 即时对错信号 |
| 6 | **路径数据驱动、agent 自主决策**:走哪步、何时换策略、何时停,取决于沿途观测 | 固定流程,无决策 |

> **6 条全中** = 长程。缺任一条都算短程,不进 30 题(但可作为某长程题里的一个桩点)。

## 2. 一道合格长程 benchmark 题的硬判据(立题验收门)

立一道题前先过这道门;任一条不过,**不允许立题**。⬜ = 数值待 owner 拍板,先给推荐默认值。

| 判据 | 推荐默认 | 为什么 |
|---|---|---|
| **阶段数** ⬜ | ≥ 4(从 策略/探索/决策/提交/报告 自然阶段里至少占 4) | 少于 4 难称"程" |
| **死依赖处数** ⬜ | ≥ 2(stage N 输入 = stage N-1 产出,断链走不下去) | 区分"长程"和"并排小题拼盘" |
| **工具调用总数** ⬜ | ≥ 10 | 真有"程"可走、误差才会放大 |
| **桩点数** | ≥ 5,每个阶段 ≥ 1(不许有黑箱阶段) | 过程要测得到 |
| **Tier 1 占比** | ≥ 70%(沿用 `checkpoint_palette.md` 配额铁律) | 可复现、低成本 |
| **走偏探测器** | ≥ 2 个桩点专门抓某类走偏(见 §4) | benchmark 的命根:不是测"对不对",是测"哪步偏了" |
| **终态 GT 锚定** | 必须锚到真实(已发表 / 实验 / 公开数据库),非编造 | `goal.md` 红线 |

**反例(不达标)**:"预测某分子 logD"、"对比 A 与 B 的 Tc"——单步/双步,无死依赖,误差不放大 → **不是长程题**,只能当桩点。

## 3. 桩点(checkpoint / ckpt)定义

> 一个桩点 = trace 里一个**可测量的中间检查点**。好不好,看**谁来判、能不能复现**(沿用三档)。

每个桩点必须记 **6 件事**:

```
{ 阶段, 桩点描述, 测什么, 档(Tier1/2/3), 判定方法, GT来源, 抓哪种走偏,
  track(科学/编排), backend_class(real-compute/mock-sensitive/mock-canned), gt_class(external-anchor/rule/internal-consistency) }  // 后三标签据 决议/0003
```

档与类型沿用 `task6/checkpoint_palette.md`:

- **Tier 1 硬校验**(主力 ≥70%)= 机器跑脚本,6 类:**数值 / 集合 / 排序 / 结构 / 守恒 / 工具落地**
- **Tier 2 AI 判官**(少量)= LLM 按 rubric 判,近二值;需 κ 校准
- **Tier 3 人工**(尽量不用)= 仅给 Tier 2 当标尺

## 4. "走偏"类型学(桩点要能抓的偏)—— 本文核心

长程任务里 agent 会以 **7 种方式走偏**;每道题的桩点至少要覆盖其中 ≥2 种。设计桩点时,明确它抓哪种:

| 代号 | 走偏类型 | 长什么样(例) | 最适合的桩点档/类型 |
|---|---|---|---|
| **D1** | **方向偏** | 一开始就盯错靶点 / 选错策略 | T2 策略 rubric;或 T1 结构(靶点 ID 合法性) |
| **D2** | **数值漂移** | 中间预测值超出真值容差(Tc 预测离谱) | T1 数值 |
| **D3** | **跳步 / 漏步** | 该做的阶段没做(漏了 novelty 检查 / 漏了稳定性过滤) | T1 工具落地(查 trace 有没有调) |
| **D4** | **依赖断裂** | stage N 没真用 stage N-1 的产出(生成候选时无视已锁定的目标体系) | T1 集合(产出 ∩ 上游约束) |
| **D5** | **幻觉 / 无依据** | 报告里的结论在 trace 里找不到支撑数据 | T2 语义(交叉验证)/ T1 结构 |
| **D6** | **过度声称 / 不知停** | 没验证就宣布成功;或该停不停继续烧 | T1 工具落地 + T2 语义(诚实标注) |
| **D7** | **约束违反** | 用了有毒/放射性元素、超预算、违反守恒律 | T1 守恒 / 集合 |

> **设计纪律**:同一阶段叠**不同走偏类型**的桩点(防钻空子——形式对但内容空);部分得分**加权求和不连乘**(一步偏不归零,但能定位偏在哪)。

## 5. 评分(沿用 `construction_methodology.md` §5,不重述)

- per-cp:`weight_i × verifier(trace, cp_i)`,verifier ∈ [0,1]
- per-stage / per-task:加权部分分 `R/T`(不连乘)+ critical cp 全过奖励
- 介入维度:同题跑 L0–L3,出介入-成功率曲线 + autonomy@0
- 主指标:过程量得分 vs 终答得分的 **agent 排名差异**(排名一样=过程量没测出新东西)
