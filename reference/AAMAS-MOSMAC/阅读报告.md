## 0. 一句话

在 StarCraft II 上造一个多目标版 SMAC：agent 群体要完成一串**相互关联的顺序子任务**，同时平衡战斗（combat）、安全（safety）、导航（navigation）三个（或两个）目标；对 9 个 SOTA MARL 算法做系统评测，证明**长程场景**是现有方法的主要短板。

## 1. 数据量

| 量纲 | 内容 |
|---|---|
| 基座 | StarCraft II（沿用 SMAC / SMACv2 设计原则，便于与既有场景直接对比） |
| 目标数 | **2 个**（combat + navigation）或 **3 个**（combat + safety + navigation） |
| 单位类型 | **3 类**：siege tanks、marines 等 |
| 任务结构 | 每个任务含**一个或多个顺序子任务**；可生成替代任务序列以研究不同变体 |
| 被评算法 | **9 个** SOTA MARL 算法 |
| 论文体量 | 10 页（AAMAS Research Paper 标准） |

## 2. 数据集形态

一条样本 = **一个 StarCraft II 场景配置**，含：
- 地图 / 单位组成 / 初始态；
- 一串顺序子任务（每个子任务有各自的目标位置或战斗要求）；
- 每个目标一个独立的奖励函数：`r_c`（combat：击杀/伤害）、`r_s`（safety）、`r_n`（navigation：到达目标位）；
- 观测空间含"移动可行性"等要素；动作空间含 no-op。

**多目标聚合**：用带权效用把 MODec-POMDP 转成单目标问题（权重可调），并可做 Pareto 前沿近似（L 维目标空间）。

## 3. "长"体现在哪

论文对"为什么长程更难"给了明确的理论与工程论述，这部分值得引用：

1. **顺序子任务串联** + **可变时间跨度**（varying temporal horizons）是 benchmark 的一等设计维度；
2. **长程下多智能体探索与时序 credit assignment 同时变难**（论文明确对比短程场景）；
3. 引用理论结果：**最优值函数假设空间的广义 Rademacher 复杂度随规划 horizon 增长**，可能导致收敛问题与局部最优；
4. 实证：缺少 combat 目标的配置会产生**奖励信号不足**，说明长程 + 多目标下奖励设计极其敏感。

## 4. 判分粒度

**环境原生的多目标奖励（每步给）+ 子任务完成情况**。
严格说它是**有过程信号的**（顺序子任务的完成本身就是里程碑），但这些信号是**RL 环境奖励**，不是"评测判据"——它不评"agent 的推理过程对不对"，只评"策略回报高不高"。

## 5. 对我方：可借 / 可打点

**可借**
1. **"顺序子任务 + 多目标"的组合确实是长程难度的有效来源**。我们的 open_discovery 模板（objectives 判优）与它同构；可以借它的**带权效用 + Pareto 前沿**表述来规范化我们的多目标判优（目前我们是"门槛×达成度"，Pareto 表述更学术、更好写）。
2. **奖励信号不足的实证教训**：他们发现去掉 combat 目标就学不动。映射到我们：**若 checkpoint 的 reward 稀疏或尺度失衡，RL 会学不动**——这是我们必须在实验里检查的（对应 T-18 快照扩容 / 拉开区分度）。
3. **引用 Rademacher 复杂度随 horizon 增长**这个理论点，是给"长程为什么难"提供理论支撑的低成本引用，写 Introduction 有用。

**为什么 AAMAS 不是我们的目标会议（关键结论）**

| AAMAS 的核心身份 | 我们的硬边界 |
|---|---|
| **多智能体**（协作/博弈/社会仿真） | GOAL.md §3.1：**单 Agent**（被测对象是一个智能体，非多智能体协同） |

从 DBLP `conf/ifaamas` 2023–2025 检索结果看，AAMAS 与 agent benchmark 相关的论文分两类：
- **MARL benchmark**（MOSMAC、EnEnv、TaxAI、Neural MMO 鲁棒性、Imitation Learning Datasets 工具箱）；
- **LLM 多智能体社会/博弈仿真**（LLM agents 的合作演化、社会困境、人格驱动决策、洗钱数据生成、多语言语音 agent 网络）。

**两类都要求"多个 agent"**。我们若投 AAMAS，唯一可行方式是把 benchmark 改成多 agent 协作发现——**这会直接违反 GOAL.md 的硬边界 1**，不做。

**结论：AAMAS 不投。** 除非未来单独立项做"多 agent 科学发现协作"，那时 MOSMAC 是最好的形式参照。
