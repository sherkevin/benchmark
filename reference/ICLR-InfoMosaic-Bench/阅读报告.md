## 0. 一句话

第一个专门评"多源信息搜寻"的 benchmark：621 道题、77 个工具、6 个域（医学/生物、金融、地图、视频、网页、多源整合），题目由 **InfoMosaic-Flow** 自动合成——**先用工具跑出可验证的真实输出，再据此反向构造题面**，并强制跨源依赖、过滤掉能被单次简单查询解掉的"捷径题"。GPT-5 只有 38.2% accuracy / 67.5% pass rate；22.4% 的失败来自工具选错或用错。

## 2. 数据集形态

一条样本 = **（自然语言复合问题，一份可验证的答案，一条被工具证据锚定的依赖链）**。

**构造管线 InfoMosaic-Flow（两阶段，这是本文最值得抄的部分）**：
1. **域内工具取证**：先调领域 MCP 工具，拿到**已验证的真实输出**（tool evidence），题目条件全部锚定在这些输出上——即"答案先于题目存在"；
2. **网页验证与精炼**：再用 web 检索交叉验证，去掉噪声/病态题。

**三道质量闸门**（对我们的质量门设计是现成参照）：
- **Tool-Call Filtering**：过滤掉根本不需要调工具的题；
- **Answer–Evidence Consistency**：答案必须与工具证据一致；
- **Coherence Filtering**：题面语义自洽；
- 之后还有**人工复核**。
- **强制跨源依赖 + 捷径过滤**：确保题不能被"一次通用 web 搜索"解掉，保证 non-triviality。

## 3. "长"体现在哪

**"长"来自跨源依赖链的深度，而非交互轮数。**

1. 一道题的答案需要**先在 A 源查到中间量，再用它去 B 源查**，形成硬依赖（这正是我们 DAG 的 `pre` 依赖在信息搜寻语境下的形态）；
2. 通用 web 搜索单独不够（论文核心发现 (i)）——必须组合专业工具；
3. 论文自己把这类能力称为跨工具的 "long-horizon reasoning"，并批评前人（τ-bench、MCP-Bench）只评孤立工具调用的正确性。

## 4. 判分粒度

**终态答案判分**（accuracy + pass rate）+ **失败归因分析**（22.4% 归因于工具选择/使用错误）。
过程本身不判分，但**因为题目由"证据链"生成，理论上具备了做过程判分的全部素材**——这是它留下的现成缺口。

## 5. 对我方：可借 / 可打点

**可借（几乎可以逐条映射到我们的方法）**

| InfoMosaic-Flow | 我们的 GT-first 反查构造法 |
|---|---|
| 先调工具拿到 verified tool evidence | 第 1 步：从科学数据库反查真实分子性质 |
| 据此反向构造复合题面 | 第 2 步：构造隐去答案的专属 query |
| 强制跨源依赖 | 第 3 步：DAG 只连真实依赖 |
| 捷径过滤（去掉单查可解的题） | 我们的"无解题测诚实性"+ 陷阱组，可再补一条**捷径过滤闸门** |
| Tool-Call / Consistency / Coherence 三闸 + 人工复核 | 我们的质量门（金标准全过 + 空转不过 + 指纹防泄漏） |

**结论：我们的方法论在 ICLR 2026 有直接同构先例并被接受**。这极大降低了"方法是否被认可"的风险——写作时应当显式引用它作为方法学同盟（"我们采用与 InfoMosaic-Flow 相同的 evidence-grounded 反向合成范式，并把它从信息搜寻推广到分子发现，且首次把证据链升级为可判分的 checkpoint DAG"）。

**必须补的一条闸门（当前我们没有）**：**捷径过滤**。若一道"找满足性质窗口的分子"题能被"一次数据库范围查询"直接解掉，它就不是长程题。我们要加一条自动检查：用一个"单次全表查询 + 排序"的 trivial baseline 跑全题集，凡被它解掉的题一律淘汰或升难度。

**可打点**

| 维度 | InfoMosaic-Bench | 我们 |
|---|---|---|
| 过程 | 有证据链但不判过程 | 证据链 → checkpoint DAG，逐节点硬判 |
| 领域深度 | 医学/生物是"查资料"层面 | 分子性质层面（ADMET、带隙、Tc） |
| 判分 | 终答 accuracy | 部分分 reward + 路径闸门 |
| 是否有 RL | 无 | 有（完整版） |
