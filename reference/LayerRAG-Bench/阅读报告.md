## 0. 一句话

**它的核心发现直接质疑"只看 groundedness（有没有依据）"这种判法**：

> `Groundedness-only evaluation also produces substantial false positives under stale and wrong-session evidence.`
> （在**过期证据**与**错会话上下文**的情况下，只判 groundedness 会产生**大量假阳性**。）

翻成人话：**agent 引了证据、格式也对，但引的是过期的或者根本不属于这次任务的证据，只查"有没有引"就会误判它对。**

## 2. 它划分的四个失效层次

| 层 | 失效形态 | 能否被 schema 归一化修复 |
|---|---|---|
| **evidence（证据层）** | **stale evidence（过期证据）** | **不能** |
| **tool-contract（工具契约层）** | schema drift（格式漂移）· missing tool output | schema drift **能**（成功率 0.000 → **0.913**）；missing output **不能** |
| **authorization（授权层）** | denied permissions（权限被拒） | **不能** |
| **session-state（会话状态层）** | **wrong-session context（错会话上下文）** | **不能** |

**它的结论原则**：`a reliability intervention should be credited for repairing its target layer without being mistaken for a universal fix`（一项可靠性干预只应在它针对的那一层被记功，不能被误当成万能修复）。

## 3. 对我方：可借 / 可打点

**可借（一条要紧的自查）**：

**我们的 cp3 是"覆盖性检查"——该查的 ID 都查过就给分。按本文的分层，这属于 groundedness-only 判法，可能有假阳性。** 具体到我们的场景：

| 本文的失效层 | 我们是否可能中招 |
|---|---|
| stale evidence（过期证据） | **低风险** —— 我们是闭合快照库，工具返回值恒等于快照真值，不存在"过期" |
| wrong-session context（错会话） | **需自查** —— per-case 视图是按题隔离的，若 agent 在 A 题里查到的值被用于 B 题的答案，我们目前**不检查跨题混用** |
| missing tool output | 我们的降级模式（`no_recording` / `unavailable`）已覆盖 |
| denied permissions | 对应我们的 `UNKNOWN_ENTITY` 拦截码，已覆盖 |

**结论**：第二行是一个真实但概率很低的缺口（单题独立跑，跨题混用的机会不多）。**记录备查，不列为待办。**

**可打点**：它是企业 RAG 域，与我们无竞争。它的价值是提供了"分层归因"的方法论——**判分失败时要能说清失败在哪一层**，这一点我们的 cp1–cp6 天然具备。
