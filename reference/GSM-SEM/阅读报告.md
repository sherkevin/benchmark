# GSM-SEM · 语义变体生成对抗记忆

> **原文**：GSM-SEM: Benchmark and Framework for Generating Semantically Variant Augmentations
> **出处**：arXiv:2605.07053，2026-05-08（v2 2026-05-26）
> **阅读方式**：基于完整摘要与元数据

## 0. 一句话
**它指出现有鲁棒性变体的通病**：大多只做**表面扰动**（改写、改名、换数字、加干扰项），**基本事实没变**；而且静态发布的变体**本身会变成新的记忆目标**。

## 1. 关键数字
| 项 | 内容 |
|---|---|
| 做法 | 扰动**实体、属性、关系**，常常**改变底层事实**，逼模型在新条件下重算 |
| 约束 | 保持原计算/答案与近似难度不变 |
| 关键特性 | **每次运行都生成全新变体**，无需重新标注 → 降低对静态公开基准的依赖 |
| 产出 | GSM8K-SEM · GSM-Symbolic-SEM · GSM-Plus-SEM（三套，全部人工验证并公开） |
| 评测 | 14 个 SOTA LLM，**最强扰动配置下平均掉分 28%** |
| 扩展 | 另应用于 BigBenchHard、LogicBench、NLR-BIRD |

## 2. 机制与判分
题目生成框架 + 变体基准。判定沿用原基准的答案比对（硬）。

## 3. 对我方
**可借（一条值得认真考虑的思路）**：

**"每次运行生成新变体"这个思路可以用于我们的格位出题机制。** 我们的 150 题是**冻结的**，一旦公开就可能被针对性优化。若把出题脚本作为"变体生成器"公开（而非只公开题目），别人每次评测都可从同一库现场抽新格位，**题目本身就不会被记住**。

**但这与 owner 已定的"case 必须工程师手写"存在张力** —— 手写保证精度，脚本生成保证不可记忆。**建议的折中**：手写的 150 题作为**标准集**（用于横向对比），脚本生成的变体作为**抗污染验证集**（用于检查某模型是否针对标准集过拟合）。这是一条具体可执行的方案。

**可打点**：数学域，无工具调用。归入"抗污染方法"类。
