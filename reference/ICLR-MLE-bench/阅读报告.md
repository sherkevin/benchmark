## 0. 一句话

把 75 个 Kaggle 竞赛离线化成一个 agent 考场，用 Kaggle 公开排行榜（人类成绩分布）作为绝对标尺，看 agent 能拿到铜牌以上的比例；最好的组合（o1-preview + AIDE）在 16.9% 的竞赛里达到铜牌水平，agent 每题可自主运行最长 24 小时。

## 1. 数据量

| 量纲 | 数值 |
|---|---|
| 竞赛数（测试集） | **75** 个 Kaggle 竞赛（人工筛选，排除 Community Competitions、无法复现评分或无法重建合理 train/test split 的） |
| 开发集 | 额外 **7** 个竞赛（避免在测试集上过拟合 agent 设计） |
| 复杂度分层 | **Low 23 个（30%）/ Medium 38 个（50%）/ High 15 个（20%）**——按"有经验的 ML 工程师写出实现需要多久（不含训练时间）"划分：<2h / 2–10h / >10h |
| 奖金总额 | 75 个竞赛累计奖金作为"经济价值"参照 |
| 运行预算 | 每题 agent 自主运行**最长 24 小时** |
| 头部成绩 | o1-preview + AIDE：16.9% 竞赛达铜牌；pass@8 提升到约两倍；GPT-4o 24h 8.7% → 更长时间 11.8% |

## 2. 数据集形态

一条样本 = **一个 Kaggle 竞赛**，包含：
- 竞赛描述（任务说明）；
- **竞赛数据集**——多数情况下由作者**从公开训练数据重新切分出新的 train/test split**（因为原始测试标签不公开）；
- 评分逻辑（复现自 Kaggle 官方 grading）；
- 与之对齐的**人类排行榜分布**（用来把 agent 分数映射到"铜/银/金牌"）。

**这是"外部标尺"设计的关键**：它不判"过程对不对"，而是把 agent 的最终提交扔进一个**已有几千人类样本的分布**里定位。

## 3. "长"体现在哪

| "长"的来源 | 说明 |
|---|---|
| **挂钟时间** | 每题最长 24 小时自主运行——这是本 benchmark 最硬的"长"，用时间而非步数刻画 |
| **实现复杂度分层** | Low/Medium/High 按"人类实现耗时"划分（<2h / 2–10h / >10h），把"长"量化成人力小时 |
| **必需步骤链** | 读数据 → EDA → 特征 → 建模 → 调参 → 交叉验证 → 生成 submission，缺一步就没有有效提交 |
| **迭代深度** | AIDE 这类 scaffold 会做解法树搜索，长程体现在"多轮自我改进"上（pass@8 显著优于 pass@1 说明方差大、需要多次尝试） |

## 4. 判分粒度

**纯终态，但标尺是连续的**：
- 直接指标 = 竞赛官方评分；
- 报告指标 = **在人类排行榜上的百分位 / 是否达到铜牌**；
- 无过程分、无中间 checkpoint。

⚠️ **它的巧妙之处值得我们借鉴**：开放任务没有唯一答案时，可以用"人类分布"把连续分数转成有语义的等级（铜/银/金）。**我们的 open_discovery（无 GT，objectives 判优）正缺这样一个标尺**。

## 5. 对我方：可借 / 可打点

**可借（对 `open_discovery` 模板尤其关键）**

1. **用"人类/文献分布"当标尺**：我们的开放发现类（如"找一个 Tc 尽可能高的超导体"）可以不设唯一答案，而是把 agent 给出的候选放进**已知材料的性质分布**里定位——报"击败了数据库中 x% 的已知材料"或"达到文献前 k 名水平"。这比自定阈值更客观，也更容易被审稿人接受。
2. **复杂度按人力小时分层**：我们可以给每题标注"领域专家完成需要多少步/多少次数据库查询"，作为难度的客观代理。
3. **报 pass@k 与方差**：MLE-bench 显示 pass@8 约为 pass@1 两倍——长程任务方差极大，只报 pass@1 会误导。我们必须报多次运行的分布。
4. **明确的运行预算（24h）**：我们的"查证预算"是同一类设计，要在论文里写成一等公民。

**可打点**

| 维度 | MLE-bench | 我们 |
|---|---|---|
| 过程 | 完全不看 | checkpoint DAG |
| 领域 | ML 工程（非科学发现） | 材料/药物发现 |
| 抗污染 | 明确承认风险，靠重切 split 缓解 | 分子匿名化 |
| 长程刻画 | 挂钟时间 + 人力小时 | checkpoint 数 + 依赖深度 + H_s |

**注意**：MLE-bench 属于"通用 agent 任务"（撞我们红线 2），因此**只能作为方法学参照，不能作为我们的任务来源**。
