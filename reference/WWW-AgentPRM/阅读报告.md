## 0. 一句话

LLM 推理的 PRM 按"这一步对不对"打分，但 agent 任务的动作**没有清晰的对错**——应该按它**离目标的接近程度（promise）**和**它带来的推进量（progress）**来评；据此重定义 agent PRM，用 **TD 估计 + GAE** 可扩展地造训练标签，比基线**计算效率高 8 倍以上**，且能用于 agent 的 RL。

## 1. 数据量

方法论文，无新 benchmark。用多个 agentic 任务（web shopping、browser navigation 等多轮决策任务）做实验；核心量化结论是**计算效率 >8×**，且 test-time compute 扩展时表现稳健提升。

## 2. 方法形态（对我们最关键）

**核心论点（必须逐字理解）**：
> "Unlike LLM reasoning, where each step is scored based on correctness, actions in agent tasks do not have a clear-cut correctness. Instead, they should be evaluated based on their **proximity to the goal** and the **progress they have made**."

于是 AgentPRM 给每一步两个量：
- **Promise**：这一步之后，从当前状态出发**最终达成目标的可能性**（≈ 状态价值 V）；
- **Progress**：这一步相对上一步**实际推进了多少**（≈ 优势 A / TD 残差）。

**标签怎么来（可规模化的关键）**：用 **Temporal Difference 估计 + Generalized Advantage Estimation (GAE)** 从轨迹里自动算，而不是靠人工标或蒙特卡洛全展开——这就是"比先前方法样本效率高得多"的来源。

**用途**：① 测试时用它做 step-level 引导（选动作、剪枝）；② 训练时把它当奖励模型做 agent RL。

## 3. "长"体现在哪

- 目标任务是多轮决策（web shopping / browser navigation），需要"基于环境反馈连续做一串智能决策"；
- **"长"带来的具体病症被它精确命名**：sequential decisions 之间存在**相互依赖**，且每一步对最终目标的贡献不同——所以既要 progress tracking，又要 exploration–exploitation 平衡。

## 4. 判分粒度

**步级（step-wise）**，但**是学出来的连续分，不是断言**。这与我们的路线正相反：
- AgentPRM：过程分 = 学习型价值估计（软、连续、可对任意动作打分，但可能出错、可被 hack）；
- 我们：过程分 = 可执行断言（硬、离散/分段、只能对"有产物的节点"打分，但不可 hack）。

## 5. 对我方：可借 / 可打点

### 5.1 它提出的质疑必须正面回答

**质疑**：如果 agent 动作本来就没有清晰对错，那"hard checkpoint 判过程"是不是在强加一个不存在的对错标准？

**我们的回答（应写进论文的 Method 或 Discussion）**：
- AgentPRM 说的"没有清晰对错"针对的是**动作层**（点哪个按钮、先搜哪个词），这确实没有对错；
- 我们的 checkpoint **不判动作，判中间产物/状态**（ADR-0008 与 GOAL.md §4.2 已明确："验证器查产物不认动作"）。"这个候选分子的 hERG 标签是否与数据库一致"**有清晰对错**；
- 因此二者不冲突而是**分层互补**：动作层用 promise/progress 这类软信号，**产物层（checkpoint）用硬断言**。这正好构成一个"软硬双层奖励"的方法学卖点，而且是我们独有的。

### 5.2 可借

1. **promise / progress 二分法可以直接嫁接到我们的 DAG 上**，而且我们能给出它的**无学习版本**：
   - `progress`（硬版）= 本步新达成的 checkpoint 的 reward 增量；
   - `promise`（硬版）= **DAG 上从当前已达成 checkpoint 集合出发，剩余可达 reward 的上界**（图上直接算，不需要训模型）。
   **这是一个干净的、可直接写成公式的贡献：把学习型 PRM 替换为 DAG 上可解析计算的 promise/progress。**
2. **TD + GAE 造标签**：若我们要训一个辅助 PRM 作对照 baseline，直接用它的做法。
3. **报计算效率**（8× compute-efficient）这个论证角度很有说服力：过程信号的价值不只是精度，还有**样本/算力效率**。我们的 checkpoint 奖励是零成本获得的（判分器本来就要跑），效率论证比它更强。

### 5.3 可打点

| 维度 | AgentPRM | 我们 |
|---|---|---|
| 过程信号 | 学习型（可能错、可被 reward hack） | 可执行断言（不可 hack） |
| 是否需要训练 | 需要（TD+GAE 造标签 + 训 PRM） | 不需要 |
| 领域 | web shopping / browser（通用） | 材料 / 药物发现 |
| 是否自带 benchmark | 无 | 有 |
