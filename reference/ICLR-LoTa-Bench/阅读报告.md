## 0. 一句话

给 LLM 任务规划器造一个可自动判分的考场：把"高层自然语言指令 → 原子技能序列"的规划结果**放进模拟器里真跑**，用模拟器的 goal condition 判成败；两套配置（ALFRED + AI2-THOR、自扩展的 WAH-NL + VirtualHome），并系统消融 LLM 选择、prompt、in-context 示例等。

## 1. 数据量

| 量纲 | 内容 |
|---|---|
| 配置 1 | **ALFRED** 数据集 + **AI2-THOR** 模拟器 |
| 配置 2 | **WAH-NL** —— 作者对 Watch-And-Help（WAH）数据集的自扩展版（补了自然语言指令）+ **VirtualHome** 模拟器 |
| 一条样本必备 | 自然语言指令 + 初始环境状态 + **goal condition** |
| 技能集 | 预定义原子技能集合 `S`，每个 `s∈S` 是一个原子动作 |
| 产出 | benchmark 代码 + WAH-NL 扩展数据集公开发布 |

**读数**：它的"数据量"贡献主要是**补齐了缺失的自然语言标注**（WAH 原本没有 NL 指令），而不是造新任务。这是一个成本低、贡献清晰的 benchmark 论文形态，值得注意。

## 2. 数据集形态

一条样本 = **（自然语言指令，初始环境状态，goal condition）**。

- **规划器输出**：一串来自预定义技能集的原子技能。基线规划器用 LLM 的 in-context learning——给若干"（NL 指令，技能序列）"示例，然后**在所有可执行技能上算概率并选最高**（即约束解码到合法动作空间，避免生成不可执行动作）。
- **判分**：把技能序列在模拟器里执行完，检查最终状态是否满足 goal condition。
- **关键补齐动作**：若数据集本身缺 goal condition，作者会补；这就是"判分必须先有可机器判定的目标"这条铁律的体现。

## 3. "长"体现在哪

- **技能序列长度**：一条高层指令（"把书从桌子移到沙发"）要分解成多个原子技能，家务类任务常十几步；
- **状态依赖**：技能之间有强前置（必须先 pick 才能 put），错序即失败；
- **技能空间约束**：规划器必须在"当前可执行技能"里选，长程中每一步的可行集都在变。

## 4. 判分粒度

**终态 goal condition 二元判分**（模拟器状态比对，完全确定性，无 LLM judge）。
无中间 checkpoint——即使 agent 前 9 步全对第 10 步错，也是 0 分。

## 5. 对我方：可借 / 可打点

**可借**
1. **"技能集约束 + 在合法动作上算概率"这个解码方式**，等价于我们的"取数网关只暴露 4+1 个工具"。它给了一个 ICLR 层面的先例：**限制动作空间不是简化问题，而是让评测可判定的必要工程**。
2. **"数据集缺 goal condition 就补上"**——同理，我们对现有科学数据集缺"可机器判定的成功判据"的补齐工作，本身就是可发表的贡献，不必羞于承认它是"补标注"。
3. **系统性消融（LLM 选择 / prompt / in-context 示例数）**：benchmark 论文必须附这类消融，否则会被批"只是个数据集"。

**可打点**
- 领域是家务 embodied（红线 2），只作方法参照。
- 它的"长"完全没有被度量（不报 step accuracy、不报 H_s），也没有部分分——我们要补的正是这两块。
