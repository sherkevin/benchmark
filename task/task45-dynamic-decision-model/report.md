# 面向可靠工具调用的动态适应模块与实时学习 Jev

> 2026-09-23。Owner 已指定研究方向，算法为作者侧候选。Laya 源码固定在 `846593571c0bff9344fd8a80b951dd61f4e39c3f`；只读审查，没有安装依赖、加载权重或运行模型。本报告承接 [Task44](../task44-online-provider-manager/report.md)，不改变 Task38 当前科学模型池的训练暂停。

## 这次提议改变了什么

我们要研究的系统有三层：动态工具适应模块维护工具状态和反馈；动态Jev用预训练判别能力与真实反馈持续给出工具选择、证据验证、复核和拒答等typed decisions；主Agent把这些决策用于可靠调用并承担最终作答或拒答。provider选择是模块中的一个动作，不能代表全部目标。Jev 是用户用来说明功能的参照，论文不必以该产品为依赖或名称。这里“动态”指决策参数随真实反馈改变，不以工具菜单变化代替学习。

这给出了比“为 Bandit 从零设计输入特征”更具体的起点，但冷启动能否获益不能预设。同功能 BBB 模型都可能写着“预测血脑屏障渗透”，文案相似时，预训练语言知识未必能区分不同权重在当前分子上的错误。工具版本标识本身不提供这种能力知识。若缺乏可区分的训练域元数据或源任务经验，初始选择应保持弱先验和高不确定性。

## Laya 可以复用到哪一步

Laya 是独立开源的 Jev 类实现，不是 TypeSafe Jev 的官方开放权重。[官方 Jev 文档](https://docs.typesafe.ai/introduction)定义 `state + typed questions → structured decisions`，Laya 延用此形态并提供可训练代码与公开检查点。

| 源码事实 | 对本项目的意义 |
|---|---|
| `laya/common.py:89–137` 是双向编码器、选项 marker、共享 scorer 和 softmax；源码为 Apache-2.0 | 能复用候选编码、非生成式打分与动态候选接口；不必让 LLM 逐 token 写工具名 |
| `agent.py` 推理在 eval/no-grad 下运行；没有逐题反馈更新入口 | 需要新增带状态版本、回报队列和真实参数更新的学习器 |
| 微调 notebook 用完整目标概率分布，proper-score reward 加 soft-target CE，离线多轮训练 | 不能原样用到“只知所选工具结果”的 Bandit：其训练标签权限不同 |
| `common.py:210` 的 confidence 是 `1−H(p)/log(K)` | 它是选项分布集中度，不是 Bandit 的后验不确定性，也不是科学预测正确率 |
| `build_sequence` 在所有候选间分配 `head_max_len`，默认英文为 192 token | 33 个相近模型的描述可能截断到不可区分；首批小池与 token 审计有必要 |
| 仓库报告 base 在 typed-decisions 约0.36，低于多数类0.461；0.766来自专门微调 | 作者自报结果显示预训练迁移需要验证，不能据其营销定位认定 BBB 零样本有效；本轮未复现这些数值 |

已本地保存 [32份源码/说明/测试与许可证](reference/laya-8465935/SOURCE.json)、微调 notebook、模型卡和配置；没有下载权重。源码与 HF 配置分别按其自身 revision 固定。可直接借用 `build_sequence`、`DecisionModel` 的选项表征、模型装载、类型接口和日志结构；重写部分反馈训练目标。已有的脚本语言 Router 选择英语/多语种检查点，并不学习具体医药模型能力。

## 必须先修正概率的含义

Laya Choice 给的是候选菜单内的相对概率，所有选项合计1；我们要估计的 `q_a(x)=P(valid且correct | x,a)` 不要求跨工具相加为1，因为多个工具可以同时正确。

因此，调用 A 后发现 A 正确，不能把 A 当唯一正确类做 softmax 交叉熵更新——这会把未调用的 B/C 错当负例。也不能把原始 Choice 的0.9写成“A在这个分子上90%会正确”，更不能把低熵分布直接转成 UCB 很小的不确定区间。官方 [Choice](https://docs.typesafe.ai/primitives/choice)与[Confidence](https://docs.typesafe.ai/confidence)文档也区分了分布和集中度。

## 第一版实现候选

第一版先闭合首个工具选择和反馈更新，把它作为最小可证伪切片；总问题仍是可靠工具调用。随后把相同的动态Jev状态接口扩展到证据验证、复核和拒答。这样可以先证明在线决策核心确实随反馈改变，再测主Agent是否学会使用这些结构化决策；最终主张必须以端到端轨迹结果为准。

1. **预训练部分。**固定一个 Laya 权重版本。输入包含功能 key、可审计分子信息、具名工具卡和已有真实返回。提取每个候选的表征，保留原 Choice 排序作为弱策略先验。初始排序的可信强度通过合法源训练/校准数据确定；没有此类证据时不将其强行视作校准收益。必须区别“完全无当前工具标签的冷启动”和“历史标签 warm start”。
2. **在线收益部分。**在候选表征上增加两个sigmoid头，分别预测有效返回率与有效返回后的正确率，两者相乘得到有效正确率。冻结整个预训练表征路径，逐题更新小型头；失败更新有效率，化学正确性标签保持缺失。第一版用显式随机探索，Bayesian读出及后验探索另作对照。这样决策参数确实在变，又能保留预训练能力；不声称官方Jev或原始Laya自带在线学习。源码现有forward只返回logits，需要新增marker embedding导出；这种表征依赖整份候选菜单，日志须保存菜单与排列。
3. **选择与学习。**按收益预测、弱先验和探索规则采样具名模型，记录本次策略概率。实际标签到达后，只用实际调用记录更新。实际失败更新可用率、保持化学正确性为空；未知真值保持 pending。若以其他目标分布估计风险或先验可靠性，要用记录的选择概率处理选择偏差，报告支持和权重方差。保留探索下限，避免错误且自信的先验使其他模型永远拿不到样本。
4. **逐渐纠正先验。**先验强度不能由 Laya confidence 直接决定。可对“固定先验权重”和“由历史真实反馈学习先验可信度”作对照；后者是待审候选机制，不预先声称新算法。后续若解冻编码器/加 LoRA，须重新处理特征与后验统计的一致性，不能把旧特征的协方差直接用于新特征。
5. **承接复核。**首请求仍学习 `q_a(x)`。当 Agent 已见 `(a1,z1)` 并再次请求，状态加入这份证据，第二个在线头学习 Task44 的 `Δ_b(s1)`，目标是追加调用的实际决策补益。它需要同题成对探测；当前单调用反馈不能识别。是否请求第二次仍归 Agent。

可立即实现的最简版本已写成[适配卡](implementation_card.md)：冻结表征、两个逐候选logistic头、弱策略先验与显式随机探索、只对已观察记录更新。Bayesian读出及反馈自适应先验权重保留为后续对照，不同时塞进第一版。这套结构可用现成估计器实现，不能默认命名为新算法；需证明新的实验设定或具体机制改变了既有方法的可实现能力。

## 最小实验必须回答的四个问题

- **冷启动先验有没有信息？**相同合法输入，比静态 Laya、普通分子特征选择器与匿名/打乱工具描述消融；区分源任务知识与当前工具标签。不能靠工具名、泄露的全表准确率或测试标签获得优势。
- **在线学习是否超过现成方法？**相同起始数据与反馈流比静态 Laya、无预训练在线头、直接参数微调、PILOT及BayesianRouter适配；LLM-PriorCB待合法取得完整配方后加入。报告先决策后更新的累计错误/后期错误、有效反馈数、全部实际成本；另列冻结泛化。引入Laya带来的计算不能从账上消失。
- **错误先验能否恢复？**以自然的领域外/工具版本变化为主；元数据打乱等人为误导只作机制压力测试。比较先验固定与可纠正两种机制，检验是否被高confidence锁死。静态缓存只能验证预登记的回放/新arm情景，不能冒充真实时间漂移。
- **Agent及复核是否获益？**固定Agent比选择器，固定选择器比Prompt/真实SFT/RL；二次调用与单调用分开，强序列近邻同观察权限，保留直接 `x→Y` 基线与原有独立确认要求。

首个现实停点是冷启动信息量：如果工具卡与预训练表征在同功能具体模型中没有信号，不能跳到“动态决策模型有效”。可以转为有合法源任务训练的适配，但要如实改称 warm start，并重新评估其额外价值。
