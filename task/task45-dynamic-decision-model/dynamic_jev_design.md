# 动态 Jev 设计卡：从工具选择到可靠调用决策

日期：2026-09-24。状态：作者侧候选设计，未训练、未冻结实验参数、未获得当前模型池运行授权。

## 目标

动态 Jev 是面向工具调用的结构化在线决策模型。它在同一套状态表示上回答四类问题：

1. 当前功能请求应选择哪个具体工具版本；
2. 已见工具输出是否足以作为证据；
3. 是否值得再调用一个工具做验证，调用哪个；
4. 当前应作答、拒答，还是继续取证。

它的输入是任务状态和候选项，输出是带候选掩码的结构化决策分布。它不把工具选择、证据可信度和最终作答混成一个概率；每种 typed decision 有自己的动作空间、标签和反馈时钟。

## 状态与模型

对第 `t` 个请求，状态为

```text
s_t = (x, function_key, candidate_versions, history, budget, policy_version)
```

其中 `x` 是分子与任务信息，`history` 包含已调用工具、原始返回、失败、当前已见证据和主 Agent 已做的动作；它不包含尚未允许观察的实验真值。预训练编码器 `E_θ` 产生状态表示；第一版固定 `θ`，只更新轻量决策头。每次 episode 缓存状态表示，避免重复编码。

对每个 typed decision `τ`，模型计算

```text
h_t = E_θ(s_t)
h_t_a = combine(h_t, candidate_a)
p_φ(a | s_t, τ) = softmax(masked_head_τ(h_t_a))
```

候选掩码禁止重复调用同一确定性版本、调用失效版本或超出预算的动作。Choice 分布只表示当前决策空间内的相对选择，不表示工具真实正确率。

## 预训练与实时学习

Laya 类预训练模型提供状态与候选的语言表示和初始决策倾向。冷启动条件必须明确为“不使用当前具体工具在目标分布上的标注效果”；使用过这类标签的版本另列为 warm start。

动态有两个时间尺度：题内看到新工具输出后立即更新证据状态和下一步决策；题间等合格真值或终止反馈到达后更新工具能力后验或轻量参数。实时部分采用事件驱动的轻量更新：

- **工具结果事件**：工具返回或失败立即写入 episode，但只在合格真值 `Y` 到达后更新该次调用涉及的有效率/正确率头；未调用工具没有负标签。
- **验证结果事件**：若主 Agent 实际发起第二次调用，记录首个输出、第二个输出和最终真值，更新“在当前证据下追加调用能减少多少决策损失”的头。未发生的第二次调用不能获得伪奖励。
- **终止动作事件**：在真值到达后，用最终错误、拒答损失、调用成本和覆盖率形成 episode utility，更新作答/拒答/继续取证头。真值缺失则保留 pending。

第一版冻结 `E_θ`，只更新逐候选收益头和 typed decision 的最后一层；可用正则化 logistic 或 neural-linear posterior，并设置最小探索概率。若后续更新 adapter 或骨干，必须重新处理历史特征与旧后验的一致性。

## 反馈与因果约束

实时更新按先决策后反馈执行。每条日志至少记录 `episode_id`、状态版本、候选菜单、动作、实际采样概率、工具版本、原始返回、真值到达时间、反馈标签和更新版本。

复核价值属于条件效应，不能由单调用准确率推导。训练期需要少量随机成对探测，保证首个工具和第二个工具都有正选择概率；主 Agent 的正式轨迹仍保留自己决定是否复核的权利。跨策略比较使用记录的行为概率做 IPS/DR 或其他预注册估计，并报告支持范围与方差。

## Agent 接口

动态 Jev 向主 Agent 返回结构化上下文，而不是一段不可审计的自然语言建议。`evidence_state` 是模型的风险建议，不是真值标签；标签由终止效用或事前独立验证合同产生：

```json
{
  "decision_type": "select|verify|final",
  "candidate_distribution": "...",
  "evidence_state": "sufficient|uncertain|insufficient",
  "recommended_action": "call|verify|answer|abstain",
  "uncertainty": "...",
  "provenance": "...",
  "jev_recommendation": "...",
  "agent_action": "...",
  "agent_overrode": false
}
```

主 Agent 读取工具原始结果和该结构化状态，执行请求、验证、复核、作答或拒答。日志同时保存 Jev 建议和 Agent 实际动作，才能归因 Agent 是否学会采纳或纠正建议。训练时可用合法轨迹做 SFT，再用终止效用做受约束的策略优化；动态 Jev 的在线更新与 Agent 参数更新分别记录，避免把外挂学习误算成 Agent 学习。

统一 episode utility 可写为

```text
L = error(final_answer, Y)
    + c_abs * 1[abstain]
    + c_call * number_of_calls
    + c_verify * number_of_verifications
    + c_delay * decision_delay
```

动态Jev的子目标是校准工具可靠率、证据风险和追加证据的边际减错收益；主Agent优化的是完整轨迹的效用与风险覆盖。

## 三层评估

1. **动态 Jev 层**：冷启动早期错误、在线累计错误、后期错误、校准、反馈样本效率和新增推理开销。
2. **动态适应模块层**：provider 选择、复核选择、拒答阈值、调用次数和证据验证收益；与静态 Laya、标准 contextual bandit、PILOT、BayesianRouter 和规则流程同信息比较。
3. **Agent 端到端层**：最终错误率、拒答覆盖、复核收益、工具调用预算、校准和轨迹质量。固定 Agent 比较模块，固定模块比较 Prompt/SFT/策略优化，再报告动态Jev、模块与Agent的三层交互。

若第一层无冷启动信息，取消冷启动主张；若第二层无净收益，取消动态适应主张；若第三层没有最终可靠性提升，不能声称 Agent 能力提升。

## 关键边界

动态 Jev 的“实时”是反馈到达后参数或后验发生更新，不是把静态 Laya 重新包装成实时系统。provider 选择是四类决策中的一个，复核、验证和拒答是同一可靠证据链上的其他动作。完整方法是否超过已有预训练路由与在线反馈方法，必须由同信息真实实验决定。
