# report · D2-② 恒答基线（BBB 族，零 API）

## 结论（先说答案）

**D2-② 的恒答基线半完成：退化策略不能白嫖这道题。**

- **「一律说不可信」（always-abstain）的损失恒等于 c**，与分子、与工具都无关。它要压过
  最强的作答策略（集成多数票，err=8.04%），必须 c < 0.0804——**c 的有效区间是
  (0.0804, 1.0]**。区间内，恒答不是最优，任务对退化策略有区分度。
- **「一律答同一标签」（constant-label）更差**：恒答阳性 err=28.67%（=少数类占比），
  恒答阴性 err=71.33%。比集成多数票（8.04%）差 3.5~9 倍——**这道题不能靠背一个固定
  标签解决**。
- **集成多数票是天花板参照**：722 可用分子里 709 个凑得出多数意见（13 个平票排除，
  不静默判正），err=8.04%；平衡面板 652 上 err=7.36%。最强的单族是 admetlab（8.45%），
  集成已经比任何单族都好。

一句话给 D2-②：**恒答基线不成立（退化策略拿不到高分），所以「记分数必须配弃答率」
这条报告硬约束被触发并已落实**——每条损失都与弃答率成对写进 JSON。

> ⚠️ **本报告对「裸答检索天花板半」的判断已被更正，见文末「更正（2026-09-15）」段。**
> 原文说裸答半「没做、只卡凭据」是错的——它 2026-09-01 就预注册并跑了第一轮，
> 且 qwen3.7-max 平衡准确率 0.800 已踩到预注册的作废阈值。原文保留作痕迹。

## 做了什么

1. 接同一份冻结真值 + 7 族投票（与 D2-① 完全同源，复用其已测过的 loader）。
2. 建脚本 `src/probe_headless/bbb_constant_answer_baseline.py`：
   算三类「作答」策略（每单族 / 集成多数票 / 恒答标签）的 never-abstain 错误率，
   套损失式 `L = I(答错) + c·I(弃答)`，在 c 网格上同时给三种动作策略
   （从不弃答 / 一律弃答 / Oracle-yield）的损失与弃答率，并从数据现算 c 有效区间。
3. 测试 14 条 + 变异验证 3 次（平票静默判正 2 失败、弃答免费 2 失败、
   Oracle 漏乘 c 2 失败），全仓 `src/probe_headless/tests/` 208 passed 1 skipped 无回归。

## 数字

**never-abstain 各作答策略错误率（722 可用分子）：**

| 策略 | 错误率 | n |
|---|---|---|
| 集成多数票 | **0.0804** | 709（13 平票排除） |
| admetlab（最强单族） | 0.0845 | 722 |
| b3clf | 0.1025 | 712 |
| lgbm_bbb | 0.1066 | 722 |
| admet_ai | 0.1180 | 661 |
| graphb3 | 0.1288 | 722 |
| fpadmet | 0.1316 | 722 |
| deeppurpose（泄漏敏感） | 0.1662 | 722 |
| 恒答阳性 | 0.2867 | 722 |
| 恒答阴性 | 0.7133 | 722 |

- **c 有效区间 = (0.0804, 1.0]**：下界是最强 never-abstain 策略的错误率（c 低于它，
  一律弃答占优），上界 1.0（答错恰好扣 1，弃答代价 ≥1 时连 Oracle 都不弃答）。
- 平衡面板 652 上集成多数票 err=0.0736（48/652），与全集 0.0804 同量级，结论稳。

## 对第三层意味着什么

1. **退化策略白嫖不了。** 恒答标签 err 是集成多数票的 3.5~9 倍，恒答弃答只在
   c<0.0804 才占优——任务对「不动脑子」的策略有区分度，这是 benchmark 成立的最低门槛。
2. **报告硬约束被触发并落实。** 入库版 §3.4.6 写明「恒答得分高则必须同时报弃答率」，
   本结果里 always-abstain 损失恒为 c、弃答率恒为 1，已成对落盘。
3. **集成多数票（8.04%）是 agent 要打败的参照线。** 一个只会调工具再投票的 agent，
   不该比这更好；要证明「判断这组预测能不能用」有价值，得在选择性作答下把损失压到
   这条线以下（靠在该弃答时弃答）。

## 更正（2026-09-15）：上文「裸答半没做、只卡凭据」是错的

> 仓规：台账级文档发现错了追加更正段、不改写原文。上面「遗留问题」第 1 条整段作废，
> 以本段为准。原 U-8 已同步重写。

**核查起因。** 我在收尾时跑了一个背景命令查 c 预注册是否对当前 7 族在役，输出里冒出
`data/bbb_census_v3/tool_conflict_candidate_pool/bbb_v1/naked_baseline/` 这个目录——
**裸答基线早就预注册并跑过了**，而我写上文时根本没查这个目录就断言它「没做」。
这是「不凭记忆断言、benchmark 分析必须基于本地落盘真实数据」（ACTION_RULES §4）
的反例，如实记下。

**真实状态（全部核过落盘文件 + 独立复算）：**

1. **预注册在**：`preregistration.json`，`schema_version=bbb-naked-baseline-v1`，
   问题原文「Can any supported agent predict the hidden experimental BBB labels
   without scientific tools well enough to invalidate the proposed diagnostic task?」
   样本 40 个（20 阳 20 阴，全部在当前 730 池内，与矛盾排除表零交集，我已逐一核过）。
2. **第一轮 n1 跑了**：6 模型，5 个有效，qwen3.5-plus 撞「模型提供方限流」4 次全失败。
   预注册要求每模型 5 轮（n1–n5）、30 个正式槽位，**只收了 5 个**。
3. **判定 INCONCLUSIVE**，理由 `Formal rounds are incomplete`——不是 STOP，因为 STOP
   规则要「任一**完整**模型均值 ≥0.80」，qwen3.7-max 只有 1/5 轮不算完整。
4. **危险信号**：qwen3.7-max 平衡准确率 **0.800**，恰好踩在预注册的作废阈值 0.80 上。
   我从 `answer.json` + `answer_key.json` 独立复算 = 32/40 = 0.800，与存档 `results.json`
   一致。其余模型：DeepSeek-V3-671B 0.75、glm-5.2 0.70、qwen3-coder-plus 0.65、
   deepseek-v3.2 0.65。
5. **预注册的下一步政策**：`INCONCLUSIVE → stop and preregister an extension before
   more runs`——**不许直接补跑 n2–n5，必须先预注册扩展**。所以这不是「给凭据就能跑完」，
   是先要裁「扩展怎么做」。

**对结论的影响。**

- 上文「恒答基线半」的全部结论**不变**（那半是零 API 纯计算，与裸答半独立，已测过）。
- 上文「D2-② 整条记半成、卡在凭据」**作废**。正确的状态是：**D2-② 裸答半已部分执行、
  判 INCONCLUSIVE、且第一轮已露出触及作废线的信号**；卡点不是凭据，是预注册政策
  （须先裁扩展）+ 作废风险（补跑后若 qwen3.7-max 完整仍 ≥0.80 即 STOP）。凭据只是
  选「补跑」时的次要门槛。
- **要害的反读（防过度反应）**：预注册 `interpretation_limit` 明写「高分只证明无工具
  可解，分不清是记忆还是无辅助化学推理」。BBB 本就结构可预测（admetlab 工具能到
  ~91.5% 准确率即是证），裸答 0.80 可能是合法化学推理而非背答案。且这与 D2-①
  **一致不矛盾**：α_i 占 54.5% 说明误差大头在分子难度，裸答 0.80 等于量出「这部分
  α_i 里有多少不靠工具就能拿到」——两者都指向「有价值的样本是高 α_i 难分子」
  （含我已量出的 14 个伪共识分子）。

**这三个选项已写进 U-8，交 owner 裁，我不自行推进**（涉及预注册扩展与可能的任务作废，
属停机条件「已定判据需再次修改」的边缘，按仓规第 7 条先停下交 owner）。
