## 1. 目标

一句话：**把「fixed 类题目到底长什么样、按什么流程造」钉成一份 ADR，并为 hERG/AMES 的实验真值给出可选的外部数据集对照表——两件都做完，出题这条线才有可执行的地基。**

起因是盘查中发现一处**未被登记的口径演进**：造题口径存在两套，且没有任何一份文档说明二者关系。

### 1.1 两套口径的实测对照

| 维度 | **A 套**（BENCH_SPEC + 路线图 + DECISIONS，owner 裁定 08-23~08-28） | **B 套**（目标.md + ADR-0006 + ADR-0007，09-13~09-15） |
|---|---|---|
| 题目单位 | 长程链 C「命中→先导」八站上的一段**原子题**（一个原子 = 两个验证点之间、只有一个可验证产出） | 每个 **（分子, 工具子集）= 一道独立任务** |
| 答案形态 | **必须目标级交付集**（选出/设计出的一组分子）；**不能是「某分子的性质值」**（那是实验级） | **「判断这组预测能不能拿去做决策」+ 选择性作答**（作答/弃答/上报） |
| 判别关 | **一道题只留一道关**；「请说出你发现的规律」这类**值型关不合法**（owner 08-27：「我们只能通过结果看能力，不能直接问规律」） | 损失 `L = I(答错) + c·I(弃答)`，c∈(0.0804,1.0]（BBB 已实测） |
| 防背路线 | **自造从未存在的新分子**（性质走 `predict_admet` mock 注入），因公开真实数据模型背过（`layer_01` 裸答 **0.952**） | **真实分子 + 难度配比**：易≤30% ⇒ 裸答投影 ~0.55；易 80.3% ⇒ 0.870 撞作废线 |
| 造题流程 | **七道闸不得跳不得倒序**（闸0 锚能力四问 → … → 闸6 预登记）；题型+参数表+离线筛子，零机时判死 | R1–R5 五组不变量 + 三个验收数（≥5000 题、难分子≥500、伪共识≥50） |

### 1.2 三个实质冲突点（不是措辞差异）

1. **答案形态对立**：A 套明令答案不能是「某分子的性质值」，而 B 套的答案恰是**单个分子上「这组预测能不能用」的判断**。
2. **防背路线互斥**：A 套裁定自造新分子，B 套 R1.2/R1.3 要求「冲突天然、不许注入 + 实验真值作锚」⇒ **只能用真实分子**。
3. **当前在推的活不一致**：路线图 §7.0 写着 **08-27 立、最高优先、唯一在推 = S1 SAR-Flip 判别关重做**（步1–3 已做，步4 裸答 k=5、步5 ≤6 run 待跑）；ADR-0007（09-16）派的是 **Step 2 真值接入 hERG→AMES**。盘面无任何文档说明谁取代谁。

### 1.3 我的判断（owner 已采纳，落 ADR 时须写明依据）

B 套不是推翻 A 套，是**演进**：09-15 用「难度配比防背」实质替代了 08-26 的「自造新分子防背」，且有 task23 实证支撑（易分子裸答 78–96%、难分子 0–60%，0.80 全来自易分子）。但这次演进**没有登记**——A 套决议既没作废也没标 Superseded，`BENCH_SPEC.md` 附录 B-4「没有一道题有合格的判别关」仍挂 ⚡️。

形式上的权威关系可判：`BENCH_SPEC.md` 附录 C 自称「唯一权威（**ADR 之下**）」⇒ ADR-0006/0007 高于它。但 ADR-0007 只管**题集层不变量**，**未管单道题怎么造、判别关怎么设**——那部分七道闸仍生效且从未被标 Superseded。故「每道 (分子,工具子集) 题要不要过七道闸」在盘面上**无解**，须 ADR 钉死。

### 4.1 由此得出的硬缺口（本任务存在的理由）

1. **ADR-0007 R2.1「真值可接」这一条，hERG 目前只在 98 分子上成立，AMES 一条都不成立。** 而 R2.1 要求「现象密度 × 真值可接 × 源干净」三条**同时**成立才入选。
2. **98 分子的 hERG 真值撑不起 R3.3（难分子 ≥500）与 R4.4（伪共识 ≥50）**，也无法与 BBB 的 730 池对齐做跨族合并——R3.3 的计数口径是「按分子计、跨族合并」，**分子池必须一致**才谈得上合并。
3. ⇒ **「hERG 接真值」的第一个真问题不是写清洗脚本，是真值从哪来。** 要接到与 BBB 同规模的 730 池，必须引入外部实验数据集（提案 §3.2 已列 TDC / ChEMBL / SAMPL / CACHE 等候选）。引入新数据源涉许可证核查与下载，**按停机条件第 3 条须 owner 授权**——这正是 owner 裁定 ② 要 agent 先出清单的原因。

### 4.2 BBB 的成功范式（候选表须对照它评估）

BBB 之所以能做到 730/730，是因为接了**一个外部专门实验数据集**（BBB_Martins），且落成了 `screening_ledger.jsonl` 这种**逐分子带 source 字段**的冻结台账形态。⇒ 候选表的评估维度由此确定：能否同样做到「730 池逐分子有真值 + 每行有可核出处 + 标签口径无歧义」。

## 5. 边界（明确不做，防范围漂移）

- **不改任何判据实现、不动冻结输入、不改 `.gitignore` 既有口径。** ADR-0009 是口径登记，不是代码改动。

- **不下载任何外部数据、不花机时、不调用任何 LLM。** 候选表是零成本调研；下载须 owner 选定后另行授权。
- **不碰 open 类。** owner 本轮明令「先不管 open 类只关注 fixed 类」。ADR-0009 只裁 fixed 类口径，`discovery_haystack` 的 30 道与其三条设计约束不在本任务范围。
- **不自行启动 S1 的步4/步5**（裸答 k=5 与 ≤6 run 都要花机时），也不自行判定 S1 作废——它的去留由 ADR-0009 提口径、owner 审。

- **不臆想外部数据集的分子数与许可证。** 候选表里每个数都要指得到出处（官方页 / 论文 / 包内元数据）；核不到出处的写「未核到」，不用估算填（DECISIONS 坑⑥：报聚合数字不核原始样本）。
