# 制药科学预测冲突诊断与恢复 Agent Benchmark：Proposal

## 1. 背景与动机

###  1.1 基本事实
1. 当前制药 Agent 已能调用大量分子性质、对接、亲和力、ADMET、蛋白结构和成药性预测工具。但这些工具多为统计学习或模拟计算，即使正常返回、格式正确、数值看似合理，也会因训练偏差、适用域变化、构象与参数假设等产生误差。多个工具可能对同一性质给出矛盾结论，甚至在错误方向上形成“伪共识”。

2. 化学信息学的工具生态极度碎片化，同一功能有一堆互不兼容的实现，而且差异大到有文献专门讨论。最典型的是 logP：RDKit 的 Crippen 算法、XLogP3、ALOGPS、ChemAxon 对同一个分子能差出 1-2 个 log 单位——这直接决定这分子是"成药性好"还是"成药性差"。你不用编造冲突，去跑一遍就有。这是天然存在的，且在制药领域这个问题尤为突出

### 1.2 研究动机

本项目的出发点是一个关于 agent 工具使用的 **一般性观察** ，以及它在制药域的一个**可测量外显**。

**A（本质问题，一般层）**：训练后 agent 的工具偏好分布 ≠ 任务最优分布。根本原因：训练-推理 harness 不一致 + 注意力向熟悉 token 集中，导致 agent 对训练时见过的工具过度自信、对功能等价的新工具系统性回避。这其实是一个很 general 的问题，可以称之为 **工具过拟合**，本质上是在训练的时候见过一些工具过多，在后续真正的生产环境工作的时候会更偏好这种工具，和这些工具的契合度更好，但是外部工具是多种多样的，其价值不取决于 agent 在训练时候见过没见过，而是取决于对于任务本身的裨益，这就产生了一个 gap，也就是本身的模型任务指标和其训练的 gap

**B（外显，行为层）**：在 K 个功能重合的工具间，agent 偏向"更熟悉的"而不是"在这个任务上更可能有效的"。因为工具过拟合的一就是对工具使用过于自信，这就是问题 A 的外显

**C（信号，数据层）**：要捕捉这个外显的 B 行为，就要有一个可衡量的信号可量化这个行为的程度，当 Agent 根据自己的偏好选择对应的工具后若该工具出现了结果错误，即捕捉到了该信号，我们要做的就是对该信号进行建模


我们本质上是想要解决问题 A，问题 A 是一个根本问题，是一个 general 的问题，在这里就是工具过拟合问题，没办法直接来解决它而只能通过他的外显来间接缓解它，表现 B 就是问题 A 的一个外显，这个 B 就是选工具有偏好，这个 B 动作会产生一个信号就是 C，也就是工具选错，这个选错的判断来自于其输出结果不对，从而我们拿到了一个信号，通过建模这个信号并将其看作一个与 loss 关联的值，通过消掉 loss 去解决 B，从而缓解 A，这是一个比较清晰的故事线，而且是有价值的，因为其最终指向了一个 general 的问题。


在叙述上，我们说真正关键的问题不是 Agent 能否处理超时或异常，而是：**当科学工具正常工作但结果不可靠时，Agent 能否利用同功能工具和其他相关性质发现异常、定位可疑属性、选择更可靠的结果，并恢复后续研发决策。** 这直接影响虚拟筛选、先导优化、蛋白/抗体设计和候选优先级判断的可信度。

## 3. 我们要做什么

### 3.1 七步流程

| 步 | 要做什么 | 产出 |
|---|---|---|
| 0 | 取一批有实验测定值的分子，用几个原理不同的工具各预测一遍同一个性质 | 一张记录表，逐行可核对谁对谁错 |
| 1 | 核查实验值本身可不可信 | 可用分子名单 |
| 2 | 遮住一部分工具，把记录表变成一批题 | 一批题，各带"该不该弃答"的标签 |
| 3 | 让 agent 自己调工具作答，按固定口径算分 | 一个总损失数 |
| 4 | 确认这批题里的信号不是"几个数字分歧大就别信" | 通过或不通过 |
| 5 | 两条改进路线：只改提示，或改权重 | 会先估把握再决定的 agent |
| 6 | 换一套工具、换一个领域，看能不能带走 | 泛化与迁移两组成绩 |

**两道关卡排在改模型之前**：第 1 步查真值站不站得住，第 4 步查信号是不是真的。任一不过就不往下做，这样最坏情况下只损失前四步，而前四步都是脚本和传统统计方法。

### 3.2 第 0 步 · 建多工具预测记录表

取一批有实验测定值的分子，用几个原理不同的工具各预测一遍同一个性质，逐行记下每个工具的预测和实验值。首版选血脑屏障渗透，理由是它有公开实验数据集，也有多个可本地运行的预测模型，同一分子上很容易出现两个不同来源的模型给出相反结论。

**每一行要记的**：分子结构、每个工具的预测值与判定、实验测定值、这一行是否出现跨体系分歧。同一批输入要重复跑几轮，只有几轮结论一致的分歧才算，避免把随机波动当分歧。

举一行看这件事长什么样：胆碱带永久正电荷，按常规判断透不过细胞膜，实验值却是能透过，因为它有专门的转运体。工具里凡是按常规规律推的都会判错，而那正是听起来最有道理的答案。

先做一个性质，验证做法成立后再扩到 pKa、logD、对接打分等同样有盲测或实验数据的性质。

### 3.3 第 1 步 · 核查实验值可信度

实验值从公开数据集直取，而这类数据集不保证内容被逐条审过——初步核查已经发现同一个分子出现相反标签的情况，取哪一条取决于源文件的行序。所以在拿它当裁判之前必须先查。

**要做两件事**：逐行裁决取哪个标签、或者整行剔除，裁决留依据；标出每个分子被哪些工具在训练时见过，之后只在都没见过的子集上比对错。

**为什么这一步不能往后放**：跳过它，后面所有以真值当裁判的数字都不成立，而这类错误在训完模型之后查不出来——那时数字都自洽，只是全都偏了。

### 3.4 第 2 步 · 遮工具造题

几个工具全错的分子很少，太稀疏，考不出"该不该认怂"。做法是每道题只让 agent 看到工具的一个子集，工具的每一种非空组合都出一道题，题量因此放大一个量级。

**弃答标签怎么定**：这道题的可见工具全部判错，就标为该弃答，由记录表按规则算出来，不需要人工判断。

**这批题要分两类**：本来所有工具就全错的，考"真的判不了时认不认怂"；有正确工具被遮掉的，考"能不能察觉证据不足"。两类混在一起会说不清测的是什么。

**同一个分子换一个子集，标签就翻转**。这就是把稀疏信号摊开的机制。

### 3.5 第 3 步 · agent 答题与算分

题面不预先摆出预测值，只给一份工具目录，agent 自己决定调哪个、要不要再多调一个复核，每次调用付代价。它要输出一个把握值，再据此决定作答还是把问题交出去。

**为什么要它主动**：给定一个分子和一个预测值、输出可信度分数，这件事经典方法已经做了几十年，我们没有优势。能拉开差距的是判断"我现在信息不够"，然后自己选一个动作去补。

**怎么算分**：答错罚一分，把问题交出去付一个较小的固定代价，两者加起来是总损失。**这样"什么时候该多查一步"不用我们规定，它从代价里自己长出来。** 成绩要对着三条参照线读——从不交出去、按多数票、只在该交时才交（上帝视角）。

**主任务是"这组结果能不能用"，不是"哪个工具准"**。后者的答案绑在具体工具上，换一套工具就作废；前者问的是这个分子本身难不难，换工具仍然成立。

**一条工程前置**：记录表要先包成几个可独立调用的工具接口，各有自己的名字和参数格式，否则这个形态跑不起来。

### 3.6 第 4 步 · 排除假信号

拿掉分子、只留几个工具的预测数字，用逻辑回归跑一遍。**若成绩打平，说明 agent 没在读分子**，学的只是"几个数字差得远就别信"——这条规律与化学无关，整条故事线作废。

这一步必须排在动模型之前。因为这个假信号跨领域通用，等到测迁移时它会显得很成功，看起来是好消息，实际是假阳性。

同时跑三条零成本对照：模型能不能直接背出答案；一律说"不可信"能拿多少分；同一张表上训个随机森林能做到多好。第三条若打平，说明我们在静态判断上没有贡献，差异只能落在主动取证上。

### 3.7 第 5 步 · 两条改进路线

**路线甲，不动模型**：统一工具目录的呈现方式，让模型没法靠名字眼熟来选；要求 agent 采信任何预测之前先写出自己的把握；把握低时强制再查一个工具。

**路线乙，改权重**：先让模型自己产生轨迹、按结果过滤，用留下来的做监督微调，把"先估把握"变成默认动作；再用一个对把握值的评分规则把它调准。不引外部强模型当老师。

**乙必须跟甲比。** 不先做甲，训练涨的分说不清是权重的功劳还是提示的功劳。

### 3.8 第 6 步 · 验证通用能力

两个方向。一是扣掉一个工具完全不训、只在它上面测；工具之间误差本来就可能相关，所以这里必须同时报两个工具误差的相关系数，否则"换工具仍然有效"这句话无法证伪。

二是换到非化学的、有标准答案的领域测，比如数学题或代码执行。**这个方向的结果只有在第 4 步通过之后才可解读**，顺序不能反。

如果第 4 步或迁移这一步失败，剩下的产出是一套带实验真值的评测集，加上"校准不迁移"这个实证负结果。负结果也可发表。

## 4. 期望结论与分析

以下六条是待验证的预期，不是预设结论。它们说的是我们预计会观察到什么行为；方案本身成不成立由 §3.1 那两道关卡决定，是另一回事。

1. 通用能力更强的 agent 不一定更谨慎。它可能更稳定地盲从专业工具，因为工具在它看来比自己专业。
2. 只看一个工具自报的置信度不足以判断它这次对不对。把工具之间的分歧、分子是否落在工具擅长的范围内、以及其他相关性质放在一起看，应该更有效。
3. 多数投票在工具误差高度相关时会失效。我们四个工具里有三个同源，这种情况尤其可能出现。
4. 复核不是越多越好。多调一个工具能提升准确率，但存在一个拐点，过了拐点只增加成本。
5. 规则型的门控、agent 自己推理、以及两者结合，可能各自适合不同的风险与预算场景，而不是有一个通用最优。
6. agent 即使最后答对，过程也可能是错误诊断加上运气。所以过程和结果必须同时评。

### 4.1 模型消耗与耗时

| 站 | 要不要大模型 | 要不要显卡 | 时间量级 |
|---|:---:|:---:|---|
| 第 0 步 建记录表 | 只用本地预测模型 | 不用 | 几天 |
| 第 1 步 核查实验值 | 不用 | 不用 | 一两天，主要花在人工裁决那几行 |
| 第 2 步 造题 | 不用 | 不用 | 分钟级 |
| 第 3 步 答题与算分 | 要 | 不用 | 贯穿全程 |
| 第 4 步 排除假信号 | 部分要 | 不用 | 几天 |
| 第 5 步 路线甲 只改提示 | 要 | 不用 | 几天 |
| 第 5 步 路线乙 冷启动 | 要 | 要，一张卡 | 几天 |
| 第 5 步 路线乙 强化 | 要 | 要，数张卡。全流程主要开销在这里 | 一到两周 |
| 第 6 步 验证通用能力 | 要 | 要 | 几天 |

三条说明：

- 走公开接口还是本地部署，成本结构完全不同。前面几站用量小，走接口最省事；强化阶段要反复采样，用量大，本地部署更划算。我们此前的实测参照是一轮十几次运行花几美元、耗时半小时量级。
- 用多大的模型还没定。冷启动之后看拒绝采样的保留率：保留率太低说明基座模型撑不住这个行为，要换更大的，显卡预算同比例上调。
- 强化阶段的开销随题目数量线性放大。第 4 步 之后若需要扩量，这一项跟着涨；第 1 步 若剔除受污染的行，题目数会变少。

## 5. 这件事对制药领域有什么用

本项目不做新的对接、性质预测或结构预测模型，做的是这些工具之上的一层可靠性评测。具体产出四样东西：

- 一批带实验真值的工具冲突数据，以及配套的评测协议。冲突来自真实模型残差，不是人工注入的。
- 一套判分口径，能量出 agent 在真实模型误差下"什么时候该相信计算结果"的判断质量，而不只是任务完成度。
- 一份关于"哪片化学空间不能信计算"的读数。这对研发团队的直接用处是决定哪些候选必须做实验验证。
- 一条从评测到改进的通路：先用不改权重的办法改外壳，再看改权重能不能再进一步，两者都对着同一批题和同一套参照线读。

## 6. 未来可继续推进的方向

§3 已经把"学习哪片区域不能信工具""预算约束下的主动复核""面向恢复过程的训练""换一套工具重测"这四条收进主线了，本节只列还没进主线的方向。

1. 跨性质约束推理。建立一个可执行的约束层，把结构、亲和力、物化性质、代谢与毒性、稳定性、成药性连起来，帮 agent 区分三种情况：真的互相矛盾、单位或定义不同、以及本来就该随条件变化。本轮只作为判分侧的配套，用来校验 agent 给出的理由是否成立，不作为提示喂给 agent——否则测的就变成指令遵循了。
2. 规划、执行、审计三个角色分工。让一个角色专门检查证据来源、参数一致性、未验证的假设和替代解释。与本项目"单个 agent"的硬边界冲突，本轮不启动。
3. 人机协同与湿实验闭环。在高风险或者确实判不了的情形下允许 agent 向专家求助，再进一步做前瞻性盲测或小规模湿实验。专家介入会破坏可重复性，湿实验目前没有条件，所以本轮只保留"把问题交出去"作为 agent 的一个输出选项，不真的接人。
4. 扩到其他模态与研发阶段。从小分子和蛋白抗体扩到核酸、蛋白降解剂、细胞与组学工具，研究上游的冲突如何传播到候选排序、安全性判断和继续或停止的决定。与"本轮收敛到制药单一性质"的裁定冲突，本轮不启动。
