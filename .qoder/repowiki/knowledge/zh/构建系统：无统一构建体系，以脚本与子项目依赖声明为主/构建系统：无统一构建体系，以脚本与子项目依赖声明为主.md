本仓库是一个研究性基准数据集与实验集合，**不存在统一的顶层构建系统**。根目录没有 Makefile、Dockerfile、.github/workflows、setup.py、pyproject.toml 或 build.sh 等任何集中式构建/打包/CI 配置。项目的“构建”本质上是按 task 维度分散的 Python 脚本执行与第三方子项目自带的依赖声明。

具体表现如下：
- **核心内核 autonomy_mvp** 仅包含纯 Python 源码与 JSON 任务定义，无任何 setup/pyproject/requirements，运行方式即 `python -m ...` 或直接调用 `run_validation.py`，依赖由用户自行安装。
- **长程任务实例化脚本**（`longhorizon/instantiate/case*_instantiate.py`、`batch_caseD.py`）同样为裸 Python 脚本，无打包元数据。
- **task1–task7 各实验目录**各自存放 runner/eval 脚本，运行方式均为 `python xxx.py`，不经过统一入口。
- **子项目自带依赖管理**：
  - `task6/archive/survey_landscape.md` 提及 BioProt 使用 `pyproject.toml` 声明 MIT 许可；
  - `deep_research_longhorizon/datasets/MultiAgentBench_MARBLE/REPO_README.md` 说明用 `poetry run pytest` + `mypy --config-file pyproject.toml`；
  - `deep_research_longhorizon/datasets/OdysseyBench/REPO_README.md`、`WebCanvas_Mind2Web-Live/REPO_README.md`、`Who_and_When/README.md` 均要求 `pip install -r requirements.txt`；
  - `task7/poc1_do_challenge/do-events-challenge2025/server/Dockerfile` 基于 `requirements.txt` 构建镜像；
  - `task7/poc3_physicianbench/PhysicianBench/` 是独立可安装包，含 `pyproject.toml`、`uv.lock`、`.venv` 等完整打包结构。
- **容器化仅在 POC 子项目内出现**：`do-events-challenge2025/server/Dockerfile` 和 `docker-compose.yml`，以及 TheAgentCompany 文档中引用的外部 Plane 部署 compose，均非本项目自身产物。
- **下载与采样工具** `deep_research_longhorizon/download_samples.py` 通过 GitHub Contents API / LFS media 通道拉取样本，属于运行时脚本而非构建流程。

结论：该仓库采用“脚本驱动 + 子项目自管依赖”的松散模式，未建立跨模块的统一构建、测试、打包与 CI 流水线。若需引入统一构建系统，建议从根级增加 `pyproject.toml`（或 `Makefile`）作为聚合入口，将各 task 的 runner 注册为 entry point，并补充 `.github/workflows` 实现自动化测试与发布。
