本模块是「POC 索引层」,不实现评测逻辑,而是把已有 `../autonomy_mvp/` 与外部 benchmark 仓库拼装成可运行的验证脚本:
- 顶层 `goal.md` / `README.md` 定义 3+1 个 POC 的目标、先后顺序与交付物,`evaluator/` 为共享 grader/agent harness 空目录(待扩 autonomy_mvp 时落代码)。
- 每个 POC 子目录自包含:入口脚本(`run_pocX.py`)负责准备 mock 输入 → 调用外部评测器 → 解析结果 → 写 `_job/pocX_summary.json`;`_job/` 是运行时工作区,按任务名建 `workspace/output/`(被测产物)和 `logs/agent/trajectory.jsonl`(轨迹日志),由被测 agent 或 mock 写入。
- POC 3(PhysicianBench)直接 fork 上游 `PhysicianBench/` 仓库,通过 `uv run pytest tasks/v1/<task>/tests` 跑其内置 6 个 cp;POC 3 入口只写 mock note 与 trajectory,其余全部委托 upstream repo。
- POC 4(PharmaBench)在本地硬编码 5 个 Tier1 硬校验 cp + 2 个 Tier2 LLM judge cp,复用 `autonomy_mvp.core.judge._judge_value_set/_judge_selection` 与 `Stage`,并自行实现加权聚合(binary Pass@1 vs weighted_equal vs weighted_by_tier)。
- 依赖方向单向:POC 脚本 → autonomy_mvp(core.judge, core.tasks.Stage) → 外部 benchmark 仓库;POC 之间互不引用,可并行独立运行。
