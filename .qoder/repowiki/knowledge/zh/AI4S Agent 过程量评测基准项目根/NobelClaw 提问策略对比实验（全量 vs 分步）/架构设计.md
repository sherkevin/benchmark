模块由「实验设计文档 + 两套 Runner + 多轮会话产物」构成：
- `goal.md` 定义受控变量法（条件 A=单条消息包含全部子步骤；条件 B=N 条消息一问一答）、评估维度与停止准则。
- `runner.py` 对接调试后端 `mlflow-debug-ymwhij-8001/api/v1`，提供 `all`/`all_cont`/`step` 三种模式，自动解析 SSE 事件中的 `decomposition`/`tool_call(propose_decomposition)` 并发送 `{confirmed_tasks:[...]}` 确认，支持 `continue` 循环驱动直到工具调用数不再增长。
- `runner2.py` 对接生产前端 `nobelclaw.aliyun-inc.com/api/v1`（Bearer JWT），提供 `single`/`multi` 模式，用于回放由 `multi_turn_user.py` 生成的反应式对话。
- `multi_turn_user.py` 仅产出系统提示 `REACTIVE_USER_SYS`，实际交互由上层 Claude 会话按规则逐轮生成下一句用户消息。
- 每个 `session_i/` 是独立对照样本：`prompts/` 存放 A/B 的 prompt 文本，`.raw/` 保存原始 JSON 流，顶层 `A_all_at_once.md`、`B_step_by_step.md`、`eval.md` 记录结果与打分。
- 分析层 `analysis.md` 汇总结论，`analyze.py`、`audit5.py`、`verify6.py`、`check_consistency.py`、`clean_qa.py`、`render.py`、`turn.py` 为辅助脚本（审计固定报告、验证数值链一致性、渲染 Markdown 等）。
依赖方向：所有 runner → HTTP → 平台 API；session 产物只读；分析脚本读取 session 产物，不反向写回。
