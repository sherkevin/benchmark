## 简介
本文件为“工作流引擎核心”的API与实现文档，聚焦以下目标：
- 工作流定义语法、任务依赖图构建与执行调度机制的接口设计
- 状态机管理、事件驱动架构与异步执行模型
- 工作流模板系统、变量路由与条件分支控制接口
- 工作流实例化、版本管理与生命周期控制
- 监控、日志收集、性能统计与故障恢复
- 调试工具、断点设置与单步执行
- 安全沙箱、权限控制与资源隔离

说明：仓库中未包含完整的工作流引擎源码，但存在若干可映射到工作流能力的模块（如编排入口、中断处理、评测指标、模拟代理、任务定义等）以及模板系统与路由文档。本文基于这些材料进行系统化梳理，并以概念性图示呈现通用工作流能力，同时标注实际代码来源以增强可追溯性。

## 核心组件
本节概述与“工作流引擎核心”相关的核心模块职责与交互关系，并给出面向API设计的要点。

- 编排入口（harness）
  - 职责：加载任务、组装上下文、驱动执行流程、协调中断与结果汇总
  - API关注点：启动参数、上下文注入、回调钩子、错误传播
- 任务定义（tasks）
  - 职责：声明式描述任务节点、输入输出契约、依赖关系
  - API关注点：任务注册、参数校验、依赖解析
- 模拟代理（sim_agents）
  - 职责：提供可插拔的执行体，用于替代真实外部调用或LLM调用
  - API关注点：代理注册、调用协议、超时与重试
- 评判器（judge）
  - 职责：对执行结果进行判定与打分
  - API关注点：评分策略、阈值配置、失败归因
- 指标与排名（metrics, ranking_metrics）
  - 职责：计算过程与结果指标，支持多指标聚合与排序
  - API关注点：指标注册、聚合函数、导出格式
- 中断处理（interruption）
  - 职责：响应外部中断信号，支持优雅退出与检查点保存
  - API关注点：中断事件、恢复点、持久化策略
- 模板与路由（template, outliners, variable_routing, tool_routing）
  - 职责：模板渲染、大纲生成、变量与工具的路由规则
  - API关注点：模板语言、变量作用域、路由匹配与优先级

## 详细组件分析

### 编排与执行（harness）
- 功能要点
  - 加载任务清单与上下文
  - 构建任务依赖图并进行拓扑排序
  - 按依赖顺序调度任务执行，支持并行度控制
  - 捕获异常并记录诊断信息
  - 暴露中断钩子，支持优雅停止与检查点
- 关键接口建议
  - 初始化：传入配置、上下文、插件注册表
  - 运行：提交工作流定义，返回实例ID与状态查询句柄
  - 控制：暂停、恢复、终止、重启
  - 查询：获取任务状态、进度、输出与错误
- 错误处理
  - 区分可恢复与不可恢复错误
  - 提供重试策略与退避算法
  - 将错误分类并写入审计日志

### 任务定义与依赖图（tasks）
- 功能要点
  - 声明式任务节点：名称、输入输出、执行体、资源需求
  - 依赖关系：显式边或隐式通过变量名推断
  - 校验：循环依赖检测、缺失输入提示
- 关键接口建议
  - 注册任务：类型、处理器、参数模式
  - 解析依赖：生成DAG并校验
  - 序列化/反序列化：支持版本迁移
- 复杂度与优化
  - DAG构建时间复杂度近似O(V+E)
  - 缓存已解析的依赖图以提升重复实例化效率

```mermaid
flowchart TD
Start(["开始"]) --> Load["加载任务定义"]
Load --> Parse["解析依赖关系"]
Parse --> Validate{"是否存在循环依赖?"}
Validate --> |是| Error["抛出依赖错误"]
Validate --> |否| BuildDAG["构建DAG"]
BuildDAG --> Cache["缓存依赖图"]
Cache --> End(["结束"])
Error --> End
```

## 性能考虑
- 依赖图构建与缓存
  - 首次构建后缓存DAG，避免重复解析
  - 增量更新：仅重算变更的子图
- 并发与资源限制
  - 控制最大并行度，防止资源争用
