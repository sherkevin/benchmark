# 五类文档：骨架模板与必答清单

> 用法：按 SKILL.md 铁律一的路由表定类型，抄对应骨架搭结构，写完拿对应必答清单逐项对。三档标注制（实答带出处 / 推断带依据 / 明写没查到）全类型通用。

## 一、方法阐述 / 阅读报告（X 是怎么工作的）

骨架：

```
# X 是怎么工作的
一句话：<入口是什么，经过什么，出口是什么，最硬的一个数字>
速读区：3–7 条带数字的关键事实

## 一条<样本>从进到出
进：<格式 + 真实例值>
站 1：<做什么、谁做的、出什么、为什么有这站>
站 2：...
出：<被谁怎么消费/判分>

## <论文/README>没写的
## 对我们的用处（读者是自己团队时）
```

必答清单（8 项，SKILL.md 已列全）：输入例值、输出与消费方式、逐站四要素、每站实现方式与关键参数、规模数字、人做还是自动、防坑机制、边界与自认局限。

活范例：`research/各benchmark造题法详解.md` §1（CNS 题走全程）、`reference/tau-bench/tau-bench.md`。

## 二、调研报告（有没有人做过 X / 该选哪条路）

骨架：

```
# <调研问题原文>
一句话答案：<直接回答问题，含最关键的取舍>
速读区：结论要点 + 数字

## 读前必备的区分（若概念易混，先立边界，如"过程量评测≠进度度量"）

## 证据组 1：<小结句就是该组结论>
<每条证据：谁、做了什么、关键数字、出处>
## 证据组 2：...

## 反面证据（主动找过推翻结论的材料吗，找到了什么）
## 没查到的 / 仍开放的问题
## 对我们的直接影响（读者拿结论去干什么）
```

必答清单（7 项）：

1. 调研问题原文（一句话，放开头，防止答非所问）
2. 一句话答案（不许"视情况而定"糊过去，有条件就把条件写明）
3. 检索范围：查了哪些来源、多少篇、截止什么时间——这决定结论的可信边界
4. 每条结论配证据和出处（可复核的文件/链接/章节），孤证要标"仅一例"
5. 反面证据：有没有专门找过"证明结论错"的材料，结果如何
6. 没查到什么，哪些问题仍然开放
7. 对我们的直接影响：这个结论改变什么决定

活范例：`research/中间检查点构建方法调研.md`（五条路、每条一个真实任务走例、速读一句话结论）。

## 三、对照分析（我们和别人差在哪）

骨架：

```
# <对比要支撑的主张/决定>
一句话：<合起来差异是什么，能主张什么、不能主张什么>

## 对比原则（谁入选谁不入选，为什么）

## 维度 1：<按重要度排，不按发现顺序>
我们怎么做：<与对方同等粒度：有走例、有例值、有出处>
别人怎么做：<同上>
差异定性：<真差异 / 互有取舍 / 我方不如人，三选一，如实>

## 总结：合起来说明什么（放不下就把总结表复制一份到开头当速读区）
```

必答清单（6 项）：

1. 对比目的：这次对比要支撑什么决定或主张
2. 对比原则：入选与排除标准（只跟真做过这件事的比）
3. 维度按重要度排序
4. **双方粒度对等**：别人给了例值和参数，我方也必须给走例、例值、出处——最常见的病是"引别人有编号引文，说自己是裸断言"
5. 每个维度给差异定性：真差异 / 互有取舍 / 我方不如人，不许含糊
6. 总结先行：最重要的定性结论（比如"这是应用型贡献不是方法型贡献"）必须出现在第一屏，不许埋在文末

## 四、进展 / 验收报告（干到哪了、做完没有）

骨架：

```
# <任务名> 进展/验收
一句话：<N 项里完成 M 项，最大的洞是什么>

## 对齐的目标（上游哪份文档哪一条）
## 完成判据（事先定的验收标准，不许事后补）

## 逐项状态
| 项 | 状态(完成/部分/未动) | 证据锚点(命令+输出+文件/commit) |

## 未完成项与风险（卡在哪、需要谁）
## 下一步（谁、干什么、完成判据是什么）
```

必答清单（6 项）：

1. 对齐的目标：上游文档与条目，防任务漂移
2. 完成判据：验收标准是事先定的哪几条
3. 逐项状态三选一（完成/部分/未动），禁止"基本完成""大体就绪"
4. 每个"完成"必须带证据锚点：跑了什么命令、输出什么、落在哪个文件、哪个 commit——没锚点就降级为"声称完成，待验"
5. 未完成项与风险如实列，含"卡在谁那里"
6. 下一步可执行：有负责人、有动作、有判据

## 五、决策记录（为什么这么定）

骨架：

```
# <决定了什么>（一句话，精确到可执行）
状态：<提议/已裁定/已废弃> ｜ 裁定人 ｜ 日期

## 问题与触发事件（出了什么事才需要决定）
## 约束（哪些是硬的，谁定的）
## 选项与取舍
| 选项 | 好处 | 代价 | 为什么没选 |
## 决定内容（精确、可验收，含生效范围）
## 后果（影响谁、要改什么、什么条件下复审）
```

必答清单（6 项）：

1. 要解决的问题与触发事件（没有触发事件的决策要说明为什么现在决）
2. 约束条件：哪些是硬约束、由谁定的（owner 原话直接引用）
3. 每个候选选项至少一句公平陈述，不许立稻草人
4. 取舍理由：选它放弃了什么，代价明说
5. 决定内容精确到可执行、可验收
6. 生效范围与复审条件

活范例：`governance/adr/` 下的既有 ADR。

## 通用兜底

不属于五类的文档（如操作规程、FAQ）：主线自定，但三条铁律照用——有一条能走到答案的线、先总后分、人话；完整性底线是"读者不需要追问就能行动"。
