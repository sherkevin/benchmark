# 正反例解剖：同一篇论文的两种写法

> 素材：MLE-bench（ICLR 2025，OpenAI）。事实全部来自 `reference/ICLR-MLE-bench/阅读报告.md`，两个版本信息量相同，写法不同。

## 反面：属性切片式（典型 AI 产出，禁止）

> MLE-bench 是 OpenAI 推出的一个全面而系统的机器学习工程能力评测基准，标志着 agent 评测领域的重要进展。
>
> **核心创新**：该基准创新性地引入了真实世界的 Kaggle 竞赛作为评测载体，充分保证了任务的真实性和挑战性。
>
> **技术架构**：系统采用了离线化处理机制、标准化评分流水线和人类基准对齐策略，构建了完整的评测闭环。
>
> **评测维度**：涵盖数据处理、特征工程、模型训练、超参调优等多个维度，全面考察 agent 的综合能力。
>
> **重要意义**：MLE-bench 为机器学习自动化研究提供了坚实的基础，对推动领域发展具有重要意义。

**病理报告**（对照 checklist.md 的编号）：

| 病 | 出处 |
|---|---|
| 空洞拔高（#1） | "标志着重要进展""具有重要意义" |
| 万能形容词（#2） | "全面而系统""充分保证"——75 个竞赛、24h 预算这些数字一个没有 |
| 报菜名（#5） | "离线化处理机制、标准化评分流水线、人类基准对齐策略"——三个名词零解释 |
| inline-header 列表（#8） | 四个加粗标签，每个标签下面是复读 |
| 数据流缺失 | 读完不知道：一条题长什么样？agent 交什么？分怎么算出来的？ |

8 项必答清单命中 0 项。读者读完只能去追问，这正是要根治的病。

## 正面：数据流式（目标写法）

> **一句话：把 75 个 Kaggle 竞赛离线化成考场，agent 每题最多自主跑 24 小时，交一份 submission，分数扔进该竞赛的人类排行榜里定位——最好的组合（o1-preview + AIDE）在 16.9% 的竞赛里达到铜牌水平。**
>
> 一条题从进到出走一遍：
>
> 1. **进**：一个 Kaggle 竞赛，含任务描述、数据集、官方评分逻辑。作者人工筛掉了无法复现评分的竞赛，留 75 个，另备 7 个当开发集防过拟合。
> 2. **重切数据**：原竞赛的测试集标签不公开，作者从公开训练数据里重新切出 train/test。不切就没法本地判分，这一步是整个"离线化"的全部内容。
> 3. **agent 答题**：拿到描述和数据后自主干活（读数据 → 特征 → 建模 → 调参），最长 24 小时，最终必须产出一份 submission 文件，缺了就是 0 分。
> 4. **判分**：用复现的官方评分逻辑算原始分。
> 5. **出**：原始分本身没有语义（不同竞赛量纲不同），所以把它放进该竞赛几千人的公开排行榜分布里，报"达到铜/银/金牌与否"。这就是它解决"开放任务没有唯一答案怎么判"的办法。
>
> 论文没写的：竞赛筛选的完整标准只给了排除项；24h 这个预算怎么定的没解释。
>
> 对我们的用处：open 类题没有唯一答案，可以学它——把 agent 给出的候选放进已知材料的性质分布里，报"击败了库中 x% 的已知分子"。

**为什么这版好**：

- 第一句就是全文（速读区），后面不看也带走了结论。
- 五步就是数据流，每步都回答了"进什么、做什么、出什么、为什么"。第 2 步顺手解释了"离线化"这个术语的全部含义——术语跟着数据流走，不用单独开一节。
- 数字全部落位：75、7、24h、16.9%。
- "论文没写的"明确列出，读者不用追问就知道边界在哪。
- 结尾落在"对我们的用处"，重要度排序里读者最关心的事没有被省略。
