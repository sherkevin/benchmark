# 技术文档写作：主线、重点、人话

> **一句话：任何文档都必须有一条读者能顺着走到答案的主线，主线类型由文档要回答的问题决定。** 解释"X 怎么工作"就走数据流（带一条真实数据从入口走到出口），回答"有没有人做过/该选哪个"就走问题→结论→证据。主线讲不出来，说明你自己还没想清楚——回去补课，不要动笔。

三条铁律，对应技术文档最常见的三种死法：

| 铁律 | 治什么病 |
|---|---|
| 一、一条主线（机制类=数据流） | 术语堆砌、结构散乱，读完画不出流程图、拼不出答案 |
| 二、先总后分 + 重点前置 | 啰嗦、抓不住重点、重要信息被追问才说 |
| 三、人话 | AI 腔、死板、不通顺、不像人写的 |

**适用**：方法阐述、阅读报告、调研报告、对照分析、进展/验收报告、决策记录、交接与汇报文档。
**不适用**：论文投稿正文（用 paper-writer）、代码注释、commit message。

## 第 0 步：动笔前必答三问

在草稿顶部先写下三行（交付前删掉）：

1. **读者是谁，读完要能干什么？** 能复述方法？能做决策？能接手干活？
2. **核心结论一句话是什么？** 写不出来 = 还没想清楚，先想清楚再动笔。
3. **主线是什么？** 先按铁律一的路由表判断文档类型：机制类是"输入→几站→输出"，调研类是"调研问题→答案→证据组"，其他类型见路由表。

答不上来就去问用户或回去读材料，不要硬写。

## 第 1 步：先搭骨架，确认了再填肉

防止写完三千字才发现结构错了。骨架 = 主线一行一节 + 每节一句话小结。机制类的骨架长这样：

```
输入：一条 Kaggle 竞赛（任务描述 + 数据集 + 官方评分逻辑）
→ 站1 离线化：从公开训练数据重切 train/test（原测试标签不公开，不切就没法判分）
→ 站2 agent 答题：自主运行最长 24h，产出 submission.csv
→ 站3 判分：用复现的官方评分逻辑算出分数
→ 输出：把分数放进该竞赛的人类排行榜分布，报"是否达到铜牌水平"
```

其他类型的骨架模板见 [templates.md](templates.md)。

用户在场就先给用户过目；批量/子任务模式无人可问时自查：机制类查**站与站能不能咬合——上一站的输出就是下一站的输入**；其他类型把每节小结连起来读，**是不是一段能回答文档问题的通顺论证**。咬不上、连不通，说明理解有洞，回材料里补。

## 铁律一：一条主线（结构层）

先按文档要回答的问题选主线，五类骨架的完整模板和各自的必答清单见 [templates.md](templates.md)：

| 文档回答的问题 | 类型 | 主线 |
|---|---|---|
| X 是怎么工作/实现的？ | 方法阐述、阅读报告 | 数据流：入口 → 逐站变换 → 出口 |
| 有没有人做过 X？该选哪条路？ | 调研报告 | 调研问题 → 一句话答案 → 按证据组展开 |
| 我们和别人差在哪？ | 对照分析 | 逐维对比，维度按重要度排 |
| 干到哪了？做完没有？ | 进展/验收报告 | 目标 → 完成项(带证据) → 未完成项 → 风险 |
| 为什么这么定？ | 决策记录 | 问题 → 约束 → 选项与取舍 → 决定 → 后果 |

不在五类里的就近套（周报≈进展报告，交接≈机制阐述+进展报告）。数据流是其中最难写好、也最常写砸的一种，展开讲：

### 机制类怎么写（数据流）

- **选一个具体例子贯穿全文**。一条真实样本、一个真实 query、一个具体分子，带着它走完全程。抽象规则跟在具体例子后面讲，不要反过来。
- **每一站写足四要素**：

| 要素 | 要求 |
|---|---|
| 进什么 | 给具体形状和例值，不是类型名——"一个 JSON，长这样：`{...}`" |
| 做什么 | 具体的变换/算法/规则，以及**谁做的**（程序？人工？LLM？） |
| 出什么 | 同样给例值 |
| 为什么有这站 | 删掉它会坏什么。素材没写设计动机时允许自己分析，但措辞上必须和事实可区分（"这一步的作用应该是……"），不冒充作者原意 |

- **公式下方紧跟"其中："**，逐项解释每个符号是什么、由谁算出、取值范围，读者不需要翻别处。
- **术语首次出现必须紧跟大白话解释**（括号或一句话），全篇同一个概念只用同一个词，不换着叫。
- **区分"算出来的"和"学出来的"**：哪些量是规则/几何关系确定性算出的，哪些是模型学出来的，逐个说清。

### 属性切片：全类型禁止的写法

把内容拆成"创新点 / 核心优势 / 技术架构 / 主要贡献"四节，每节罗列名词——读者读完记住一堆名词，却画不出流程图、拼不出答案。

**判据：读完任何一节，能不能回答"这时数据/论证推进到哪了"？不能，就是切片文，重写。**

### 机制类必答清单（8 项）

阐述一篇论文/一个系统怎么实现时，以下 8 项每项必须有答案，或明确写"论文没写/没查到"。这条治"忽略重要信息、要读者追问"。**其他四类文档各有自己的必答清单，在 [templates.md](templates.md)；下面的三档标注制全类型通用**：

1. 输入长什么样（格式 + 一条真实例值）
2. 输出长什么样，被谁怎么消费/判分
3. 中间经过几站，每站四要素
4. 每站的实现方式：规则？模型？人工？关键参数和阈值是多少
5. 规模数字：数据量、步数、耗时、成本
6. 哪些环节是人做的、哪些是自动的（这决定别人能不能复制）
7. 防坑机制：怎么质检、防作弊、防数据污染
8. 边界：什么情况下失效，作者自己承认的局限

每项的答案分三档标注，禁止混用：

- **实答**：素材里有明文，直接写，带出处。
- **推断**：素材没明说但能从证据推出来，写成"推断：……（依据：X）"，不许写成断言。
- **没写**：查不到也推不出，就写"论文没写"。它本身就是重要信息，禁止用"业内普遍认为"之类的话盖过去。

## 铁律二：先总后分 + 重点前置（内容取舍层）

- **全文开头设速读区**：一句话结论 + 3–7 条带数字的关键事实。读者只看速读区也能带走答案。
- **每节第一句 = 该节结论**。跳读者只读每节首句也能跟上主线。
- **按读者关心程度排序，不按论文章节顺序**。读者最想问的问题先答。
- **数字换形容词**："75 个竞赛、每题最长 24h"，不写"大量竞赛、长时间运行"。
- **删除测试**：交付前逐段自问"删掉这段，读者损失什么？"答不上来就删。同一信息第二次出现就删。
- **背景铺垫最多两句**。读者要答案，不要上课。
- **信息完整优先于篇幅**：篇幅要求和 8 项必答冲突时，砍废话、不砍必答项。

## 铁律三：人话（语言层）

写完逐句过一遍去 AI 腔自查，完整模式表见 [checklist.md](checklist.md)。最高频的几条：

| 模式 | 反例 | 处理 |
|---|---|---|
| 空洞拔高 | "标志着……的重要里程碑" | 删，或换成具体事实 |
| 万能形容词 | "强大/高效/显著提升"（无数字） | 换成数字，换不了就删 |
| 八股连接词 | "值得注意的是/综上所述/总而言之" | 直接删，句子照样通 |
| 假排比 | "不仅……更是……"、强行三连 | 拆成平实陈述句 |
| inline-header 列表 | "**性能**：性能得到了提升" | 合并成正常句子 |
| 报菜名 | "采用了X机制、Y架构、Z策略"（不解释） | 每个名词讲清，讲不清就删 |
| 编话填坑 | 查不到就写"业内普遍认为……" | 写"没查到"，就此打住 |
| emoji / 滥加粗 | 🚀✅、整段加粗 | emoji 禁用；一屏加粗不超过 3 处 |

**通顺测试**：拗口的句子念出来，一口气读不完就拆短。一句话只说一件事。

## 交付前自检（5 问，逐条过）

1. 只读速读区，能不能知道核心结论？
2. 顺着文档，能不能复述主线——机制类能画出数据流图，其他类能把"问题→答案→证据"一口气讲完？
3. 有没有术语没解释？有没有公式符号没在"其中："里出现？
4. 本类型的必答清单是否每项有答案或标了"没写"？
5. 随机挑三段做删除测试，真的删不动了吗？

重要交付再加一步读者测试：开一个无上下文的子 agent，只给它文档，让它回答读者最可能问的 5 个问题；答错的地方就是文档的洞，修完再交。

## 重写存量文档模式

用户扔来旧文档要求"改成人话"时，按此流程：

1. **先诊断后动笔**，报三行诊断：结构（主线是什么、断在哪，是不是属性切片）、完整性（本类型必答清单缺几项）、语言（AI 腔浓度，引 2–3 句原文为证）。
2. **缺信息先补课**：必答清单缺的项，去源头（论文/代码/数据）查，查不到标"没查到"。**禁止只做语言润色掩盖信息缺失——那是给烂结构打蜡。**
3. 按第 1 步搭新骨架 → 迁移旧文档里活的内容（数字、事实、例子、出处）→ 按三铁律重写。
4. **旧文档的具体数字、出处、锚点一个不许丢；语言可以重写，事实必须原样搬运，禁止在重写中发明新事实。**
