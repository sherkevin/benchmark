# AAMAS 论文行文结构与段落逻辑审计

日期：2026-09-29
状态：研究依据；不替代三份生效评价标准。
目的：把“好论文为什么读起来成立”拆成可检查的段落功能、论证顺序和转接规则，并映射到本项目的医药工具选择故事。

## 1. 先把结论说清楚

AAMAS 没有规定“录用论文必须有几段引言、每段必须写几句”。论文被录用也不是因为套中了某个模板。能稳定复用的是一种**论证行为**：论文先让读者接受一个重要而具体的现实问题，再展示一个可复现的失效，再解释失效的原因，提出只针对这个原因的机制，最后用与机制一一对应的证据收口。

因此，本文档不是录用承诺，也不是官方评分表。它是根据 AAMAS 官方的 originality、significance、soundness、reproducibility、clarity、relevance、presentation、state of the art 要求，结合原文级阅读和 `earning-roles` 项目的结构审查材料，形成的内部写作约束。

## 3. 好论文的段落行为逻辑

### 3.1 一篇论文只有一个主张轴

论文先确定一句可以在走廊里复述的话。它不是标题里的技术名，而是：

> 在什么现实条件下，什么旧假设会失败；我们改变了什么对象或计算；哪组证据能证明这个改变确实有用。

全文每一节都要回答这条主张轴的一部分：

- Introduction 让读者理解问题和 insight；
- Method 把 insight 变成对象、接口和更新；
- Experiments 测试它是否超过最强替代解释；
- Discussion 说明结果意味着什么、在哪些条件下失效；
- Conclusion 留下一条可迁移的教训。

如果删掉一节后主张更紧凑，说明这节没有服务主轴，应移到 appendix 或删除。

### 3.2 引言的六段漏斗

这是一个高频结构，不是死模板。每段只承担一个任务，最后一句把问题交给下一段。

| 段落 | 只回答一个问题 | 本项目要写什么 | 末句如何转接 |
|---|---|---|---|
| P1 立场景 | 领域为什么在意？ | 科学工具正在成为 agent 的可调用能力；同一性质可由多个 provider 估计 | 但“能返回”不等于“可用” |
| P2 定失败 | 具体哪里坏？ | 同一分子/端点上 provider 正常返回但互相矛盾；给一个可核对案例 | 这不是格式问题，而是选择时无法知道谁会错 |
| P3 剖根因 | 旧方法为什么不够？ | 调用前不能看未选输出；正确性反馈 selected-only 且延迟；post-call confidence 与 pre-call choice 属于不同信息 | 因此静态赢家和普通即时 bandit 没有覆盖同一个时序 |
| P4 写洞察 | 我们真正改变了什么？ | 把调用前选择、调用后验证/升级和延迟更新拆成同一事件合同中的不同阶段；动态 JEV 是可恢复状态，不是一个新名字 | 这个切口必须进入 formal model 和实验 |
| P5 述方法 | 方法怎样落地？ | 输入、provider 状态、事件队列、选择/验证/更新接口，以及计算/内存代价 | 下一节定义对象和信息边界 |
| P6 列贡献 | 哪些是可验证贡献？ | 每个 bullet 写“主张 + 对照/证据 + 失败条件”；没有真实结果时只能写候选，不写提升 | 读者应知道后文哪张表回答哪条主张 |

引言不得按“我们先尝试了 A，后来改成 B”写。失败尝试进入 ablation、error analysis 或 appendix；正文先给最终研究对象和公平比较边界。

### 3.3 段落内部的三步

每个正文段落默认遵循：

1. **Topic sentence**：第一句说本段要证明或定义的关系；不能只说“本节介绍……”；
2. **支持句**：给事实、反例、公式、引用或实验观察；每个符号第一次出现要解释并给一个实例；
3. **桥接句**：说明这段结果为什么把读者带到下一段，而不是重复本段内容。

一个段落只做一个动作。以下内容应拆开：问题的重要性、方法定义、实验结果和局限不能塞在同一段里。长段落不是深度；如果第一句抽出来不能形成连贯 outline，说明段落顺序或 topic sentence 有问题。

## 4. 各章节的行为顺序

### 4.1 Abstract：六到八句完成一次闭环

1. 现实实践；
2. 具体失败或知识缺口；
3. 命名研究对象/视角；
4. 一句说清机制改变了什么；
5. 说明覆盖哪些任务、端点、baseline 和反馈条件；
6. 只写真实证据支持的 headline result；
7. 写机制性发现或边界；
8. 留下一条长期意义。

没有 confirmation 数字时，摘要只能写问题、协议和证据边界，不能用 development replay 的数字装成方法效果。

### 4.2 Related Work：按冲突关系写，不按年份堆

每个小段先命名一个最近工作族，再说它解决了什么，最后只用一句话说明与本文的差异或继承关系。对本项目至少分三组：

- static/offline tool routing；
- contextual online provider selection；
- delayed/partial feedback 或 dynamic model pool。

P04/P06 已经覆盖 contextual provider selection；因此 related work 的任务不是证明“没人做过工具选择”，而是精确指出 selected-only delayed correctness、provider/version lifecycle 和 recoverable update 是否被覆盖。

### 4.3 Problem/Method：先接口，再步骤，再替代方案

每个方法小节开头用 1–2 句告诉读者本节要解决什么。固定顺序是：

1. **输出是什么**：selector、verifier、updater 各自输出什么，什么时刻输出；
2. **输入和可见信息是什么**：分子、端点、菜单、已释放事件、当前 provider output；
3. **执行步骤是什么**：选择、调用、终止、反馈释放、状态更新；
4. **公式/伪代码是什么**：只写前面已经解释过的对象；
5. **替代方案为什么不够**：放在机制说明末尾，不能先让读者走一圈失败路线。

方法段落的公式必须可实现：每个原始符号都要有具体 case；不能临时添加没有数据来源的新状态变量。复杂度、更新 p95、内存和恢复语义属于方法定义，不留给实验读者猜。

### 4.4 Experiments：按研究问题，不按执行顺序

建议固定成四个 RQ：

- RQ1：直接选择任务是否比 Best Fixed 和最强合法在线近邻更好？
- RQ2：调用后验证/升级是否在匹配调用成本下提升最终正确性？
- RQ3：动态 provider/version 事件后，更新是否比 Frozen/Reset/Warm-start 更快恢复？
- RQ4：延迟、失败、菜单规模、端点和 scaffold 变化时，方法在哪里失效？

每个 RQ 由一张主表或图回答。先给 hero result，再给机制消融，再给边界/错误分析。主结果表不是所有 run 的流水账；smoke、接口测试、失败尝试和确认结果分开。

### 4.5 Discussion 与 Conclusion：解释和收口

Discussion 不重复“Table X 提升了多少”，而要解释为什么观察到这一现象、哪一假设被支持/反驳、结论能推广到哪里。Limitations 要写科学边界，例如 provider training lineage、truth conflict、feedback delay、动态事件覆盖，不写成过程忏悔。

Conclusion 只保留一条持久教训：例如“可靠工具调用的关键不是把静态路由器换成更大的 backbone，而是把选择、验证和延迟反馈放进同一条可审计的信息链”。不要在结论里引入新的方法、数据或未来工作清单。

## 5. 行文风格约束

- 一个概念一个术语；JEV、selector、verifier、updater、provider 不互换叫法；
- 先用日常语言解释，再给术语和正式定义，再给例子；
- 主动语态，短句，少用空泛的“显著”“有效”“创新”；
- 引用必须做对比工作，不能挂名装饰；
- 公式前先说它要计算什么，公式后说明它如何被日志恢复；
- 用具体失败和真实数字，不用“工具越来越多所以很难”这类背景句替代问题；
- 不写编年史，不把内部调参过程放进主线；
- 结果用绝对差、区间和分母说话；不因为小数点精度制造确定性；
- 每个强主张都要在正文找到对应证据，证据不够就缩小主张；
- 负结果要保留，但放在它能解释机制边界的位置；不能让摘要先替方法道歉，也不能藏掉关键失败。

## 6. 针对本项目的段落级自检

### 6.1 Topic-sentence pass

把引言、方法、实验和讨论的每个段落第一句单独抽出来。只读这些句子，读者应该能依次复述：

`真实分歧 → 选择时序 → 旧方法缺口 → 动态 JEV insight → 可执行接口 → RQ 证据 → 边界`。

任何一处跳回背景、重复定义、突然出现新符号或提前报结果，都要重写段落顺序。

### 6.2 Claim–evidence pass

为每个 contribution 建四列：claim、最近邻、证伪实验、当前证据状态。当前三条候选主张必须分别绑定：

1. direct selected-only selection；
2. delayed online update；
3. post-call verification/escalation。

如果一条证据同时被拿来证明三个主张，默认不通过，除非它确实包含三个可分开的 intervention。

### 6.3 Reviewer five-question pass

只给审稿人标题、摘要、引言和主图，他应能回答：

1. 具体失败是什么？
2. P04/P06 等最近方法为什么不够？
3. 新机制改变了哪个信息或计算？
4. 哪张图/表能推翻它？
5. 在什么条件下不工作？

答不出来时，不靠增加背景段修复；优先修 P2–P5 的转接或缩小主张。

## 7. 适用边界

这套规则是论文的内部写作和论证检查，不是 AAMAS 录用公式，也不是要求每篇论文都使用六段引言、四个 RQ 或 theorem。它的作用是让本项目的故事、方法、实验和文字在同一条因果链上。真正决定能否投稿的是：问题重要性、方法 soundness、最近邻差异、真实证据和可复现性是否同时成立。
