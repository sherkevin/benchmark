# 动态 JEV 创新性与线性状态审查

日期：2026-09-25  
目的：审查当前方案是否有方法创新，以及能否借鉴 linear attention 得到可实现的在线更新。

## 结论

当前 v4 数学方案是一个可实现的任务定义和 Bayes/动态规划参考问题，但还不是一篇可以直接声称“新算法”的方法。以下单项均已有直接或近邻先例：

- contextual bandit 工具/模型路由；
- 预训练表示 + selected-arm 二元反馈 + 在线线性头；
- delayed feedback；
- abstain/fallback 和 risk-coverage；
- expected improvement / VOI；
- closed-form JEV head 和周期性 observe；
- linear attention 的递推状态和 delta-rule 更新。

因此，“冻结 Laya/AnyJev + 在线 RLS/LinUCB + 延迟队列”会被审稿人判断为合理的工程组合，而非单独的新数学方法。

当前最小可识别的贡献应写成：**在只观察已调用工具、真值延迟到达、工具结果可能相关的情况下，给 typed tool decision 提供一个无需回放历史的在线状态更新器，并用随机复核探针学习 verification gain；线性状态只是实现该反馈合同的计算机制。** 这仍需理论和实验支持，不能先称为原创算法。

## 已有先例

### Linear attention / fast weights

Katharopoulos et al., ICML 2020, *Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention*：利用结合律，把注意力写成递推状态 $S_t=S_{t-1}+\phi(k_t)v_t^\top$、$z_t=z_{t-1}+\phi(k_t)$，查询时用 $q_t^\top S_t/(q_t^\top z_t)$。来源：[PMLR](https://proceedings.mlr.press/v119/katharopoulos20a.html)。

Schlag et al., ICML 2021, *Linear Transformers Are Secretly Fast Weight Programmers*：将同一状态解释为可编程 fast weight，并给出 delta-rule 更新和动态写入率。来源：[PMLR](https://proceedings.mlr.press/v139/schlag21a.html)。

因此，把 JEV 写成 key/value 递推本身不能作为新颖性来源。它最多证明了固定表示下的常数状态、流式计算和更新复杂度。

### Closed-form JEV head

AnyJev L2 已经在中间 hidden state 上拟合闭式线性头；`observe` 收集标签，在 30、60、120 等节点周期性重新求解。来源：[AnyJev method v3](https://github.com/nokia-applied-research/AnyJev/blob/main/docs/method_v3.md)。

这直接覆盖了“JEV + 小型闭式 head + 标签到达后更新”的一般想法。我们的差异只能是 selected-only、延迟真值、工具 action/value 语义和复核收益；不能声称首次提出实时 JEV。

### Online routing / partial feedback

PILOT（Findings EMNLP 2025）已经把预训练 query/model embedding、二元 selected-arm feedback、online ridge/LinUCB 与预算策略组合起来。来源：[PILOT](https://aclanthology.org/2025.findings-emnlp.1301/)。

PAK-UCB 已研究带 context 的在线生成器选择、新模型到达和 RFF 加速；NeMoS 已研究在线模型池、active feedback 和 model add/remove。项目本地的 `research/Method_Paper_Public_Benchmark_Survey_20260924.md` 已记录这些协议。

### Delay / abstention / VOI

Joulani et al., ICML 2013 给出 delayed-feedback online learning 的通用变换和延迟 regret 代价：[PMLR](https://proceedings.mlr.press/v28/joulani13.html)。

风险敏感的 abstention、trusted region、conservative baseline 和 expected improvement 都已有理论邻居；`research/AAMAS2027_Problem_Formulation_Neighbor_Review.md` 与 `research/AAMAS2027_Structural_Gap_Review.md` 已逐项审查。2026 年的 Pandora's Router 还直接研究了带成本的 value estimation，并给出 Gaussian 条件下的闭式 VOI：[arXiv 2608.20316](https://arxiv.org/abs/2608.20316)。

## 可借鉴 linear attention 的最小递推

### 先区分“可计算状态”和“可计算 Bellman”

v4 中的 $Q_{\mathrm{call}}(h,p)$ 仍含有 $\Pr(o\mid h,\mathrm{CALL}(p))$ 的期望。只给每个 provider 一个正确率估计 $q_p(h)$，不能推出这个返回分布，也不能推出第二个工具的条件复核价值。因此 linear state 可以直接实现 M0 的 correctness head，却不能自动把 v4 的 Bellman 或 VOI 精确算出来。

第一版有两个合法选择：

1. 固定终止规则，只学习 provider correctness；此时不声称精确 Bellman；
2. 用预登记的随机复核 probe 直接观测 verification gain，单独训练 gain head；此时把 Bellman 写成 policy approximation，而不是精确求解。

只有在给出工具输出的条件分布模型、有限 outcome bins 或共轭观测模型后，才可以讨论可计算的 Bellman/VOI。

先只解决 M0：估计被调用 provider 的正确概率。令冻结的 Laya/AnyJev 表示经过非负特征映射得到 $k_i=\phi(h_i,p_i)\in\mathbb R_+^d$，其中 $h_i$ 是调用时可见的历史，$p_i$ 是实际调用的 provider，$c_i\in\{0,1\}$ 是真值到达后的正确性标签。

维护两个状态：

$$S_n=\rho S_{n-1}+k_i c_i,\qquad Z_n=\rho Z_{n-1}+k_i,$$

其中 $\rho\in(0,1]$ 是固定遗忘系数；若当前没有反馈到达，则只做 $S_n=\rho S_{n-1}, Z_n=\rho Z_{n-1}$。查询时：

$$\hat q_n(h,p)=\frac{\phi(h,p)^\top S_n+\alpha_0}{\phi(h,p)^\top Z_n+\alpha_0+\beta_0}.$$

这与 linear attention 的 numerator/denominator 递推完全同构。若 $\phi\geq0$、$c_i\in\{0,1\}$、$\alpha_0,\beta_0>0$，则 $\hat q_n\in(0,1)$；历史不需要保存，更新和查询均为 $O(d)$，每个 provider 的状态为 $O(d)$。这证明了“可以实时计算”，但没有证明它比 LinUCB、RLS 或 AnyJev 更准。

更稳妥的带不确定性版本是递推加权 ridge：

$$A_n=\rho A_{n-1}+k_i k_i^\top,\qquad b_n=\rho b_{n-1}+k_i c_i,\qquad w_n=A_n^{-1}b_n.$$

查询均值和不确定性为：

$$\mu_n=k^\top w_n,\qquad s_n^2=k^\top A_n^{-1}k.$$

使用 Sherman--Morrison 可以在 rank-one 反馈下更新：

$$A_n^{-1}=\rho^{-1}\left(A_{n-1}^{-1}-\frac{A_{n-1}^{-1}kk^\top A_{n-1}^{-1}}{\rho+k^\top A_{n-1}^{-1}k}\right).$$

这版是标准 RLS/LinUCB 的递推形式，更新为 $O(d^2)$；使用对角 $A_n$ 才能降到 $O(d)$，但会引入近似。不要同时把两版都叫“我们的新算法”。

## 真正可能形成贡献的部分

线性状态需要和任务专属反馈合同绑定，才有可能成为论文贡献：

1. **selected-only delayed state**：只有真实调用且已经到达的 $c_i$ 更新；未调用 provider 不补标签；pending 事件 exactly-once，乱序按 arrival event 处理。
2. **typed gain head**：随机复核探针产生 $g_i=\mathbf 1[$第二个 provider 修正了当前答案$]$ 或带损失的 verification gain。JEV 学的是复核的条件增益，不把单 provider accuracy 当 VOI。
3. **risk gate**：只有估计的 gain 下置信界超过调用成本时才复核，否则作答或拒答。门控必须与工具错误相关性和 baseline 估计误差一起评估。
4. **漂移处理**：$\rho<1$ 处理 provider 版本漂移，但需要报告遗忘偏差和恢复时间；不能只报最终准确率。

可形成的理论结果应是任务条件下的定理，而不是重新证明 linear attention：

- 递推状态只使用已到达反馈，查询等价于一个加权经验风险最小化解；
- 延迟 $\Delta$ 对 prequential loss/regret 的额外代价，至少与 Joulani 的 delayed-feedback 分析对齐；
- 在 $\phi$ 有界、随机复核概率有正下界、反馈条件分布稳定或总漂移受限时，verification-gain 估计误差和 unsafe-answer risk 的界；
- 说明 $\rho$ 带来的 bias--adaptation trade-off。

在这些假设未验证之前，不要声称 Bayes-optimal、全局最优或准确率必然提高。

## 审稿人会判为“拼装”的情形

- 只把 Laya/AnyJev 输出接到 LinUCB/RLS，然后称 dynamic JEV；
- 只展示 closed-form 或 $O(d)$ 更新，没有 selected-only 合法性和反馈队列实验；
- 把 AnyJev 的 choice probability 当作 provider correctness；
- 用完整缓存给未调用工具补标签；
- 用静态 provider accuracy 代替条件 verification gain；
- 只报告终局 accuracy，不报告 prequential loss、risk-coverage、calls、update latency 和 drift recovery；
- 只和 random 比，不和 PILOT、LinUCB/LinTS、AnyJev observe、CAMS/NeMoS 等同信息近邻比。

## 建议的论文定位

第一版应把主张收窄为：

> 在延迟、selected-only 的工具真值反馈下，线性状态 JEV 能否用固定大小的递推状态学习 provider 正确性和验证增益，并在受控调用预算下改善风险—覆盖率曲线？

M0 只评估正确性 head；M1 用随机复核识别 gain；M2 才学习 gate。若 M0/M1 不能稳定超过强基线，不能继续扩展到主 Agent，也不能把“实时 JEV”写成已验证贡献。
