## 2. 已经站得住的经验事实

T2 已把旧工具池冻结成真实的 production-like incumbent，而不是为了制造 headroom 使用弱 baseline：
- LLMRouterBench：full prompt TF-IDF + per-arm Ridge，stationary macro 0.71550。
- ASlib SAT12-ALL：113 features + ExtraTrees，utility 0.92483 / PAR10 902.01。
- BBB：train-derived Best Fixed，accuracy 0.93098。

在此基础上 challenger opportunity 仍非零，因此 T3 不是人为制造的问题：
- LLMRouterBench：+0.05715 macro；
- ASlib：+0.00932 utility；
- BBB：+0.03921 accuracy。
Formal T3 的 classic online baselines 在三套环境里平均 IOU 全为负。最保守的 Beta-TS 伤害最小，但几乎不采用 challenger；UCB/LinUCB 则把 zero-history uncertainty 当价值，产生明显 over-exploration。

最重要的现象不是“新工具不好”，而是：
1. 新工具确实存在局部正增益；
2. mature incumbent 已经吃掉大部分容易获得的收益；
3. 剩余正增益集中在稀疏 context 子集；
4. 因此探索的 false-positive cost 往往大于 rescue gain。

校准后单纯把 exploration 调保守仍不能解决 mature pool：
- LLMRouterBench K=20 最佳 calibrated gate IOU = -0.00076；
- ASlib K=31 最佳 calibrated gate IOU = -0.00650。

这说明当前研究对象应写成 **few-shot high-precision conditional adoption**，而不是 generic routing 或“更多使用新工具”。

## 3. 最近邻 baseline 对当前创新空间的压缩

已有工作已依次占掉多层可能的 novelty：
- shared / hierarchical prior：MTSS、warm-start contextual bandits；
- cross-task shared subspace：P-LinUCB / P-TS（AISTATS 2024）；
- fixed-pool prompt-aware model routing：PAK/RFF-UCB（ICML 2025）；
- arriving-arm screening：UCB-AA（2026 concurrent）；
- conservative exploration against a baseline：CLUCB/后续 conservative CB；
- relative / residual effect modeling：Action-Centered Contextual Bandits（NeurIPS 2017）；
- production baseline + high-confidence deployment gate：SEA；
- runtime new-model onboarding + cold-start burn-in + offline priors：ParetoBandit（arXiv:2604.00136, 2026）。

因此以下表述都不能再作为论文核心创新：
“首次动态接入新工具”“首次 shared prior”“首次相对 incumbent 学 residual”“首次安全探索”“首次 warm-start newcomer”。

ParetoBandit 尤其接近：它支持 runtime hot-swap，新 model 先短 forced exploration，再进入 UCB，并从 offline prior bootstrap；论文报告 cold-started model 在约 142 steps 达到 meaningful adoption。
来源：https://arxiv.org/abs/2604.00136
## 4. 当前仍可能成立的研究缝隙

目前最有防守性的交叉问题是：

> 已有成熟 contextual incumbent；一个没有可信 tool-side competence metadata、零行为历史的 black-box challenger 中途到达；它只在稀疏 context 区域有正增益。如何利用旧工具/旧任务中学到的结构，在极少 behavioral feedback 下高精度识别 `g_new(x)>0`，同时避免 uncertainty-driven over-exploration 与 negative transfer？

这里真正要证明的不是“能学”，而是 **feedback/sample efficiency + beneficial-adoption precision + positive IOU**。

如果最终方法只是以下任何一种，创新不足：
- LinUCB + prior；
- ACTS 直接套用；
- CLUCB 换名；
- P-LinUCB 直接搬到 tool 上；
- ParetoBandit 的 fixed burn-in + UCB；
- UCB-AA 加一个 context encoder。

## 5. T3 当前 baseline 信号

第一轮 Action-Centered TS 结果也仍是负 IOU：
- LLMRouterBench：IOU -0.05523，precision 5.95%，recall 36.84%；
- ASlib：IOU -0.13360，precision 12.34%，recall 35.53%；
- BBB：IOU -0.01353，precision 3.91%，recall 48.87%。

PAK/RFF-UCB 64-RFF pilot 同样明显负 IOU：
- LLMRouterBench -0.06992；
- ASlib -0.33398；
- BBB -0.03006。

但这两组目前只应读作“第一轮适配没有自动解决问题”，不能直接作为论文最终 baseline 数字：PAK/RFF 仍需检查 adaptation fidelity 与超参；ACTS 也需核其随机化/参数与原论文协议是否适合本 setting。

## 6. 下一道真正的 Go/No-Go
下一步不应扩 benchmark，也不应开始 LLM RL。应先关闭四个 baseline 风险：

1. 验证并正式冻结 PAK/RFF-UCB 的 faithful adaptation；
2. 跑 P-LinUCB/P-TS，回答“历史工具共享子空间是否已经足够”；
3. 验证 Action-Centered TS 适配，并补齐 task29 正式表；
4. 加 ParetoBandit-style “brief forced newcomer burn-in + UCB / prior warm-start” comparator。

只有这四类仍不能在小 feedback budget 下获得稳定正 IOU，才有充分理由设计 Ours。

对 Ours 的最低成功线保持不变：
- LLMRouterBench + ASlib 至少两套主环境平均 IOU 转正；
- 相比最强非 oracle baseline，达到更低 Challenger Regret；
- 增益来自更高 beneficial-adoption precision，而不是无脑提高 challenger usage；
- T4 中以更少 B 达到相同 IOU/regret，才能声称 sample efficiency；
- 若使用 transfer，T6 必须证明去掉 cross-tool/task transfer 后显著退化。
