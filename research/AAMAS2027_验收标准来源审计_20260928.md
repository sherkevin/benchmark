# AAMAS 2027 三份验收标准的来源审计

日期：2026-09-28
状态：来源审计；不替代六份生效主线文档

## 结论先说

三份验收标准不是凭空构造的，但也不是对历届 AAMAS 优秀论文做了完整统计后得到的“官方评分表”。它们由三层材料合成：AAMAS 2027 官方硬要求、对 2023–2026 代表性论文的定性阅读、以及针对本项目数据和信息边界的作者侧验收门槛。

因此，文档里的“必须”要分级理解：投稿与审稿页面明确写出的属于官方硬要求；从多篇论文归纳出的属于高概率审稿规律；为防止本项目自建 routing 层被误读而加的属于项目特定门槛。后两类不能冒充 AAMAS 官方条款。

## 一、官方硬要求

| 官方要求 | 原文依据 | 在三份标准中的落点 |
|---|---|---|
| 评价 originality、significance、soundness、reproducibility、clarity、relevance、presentation 和 state of the art | [AAMAS 2027 Call for Main Track](https://warwick.ac.uk/fac/sci/dcs/aamas2027/calls/call-for-main-track/) | 三份标准都要求问题重要、方法正确、证据可复核、表述清楚并理解最近工作 |
| IASI 应用稿说明 application context、agent 的作用、应用新意以及 benefit/feasibility/adoption/impact 证据；对 LEARN/GAAI 不是统一硬条款 | 同上 | 故事线标准把真实失败场景、agent 介入点和可测收益作为本项目的加严要求 |
| 核心内容必须在正文自洽；补充材料不是核心论证的替代品 | [AAMAS 2027 Submission Instructions](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/instructions/) | 方法标准要求输入、反馈、更新和关键实验在正文可审查 |
| 8 页正文、双盲、格式和匿名要求 | 同上 | 属于投稿检查，不等同于科学质量标准；当前三份验收文档没有把页数冒充创新要求 |
| 作者对 AI 辅助生成的内容、引用、实验和方法负责 | 同上 | 本审计和实验日志要求来源、真实运行和证据链；这不是论文贡献本身 |
| reviewer 将按统一技术贡献整体评价，不是按“有几个模块”计分 | [AAMAS 2027 Reviewer Guidelines](https://warwick.ac.uk/fac/sci/dcs/aamas2027/guidelines-and-policies/reviewer-guidelines/) | 故事线标准禁止用模块堆叠制造创新 |

## 二、代表性论文归纳出的规律

已有调研文件 `research/AAMAS_2023-2026_论文调性与DynamicToolRouting选题调研.md` 明确写了范围：重点阅读 2023–2026 AAMAS Main Track / Full Research Paper 中与 LEARN、bandit、online learning、RL、agent evaluation、GAAI 相关的代表性论文，不是全会论文计量。

已纳入的样本包括：

- AAMAS 2024 *Learning to Schedule Online Tasks with Bandit Feedback*：具体技术瓶颈 → 形式化模型 → 针对性算法 → 理论分析 → synthetic + real validation → canonical baselines。
- AAMAS 2025 *Truthful Mechanisms for Linear Bandit Games with Private Contexts*：成熟范式加一个现实且可形式化的困难，方法和理论都围绕该困难展开。
- AAMAS 2025 *Human-Aligned Skill Discovery*：问题、机制和 trade-off 直接对应，实验不靠庞大系统取胜。
- AAMAS 2026 *Truthful Reverse Auctions for Adaptive Selection via Contextual MAB*：同功能 provider routing 已有近邻，因此“使用 contextual bandit”本身不足以构成新意。

从这些样本得到的不是硬门槛，而是审稿风险提示：要指出现有方法为什么在某个现实条件下失败，把条件写进模型，再用最近邻 baseline、消融和边界分析验证。对应到三份标准，就是故事链、形式化信息边界、公平 baseline、可证伪实验和失败边界。

AAMAS 2024/2025 的获奖和 proceedings 页面可以作为优秀论文的补充阅读入口，但奖项本身不是评分规则：

- [AAMAS 2024 awards](https://www.ifaamas.org/Proceedings/aamas2024/pdfs/awards.pdf)
- [AAMAS 2025 awards](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/awards.pdf)
- [AAMAS 2023 awards](https://www.ifaamas.org/AAMAS/aamas2023/best_paper_and_demonstration_awards.html)

目前没有对这些获奖论文逐篇编码其 benchmark、baseline、消融和失败分析，也没有计算出“优秀论文的统计规律”。这部分只能叫代表性阅读，不应写成完成了系统综述。

## 三、我们自己加的项目门槛

以下要求不是 AAMAS 统一明文条款，是为了让本项目的特殊主张可被审查：

- 公共 truth layer 与自建 provider routing layer 分开命名；
- 调用前不能读取未选 provider 输出和当前真值；
- 延迟 selected-only 反馈、失败和缺失值逐事件记录；
- provider 训练成员、checkpoint 和 family 相关性单独审计；
- confirmation 方法冻结后只读一次；
- 选择、调用后验证和拒答分开报告；
- 每个数字能由原始日志和恢复脚本重算。

这些是本项目的科学防守线，不应在论文中写成“ AAMAS 要求所有论文必须使用 TDC / scaffold split / 33 provider”。

## 四、目前三份验收文档的可信等级

| 文档部分 | 当前等级 | 说明 |
|---|---|---|
| originality/significance/soundness/reproducibility/clarity/relevance/state of the art | 官方依据 | 可直接引用 AAMAS 2027 页面 |
| 技术瓶颈 → 形式化 → 对照 → 消融/边界 | 代表性论文规律 | 已有定性样本，但不是系统统计 |
| truth/provider/feedback/no-leakage/恢复协议 | 项目特定门槛 | 由当前任务的信息边界和数据风险推出 |
| “必须公认 benchmark”“baseline 要现代” | 项目侧加严 | AAMAS 不规定唯一 benchmark，但本项目需要防止自建回放承担过强结论 |
| “创新不能被一次失败自动推翻” | 治理原则 | 保护决议和研究连续性，不是 reviewer 打分项 |

## 五、下一步如何补足

如果要把“优秀论文规律”说得更强，下一轮应按固定表格抽取至少 2023–2026 每年 5–10 篇与 LEARN/GAAI/online decision 最接近的主轨论文，并记录：核心问题、方法机制、理论/实验类型、baseline 数量、数据独立性、消融、失败分析和代码/数据开放情况。完成编码前，三份验收文档只能保持当前的分级措辞，不能升级成“由历届优秀论文普遍证明的硬规则”。

## 六、2026-09-28 原文级补证

本轮又完成了 8 篇与本项目最接近的论文原文级阅读，保存了来源、PDF 页数、SHA-256 和逐页阅读记录：`research/AAMAS2027_相关论文逐篇阅读记录_20260928.md`；轻量来源清单在 `research/paper_sources/aamas_related/manifest.json`。本轮逐篇核对了问题定义、方法、理论、baseline、实验协议和限制，而不是只读取摘要。

补证后可以更有把握地写出三条项目相关结论：

1. contextual bandit / LLM routing 本身不是充分创新；AAMAS 2026 provider selection、C2MAB-V 和 online multi-LLM selection 已经覆盖了这条基本路线。
2. 动态工具池、delayed/noisy selected-only feedback 是明确的未闭合边界，但必须真正进入 formal model、更新算法和 replay/confirmation protocol，不能只作为动机。
3. RouterBench 和 GraphRouter 能作为静态/离线 routing 对照，但 full-panel、offline few-shot 和 Oracle 不能冒充实时 selected-only 学习证据。

这次补证仍不等于完成 2023–2026 每年 5–10 篇论文的系统编码；在该编码完成前，验收标准继续保持“官方要求 / 代表性论文规律 / 项目特定门槛”三层分级，不升级为 AAMAS 官方评分表。

## 七、2026-09-29 v003 评分机制审计

本轮把三份生效评价标准升级为 v003。升级不是增加“审稿人喜欢什么”的主观形容词，而是把前述 O/P/C 证据翻译成可复核评分：

- 故事线标准：12 项、权重 100、每项 0–4 分；除问题、因果链、最近邻和创新外，把 Abstract、六段引言漏斗、章节/RQ、topic sentence → support → bridge、术语/case 和行文语气纳入同一张评分表。
- 方法论标准：M1–M15，每项 0–4 分，满分 60；单独检查对象、时间队列、信息隔离、失败语义、机制必要性、推导、实现一致性、动态事件、实时成本、消融、恢复和主张校准。
- Benchmark/Baseline 标准：B1–B15，每项 0–4 分，满分 60；把公共 truth layer 与自建 provider routing layer 分开，检查 truth、label、split、provider lineage、selected-only 事件、family 相关性、baseline fidelity、统计、恢复和 confirmation。

每项都要求 evidence path、hash 或日志行号；作者和未参与实现的复核者独立打分，取较低分；硬门槛先于总分。49/60 或 85/100 的线是项目内部 go/no-go 线，不是 AAMAS 官方分数，也不提供录用保证。

这次升级使用了 O/P/C 分层，避免把段落数量、TDC、scaffold split、33-provider 菜单或 selected-only 规则误写成 AAMAS 对所有投稿的统一要求。代表性论文提供的是可重复的论证行为线索，项目门槛提供的是本任务的信息公平和可复现防守线。当前评分标准也明确：full-panel 只能用于 fit-only warm start、Oracle 或审计；静态结果不能改名为 online 效果；未证明 provider 独立训练成员时必须收窄 claim。

## 八、2026-09-29 v004：整体组合、动态范围与确认阶段的修正

v003 的只读审查发现三类执行歧义：部分硬闸门把 PASS 条件写成正向问句却用“回答是即失败”，组合式方法可能被误读为组件清单自动否决，dynamic 同时混用了反馈自适应与环境非平稳。确认阶段还存在“开放确认需要确认结果”的循环。v004 做的是评分逻辑修正，不是把候选方法宣布为创新或有效。

- **整体方法判定**：v004 用“PASS 条件 | FAIL 触发条件 | 证据”逐行填写，只有明确 FAIL 直接挡住投稿；UNKNOWN 必须补证据。组合方法按完整机制、统一接口或不变量、问题契合、匹配消融和可量化 integration gain 判定。已有组件需要准确引用，但不再作为组合贡献的自动否决。这个规则已在 `docs/决议/0003-组合方法的整体贡献判定.md` 固化。
- **dynamic_scope 分层**：`feedback-adaptive` 是 selected-only 延迟反馈释放后改变后续状态/动作的主线；`environment-nonstationary` 只在 provider、version、menu 或数据分布发生事件并有对应证据时声明；`both` 需要两套证据。
- **确认两阶段**：Stage A 只判断 `ELIGIBLE_FOR_CONFIRMATION`（真值、标签、split、provider lineage、信息隔离、日志和 runner 合格）；Stage B 在方法、菜单、阈值、epoch 与 baseline 冻结后一次性读取 confirmation，才可标记 `CONFIRMED`。
- **正文措辞边界**：组件来源、近邻和失败风险留在内部审查与相关工作；正文用正向、可检验的整体机制描述，不主动写“只是组合”或其他防守性自我贬低。

当前候选方法仍只有候选数学卡和既有事件字段审计：10,621 条有效二元记录中恢复 mismatch 为 0，155 条字段缺失/非二元记录被排除；这不是选择效果，也不是 confirmation。
