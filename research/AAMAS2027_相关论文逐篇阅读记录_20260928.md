## 2. 逐篇阅读记录

### P01 — Learning to Schedule Online Tasks with Bandit Feedback

**原文位置。** PDF pp.1–2（问题、贡献和相关工作）；pp.3–4（system model 与 DOL-RM）；pp.5–6（假设、定理和证明结构）；pp.7–8（synthetic 与 real-world 实验）。

**它真正解决的困难。** 任务到达分布未知，且被选动作的 reward 和 cost 在任务完成后才反馈。作者不是简单地“用 bandit 做调度”，而是把“未知 reward/cost + 未知 arrival distribution”同时写进模型。DOL-RM 将 optimistic reward/cost estimation 与 Robbins–Monro 的到达分布学习合在一起，并给出 $O(T^{3/4})$ regret（p.1–2、p.5）。

**实验怎么证明。** synthetic 两任务型、七任务型；真实 ML 训练调度；baseline 包括 TS、UCB、$ω$-UCB 和需要先验信息的 Oracle。真实实验按训练 epoch 选择动作，把测试集 AUC 当 reward、训练时间当 cost，并报告均值曲线和标准差（pp.7–8）。

**对我们的直接约束。** “有反馈就用 contextual bandit”不够。我们必须明确自己的额外困难：工具结果是 selected-only、反馈可能延迟/缺失，且候选工具能力随模型/版本变化；方法、理论和实验都要围绕这些困难。若不能给出可计算保证，至少要给出明确的可验证更新不变量和失败边界。

### P02 — Human-Aligned Skill Discovery

**原文位置。** PDF pp.1–2（问题、related work、贡献）；pp.4–5（HaSD objective、算法和 baseline）；pp.5–8（Nav2D、feedback budget、Safety Gymnasium）；p.12（限制与结论）；appendix pp.13–16（实现细节）。

**它真正解决的困难。** 传统 skill discovery 追求多样性，却可能发现不安全、不可用的行为。HaSD 将 skill diversity 与 human-alignment 写成同一个多目标目标；$α$-HaSD 进一步显式控制 diversity–alignment trade-off（pp.1–2、p.4）。这里的贡献不是增加一个反馈模块，而是把“发现什么”和“是否符合偏好”的冲突放入目标函数。

**实验怎么证明。** baseline 分成四类：无偏好信息（DIAYN、LSD）、完整信息（SMERL）、偏好信息（CDP、SMERL+PbRL）、本文方法；Nav2D 和 Safety Gymnasium 多个环境；报告 coverage、alignment、Pareto front、hypervolume、下游任务以及不同 feedback budget。作者还用 40/400/1400/unlimited 反馈做敏感性分析，并报告真实人类反馈的噪声影响（pp.5–8、p.12）。

**对我们的直接约束。** 如果我们把“验证/拒答/反馈”作为贡献，必须把它和选择目标之间的冲突写进正式目标，并做反馈预算与噪声敏感性实验。不能只报告一个平均准确率。作者自己指出反馈数量、反馈模型准确率和何时提问是限制，这正好对应我们要审查的 delayed verification 与 probe 设计（p.12）。

### P03 — Truthful Mechanisms for Linear Bandit Games with Private Contexts

**原文位置。** PDF pp.1–2（动机、related work、贡献）；pp.2–3（private-context model）；pp.3–6（truthful-TS 机制和 regret 分析）；pp.7–8（simulation 与 conclusion）。

**它真正解决的困难。** 普通 UCB/TS 假定 context 可观测且诚实，但这里每轮来的 agent 可以为了即时收益伪报 context。作者证明低 regret 的 UCB/TS 在伪报下可能线性 regret，再设计 truthful-TS 机制；在其假设下给出 $O(log T)$ regret（pp.1–2、pp.3–6）。创新来自 strategic private context 这一约束，而不是来自“换一种 TS 实现”。

**实验怎么证明。** 先用小规模 $N=d=K=2,T=50$ 比较 Gaussian/Laplace noise，再扩展到 $Nin{3,5,9}$、$din{5,9}$、$K=6$，每个参数配置运行 100 次并报告平均 regret（p.7）。

**对我们的直接约束。** 我们不能借用这篇论文的 truthfulness 结论，因为工具选择没有 strategic provider/context misreporting。可借的是研究结构：先证明现有算法在新增现实约束下失效，再设计正对该失效的机制，并让理论指标与实验指标一致。

### P04 — Truthful Reverse Auctions for Adaptive Selection via Contextual MAB

**原文位置。** PDF pp.1–3（LLM provider selection 问题、related work、model）；pp.7–9（REV-BaseLinUCB-S、REV-SupLinUCB-S-OPT、ROSA）；pp.17–18（实验和结论）。

**它是我们的最近邻和创新风险。** 这篇工作已经把“query-dependent LLM/provider selection + contextual MAB + 在线反馈”写成正式问题，并用 reverse auction 处理 provider cost truthfulness。其核心新意是 reverse self-resampling ROSA、单调 allocation 和 truthfulness/regret 组合，而不是 contextual bandit 本身（pp.1–3、pp.7–9）。

**实验边界。** 实验是合成的：4 个 strategic providers、5 维 Gaussian context，另测 exponential reward noise；$T=10^5$，40 个随机种子，和 clairvoyant benchmark 比较（p.17）。没有动态新增 provider、selected-only 延迟反馈或真实医药工具调用。

**对我们的直接约束。** 论文中不能把“动态选择工具”或“使用 contextual bandit”单独写成创新。我们的切口必须和它分开：具体科学工具/版本、二值正确性、反馈只在终止或验证后到达、候选池可变化，以及在这些条件下的实时 JEV 更新。若方法只剩普通 LinUCB/TS 加一个新名字，会被最近邻直接覆盖。

### P05 — C2MAB-V

**原文位置。** PDF pp.1–3（动机与问题）；pp.5–10（部分反馈、代价约束、算法、理论和实验）；appendix pp.20+（更完整的实验与证明）。

**它真正解决的困难。** 组合式选择多个 LLM，reward/cost 不确定，只有被选子集得到部分反馈，并且有长期 cost budget。C2MAB-V 用 relaxed/discretized combinatorial optimization、reward/cost confidence bounds 和 continual feedback，给出 regret 与 constraint violation 分析（pp.1–3、pp.5–8）。

**实验怎么证明。** SciQ、9 个 LLM、三种 reward model（AWC/SUC/AIC），10 个 seeds 和 95% CI；baseline 包括 always ChatGPT-4、always cheap model、CUCB、TS、$ε$-Greedy，并做 budget/参数消融（pp.9–10）。论文明确声明其评估不覆盖 offline pretraining 和 cold-start（p.9 脚注）。

**对我们的直接约束。** 这是可选的 cost-aware/partial-feedback baseline，但不是我们“动态新增工具 + 冷启动”的最近邻。它提醒我们必须把 feedback eligibility、cost 和 violation 单独记账，不能把全 panel 的结果当作在线反馈。

### P06 — Online Multi-LLM Selection via Contextual Bandits under Unstructured Context Evolution

**原文位置。** PDF pp.1–2（问题与贡献）；pp.4–5（形式化、Greedy LinUCB、myopic regret）；pp.8–12（baseline、数据、实验、限制）。

**它真正解决的困难。** 多轮交互中 prompt 由黑盒过程演化，未来 context 不可模拟/预测。作者因此放弃 sequence-wise planning，定义 myopic regret，并用每个 LLM 一个 LinUCB 模型在线更新（pp.4–6）。这比“普通 router”更清楚地说明了什么时候 contextual bandit 是合理的。

**实验怎么证明。** 对比 MetaLLM、MixLLM、Majority Voting、Random 及候选 LLM；使用 MMLU-Pro、AIME、GPQA、Math500，20% offline initialization、80% online test，报告 accuracy/cost，并测试 budget-aware 和 position-aware 变体（pp.8–11）。

**它给我们的关键机会。** 论文限制中明确写了三点：myopic、feedback 可能 noisy/delayed、LLM pool 被当作 fixed；dynamic model pool 和 delayed/noisy feedback 被留作 future work（p.12）。这正是我们可以承接的技术缺口，但必须用“动态工具池 + 延迟 selected-only 反馈”做真正的 formal extension，不能只在论文里口头说 dynamic。

### P07 — RouterBench

**原文位置。** PDF pp.1–3（benchmark 动机和 cost-quality framework）；pp.5–7（benchmark construction、datasets、splits、baselines、metrics）；pp.8–12（predictive/non-predictive router experiments）。

**它解决的问题。** 建立一个可复用的静态 multi-LLM routing 数据集：11 个模型、8 个数据集、64 个任务，405,467 条预生成 inference outcomes；统一比较 performance、cost 和 cost-quality trade-off（pp.1–2、pp.5–7）。

**它能证明什么，不能证明什么。** 它很适合做静态 routing representation/baseline 的外部对照，但预生成全 panel 输出意味着每个样本的所有模型结果事先存在。直接使用不能证明 selected-only、延迟反馈或实时更新。它的 Oracle 也使用每个输入的全 panel 最优模型，必须明确标为 privileged upper bound（pp.5–8）。

**对我们 benchmark 的约束。** 自建医药回放可以作为核心任务，但要把公共 benchmark 的作用说清楚：RouterBench 是外部 routing sanity check；医药任务提供独立 truth、具体 provider/版本和 delayed replay。两者不能混成一个“公认 benchmark 已经覆盖在线学习”的结论。

### P08 — GraphRouter

**原文位置。** PDF pp.1–2（问题与贡献）；pp.4–6（heterogeneous graph、new LLM setting、data split）；pp.7–10（baseline、metrics、new-LLM experiments、ablation、limitations）。

**它真正解决的困难。** 用 task/query/LLM 异构图和 edge prediction 建模 interaction；通过 LLM 描述生成节点 embedding，测试阶段用新 LLM 的 few-shot interaction 适应新节点（pp.4–6）。

**它和我们的区别。** GraphRouter 的 new-LLM setting 仍然是 offline graph training 加测试期 auxiliary few-shot；新模型的交互样本来自训练 queries，且不是 selected-only 的持续在线反馈。它适合做 representation/cold-start 对照，不是我们实时 JEV 的替代品。

**实验怎么证明。** 四类数据集、10 个 LLM；baseline 包括 Largest/Smallest、Prompt LLM、HybridLLM、FrugalGPT、C2MAB-V 和 Oracle；报告 performance/cost/reward 三类指标，另做 new-LLM few-shot 和 GNN size/layer ablation（pp.6–9）。

## 3. 交叉规律：这次能确定的东西

### 3.1 真正有说服力的创新形态

八篇论文共同支持的不是“模块越多越创新”，而是：

1. 指出一个现有方法在具体现实条件下会失败；
2. 把这个条件写进可执行的 formal model；
3. 设计只针对该失败原因的机制；
4. 用最近邻、canonical baseline、oracle/privileged control、消融和边界实验分别回答不同问题；
5. 论文主动说明方法在哪些条件下不成立。

这是从逐篇原文归纳的研究结构，不是 AAMAS 官方固定评分表。

### 3.2 对我们当前故事的硬约束

- “工具选择”或“contextual bandit”本身不能作为创新；P04、P05、P06 已经覆盖这条路线。
- “在线”必须在实验协议中体现：选择前只看允许信息，未选工具输出不进入更新，反馈按真实到达时间释放。
- “动态”必须有事件：新 provider/version 到达、旧 provider 失效或能力漂移，并报告 arrival 后 recovery，而不是只在静态数据上重训。
- “JEV”必须定义成可计算对象：输入、输出、标签、更新量、延迟、缓存/状态、推理开销和冻结规则都要能从日志恢复。
- 自建医药 benchmark 可以作为主任务，但不能承担“公认 benchmark”的全部证明责任；至少需要 RouterBench 之类外部 sanity check，或者明确把论文主张限制在医药工具回放环境。
- Oracle、full-panel offline fit、GraphRouter few-shot 都只能作为 privileged controls，不能混进 online baseline 排名。
