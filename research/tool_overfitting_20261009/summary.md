# 工具过拟合与“bash 更强”证据复核

- **日期**：2026-10-09
- **目的**：为论文故事线确定问题切口；先复核“bash 能力强于多工具”的证据，再决定是否把它作为根因。
- **结论状态**：动机证据已收集，因果解释和药物迁移仍待本项目实验验证。

## 1. 目前能确认的事实

1. DeepSeek 相关材料的核心现象是：同一模型在不同 harness、profile 和工具表面下，分数可以明显变化。已有内部调查把 DSH Minimal 与 Standard 的差异整理为约 99 vs 91，并同时记录了官方极简模式、独立复现和其他 harness 的结果。这个现象支持“能力是 model × harness 的联合结果”，不支持“少工具本身更好”。
2. OpenAgent 将开放世界变化拆成 query、action、observation 和 domain shift；其中 action shift 明确包含重命名工具和 schema 噪声。这为我们的实验提供了现成的变量分解：保持功能不变，只改变表面；再独立改变未见工具和领域。
3. DSGym 报告了 shortcut solvability、domain grounding error、simplicity bias 和 insufficient verification，并使用执行结果生成可核验轨迹。它说明“答案对了”与“真正依赖数据并完成了验证”不是一回事。
4. Braintrust 的公开工程评测给出相反的工具抽象结果：在其任务和 scorer 下，结构化 SQL 高于裸 bash；bash 加 SQLite 后通过交叉检查恢复到高准确率。该页面还记录了 schema 信息缺失、评分标准错误/歧义和数据加载错误。它直接说明，不能把某一次“bash-only”现象概括为 bash 的普遍优势。

## 2. 对论文切口的修正

论文不从“工具返回冲突答案”开始。更准确的切口是：**训练时熟悉的工具表面是否会被智能体误当成当前任务的适配度？**

同功能工具通常会被 agent 先选一个，而不是一开始就把多个工具拿来裁决。因此，研究对象有两个连续决策：

- 调用前：根据任务、工具工作范围和已有可靠性证据选哪个；
- 调用后：结果是否足够可信，是否需要相互验证、互补调用、继续申请工具或拒答。

“选中工具返回错误”是可观测结果信号，不是过拟合的充分证明。错误还可能来自任务理解、分子表示、工具噪声或独立真值边界。要把它解释为熟悉偏好，至少要做四组控制：

1. 同一功能、同一输出质量，只置换名称和 schema；
2. 同一功能和表面，只换成训练未见的包装或版本；
3. 同一任务和表面，改变工具真实工作范围；
4. 用独立端点真值、选择序列、验证动作和拒答行为共同评分。

## 3. 推荐的第一版诊断矩阵

| 轴 | 处理 | 目的 |
|---|---|---|
| 表面 | 原名/schema vs 置换名/schema | 测熟悉度是否影响选择 |
| 可见性 | 训练见过的包装 vs 未见包装 | 测工具泛化 |
| 功能 | 同功能重叠工具 vs 无关工具 | 区分真正的任务适配 |
| 反馈 | 无反馈、立即释放、延迟释放 | 测可信度更新是否因果有效 |
| 动作 | 单次选择 vs 选择后核验/互补/拒答 | 测完整可信调用能力 |
| 评估 | 选中正确率、验证率、拒答校准、调用成本、下游 top-k 命中 | 不把一次选择分数冒充整体能力 |

建议的最小成功条件是：在表面置换和未见包装下，选择仍跟随独立真值定义的任务效用；结果不可靠时，验证/拒答策略提高最终可交付正确率，并控制额外调用成本。

## 4. 不能写进论文的结论

- 不能写“bash 普遍强于多工具”。
- 不能写“错误选择必然由工具过拟合造成”。
- 不能写“只要打乱工具名字就学到了通用能力”。
- 不能把同一工具集合上的再训练结果当成未见工具泛化。
