## 1. 任务目标与约束

目标是在同一台 Linux 服务器上，对以下 10 个工具进行可审计安装，并在一份新的 730 分子输入上运行全部冻结端点：

1. OPERA
2. CONCERTO
3. TRIDENT
4. CardioTox
5. BayeshERG
6. CYPlebrity
7. CYPstrate
8. CypReact
9. EPA TEST
10. VEGA QSAR

执行遵守四条硬约束：

1. **环境隔离**：每个工具独占 Conda prefix、`HOME`、`TMPDIR`、pip/conda/Hugging Face 缓存、源码和权重目录，只共享宿主机内核与 GPU 驱动。
2. **时间封顶**：每个工具安装尝试的累计单调时钟不超过 7200 秒，预算从所有历史 receipt 汇总，而不是每次重试重新计时。
3. **失败不美化**：安装失败、权重不可达、协议错误或单分子失败都保留原始状态，不删除失败分子，不补造数值，不用非官方模型替换缺失的官方模型。
4. **产物不覆盖**：每次安装、冒烟和全量运行都创建独立目录与 nonce；同名产物存在时拒绝覆盖。

正式运行的验收口径也已经固定：

- 输入必须恰好 730 行，ID 非空且唯一，SMILES 非空，原始顺序不变；
- 正式输入中的非法或工具不支持 SMILES 不会被预先删除，而是在运行结果中形成逐分子失败终态；
- 成功工具先跑咖啡因、地西泮和修正后的糖类 SMILES；
- 冒烟只判断输出是否可解析、数值是否有限、分类值是否合法，不拿预期生物学方向反向筛工具；
- 通过冒烟后，每个工具用两个独立进程和两个独立目录运行 `full-r1`、`full-r2`；
- 两轮结果分别保留并逐端点比较，不用平均值掩盖随机漂移。

## 4. 已安装成功的五个工具

### 4.1 CYPstrate：18 个 CYP 底物分类端点

CYPstrate 0.0.25 安装在独立环境中，源码 revision 为 `c153960de7fba9b9b07047b7f20e55277a88fb41`，许可证为 BSD-3-Clause。

冻结范围为 9 个 CYP 亚型，每个亚型各保留两种官方模型模式：

- CYP1A2、CYP2A6、CYP2B6、CYP2C8、CYP2C9、CYP2C19、CYP2D6、CYP2E1、CYP3A4；
- `best_performance`：优先性能；
- `full_coverage`：优先覆盖率；
- 合法输出为 `Substrate`、`Non-substrate` 或 `No prediction`。

安装累计 2941.550 秒，最后一次安装 receipt 成功。

### 4.2 TRIDENT：9 个水生生态毒性模型

TRIDENT 固定到 revision `d4f70d4214587496a81e1b59f9449ced33203673`，许可证为 MIT。冻结的是 `{EC50, EC10, EC50EC10} × {fish, invertebrates, algae}` 九个官方模型版本，输出单位为 `log10(mg/L)`。

安装过程中处理了三个只改变运输或运行环境、不替换模型内容的问题：

1. 官方环境文件是 Windows Conda 导出，无法直接在 `linux-64` 求解，因此新建 Linux Python 3.9 环境；
2. 使用 CPU-only `torch 2.2.2+cpu`，避免无用 CUDA 运行库和 H20 架构兼容问题；
3. `huggingface.co` 从本机不可达，因此通过 `hf-mirror.com` 获取相同 Hugging Face 仓库字节，并逐一记录 9 个 `pytorch_model.bin` 的 SHA-256。

最终失败点并不在模型本身，而在缓存路径：`snapshot_download` 把模型存到 `$HF_HOME/hub`，Transformers 又把 `TRANSFORMERS_CACHE` 直接当作 cache directory。将其修正为 `$HF_HOME/hub` 后，离线健康检查通过。

真实健康检查输入为咖啡因：

```text
SMILES: CN1C=NC2=C1C(=O)N(C)C(=O)N2C
模型: EC50_fish
输出: 2.3124947547912598 log10(mg/L)
状态: HEALTH_CHECK_OK
```

薄适配器随后又独立运行同一输入，得到完全相同的 `value_num=2.3124947547912598`，证明安装入口和批量运行入口使用了同一套离线权重。

### 4.3 CypReact：9 个 CYP 反应物分类端点

CypReact 版本为 `2.0.0-SNAPSHOT`，源码 revision 为 `eb5925f364ecb3b3a4dbdf603b4abdb11a4c8c3f`，许可证为 MIT。

冻结端点覆盖 CYP1A2、2A6、2B6、2C8、2C9、2C19、2D6、2E1、3A4，合法标签为 `R` 或 `N`。安装一次成功，累计 697.585 秒。

### 4.4 CYPlebrity：5 个 CYP 抑制概率端点

CYPlebrity 0.0.15 固定到 revision `ea7c86d253599cbccdc819f59aeed436ba50405f`，许可证为 BSD-3-Clause。

冻结端点为 CYP1A2、CYP2C9、CYP2C19、CYP2D6、CYP3A4 的抑制概率。安装累计 1522.766 秒，最终健康检查通过。

### 4.5 BayeshERG：1 个 hERG 阻断概率端点

BayeshERG 固定到 revision `25e9466499905a952f9d41cc6bc6886c3f247acb`。代码许可证为 MIT；训练权重为 CC-BY-NC-4.0，因此当前只用于内部研究评估，不重新分发权重。

## 5. 五个失败工具为何没有继续“硬修”

### 5.1 OPERA：安装预算耗尽

OPERA 共运行 6 次安装尝试，累计单调时钟 7200.012 秒，已经触发每工具 7200 秒硬上限。最后阶段下载官方 v2.9.2 CL+MCR 归档时到达约 97.82%，距离完成约差 44.8 MB；根因是 GitHub release CDN 在本机出口长期降速。

当前没有完整官方二进制，因此没有冻结端点，也没有绕过预算继续下载。如果未来另行批准新预算，可以利用已保留的分块继续传输，但这不属于当前批次。

### 5.2 CONCERTO：官方权重不可达，旧 GPU 栈也不可用

CONCERTO 的核心 GROVER 预训练权重在本机无法从官方引用位置取得：腾讯链接返回 HTML，Google Drive 出口为 HTTP 000，OneDrive 返回重定向而不是权重二进制。

即使权重可得，项目固定的 CUDA 10.2、PyTorch 1.8.1、DGL 0.6.1 组合也不能直接面向 H20 的 `sm_90`。没有使用第三方权重替代官方资产，因此在 127.137 秒后以 rc=9 留下结构性失败回执。

### 5.3 CardioTox：旧依赖环境级联失败

CardioTox 共尝试 5 次，累计 6406.146 秒。官方 `environment.yml` 的 Conda 主体可以创建，但其中 pip 段包含较旧的 TensorFlow 与密码学依赖组合；在当前 Linux/Python 环境中触发 cryptography、pyOpenSSL 和 Rust 构建链的级联冲突。

当前结果保留为安装失败，没有通过任意升级或替换模型依赖来制造“看似成功”的环境。

### 5.4 EPA TEST：构建依赖与运行形态均不满足

EPA T.E.S.T. v5.1.2 共尝试 2 次，累计 606.475 秒。Maven 构建所需工件无法从本机解析；可核查的官方运行形态又以 Java GUI 为主。当前没有形成可在本服务器批量、无显示运行的官方入口。

### 5.5 VEGA QSAR：官方包传输失败，官方入口仍是 GUI

VEGA QSAR 1.2.6 的 HEAD 请求成功，服务端确认：

```text
HTTP 200
content-type: application/zip
content-length: 228650644
```

但从意大利 Aruba 主机下载该 228 MB ZIP 时，3631.903 秒后以 curl rc=28 超时。因此本轮没有完成 ZIP 解包和 JAR manifest 的本机复核。

独立的官方资料核查只发现 `Vega-launcher-LINUX.sh` 和 `java -jar VEGA.jar` 两种 Swing GUI 启动方式，没有找到官方 headless、CLI 或批处理入口；官方还说明首次启动需要联网下载 Python/Conda 附加文件。第三方 `ideaconsult/quarkus-vega-cli` 能增加 CLI，但它不是官方入口，未被采用。

## 6. 已完成的控制与审计能力

### 6.1 输入冻结

控制器支持 CSV、TSV、JSONL 输入。绑定时要求：

- 恰好 730 行；
- ID 和 SMILES 均非空；
- ID 唯一；
- 记录原始行号、SMILES 和单行 SHA-256；
- 冻结后内容变化会被自哈希校验发现。

正式输入中的非法 SMILES 不会被预筛删除。只有三分子冒烟输入会先过 RDKit 语法闸，避免把错误的测试样本当作工具故障。

### 6.2 安装预算与独立环境

`drug_prediction_campaign.py` 从全部历史 install receipt 累加安装秒数；预算耗尽后，后续安装命令会被拒绝。每个工具获得独立的：

```text
env/
home/
tmp/
cache/conda/
cache/pip/
cache/huggingface/
src/
weights/
install-attempts/
```

当前 `verify` 结果确认 10 个工具环境路径互不重复。

### 6.3 端点冻结与结果协议

端点清单来自官方模型、CLI、文档或随附权重，不根据后续预测结果增删。端点文件带自哈希，若内容变化，`load_endpoints()` 会拒绝继续运行。

每个“分子 × 端点”必须产生一条终态记录。成功记录要求数值有限或类别属于合法集合；失败记录保留 `error_type` 和 `error_message`。批任务崩溃时，缺失组合会转成明确失败行，不会静默消失。

### 6.4 双轮独立运行与导出

`full-r1`、`full-r2` 使用不同的进程、目录和 nonce。成功工具的导出逻辑会保留两轮各自的值、标签、状态和错误，并按端点报告：

- 两轮完全一致的数量；
- 最大绝对差；
- 最大相对差；
- 分类不一致清单。

失败工具的 730 行状态表仍属于最终交付阶段的待完成项：预测列应留空，并指向安装失败证据，不能误用成功工具的端点导出路径。
